## REQ-EMP-001 任职记录采用事件溯源版本链

## REQ-EMP-003 向后更新（追溯变更同步）

| 项 | 内容 |
|---|---|
| **业务目的** | 补录一条生效日期更早的任职记录时，把变更同步到已存在的、生效日期更晚的记录，保证"当前生效任职"的数据正确 |
| **触发条件** | **同时满足**：① 有对应字段变化；② 业务开始日期**之后**存在该员工**当前任职周期**内 `审批状态=生效` 的记录，**或**业务开始日期**及之后**存在 `审批状态 ∈ {审批通过, 审批中, 草稿, 已驳回}` 的记录 |
| **触发时机** | · 直接调动/转正、定时任务直接转正 → **数据保存时**<br>· 转正/试用期考核审批通过且结果为转正 → 插入转正记录时<br>· 调动/转正申请、批量调动申请、第三方 → 审批通过后立即生效时，或由定时任务在生效日期当天生效时<br>· 对外接口插入 → 数据插入成功时<br>· 导入调动、导入任职（新增模式）→ 数据导入成功时，**且**【是否更新后续任职】未填或填「是」 |
| **同步字段** | 所有未标记不继承的自定义字段 + REQ-EMP-002 R1 中列出的标准字段（不含 `Remarks`；含 `JobNumber`） |
| **⭐ 同步算法** | **值匹配替换**，非无条件覆盖：<br>设字段 F 从 `旧值` 变为 `新值`，则对本任职周期内生效日期更晚的每条记录 X：<br>　`if X.F == 旧值 then X.F = 新值 else 不变`<br>若插入记录的 F 与前一条**相同**，则 F **不参与**向后更新 |
| **特殊规则（必须实现）** | ① 字段引用的部门/人员/职务等值**已停用** → 不向后更新<br>② 职位与部门**同时**变化 → 仅更新"职位与部门**都**等于变动前值"的后续记录<br>③ 职务/职位变更时，**职务序列一并**向后更新<br>④ **`是否部门负责人` 不自动向后更新**（原站理由：更新不符合预期会引发数据泄露），需手动更新 |
| **编辑触发的额外条件** | 编辑任职记录时需**同时满足**：① 有字段变化；② 被编辑记录是**当前或未来生效的主职**任职记录；③ 满足上述触发条件②；④ 从支持的入口编辑 |
| **编辑入口支持矩阵** | 支持：页面单条编辑任职记录、编辑人员/实习生、批量导入内部员工/实习生（编辑模式或有则编辑无则新增）、对外接口编辑任职、调动交接编辑已生效调动记录<br>**不支持：批量编辑任职记录**（原站建议改用导入） |
| **补录表单默认值（DEC-041）** | 补录（生效日期早于员工已有的最新记录）时，表单中未改动字段的默认值取**插入日期当时生效的那条记录**（插入点前一条），不取最新记录。“是否有变化”也以该前一条记录为基准判断 |
| **配置边界** | 导入时的【是否更新后续任职】开关**首版保留**（需在导入模板中配置该字段） |
| **权限** | 随触发业务的权限 |
| **证据** | 手册 `向后更新`(112855719) 🟡；原站实测 2026-09-28（AC-FWD-01/02/06/07 🟢，W-240～242） |
| **目标差异** | **DEC-041**：原站补录表单默认取最新记录（实测 W-240 把 09-20 的人员类别带回 09-10），复刻改为取插入点前一条 |
| **验收** | AC-FWD-01 ~ AC-FWD-12 |

## REQ-EMP-004 任职记录审批状态机

| 项 | 内容 |
|---|---|
| **状态枚举** | `草稿` → `审批中` → {`审批通过`, `已驳回`} → `生效`；另有撤销路径 |
| **⭐ 核心规则** | **`审批通过` 与 `生效` 是两个不同状态，不可合并** |
| **生效规则** | · 审批通过日期 **≥** 生效日期 → **立即**转为 `生效`<br>· 审批通过日期 **<** 生效日期 → 保持 `审批通过`，由**定时任务**在生效日期当天转为 `生效`<br>· 直接业务（直接调动/直接离职等）→ **保存即 `生效`**，不经过 `审批中`/`审批通过` |
| **生效时的系统动作** | ① 新增任职记录并设 `是否当前生效=是`，原记录置否<br>② 执行向后更新（REQ-EMP-003）<br>③ 执行业务联动（见 REQ-TRF-*） |
| **撤销规则** | · `审批中` → 可**撤销流程**，**不生成**任职记录<br>· `审批通过`/`生效`/直接业务 → 只能**删除任职记录** |
| **依赖** | 审批中心（REQ-APV-*）、定时任务框架（B-10） |
| **证据** | 手册 112855719 触发时机表 🟡；109724216 撤销规则 🟡 |
| **验收** | AC-TRF-04、AC-TRF-05、AC-TRF-06、AC-TRF-07、AC-TRF-08 |

| **⭐ 存储粒度** | **`(user_id, app_code) → scope`** —— 同一用户在同一应用下**只有一份**数据范围，由其**所有身份共享**（🟢 实测：编辑 A4 一条授权记录，其 2 条记录范围同步变更；A3 编辑 1 条，4 条同步变更） |

| **⭐ 默认值语义** | `默认管理单元` = **空 = 无数据范围权限**（🟢 原站 UI 原文「默认管理单元无数据范围权限」；🟢 实测 A4 数据 0 条）<br>**复刻必须实现为 fail-closed**，不得实现为"未配置即全部"<br>**⭐ 例外（官方文档 HRSAAS/4751390 🟡）**：身份经「组织角色型」动态授权获得，且管理单元为默认管理单元时，在**人事、假勤**两类应用中，数据范围 = 该用户所担任角色的组织。若用户授权中另设了管理单元，则以所设管理单元为准。复刻要把这条实现为显式分支，不能用“默认=全部”来近似 |
| **⭐ 消费侧：实体/页面怎样套用范围**（2026-09-22，官方文档 🟡） | 每个实体声明**鉴权字段**（人员字段、部门字段），引用一条**权限规则**。官方原例是任职记录：`人员 ∈ 管理人员范围 AND 部门 ∈ 管理组织范围`。页面可以覆盖实体规则。除授权侧的管理单元外，页面还可以按 **汇报关系 / 组织关系 / 使用用户**（首版）和 项目关系（⏸）派生范围，多条规则取并集。**身份数据权限**可让指定身份看全部数据。优先级：身份 > 页面/数据源 > 实体（见 `02_业务建模/11_数据权限模型.md` §13）。首版不做数据权限触发器脚本，只预留扩展点 |
| **范围维度因应用而异** | 组织员工/审批中心 → 组织范围；薪酬管理 → **薪资组范围**；其余 → 管理单元。`scope_kind` 的可选集合是**应用元数据的一部分** |
| **生命周期规则** | R1. 撤销某身份时**不得**连带删除数据范围（其他身份仍在使用）<br>R2. 新授予一个覆盖同应用的身份时，**自动沿用**已有范围 |
