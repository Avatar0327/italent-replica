## 10. ⭐⭐ 关键发现：功能权限 ≠ 数据权限（A4 实测）

授予 `标准版系统管理员（组织员工）_简` 后，A4 的**功能权限完全打通**，但**数据范围为空**：

| 验证项 | 结果 |
|---|---|
| 「组织员工」菜单组出现 | ✅ 21 个顶级菜单 / 103 条 |
| `TenantBase.EmploymentRecord` IndexPage | ✅ 200「调动中员工」 |
| `TenantBase.Organization` IndexPage | ✅ 200「启用的组织」 |
| `TenantBase.EmployeeInformation` IndexPage | ✅ 200「在职员工」 |
| **组织列表实际数据（无筛选）** | ❌ **0 条**（「这里什么都没有...」） |
| **任职记录实际数据（默认筛选）** | ❌ **0 条** |
| 搜索 `RUN20260922_ORG_SRC`（A0 下有 1 条） | ❌ **0 条** |

### 10.1 结论
> **菜单可见 + 接口 200 + 视图元数据正常返回 ≠ 能看到任何一条数据。**
>
> A4 的授权记录中，`组织员工` 的管理单元是 **`默认管理单元`**，
> 实测其**实际覆盖范围为空**，不是"全租户"。
>
> 这推翻了一个容易犯的假设：「默认管理单元 = 默认给全部数据」。
> 实际是：**默认管理单元 = 未配置具体范围 = 无数据**。

### 10.2 对复刻权限模型的硬性要求
1. **功能权限与数据权限必须分两层独立建模与独立验证**。只验证"菜单出现/接口不报错"会得出完全错误的结论。
2. **数据范围的"默认值"语义必须显式定义**。原站的"默认管理单元"是**空**而非**全部**；复刻若把默认设为"全部"，会造成越权。
3. 授权记录的数据范围必须支持 **组织范围【组织名(编码)(包含下级)】** 这种表达（已在 A0 的授权列表中见到实例：`组织员工：组织范围【HT公司(zz10224)(包含下级)】`）。
4. **验收场景必须包含"有功能权限但数据范围为空"这一状态**——这是真实会发生的配置错误，系统应给出可理解的提示，而不是静默返回空列表。
   > 原站此时显示「这里什么都没有...」，与"确实没有数据"无法区分。→ **建议差异 D-003**：复刻版应区分"无数据"与"无数据权限"。
