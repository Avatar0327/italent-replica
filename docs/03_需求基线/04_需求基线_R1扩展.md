# 需求基线：R1 扩展（多租户、平台层、编制、职务体系、跨对象联动、审计）

> 版本：v0.1（2026-09-27）
> 本文件为已有规格文档补上需求编号，使路线图任务、需求、验收三者可以追溯。规则细节以规格文档为准，这里只写**要做什么、边界在哪、按什么验收**。
> 证据标记沿用全局约定：🟢 运行 / 配置证据，🟡 官方文档或推断，🔴 未取证。

## REQ-TEN-001 多租户隔离（R1-T00）

| 项 | 内容 |
|---|---|
| **依据** | DEC-006（对外 SaaS、多租户） |
| **规则** | R1. 业务数据、配置、身份、管理单元、流程、开关、文件、定时任务、日志全部带租户维度<br>R2. 任何跨租户读写一律拒绝，后端强制，不依赖前端<br>R3. 配置分两层：系统级预置（平台下发）与租户级覆盖；租户可以编辑部分预置配置，也可以“恢复”为系统级配置（原站实体 / 页面数据权限即如此，🟢 `11` §13.1）<br>R4. 日志保留期为租户级配置（DEC-019，`20` §5） |
| **原站证据** | 原站所有接口带 `tenantId`；组织 / 身份按租户隔离（🟢 租户侧观察）。原站的隔离实现不可见，**方案由复刻方自行设计** |
| **验收** | AC-TEN-01 两个租户各建同名组织，互相不可见；AC-TEN-02 用租户 A 的会话请求租户 B 的对象 ID → 拒绝；AC-TEN-03 租户覆盖一条预置配置后点“恢复” → 回到系统级配置 |
| **开发判定** | 可开发 |

## REQ-PLT-001 平台运营层（R1-T17）

| 项 | 内容 |
|---|---|
| **依据** | DEC-006；REQ-PRM-001 中的 L0 层 |
| **规则** | R1. 租户开通 / 停用，由平台方操作<br>R2. 开通时下发标准对象、标准身份（含 8 类企业管理员）、标准流程（**带发起条件**，DEC-018）、标准开关<br>R3. 许可证：按产品线发放余额；授予身份即消耗名额（🟢 AC-PRM-08）；余额为 0 时的行为待定（AC-PRM-09 🔴）<br>R4. 租户侧只看到余额与使用明细，看不到平台层 |
| **原站证据** | 平台层对租户账号不可见；余额与消耗 🟢；8 类管理员矩阵 🟡（`06` §7.1） |
| **验收** | AC-TEN-04 新开租户后，租户管理员可见 8 类管理员身份与标准流程；AC-PRM-08 / 09 |
| **开发判定** | 受限可开发：R3 中“余额为 0”的行为由复刻方定义（建议：拒绝授权并提示） |

## REQ-EST-001 编制管理（R1-T04）

| 项 | 内容 |
|---|---|
| **规格** | `02_业务建模/18_编制管理_规则规格.md` |
| **首版范围** | 编制方案（年度周期；无细分或按职位细分；维护方式 ①）；组织编制（本级 / 含下级 / 预留，四条一致性约束）；**严格控制**（是 → 拒绝；否 → 提示后继续）；编制时机只做**调入 / 调出**两项；调动表单显示编制信息；带编调动 |
| **可选（视进度）** | 季度 / 月度周期、按差值向后更新、复制下期（整批要么全成要么全不生成） |
| **不做** | Offer / 入职 / 离职占编时机（依赖 R2）；自定义编制维度（DEC-001） |
| **与原站差异** | DEC-015：批量操作不拦截，但逐行标出超编警告（原站完全不校验） |
| **验收** | AC-EST-01 ~ 07 |
| **开发判定** | 可开发（规则为官方文档 🟡，须跑 AC-EST 补测） |

## REQ-JOB-001 职务体系（R1-T04）

| 项 | 内容 |
|---|---|
| **规格** | `02_业务建模/19_职务体系_对象规格.md` |
| **首版范围** | 职层、职等、职级类别、职级、职务序列（建议 ≤ 3 级，冗余祖先列）、专业条线、职务、职位（所属组织 + 对应职务 + 直线 / 虚线上级职位）；全部带生效 / 失效日期与状态 |
| **规则** | R1. 职务的最低~最高职级 / 职等、职级的开始~结束职等作为任职时的约束：表单按区间（级别数值）过滤候选，服务端保存再校验（原站实测为候选过滤，AC-JOB-01 🟢）；职务体系对象的设立日期只作记录，不参与候选过滤、不拦截（DEC-040）<br>R2. **DEC-011**：直线经理两种来源并存，开关「调整员工直线经理」开启时按职位树同步到任职记录<br>R3. **DEC-016**：有在岗人员的职位禁止停用<br>R4. 未来生效的职务体系对象，生效日前不可在任职表单中选择 |
| **不做** | 职位复制、职位共享范围、预留维度 3–5 上级 |
| **验收** | AC-JOB-01 ~ 05 |
| **开发判定** | 可开发 |

## REQ-LNK-001 调动的跨对象联动（R1-T10）

| 项 | 内容 |
|---|---|
| **规格** | `02_业务建模/21_调动跨对象联动_对象规格.md` |
| **规则** | R1. 联动在**生效时**执行（不是审批通过时）：任职新版本、合同变更、兼职调整、职责转交（下属 + 组织角色）、组织角色变更、试岗开始<br>R2. 合同与任职同构：新版本 + 指向变动前版本<br>R3. 职责转交允许部分失败：记录失败数与明细，可重试<br>R4. 薪酬不在首版：只保存“是否调整薪资”，生效时生成“待调薪”提醒，不改薪资档案<br>R5. 存在联动变更时禁止删除调动任职（DEC-012） |
| **验收** | AC-LNK-01 ~ 06、AC-TRF-07 ~ 10 |
| **开发判定** | 受限可开发：R1 的执行顺序与失败补偿由复刻方设计；兼职结束日期口径（AC-LNK-06）待确认 |

## REQ-AUD-001 审计日志（R1-T16）

| 项 | 内容 |
|---|---|
| **规格** | `02_业务建模/20_审计日志_规格.md` |
| **规则** | R1. **DEC-019**：所有对象（含任职记录、组织、员工信息）的新增、编辑、删除写入统一的字段级变更日志，格式为「字段:从【旧】修改为【新】」，并记录操作人、时间、操作类型、对象、数据 ID、来源动作、来源页面、终端、IP、TraceID<br>R2. 删除时保存被删记录的完整快照<br>R3. 批量 / 导入 / 导出保留任务级日志（条数、结果、错误报告、附件、下载记录）<br>R4. 系统任务的操作人记为“系统”<br>R5. 保留期为租户级配置；日志审计菜单仅租户管理员、审计管理员可见 |
| **与原站差异** | 原站组织员工的单条操作不进数据变更日志（🟢 `20` §3）；复刻版纳入 |
| **验收** | AC-AUD-01 ~ 06 |
| **开发判定** | 可开发 |
