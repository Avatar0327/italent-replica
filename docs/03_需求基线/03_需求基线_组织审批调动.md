## REQ-ORG-001 组织对象与多维层级

| 项 | 内容 |
|---|---|
| **业务目的** | 表达企业的行政、业务、财务三种组织归属，支撑数据范围、审批路由、报表汇总 |
| **对象** | 组织（人事侧 `TenantBase.Organization`） |
| **标准字段（DEC-005 口径）** | 机构ID(编码)、名称、简称、全称、大类（默认"部门"）、层级、负责人、HRBP、虚拟组织(是/否)、所在地点、成本中心、设立日期、启用日期、禁用日期（默认 `9999-12-31`）、显示顺序、在岗人数、备注；**多维组织**：行政维度上级+顺序号、业务维度上级+顺序号、财务维度上级+顺序号 🟢 |
| **演示字段（不纳入）** | 商务机构/分类/标签/组分类、是否大客、市场分类、晋降级类别、管理提成类别、社保标准、社保缴纳机构、首发规则、个税标准、发薪账户、餐补标准、打卡企微、经营号码、区长、品牌、区域、面积、督导 |
| **规则** | R1. 仅「名称 + 行政维度上级」必填即可创建 🟢<br>R2. 组织不是单棵树：三个维度各自独立的上级与顺序号 🟢<br>R3. 组织管理下存在 `组织`/`业务组织`/`利润中心`/`成本中心` 四个并行视图 🟢<br>R4. **`负责人` 与 `HRBP` 必须是结构化人员引用** —— 它们是审批路由表达式的取值来源（见 REQ-APV-002） 🟢<br>R5. 列表按名称搜索为**精确匹配** 🟢（复刻可改为模糊，列为可选差异）<br>R6. **机构全称（DEC-021）**：存储统一为从租户根起算、以 `/` 分隔的全路径（原站两处口径不一，C-004）；显示时按租户配置的“起始层级”截取（对应原站「组织全称显示设置」）；所有列表、接口、导出使用同一口径；组织改名或移动时下级全称同步刷新 |
| **权限** | 组织管理员、标准版系统管理员可维护；人事管理员不可创建组织（官方矩阵 🟡） |
| **开发判定** | **可开发**（2026-09-22 复核）：G-011（人事与平台两侧是同一份数据）、G-013（1 个恒在的行政维度 + 4 个可开关的扩展维度，扩展维度非必填）、G-014（109 个标准字段）均已关闭，见 `10_组织对象_实测规格.md` §8 |
| **验收** | AC-ORG-01 ~ 11 |

## REQ-SYS-002 排序规则与排序编码（DEC-037）

| 项 | 内容 |
|---|---|
| **模型** | 排序规则（编码、名称、类型、状态、适用对象 / 字段、是否含子集）+ 规则项（序号、排序属性、正序 / 倒序、引用子规则）；预置 人员默认排序规则、组织默认排序规则，以及被引用的 组织行政隶属关系 / 职位 / 职务 / 职级 / 职等 子规则 🟢 |

## REQ-APV-002 审批人动态解析 ⭐

| 项 | 内容 |
|---|---|
| **业务目的** | 审批人随组织与任职数据自动确定，不需要在流程里写死具体人 |
| **规则** | R1. 审批人通过**对象关系路径表达式**解析，而非固定人员 🟢<br>R2. 调动流程实测的四种解析路径 🟢：<br>　· 调出部门负责人 = 人员 → **最新任职记录** → 部门 → 负责人<br>　· 调入部门负责人 = **本条任职记录** → 部门 → 负责人<br>　· 调入部门 HRBP = 本条任职记录 → 部门 → HRBP<br>　· 调入一级组织负责人 = 本条任职记录 → 部门 → 一级组织 → 负责人<br>R3. 「调出/调入」的区分靠**从哪条任职记录取部门**（最新生效记录 vs 本次申请记录），不靠角色 🟢<br>R4. 每个节点独立配置：审批人为空时的处理、相同审批人是否跳过、历史相同审批人是否跳过（各有跳过后结果） 🟢 |
| **首版最小表达式集** | 流程所有者；最新任职记录部门负责人；本条记录部门负责人；本条记录部门 HRBP；上溯一级组织负责人。以上五种覆盖已取证测试调动流程全部节点；F-028 / DEC-230 新增**直接上级**（`direct_manager`）：流程主体员工 → **最新生效主职任职记录** → `directManagerId`，不取发起人、本次申请或未来未生效任职；原站来源待取证 #95 |
| **无有效审批人（DEC-054）** | R5. **首节点**审批人解析为空 → **提交即报错**，不生成实例（原站开始节点 `submitCheckType=1` 不可删，`14` §8.3）<br>R6. **中间节点**审批人为空 → 转流程**异常管理员**（原站实测 G-030，`14` §8.7）；流程定义的异常管理员**必填**，发布时校验 |
| **禁止自审（DEC-058）** | R7. 审批人解析结果是**发起人本人**或**异动员工本人**时，该节点对此人自动跳过，任务转其上级；上级无法解析时转异常管理员。自审跳过**不得**以“同意”计入，节点日志写明“自审跳过”。DEC-068 已明确：取该审批人最新生效主职任职的直线经理；为空、仍为本人或已在本单审批链上时转异常管理员 |
| **开发判定** | ~~**受限可开发**（2026-09-22 复核）：G-033 已关闭（抄送是审批人手动选人的动作；消息规则见 `14` §8.2）；首节点提交时的空执行人校验已证。**仍禁止推断**：中间节点审批人为空、配置为「无操作」时的流转（G-030）~~<br>→ **可开发**（2026-09-30 复核）：G-030 已于 2026-09-28 实测（中间节点为空 → 异常管理员，`14` §8.7），并由 DEC-054 定为复刻规则（R5/R6） |
| **验收** | AC-APV-01 ~ 04、AC-APV-13（DEC-054）、AC-APV-15（DEC-058 自审）、AC-APV-38～42（F-028 直接上级） |
