## 1. 业务理解
### 1.1 模块目标
人才评定是任职资格的“评定环节”（DEC-009）：企业按任职类别和级别组织晋级评审，判断员工能否获得更高一级任职资格。
HR 配好活动类型、周期、评审组和评价表后发布评定活动；员工申报或被提名，经资格审批、材料举证、答辩打分和跟场人校准，最后发布结果并写入任职资格子集。
用户包括评定管理员（活动设置、基础设置）、评定专员（评定过程、评定记录）、评委、跟场人和申报员工。
首期做标准模式评价表和四类环节各一个；高级模式、多个材料 / 答辩环节、考核与学习函数条件、统计看板、干部述职不做（`24` §4）。

### 1.2 核心对象与关系
| 对象 | 说明 | 关键关系 / 约束 | 规格位置 |
|---|---|---|---|
| 活动类型 | 名称、顺序号、是否同步任职资格子集 | 名称唯一；“同步任职记录”首版不提供 | `24` §2、补充 Q-M0-152；DEC-025 |
| 活动周期 | 评定窗口，供统计 | 名称唯一；被活动引用不能停用 | `24` 补充 Q-M0-170 |
| 通用评分项 | 标准之外的评分项（现场表现等），评分或评级 | 被评价表引用时拒绝停用 | `24` 补充 Q-M0-171 |
| 评审组 / 成员 | 评委分组，组长 0 或 1 个（有成员也可不设，多于 1 个返回 400），所属组织必选 | 列表按所属组织裁剪；成员离职自动退出 | DEC-331①、DEC-400②；F-092 |
| 评价表（标准模式） | 按指标评分或评总分；最多一条任职资格标准 + 若干通用评分项 | 无编码、名称不唯一；被活动引用不能停用 | `24` EV-R3～R5；DEC-413 |
| 评定活动 | 类型、周期、年度、所属组织、组织范围、申请人、申请类别 / 级别、跨级、生效日期、状态 | 三步向导，第三步一次保存 | `24` §2、§3.2 |
| 参评条件 / 明细 | 通用 / 附加，本人 / 非本人各一套；字段 + 运算符 + 值 + 组合表达式 | 不设条件则不校验 | `24` EV-R10、R11 |
| 活动环节 | 资格申报、材料举证、答辩评审、结果发布；评价表、审批流程、转入方式、破格 | 首尾环节必有；答辩 → 发布只能手动 | `24` EV-R12、R13 |
| 员工评定数据 | 一人一活动一条（未通过 / 终止后再报新建一条）；各阶段状态分列 | 终止原因：离职 / 完成活动 / 撤销 | `24` §3.8；设计 §3.5；DEC-378 |
| 场次、评委记录、指标明细 | 场次时段、评委逐项打分与弃权 | 评分项在评委首次保存时冻结 | `24` §2；DEC-153 |

### 1.3 关键流程与规则
1. 评定结果只写任职资格子集，不生成调动任职；职级变化由 HR 另行发起调动（DEC-025；`24` EV-R1、AC-EV-09）。
2. 活动适用范围 = 申请人任职部门 + 申请类别 + 申请级别；同组织同类别已有进行中活动时拦截（EV-R9；DEC-372②）。
3. 跨级限制 N 表示最多高出 N 级，必填，取值 1～5（DEC-372①；`24` 补充 Q-M0-154；AC-EV-01）。
4. 参评条件分通用与附加，本人申报与他人提名各一套；字段为空按“与比较值不同”判定（EV-R10；`24` 补充 Q-M0-155）。
5. 编辑锁：已有报名后只能改部分字段，不能删环节；评价表被“进行中且已有提名”的活动引用后锁定评分规则（EV-R14、EV-R5；AC-EV-05）。
6. 发布按当前生效信息匹配通知范围；取消发布只在无报名时可用，不撤回已发通知（EV-R15）。
7. 状态按阶段分列（申报 / 材料 / 答辩 / 结果）；撤销、完成活动、离职共用一个终止内核，在途审批立即作废（设计 §3.5；DEC-365④）。
8. 离职任职生效时终止其进行中的评定并记原因；评定所在周期内已离职的员工，后续写命令一律 409（DEC-032；设计 §4.4）。
9. 多评委最终得分只统计已提交的评委，弃权不计；有评委既未提交也未弃权时不能进入“已评审”（DEC-044；AC-EV-06、AC-EV-12）。
10. 跟场人确认校准后锁定评委评价，提交和弃权都拒绝（DEC-046；AC-EV-08）。
11. 加权平均时指标实际权重 = 标准整体权重 × 指标在标准中的权重（EV-R4；AC-EV-07）。
12. 结果发布须手动；资格审批通过只代表申报阶段通过，结果发布后才按评定生效日期写入子集（审批通过 ≠ 生效；EV-R42、R43；设计 §4.5）。
