## 1. 业务理解
### 1.1 模块目标
员工与任职是人事数据的主干：员工信息存“人”的属性（一人一份），任职记录存“在哪个组织、什么职务、什么状态”的时间序列（每次业务一条）。
HR 用它查员工、看档案和任职变迁，调动、转正、离职等业务都落到任职版本链上；人员子集（教育、履历等 13 类）补充档案明细。
首期复刻：任职版本链、继承、向后更新、定时生效、撤销删除的完整后端（R1-T05/06/08/11/12），页面只做员工列表与档案只读（FE-R1b）。新建员工 / 录用入职属 R2（`34_录用入职_规格.md`），本模块未做页面。

### 1.2 核心对象与关系
| 对象 | 说明 | 关键关系 / 约束 | 规格位置 |
|---|---|---|---|
| 员工信息 `TenantBase.EmployeeInformation` | 人的属性：姓名、证件、联系、入离职日期、排序号、时长派生字段 | 挂在平台用户上，一个用户一份；不含任职字段 | `17` §1、§1.1 |
| 任职记录 `TenantBase.EmploymentRecord` | 一次业务一条版本，只写本次变更字段，其余继承 | 生效区间 [生效日期, 失效日期]；主职失效日期由时间轴自动赋值 | `07` §1；`15` §1.1 |
| 任职周期（StaffID） | 一次入职到一次离职 | 新增入职、重聘、退休返聘开新周期；跨周期不继承 | `07` §2、§2.1 |
| 任职变动记录 `EmploymentChange` | 主职记录创建时生成，指向前一条生效主职 | “变更前 XX”沿它取上一条同名字段，不单独建列 | `15` §2、§11 |
| 两个标志位 | 是否当前生效 / 是否最新主职 | 未来生效记录可“最新”而不“当前”，必须分开实现 | `15` §1 |
| 人员子集（13 个） | 教育、工作履历、家庭、证书等 | 冗余员工排序字段；工作履历可由任职同步生成 | `22` §1～§3 |
| 人员状态 / 入职状态 | 待入职、试用、正式等 | 由业务推导，不可在任职编辑中直接改 | `15` §9 |
| 头像 | 账号层字段，员工侧只读引用 | 不用档案照片代替；范围外人员与姓名同口径显示 | `17` 头像补充；DEC-327 |

### 1.3 关键流程与规则
1. 任职是事件溯源版本链：每次业务新增一条记录，不 UPDATE 当前值；“变更前”从链上一条取（`07` §1；`15` §2；AGENTS.md §2）。
2. 字段继承只在同一任职周期内发生，入职类业务全部不继承；自定义字段可设继承开关（`07` §2、§3；AC-EMP-01～08）。
3. 审批状态有草稿 / 审批中 / 审批通过 / 已驳回 / 生效，“审批通过”与“生效”分开；未来生效日由定时任务按租户时区落地，失败记待办可重试（`07` 附 A2；DEC-052、DEC-056）。
4. 同一周期同一生效日允许多条主职业务，按操作先后排序；前序生效失败时其后的待生效业务挂起（DEC-108、DEC-112）。
5. 早于当前周期入职生效日的业务一律拒绝，不向已结束周期补录（DEC-111；`07` 附 A9 Q-M0-19）。
6. 补录触发向后更新：按值匹配替换后续记录，四条特殊规则（停用不更新、部门与职位成对、职务带序列、负责人标记不传）；补录默认值取插入点前一条（`07` 附 A5；DEC-041、DEC-107、DEC-120）。
7. 删除任职：有联动变更或其后存在在途申请时拒绝，提示先撤销（DEC-012、DEC-126、DEC-172；`07` 附 A11，有意差异 D-001）。
8. 任职记录可见口径：记录所在部门或员工当前部门在操作人范围内即可见；联动改写不可见记录时整单拒绝（DEC-177、DEC-178）。
9. 数据范围默认空（fail-closed）：员工列表、档案、子集都按服务端人员范围与字段权限裁剪，前端不补字段（AGENTS.md §2；`11_数据权限模型.md`）。
10. 人员状态、入职状态只能由业务推导，新增 / 编辑 / 批量 / 导入中带入一律 400（AC-EMP-18；`15` §9）。
11. 员工信息的组织 / 职务排序号与人员组合排序编码预计算存储、周期重算（DEC-089、DEC-148）。
12. 教育经历“最高学历”同一员工唯一并回写员工信息；调动 / 入职 / 离职按开关同步本单位工作履历（`22` §2 第 3～4 条、附录 Q-M0-37 / 69）。
