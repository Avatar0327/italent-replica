## 1. 业务理解
### 1.1 模块目标
调动是员工在职期间最频繁的任职变化：换部门、换职务职位、调职级，往往同时牵动合同、职责、下属和试岗。原站把它做成“任一角色发起 → 审批流转 → 到期生效”的单链路，没有“调出方 / 调入方 HR 对接”（`08` §1）。审批中心是这条链路的通用中枢：按审批类型匹配流程、动态解析审批人、承载待办与审批详情，离职、转正等业务共用。首期复刻 HR 发起（含直接调动）、审批中心待办 / 已申请 / 详情与四个基本动作，后端已覆盖流程定义、加签会签、管理员干预与跨对象联动。

### 1.2 核心对象与关系
| 对象 | 说明 | 关键关系 / 约束 | 规格位置 |
|---|---|---|---|
| 调动申请（业务单） | HR / 经理 / 员工发起的一次调动；状态 草稿 → 审批中 → 审批通过 → 生效，另有驳回、撤销、作废 | 审批期间只存申请单，生效时才写任职版本链（DEC-125） | `08` §12 |
| 任职记录（调动版本） | 生效时新增的一条任职版本，继承未变更字段 | 版本链按生效日期排列；“原值”从上一条取，不单独建列 | `08` §12；`07` |
| 调动类型 / 原因 / 交接配置 | 本租户启用 19 个调动类型、7 个调动原因；交接事项与发起规则 | 类型决定带出规则；交接审批通过时自动发起 | `13` §3、§6.1～6.2 |
| 调动设置开关 | 原站 SwitchType 31 / 66 / 94 / 95 / 98；复刻新增“允许直接调动” | 开关关闭时后端同步拒绝（DEC-051） | `13` §2、§2.0 |
| 流程定义与版本 | 审批类型 + 发起条件 + 优先级 + 节点；发布生成版本 | 在途实例按发起时版本运行；异常管理员必填 | `14` §1～4 |
| 审批节点 / 任务 | 节点审批人全部为动态表达式（部门负责人、HRBP、直接上级等） | 节点级配置详情页表单、抄送、加签、驳回规则 | `14` §2、§2.1.1、§2.2 |
| 联动子项 | 合同变更、职责转交（下属 / 组织角色）、调动交接、试岗、待调薪提醒、结束兼职 | 生效时执行，逐项记结果，可重试 | `21` §1～3 |

### 1.3 关键流程与规则
1. 三类发起人共用一个调动表单与提交服务，按身份裁剪字段与按钮（`08` §1；DEC-053）。
2. 流程匹配先按审批类型过滤，再按优先级判断发起条件；同类型都不满足即报错，不跨业务兜底（`14` §8.1；DEC-017）。
3. **审批通过 ≠ 生效**：通过日 ≥ 调动日立即生效，否则由定时任务在调动日按租户时区落地；失败记 failed、次数、原因并生成 HR 待办，可重试（`08` §12、§16；DEC-052、DEC-056）。
4. **版本链**：审批期间不写任职记录，生效时新增一条版本并按“值匹配替换”向后更新（`08` §12；DEC-125）。
5. 直接调动保存即生效，不走审批；租户开关“允许直接调动”默认开，关闭后按钮隐藏、接口拒绝（`08` §16；DEC-051）。
6. 联动在生效时整体执行；首版“调整薪资”只记标志并生成待调薪提醒（`21` §3；DEC-002）；有联动变更的已生效调动阻止删除（DEC-012）。
7. 审批人最小披露：只看本节点表单字段，不因审批获得档案范围（`14` §10；DEC-057）。
8. 禁止盲审：本单变化字段中有审批人无权查看的，同意 / 驳回均不可用；禁止自审：发起人或异动本人被解析为审批人时跳过并转直线经理（`14` §10；DEC-058、DEC-068）。
9. 管理员不得代签，只能转交或干预，每次管理动作入审计；转交给自己须填理由（`14` §10；DEC-063、DEC-070）。
10. **数据范围 fail-closed**：HR 选人受数据范围约束；管理员转交 / 改派目标须在其管理单元范围内（AC-TRF-03；F-067，PR #154）。
11. 无有效审批人：首节点为空提交即报错，中间节点为空转异常管理员（`14` §8.3、§8.7；DEC-054）。
12. 管理委托（委托人 ∩ 受托人 ∩ 范围）首版不做，转交与加签照原站保留（`14` §10；DEC-064）。
