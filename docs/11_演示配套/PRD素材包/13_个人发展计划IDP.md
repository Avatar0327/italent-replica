## 1. 业务理解
### 1.1 模块目标
IDP 把“员工下一步怎么成长”落成一份有阶段、有审批、有回顾的计划。HR 先配好发展计划流程（若干子流程串联，每段走一条审批流）
和计划模板（基本信息、关键信息、发展目标、回顾、总结等模块），再给员工发起计划；员工与指导人在各阶段节点里制定目标、做回顾，
HR 可以催办、跳转、转交、开启下个阶段或终止。IDP 在原站是独立应用，挂在「继任与发展」菜单下（DEC-009）。
首期：流程、模板、计划执行、带教 / 职业发展 / 轮岗信息维护与 HR 干预后端都已合并；导入、导出、学习计划等不在首期。

### 1.2 核心对象与关系
| 对象 | 说明 | 关键关系 / 约束 | 规格位置 |
|---|---|---|---|
| 发展计划流程 | 名称、所属组织、向下公开、启用 | 被模板引用后不能改子流程顺序与开启方式 | `28` §1、IDP-R5 |
| 子流程 | 顺序、类别、关联审批流、开启方式与规则、结束通知模板 | 一个子流程 = 一条审批流实例；预置 制定计划 / 中期回顾 / 期末回顾 | `28` IDP-R1～R3、Q-M0-115③ |
| 计划模板 | 名称唯一、流程、发布状态、模块列表 | 被引用后不能增删模块，模块设置对已有计划实时生效 | IDP-R6、IDP-R12、G-056a |
| 模板模块 | 基本信息 / 关键信息 / 综述 / 盘点结果 / 发展目标 / 回顾 / 总结 | 节点权限按流程节点配置可用按钮 | Q-M0-115④；DEC-296④ |

### 1.3 关键流程与规则
1. 子流程串联，每段引用一条已发布审批流（审批类型“发展计划”）；预置三条审批流都是“员工本人 → 指导人”两个处理节点（`28` IDP-R1、Q-M0-115③）。流程匹配先按审批类型过滤（AGENTS §2）。
2. 开启方式分自动（上一阶段结束即开、固定日期、相对时间）和手动；系统按租户时区每天凌晨 2 点开启到期阶段，审批流开不起来就记“开启失败”，由 HR 查明后手动开启（IDP-R2、IDP-R3；DEC-296⑤、DEC-056；AC-IDP-01、AC-IDP-08）。
3. 上一阶段结束、下一阶段未开时，当前阶段显示“努力提升中”；最后一个子流程结束后计划自动结束（IDP-R4；`28` 结束通知实测）。
4. 被模板引用的流程不能改子流程顺序与开启方式；被计划引用的模板不能删除、不能增删模块，模块设置实时生效（IDP-R5、IDP-R12；AC-IDP-03）。
5. 通用目标只对之后发起的计划生效；开了无目标校验时没有目标不能提交；统一下发任务只能针对同一模板的计划（IDP-R9、IDP-R10、IDP-R15；AC-IDP-04～06）。
6. 节点权限按流程节点配置可用按钮（新增 / 编辑 / 删除目标等），不按角色；参与人只看固定字段集（DEC-296④；Q-M0-115④）。
7. 审批口径照原站：员工填写节点就是审批节点；同一 / 历史审批人跳过等回避做成节点级开关，IDP 预置流程全部关闭；指导人可驳回、驳回到上一步（DEC-318；K-37～K-39）。
8. 流程干预：跳转只能在当前子流程内，阶段第一个节点不能向前跳；转交目标须在操作人 IDP 管理范围内且已绑定员工，例外是该计划已有的指导人 / 带教人，几类失败的错误响应一致；计划所有者可全量干预（IDP-R16；DEC-321、DEC-354、DEC-358；AC-IDP-02）。
9. 终止不发结束通知并收回待办；正常结束才发结束通知，发给员工本人，变量在发送时取值（`28` Q-M0-139；发送待 F-059）。
10. 关键信息只取与计划起止有交集的记录；轮岗判重键在原站基础上补“员工”（IDP-R7、IDP-R21；D-063；AC-IDP-07）。
11. 胜任力来源五选，“所属人才池”取出池标准；员工从库选目标时，候选只列本计划已确定的来源，只投影名称 / 定义 / 类别（IDP-R8；G-056、T-406；DEC-307）。
12. 平台约定：写命令带 revision 与命令 ID、批量干预逐条回执；数据范围默认为空（fail-closed）；业务与审计同事务（AGENTS §10；`plan-routes.ts` 文件头注释）。
