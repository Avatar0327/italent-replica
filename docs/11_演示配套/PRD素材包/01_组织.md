## 1. 业务理解
### 1.1 模块目标
组织是人事主数据的骨架：任职、数据范围、审批路由、编制和报表都按组织归属来算。HR / 组织管理员在这里维护组织的名称、
上级、设立与停用，并能按任意历史时点查看当时的组织架构。原站的组织不是一棵树，而是行政维度加若干扩展维度的多条并行层级，
且组织本身按生效日期保存版本。首期做组织对象的完整后端（新建、变更、更正、停用、导入、联动任职）和 PC 端的列表、架构图、
详情、变更与停用页面；组织调整审批（规格 `33`）属 R2。

### 1.2 核心对象与关系
| 对象 | 说明 | 关键关系 / 约束 | 规格位置 |
|---|---|---|---|
| 组织（对象） | 恒定标识，人事侧与平台侧是同一份数据 | 内部 ID 与业务编码分离，编码租户内唯一（DEC-060） | `10` §8.1；`17` §2.1 |
| 组织版本 | 某一时段的组织快照（生效日～失效日，默认失效 `9999-12-31`） | 变更追加版本，不原地改写；首版生效日 = 设立日期（DEC-130） | `10` §6、§8.3、§11 |
| 多维上级 | 行政维度恒在；业务、利润中心（产品）、预留 4 / 5 可开关 | 每维各有上级与顺序号；成本中心不是维度（DEC-134） | `10` §2、§8.2、§13 |
| 组织变更记录 | 前后两个版本 ID 串起版本链 | 与任职记录同构，复用“有效期版本 + 变动记录” | `17` §2、§2.1 |
| 编码预占 | 打开新建表单即占号，取消或保存后释放 / 消耗 | 释放的编码可复用；并发打开拿到不同编码 | `10` §4.2、§11 |
| 组织设置 | 维度开关、全称起始层级 | 全称存全路径、显示从第几级起（DEC-021） | `10` §8.2；AC-ORG-10 |
| 联动任职 | 改名 / 改行政上级时按选择追加「组织调整」任职 | 只追加版本，原记录止于前一天（DEC-137） | `10` §16、§17 |

### 1.3 关键流程与规则
1. 组织按生效日期保存版本，变更一律追加新版本，可按任意日期查看当时快照（`10` §8.3；`17` §2.1；硬规则·版本链）。
2. 层级是多维的：行政维度恒在，业务 / 利润中心 / 预留 4、5 由租户开关，各维独立上级与顺序号，不用单一 parent_id（`10` §2、§8.2；硬规则·组织层级）。
3. 新建时设立日期必填并作为首版生效日，可倒填或填未来日期（`10` §11；DEC-130）；只填名称 + 行政上级即可建成（AC-ORG-03）。
4. 编码在打开新建表单时预占，取消释放、保存消耗，释放后优先复用（`10` §4.2；AC-ORG-01 / 02）。
5. 「编辑」只更正设立日期、不产生新版本，且不得晚于后一版本生效日、不得早于上级设立日（`10` §18；DEC-147）。
6. 「变更」改名或改行政上级时必填“是否新增任职”：选“是”为本组织及下级在职员工追加「组织调整」记录，不走审批（`10` §16、§17；DEC-137）；导入同样必填（DEC-207）。
7. 保存前预检在途任职，只提醒、不拦截；迟到执行区间内另有业务时 fail-closed 交 HR 处理（`10` §17；DEC-278、DEC-186）。
8. 停用上级级联停用整支下级；整支内仍有在职人员、在岗职位或在途调入（含审批中）即整单拒绝，不做自动转移（`10` §9；DEC-129、DEC-196）。
9. 负责人 / HRBP / 店长候选为全租户在职内部员工，不按操作人数据范围过滤，只返回最少字段（`10` §14；DEC-135）。
10. 组织名称搜索为精确匹配（`10` §6；AC-ORG-06）；数据范围“含下级”不因下级停用而收缩（DEC-146）。
11. 默认无可见组织（fail-closed），每次请求重算租户与范围；跨租户组织 ID 一律拒绝（硬规则·数据范围、租户隔离；AC-ORG-26）。
12. 写请求带 revision，不一致返回 409，客户端回查后重新打开再提交，不盲重试（AGENTS §10；DEC-067）。
