## 路线概览

这条路线讲继任管理的主链路：HR 维护“某个组织 / 职位有谁来接班”（继任记录），系统把它画成组织继任地图和职位继任地图，再叠加职位风险等级、组织健康度，帮助业务看清后备力量。给 HR 与业务负责人看。后端（继任记录、地图、风险与健康度结果、计算任务）已就绪，页面按规划是展示与基础维护；规则配置（风险 / 健康度条件行）不在 FE-R3d 展示范围内。

## 前置准备

1. 启动与重置：`pnpm demo`（写入种子并同时起后端 :3000 与前端 http://localhost:5173），出问题用 `pnpm demo:reset`，细节见 README“本地演示”章节。
2. 种子没有给任何身份授予继任权限。先切到 系统管理员（演示），进入 企业设置，授权摘要（真实文案取自 apps/web/src/settings，完整配方详见 06_企业设置.md 的授权配方）：
   - “用户授权”页右上“新增”→ 抽屉“新增用户授权”，填“用户编号”，在“身份”下拉选“继任管理员（继任与发展） (standard_succession_admin)”→“保存”；若只演示记录与地图维护，也可选“继任 HR（继任与发展） (standard_succession_hr)”（不含风险 / 健康度等级规则配置）。
   - 该行“操作”列“数据范围”按钮 → 抽屉“数据范围”：“应用编码”填 SuccessionAndDevelopment → “查询数据范围”→“编辑”，选“组织范围”→“添加组织”，填“研发中心”的组织编号并勾选“包含下级”→“保存”。数据范围默认为空，继任记录与地图都按目标组织过滤，不设范围就看不到数据（页面提示“当前没有可查看的数据范围”）。
   - 继任管理员只对规则配置类对象（风险 / 健康度等级、人员范围、默认颜色）预置“看全部”，记录和地图不预置。
3. 切到 HR专员（演示），菜单“人才管理”分组出现“继任管理”。建议打开顶部栏“注释”开关（若 FE-R3d 登记了注释）。

## 步骤 1：授权后进入应用，认识页面结构

- **演示身份**：HR专员（演示）
- **页面与路由**：/succession；左侧菜单“人才管理”→“继任管理”
- **操作**：点左侧菜单“继任管理”；浏览页面顶部的页签或子导航（暂定：“继任列表”“组织继任地图”“职位继任地图”）；未授权时对比：切回 平台研发部经理（演示），确认菜单里没有“继任管理”。
- **讲解要点**：
  - 菜单可见性来自服务端权限快照，只有拥有对象 `Succession.Map` 的身份才看到入口，前端不硬编码角色（DEC-043 数据范围按“用户 × 应用”存一份，应用编码 SuccessionAndDevelopment）。
  - 原站“继任与发展”菜单下有组织继任地图、职位继任地图、继任列表等（规格 27 §1），IDP 同属该菜单；复刻按两个应用分别入口：本应用 /succession，IDP 见 13_个人发展计划IDP.md（/idp）。
  - 数据范围默认为空（fail-closed），这是八条硬规则之一，授权后要再设范围才有数据。
- **预期结果**：HR专员（演示）菜单出现“继任管理”并进入 /succession；页面形态以 FE-R3d 合入版本为准；平台研发部经理（演示）看不到该入口。
- **高亮目标**：左侧菜单“人才管理”分组下的“继任管理”项；页面顶部页签条（暂定）。

## 步骤 2：新增组织继任记录

- **演示身份**：HR专员（演示）
- **页面与路由**：/succession，继任列表（暂定）
- **操作**：
  1. 点列表右上“新增”（暂定，对应对象按钮 create），选继任类型“组织继任”。
  2. 目标组织选“平台研发部”（负责人自动带出）；继任者在搜索框输入“罗雪慧”选择（DEMO-0031，平台研发部直属）；准备度留空或选可用项；后备类型选“正职”（暂定，对应 principal）；开始时间默认今天。
  3. 先故意把开始时间选成明天，点保存看拒绝；改回今天后保存。
  4. 再给“数据研发部”添加继任者“刘扬宇”（DEMO-0039）。
- **讲解要点**：
  - 规则 SC-R2：开始 / 结束时间都不得晚于今天，不允许维护未来生效的继任（AC-SC-01：开始时间填明天 → 拒绝）；结束时间为空表示当前生效（库内存 9999-12-31）。
  - 继任者下拉按 DEC-308 全租户搜索（含待入职，最多 30 条），不受 HR 数据范围限制，与原站一致；目标组织必须在操作人数据范围内。
  - 同一人可同时是多个组织 / 职位的继任者，不设上限（DEC-034）。目标和继任者建后不可改（FIELD_IMMUTABLE），只能改准备度、后备类型、起止时间。
- **预期结果**：保存后列表出现一行：类型组织、目标“平台研发部”、负责人（平台研发部经理（演示））、继任者“罗雪慧”、状态生效中（暂定）；开始时间为明天时保存被拒绝并提示时间不合法。
- **高亮目标**：列表右上“新增”按钮；表单里的“目标组织”“继任者”“开始时间”字段；保存失败时的错误提示；新增后列表中的新行。

## 步骤 3：组织继任地图

- **演示身份**：HR专员（演示）
- **页面与路由**：/succession，组织继任地图（暂定）
- **操作**：
  1. 切到“组织继任地图”，默认以行政维度最顶层组织为根展开，层数默认 3 层；调整层数（2～4）或指定根为“研发中心”。
  2. 看“研发中心 → 平台研发部 / 数据研发部 → 前端开发组…”的树，点开“平台研发部”卡片。
  3. 打开地图显示设置（暂定名“显示设置”），切换“隐藏虚拟组织”“显示现任人员”，隐藏一个子组织。
- **讲解要点**：
  - 规则 SC-R5：地图从一个根展开，默认 3 层（2～4 可选），组织卡片展示负责人、继任者列表（继任者、准备度、后备类型、开始时间）、健康度等级、绿化率 / 在岗人数 / 编制数；超出数据范围的组织及其下级不出现。
  - 卡片上的绿化率、在岗人数每 4 小时计算一次，没算过显示“--”（SC-R6）；开关“本人继任者是否可见”为否时，登录人看不到自己的继任者（SC-R7）。
  - 地图只读，数据来自继任记录；个人显示设置（根、层数、隐藏的组织、是否显示现任等）保存在个人偏好里，不影响他人。
- **预期结果**：树根为“研发中心”（范围内顶层）；“平台研发部”卡片显示继任者“罗雪慧”、负责人为平台研发部经理（演示）；“数据研发部”卡片显示继任者“刘扬宇”；其他组织卡片无继任者；健康度、绿化率显示“--”或默认颜色。
- **高亮目标**：地图根节点与树状层级；“平台研发部”组织卡片的继任者区域；地图顶部的层数 / 根选择与显示设置入口（暂定）。

## 步骤 4：新增职位继任记录（依赖关键职位）

- **演示身份**：HR专员（演示）
- **页面与路由**：/succession，继任列表（暂定）
- **操作**：
  1. 点“新增”，继任类型选“职位继任”。
  2. 目标职位选“平台研发部经理”（该职位须已标为关键职位，见数据缺口）；继任者选“张清勇”（DEMO-0032）；岗位胜任度如有则忽略（首版延期，DEC-311②）。
  3. 保存。
- **讲解要点**：
  - SC-R1：职位继任的目标职位必须是管理单元内组织下的关键职位（关键职位 = 职位上的标记字段，G-054）；现任人员为主职，兼职来源首版为空（设计 §0 P2）。
  - 种子里没有任何关键职位标记，且 main 上的职位页面是否提供“关键职位”开关未核实，所以这一步是路线里最依赖补数据的一步：若目标职位下拉为空，现场改讲“规则与限制”，不要硬演。
  - 校验原则同步骤 2：时间不得晚于今天、目标和继任者建后不可改。
- **预期结果**：补好关键职位标记后，保存成功，列表新增一行类型“职位”、目标“平台研发部经理”、现任“平台研发部经理（演示）”、继任者“张清勇”；若无关键职位，下拉为空或保存被拒绝，属预期缺口。
- **高亮目标**：表单“继任类型”切换；“目标职位”下拉；列表中类型为“职位”的新行。

## 步骤 5：职位继任地图

- **演示身份**：HR专员（演示）
- **页面与路由**：/succession，职位继任地图（暂定）
- **操作**：
  1. 切到“职位继任地图”，观察以关键职位为节点的树，节点显示现任人员、继任者、风险等级颜色。
  2. 切换筛选“展示无继任者的职位”（暂定名）开 / 关，对比节点数量。
  3. 如数据允许，口头演示“中间职位停用”或“上级职位不在数据范围内”的断层规则。
- **讲解要点**：
  - SC-R8 / AC-SC-06：中间职位停用导致断层时，下级挂到断层的上级；因权限导致的断层则多根显示（DEC-453④），所以同一份数据不同身份看到的树不同。
  - “展示无继任者的职位”默认开（Q-M0-177）；开关为关时，自身与子树内都无继任者的子树被去掉。
  - 当前只能展示已标记的关键职位；职位继任地图没有“层数”参数，只按时间点（asOf）取数。
- **预期结果**：补好关键职位后，树上出现“平台研发部经理”节点：现任“平台研发部经理（演示）”，继任者“张清勇”，风险等级未计算时为默认颜色；无关键职位时地图为空态。
- **高亮目标**：地图中的“平台研发部经理”节点卡片（现任、继任者区域）；“展示无继任者的职位”开关（暂定）。

## 步骤 6：职位风险等级与组织健康度

- **演示身份**：HR专员（演示）
- **页面与路由**：/succession，职位继任地图 / 组织继任地图页内（暂定，按钮位置待 FE-R3d 确认）
- **操作**：
  1. 在职位继任地图点“计算职位风险等级”（暂定名，对应按钮 computeRisk），等待计算完成提示。
  2. 在组织继任地图点“计算健康度”（对应 computeHealth）、“计算统计”（暂定，对应 computeStats，生成绿化率 / 在岗人数）。
  3. 对某个组织或职位手动赋值等级（对应 assign），再对组织点“重置”看是否覆盖。
- **讲解要点**：
  - 风险与健康度都是异步计算：点按钮后只是创建计算任务（后端返回任务号），完成后消息通知；手动赋值的结果不会被后续重算覆盖（SC-R10、AC-SC-07）；组织健康度“重置”才会按规则重算并清掉手动标记（DEC-305④）。
  - 规则本身（条件行 + 表达式，规则统一用表达式引擎，DEC-211）属于继任管理员的规则配置，按规划 FE-R3d 只做展示，不做规则配置页面；种子里没有任何等级规则，所以计算结果的等级可能为空、只显示默认颜色。
  - 数据范围：计算对象 = 请求人范围 ∩ 地图显示；健康度则取权限范围内全部组织。
- **预期结果**：计算后弹出任务已提交 / 完成提示；没有等级规则时，节点上无等级名；手动赋值需先有可选等级（`/risk-levels/options` 为空则无法赋值）。
- **高亮目标**：地图工具栏上的“计算职位风险等级”“计算健康度”按钮；节点卡片上的等级颜色标记；赋值 / 重置入口（暂定）。

## 步骤 7：结束继任记录

- **演示身份**：HR专员（演示）
- **页面与路由**：/succession，继任列表（暂定）
- **操作**：
  1. 在继任列表勾选步骤 2 创建的“数据研发部 / 刘扬宇”记录，点“结束”（对应按钮 end）。
  2. 选择结束日期（不得晚于今天），可填原因，确认。
  3. 回到组织继任地图刷新，对比“数据研发部”卡片。
- **讲解要点**：
  - SC-R3：批量结束，把所选记录的结束时间设为所选日期（≤ 今天）并可填原因，结束后不再出现在最新地图上，但记录保留（时间轴），可通过历史视图 / 状态筛选查看；删除则是软删除，保留审计快照。
  - 员工离职时系统会自动结束其作为继任者的当前生效记录，结束日 = 离职生效日（SC-R4、AC-SC-02）；本演示租户无离职流程，只口述。
  - 盘点同步：盘点模板“继任信息”模块的提名可按覆盖 / 追加 / 范围内覆盖三种策略同步到继任地图（SC-R14）；上一条路线 11_人才盘点.md 中该链路暂未开放，只口述。
- **预期结果**：被结束的记录状态变“已结束”（暂定），默认列表（只看生效的）不再显示；组织继任地图上“数据研发部”卡片不再有继任者“刘扬宇”。
- **高亮目标**：列表勾选框与顶部“结束”按钮；结束日期选择弹窗；组织地图上“数据研发部”卡片的继任者区域。
