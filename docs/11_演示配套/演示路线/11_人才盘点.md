## 路线概览

这条路线给产品、业务和评审同事看“人才盘点”应用在复刻系统里做到哪一步：盘点项目、盘点模板、九宫格设置是接服务端真实接口的配置侧；项目详情里的八个页签、九宫格落位、校准会是演示桩（DEC-456②，PR-C / PR-D 暂停）。全程要反复讲清真假边界，避免把合成样例当真实结果。

## 前置准备

1. 启动与重置：`pnpm demo`（写入种子并同时起后端 :3000 与前端 http://localhost:5173），出问题用 `pnpm demo:reset`，细节见 README“本地演示”章节。
2. 授权：种子本身没有任何身份拥有盘点权限，由 系统管理员（演示）在 企业设置 → 用户授权给 HR专员（演示）授“盘点管理员（人才盘点）”，并按（用户 × 应用）设数据范围，完整配方见 06_企业设置.md 的授权配方。**本演示库已按该配方授好**：HR专员（演示）已持有“盘点管理员（人才盘点）”，TalentReview 的数据范围已设为管理单元“演示全部组织范围”（含研发中心 / 运营中心 / 职能中心三个一级组织及下级）。切到 HR专员（演示）后左侧“人才管理”分组即可见“人才盘点”。全新库（执行过 `pnpm demo:reset`）则需重新授权。
3. 数据范围类型提示：除“组织员工”外，人才类应用的数据范围只能选“管理单元”，选“组织范围”会被服务端拒绝（页面只显示“请检查表单字段”，看不到具体原因，见 06 的待核对）。
4. DEC-415（盘点管理员对“盘点项目 / 盘点模板”预置看全部）实测情况：HR专员（演示）的权限快照里，TalentReview 的数据范围摘要是“全部”，而同样设了管理单元的人才标准、继任管理是“限定 32 个组织”，说明预置看全部已在本租户生效；步骤 2 起列表与新增均正常。没有做“撤掉范围后是否仍可见”的反向验证（不得变更授权）。
5. 走查时已在库里留下编码 DEMO_REVIEW_2026 的盘点项目与一个盘点模板（见“待核对”末条）。再次完整演示时，若不想复用，请 `pnpm demo:reset` 后重新授权，或把步骤 2 的编码改成别的（如 DEMO_REVIEW_2026B）；同编码重复提交的提示文案未核对。
6. 建议打开顶部栏右侧“注释”开关，讲解时展示“原站做法 / 我们的取舍 / DEC / 实现档位”。

## 步骤 1：进入应用，认识四个页签

- **演示身份**：HR专员（演示）

- **讲解要点**：
  - 页签是否出现取决于服务端权限快照里是否有对应对象（项目 / 模板 / 九宫格），前端不硬编码角色；“盘点校准会”页签随盘点项目对象一并出现。
  - 真实接口：盘点项目、盘点模板、九宫格设置三块的列表、详情、保存和状态流转都走后端；演示桩：项目详情里的八个页签内容、九宫格落位、整个“盘点校准会”页签，都是前端合成样例，页面会标“演示数据”（顶部栏的“演示数据”标签是整个演示环境的标识，不是桩页面独有）。
  - 打开“注释”后有两张卡：应用级（DEC-456、DEC-045、DEC-056，L2）“原站做法：顶部切换应用，左侧菜单可收起；列表用图标与视图下拉，无独立面包屑，详情从右侧抽屉打开。我们的取舍：按第 1 批实测对齐颜色和尺寸，使用组件库绘制控件。菜单结构与租户资料为演示适配，权限读取现有接口。”；页面级 `talent-review-projects`（DEC-456、DEC-056，L2）：原站“盘点项目分进行中与已结束视图，内容页有四张看板与八个页签，无独立面包屑”；取舍“使用 FE-0 右侧详情抽屉；项目配置与状态接现有接口，场景和报告模板缺少字段时显示 --；关联名称接口待补，真实关联暂回显 ID；列表最多读取 4000 条，超限报错”。切到“盘点模板”“九宫格设置”页签，页面级卡片随之换成各自的注释；“盘点校准会”页签没有页面级注释卡。
- **预期结果**：页签条依次为 盘点项目 / 盘点模板 / 九宫格设置 / 盘点校准会，默认落在“盘点项目”，视图为“进行中的盘点项目”，列表空表显示“这里什么都没有…”“共0条”（走查时的初始状态；已走查过的库里会有 DEMO_REVIEW_2026 一行）；“盘点模板”同样为空表，“九宫格设置”有 2 行，“盘点校准会”有 1 行带“演示数据”提示。

## 步骤 2：新增盘点项目（真实接口）

- **演示身份**：HR专员（演示）
- **页面与路由**：/talent-review，“盘点项目”页签
- **操作**：
  1. 点列表右上“新增”（蓝色主按钮；旁边是“刷新”和灰置的“导出”），右侧抽屉标题“新增盘点项目”，分组“基本信息”，字段依次为：编码、名称、所属组织、盘点年度、盘点周期、开始时间、结束时间、所属分类、人才标准、盘点计算规则、业务日期、向下公开、引入上次结果、共享组织。
  2. 先不填直接点“保存”，七个必填项（编码、名称、所属组织、盘点年度、盘点周期、开始时间、结束时间）下方都出现红色“请填写此项”；编码故意填“1bad code”，提示“以字母开头，仅含字母、数字、下划线，最多50位”。
  3. 正式填：“编码”DEMO_REVIEW_2026、“名称”2026年度人才盘点（演示）、“所属组织”点开下拉可输入“研发中心”搜索后选中（候选是组织名称）、“盘点年度”2026、“盘点周期”2026年度。
  4. “开始时间”2026-10-01，“结束时间”先故意选 2026-09-01，点“保存”，抽屉顶部和“结束时间”字段下都出现“结束时间不能早于开始时间”；再改成 2026-12-31。
  5. 其余字段留空（“所属分类”“人才标准”“盘点计算规则”点开下拉都只有“这里什么都没有...”，因为种子没有这些数据）。点“保存”。
- **讲解要点**：
  - 必填项是编码、名称、所属组织、盘点年度、盘点周期、开始时间、结束时间；名称、盘点周期最多 50 字；编码规则如上。
  - 所属组织、所属分类、人才标准、盘点计算规则、共享组织是下拉引用，选项来自服务端；写请求带对象 revision 与命令 ID，结果未知时提示“结果未知，请关闭表单并刷新列表，按编码或名称回查后再决定是否重新提交”，体现平台“写命令幂等 / 禁止盲重试”约定（AGENTS §10）。
  - 所属分类、盘点计算规则、人才标准在种子里没有候选，留空不影响保存。
- **预期结果**：保存后抽屉直接关闭、列表自动刷新（没有单独的成功提示条）。“进行中的盘点项目”视图里出现“2026年度人才盘点（演示）”，状态“新建”，操作列“编辑”“启动”“结束”。列顺序为 名称 / 所属分类 / 盘点场景 / 所属组织 / 盘点报告模板 / 开始时间 / 结束时间 / 盘点年度 / 盘点计算规则 / 状态 / 结果审批流程 / 操作；“开始时间”2026-10-01、“结束时间”2026-12-31、“盘点年度”2026；**“所属组织”列实测显示的是组织 ID（一串 UUID），不是“研发中心”**，这是注释里写明的“关联名称接口待补”；所属分类、盘点场景、盘点报告模板、盘点计算规则、结果审批流程都显示“--”。
- **高亮目标**：列表右上“新增”按钮；抽屉里的“编码”“所属组织”“开始时间”“结束时间”字段及红色校验提示；列表新出现的一行及其“状态”列（所属组织回显 ID 的那一格，讲解时直接指出）。

## 步骤 3：启动、结束、重启与三种视图、筛选

- **演示身份**：HR专员（演示）
- **页面与路由**：/talent-review，“盘点项目”页签
- **操作**：
  1. 在新项目行“操作”列点“启动”，弹出确认气泡“确认执行此操作？”（“取消”“确定”），点“确定”→ 状态变“进行中”，操作变为“编辑”“结束”。
  2. 点列表左上视图标题“进行中的盘点项目 ▾”，下拉三项“进行中的盘点项目 / 已结束的盘点项目 / 全部盘点项目”。
  3. 点“结束”，确认气泡文案“结束评估后，盘点项目数据禁止修改。是否继续？”，点“确定”→ 项目离开进行中视图；切到“已结束的盘点项目”视图可见，状态“已结束”，操作只剩“重启”。
  4. 点“重启”，同样弹出“确认执行此操作？”，点“确定”→ 回到“进行中”。
  5. 筛选：点“名称 ▾”弹出“搜索名称”输入框（输入 2026 命中，输入不存在的字样则空表）；“所属组织 ▾”弹出下拉可按组织筛选；“开始时间 ▾”“结束时间 ▾”弹出起止区间；“盘点场景 ▾”灰置；“高级筛选”打开抽屉，字段为名称、所属组织、开始时间、结束时间、盘点年度，底部“清空”“取消”“确定”。
- **讲解要点**：
  - 状态机：新建 →（启动）→ 进行中 →（结束）→ 已结束 →（重启）→ 进行中；按钮由服务端返回的权限和项目状态共同决定，新建可“编辑 / 启动 / 结束”，进行中可“编辑 / 结束”，已结束只能“重启”。结束后数据禁止修改（原站口径）。三个状态按钮都带确认气泡，只是“结束”的文案专门提示不可修改。
  - 三种视图的列不同：“已结束的盘点项目”多出“共享组织”“参与人数”“应用场景”，不含“结果审批流程”；“进行中的盘点项目”与“全部盘点项目”则有“结果审批流程”，对应原站两个视图。
  - 列表是完整读取授权结果后在前端筛选和分页，最多 4000 条，超过会报错而不是展示不完整列表（注释里写明）。
  - 操作成功后同样没有成功提示条，靠列表状态变化体现。
- **预期结果**：每次操作后列表自动刷新，状态列依次为“进行中”→“已结束”→“进行中”；视图切换时列数变化。走查结束时该项目停在“进行中”。
- **高亮目标**：项目行“操作”列的“启动”“结束”“重启”链接；确认气泡；列表左上的视图切换标题；筛选区的“名称 ▾”“所属组织 ▾”与“高级筛选”链接。

## 步骤 4：项目详情：盘点配置（真实）与八个页签（演示桩）

- **演示身份**：HR专员（演示）
- **页面与路由**：/talent-review，“盘点项目”页签，点项目名称打开右侧详情抽屉
- **操作**：
  1. 点“2026年度人才盘点（演示）”名称，打开详情抽屉，头部按钮为“编辑项目”“结束”（项目为进行中时）。
  2. 展开摘要区折叠面板“盘点配置”（默认折叠），对照步骤 2 填的值；下面是四块摘要“进度监控（盘点信息采集进展）/ 盘点场景 / 人才标准 / 盘点维度”。
  3. 依次点八个页签：“盘点对象”“多人评价关系”“指标明细”“九宫格”“组织继任地图”“职位继任地图”“仪表盘”“结果审批流程”（默认停在“盘点对象”）。
  4. 回到“盘点对象”页签，指给观众看灰置的“添加盘点对象”“流程干预”“编辑盘点结果”“同步数据”按钮；到“九宫格”页签再指灰置的“加入人才池”“发起IDP”“导出”。
- **讲解要点**：
  - 分界线：“盘点配置”折叠面板（编码、所属组织、盘点年度、盘点周期、开始时间、结束时间、所属分类、盘点计算规则、人才标准、向下公开、共享组织）来自真实接口；摘要四块目前只有“进度监控”有提示文案“盘点信息采集进展”，其余三块显示“--”。
  - 八个页签每页顶部都有蓝色提示“演示数据”标签 + “独立合成样例，不代表当前项目的真实人员或结果。”，并说明“此区域暂供演示，计算、校准和审批操作尚未开放。”两个页签对任何项目显示的都是同一份样例：“盘点对象”表列为 姓名 / 任职资格 / 任职类别 / 任职级别 / 状态 / 当前步骤 / 当前步骤执行人 / 计算状态 / 计算消息 / 在线报告，只有一行“合成员工甲”（任职资格 / 类别 / 级别为“--”，状态“进行中”，当前步骤“上级评价”，执行人“合成负责人”，计算状态“未计算”，计算消息“暂未接入”，在线报告“--”）；“指标明细”列为 姓名 / 部门 / 模块 / 指标名称 / 权重 / 计算得分 / 最终得分 / 计算等级 / 最终等级，一行：合成员工甲、示例研发部、“模块”、执行落地能力、100%、4.4、4.4、“--”、“--”。
  - “多人评价关系”是空表（列 姓名 / 角色 / 当前步骤执行人，“这里什么都没有...”）；“九宫格”页签是 3×3 样例，每格“0人，0%”，格子名为“低 / 中 / 高胜任度”，旁边有“优秀占比高”“九宫格说明”和“配置预览不包含真实人员落位。”；“仪表盘”提示“仪表盘统计接口待接入，暂不将合成样例汇总为真实统计。”；“结果审批流程”显示“暂未接入”；两个继任地图页签提示“继任地图在 FE-R3d 页面片实现，此处仅保留原站页签结构。”
  - 注释 `talent-review-demo`（详情抽屉里页签条下方一张卡）：原站详情含盘点对象、多人评价关系、指标明细、九宫格、两种继任地图、仪表盘与结果审批流程，校准会独立列表；取舍：PR-C / PR-D 按 DEC-456② 暂停，用集中演示桩呈现独立合成样例、暂停计算 / 校准写入 / 审批及跨模块动作，地图交 FE-R3d，不把未验证 Canvas 内容当产品行为，DEC-456，L2。抽屉顶部另有页面级 `talent-review-projects` 卡。
