## 路线概览

这条路线给产品 / 客户讲“调动闭环”：HR 在调动管理里发起他人调动申请，表单自动带出调动前信息；申请进入审批中心，经理同意或驳回；经理自己给本部门员工发起的单会因自审回避跳过本人，落到异常管理员，异常管理员没有任职字段权限、不能直接审批，只能转交给 HR；HR 终审后“审批通过”与“生效”是两个状态。

| 步 | 身份 | 页面 | 一句话 |
|---|---|---|---|
| 1 | HR专员（演示） | 调动管理 /transfer | 视图切换、演示数据说明、注释层 |
| 2 | HR专员（演示） | 调动管理 → 他人调动申请 | 表单“原 / 新”成对展示，带出调动前信息与联动区块 |
| 3 | HR专员（演示） | 调动管理 → 我的申请 | 提交新单；看到被驳回（TRF-14）和已撤销（TRF-15）的种子单 |
| 4 | 平台研发部经理（演示） | 审批中心 → 待处理 | 看详情（原信息 / 申请信息 / 审批记录），同意 TRF-01 |
| 5 | 平台研发部经理（演示） | 审批中心 → 待处理 / 已处理 | 驳回新单；已处理页是演示数据 |
| 6 | 异常管理员（演示） | 审批中心 → 待处理 | TRF-04 只能转交，转交给 HR专员 |
| 7 | HR专员（演示） | 审批中心 → 待处理 | 终审 TRF-02：审批通过不等于生效 |

## 前置准备

- 启动：`pnpm demo`（写入种子并起后端 :3000 与前端 http://localhost:5173）；要回到干净数据用 `pnpm demo:reset`（先停掉 `pnpm demo`）。种子单据一旦被现场操作（转交、审批等）就视为用户接管，之后 `pnpm demo:seed` 不会复原，要复原只能 reset（DEC-477）。
- 身份切换：页面顶部栏里的“切换演示身份”下拉，选人后整页刷新并跳到该身份的推荐入口；入口不是本路线页面时，用顶部应用切换下拉进入“调动管理”或“审批中心”。顶部“注释”开关打开后，页面显示“原站做法 / 我们的取舍 / DEC / 实现档位”。
- 授权：本路线使用的三个身份都由种子授权，不需要现场授权。
- 转交目标：步骤 6 要填 HR专员（演示）的账号编号（UUID）。打开仓库根目录 `.demo/personas.json`（`pnpm demo` 生成，已被 git 忽略），找到 `name` 为“HR专员（演示）”那一项的 `userId` 复制备用，不要把它写进任何文档或提交。
- 对号入座：审批中心的标题一律是“调动申请”，不带人名（审批人只看本单字段，DEC-057）；同一身份有多张单时，用“接收 / 发起时间”区分（种子单 1～6 天前，现场新建的是今天）。

- **讲解要点**：提交即发起审批流“演示调动流程”：节点 1“直接上级审批”（被调动人所在部门负责人）→ 节点 2“调入部门HRBP审核”，两个节点都开启自审回避（见 README 演示数据规模）。“我的申请”列表接真实接口：除了刚提交的一条，还能看到种子里 HR 发起的两张：DEMO-TRF-14（孔悦美，经理已驳回，状态“已驳回”）和 DEMO-TRF-15（沈俊彤，HR 自己撤销，状态“已撤销”）。这里要点明 README 的第③处：普通员工在界面上没有“撤回”，所以种子里的撤回单由 HR 发起并撤回；发起人在详情的“操作”区才会看到“撤销”按钮，撤销会让本次审批停止（提示“是否可以修改后重新提交，以业务申请单为准”）。本步不要点“撤销”，后面要用这张单演示驳回。

- **页面与路由**：审批中心 `/approval`，页签“待处理”
- **操作**：切到异常管理员后，顶部应用切换进入“审批中心”；列表里有两条“调动申请”，节点都写“直接上级审批（异常管理员）”：2026/10/13 10:00 的是 DEMO-TRF-04（张清勇 → 基础架构组），2026/10/12 10:00 的是 DEMO-TRF-05（刘扬宇 → 算法组）；点较新的 TRF-04 的“去处理”；“申请信息”页签只写“当前节点没有可显示的申请字段。”，“审批记录”里有一行“直接上级审批 已跳过”和一行“待处理”；观察“操作”区只有“转交”；点“转交”，弹窗“转交”里“转交给（账号编号）”粘贴 HR专员（演示）的 `userId`，“审批意见”填“请 HR 办理”，点“保存”（保存未实点；弹窗字段与“取消”“保存”已核对，账号编号输入框的灰字提示是“填写接收人的账号编号，可联系管理员获取。”）。
- **讲解要点**：这是 README 的第①处：经理（平台研发部经理）给自己部门员工发起的单，直接上级审批节点的审批人恰是发起人，自审回避把本人跳过，任务落到流程配置的异常管理员；异常管理员没有任职记录字段的查看权限，看不到本单变化字段，属于盲审，不显示“同意 / 驳回”，直接审批会 403，只能转交（DEC-058 禁止盲审与自审；规格 docs/02_业务建模/14_审批流模型_实测.md）。第②处：审计管理员那张在途单 DEMO-TRF-03（本人入口，调往财务部）的第一节点落在生成的财务部负责人身上，不在九人切换清单里，保持在途展示即可，不能现场办理。转交输入的是账号编号而不是姓名，这是当前版本的取舍，可顺带说明。

## 步骤 7：HR 终审：审批通过不等于生效

- **演示身份**：HR专员（演示）
- **页面与路由**：审批中心 `/approval`，页签“待处理”
- **操作**：切到 HR专员（演示），进入“审批中心”；列表里种子只有一行 DEMO-TRF-02（罗雪慧 → 后端开发组，节点“调入部门HRBP审核”，2026/10/12 10:00）；做完步骤 4 和 6 后才会多出 TRF-01、TRF-04 两行；点 TRF-02 的“去处理”，“操作”区有“同意”“驳回”（没有“转交”），先看“审批记录”页签里“直接上级审批 审批通过”，“调入部门HRBP审核 待处理”，再点“同意”，意见留空直接“保存”（保存未实点）。随后点左侧“已申请”页签看自己发起的那几条（种子里是“已驳回”“已撤销”两行，已核对）。
- **讲解要点**：TRF-02 的生效日期种在 14 天后（演示库当天写入则为 2026-10-28，详情“申请信息”里可见），所以同意后详情顶部出现提示“审批已通过，业务是否生效以业务申请单为准。”，状态标签变为“审批通过”：审批通过与生效是两个状态，未来生效日由定时任务落地（演示进程 30 秒轮询，生效日到期才改任职记录；硬规则“审批通过 ≠ 生效”，规格 docs/02_业务建模/07_任职记录与调动_核心机制.md）。对照种子里已完成的 6 张（TRF-07～12）：它们提交时就用历史日期，所以审批通过当天即生效。收尾可再提一句 HR 看到的 TRF-01 / TRF-04 同样需要在这个节点办理，不在本路线继续走。
- **预期结果**：同意后弹窗关闭，TRF-02 离开“待处理”；重新打开可见状态“审批通过”及上述提示；“已申请”页签仍显示 HR 发起的单（TRF-14“已驳回”、TRF-15“已撤销”，以及步骤 5 被驳回的新单）。
- **高亮目标**：列表“节点”文字“调入部门HRBP审核”；“审批记录”页签；“同意”按钮；详情顶部蓝色提示“审批已通过，业务是否生效以业务申请单为准。”。
