## 路线概览

讲 360 评估管理端的三件事：套卷（含评价角色、评定等级、指标、题目）怎么建、怎么预览和启用；活动怎么新增，详情里有“基本信息 / 评价关系 / 套卷”三个页签；评价关系里评价对象和评价者怎么配。要说清边界：本页面片覆盖活动、套卷与评价关系，进程控制、作答与报告页面另行接入（后端已有对应接口）；列表按接口返回的至多 500 条分页，不捏造评价人数或进度。

## 前置准备

- 启动：`pnpm demo`；重来用 `pnpm demo:reset`（命令说明见 README“本地演示”章节）。顶部栏打开“注释”开关；本模块注释键为 `survey360`（DEC-464、DEC-456、DEC-280、DEC-149，L3）。
- 授权摘要（文案读自 apps/web/src/settings/GrantsPage.tsx、ScopeEditor.tsx）：由“系统管理员（演示）”进入“企业设置”，后台菜单“权限管理/用户授权”→“新增”→ 表单“新增用户授权”填“用户编号”（占位“输入本租户用户编号”，可在“用户管理/内部员工”点 HR专员姓名，详情里有“用户编号”）、“身份”选“360系统管理员 (standard_360_system_admin)”→ 保存；再点该行“操作”列“数据范围”，抽屉里填“用户编号”、“应用编码”填 Survey360，点“查询数据范围”→“编辑”，数据范围选“组织范围”（组织选“研发中心”并勾“包含下级”）后保存。360 身份由企业管理员在“用户授权”里授予，不消耗许可，数据范围不预置，默认为空（fail-closed，DEC-043、DEC-280）。授权配方的完整操作详见 06_企业设置.md 的授权配方。
- 360 身份编码与名称（packages/domain/src/survey360/catalog.ts）：360系统管理员（standard_360_system_admin，可以查看、编辑所有评估活动，不受数据权限控制）；360高级管理员（standard_360_advanced_admin，只能查看自己创建的和被授权的评估活动，不能编辑非本人创建的套卷）；360一般管理员（standard_360_general_admin，同高级管理员，看不到“从系统管理中同步人员信息”）。
- 授权后“切换演示身份”选“HR专员（演示）”，从顶部应用切换进入“人才管理”分组下的“360 评估”。

## 步骤 1：授权 360 系统管理员

- **演示身份**：系统管理员（演示）
- **页面与路由**：企业设置 `/settings`，后台菜单“权限管理/用户授权”（`/settings/menu/permission.user_grant`）
- **操作**：按“前置准备”的授权摘要给 HR专员（演示）新增“360系统管理员”，再对 Survey360 设组织范围。
- **讲解要点**：360 身份走平台通用的“身份 × 应用”（应用 Survey360）；三类内置身份的差别靠按钮承载：“全部活动”（系统管理员看全部活动，不受精细化权限限制）、“编辑他人套卷”、“从系统管理中同步人员信息”（DEC-280①②）。数据范围在 360 里用于裁剪人员库中可见的人，活动可见性由“持有全部活动按钮”或“创建人 / 被授权”决定。
- **预期结果**：用户授权列表出现 HR专员（演示）的“360系统管理员”行；切换到 HR专员后，“人才管理”下出现“360 评估”。
- **高亮目标**：用户授权页右上“新增”；新增表单“身份”下拉；授权行末尾“数据范围”按钮。

## 步骤 2：评估活动页签与状态筛选

- **演示身份**：HR专员（演示）
- **页面与路由**：360 评估 `/survey360`，顶部三个页签“评估活动 / 套卷 / 题库 · 企业自定义”
- **操作**：点“360 评估”；看页签条；在“评估活动”下看状态页签“全部 / 草稿 / 已启用 / 已停用”并逐个点；看列表下方灰字；再点“套卷”页签，看状态页签“全部 / 草稿 / 已启用 / 已使用”。
- **讲解要点**：原站活动以全部、草稿、已启用、已停用页签区分，详情含基本信息、套卷、评价关系，题库以企业自定义套卷模板列表呈现；我们的取舍：活动、套卷、模板、评价关系接现有接口，操作与字段由权限驱动，列表按接口返回至多 500 条分页，“筛选与分页仅作用于本次返回结果”，不捏造评价人数或进度（注释层 survey360）。三个页签是否出现取决于活动和套卷对象的查看权。“题库 · 企业自定义”页签按设计是企业自定义套卷模板列表，但读代码发现前端请求的路径与后端登记的路径疑似不一致（见“待核对”），走查前不要把它当作确定可用的页面。
- **预期结果**：活动列表表头“名称 / 应用场景 / 评价形式 / 状态 / 启用时间 / 停用时间 / 操作”，初始为空态“这里什么都没有…”；右上有“刷新”和“新增活动”，以及灰掉的“导出”；列表下方灰字“接口最多返回 500 条；筛选与分页仅作用于本次返回结果。”；套卷列表表头“名称 / 套卷类别 / 状态 / 操作”，右上“新建套卷”。
- **高亮目标**：顶部三个页签；列表上方“全部 / 草稿 / 已启用 / 已停用”状态页签；右上“新增活动”按钮；列表下方“接口最多返回 500 条…”灰字。

## 步骤 3：新建套卷

- **演示身份**：HR专员（演示）
- **页面与路由**：360 评估 `/survey360`，页签“套卷”，右侧抽屉“新建套卷”
- **操作**：点“套卷”页签右上“新建套卷”；名称填“领导力 360 套卷”；“套卷类别”选“关键行为”（可选“关键行为 / 等级评定”）；“总分规则”选“加权平均”（可选“加权平均 / 加权求和”）；“指导语”填一句说明；点“保存”。
- **讲解要点**：套卷是一组带评价角色、评定等级、指标、题目的问卷；创建时只填头部信息，内容在保存后通过“编辑”整卷提交（代码里新建时没有内容编辑区）。套卷状态为草稿、已启用、已使用，已使用的套卷只能改文字与权重（页面提示“已使用套卷只能修改文字与权重；启用活动引用时由服务端拒绝修改”）。创建命令未确认结果时降为 L2：重开仅可查看，不恢复在途表单（DEC-464）。
- **预期结果**：保存后抽屉关闭，列表出现“领导力 360 套卷 / 关键行为 / 草稿”。
- **高亮目标**：“新建套卷”抽屉里的“套卷类别”“总分规则”下拉；抽屉底部“保存”；列表中新增行的“草稿”状态。

## 步骤 4：套卷内容、预览与启用

- **演示身份**：HR专员（演示）
- **页面与路由**：360 评估 `/survey360`，套卷详情抽屉（页签“基本信息 / 预览”）
- **操作**：点套卷名称打开详情抽屉；点右上“编辑”，在“题目与计分”里依次点各分组下的“添加”：“评价角色”选“上级”“同事”“自评”并各填权重；“评定等级”加一个等级“五分制”，其下选项依次填“选项文字”和“分值”（可勾“不计分”“必填说明”）；“指标”加“战略思维”并选“评定等级”；“题目”加“能清晰说明团队方向”，“所属指标”选“战略思维”，“评定等级”选“五分制”；保存；切到“预览”页签；再点右上“启用”，在确认框“确认操作”点确定。
- **讲解要点**：内容按稳定编码引用（指标引用上级指标、题目引用所属指标与评定等级），整卷一次写入，缺失引用不会被当作空值清掉，数据不完整时页面提示“套卷引用或字段不完整，无法安全编辑”。启用会校验套卷；一旦被启用的活动引用就成为“已使用”，之后只能改文字与权重。预览按权限显示指导语和角色、指标、题目、评定等级表格。评价角色来自租户评价角色（内置：自评、上级、同事、下级、客户、其他，首次读取时自动补齐）。
- **预期结果**：保存后“预览”页签展示指导语和四张表（角色、指标、题目、评定等级，评定等级行可展开看选项与分值）；确认启用后状态变为“已启用”，“启用”按钮消失。
- **高亮目标**：详情抽屉右上“编辑 / 启用”按钮；编辑表单里“评价角色”“评定等级”“指标”“题目”四个分组各自的“添加”；“预览”页签；“确认操作”对话框。

## 步骤 5：新增活动

- **演示身份**：HR专员（演示）
- **页面与路由**：360 评估 `/survey360`，页签“评估活动”，弹窗“新增活动”
- **操作**：点“新增活动”；“基本信息”分组填名称“2026 年度领导力 360”、应用场景“年度领导力盘点”、评价形式选“一次评价一人”（可选“一次评价一人 / 一次评价多人”）；“评价者作答页面设置”分组填欢迎语，“作答页评价者姓名”选“显示”，“评价角色是否显示”选“显示评价角色名称”（另有“显示角色预设文本”“不显示评价角色”）；点“保存”。
- **讲解要点**：活动头部信息分基本信息和评价者作答页面设置；评价形式在活动离开草稿后不再可改（代码里非草稿时该字段只读）；作答页的匿名与角色展示策略（评价者姓名是否显示、评价角色是否显示）由租户在活动层配置，对应原站作答页设置。新建同样受命令保护，未确认结果时只读（DEC-464）。
- **预期结果**：保存后列表出现该活动，状态为“草稿”，应用场景与评价形式显示中文（如“一次评价一人”），启用 / 停用时间显示 “—”。
- **高亮目标**：“新增活动”弹窗的两个分组标题；“评价形式”下拉；“评价角色是否显示”下拉；列表新行的“草稿”状态。

## 步骤 6：活动详情：基本信息与套卷页签

- **演示身份**：HR专员（演示）
- **页面与路由**：360 评估 `/survey360`，活动详情抽屉，页签“基本信息 / 评价关系 / 套卷”
- **操作**：点活动名称；在“基本信息”看字段；点“套卷”页签，读顶部说明并看嵌套的套卷列表；点右上“编辑”看弹窗，再取消。
- **讲解要点**：详情复用统一的右侧抽屉。活动本身不直接挂套卷：套卷通过评价对象关联到活动，页签顶部说明原文为“可选套卷库：套卷通过评价对象关联到活动，请在评价关系中为人员选取套卷”，这里的套卷列表是可选库，不是已关联清单。“编辑”按权限出现。
- **预期结果**：“基本信息”两列显示名称、应用场景、评价形式、欢迎语、作答页评价者姓名（显示 / 不显示）、评价角色是否显示（如“显示评价角色名称”）；“套卷”页签显示套卷列表，其中有步骤 3～4 建的“领导力 360 套卷（已启用）”。
- **高亮目标**：详情抽屉的三个页签；“套卷”页签顶部说明文字；右上“编辑”按钮。

## 步骤 7：评价关系：评价对象与评价者

- **演示身份**：HR专员（演示）
- **页面与路由**：360 评估 `/survey360` → 活动详情 → 页签“评价关系”，二级抽屉“设置评价者”
- **操作**：点“评价关系”页签，读灰字说明；点“添加评价对象”，在弹窗里“选择人员”下拉点开看候选，“选取套卷”下拉选“领导力 360 套卷”；（有人员数据时）保存后在列表行点“设置评价者”，在抽屉里点“添加评价者”，选人员并选“评价角色”。
- **讲解要点**：评价关系 = 评价对象（谁被评）+ 评价者（谁来评、什么角色）。每个评价对象须选 1～3 个不重复的已启用套卷，否则提示“每个评价对象请选择 1～3 个不重复的已启用套卷”；设置评价者抽屉提示“建议各评价角色至少3人（上级和自评除外），以增加匿名性和准确性”。人员来自独立的 360 人员库，服务端按当前范围裁剪，这是 360 人员与组织员工分库、通过同步挂接的设计（规格 25，DEC-030 同步规则）；本页面片不带“从系统管理中同步人员信息”入口。
- **预期结果**：列表表头“评价对象 / 套卷 / 操作”，初始为空；“选择人员”下拉在没有 360 人员时为空，无法继续（数据缺口）；补人员后列表出现评价对象行，“套卷”列显示接口 ID（页面未补名称）。
- **高亮目标**：“评价关系”页签里的灰字“人员来自独立的 360 人员库…”；“添加评价对象”按钮及弹窗的“选取套卷”；“设置评价者”抽屉里的匿名性提示和“添加评价者”按钮。

## 步骤 8：启用与停用活动

- **演示身份**：HR专员（演示）
- **页面与路由**：360 评估 `/survey360` → 活动详情抽屉右上按钮
- **操作**：在草稿活动的详情里点“启用”，在“确认操作”对话框读正文后确定；观察结果；（补数据成功启用后）再点“停用”。
- **讲解要点**：启用会校验套卷与评价关系，所以没有评价关系的草稿活动启用应被服务端拒绝并给出原因；停用会触发计分，对话框正文原文为“启用会校验套卷与评价关系；停用会触发计分。将按当前版本提交。”启用后生成作答链接等后续（进程控制、作答、报告）不在本页面片里。所有写操作带对象版本号，版本不一致返回 409，需刷新后显式重提，不自动盲重试（平台通用约定）。
- **预期结果**：没有评价关系时，顶部出现红色失败提示（具体文案以后端为准），活动状态保持“草稿”；校验通过时状态变为“已启用”，列表“启用时间”有值，按钮变为“停用”；停用后状态为“已停用”，“停用时间”有值。
- **高亮目标**：详情抽屉右上“启用 / 停用”按钮；“确认操作”对话框正文；列表中状态与“启用时间”列。

## 待核对

- “题库 · 企业自定义”页签：前端按种类拼出的请求路径是 `/api/tenant/survey360/templates`，而后端登记的模板路径是 `/questionnaire-templates`（apps/api/src/modules/survey360/policy.ts），读代码判断该页签的列表、详情与新增都会请求到不存在的路径，预计显示加载失败；需走查确认，若属实，这是前端缺陷，应反馈总编排安排修复；路线里该页签暂不作为演示步骤。
- 步骤 4 的编辑表单是否在新建后立即可见“题目与计分”区，取决于详情接口是否返回角色、等级、指标、题目四个数组，读代码推断为是。
- 步骤 7：评价角色、人员选择的候选接口可见性依赖 Survey360 数据范围；360 人员库是否有别处的同步入口（后端有“从系统管理中同步人员信息”的接口）待核对。
- 步骤 8：没有评价关系时启用的具体错误文案与是否真被拒绝，需走查确认（启用校验在后端 checkEnable，本路线按注释层“启用会校验套卷与评价关系”推断）。
- 授权摘要中 Survey360 组织范围对 360 人员库的实际裁剪效果（按挂接员工的当前任职组织）为读代码推断。
