## 路线概览

合同协议是“组织员工”下的独立菜单入口（DEC-482），不新增后端应用，也不新增数据范围份额。这条路线给产品和客户看三件事：六个卡片视图的信息架构与原站一致；哪些读的是真实只读接口（视图列表、合同详情的合同信息、合同类型 / 续签规则 / 设置），哪些是页面标“演示数据”的合成样例（高级筛选、排序、导出、任职信息、版本链、类型样例）；所有写操作（新建、变更、续签、终止、保存）本阶段都是灰掉的“即将上线”，等第二段。

## 前置准备

- 启动：`pnpm demo`（写入种子并同时起后端 :3000 与前端 http://localhost:5173）；需要重来用 `pnpm demo:reset`，只补种子用 `pnpm demo:seed`（命令说明见 README“本地演示”章节）。
- 顶部栏打开“注释”开关；本模块的注释键是 `contracts`（页面顶部工具条下方出现“原站做法 / 我们的取舍”与 DEC-456、DEC-476、DEC-482、L2）。
- 用右上角“切换演示身份”选“系统管理员（演示）”。该身份是标准版系统管理员（组织员工）加租户管理员，带 TenantBase 全部数据范围，菜单里有“合同协议”，且能看到合同的配置类入口（自动续签规则、合同管理设置）；不需要额外授权。
- 没有现成合同数据；第 4、6 步要展示记录与规则明细，需要先补种子（见“数据缺口”）。

## 步骤 1：进入合同协议，说清读写边界

- **演示身份**：系统管理员（演示）
- **页面与路由**：左侧菜单“组织员工”分组 → “合同协议”，路由 `/contracts`（应用 staff 下的独立入口，登记 id = contracts）
- **操作**：点左侧“合同协议”；打开顶部“注释”开关；指给观众看页面顶部的工具条（“合同协议”“合同类型”“自动续签规则”“合同管理设置”四个链接）和标题右侧灰掉的“新建 · 即将上线”按钮；把鼠标停在该按钮上看提示“即将上线”。
- **讲解要点**：原站做法是六个卡片视图、横向滚动表格、整页详情与右侧高级筛选，设置单独展示；我们的取舍是只读接口直连，缺失的筛选、排序、任职和版本链用独立演示数据，关联对象暂显示接口 ID，写操作待第二段（注释层，DEC-456、DEC-476、DEC-482，L2）。强调两条线：真实的是服务端按数据范围和字段权限裁剪后的只读列表；演示桩的页面一律带“演示数据”标签，不是真实业务数据。
- **预期结果**：打开默认进入“即将到期”视图；标题“合同协议”；“新建 · 即将上线”为灰色不可点；工具条里四个链接齐全（系统管理员有合同类型、自动续签规则、合同管理设置的权限）；注释卡片显示上述原站做法与取舍。
- **高亮目标**：左侧菜单“合同协议”项；页面顶部工具条的四个链接；标题右侧灰色的“新建 · 即将上线”按钮；注释卡片。

## 步骤 2：六个卡片视图与真实空态

- **演示身份**：系统管理员（演示）
- **页面与路由**：合同协议 `/contracts`，视图由查询参数 `view` 决定（如 `/contracts?view=valid`）
- **操作**：依次点标题下方的六张卡片：“即将到期”“入职缺失”“过期未续签”“审批中合同协议”“有效合同协议”“全部合同协议”。在“即将到期”里把“合同到期天数”输入框从 30 改成 90；观察各视图顶部蓝色提示条的文字；翻页区点“下一页”看是否可用。
- **讲解要点**：六个视图对应原站的六个卡片，卡片上的数字目前都显示 “--”（页脚写“总数暂未提供”），因为现有列表接口不返回各视图总数，我们不编造数字。各视图口径提示来自规格：即将到期读现有接口，“已续签排除口径待后端补齐”；入职缺失当前按“无有效合同”查询，“按所选合同类型检查缺失人员仅支持演示预览”；过期未续签按租户合同续签类型设置判定，连续后续合同视为已续签；全部合同协议里“合同记录与未生效申请分别展示，审批通过不代表生效”，这对应硬规则“审批通过不等于生效”，状态值也分开：审批中、已批准未生效、生效、已驳回。每页 15 条，翻页读服务端，“原站翻页行为未验证”。
- **预期结果**：除“入职缺失”外，其余视图表格显示“这里什么都没有...”（种子没有合同）；“即将到期”改天数后重新请求仍为空。“入职缺失”读真实接口，应列出没有有效合同的在职员工（种子 200 名，每页 15 条，“下一页”可点）；但表格列按合同对象的可见字段过滤，姓名、工号、邮箱等不属于合同对象的列可能被过滤掉，只剩末尾“合同详情”列的 “--”，这是读代码的推断，需走查确认。每个视图下方都有“上一页 / 页码 / 下一页”。
- **高亮目标**：标题下方六张视图卡片（含 “--” 数字）；列表上方蓝色提示条；“合同到期天数”输入框；表格空态文字；页脚“总数暂未提供”和翻页按钮。

## 步骤 3：高级筛选、演示筛选 / 排序与导出

- **演示身份**：系统管理员（演示）
- **页面与路由**：合同协议 `/contracts`（任一视图，建议“即将到期”），右侧抽屉“高级筛选”
- **操作**：点筛选行里的“高级筛选”链接，打开右侧抽屉；抽屉顶部看蓝色提示；在“合同类型”下拉里选“劳动合同”；点“确定”；回到列表后点任一列表头排序；点“导出演示数据”；再点“返回接口数据”；最后再试一次“演示筛选 / 排序”按钮和“清空已选”。
- **讲解要点**：原站的高级筛选在右侧抽屉，我们保留了交互，但后端现有接口不支持这些筛选与排序，所以点“确定”后页面切换到独立合成样例，并显示蓝色“演示数据”标签和说明“独立合成样例预览，不代表真实合同或原站的筛选、排序规则”。表头排序、CSV 导出同样只作用于合成样例。合成样例来自演示桩（DEC-456 演示层），不写入服务端。这里要讲清：演示模式下表格显示全部列，真实模式下列受字段权限约束。
- **预期结果**：抽屉标题“高级筛选”，内含“未命名”分组、合同到期天数、姓名、工作地点、法人公司、部门、合同类型、期限类型、开始时间、截止时间；选“劳动合同”确定后，列表出现 1 行：合成甲，合同编号 DEMO-CT-A，合同类型劳动合同，法人公司“合成科技公司”，期限类型固定期限，生效日期 2026-01-01，终止日期 2027-06-30，签订次数 2；“演示筛选 / 排序”按钮变成“返回接口数据”，“导出演示数据”可点并下载 demo-contracts.csv；不选类型直接确定则有两行（另一行合成乙，合同类型实习协议）。点“返回接口数据”回到真实空态。演示模式下翻页按钮灰掉，合同详情列只显示 “--”。
- **高亮目标**：筛选行里的“高级筛选”链接；右侧抽屉顶部“演示数据”蓝色提示和“确定”按钮；列表上方“演示数据”标签；“导出演示数据”和“返回接口数据”按钮；合成甲所在行。

## 步骤 4：合同详情（合同信息读真实接口，任职与版本链是独立样例）

- **演示身份**：系统管理员（演示）
- **页面与路由**：合同详情 `/contracts/records/:id?view=<视图>`，从“有效合同协议”或“全部合同协议”的列表行进入（登记在合同协议入口下的子路径 `records/:id`）
- **操作**：（需先补种子，见“数据缺口”）在“有效合同协议”里点某行末尾的“查看合同”；看“合同信息”卡片；再看下一张卡片顶部蓝色提示，往下读“任职信息”和“版本链（独立样例）”；点标题右侧“返回列表”。
- **讲解要点**：整页详情对应原站的合同详情页。上半张“合同信息”读 `GET /api/tenant/contracts/records/:id`，字段按当前身份的字段权限裁剪，人员、公司、合同类型等关联字段暂显示接口 ID（注释层“关联对象暂显示接口 ID”）；下半张“任职信息”（入职日期 2025-01-01，机构合成示例机构，部门合成研发部，职务合成工程师，直线经理合成经理甲，虚线经理合成经理乙）和“版本链（独立样例）”（2025-01-01 新建合成合同（版本 1）；2026-01-01 变更合成合同（版本 2））是演示桩，页面明确提示“任职信息与版本链尚未接入；以下独立样例与当前合同无关联”。版本链的真实形态是每次业务一条新记录，与任职记录的版本链思路一致，规格见 32 号文档。“编辑 / 变更 / 续签 / 终止”四个按钮灰掉并标“即将上线”。“审批中”的申请行和“入职缺失”行没有“查看合同”入口（页面里显示 “--”）。
- **预期结果**：标题“合同详情”；“合同信息”卡片按两列显示人员、编号、公司、合同类型、期限类型、签订日期、生效日期、终止日期、实际终止时间、签订次数、原合同 ID、版本号、状态、审批状态（有权限的字段才出现，空值显示 “--”）；第二张卡片带“演示数据”标签；四个操作按钮为灰色。
- **高亮目标**：列表行末尾“查看合同”；详情页“合同信息”卡片；第二张卡片顶部“演示数据”提示与“版本链（独立样例）”列表；右上角灰色的“编辑 · 即将上线”等四个按钮；“返回列表”按钮。

## 步骤 5：合同类型（真实接口为空，独立样例展示）

- **演示身份**：系统管理员（演示）
- **页面与路由**：合同类型 `/contracts/types`（顶部工具条“合同类型”链接）
- **操作**：点工具条“合同类型”；看表头与说明文字；点“查看独立样例”；再点“返回接口数据”；翻页区试“下一页”。
- **讲解要点**：合同类型是租户主数据，真实接口 `GET /api/tenant/contracts/master-data/types` 按数据范围读取；种子里没有类型，所以默认空表。“显示顺序尚未接入”，演示顺序只在独立样例中展示（页面说明文字）。独立样例的三条是合成数据，不代表原站默认类型。“新建 · 即将上线”灰掉，主数据维护等第二段。
- **预期结果**：标题“合同类型”；表头为“合同类型编码 / 合同类型名称 / 状态 / 显示顺序”；默认“这里什么都没有...”；点“查看独立样例”后出现“演示数据”标签和三行：DEMO-LABOR 劳动合同 启用 1，DEMO-INTERN 实习协议 启用 2，DEMO-OTHER 其他 停用 3；翻页按钮在样例模式下灰掉。
- **高亮目标**：标题行右侧“新建 · 即将上线”；“查看独立样例 / 返回接口数据”切换按钮；“演示数据”标签；样例表三行。

## 步骤 6：自动续签规则（开关只读，规则明细在抽屉里）

- **演示身份**：系统管理员（演示）
- **页面与路由**：自动续签规则 `/contracts/rules`（顶部工具条“自动续签规则”链接）
- **操作**：点工具条“自动续签规则”；看“合同到期自动续签”开关与说明；（补种子后）在规则表某行点“规则信息”，在右侧抽屉里看“流程发起规则”并尝试“保存 · 即将上线”。
- **讲解要点**：规则表列为“优先级 / 规则名称 / 适用组织范围 / 人员范围 / 续签规则明细”，明细按“合同类型 · 到期前天数 · 续签期限（月）”汇总。开关读合同管理设置的 autoRenew，只读（灰掉），说明写“开启后根据配置自动发起合同续签流程；本页只读，自动执行行为未验证”，我们不声称已实现原站的自动执行。规则的业务含义是：到期前按天数、按合同类型发起续签流程，规则按“优先级”排序，适用范围分组织范围和人员范围。这个页面要求配置类对象权限，只有租户管理员 / 合同配置管理员可见。
- **预期结果**：标题“自动续签规则”；开关区域标题“合同到期自动续签”，开关为只读状态；表格默认“这里什么都没有...”（种子没有规则）；有规则后点“规则信息”，抽屉标题“规则信息”，含名称、优先级、适用组织范围、人员范围、状态，下方“流程发起规则”逐条显示合同类型、到期前天数、续签期限（月）、发起人、后续不存在的合同类型；抽屉底部“保存 · 即将上线”为灰色。
- **高亮目标**：“合同到期自动续签”标题与灰掉的开关；规则表末列“规则信息”按钮；抽屉里“流程发起规则”区块；抽屉里灰色的“保存 · 即将上线”。

## 步骤 7：合同管理设置（只读设置项与过期未续签口径）

- **演示身份**：系统管理员（演示）
- **页面与路由**：合同管理设置 `/contracts/settings`（顶部工具条“合同管理设置”链接）
- **操作**：点工具条“合同管理设置”；读蓝色提示；逐项看设置字段；回到“合同协议”点“过期未续签”卡片，对照提示条。
- **讲解要点**：设置页展示租户级合同设置：到期后自动终止、离职 / 退休后可继续签订类型、第 3 次签订默认为无固定期限的类型、离职重聘累计签订次数、续签类型设置、自动编号、唯一键。提示“续签类型仅用于过期未续签判定；后续合同开始日期与原终止日期连续时视为已续签”，与“过期未续签”视图口径是同一套。页面只读，“保存 · 即将上线”灰掉。字段值来自 `GET /api/tenant/contracts/settings`，按字段权限裁剪。
- **预期结果**：标题“合同管理设置”；蓝色提示条；字段为两列描述列表，布尔显示“是 / 否”，类型列表显示接口 ID 用“、”连接，空值 “--”；右上角灰色“保存 · 即将上线”。
- **高亮目标**：蓝色提示条；设置字段列表（“续签类型设置”“到期后自动终止”两项）；灰色的“保存 · 即将上线”。

## 步骤 8：换成 HR专员（演示），看权限差异

- **演示身份**：HR专员（演示）
- **页面与路由**：合同协议 `/contracts`；再手动访问 `/contracts/rules`
- **操作**：用“切换演示身份”选“HR专员（演示）”，整页刷新后点左侧“组织员工”下的“合同协议”；看工具条；再在地址栏改成 `/contracts/rules` 回车。
- **讲解要点**：同一页面不同身份：HR专员持有人事管理员（组织员工）身份，能看合同与合同类型，但自动续签规则、合同管理设置属于配置类对象，由租户管理员 / 合同配置管理员持有，HR专员没有。菜单可见性来自服务端权限快照，前端不硬编码角色；数据范围默认为空（fail-closed，DEC-043），HR专员的范围是“全部一级组织含下级”，所以入职缺失仍能看到数据，而没有范围的身份会看到“当前没有可查看的数据范围”。
- **预期结果**：工具条只有“合同协议”“合同类型”两个链接（推断）；访问 `/contracts/rules` 显示“暂无访问权限”；视图与演示筛选行为与系统管理员一致。
- **高亮目标**：工具条中缺少的“自动续签规则”“合同管理设置”位置；地址栏改后页面中央的“暂无访问权限”提示。
