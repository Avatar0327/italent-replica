## 路线概览

讲“人才评定”活动设置的完整配置体验：活动信息、参评条件、活动环节三步向导，发布与取消发布，参评名单，以及后续环节的阶段示意。要特别说明：评定的后续环节（提名、申报、材料、答辩、校准、结果发布）按 DEC-456 暂停，页面“评定过程”页签是标有“演示数据”的合成示意，不是真实业务数据，也不写入评定状态。适合给 HR 业务方和产品看配置能力与取舍。

## 前置准备

- 启动：`pnpm demo`；重来用 `pnpm demo:reset`（命令说明见 README“本地演示”章节）。顶部栏打开“注释”开关；本模块的注释键是 `evaluation`（L3）与 `evaluation-paused`（L2）。
- 授权摘要（文案读自 apps/web/src/settings/GrantsPage.tsx、ScopeEditor.tsx）：由“系统管理员（演示）”进入“企业设置”，后台菜单“权限管理/用户授权”→“新增”→ 表单“新增用户授权”填“用户编号”（占位“输入本租户用户编号”，可在“用户管理/内部员工”点 HR专员姓名，详情里有“用户编号”）、“身份”选“评定管理员（人才评定） (standard_evaluation_admin)”→ 保存。再点该行“操作”列的“数据范围”，在抽屉里填“用户编号”和“应用编码”（TEvaluation；因为评定管理员同时带任职资格只读对象，类别与级别下拉需要再对 Qualification 设一份），点“查询数据范围”→“编辑”，数据范围选“组织范围”或“管理单元”并保存。数据范围默认为空（fail-closed，DEC-043），页面提示原文：“数据范围按‘用户 × 应用’共享；默认管理单元为空范围，撤销身份不会删除共享范围。”授权配方的完整操作详见 06_企业设置.md 的授权配方。
- 补种子的数据：至少 1 个活动类型、1 个周期、1 个任职类别和 1 个任职级别（见“数据缺口”）。评审成员（负责人候选）来自查看人人员范围内的员工，种子已有。
- 授权后切换到“HR专员（演示）”，从顶部应用切换进入“人才管理”分组下的“人才评定”。

## 步骤 1：授权评定管理员

- **演示身份**：系统管理员（演示）
- **页面与路由**：企业设置 `/settings`，后台菜单“权限管理/用户授权”（`/settings/menu/permission.user_grant`）
- **操作**：按“前置准备”的授权摘要，给 HR专员（演示）新增“评定管理员（人才评定）”，再点“数据范围”设 TEvaluation（和 Qualification）的范围。
- **讲解要点**：人才评定是独立应用 TEvaluation，身份与数据范围各自独立；评定管理员拥有人才评定的全部信息，含活动设置与基础设置，可见数据按数据范围控制。评定专员身份只带流程对象（评定过程、评定记录），不含活动设置。数据范围按（用户 × 应用）存一份，撤销身份不会删除范围（硬规则、DEC-043）。
- **预期结果**：用户授权列表出现 HR专员（演示）的“评定管理员（人才评定）”行，状态启用；该用户的范围查询返回已设的范围。
- **高亮目标**：用户授权页右上“新增”；新增表单“身份”下拉；授权行末尾“数据范围”按钮。

## 步骤 2：活动设置列表

- **演示身份**：HR专员（演示）
- **页面与路由**：人才评定 `/evaluation`（菜单“人才管理”分组下的“人才评定”，页面标题“活动设置”）
- **操作**：点“人才评定”；看列表表头；点状态下拉（选项“全部 / 草稿 / 进行中 / 已完成”）逐项切换；把鼠标停在“导出”上；点“刷新”。
- **讲解要点**：原站活动设置以名称、年度、周期、状态、所属组织、报名人数、负责人列表呈现；我们复用统一视图标题、原站主题与右侧详情抽屉（注释层 evaluation：DEC-464、DEC-456、DEC-045、DEC-056，L3）。引用名称（周期、所属组织）未返回时只显示标识，不补造名称。“新建评定活动”按钮是否出现由服务端按钮权限决定，不是前端写死角色。
- **预期结果**：表头为“名称 / 年度 / 周期 / 状态 / 所属组织 / 报名人数 / 负责人 / 操作”，初始为空态“这里什么都没有…”（若范围为空则为“当前没有可查看的数据范围”）；右上有“刷新”“新建评定活动”和灰掉的“导出”（提示“导出功能准备中”）。
- **高亮目标**：列表标题“活动设置”；状态下拉；右上“刷新”和“新建评定活动”按钮；灰掉的“导出”。

## 步骤 3：新建评定活动 · 活动信息

- **演示身份**：HR专员（演示）
- **页面与路由**：人才评定 `/evaluation`，右侧大抽屉“新建评定活动”，顶部三步条第一步“活动信息”
- **操作**：点“新建评定活动”；看顶部三步条“活动信息 / 参评条件 / 活动环节”；依次填：名称“2026 年度专业序列职级评定”；活动类型、周期选补种子的数据；所属组织选“人力资源部”；年度 2026；负责人选一位员工；开始日期 2026-11-01、结束日期 2026-12-31；评定生效日期 2027-01-01；申请人勾“员工本人”和“非员工本人”；“组织范围”选“研发中心”（下面会出现“包含下级 · …”复选框）；申请类别、申请级别各选一项；“可跨级数”保持 1；点“下一步”。
- **讲解要点**：向导分三步对应原站的“活动信息、参评条件、活动环节”。必填项齐全才能进入下一步，未授权编辑的字段不会渲染成可填，缺少必填字段的编辑权时顶部提示“字段未授权，无法创建完整记录”。适用范围包括组织范围（可包含下级）、申请类别与级别：同一时间进行中的活动，适用范围不得与已有活动重复（DEC-372②，发布时由服务端拦截）。日期校验：开始日期不能晚于结束日期（提示“开始日期不能晚于结束日期”）。
- **预期结果**：第一步字段为两列表单，含名称、活动类型、所属组织、年度、周期、负责人、开始日期、结束日期、评定生效日期、申请人、组织范围、申请类别、申请级别、可跨级数、活动通知范围；漏填必填项点“下一步”会提示“请填写必填项”；通过后进入第二步。若活动类型、周期、申请类别下拉为空，则无法越过本步（数据缺口）。
- **高亮目标**：抽屉顶部三步条；“活动类型”“周期”“申请类别”三个下拉；“组织范围”下的“包含下级”复选框；抽屉底部“取消 / 下一步”按钮。

## 步骤 4：新建评定活动 · 参评条件

- **演示身份**：HR专员（演示）
- **页面与路由**：人才评定 `/evaluation`，向导第二步“参评条件”
- **操作**：点“添加”新增一条条件；“参评条件”下拉选“通用条件”，“申请人”选“员工本人”；点条件下的“添加”新增一行明细，“运算符”选“大于等于”，“字段来源”“字段”“值”按页面提示填写；再添加一条，把“参评条件”改成“附加条件”，观察出现“申请类别”“申请级别”；在“组合表达式”里写组合关系；点“下一步”。
- **讲解要点**：参评条件是对申请人的资格门槛，通用条件对所有申请适用，附加条件可按类别、级别限定；运算符含等于、不等于、大于、小于、大于等于、小于等于、为空、不为空、介于。提示“字段来源与字段编码须使用已配置的业务元数据；保存时由服务端校验”，所以前端不猜字段，条件元数据选择器后续完善（注释层 evaluation）。“介于”要求两端类型一致、开始值不大于结束值，否则分别提示“参评条件范围两端须为相同类型”“参评条件开始值不能大于结束值”。条件非必填。
- **预期结果**：每条条件是一个分组块，含“条件明细 #1”及运算符、字段来源、字段、值、结束值；没有条件时可直接下一步，详情中显示“未设置参评条件”。
- **高亮目标**：条件块里的“参评条件”“申请人”两个下拉；“运算符”下拉；下方灰色提示“字段来源与字段编码须使用已配置的业务元数据”；“组合表达式”输入框。

## 步骤 5：新建评定活动 · 活动环节，保存草稿

- **演示身份**：HR专员（演示）
- **页面与路由**：人才评定 `/evaluation`，向导第三步“活动环节”，随后列表
- **操作**：默认已有“资格申报”和“结果发布”两个环节；给“资格申报”填开始 / 结束日期（落在活动起止内）和“审批流程编码”，转入方式保持“流程完成后自动转入”，勾“强控报名截止”；点“添加”，新环节默认为“材料举证”，位置在“结果发布”之前，填日期；用“上移 / 下移”试排序（只有中间环节可移动）；把环节类型下拉改成“答辩评审”，观察出现“评价表”下拉、转入方式只剩“手动转入”；点“保存”。
- **讲解要点**：环节规则：资格申报、结果发布各 1 个且分别居首尾；材料举证、答辩评审各最多 3 个；答辩评审必须选评价表且只能手动转入；资格申报必须有审批流程；环节日期应在活动起止内（规格 24 EV-R12～R14，域规则 packages/domain/src/evaluation/activity-rules.ts）。这些在前端先校验、后端再校验，违反时提示具体原因。创建命令带命令 ID，结果未确认时降为 L2：重开抽屉只显示命令 ID、对象与摘要，只可查看，不恢复或重发在途表单（DEC-464、注释层 evaluation）。
- **预期结果**：保存成功后抽屉关闭，列表出现这条活动，状态 Tag 为灰色“草稿”，报名人数 0；提交过程中抽屉不可关闭。环节规则不满足时顶部红色提示相应中文原因。
- **高亮目标**：“活动环节”步骤里各环节的“环节名称”“开始日期”“结束日期”；“审批流程编码”输入；“添加”“上移 / 下移”按钮；抽屉底部“上一步 / 保存”。

## 步骤 6：活动详情与发布

- **演示身份**：HR专员（演示）
- **页面与路由**：人才评定 `/evaluation`，点名称或“查看”打开右侧详情抽屉，页签“活动信息 / 参评条件 / 活动环节 / 参评名单 / 评定过程”
- **操作**：点刚建的活动名称；依次点“活动信息”“参评条件”“活动环节”页签；点抽屉右上“发布活动”，在确认框“确认操作”点确定；观察状态变化；再点“取消发布”。
- **讲解要点**：详情读真实接口；“发布活动”只对草稿出现，“取消发布”只对进行中且报名人数为 0 的活动出现；确认框写明“取消发布不会撤回已发送通知”。发布时服务端检查：进行中的活动适用范围不能与其他进行中的活动重复，违反返回 409，提示“适用范围与已有活动【…】重复，请修改”（DEC-372②，可建第二个相同范围的活动演示）。报名后锁定部分字段（活动类型、组织范围、申请类别 / 级别、评定生效日期、通知范围；规格 EV-R14，AC-EV-05）。所有写操作带版本号，版本不一致返回 409 并要求刷新后显式重提。
- **预期结果**：详情“活动信息”显示名称、状态、年度、周期、所属组织、开始 / 结束日期、评定生效日期、报名人数；“活动环节”显示环节卡片（如“资格申报 开始日期 ～ 结束日期”）；发布成功后状态变为蓝色“进行中”，按钮变为“取消发布”；已完成活动没有“编辑”按钮。
- **高亮目标**：详情抽屉右上“刷新 / 编辑 / 发布活动”按钮组；“确认操作”对话框；列表或详情里的状态 Tag；抽屉里的五个页签。

## 步骤 7：参评名单（真实只读列表）

- **演示身份**：HR专员（演示）
- **页面与路由**：人才评定 `/evaluation` → 详情抽屉 → 页签“参评名单”
- **操作**：点“参评名单”页签；看表头。
- **讲解要点**：这是读 `staff-evaluations` 接口的真实只读列表，展示该活动下的员工评定数据；员工申报、提名、材料与答辩等后续环节暂停，所以新活动此处为空（DEC-456 之后评定后续 L3 暂停，见注释层 evaluation-paused）。需要评定管理员或评定专员持有员工评定数据的查看权，没有则显示“暂无访问权限”。
- **预期结果**：标题“参评名单”，表头可含“人员 / 申请类别 / 申请级别 / 当前环节 / 申报状态 / 最终结果 / 最终得分”（按字段权限裁剪），行为空：“这里什么都没有…”。
- **高亮目标**：“参评名单”页签；名单表头；空态提示。

## 步骤 8：评定过程（演示数据示意）与“完成活动（演示）”

- **演示身份**：HR专员（演示）
- **页面与路由**：人才评定 `/evaluation` → 详情抽屉 → 页签“评定过程”
- **操作**：点“评定过程”页签；看橙色“演示数据”标签和四个阶段卡片；读下方说明；点“完成活动（演示）”。
- **讲解要点**：页面标有“演示数据”，是合成样例，不是真实业务数据：四个阶段卡片“资格申报 / 材料举证 / 答辩评审 / 结果发布”是静态示意，说明文字为“以下为独立合成流程示意，不代表本活动人员或实际进度”和“后续提名、申报、材料、答辩、校准与结果发布暂为演示，未写入业务数据”。原站做法是评定过程显示阶段卡与参评人员，后续包括材料、答辩、校准、结果发布与完成活动；DEC-456 在途 PR 收口后暂停后续 L3，本页不模拟真实人员进度，也不写入或修改评定状态（注释层 evaluation-paused：DEC-456，L2）。“完成活动（演示）”按钮只弹说明窗，不改变活动状态。
- **预期结果**：页签内先出现注释卡片（开启注释时），“演示数据”橙色标签，四个阶段卡片各带“演示数据”字样；点“完成活动（演示）”弹出信息框，标题“完成活动（演示）”，正文“完成活动演示：实际完成接口尚未接通，此预览不会终止人员评定或更改活动状态。”；回列表该活动状态不变。
- **高亮目标**：“评定过程”页签；橙色“演示数据”标签；四个阶段卡片；“完成活动（演示）”按钮及其弹窗。

| 缺什么 | 影响步骤 | 路线里怎么绕开 | 建议补种子的内容 |
