## 路线概览

这条路线给客户的 IT / 安全负责人看：企业设置怎么管人（内部员工、外部用户）、怎么管能力（身份与对象权限）、怎么管可见数据（数据范围按“用户 × 应用”存一份，默认空，fail-closed），以及审计怎么追溯。第 3～5 步的操作，同时是其他模块路线“前置准备”里引用的授权配方（见文末“附”）。注意步骤顺序：人才类应用的数据范围只接受“管理单元”类型，所以管理单元（步骤 4）要先于设范围（步骤 5）。

| 步 | 身份 | 页面 | 一句话 |
|---|---|---|---|
| 1 | 系统管理员（演示） | 企业设置 → 内部员工 | 菜单由服务端快照决定；用户列表与“演示占位”列；取用户编号 |
| 2 | 系统管理员（演示） | 企业设置 → 身份管理 | 标准身份与对象权限（字段 / 按钮）明细 |
| 3 | 系统管理员（演示） | 企业设置 → 用户授权 | 把“人才标准管理员（人才标准）”授予 HR专员（演示） |
| 4 | 系统管理员（演示） | 企业设置 → 管理单元 | 新建“演示全部组织范围”管理单元（三个一级组织含下级），取管理单元编号 |
| 5 | 系统管理员（演示） | 用户授权 → 数据范围 | 给 HR专员 设 TalentCenter 应用的数据范围（管理单元类型） |
| 6 | 系统管理员（演示） | 用户授权 | 撤销身份，数据范围仍在，再授予（DEC-043） |
| 7 | 审计管理员（演示） | 企业设置 → 数据变更日志 | 只看到审计入口；筛选、详情 |

## 前置准备

- 启动：`pnpm demo`（写入种子并起后端 :3000 与前端 http://localhost:5173）；要回到干净数据用 `pnpm demo:reset`（先停掉 `pnpm demo`）。本路线会改授权数据，重复演示前建议 reset。
- 身份切换：顶部栏的“切换演示身份”下拉（选项形如“HR专员（演示）（HR（HRBP））”）；选人后整页刷新。系统管理员（演示）没有员工自助，切换后默认落在调动管理，需手动用顶部“应用导航”下拉进入“企业设置”（下拉里依次是 组织管理 / 职务体系 / 员工 / 调动管理 / 审批中心 / 企业设置 / 合同协议）。顶部“注释”开关打开后，页面显示“原站做法 / 我们的取舍 / DEC / 实现档位”。
- 本路线现场要写入的授权对象是 HR专员（演示）。用户编号的取法见文末“附”的 A 段；一级组织编号和管理单元编号的取法见 C 段。设置页没有用户 / 组织 / 管理单元选择器，**三类编号都要手工粘贴 UUID**，建议演示前先把 HR专员 的用户编号、三个一级组织编号放进文本编辑器备用。
- 企业设置左侧菜单下有很多子项（来自服务端权限快照里的企业设置菜单，按管理员身份取并集）。本页面片只实现其中 7 个：内部员工、全部用户、外部用户、身份管理、用户授权、管理单元、数据变更日志；其余菜单（如“管理后台首页”）点进去只显示“页面或记录不存在”，讲解时不要点。

## 步骤 1：企业设置入口与用户列表

- **演示身份**：系统管理员（演示）
- **页面与路由**：企业设置 `/settings` → 自动跳转 `/settings/menu/users.internal`（左侧菜单“企业设置”下的“用户管理/内部员工”，页内按钮“内部员工”）
- **操作**：打开“注释”开关；进入“企业设置”；看页内顶部按钮条（内部员工、全部用户、外部用户、身份管理、用户授权、管理单元、数据变更日志）和右侧标签“当前用户权限”（悬停可见说明）；在“内部员工”列表里点姓名链接“HR专员（演示）”（第 1 页第 1 行；前 7 行依次是 7 个演示身份，其后是生成员工），在右侧“查看详情”抽屉里看“基本信息”；关闭后切到“外部用户”，点右上“新增”（注意点按钮，别点到页面说明文字里的“新增”二字）看“新增外部用户”表单（姓名、联系邮箱、业务身份），不保存，点“取消”。
- **讲解要点**：注释层 `settings`（原站做法：企业设置以用户、身份授权、管理单元列表为主，标题是视图切换，无独立面包屑；我们的取舍：复用底座列表与右侧抽屉，权限由服务端菜单决定，数据范围按用户与应用共享，用户接口缺少的原站列保留空占位，不补造个人数据；DEC-456 / DEC-043 / DEC-019 / DEC-056 / DEC-470，实现档位 L3）。注释层 `settings.snapshot`（L2）：菜单及只读状态来自当前用户权限快照，前端不硬编码角色。要说明：“登录手机号 / 联系手机号 / 部门 / 职务 / 工号 / 入职时间 / 直线经理”这些列显示“—”，悬停提示“演示占位：当前用户接口尚未提供该字段”，这是演示占位，不是真实数据缺失。页面提示“内部员工账号随员工建档自动产生……外部用户通过‘新增’登记”。
- **预期结果**：内部员工列表列为 姓名 / 登录手机号 / 联系邮箱 / 联系手机号 / 部门 / 职务 / 工号 / 入职时间 / 直线经理 / 状态，状态标签“启用”，每页 15 条；右上有“刷新”“导出”（内部员工页没有“新增”）；详情抽屉标题“查看详情”，分区“基本信息”，含 姓名 / 联系邮箱 / 业务身份（内部员工为“—”）/ 状态 / 用户编号 / 版本。“外部用户”页列为 姓名 / 登录手机号 / 联系邮箱 / 联系手机号 / 用户类型 / 业务身份 / 来源 / 创建人 / 创建时间 / 状态，右上有“新增”“刷新”“导出”；列表里只有两行：系统管理员（演示）（用户类型“外部用户”，业务身份“租户管理员”）和异常管理员（演示）（业务身份“异常管理员”），来源 / 创建人 / 创建时间显示“—”。“新增外部用户”抽屉分区“基本信息”，字段 姓名 / 联系邮箱 / 业务身份，底部“取消”“保存”。列表里的联系邮箱是合成邮箱（example.com），讲解时不必念出。
- **高亮目标**：页内顶部按钮条；右侧“当前用户权限”标签（悬停是浏览器原生提示，需停留片刻）；列表里带“—”的占位列；详情抽屉里的“用户编号”一行；“外部用户”页的“新增”按钮。

## 步骤 2：身份管理：标准身份与对象权限

- **演示身份**：系统管理员（演示）
- **页面与路由**：企业设置 → “身份管理”，`/settings/menu/permission.profiles`（左侧菜单“权限管理/身份管理”）
- **操作**：点“身份管理”；在“筛选当前已加载记录”框输入“人才”后**按回车**（这是带搜索按钮的输入框，不按回车不会过滤；匹配名称或编码，命中 4 行：评定管理员（人才评定）、评定专员（人才评定）、人才标准管理员（人才标准）、盘点管理员（人才盘点））；点“人才标准管理员（人才标准）”的名称链接；在右侧抽屉“身份管理”里先看“名称 / 编码 / 关联应用 / 说明 / 版本”，再点下方对象页签（TalentCenter.Category 等 6 个），依次看“字段权限”表（字段 / 查看 / 编辑）和“按钮权限”表（编码 / 类型）。关闭抽屉，清空搜索框再按回车，列表第 1 行即名称为“员工”的身份，看“操作”列。
- **讲解要点**：页面提示“功能权限与数据范围独立配置；此页展示服务端返回的身份与对象权限”：身份只管功能（对象、字段、按钮），能看哪些行由数据范围单独管，这是复刻的核心约定（docs/02_业务建模/11_数据权限模型.md）。“类型”列区分“标准”和“自定义”；标准身份是开通租户时预置的（packages/domain/src/platform/standard-presets.ts）。“员工”身份在“操作”列显示“自动适用于全体员工”，所有员工自动持有，不能手工授予或撤销。可提一句：这里也能“新增”自定义身份（编码、关联应用用英文逗号分隔），但本路线不演示。
- **预期结果**：列表列为 名称 / 编码 / 关联应用 / 类型 / 说明 / 操作，共 16 条标准身份（每页 15 条，第 2 页还有 1 条；按编码排序，“员工”在第 1 行），如“标准版系统管理员（组织员工）”“人事管理员（组织员工）”“人事专员（组织员工）”“经理身份（组织员工）”“继任管理员（继任与发展）”“评定管理员（人才评定）”“360系统管理员”等；“人才标准管理员（人才标准）”的说明是“拥有人才标准的全部功能，可见数据按管理单元控制”（这句话直接铺垫步骤 4、5：该应用的范围只能用管理单元）。详情抽屉的页签名是对象编码（如 TalentCenter.Category），表格里“是 / 否”表示可查看 / 可编辑；按钮权限表的“编码”列是 create / delete / update，“类型”列是 list / detail。
- **高亮目标**：列表“编码”“关联应用”两列；“类型”列的“标准”标签；“员工”那行“操作”列的“自动适用于全体员工”；详情抽屉的“字段权限”“按钮权限”两张表。

## 步骤 3：用户授权：授予标准身份

- **演示身份**：系统管理员（演示）
- **页面与路由**：企业设置 → “用户授权”，`/settings/menu/permission.user_grant`
- **操作**：点“用户授权”；看列表（用户编号 / 身份 / 类型 / 状态 / 操作，用户编号列显示的是整串 UUID，不显示姓名）；点右上蓝色“新增”，在抽屉“新增用户授权”里：“用户编号”输入框（占位“输入本租户用户编号”）粘贴 HR专员（演示）的编号，点“身份”下拉，**向下滚动列表**（下拉不支持输入搜索，一屏只显示约 10 项）选“人才标准管理员（人才标准） (standard_talent_admin)”，点“保存”。
- **讲解要点**：页面提示“新增授权沿用该用户已有的应用范围；若需调整，请进入数据范围。自动身份不可手工撤销。”：授予身份和设范围是两件独立的事；新授身份时设的范围覆盖已有范围（DEC-043）。授予后默认数据范围为空，HR专员 此时能看到“人才标准”菜单，但列表显示“当前没有可查看的数据范围”，要到步骤 5 设范围才有数据（硬规则：数据范围默认为空，fail-closed，不得默认“全部”）。如果许可余额不足，保存仍成功，页面顶部出现黄色提示“授权已成功，但许可超额”（DEC-143，超额是成功回执而不是失败）；走查中授予 6 个人才类身份均未出现该提示。
- **预期结果**：保存成功后抽屉关闭，列表刷新，**末尾**多出一行：用户编号为 HR专员 的编号（与“人事管理员（组织员工）”那行同一串）、身份“人才标准管理员（人才标准）”、类型“手工授权”、状态“启用”，操作列有“数据范围”“撤销”两个链接。初始列表只有 3 行（“共3条”）：标准版系统管理员（系统管理员）、人事管理员（HR专员）、经理身份（审计管理员）。
- **高亮目标**：右上“新增”按钮；抽屉里“用户编号”输入框与“身份”下拉；新增行的“数据范围”“撤销”链接；页面顶部蓝色提示文字。

## 步骤 4：管理单元：先建一个“全部组织”的范围

- **演示身份**：系统管理员（演示）
- **页面与路由**：企业设置 → “管理单元”，`/settings/menu/permission.mous`（左侧菜单“权限管理/管理单元”）
- **操作**：点“管理单元”；页签停在“管理单元”，列表为空（显示“这里什么都没有…”）；点“新增”，抽屉“新增管理单元”里：“名称”填“演示全部组织范围”，“编码”填 `DEMO-MOU-ALL`，“说明”可空，“组织范围条目”点“添加组织”三次，三行“组织编号”分别粘贴三个一级组织编号（取法见文末“附”的 C 段），“组织维度”保持“行政”，每行勾选“包含下级”，点“保存”；点新行的名称链接看详情；再点上方页签“数据范围”，说明这里与步骤 5 是同一个编辑器。**取管理单元编号**：页面上看不到管理单元编号（列表、详情都没有），需打开浏览器开发者工具的“网络”面板，保存时找 `mous` 的 POST 请求（或刷新列表的 `mous?limit=…` GET 请求），响应里的 `id` 即编号；复制备用。
- **讲解要点**：管理单元是可复用的一组组织范围，可以被数据范围引用；**人才标准、任职资格、人才评定、360 评估、人才盘点、继任与发展这些应用的数据范围只接受“管理单元”类型**，只有组织员工（TenantBase）才允许直接选“组织范围”（服务端按应用限定可选范围类型，直接选“组织范围”保存会被拒）——这也解释了步骤 2 里“可见数据按管理单元控制”的说明。管理单元的增删改首版只开放给租户管理员（系统管理员（演示）是租户管理员），系统 / 用户 / 权限管理员可见但只读（规格 docs/02_业务建模/06_权限模型_运行实证.md）。“上级管理单元编号”列是原站的层级字段，本页面片新建时固定为空。
- **预期结果**：新行列为 名称 / 编码 / 说明 / 上级管理单元编号（空）/ 状态“启用”；详情抽屉标题“管理单元”，含 名称 / 编码 / 说明 / 上级管理单元编号（“—”）/ 版本（1），以及“组织范围”小标题下三行“组织编号 · admin · 包含下级”。名称或编码为空直接点“保存”，表单提示“请填写此项”“请检查必填项及格式”，不会提交。
- **高亮目标**：页签“管理单元”“数据范围”；右上“新增”按钮；抽屉里的“编码”与“组织范围条目”区；详情抽屉的“组织范围”小标题。

## 步骤 5：数据范围：按（用户 × 应用）设置

- **演示身份**：系统管理员（演示）
- **页面与路由**：用户授权页 → 行内“数据范围”（右侧抽屉“数据范围”）；同一编辑器也在“管理单元”页的“数据范围”页签
- **操作**：回“用户授权”，点 HR专员 那行（编号与“人事管理员”行相同）的“数据范围”；抽屉里“用户编号”已预填，“应用编码”输入 `TalentCenter`，点“查询数据范围”；看到“数据范围”显示“默认管理单元（空范围）”、版本 0，点“编辑”；在弹出的“数据范围”表单里，“数据范围”下拉选“管理单元”（下拉里有三项：默认管理单元（空范围）/ 管理单元 / 组织范围，别选成第一项），在“管理单元编号”粘贴步骤 4 取到的编号，点“保存”；保存后抽屉里“数据范围”一行变成该管理单元编号、版本 1（可再点“刷新”核对）。可选的对比演示：改选“组织范围”并填三个组织后保存，会被拒绝，抽屉显示“请检查表单字段”（实际原因是服务端返回“该应用不支持此范围类型”，页面没有显示这句，讲解时口头说明）。
- **讲解要点**：数据范围按（用户 × 应用）存一份，由该用户在此应用下的所有身份共享（DEC-043，原站实测照搬）；默认是“默认管理单元（空范围）”，不是全部；三种范围类型：默认空范围、管理单元、组织范围，但可选类型由应用决定（人才类应用只能用管理单元，TenantBase 三种都可）。组织范围每条独立选择维度（行政 / 业务 / 利润中心（财务）/ 预留维度4 / 预留维度5）和是否包含下级——组织层级不是单一上级，各维度各有一棵树（硬规则）；这在管理单元的“组织范围条目”里同样适用。页面直接让管理员粘贴编号，是当前版本的取舍（没有组织 / 管理单元选择器），讲解时可顺带说明。
- **预期结果**：首次查询显示 用户编号 / 应用编码 / 数据范围“默认管理单元（空范围）”/ 版本 0；保存后“数据范围”一行为管理单元编号（页面只显示编号，不显示名称），版本变为 1。随后切到 HR专员（演示），进入“人才标准”（`/talent`）：设范围前列表显示“当前没有可查看的数据范围”，设范围后显示“这里什么都没有…”（范围已生效，只是种子没有指标库数据；路线 07 起现场新建）。
- **高亮目标**：“应用编码”输入框与“查询数据范围”按钮；“数据范围”一行的描述文字；“编辑”按钮；编辑表单里“数据范围”下拉与“管理单元编号”输入框。

## 步骤 6：撤销身份，范围不被连带删除

- **演示身份**：系统管理员（演示）
- **页面与路由**：企业设置 → “用户授权”
- **操作**：在 HR专员 的“人才标准管理员（人才标准）”行点“撤销”，在“撤销此身份？该用户的共享数据范围会保留。”的抽屉里点“保存”（抽屉内没有别的字段，只有“取消”“保存”）；该行状态变为“已撤销”、操作列只剩“数据范围”后，点同一行“数据范围”，应用编码 `TalentCenter`，点“查询数据范围”，范围仍是原管理单元编号、版本不变；再点右上“新增”，用同样的用户编号和身份重新授予，点“保存”。撤销期间切到 HR专员（演示）会发现“人才标准”菜单消失（刷新后），重新授予后恢复。
- **讲解要点**：这是硬规则“身份 ↔ 数据范围多对一，撤销身份不得连带删除范围”（DEC-043：撤销身份后范围不回滚）；页面提示“默认管理单元为空范围，撤销身份不会删除共享范围”。重新授予后无需再设范围，沿用已有范围（“新增授权沿用该用户已有的应用范围”）。只有“手工授权”且“启用”的行才有“撤销”，自动授权的身份（如员工）不可撤销。
- **预期结果**：撤销后该行状态“已撤销”、操作列不再有“撤销”；数据范围查询结果与撤销前一致（同一管理单元编号、版本号不变）；重新授予后列表**末尾多出一行**启用的同身份授权，原“已撤销”行保留（撤销是留痕，不删行）。
- **高亮目标**：该行的“撤销”链接；撤销抽屉标题文字；“已撤销”状态标签；撤销后查询出的“数据范围”描述仍是原管理单元编号。

## 步骤 7：审计管理员查看数据变更日志

- **演示身份**：审计管理员（演示）
- **页面与路由**：企业设置 `/settings` → 自动跳到 `/settings/menu/audit.business`（左侧菜单“日志审计/业务操作日志”，页内按钮“数据变更日志”）
- **操作**：切到审计管理员（演示），顶部应用切换进入“企业设置”；页内只有“数据变更日志”一个按钮（左侧菜单“权限管理/权限查询”和“日志审计”下另有 5 个入口，点进去多半是“页面或记录不存在”，不要点）；看“操作时间”窗口（默认近 90 天）和列表（最新的在最上面，是前面步骤 3～6 产生的授权 / 范围变更）；点“高级筛选”，在右侧抽屉点“开始日期”选日历里的今天，“对象”填 `permission_user_app_scope`，点“确定”；点结果里“数据编号”链接（如“用户编号:TalentCenter”形式）打开详情。“对象”框只接受对象编码；填中文“用户授权”会提示加载失败。
- **讲解要点**：审计管理员的企业设置里只有审计入口，没有用户、授权、管理单元（菜单由服务端按管理员身份给出，前端不硬编码）。数据变更日志是字段级变更日志，每个写操作与审计同事务写入（DEC-019，规格 docs/02_业务建模/20_审计日志_规格.md）；审计管理员持只读的“经理身份”加全部组织范围，能看到的行和字段仍按当前权限裁剪（AGENTS.md 第 10 节：读取历史记录时仍按当前权限裁剪）；日志时间按租户时区显示（DEC-056）。删除类操作会带“删除快照”小节。
- **预期结果**：列表列为 数据编号 / 操作人 / 操作时间 / 操作 / 对象 / 变更内容 / 来源动作，分页用“下一页”游标，列表上方显示“操作时间: 起 ~ 止”；每次授权保存产生一行“新增 / 用户授权”（变更内容含 profileId 等），撤销产生“编辑 / 用户授权”（状态:从【active】修改为【revoked】），设范围产生“编辑 / permission_user_app_scope”（业务类型、管理单元编号等“从…修改为…”），操作人均为系统管理员（演示）；按对象过滤后只剩范围变更；筛选抽屉标题“高级筛选”，含 开始日期 / 结束日期 / 对象 / 字段 四项，底部“清空”“取消”“确定”；详情抽屉标题“数据变更日志”，含 操作人 / 操作时间 / 对象 / 数据编号 / 来源动作 / 追踪编号，下方“变更内容”。
- **高亮目标**：页内仅有的“数据变更日志”按钮；列表里“变更内容”一列的“从【…】修改为【…】”；“操作时间”窗口文字；“高级筛选”链接；详情抽屉的“变更内容”小标题。

## 附：给演示身份授予标准身份与数据范围的操作配方

> 其他路线（尤其是 R3 人才模块）的“前置准备”引用本节。操作人固定为系统管理员（演示），作用对象为复刻系统的演示租户（不涉及北森测试租户）。以下按钮文案均取自 apps/web/src/settings/messages.ts 与组件，并已在 2026-10-14 用本地 `pnpm demo` 逐项实点（给 HR专员（演示）授予 6 个人才类标准身份并设范围，6 个应用页面均能打开）。
> **总流程**：A 取用户编号 → C0 取一级组织编号 → C1 新建管理单元并取其编号 → 对每个要授的身份重复 B（授身份）+ C2（设该身份关联应用的范围，范围一律选“管理单元”）→ D 切到目标身份校验。管理单元只需建一次，所有应用共用。

**A. 取目标用户的用户编号（UUID）**
1. 方案一：用文本编辑器打开仓库根 `.demo/personas.json`（`pnpm demo` 生成，已被 git 忽略），找到目标演示身份的 `name`（如“HR专员（演示）”），复制同一项的 `userId`；也可在浏览器打开 `http://localhost:5173/__demo/personas` 查看同样内容。
2. 方案二：企业设置 → “内部员工” → 点姓名链接（演示身份在第 1 页前 7 行：HR专员 为第 1 行），在“查看详情”抽屉复制“用户编号”。
3. 用户编号只用来粘贴，不写进文档或提交。
4. 复制 UUID 时用鼠标拖选整串，不要双击（连字符通常会把 UUID 断成一段）。

**B. 授予标准身份**
1. 切到“系统管理员（演示）”，顶部应用切换进入“企业设置”，页内点“用户授权”。
2. 点右上蓝色“新增”，打开抽屉“新增用户授权”。
3. “用户编号”粘贴 A 段的编号（必须是 UUID，否则提示“请检查必填项及格式”）。
4. 点“身份”下拉，选目标身份（下拉项文案为“名称 (编码)”，如“人才标准管理员（人才标准） (standard_talent_admin)”）。**下拉不能输入搜索，且每次只渲染约 10 项，要在下拉里滚动鼠标滚轮**才能看到靠后的“继任管理员（继任与发展）”“人才标准管理员（人才标准）”“盘点管理员（人才盘点）”。下拉按编码排序，不含“员工”（自动持有身份，不可手工授予）。
5. 点抽屉底部“保存”。成功后抽屉关闭，列表**末尾**多一行“手工授权 / 启用”（用户编号列是整串 UUID，用前 4 位与 A 段编号对照）。若出现黄色提示“授权已成功，但许可超额”，授权已生效，按提示联系运营补许可，不影响演示；实测 6 个人才类身份都没有触发。
6. 一个身份关联多个应用时（见 F 表“需设范围的应用编码”列），每个应用要各设一份范围。
7. 授予后不需要刷新，但目标身份那一侧要“切换身份”或刷新页面才会读到新的权限快照（见 D）。

**C0. 取三个一级组织的编号**
1. 设置页没有组织选择器。种子已给 HR专员（演示）按“全部一级组织含下级”设好了 TenantBase 范围，利用它：用户授权 → HR专员 那行（编号与“人事管理员（组织员工）”相同）的“数据范围” → “应用编码”填 `TenantBase` → “查询数据范围”，“数据范围”一行显示三个“组织编号 (admin, 包含下级)”，就是研发中心、运营中心、职能中心三个一级组织的编号（三条的先后顺序未核对对应哪个组织，不影响“全部组织”）。逐个复制备用。**只查询，不要点“编辑”保存**，否则会覆盖 HR专员 的 TenantBase 范围。
2. 要限制到某个部门，组织编号目前只能从浏览器开发者工具的网络面板里查 `/api/tenant/org/organizations` 的返回。

**C1. 新建管理单元并取编号（只做一次）**
1. 企业设置 → “管理单元” → 页签“管理单元” → “新增”。
2. “名称”填“演示全部组织范围”，“编码”填 `DEMO-MOU-ALL`；点“添加组织”三次，三行“组织编号”粘贴 C0 的三个编号，“组织维度”保持“行政”，三行都勾选“包含下级”；点“保存”。
3. 取管理单元编号：页面不显示。保存前先打开浏览器开发者工具的“网络”面板，保存后找 `mous` 的 POST 请求（状态 201），响应 JSON 里的 `id` 就是管理单元编号；或刷新列表后看 `mous?limit=15&offset=0` 请求的响应。复制备用。
4. 取到一次后更省事的办法：给第一个应用设好范围后，再查询该应用的数据范围，“数据范围”一行显示的就是这个管理单元编号（页面只显示编号，不显示名称），后面几个应用可直接从这里复制。

**C2. 为某个（用户 × 应用）设置数据范围（默认空，必须显式设）**
1. 在“用户授权”列表里点目标行的“数据范围”（行内链接；仅租户管理员可见），打开抽屉“数据范围”，“用户编号”已预填。
2. “应用编码”输入 F 表的应用编码（区分大小写），点“查询数据范围”。首次应显示“默认管理单元（空范围）”、版本 0。
3. 点“编辑”，弹出“数据范围”表单。在“数据范围”下拉选“管理单元”（三项：默认管理单元（空范围）/ 管理单元 / 组织范围；选项里“默认管理单元（空范围）”文字也含“管理单元”，别点错），在“管理单元编号”粘贴 C1 的编号。
4. **不要选“组织范围”**：只有 TenantBase（组织员工）允许“组织范围”；其余应用（TalentCenter / Qualification / TEvaluation / Survey360 / TalentReview / SuccessionAndDevelopment）选“组织范围”保存会被服务端拒绝（原因“该应用不支持此范围类型”），页面只提示“请检查表单字段”，容易误判成填错。
5. 点表单底部“保存”，成功后表单关闭，抽屉里“数据范围”一行变成管理单元编号、版本 1（可再点“刷新”核对）。保存提示“记录已被更新，请刷新后重新提交”时，点“刷新”后重来（409 冲突，不要盲目重试）。
6. 范围是（用户 × 应用）一份：同一用户在同一应用下有多个身份时共享一份；已有范围会被新保存的整体覆盖。不要对 TenantBase 做编辑保存（会覆盖种子范围）。
7. 管理单元里的组织范围是直接“全部一级组织含下级”，所以 R3 列表里能看到范围内的全部数据，不会再出现“当前没有可查看的数据范围”。

**D. 生效校验**
1. 切到目标身份（切换后整页刷新，权限快照重新读取），在左侧菜单“人才管理”分组和顶部“应用导航”里确认出现对应应用；菜单可见性来自服务端，不是前端写死。已实测 HR专员（演示）授予后依次出现：人才标准（`/talent`）、任职资格（`/qualification`）、人才评定（`/evaluation`）、360 评估（`/survey360`）、人才盘点（`/talent-review`）、继任管理（`/succession`）。
2. 授了身份、没设范围时，人才标准（`/talent`）、人才评定（`/evaluation`）的列表显示“当前没有可查看的数据范围”（fail-closed）；任职资格页（`/qualification`）未设范围时已实测只显示“这里什么都没有…”，不区分；其余三个应用未单独核对未设范围的显示。设好范围后，种子没有 R3 样例数据，列表统一显示“这里什么都没有…”（盘点、继任、360 另有“共0条”），这是正常的，路线里现场新建数据。

**E. 撤销（演示 DEC-043）**
1. “用户授权”列表目标行点“撤销”，抽屉标题“撤销此身份？该用户的共享数据范围会保留。”，点“保存”。
2. 撤销后再按 C2 查询同一应用，范围仍在（编号与版本不变）；再按 B 段重新授予即可复用范围（已实测：重新授予成功，列表末尾追加新行，旧的“已撤销”行保留）。撤销后目标身份刷新页面，对应应用的菜单消失。
3. 要把一个临时账号的范围恢复成空：对它再走 C2，“数据范围”下拉选“默认管理单元（空范围）”保存（版本号会继续加 1，不会回到 0）。
