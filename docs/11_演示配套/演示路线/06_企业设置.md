## 路线概览

这条路线给客户的 IT / 安全负责人看：企业设置怎么管人（内部员工、外部用户）、怎么管能力（身份与对象权限）、怎么管可见数据（数据范围按“用户 × 应用”存一份，默认空，fail-closed），以及审计怎么追溯。第 3～5 步的操作，同时是其他模块路线“前置准备”里引用的授权配方（见文末“附”）。

| 步 | 身份 | 页面 | 一句话 |
|---|---|---|---|
| 1 | 系统管理员（演示） | 企业设置 → 内部员工 | 菜单由服务端快照决定；用户列表与“演示占位”列；取用户编号 |
| 2 | 系统管理员（演示） | 企业设置 → 身份管理 | 标准身份与对象权限（字段 / 按钮）明细 |
| 3 | 系统管理员（演示） | 企业设置 → 用户授权 | 把“人才标准管理员（人才标准）”授予 HR专员（演示） |

| 5 | 系统管理员（演示） | 用户授权 | 撤销身份，数据范围仍在，再授予（DEC-043） |
| 6 | 系统管理员（演示） | 企业设置 → 管理单元 | 新建管理单元；管理单元与数据范围页签 |

## 前置准备

- 启动：`pnpm demo`（写入种子并起后端 :3000 与前端 http://localhost:5173）；要回到干净数据用 `pnpm demo:reset`（先停掉 `pnpm demo`）。本路线会改授权数据，重复演示前建议 reset。
- 身份切换：顶部黄色“本地演示”条的“切换演示身份”下拉；系统管理员（演示）没有员工自助，切换后手动用顶部应用切换进入“企业设置”。顶部“注释”开关打开后，页面显示“原站做法 / 我们的取舍 / DEC / 实现档位”。
- 本路线现场要写入的授权对象是 HR专员（演示）。用户编号的取法见文末“附”的 A 段。
- 企业设置左侧菜单下有很多子项（来自服务端权限快照里的企业设置菜单，按管理员身份取并集）。本页面片只实现其中 7 个：内部员工、全部用户、外部用户、身份管理、用户授权、管理单元、数据变更日志；其余菜单点进去会提示页面不存在，讲解时不要点。

## 步骤 1：企业设置入口与用户列表

- **演示身份**：系统管理员（演示）
- **页面与路由**：企业设置 `/settings` → 自动跳转 `/settings/menu/users.internal`（左侧菜单“企业设置”下的“用户管理/内部员工”，页内按钮“内部员工”）
- **操作**：打开“注释”开关；进入“企业设置”；看页内顶部按钮条（内部员工、全部用户、外部用户、身份管理、用户授权、管理单元、数据变更日志）和右侧标签“当前用户权限”（悬停可见说明）；在“内部员工”列表里点任一人的姓名链接（如分页翻到“HR专员（演示）”，或直接用文末附录 A 段的办法取编号），在右侧“查看详情”抽屉里看“基本信息”；关闭后切到“外部用户”，点“新增”看“新增外部用户”表单（姓名、联系邮箱、业务身份），不保存，点“取消”。
- **讲解要点**：注释层 `settings`（原站做法：企业设置以用户、身份授权、管理单元列表为主，标题是视图切换，无独立面包屑；我们的取舍：复用底座列表与右侧抽屉，权限由服务端菜单决定，数据范围按用户与应用共享，用户接口缺少的原站列保留空占位，不补造个人数据；DEC-456 / DEC-043 / DEC-019 / DEC-056 / DEC-470，实现档位 L3）。注释层 `settings.snapshot`（L2）：菜单及只读状态来自当前用户权限快照，前端不硬编码角色。要说明：“登录手机号 / 联系手机号 / 部门 / 职务 / 工号 / 入职时间 / 直线经理”这些列显示“—”，悬停提示“演示占位：当前用户接口尚未提供该字段”，这是演示占位，不是真实数据缺失。页面提示“内部员工账号随员工建档自动产生……外部用户通过‘新增’登记”。
- **预期结果**：内部员工列表列为 姓名 / 登录手机号 / 联系邮箱 / 联系手机号 / 部门 / 职务 / 工号 / 入职时间 / 直线经理 / 状态，状态标签“启用”，每页 15 条；右上有“刷新”（内部员工页没有“新增”）；详情抽屉标题“查看详情”，分区“基本信息”，含 姓名 / 联系邮箱 / 业务身份 / 状态 / 用户编号 / 版本；“外部用户”页有“新增”按钮，系统管理员（演示）自己通常出现在“外部用户”列表里（开通时登记为外部用户，业务身份见页面）。
- **高亮目标**：页内顶部按钮条；右侧“当前用户权限”标签；列表里带“—”的占位列；详情抽屉里的“用户编号”一行；“外部用户”页的“新增”按钮。

## 步骤 2：身份管理：标准身份与对象权限

- **演示身份**：系统管理员（演示）
- **页面与路由**：企业设置 → “身份管理”，`/settings/menu/permission.profiles`（左侧菜单“权限管理/身份管理”）
- **操作**：点“身份管理”；在“筛选当前已加载记录”框输入“人才”；点“人才标准管理员（人才标准）”的名称链接；在右侧抽屉里先看“名称 / 编码 / 关联应用 / 说明 / 版本”，再点上方对象页签，依次看“字段权限”表（字段 / 查看 / 编辑）和“按钮权限”表（编码 / 类型）。再清空搜索，找到名称为“员工”的身份看“操作”列。
- **讲解要点**：页面提示“功能权限与数据范围独立配置；此页展示服务端返回的身份与对象权限”：身份只管功能（对象、字段、按钮），能看哪些行由数据范围单独管，这是复刻的核心约定（docs/02_业务建模/11_数据权限模型.md）。“类型”列区分“标准”和“自定义”；标准身份是开通租户时预置的（packages/domain/src/platform/standard-presets.ts）。“员工”身份在“操作”列显示“自动适用于全体员工”，所有员工自动持有，不能手工授予或撤销。可提一句：这里也能“新增”自定义身份（编码、关联应用用英文逗号分隔），但本路线不演示。
- **预期结果**：列表列为 名称 / 编码 / 关联应用 / 类型 / 说明 / 操作，多个标准身份（如“标准版系统管理员（组织员工）”“人事管理员（组织员工）”“人事专员（组织员工）”“经理身份（组织员工）”“继任管理员（继任与发展）”“评定管理员（人才评定）”“360系统管理员”等，名称以实际为准）；详情抽屉的页签名是对象编码（如 TalentCenter.…），表格里“是 / 否”表示可查看 / 可编辑。
- **高亮目标**：列表“编码”“关联应用”两列；“类型”列的“标准”标签；“员工”那行“操作”列的“自动适用于全体员工”；详情抽屉的“字段权限”“按钮权限”两张表。

## 步骤 3：用户授权：授予标准身份

- **演示身份**：系统管理员（演示）
- **页面与路由**：企业设置 → “用户授权”，`/settings/menu/permission.user_grant`
- **操作**：点“用户授权”；看列表（用户编号 / 身份 / 类型 / 状态 / 操作）；点右上蓝色“新增”，在抽屉“新增用户授权”里：“用户编号”粘贴 HR专员（演示）的编号，“身份”下拉选“人才标准管理员（人才标准） (standard_talent_admin)”，点“保存”。
- **讲解要点**：页面提示“新增授权沿用该用户已有的应用范围；若需调整，请进入数据范围。自动身份不可手工撤销。”：授予身份和设范围是两件独立的事；新授身份时设的范围覆盖已有范围（DEC-043）。授予后默认数据范围为空，HR专员 此时在人才应用里什么都看不到，要到下一步设范围才能看到数据（硬规则：数据范围默认为空，fail-closed，不得默认“全部”）。如果许可余额不足，保存仍成功，页面顶部出现黄色提示“授权已成功，但许可超额”（DEC-143，超额是成功回执而不是失败）。
- **预期结果**：保存成功后抽屉关闭，列表刷新，多出一行：用户编号为 HR专员 的编号、身份“人才标准管理员（人才标准）”、类型“手工授权”、状态“启用”，操作列有“数据范围”“撤销”两个链接；该身份不占许可名额，预期不出现超额提示。
- **高亮目标**：右上“新增”按钮；抽屉里“用户编号”输入框与“身份”下拉；新增行的“数据范围”“撤销”链接；页面顶部蓝色提示文字。

## 步骤 4：数据范围：按（用户 × 应用）设置

- **演示身份**：系统管理员（演示）
- **页面与路由**：用户授权页 → 行内“数据范围”（右侧抽屉“数据范围”）；同一编辑器也在“管理单元”页的“数据范围”页签
- **操作**：点步骤 3 新增那行的“数据范围”；抽屉里“用户编号”已预填，“应用编码”输入 `TalentCenter`，点“查询数据范围”；看到“数据范围”显示“默认管理单元（空范围）”，点“编辑”；在“数据范围”下拉选“组织范围”，点“添加组织”三次，每行“组织编号”粘贴一个一级组织编号（取法见文末“附”的 C 段），“组织维度”保持“行政”，勾选“包含下级”，点“保存”；保存后点“刷新”核对。
- **讲解要点**：数据范围按（用户 × 应用）存一份，由该用户在此应用下的所有身份共享（DEC-043，原站实测照搬）；默认是“默认管理单元（空范围）”，不是全部；三种范围：默认空范围、管理单元、组织范围；组织范围每条独立选择维度（行政 / 业务 / 利润中心（财务）/ 预留维度4 / 预留维度5）和是否包含下级——组织层级不是单一上级，各维度各有一棵树（硬规则）。页面直接让管理员粘贴组织编号，是当前版本的取舍（没有组织选择器），讲解时可顺带说明。
- **预期结果**：首次查询显示 用户编号 / 应用编码 / 数据范围“默认管理单元（空范围）”/ 版本；保存后“数据范围”一行变为三条“组织编号 (admin, 包含下级)”，版本号加 1。随后切到 HR专员（演示），在人才标准应用里可看到范围内的数据（路线 07 起使用）。
- **高亮目标**：“应用编码”输入框与“查询数据范围”按钮；“数据范围”一行的描述文字；“编辑”按钮；抽屉里“组织范围条目”区的“添加组织”按钮、“包含下级”勾选框。

## 步骤 5：撤销身份，范围不被连带删除

- **演示身份**：系统管理员（演示）
- **页面与路由**：企业设置 → “用户授权”
- **操作**：在 HR专员 的“人才标准管理员（人才标准）”行点“撤销”，在“撤销此身份？该用户的共享数据范围会保留。”的抽屉里点“保存”；该行状态变为“已撤销”后，点同一行“数据范围”，应用编码 `TalentCenter`，点“查询数据范围”，范围仍是三条组织；再点右上“新增”，用同样的用户编号和身份重新授予，点“保存”。
- **讲解要点**：这是硬规则“身份 ↔ 数据范围多对一，撤销身份不得连带删除范围”（DEC-043：撤销身份后范围不回滚）；页面提示“默认管理单元为空范围，撤销身份不会删除共享范围”。重新授予后无需再设范围，沿用已有范围（“新增授权沿用该用户已有的应用范围”）。只有“手工授权”且“启用”的行才有“撤销”，自动授权的身份（如员工）不可撤销。
- **预期结果**：撤销后该行状态“已撤销”、操作列不再有“撤销”；数据范围查询结果与撤销前一致（三条组织、版本号不变）；重新授予后列表多出一行启用的同身份授权。
- **高亮目标**：该行的“撤销”链接；撤销抽屉标题文字；“已撤销”状态标签；撤销后查询出的“数据范围”描述仍有三条组织。

## 步骤 6：管理单元

- **演示身份**：系统管理员（演示）
- **页面与路由**：企业设置 → “管理单元”，`/settings/menu/permission.mous`（左侧菜单“权限管理/管理单元”）
- **操作**：点“管理单元”；页签停在“管理单元”，列表为空；点“新增”，抽屉“新增管理单元”里：“名称”填“演示全部组织范围”，“编码”填 `DEMO-MOU-ALL`，“说明”随意，“组织范围条目”点“添加组织”三次并粘贴三个一级组织编号（同步骤 4），勾选“包含下级”，点“保存”；点新行的名称链接看详情；再点上方页签“数据范围”，说明这里与步骤 4 是同一个编辑器。
- **讲解要点**：管理单元是可复用的一组组织范围，可以被数据范围引用（数据范围的第二种类型“管理单元”）；管理单元的增删改首版只开放给租户管理员（系统管理员（演示）是租户管理员），系统 / 用户 / 权限管理员可见但只读（规格 docs/02_业务建模/06_权限模型_运行实证.md）。“上级管理单元编号”列是原站的层级字段，本页面片新建时固定为空。
- **预期结果**：新行列为 名称 / 编码 / 说明 / 上级管理单元编号（空）/ 状态“启用”；详情抽屉标题“管理单元”，含 名称 / 编码 / 说明 / 上级管理单元编号 / 版本，以及“组织范围”小标题下三行“组织编号 · admin · 包含下级”。
- **高亮目标**：页签“管理单元”“数据范围”；右上“新增”按钮；抽屉里的“编码”与“组织范围条目”区；详情抽屉的“组织范围”小标题。

## 步骤 7：审计管理员查看数据变更日志

- **演示身份**：审计管理员（演示）
- **页面与路由**：企业设置 `/settings` → 自动跳到 `/settings/menu/audit.business`（左侧菜单“日志审计/业务操作日志”，页内按钮“数据变更日志”）
- **操作**：切到审计管理员（演示），顶部应用切换进入“企业设置”；页内只有“数据变更日志”一个按钮；看“操作时间”窗口和列表；点“高级筛选”，在右侧抽屉填“开始日期”为今天、“对象”填 `TenantBase.EmploymentRecord`、“字段”填 `departmentId`，点“确定”；点结果里“数据编号”链接打开详情。
- **讲解要点**：审计管理员的企业设置里只有审计入口，没有用户、授权、管理单元（菜单由服务端按管理员身份给出，前端不硬编码）。数据变更日志是字段级变更日志，每个写操作与审计同事务写入（DEC-019，规格 docs/02_业务建模/20_审计日志_规格.md）；审计管理员持只读的“经理身份”加全部组织范围，能看到的行和字段仍按当前权限裁剪（AGENTS.md 第 10 节：读取历史记录时仍按当前权限裁剪）；日志时间按租户时区显示（DEC-056）。删除类操作会带“删除快照”小节。
- **预期结果**：列表列为 数据编号 / 操作人 / 操作时间 / 操作 / 对象 / 变更内容 / 来源动作，分页用“下一页”游标，列表上方显示“操作时间: 起 ~ 止”；筛选抽屉标题“高级筛选”，含 开始日期 / 结束日期 / 对象 / 字段 四项，底部“清空”“取消”“确定”；详情抽屉标题“数据变更日志”，含 操作人 / 操作时间 / 对象 / 数据编号 / 来源动作 / 追踪编号，下方“变更内容”。

## 附：给演示身份授予标准身份与数据范围的操作配方

> 其他路线（尤其是 R3 人才模块）的“前置准备”引用本节。操作人固定为系统管理员（演示），作用对象为复刻系统的演示租户（不涉及北森测试租户）。以下按钮文案均取自 apps/web/src/settings/messages.ts 与组件。

**A. 取目标用户的用户编号（UUID）**
1. 方案一：用文本编辑器打开仓库根 `.demo/personas.json`（`pnpm demo` 生成，已被 git 忽略），找到目标演示身份的 `name`（如“HR专员（演示）”），复制同一项的 `userId`。
2. 方案二：企业设置 → “内部员工” → 逐页（每页 15 条）找到目标姓名，点姓名链接，在“查看详情”抽屉复制“用户编号”。
3. 用户编号只用来粘贴，不写进文档或提交。

**B. 授予标准身份**
1. 切到“系统管理员（演示）”，顶部应用切换进入“企业设置”，页内点“用户授权”。
2. 点右上蓝色“新增”，打开抽屉“新增用户授权”。
3. “用户编号”粘贴 A 段的编号（必须是 UUID，否则提示“请检查必填项及格式”）。
4. “身份”下拉选目标身份（下拉项文案为“名称 (编码)”，如“人才标准管理员（人才标准） (standard_talent_admin)”）。
5. 点抽屉底部“保存”。成功后列表多一行“手工授权 / 启用”。若出现黄色提示“授权已成功，但许可超额”，授权已生效，按提示联系运营补许可，不影响演示。
6. 一个身份关联多个应用时（见下表“应用编码”列），每个应用要各设一份范围。

**C. 设置数据范围（默认空，必须显式设）**
1. 在“用户授权”列表里点目标行的“数据范围”（行内链接；仅租户管理员可见），打开抽屉“数据范围”，“用户编号”已预填。
2. “应用编码”输入下表的应用编码（区分大小写），点“查询数据范围”。首次应显示“默认管理单元（空范围）”。
3. 点“编辑”，在“数据范围”下拉选“组织范围”（或“管理单元”，需填“管理单元编号”）。
4. 要给“全部组织”：点“添加组织”，每条“组织编号”粘贴一个**一级组织**的编号，“组织维度”选“行政”，勾选“包含下级”。一级组织共三个：研发中心、运营中心、职能中心。现成的取法：先对 HR专员（演示）按本段第 1～2 步查询应用编码 `TenantBase`，“数据范围”一行里列出的三个组织编号就是这三个一级组织（种子已按“全部一级组织含下级”设好）；逐个复制即可。要限制到某个部门，组织编号目前只能从浏览器开发者工具的网络面板里查看 `/api/tenant/org/organizations` 的返回（设置页没有组织选择器）。
5. 点抽屉底部“保存”，再点“刷新”核对：“数据范围”一行应列出所设组织，版本号加 1。保存提示“记录已被更新，请刷新后重新提交”时，点“刷新”后重来（409 冲突，不要盲目重试）。
6. 范围是（用户 × 应用）一份：同一用户在同一应用下有多个身份时共享一份；已有范围会被新保存的整体覆盖。

**D. 生效校验**
1. 切到目标身份（切换后整页刷新，权限快照重新读取），在顶部应用切换里确认出现对应应用；菜单可见性来自服务端，不是前端写死。
2. 进入应用后列表为空且提示“当前没有可查看的数据范围”，说明范围未设或为空（fail-closed）；设好后重新切换身份。

**E. 撤销（演示 DEC-043）**
1. “用户授权”列表目标行点“撤销”，抽屉标题“撤销此身份？该用户的共享数据范围会保留。”，点“保存”。
2. 撤销后再按 C 段查询同一应用，范围仍在；再按 B 段重新授予即可复用范围。
