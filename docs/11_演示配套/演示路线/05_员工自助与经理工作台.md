## 路线概览

这条路线给产品 / 客户演示“员工自助”和“经理自助”两个入口：员工在自助里看自己的档案与任职记录、发起本人调动，申请进入审批后，直线经理在管理者工作台看到团队成员、待办并跳转审批中心。两个入口都只显示服务端按本人权限裁剪后的数据，不由前端硬编码角色。

| 步 | 身份 | 页面 | 一句话 |
|---|---|---|---|
| 1 | 平台研发员工甲（演示） | 员工自助 → 我的档案 /self | 只读档案，标有“演示数据”的人员子集分区 |
| 2 | 平台研发员工甲（演示） | 员工自助 → 人事申请 /self/applications | 任职记录列表，发起“本人调动申请” |
| 3 | 平台研发员工甲（演示） | 员工自助 → 我的申请 /self/requests | 新单“审批中”，种子里被驳回的 TRF-13 |
| 4 | 平台研发部经理（演示） | 管理者工作台 /manager | 团队分类计数、下属档案搜索、演示布局卡片 |
| 5 | 平台研发部经理（演示） | 团队成员 /manager/team | 分类、搜索、高级筛选、成员信息抽屉 |
| 6 | 平台研发部经理（演示） | 待办 /manager/todos | 待处理 / 已处理 / 已申请，前往审批中心 |
| 7 | 平台研发部经理（演示） | 人事申请 /manager/applications | 他人调动申请入口（经理发起的口径） |

## 前置准备

- 启动：`pnpm demo`（写入种子并起后端 :3000 与前端 http://localhost:5173）；要回到干净数据用 `pnpm demo:reset`（先停掉 `pnpm demo`）。
- 身份切换：顶部黄色“本地演示”条的“切换演示身份”下拉；员工甲默认跳到 `/self`，平台研发部经理默认跳到 `/manager`。顶部“注释”开关打开后，页面显示“原站做法 / 我们的取舍 / DEC / 实现档位”。
- 授权：种子已给这两个身份授好权，不需要现场授权。员工甲靠自动持有的“员工”身份，经理靠“经理身份（组织员工）”；两者都没有 HR 的调动管理入口。
- 与路线 04 的关系：本路线现场会产生一张员工甲的新单，路线 04 的经理待办里也会因此多一行；两条路线可单独演示，不会互相阻塞。

## 步骤 1：我的档案（只读）

- **演示身份**：平台研发员工甲（演示）
- **页面与路由**：员工自助 `/self`（菜单“员工自助”，分组“工作台”；`/self/profile` 同页），页内导航“我的档案”
- **操作**：进入后停在“我的档案”；看头部（头像摘要、姓名、部门、“工号：DEMO004”）；点“查看详情”打开右侧抽屉看“任职信息”页签后关闭；回到页面，依次点上方页签“人员信息”“任职记录”（后者会跳到“人事申请”，先点回“我的档案”）；点页面右侧的锚点“工作履历”“教育经历”“家庭成员”；点右上“刷新”。
- **讲解要点**：注释层 `self.profile`：原站“我的档案”是头像摘要、横向页签、双列字段分区加右侧分区导航；我们复用 FE-0 主题与详情抽屉，真实档案只读，按本人接口裁剪（DEC-456 / DEC-470 / DEC-057，实现档位 L2）。页面写明“我的档案为只读；人事变动请通过人事申请发起。”。“工作履历”“教育经历”“家庭成员”三个分区带金色“演示数据”标签：种子没有人员子集数据，页面标有“演示数据”，是合成样例（“合成示例公司”“合成示例大学”），不是真实业务数据，不会写入业务（演示桩 apps/web/src/demo-stubs/self-service.ts）。
- **预期结果**：“员工信息”分区只有“姓名”“工号”两项；“任职信息”分区显示部门（平台研发部）、职务等；三个演示分区可见，家庭成员显示“暂未接入”空态；抽屉标题为员工姓名。
- **高亮目标**：头部“工号”与“查看详情”按钮；“员工信息”分区下方的只读说明文字；“工作履历”分区标题旁的“演示数据”标签；页面右侧锚点导航。

## 步骤 2：人事申请与本人调动申请

- **演示身份**：平台研发员工甲（演示）
- **页面与路由**：员工自助 → 页内导航“人事申请”，路由 `/self/applications`
- **操作**：点页内导航“人事申请”；观察列表上方蓝色提示“可以在当前页面查看您的任职变动信息”和右上按钮；鼠标悬停灰色的“离职申请”“新增兼职申请”看提示；点蓝色“本人调动申请”；在抽屉里“调动日期”保持默认（今天），“调动原因”不选；在“新部门”下拉选“前端开发组”，留意“新直线经理”自动带出；点“提交”。
- **讲解要点**：注释层 `self.applications`：原站人事申请展示任职变动列表，顶部发起本人或他人调动；我们的按钮读取现有权限，未确认命令在页面级只读锁定，刷新由用户确认后主动执行（DEC-456 / DEC-205 / DEC-402 / DEC-464，L2）。表单与 HR 端是同一张，按字段权限裁剪（DEC-205）：员工端默认只有调动日期（必填）、调动原因、原 / 新部门、原 / 新直线经理、职务、职级、职务序列，没有异动类型、薪资、合同、试岗、带编；职务、职级、职务序列对员工只读，“新直线经理”只能从新部门及其上级链选（DEC-209，有意收紧）。“离职申请”“新增兼职申请”置灰，提示“当前自助入口尚无对应后端能力”，演示时说成“规划中”，不要现场点。
- **预期结果**：列表是员工甲自己的任职记录，列含“姓名”“开始日期”“结束日期”“审批状态”及部门等字段；抽屉标题“本人调动申请”，表单里“员工：”后是本人姓名，“任职调整”分区是“原部门 / 新部门（必填）”成对字段，底部只有“提交”按钮，下方说明“新直线经理可从新部门及其上级链的在职员工中选择；职务、职级和职务序列只读。”和一个禁用的“兼职调整”区；提交后抽屉关闭，页面顶部出现绿色提示“申请已提交审批，请在“我的申请”核对。”。
- **高亮目标**：列表右上“本人调动申请”按钮及灰色的“离职申请”“新增兼职申请”；抽屉里“原部门 / 新部门”成对字段；“提交”按钮；顶部绿色成功提示。

## 步骤 3：我的申请：新单与被驳回的 TRF-13

- **演示身份**：平台研发员工甲（演示）
- **页面与路由**：员工自助 → 页内导航“我的申请”，路由 `/self/requests`
- **操作**：点页内导航“我的申请”；看列表；点最新一行“调动申请”的标题链接，在右侧抽屉“申请信息”页签里看“审批状态”和任职信息；关闭后再点较早一行（5 天前）打开对比。
- **讲解要点**：“我的申请”是只读七列表格（标题 / 类别 / 发起人 / 当前处理人 / 审批状态 / 申请理由 / 申请时间，注释层 `self.applications` 的原站做法）。较早那条就是种子 DEMO-TRF-13：员工甲本人提交、调往数据研发部，被经理驳回（审批意见“演示：信息不全，请补充后重新提交”）；员工在自助里只能看状态，驳回意见在审批中心里看。普通员工在界面上没有“撤回”按钮，这是 README 演示注意事项的第③处；撤回单由 HR 发起并撤回（种子 DEMO-TRF-15，路线 04 展示）。“当前处理人”体现审批流：新单的处理人是平台研发部经理（直接上级审批节点）。
- **预期结果**：列表至少 2 行，新单状态“审批中”，TRF-13 状态为驳回类（预期显示“已退回”）；抽屉标题为“调动申请”，页签“申请信息”，含“审批状态”和任职信息明细。
- **高亮目标**：列表“审批状态”与“当前处理人”两列；最新一行的标题链接；抽屉“申请信息”页签。

- **预期结果**：“团队成员”卡片右上有“全部”链接；五个分类按钮各带数字（以服务端为准）；点“在岗人员”或搜索后，右侧弹出标题为“在岗人员”或“下属档案搜索”的抽屉，内含“成员信息”分区的团队列表；左侧“待办”卡片已有数据（见步骤 6）；四张演示卡片可见。
- **高亮目标**：“团队成员”卡片的分类计数按钮；“下属档案搜索”卡片的搜索框与“搜索”按钮；四张带“演示数据”标签的卡片；页内导航条。

## 步骤 5：团队成员列表

- **演示身份**：平台研发部经理（演示）
- **页面与路由**：管理者工作台 → 页内导航“团队成员”，路由 `/manager/team`
- **操作**：点页内导航“团队成员”；“人员分类”下拉依次选“全部”“试用中”；在“姓名 / 工号 / 邮箱”框输入“员工甲”回车；点“高级筛选”，在右侧抽屉里选“人员分类”，点“确定”；点结果里姓名链接打开“成员信息”抽屉；点右上“刷新”。

- **高亮目标**：“人员分类”下拉；搜索框；“高级筛选”链接；姓名链接；“成员信息”抽屉。

- **高亮目标**：列表上方“待处理 / 已处理 / 已申请”页签；列表“当前节点”列；抽屉右上“前往审批中心”按钮。

- **讲解要点**：经理走的是“他人调动申请”，表单与 HR 端同一张，字段按经理的字段权限裁剪（DEC-205）；经理给自己部门的员工发起的单，直接上级审批节点就是经理本人，自审回避会把本人跳过、转给异常管理员，种子 DEMO-TRF-04 / 05 就是这样的单（路线 04 步骤 6 展示）。没有经理发起资格的身份进入该页会看到“暂无访问权限”。不建议现场提交，以免制造新的异常管理员待办。

- **高亮目标**：页面右上“他人调动申请”按钮；抽屉里“按姓名搜索员工”框与“调动人员”下拉；页面说明文字。
