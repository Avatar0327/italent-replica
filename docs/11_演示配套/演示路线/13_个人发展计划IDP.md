## 路线概览

这条路线讲 IDP 在复刻系统里的完整闭环：HR 先定义“发展计划流程”（三个子流程串联，每个子流程引用审批中心里一条已发布的审批流），再做“发展计划模板”（基本信息、关键信息、发展目标、回顾、总结评价等模块），发布模板后为员工发起“发展计划”，计划按子流程分阶段推进，HR 可做流程干预。给 HR、人才发展团队看。

| 步 | 身份 | 页面 | 一句话 |
|---|---|---|---|
| 1 | HR专员（演示） | /idp | 取得 IDP 管理权限后进入应用（当前无身份可授，已实点验证入口不可见） |
| 2 | HR专员（演示） | /idp 发展计划流程（暂定） | 新建发展计划流程，配置三个子流程 |
| 3 | HR专员（演示） | /idp 发展计划模板（暂定） | 新建模板，配置模块与通用目标 |
| 4 | HR专员（演示） | /idp 发展计划模板（暂定） | 发布模板并复制 |
| 5 | HR专员（演示） | /idp 发展计划（暂定） | 为平台研发员工甲新建发展计划 |
| 6 | HR专员（演示） | /idp 发展计划（暂定） | 开始计划，查看阶段与当前步骤 |
| 7 | HR专员（演示） | /idp 发展计划（暂定） | 流程干预：催办、跳转、开启下一阶段、终止 |

4. 步骤 6、7 需要审批流程可用：开通租户时预置“标准制定计划流程”“标准中期回顾流程”“标准期末回顾流程”（`packages/domain/src/approval/presets.ts`；本演示库里是否已发布、在审批中心是否可见未核实），节点为员工本人 → 指导人，且 IDP 流程默认不做自审回避（DEC-318、DEC-332①）。
5. 打开顶部栏“注释”开关（FE-R3d 登记注释层后才会出现 IDP 页面级卡片）。

## 步骤 2：新建发展计划流程与三个子流程

> 状态：待 FE-R3d 合入后核对（本步全部按规格推断；当前无身份可进入 /idp，无法实点）。

- **演示身份**：HR专员（演示）
- **页面与路由**：/idp，发展计划流程（暂定）
- **操作**：
  1. 点“新增”，填“名称”演示发展计划流程、“所属组织”选“研发中心”，“向下公开”选“是”，“启用”选“是”。
  2. 添加三个子流程：名称“制定计划”、类别“制定计划”、关联审批流程选“标准制定计划流程”，开启方式“手动”；名称“中期回顾”、类别“回顾”、关联“标准中期回顾流程”，开启方式“自动”、开启规则“相对时间：参照点 计划开始时间，后 90 天”；名称“期末回顾”、类别“回顾”、关联“标准期末回顾流程”，开启方式“自动”、不设规则（= 上一阶段结束即开启）。
  3. 保存。
- **讲解要点**：
  - 规格 IDP-R1 / R2：流程 = 多个子流程串联，每个子流程引用审批中心一条已发布流程（审批类型按 idp_plan / idp_mid_review / idp_final_review 隔离，DEC-017，不跨类型兜底）；开启方式自动或手动，自动规则可固定日期、相对时间（参照计划开始 / 结束、上一阶段结束、任职记录生效时间；当天 / 前 N 天 / 后 N 天）；自动开启统一在凌晨 2 点（租户时区，DEC-296⑤ / DEC-056）。
  - 流程被模板引用后不能再改子流程顺序和开启方式（IDP-R5），也不能删除；审批流的修改只对未开始的子流程生效。
  - 子流程审批流选项只列已发布的 IDP 类型流程，这也是为什么开通时要预置三条标准审批流。
- **预期结果**：保存成功后列表新增“演示发展计划流程”，所属组织“研发中心”（可能回显 ID），启用；详情里依次看到三个子流程及其开启规则说明文本。
- **高亮目标**：列表右上“新增”；表单里的子流程列表区域（“关联审批流程”“开启方式”字段）；保存后详情的子流程顺序。

> 状态：待 FE-R3d 合入后核对（本步全部按规格推断；当前无身份可进入 /idp，无法实点）。

- **操作**：
  1. 点“新增”，填“名称”2026年度员工发展计划模板、“所属组织”选“研发中心”、“向下公开”选“是”、“发展计划流程”选“演示发展计划流程”，保存。
  2. 进入模板详情的模块配置区：确认固定存在的“基本信息”模块；添加“发展目标”模块（勾选允许自定义目标、允许从库引用，开启“目标回顾”“制定任务”）、“回顾”模块、“总结评价”模块。
  3. 在“发展目标”模块下添加一个“通用目标”：名称“提升跨团队沟通能力”，衡量标准“每季度至少主导一次跨团队评审”，发展建议“参加沟通技巧培训”。
- **讲解要点**：
  - 规格 IDP-R6 / R7：模板名称不能重复（重复时提示“模板名称已存在”），只能选启用的流程（否则“只能选择启用的发展计划流程”）；基本信息模块固定不可删；其他模块类型：关键信息、综述、盘点结果、发展目标、回顾、总结评价，每种在一个模板里只能有一个。
  - IDP-R8：发展目标的来源有自定义目标和胜任力库目标；胜任力来源五选（当前职位、继任职位、轮岗职位、拟晋升职位、所属人才池），其中所属人才池取出池标准（G-056，用户已确认）；人才池、盘点结果模块依赖 R3-T06 / 盘点，首版口述。
  - IDP-R9：通用目标只对之后新发起的计划生效，已发起的计划不变（AC-IDP-04）；各流程节点上的按钮（新增 / 编辑 / 删除目标、编辑模块内容）按节点配置（DEC-296④）。
- **预期结果**：模板详情出现“基本信息”“发展目标”“回顾”“总结评价”四个模块，通用目标列表有 1 条；模板状态为草稿（暂定，对应 status 非 published）。
- **高亮目标**：模板表单的“发展计划流程”下拉；模块列表与“基本信息”固定模块；“发展目标”模块下的通用目标区域。

## 步骤 4：发布模板与复制

> 状态：待 FE-R3d 合入后核对（本步全部按规格推断；当前无身份可进入 /idp，无法实点）。

- **操作**：
  1. 在模板详情或列表行点“发布”（对应按钮 publish），确认。
  2. 再点“复制”（对应按钮 copy），得到一份副本，修改名称为“2026年度员工发展计划模板（副本）”。
  3. 对副本点“取消发布”（对应 unpublish）或“删除”演示收回。
- **讲解要点**：
  - 只有已发布的模板才能用来发起计划（“只能用已发布的模板新建发展计划”）；发布时会校验所引用的流程仍启用，流程里的审批流如被弃用会提示 IDP_APPROVAL_PROCESS_DISCARDED（子流程的审批流需要重新选）。

  - 复制是原站已有能力，复制得到的是新模板（新模板不继承被引用状态）。
- **预期结果**：原模板状态变“已发布”（暂定）；复制后列表多一条副本；副本可取消发布或删除，已发布且被引用的模板删除会被拒绝。
- **高亮目标**：模板行或详情页的“发布”“复制”按钮；状态列“已发布”标识。

  1. 在新计划行点“开始”（对应按钮 start），确认。
  2. 打开计划详情，看“阶段”（子流程）列表和“当前阶段 / 当前步骤”。
  3. 切到 平台研发员工甲（演示），找到“制定计划”待办，进入后填写发展目标并提交；再切到 平台研发部经理（演示），审批该计划。
- **讲解要点**：
  - 开始后第一个子流程开启，生成一条审批流实例并给员工本人发待办（节点链：员工本人 → 指导人，DEC-318 K-37 / K-39）；IDP 不做自审回避是因为员工处理自己的节点是正常路径，回避开关是节点级、IDP 预置流程默认关闭（DEC-332①）。
  - 阶段状态：待开启 / 进行中 / 已结束 / 开启失败；上一阶段结束、下一阶段未开启的空档，当前阶段显示“努力提升中”（IDP-R4）；每天定时任务按租户时区凌晨开启当天应开启的子流程，失败的记“开启失败”并可由 HR 手动开启（AC-IDP-08）。
  - 无目标校验：发展目标模块开启该开关后，员工未建目标就提交会被拒绝（AC-IDP-05）。
- **预期结果**：计划状态变“进行中”；阶段列表第 1 个“制定计划”进行中，当前步骤为员工填写节点，执行人“平台研发员工甲”；员工提交后当前步骤转到指导人“平台研发部经理（演示）”。
- **高亮目标**：计划行 / 详情的“开始”按钮；详情里的阶段列表与“当前阶段”“当前步骤”字段；员工待办入口（待核对）。

## 步骤 7：流程干预

> 状态：待 FE-R3d 合入后核对（本步全部按规格推断；当前无身份可进入 /idp，无法实点）。

- **演示身份**：HR专员（演示）
- **页面与路由**：/idp，发展计划（暂定），列表或详情上的“流程干预”入口（暂定）
- **操作**：
  1. 勾选进行中的计划，依次演示“催办”“转交”“跳转”“开启下一阶段”“终止”（对应按钮 urge / transfer / jump / startNext / terminate）。
  2. “开启下一阶段”时若当前有进行中的阶段，选择“跳过”或“结束当前阶段再开启下一阶段”。
  3. “跳转”选当前子流程内的某个节点，填原因。
- **讲解要点**：
  - IDP-R16：跳转只能在当前子流程内，不能跨阶段；在阶段第一个节点时不能向前跳（AC-IDP-02）；转交受管理单元限制，会撤回原待办、给新人发待办（审批中心里管理员不得代签，DEC-063，与这里的 HR 干预是两件事）；“开启下一阶段”提前启动手动或自动阶段。
  - 所有干预都写审计，记录动作、原因、阶段和跳转目标节点（DEC-321）；终止用于人员离岗时暂停培养，保留计划，回岗后可再发起（IDP-R14）；已结束的计划 PDF 导出首版延期。
  - 学习计划、测评关联、IDP 看板、AI 发展专家均为暂停项（规格 28 §3）。
- **预期结果**：催办后员工收到提醒（通知状态以后端为准）；跳转后当前步骤变为所选节点；开启下一阶段后阶段列表第 2 项进入进行中；终止后计划状态变“已终止”，不能再修改。
- **高亮目标**：列表勾选框与顶部“流程干预”按钮组；干预弹窗里的“原因”“目标节点”字段；详情里的阶段列表状态变化。
