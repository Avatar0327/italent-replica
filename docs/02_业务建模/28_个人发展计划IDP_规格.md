> 取证：2026-09-28，A0 只读。
> - 配置证据 🟢：`IDP` 23 个对象；本租户 发展计划 88、模板 11、流程 3、职业发展信息 5、轮岗信息 7、带教信息 0
> - 官方文档 🟡：HRSAAS 124027089、124027190、124027204、124027211、123241889、123241891、124027216、76874301、76874303
> - 边界：IDP 是独立应用 `IDP`，挂在「继任与发展」菜单下（`16` §6）；DEC-009 以继任与发展为唯一入口，IDP 随之纳入

## 1. 结构

```
发展计划流程 IDPProcess（名称、所属组织、向下公开、启用）
 └─ 子流程 SubProcess（顺序、类别（制定计划 / 回顾 / 总结评价）、关联审批流程、开启方式、开启规则、结束通知模板）
发展计划模板 IDPTemplate（名称唯一、所属组织、向下公开、流程、发布状态）
 ├─ 模块 IDPTemplateModule（基本信息（固定）/ 关键信息 / 综述 / 盘点结果 / 发展目标 / 回顾 / 总结评价；模块配置、排序）
 └─ 模板通用目标 IDPTemplateCommonGoal（模块、名称、衡量标准、发展建议、学习计划）
发展计划 Idp（员工、模板、流程、开始 / 结束时间、状态、当前阶段 / 步骤 / 执行人、下个阶段及开启方式、指导人 / 指导人角色、流程实例）
 ├─ 发展目标 IdpGoal（模块、目标名称、衡量标准、发展建议、起止时间、是否通用目标、来源类型、学习计划）
 │    ├─ 任务 Task（负责人、参与人、审批人、评价人、起止、可见范围）
 │    └─ 目标回顾 GoalReview（目标进度、工作成果、附件）
 ├─ 综述 Analysis（现状分析、待发展项）
 └─ 回顾 Review（总结、改进方法）
关键信息来源：职业发展信息 Career、轮岗信息 WorkShift、带教信息 TutorShip、储备人才信息（人才池）
```

## 2. 规则（🟡）

### 2.1 流程
| # | 规则 |
|---|---|
| IDP-R1 | 发展计划流程 = 多个**子流程**串联，每个子流程引用审批中心一条**已发布**流程（预置三条：制定计划、中期回顾、期末回顾；节点为员工与指导人） |
| IDP-R2 | 子流程开启方式：**自动**（无规则 = 上一阶段结束即开启；或按固定日期；或按相对时间：参照点 = 计划开始 / 结束时间、上一阶段结束时间、任职记录生效时间、自定义日期字段，前 N 天 / 后 N 天 / 当天）或**手动**（HR 点“开启下一阶段”） |
| IDP-R3 | 系统**每天零点**查找当天应开启的子流程；因审批流校验失败（节点异常、找不到待办人）未能开启的，记为开启失败，需 HR 查明后手动开启 |
| IDP-R4 | 上一阶段结束、下一阶段未开启的空档期，计划的当前阶段 = “**努力提升中**”；自动开启的阶段可由 HR **提前手动开启** |
| IDP-R5 | 被模板引用的流程**不能改子流程顺序和开启方式**；审批流的修改只对未开始的子流程生效 |

### 2.2 模板
| # | 规则 |
|---|---|
| IDP-R6 | 模板名称不能重复；只能选启用的流程；可复制；默认向下公开 |
| IDP-R7 | 基本信息模块固定不可删；关键信息取计划**起止时间内有交集**的职业发展、轮岗、带教、储备人才记录 |
| IDP-R8 | 发展目标来源：自定义目标；胜任力库目标（人才标准指标），胜任力来源五选：当前职位、继任职位（最后修改的继任记录的目标职位）、轮岗职位（计划结束时间往前第一条轮岗）、拟晋升职位（计划结束时间往前第一条职业发展信息）、所属人才池（最近修改的储备人才记录所在池的**出池标准**；🟢 原站实测 T-406 确认取出池标准，复刻照搬，G-056 ✅） |
| IDP-R9 | 模板通用目标：HR 在模板中统一设置，只对**之后新发起**的计划生效 |
| IDP-R10 | 发展目标模块开关：目标回顾（总开关）、制定任务、**无目标校验**（无目标时不能提交）；各步骤角色可设 可见 / 新增 / 编辑 / 删除 |
| IDP-R11 | 盘点结果模块：只取**已结束**盘点项目中、流程未终止的盘点结果；时间基准可选盘点项目开始或结束时间，取计划开始或结束时间之前的结果；可限定盘点分类 |
| IDP-R12 | **模板被引用后**：不能增删模块，只能改基本信息、关键信息、发展目标模块；模块设置的修改对已生成的计划**实时生效**（本租户页面提示） |

### 2.3 计划（HR 端）
| # | 规则 |
|---|---|
| IDP-R13 | 新建计划：选员工、指导人（指定角色或指定人）、模板、起止时间；也可导入（新增 / 更新 / 新增或更新，按“员工 + 计划名称”判重）或从人才池发起 |
| IDP-R14 | 状态：**未开始 → 进行中 → 已结束**，另有**终止**（人员离岗时暂停培养，保留计划，回岗后再发起） |
| IDP-R15 | HR 可批量导入发展目标、给**使用同一模板**的计划统一下发任务（模板不同须分开下发） |
| IDP-R16 | 流程干预：**跳转**（只能在**当前子流程内**跳，不能跨阶段；在阶段第一个节点时不能向前跳）、**转交**（受管理单元限制，撤回原待办、给新人发待办）、**跳到下一步**（不能跨阶段；已是最后一个节点或下一节点未开启时失败并说明原因）、**开启下一阶段**（勾选中有进行中阶段的：可选“跳过”或“结束当前阶段再开启下一阶段”）、**催办** |
| IDP-R17 | 已结束的计划可导出 PDF（按打印模板，异步打包）；删除**不可恢复** |
| IDP-R18 | 员工端驳回：在节点详情页配置“跳转”按钮并改名为“驳回”（本质仍是子流程内跳转） |

### 2.4 关键信息维护
| # | 规则 |
|---|---|
| IDP-R19 | 带教信息：带教人、被带教人、起止时间；判重键 = 带教人 + 被带教人 + 起止时间 |
| IDP-R20 | 职业发展信息：发展员工、当前与拟晋升的 职位 / 职务 / 职级、条线、优势项、待发展项、意向城市、起止；判重键 = 员工 + 起止时间 |
| IDP-R21 | 轮岗信息：员工、轮岗部门、职位、职务、导师、起止；轮岗部门与职位的选择范围受**管理单元**限制；判重键 = 部门 + 职位 + 职务 + 起止 |
| IDP-R22 | 以上三类新增 / 导入时，员工须在「员工选择」实体的数据权限内 |

## 补充：IDP 枚举与子流程配置（Q-M0-115，2026-10-08，A0，只读）

- 发展计划状态 `IdpStatus`：未开始 = 0、进行中 = 1、已结束 = 100、已终止 = 200。“当前步骤”字段也用这个数据源。
- 批量开启下一阶段时，对已有进行中阶段的处理 `StartNextSubProcessType`：不处理进行中的发展计划 = 0、结束进行中的阶段并开启下一阶段 = 1。
- 指导人角色 `IDP.TutorRole`：直线经理 = 1、间接经理 = 2、第三 / 四 / 五级主管 = 3 / 4 / 5、导师 = 6、部门HRBP = 11、部门负责人 = 12、其他人 = 0。与人才池的枚举**不同**。
- 子流程 `SubProcess` 的枚举：
  - 类别：制定计划 = 1、回顾 = 2、总结评价 = 3。
  - 名称（关联审批流程）：制定计划 = 1、中期回顾 = 2、末期回顾 = 3。
  - 开启方式：自动开启 = 1、手动开启 = 100。
  - 发起时间类型：固定时间 = 0、相对时间 = 1。
  - 始于：当天 = 0、前N天 = 1、后N天 = 2。
  - 参照时间点：发展计划开始时间、发展计划结束时间、上一阶段结束时间、任职记录.生效时间。
- 本租户 14 条子流程实例（共 6 条流程）显示：
  - 开启规则会生成说明文本，形如“上一流程结束后自动开启”，或“于〈参照时间点〉当天 / 前 5 天的**凌晨 2 点**自动开启”。
  - 一条流程通常是 制定计划 → 中期回顾 → 期末回顾。各阶段可以分别设成手动或自动。
  - 子流程名称可以改（如“JDB制定计划”），名称与类别不必一致（有一条“期末回顾”的类别是“制定计划”）。
- 开关参数 `IDP.SwitchParameter`：新建目标时允许从胜任力库中选择（是 / 否）、胜任力对标数据（`IDP.CompRelaDataType`）。
- 未做：模块配置 JSON 的结构、流程干预的限制（需写入）。

### 模板模块配置结构（Q-M0-115 ④，2026-10-08，A0，只读）

  - `canDefinition` 允许自定义目标；`canRefFromLibrary` 允许从胜任力库引用；`compencyLibrarySource` 引用来源（样本为 3）。

## 补充：流程干预入口（Q-M0-115 ⑥，2026-10-08，A0，只读）
- 入口：继任与发展 → 人才发展计划 → 发展计划（`IDP.Idp`，视图 `IDP.SingleObjectListView.IdpList`）。页签：未开始&进行中 / 已结束的计划 / 已终止的计划。A0 可见 7 条计划，都是真实人员的计划；W-114 为 A5 建的 IDP_01 **不在 A0 的列表中**。
- 顶部按钮：新增、开始、**流程干预 ▾**（催办 / 跳转 / 开启下个阶段 / 终止计划）、导入导出、更多。列表上的干预菜单**没有**“转交”“跳到下一步”（IDP-R16 列了这两项，可能在详情页或流程管理页，未查）。
- 「跳转」弹窗：跳转至节点（下拉，必填）、跳转原因；保存 / 取消。下拉候选在本次未展开（选中的是真实人员的计划，只看不改）。
- 「开启下个阶段」：勾选计划后，直接弹气泡确认“确定开始吗？”（否 / 是），**没有**“跳过 / 结束当前阶段”的选择框。IDP-R16 说的二选一可能只在当前阶段进行中、且下个阶段为手动开启时才出现，未确认。本次点“否”，未执行。
- ⑥ 的限制（跨阶段跳转、跳过与结束当前阶段的区别）要实测，就得对一条计划执行干预，会给计划执行人 / 指导人派待办。A0 能看到的计划都属于真实人员，W-114 的测试计划 A0 看不到 → **按规则跳过**。如需实测，可让 A5（W-114 的发起账号）登录后对 IDP_01 执行。

## 补充：发展计划流程、子流程与审批流（Q-M0-115 ③，2026-10-08，A0，只读）
- **三层结构**：发展计划流程（`IDP.IDPProcess`）→ 子流程（`IDP.SubProcess`，按排序 1/2/3，类别 制定计划 / 回顾 / 总结评价）→ 每个子流程关联一条**审批流程**（配置中心 app = IDP，审批类型“发展计划”，对象“发展计划”）。
- 发展计划流程列表（`IDPProcessesList`，A0 可见 2 条）：DZ-IDP流程（2026-09-02）、测试流程（2022-10-09，计划列表里引用最多）。字段：名称、所属组织、是否公开、是否已使用。
- 子流程共 14 条，分属 6 个流程 ID（其余 4 个流程不在 A0 的列表视图里）。开启方式与规则：
  - 测试流程：制定计划 手动开启 → 中期回顾 于上一阶段结束当天凌晨 2 点自动 → 期末回顾 同上。
  - DZ-IDP流程：三段都“上一流程结束后自动开启”。
  - 其他流程：有“于发展计划开始时间当天 / 前 5 天的凌晨 2 点自动开启”和纯手动的组合；子流程可配“流程结束消息通知模板”。
- **审批流（配置中心，app = IDP，5 条已发布）**：
  | 审批流 | 编码 | 节点（处理人） | 出口动作 |
  |---|---|---|---|
  | 制定计划 | MakePlan | 开始（流程所有者）→ 制定发展目标（发展计划 - 姓名 = 员工本人）→ 审批发展计划（发展计划 - 指导人）→ 结束 | 员工：同意 / 跳转到指定节点；指导人：同意 / 驳回 / 退回上一步 / 跳转到指定节点 |
  | 中期回顾 | MidReview | 开始 → 员工中期回顾（员工本人）→ 指导人中期回顾（指导人）→ 结束 | 同上 |
  | 期末回顾 | FinalReview | 开始 → 员工期末回顾 → 指导人期末回顾 → 结束 | 同上 |
  | JDB制定计划（租户） | NewCode20260107181503780 | 在“制定计划”基础上加 HR审核（公共变量“JDB制定计划-HR审核”） | HR：退回上一步 / 跳转到指定节点 / 同意 |

## 补充：#115 R3-T07 PR-B 口径核对（K-35 / K-37 / K-38 / K-39，2026-10-08，A0 只读）
来源：配置中心审批流 MakePlan（制定计划，`/WorkFlow/ProcessV2/Get?app=IDP&operateType=LAYOUT`）的节点配置原值；另比对了 中期回顾、JDB制定计划，以及继任与发展的 5 条审批流。

**K-37 员工填写节点算不算审批节点、有没有自审回避**
- 算审批节点：“制定发展目标”的 activityType = 3（审批节点），与“审批发展计划”（指导人）同类型。处理人 = 汇报关系“发展计划 - 姓名 - 员工本人”。
- 两个处理节点的跳过开关**全部关闭**：`isSameAssigneeSkip`（同一审批人跳过）= false、`isHistorySameAssigneeSkip`（历史审批人跳过）= false、`isSameExpressionSkip`（满足表达式跳过）= false。开关打开时的跳过结果预置为“同意”。
- 开始节点处理人 = 流程所有者（`owner`），也没开跳过。
- 节点级的 `isAddSign`（加签）、`isRetweeted`（转交）、`isCopySend`（抄送）都是 false，所以本租户不存在“会签 / 转交 / 加签之后要不要回避”的情形。HR 的“转交”走的是流程干预，不在审批节点上。
- 结论：原站 IDP 不做自审回避，员工处理自己的节点是正常路径；回避是按节点可配的开关，默认关。对复刻：R1 引擎的“自审跳过”、F-048 的多主体回避，要做成节点级开关，IDP 预置流程默认关，否则员工节点会被自动跳过。

**K-38 发起人、处理人为空时怎么办**
- 发起人 = 开始节点的“流程所有者”（`assignee.variable = owner`），即计划的所有者（Onwer，通常是建计划的 HR，或从人才池发起的人），不是员工本人。
- 处理人为空：`noAssignee.type = 0`，其他审批流同值处带文字“**无操作**”。也就是不自动跳过、不转给管理员；推断流程会停在该节点，或提交时报错（🟡 未实测）。
- 与 DEC-098（无上级时的处理）对照：原站这里是“无操作”，不是自动兜底给 HR。若复刻定为“退回给 HR”，属于复刻自定，需登记差异。
- K-38 第 2 步（给无账号员工建计划并启动）没做：只读结论已能定“原站不兜底”，实际报错文案需要实测才能拿到。

**K-39 驳回 / 撤回 / 重提 / 审批中编辑**
- 员工节点：出口只有“同意”（意见必填）和系统动作“跳转”（只能跳到指导人节点）；`isRejectToStart`、`isRejectToPrevious`、`isAborted`（终止）、`isRevoke`（撤回）、`isRetrieve` 都是 false。
- 指导人节点：同意（意见必填）/ 驳回（意见不必填）/ **驳回到上一步**（`isRejectToPrevious = true`，`isResubmitThisActivity = false`，即重新提交后按正常顺序走，不直接回到驳回人）/ 跳转（只能跳到员工节点）；`isRevoke` = false。
- 撤回（`isRevoke`）是节点级开关，本租户关闭，但**不是被禁用的功能**。审批中能不能编辑，由节点表单上配置的按钮决定（新增 / 编辑 / 删除目标等，见上文）。
- 结论：原站有驳回、驳回到上一步、跳转、流程干预；撤回能配置但默认关；重提就是被驳回后重新提交“同意”。没有证据显示这些操作被平台禁用 → 按用户“提示、不拦截”的偏好，复刻不禁用，只做节点开关。
- 附：消息规则——员工“同意”后给指导人发邮件“审批计划通知”（`isSendEmail = true`）；跳转、驳回各有待办模板。

**K-35 轮岗判重与关键信息字段**
