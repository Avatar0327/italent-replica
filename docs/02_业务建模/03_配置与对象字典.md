## 2. 配置提取方法（已验证可行）

原站所有列表页由两个通用接口驱动，登录态下可直接读取**配置元数据**：

| 接口 | 方法 | 返回 |
|---|---|---|
| `/api/v2/UI/IndexPage?metaObjName=<对象>&app=<应用>&viewName=<视图>` | GET | 页面组件树：布局、搜索表单、控件类型、按钮、导航视图、列定义 |
| `/api/v2/UI/TableList?viewName=<列表视图>&metaObjName=<对象>&app=<应用>` | POST | 列配置（`sub_cmps` 中的 `MetaColumn`）+ 分页 + 排序 + 视图默认过滤条件 |

**用途**：对纳入范围的每个对象，用这两个接口取出列/字段/控件/按钮/默认条件，作为配置证据；再用 UI 实操验证规则是否真的生效。
**限制**：接口返回的是**该账号该视图**的配置，不等于对象的全量字段定义；也不代表规则在运行时的实际行为。

## 4. 权限条目

### PRM-001 A0（何份晓）的实测权限边界
| 对象 | 结果 | 证据 |
|---|---|---|
| `UserFramework.User` | ✅ 可读（列表 226 条） | IndexPage 200 + TableList 200 |
| `UserFramework.UserPermissionV2`（用户授权） | ✅ 可读 | IndexPage 200 |
| `UserFramework.AdminPermission`（管理员） | ✅ 可读 | IndexPage 200 |
| `UserFramework.Mou`（管理单元） | ✅ 可读 | IndexPage 200 |
| `UserFramework.Organization`（组织） | ✅ 可读 | IndexPage 200 |
| `UserFramework.Position`（职务） | ✅ 可读 | IndexPage 200 |
| `MetaDataManagement.ProfileV2`（身份管理） | ❌ **403 拒绝** | `{"code":"403","message":"只有机构运营人员有权查看数据!"}` |

**结论（重要）**：菜单里**能看到**「身份管理」，后端**拒绝**访问。
→ 证实「菜单可见 ≠ 有权限」，且 **A0 不是无限权限的管理员**：平台运营级配置（身份定义）保留给北森自身运营人员，租户管理员不可见。
→ 复刻规划必须把「租户管理员权限」与「平台运营权限」分成两层，不能把 A0 当作系统最高权限来建模。
**限制**：此结论基于接口层探测，`身份管理` 的 UI 入口行为（是否给出友好提示）尚未实测；也未验证是否有其他路径可查看身份。

**结论**：原站字段是**两层模型**：存储类型（8 种）× 控件（约 30 种）。同一种控件可以落在不同的存储类型上，例如“员工单选”既可以存为整数（UserID），也可以存为长整数；“单选列表”可以存为字符串编码，也可以存为整数。多选控件（员工多选、复选框、部门多选）一律按字符串存（多值拼接）。
**复刻要求**：字段元数据分为 `data_type`（存储）和 `widget`（控件）两列；多值字段建议改用数组或关联表存储，不照搬原站的字符串拼接（实现建议，不改变业务行为）。
