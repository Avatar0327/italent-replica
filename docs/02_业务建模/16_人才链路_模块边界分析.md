## 2. 官方手册的归属（目录结构 🟡）

| 功能 | 手册中的位置 | 推断 |
|---|---|---|
| 在线盘点 | **继任云 → 继任-设置 → 在线盘点设置-继任**（18 节点）；继任云常见问题「在线盘点的应用场景」 | 在线盘点是**继任云内的一个配置子域**，不是独立产品 |
| 人才标准 | **继任云 → 继任-其他功能 → 人才标准模块**（含人才标签库） | 人才标准挂在继任云下 |
| 人才评定 | **人事云 → 任职资格管理 → 人才评定**（18 节点） | 人才评定是**任职资格的评定环节** |
| 人才模型 | **测评云 → 测评中心介绍 → 配置和使用人才模型** | 人才模型服务于**测评**，与盘点链路无直接关系 |
| 标签库 | 人才标准模块 → 人才标签库；数字人才 → 人才标签 | 标签库横跨人才标准与数字人才 |
| 360度评估 | **测评云 → 360度评估系统** | 属测评云 |

## 3. 配置中心应用清单（🟢）
配置应用中有 `继任与发展`、`人才标准`、`人才模型`、`任职资格`、`人才评定`、`360评估反馈`、`标签库`、`数字人才`，**没有独立的「在线盘点」应用**。
应用编码注册表同样无独立编码（`SuccessionAndDevelopment`=继任与发展）。

## 4. 待登录后核实的唯一事实
**「在线盘点」菜单组下各菜单项的 `appName` 是否为 `SuccessionAndDevelopment`。**
- 若是 → 两个菜单组是**同一应用的两套入口**（大概率新旧版或两种使用场景），首版只需做一套
- 若否 → 需进一步看是否两套独立数据

核实方式：A0 登录后，在菜单注册表 `getallbyuser` 中过滤菜单组「在线盘点」取 `appName`。

## 5. 建议（待你确认）

### OPEN-004 建议
| 方案 | 内容 |
|---|---|
| **建议** | 以**「继任与发展」为唯一入口**建设盘点/人才池/继任；「在线盘点」不单独建设，其独有的「盘点校准会」「组织人才分析」并入继任与发展 |
| 理由 | 手册把在线盘点放在继任云的设置子域下；配置中心无独立应用；同名功能 4 项重叠，做两套是重复建设 |
| 人才标准 | 作为**独立模块**建设（有独立菜单组、独立配置应用、独立身份「人才标准管理员（人才标准）」），被任职资格、盘点共同引用 |

### OPEN-006 建议
| 模块 | 建议 | 理由 |
|---|---|---|
| 人才评定 | **纳入**（作为任职资格的子功能） | 手册中就是任职资格管理的一部分，任职资格已纳入首版 |
| 人才模型 | **暂缓** | 服务于测评云，测评不在首版 |
| 标签库 | **暂缓** | 横跨数字人才，数字人才不在首版；人才标准内的标签可先用简单字段 |
| 360度评估 | **维持纳入**（DEC-002 已决），但注意它属测评云，依赖题库/套卷/评价关系，工作量不小 |

## 6. 登录后核实结果（2026-09-22）🟢
菜单注册表中各菜单组菜单项的 `appName` 分布：

| 菜单组 | appName 分布 |
|---|---|
| **在线盘点** | `SuccessionAndDevelopment` × 25、`TalentCenter` × 1 |
| **继任与发展** | `SuccessionAndDevelopment` × 38、**`IDP` × 8**、`TalentCenter` × 1、`PeopleAnalytics` × 1、`TenantBase` × 1 |
| 人才标准 | `TalentCenter` × 4 |
| 人才评定 | `TEvaluation` × 13 |
| 任职资格 | `Qualification` × 10 |

**结论**：「在线盘点」与「继任与发展」是**同一个应用 `SuccessionAndDevelopment` 的两套入口**。第 5 节建议成立。
附带发现：「继任与发展」下的「人才发展计划」属于独立应用 **`IDP`**（个人发展计划），首版若纳入继任与发展，需明确 IDP 是否一并纳入。
