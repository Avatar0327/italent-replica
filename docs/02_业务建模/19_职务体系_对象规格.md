# 职务体系：对象规格（R1-T04）

> 来源：配置证据。数据来自 `GetMetaFieldList?app=TenantBase&metaObjName=<对象>`，2026-09-22 只读获取，账号 A0。
> 下表只列业务字段，已剔除系统记账字段（创建人/修改人/时间、删除状态、所属单元、多语言名称等）。`*` 表示本租户的自定义字段，按 DEC-005 **不复刻字段实例**，仅作为“自定义字段示例”。
> 注：`TenantBase.JobPosition` 返回 0 个字段；职位对象的实际编码是 `TenantBase.Position`。

## 1. 对象关系

```
职层 JobLayer ──< 职等 JobGrade（等级、评估分上下限）
职级类别 JobLevelType ──< 职级 JobLevel（级别；开始职等~结束职等）
职务序列 JobSequence（树，最多 10 级，冗余一级~十级序列）── 关联职级类别
专业条线 ProfessionalLine（树）
职务 JobPost：序列、条线、职级类别、最低~最高职级、最低~最高职等、胜任力模型、关联任职资格
   └──< 职位 Position：所属组织、对应职务、直线/虚线/预留 3–5 维度上级（职位树，多维）、编制数与在岗统计
任职记录 → OIdJobPost / OIdJobPosition / OIdJobLevel / OidJobGrade / OIdJobSequence / OIdProfessionalLine
```

**所有职务体系对象都有 `StartDate`/`StopDate`/`Status`**，与组织对象一样是**带生效期的主数据**。每个对象都有 `LUQualificationData`（关联任职资格），这是与人才链路「任职资格」模块的接口（见 16）。

## 2. 各对象字段

| 对象 | 标准业务字段 | 要点 |
|---|---|---|
| **职层** JobLayer | 名称、层级 `JLaLevel`、生效/失效、状态 | 最简单的字典 |
| **职等** JobGrade | 名称、等级 `Grade`、评估分下限/上限 `ScoreLow/ScoreHigh`、职层 `JobLayer`、排序编码 | 职等可以由**岗位评估分**区间推出 |
| **职级类别** JobLevelType | 名称、顺序、生效/失效、状态 | 如 管理类 / 专业类 |
| **职级** JobLevel | 名称、级别 `Level`、职级类别、**开始职等 / 结束职等**、排序编码 | 一个职级对应一段职等区间。本租户自定义了薪资上限、中位、下限值 |
| **职务序列** JobSequence | 名称、上级序列 `POId`、层级、**一级~十级序列**（冗余祖先）、关联职级类别、顺序、数据来源、外部 ID | 树形；冗余祖先列用于按“一级序列”做编制维度（见 18 §7） |
| **专业条线** ProfessionalLine | 名称、上级条线、顺序 | 树形 |
| **职务** JobPost | 编码、名称、职务序列、专业条线、职级类别、**最低 / 最高职级**、**最低 / 最高职等**、胜任力模型、职责描述（多语言）、任职要求、关键职务、涉密职务、设立日期、评估总分、在岗人数、兼职数、**同步序列到任职** | 本租户自定义了 14 个字段（干部属性、能力要求等） |
| **职位** Position | 编码、名称、**所属组织**、**对应职务**、职位序列、专业条线、职级类别、最低 / 最高职级、职等、工作地点、**直线上级 / 虚线上级 / 预留维度 3–5 上级及各自顺序号**、标准职位、职位共享范围、关键职位、涉密职位、编制数、实有人员、预增员、预减员、超缺编、在岗人数、兼职数、创建职位方式、复制职位（范围、来源组织、复制后动作）、停用职位时的人员转移、调整员工直线经理、同步序列到任职 | 职位 = 组织 × 职务的实例化；**职位自身是一棵多维汇报树**（与组织的 5 维对应）；职位上直接挂编制统计 |

## 3. 对复刻的要求

1. **职位树决定汇报线**：`POIdPositionAdmin`（直线上级职位）与 `IsChangePOIdEmpAdmin`（调整员工直线经理）说明，原站可以由**职位上下级推导员工的直线经理**。这与任职记录上的 `POIdEmpAdmin` 是两条来源。**DEC-011（2026-09-27）：两者并存，由开关「调整员工直线经理」控制是否按职位树同步**（验收 AC-JOB-05）。
2. **区间约束**：职务的 最低~最高职级 / 职等，职级的 开始~结束职等，是任职时的**合法性约束**来源。**实测（2026-09-28，AC-JOB-01）🟢**：任职表单上是**选项过滤**——选定职务后，「职级」下拉与「全部查找」只列级别在区间内的职级（按级别数值比较），区间外职级根本选不到；导入 / 接口是否同样拦截未测 ⏸。复刻：表单按区间过滤候选，服务端保存时再校验一次（防导入 / 接口绕过）。
3. **停用级联**：停用职位时可以指定“人员转移到”哪个职位，也就是说**停用会触发人员批量转岗**。**DEC-016：有在岗人员时禁止停用**，不做自动转移。
4. **同步序列到任职**（`SyncSeqToRecord`）：职务或职位的序列变化时，是否把新序列写回员工的任职记录。这属于向后更新类行为，与 07 附录 A 的规则衔接。
   - **2026-10-03 只读取证（Q-M0-16，A5）**：两种触发方式。① 职务 / 职位上的字段「同步序列到任职」（`SyncSeqToRecord`，是 / 否；新建时隐藏、编辑时可改），字段说明原文：“用于修改序列之后是否同步任职记录的设置，如果选择是则更新职务之后会自动更新任职记录/Offer上的序列”；② 列表按钮「同步职务序列到任职」（`SyncJobPostSeqToRecord`，接口 `JobPost/syncJobPostSequenceToRecord`，勾选职务后执行）与「同步职位序列到任职」，确认框原文：“系统会将使用了选中职务的任职记录/Offer上的序列同步为职务的序列”（手册 HRSAAS 126746793、126746820）。即范围按“引用该职务 / 职位的任职记录与 Offer”，不是按值匹配，也不经向后更新规则。
   - 🟡 仍未确认：“使用了该职务的任职记录”是否包含历史记录和未来记录，是原地改写还是另生成新版本。要确证需写入实测（改一个测试职务的序列后同步，看各时段记录），需先征得用户同意。
5. **职位重名（Q-M0-02，2026-09-30 🟢 本租户配置证据）**：开关 SwitchType 83「同一部门下的职位允许重复」（视图 `TenantBase.DuplicatePositionNameAllowedWithinTheSameOrg`，设置页：组织员工 → 设置 → 组织 → 职位名称规则），本租户 **未启用**（`IsEnable=否`，系统出厂值，2024-11-15 创建后未改）。即：**同一部门下职位名称不允许重复**；开关只约束同一部门，跨部门同名不受此开关限制。复刻（DEC-062）：做成租户开关，出厂按本租户取值预置为“关”。🟡 待证：重复判定是否只比对启用中的职位、是否区分有效期——开发时按“同部门、启用中的职位名称不重复”实现，并在 AC-JOB-06 标注。
6. **业务编码（DEC-060，2026-09-30）**：职务、职位等对象的主键用系统 ID，`编码`字段单独存放、按租户唯一；从北森导入时保存“原站编码 ↔ 内部 ID”映射并检测冲突（冲突不覆盖，列清单处理），验收 AC-ORG-12（同一机制）。
7. 设立日期只作记录（DEC-040；DEC-053 维持，不采纳 GPT 方案）。
8. 首版范围（DEC-001 R1 固定配置）：职层、职等、职级类别、职级、职务序列（建议不超过 3 级）、专业条线、职务、职位。职位的“复制”“共享范围”“预留维度 3–5 上级” ⏸。
