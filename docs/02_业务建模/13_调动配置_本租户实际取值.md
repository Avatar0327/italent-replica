| SwitchType | 开关名 | 本租户状态 | 官方说明（原文摘录） |

### 2.1 ⚠️ SwitchType 31 的边界规则（易漏）
> **「调动后部门不受权限控制」只对标准产品表单生效，对自定义表单不生效。**
>
> 即：同一个开关在**标准表单**上放开权限控制，在**自定义表单**上仍受控。
> 复刻必须把这条边界写进需求，否则会出现"开了开关但某些表单仍受限"的不可解释行为。
> → 影响验收场景 **AC-TRF-19 / AC-TRF-20**，需补充"标准表单 vs 自定义表单"两个分支。

### 2.2 SwitchType 98 的连带效应（新发现）
> 调动时调整组织角色 → **自动为对应组织生成一条"组织变更记录"**。
>
> 说明**调动业务会写入组织对象的变更历史**，不只写任职记录。
> 组织也有自己的版本/变更记录链条。→ 新缺口 **G-023**：组织变更记录的对象与结构未取证。

### 2.3 SwitchType 95 的依赖链
> 依赖「公共设置 → 任职信息联动薪资范围」开关。
> 说明开关之间存在**依赖关系**（A 开了 B 才有意义）。
> → 复刻的开关模型需支持**依赖声明**，否则会出现配置组合无效但无提示。→ 新缺口 **G-024**

### 3.1 观察
1. **调动类型有生效日期与状态**，是**有时效的字典**，不是静态枚举。
   → 复刻的字典模型必须支持 `生效日期 + 启用/停用`，而不是简单的 code-value 表。
   → 操作列为 `编辑 / 停用 / 删除`（停用与删除是两个不同动作）。
2. **显示顺序可重复**（多个类型都是 1、2、3…），且部分为空（`--`）。
   → 排序不是唯一键；空值的排序行为待验证。
3. `YG*` 前缀的 6 个类型集中创建于 2026-05-22，明显是某次演示/测试批次的自定义类型。
   → 按 **DEC-005** 口径，这些属于**演示数据**，复刻首版**不纳入**；
   　 标准类型（跨部门调动、职务职位调整、职级调整、部门内调岗、工作地调整、汇报关系调整、跨单位调动、晋升/晋级/平调/降职/降级）为**标准**。
   → `合同主体变更` 与 `调动` 标 **待定**，需确认业务语义。
4. 与调动管理视图上的 20 个按钮**不是一一对应**：
   - 按钮里有 `外派申请`、`跨公司调动申请`，调动类型里对应的是 `YG跨公司调动`，没有"外派"
   - 调动类型里有 `平调`、`降级` 等，按钮里没有独立入口
   → **调动类型（字典）与调动按钮（功能入口）是两套独立配置**，多对多。缺口 **G-025**：两者如何绑定未取证。

页面说明原文（三条）：
1. 启用调动交接流程前，请先确认调动交接流程与调动审批流程已配置完成
2. 启用后，可以在调动管理中手动发起调动交接流程
3. **如果在调动申请流程中配置调动工作交接的节点，建议关闭此调动交接流程开关**

**C-007 结论（2026-09-28）**：A1 的跨部门调动（调动日期 09-20，审批通过 09-28）没有自动发起交接，原因是**生效日期早于审批通过日期，而附加选项未勾选**。这是规则的正常行为，不是缺陷。
自动发起的完整判定：
1. 开关开启，并勾选「自动发起」；
2. 异动类型在业务范围内（本租户仅跨部门调动）；
3. 到达时机：审批通过时，或审批通过后距生效日 N 天；
4. 生效日期 ≥ 审批通过日期；否则仅在勾选附加选项、且 当前日期 − 生效日期 ≤ 30 天时发起。

→ 原站有**两种交接设计**：独立交接流程（本租户采用）或在调动审批流内加交接节点。二者**互斥**。

### G-037 字段场景别名（2026-09-27 🟢 关闭）
- 证据：「调动中员工」列表接口（`TableList`，视图 `TenantBase.SingleObjectListView.EmployeesInTransferListView`）返回的列定义中，`cmp_name = TransitionTypeOID` 的列 `title = "调动类型"`；而同一字段在对象元数据（`GetMetaFieldList`）里的标签是「异动类型」（`15` 字段规格）。
- 结论：**“别名”是视图层（列表列 / 表单项）对字段显示名的覆盖**，字段本身只有一个标准标签。组织的「利润中心 / 产品维度」同理：字段是预留维度 `Reserve3`，显示名由多维度组织设置（开关页 SwitchTypes 88~92）或视图配置决定（`10` §8）。
- 复刻要求：视图定义里每个列 / 表单项都允许覆盖显示名（可多语言），对象字段保留唯一的标准标签；导出、日志、接口统一使用字段编码和标准标签，避免同一字段在不同地方名字不一致而产生误解。
