## 1. 主线

```
[Offer] 新建（社招 / 校招 / 实习；来源：新增人员 / 实习生转正 / 校招生提前实习）
   → Offer 审批（单个 / 批量多单 / 批量一单）→ 发送（邮件 / 短信 + 附件 + 答复链接）
   → 候选人接受 / 拒绝（或 HR 转移状态）
   → 同步待入职（时机可配）
[待入职] 添加 / 导入 / 扫码添加 / Offer 同步 → 信息采集、入职材料、入职准备事项、背调、电子签
   → 改期 / 取消入职
   → 入职（直接）或 入职申请（审批）→ 生效：员工信息 + 任职记录（入职）+ 合同 + 薪资 / 社保（⏸）
[新员工融入] 方案（阶段 + 任务）→ 入职后自动或手动发起 → 办理人处理任务
```

## 2. Offer

### 2.1 状态
待发 Offer（未发起审批 / 审批中 / 审批通过 / 不通过）→ 已发 → 已接受 / 已拒绝 → 已入职；另有**失效**。

| 可转移 | 转移后 |
|---|---|
| 待发 | 已接受、已拒绝 |
| 已发 | 待发、已接受、已拒绝 |
| 已接受 | 已拒绝；**未同步待入职**时可手动到已入职 |
| 已拒绝 | 待发、已接受 |

已接受 → 待发 须先经过已拒绝；已发或已接受转为已拒绝时，若已有待入职记录，**联动取消待入职**。

### 2.2 规则（🟡）
| # | 规则 |
|---|---|
| OF-R1 | Offer 上维护 基本信息、任职信息、合同、薪资、社保；同步待入职时按固定映射写入 员工信息 / 任职记录 / 合同 / 薪资档案 / 社保档案（字段清单见手册 113742961） |
| OF-R2 | 新建时校验：证件号、手机号、邮箱与离职人员重复 → 重聘提示（按重聘判定规则）；姓名 + 手机 / 邮箱 / 证件号命中**黑名单** → 不能入职；身份证号带出出生日期、性别、籍贯、户籍 |
| OF-R3 | 按 Offer 类型设置「发送前须审批通过」；开启后才能设置**必审字段**（非必填字段） |
| OF-R4 | **必审字段**：审批通过后修改必审字段须再审。开关「审批通过允许再次发起审批」开 → 直接重新发起（已发：作废候选人链接、状态回待发，已有待入职 → 取消入职，进行中电子签撤销；已接受：同样回待发并取消试工 / 入职）；关 → **失效原 Offer 并复制一份新 Offer 发起审批** |
| OF-R5 | 发送：可选 Offer 通知模板（按模板适用范围精确匹配；只有一个可用时自动带出）、附件模板（可加密，密码插入通知）、自定义附件、抄送 / 密送；可暂存 |
| OF-R6 | 候选人答复：接受 → 已接受；开关「候选人完成电子签署后才视为接受」开且发了电子签 → 须完成签署才变已接受；拒绝 → 已拒绝。**答复链接有效期**默认 15 天（1–30，修改对历史 Offer 生效） |
| OF-R7 | **失效**：可对 审批通过 / 不通过的待发、已发、已接受、已拒绝 Offer 操作；失效后答复链接失效；有待入职记录时二次确认后**删除待入职**；失效 Offer 可复制重发 |
| OF-R8 | **同步待入职时机**（开关，默认开）：发送时 / 接受时 / 接受且距入职日 ≤ N 天（1–90，默认 30，由每晚定时任务补同步）；关闭则手动“立即同步”。在职实习生的正式 Offer 是否同步可单独关（改走实习转正；已离职的实习生不受此开关限制） |
| OF-R9 | 取消入职后是否把 Offer 改为已拒绝（开关，默认开） |
| OF-R10 | **编制 / 预算管控**：表单可显示编制信息；按占编时机和严格控制做强 / 弱控；**候选人接受不校验**，但同步待入职时强控超编则**同步失败**；**批量操作不校验**（与 DEC-015 一致） |
| OF-R11 | **招聘需求人数管控**：剩余可关联 Offer 数 = 需求人数 − 已到岗 − 流程中 Offer 数（去重）；新建时 ≤ 0 视为超出，编辑 / 审批时 < 0 视为超出；强控拒绝，弱控提示；批量操作按招聘需求打包校验，超出则该需求下全部失败 |
| OF-R12 | 按 Offer 类型匹配表单（新建、编辑、发起审批、查看统一用该类型的表单；类型为空按社招） |
| OF-R13 | **授权模式**六选一：应聘职位 且 管理单元 / 应聘职位 或 管理单元 / 管理人 或 管理单元 / 仅应聘职位 / 仅管理单元 / 仅管理人（管理人 = 创建人或共享人；可设不受限身份） |

## 3. 待入职与入职

### 3.1 规则（🟡）
| # | 规则 |
|---|---|
| EN-R1 | 视图：全部待入职（入职状态 ≠ 取消）、今日待入职（入职日或报到日 = 今天）、已取消、已入职 |
| EN-R2 | 来源：Offer 同步、添加、**导入（新增 / 重聘入职 / 编辑 三种分开，防止误合并）**、扫码添加（二维码有效期默认 30 天，最长 365） |
| EN-R3 | **信息采集**：自动 / 手动（单个、批量）/ 扫码；免登录或手机验证码（扫码找不到手机号时用 姓名 + 身份证号验证）；按人员范围（员工信息 / 任职 / 合同公司的白名单字段）+ 优先级匹配采集模板和**必填子集**；可走审批；可自动催办；信息采集时填与离职人员相同的证件号 → HR 收到“离职重聘待确认”待办 |
| EN-R4 | **入职材料**：按规则生成每人的材料清单（必备 / 非必备、可补交）；状态：无材料 / 未提交 / 未交齐 / 已交齐 / 已收齐 / 无必备；HR 可确认接收、催办；入职后可自动催办（每天 6–7 点，每人每天一次） |
| EN-R5 | **入职准备事项**：事项 = 类别（分配工号 / 分配邮箱 / 其他）+ 办理表单 + 规则（适用范围 → 办理人：指定人 / 角色（直线上级、部门负责人、HRBP）/ 高级（职位、职务、身份））；同一事项多个办理人时**任一人办完即完成**，其他人待办撤销并通知；可合并待办、批量办理；办理结果按编码映射回写员工信息 / 任职记录 |
| EN-R6 | 入职准备**自动发起**：同步到待入职时，或入职日前 N 天（新建时已在 N 天内也会发起）；**自动催办**：入职日前 N 天起每天催办未完成事项 |
| EN-R7 | **入职必备事项**（默认全关）：信息采集必须完成 / 指定材料必须提交 / 指定准备事项必须完成——未满足则**不能入职或发起入职申请**（批量入职时逐人校验，失败者提示） |
| EN-R8 | **改期入职**：联动更新试用期结束日期与合同日期；延后 → 入职状态 = 延期；通知入职准备负责人；**已取消入职的人也可通过改期恢复** |
| EN-R9 | **取消入职**：状态 = 取消，通知准备事项负责人；可发消息让候选人**撤回个人信息**（仅新增入职、信息采集已暂存 / 提交 / 退回 / 待确认重聘；撤回 = 清空员工信息除姓名、邮箱外的全部字段并删除全部子集，并在备注中写明）；重聘人员无权撤回 |
| EN-R10 | **入职 / 入职申请**：单个或批量（批量只改 人员、入职日期、邀请激活账号，改入职日期联动试用期与合同日期）；可暂存；可重聘合并；表单显示编制并按规则强弱控；审批支持合并待办和批量同意 / 不同意，可校验须完成入职电子签 |
| EN-R11 | 生效：审批通过且到入职日 → 按雇佣关系进入员工或实习生列表；有合同信息则生成合同；是否有试用期决定人员状态（试用 / 正式）；外部人员不走入职审批 |
| EN-R12 | **自动生成邮箱**：规则按 组织范围 + 附加人员条件 + 优先级匹配（**命中第一条即停止**，该条失败不再尝试下一条）；前缀字段 + 后缀，重名时在最大序号上 +1；前缀为空或含非法字符 → 失败并写失败原因；重聘入职 / 实习转正不生成；时机：发起入职准备时 或 入职 / 入职申请时 |
| EN-R13 | **重聘 / 返聘判定**：证件号固定为判定项，手机号、邮箱可选；重聘方式：合并人员（默认，档案连续）/ 生成新人员（劳动密集型）/ 手动选择（可设默认）；一经确认不可更改 |
| EN-R14 | 删除待入职**不可恢复** |
| EN-R15 | **入职管理授权模式**六选一（同 OF-R13，另有“仅管理单元”时法人公司取待入职阶段的合同） |

## 4. 新员工融入

| # | 规则 |
|---|---|
| ON-R1 | 任务池：类别 行政事项 / 团队融入 / 工作融入 / 新员工介绍 / 试用期考核（发起组织员工考核流程或绩效活动）/ 试用期目标（⏸）/ 学习计划（⏸）/ 其他；可自定义办理表单与流程；**被方案关联或已生成过任务的不能删除**；修改任务不影响已发起的计划（名称、说明等可选同步） |
| ON-R2 | 方案：名称、**优先级与范围不可重复**（组织范围 ∩ 附加人员条件）；命中多个取优先级最高；阶段与任务的开始 / 截止 = 入职后第几天 / 周 / 月；办理人 = 指定人 / 角色（部门负责人、直线上级、导师、HRBP）/ 高级 / 员工本人；可设员工是否可见；到期提醒天数（任务级优先于方案级） |
| ON-R3 | 自动发起：开关开启后，通过 入职 / 入职申请 / 批量入职 / 实习转正（含申请、批量）入职时，**入职后约 1 分钟**自动发起；计划发起时生成全部任务，开始日 ≤ 当天的立即“未完成”，其余由**每天 6:30** 的定时任务开启（开启时重新取办理人） |
| ON-R4 | 撤销计划：融入状态 → 已终止，已完成任务不变，其余任务终止；已完成的计划不能撤销；可重新发起（已完成任务不受影响） |
| ON-R5 | 离职生效时，融入计划与任务自动终止（`30` DM-R8） |
