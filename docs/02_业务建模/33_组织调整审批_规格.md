# 组织调整审批：规格（R2-T08，G-015）

> 取证：2026-09-28，A0 只读。官方文档 🟡：HRSAAS 116395120、259915794（一体化组织调整，新版）、116395124 / 29 / 32（组织调整申请，旧版）。
> 与 R1 衔接：组织对象 `10`、职位 `19`、编制 `18`、调动 `08`、兼职 `31`；组织变更记录 `OrganizationChange`（`17`）。

---

## 1. 两个版本

| | 旧版「组织调整申请」 | 新版「一体化组织调整」 |
|---|---|---|
| 调整对象 | 组织（新建 / 变更 / 停用）+ 由此联动的任职、职位、汇报关系 | 组织、**职位、编制、人员调动、兼职** 在一张单据里一起调 |
| 操作方式 | 表单添加明细，或拖拽生成明细；预览树状图 / 卡片图 | 左树右表拖拽调整 + 可编辑表格两种；预览含职位、编制、在岗、兼岗增减 |
| 不走审批 | — | 「组织调整」按钮直接生效（需灰度） |
| 状态 | 开通新版后**旧版不能再用** | 灰度，2025-07 起陆续迁移 |
| 本租户用哪版 | 🔴 待核（§5） | |

→ **建议复刻只做新版**（覆盖旧版全部能力），待用户确认。

## 2. 公共规则（两版一致）

| # | 规则 |
|---|---|
| OA-R1 | 单据：调整主题、**生效日期**（全部生成的组织、职位、调动记录都按此日生效）、调整范围、**审批主体组织**（审批流按它取审批人，数据权限也按它鉴权）、调整内容 |
| OA-R2 | 新建组织：编码按自动编码规则；行政维度顺序号默认 = 同级最大 + 1；层级默认 = 上级 + 1（可改） |
| OA-R3 | 变更组织时，若上级或名称变化 → 必填“**是否新增任职**”（是 = 为组织下人员结束旧任职、按生效日新增一条任职，用于追溯组织全路径） |
| OA-R4 | 若负责人变化 → 必填“**原负责人直接下属的直线经理调整为新负责人**”；若上级或负责人变化 → 必填“新负责人的直线经理是否调整”，是则默认 = 上级组织负责人 |
| OA-R5 | 停用组织：**同时停用全部下级**；可填“职位 / 人员转移到”目标组织 → 在目标组织下复制同名职位、把人员调动过去，原职位停用；新版支持**分批转移**（任职的组织 / 直线经理 / 虚线经理，职位的所属组织）；未填转移组织且组织下仍有任职 → 旧版：提交后提醒，审批完成前不处理则无法生效；新版：**不允许提交** |
| OA-R6 | 组织自定义字段要能调整：在调整明细对象上成对建“原字段（old+编码）/ 新字段（编码）” |
| OA-R7 | 审批中编辑：只允许当前节点审批人编辑审批中 / 驳回 / 草稿状态的数据；移动端只能改主表单，不能改明细 |
| OA-R8 | **生效处理**：调整数据量（组织、下级、职位、任职、编制）≤ 5000 → 审批完成即时处理；> 5000 → 次日 03:00 处理；生效日期在未来时先生成数据、到期才变“当前生效” |
| OA-R9 | 生效处理期间，涉及部门的员工**暂停** 入职、编辑任职、调动、转正、实习转正，以及所有人员 / 任职 / 调动类导入 |
| OA-R10 | 处理结果：全部成功 → 调整完成；部分失败 → 标记失败行及原因，修正后可“重新执行”；完成后通知申请创建人 |

## 3. 新版专有规则

| # | 规则 |
|---|---|
| OA-R11 | 典型场景与联动：新增部门（复制职位、定编、调入人员）；换负责人（不在本部门 → 调入或新增兼职并结束原负责人兼职，更新汇报关系）；更名 / 换上级（为部门人员生成新任职以追溯全路径；上级变化同时减原上级、增新上级编制）；停用（职位随人转移或停用；编制**全部**转移，不支持部分；人员转移；兼职结束或转移） |
| OA-R12 | 人员：员工调入（选人 → 调动可编辑表格，调动后直线经理默认 = 新部门负责人，若负责人是本人则取上级部门负责人；有同名职位自动带出，否则可新建或复制原职位）、拖拽调动、员工异动 |
| OA-R13 | 兼职：新增兼职；结束兼职（结束日期默认 = 生效日期 − 1） |
| OA-R14 | 编制：只能给**本单据新建的组织**新建编制 |
| OA-R15 | 调动**只调任职字段**，不支持变更合同、调薪、带编调动、试岗、职责转交 |
| OA-R16 | **数量上限**：组织明细 ≤ 100（被连带停用的下级也计入）；职位 ≤ 500；调动 ≤ 500（换负责人、停用转移生成的也计入）；兼职 ≤ 500 |
| OA-R17 | 提交分两段校验：组织类校验立即返回；其余异步校验，右侧进度条，失败可查看详情修正后再提交 |
| OA-R18 | 审批详情页：架构树 / 架构图预览（可导出）、按类别的明细列表（无数据的列表不显示）；可按节点配置可见列表 |

## 补充：单据状态与执行（Q-M0-119，2026-10-08，A0，只读）

- 列表视图 `TenantBase.SingleObjectListView.AddOrgAdjustListView`（一体化组织调整审批）共 42 条：
  - 新版：已暂存 10、审批中 6、审批通过且已执行 3。
  - 旧版（是否新版为空）：审批通过且已执行 19、已暂存 4。
- 枚举：
  - 审批状态 `TenantBase.ApprovalStatus`：草稿 = 0（列表显示“已暂存”）、审批中 = 1、审批通过 = 2、审批未通过 = 3、生效 = 4、作废 = 5、已驳回 = 6。
  - 执行状态 `ExecutionStatus`：未执行 = 1、已执行 = 2、执行中 = 3。
  - 明细调整类型：新增 = 1、变更 = 2、停用 = 3。
  - 明细执行结果：成功 = 1、失败 = 2。
  - 停用组织调编方式：各上级编制同步减少 = 1、编制转移至目标组织 = 2。
  - 半级组织：高半级显示 = 1、低半级显示 = 2。
  - 层级 1～10。
  - 明细另有：是否新增任职、原负责人的直属下级是否转交给新负责人、负责人的直线经理是否调整、更新下级层级、同步调整编制、是否分批转移、是否暂存。
- **生效时机（OA-R8）**：新版单据生效日期 2031-01-01、审批通过后**已执行**，执行备注“成功执行3个调整，失败0个调整”。即未来生效的单据在**审批通过时就执行**（落成未来版本），不是到生效日才执行。
- **部分失败**：旧版有一条“成功执行0个组织，失败1个组织”，状态仍为“审批通过 / 已执行”。失败不改变审批状态和执行状态，失败只在执行备注和明细执行结果里体现。“重新执行”入口未查。
- 执行备注的写法：新版“成功执行N个调整，失败M个调整”，旧版“…个组织”。
- 未做（需写入）：审批中锁定、驳回 / 撤回、编制联动。
