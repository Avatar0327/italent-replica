# 360 度评估：规格（R3-T03）

> 取证：2026-09-28，A0 只读。
> - 配置证据 🟢：`I360Cloud` 74 个对象（`01_证据/导出/R3_对象字段_配置证据.md`）；本租户 评估活动 44、套卷模板 11、报告模板 6；「人员」副本 0 条
> - 官方文档 🟡：HRSAAS 测评云 / 360 度评估系统（60981524 下 67 页），重点 118949521~118950343、180456603、200212729、210929280、211714170/72
> - 定位：DEC-002 纳入；属测评云，是**独立的一套人员与评价关系体系**，与组织员工通过“同步人员”衔接

---

## 1. 业务主线（官方“5 步”）

```
① 创建活动（基本信息、作答页设置、结果处理方式、授权）
② 设置套卷（关键行为 / 等级评定 / 民主推荐表 / 多选题；指标、题目、选项、角色权重、计分规则）
③ 设置评价关系（评价对象 → 选取套卷(1–3) → 设置评价者，可请上级 / 本人 / 他人确认）
④ 进程控制（启用活动 → 发邀请：邮件、短信、iTalent 待办 → 监控进度、催促、重新作答）
⑤ 结果（停用活动 → 数据筛选 / 屏蔽无效 → 计分 → 个人报告、团队报告、报表）
```

## 2. 对象（🟢）

| 对象 | 作用 |
|---|---|
| 活动 `ActivityCloud` / `Activity` | 名称、应用场景（单选标签）、状态（草稿 / 已启用 / 已停用）、评价形式（一次评价一人 / 一次评价多人）、欢迎语、多角色合并作答、作答不认真提醒、无效数据提示卡、屏蔽最高最低分、“手松手紧”事后控制、评价对象显示顺序、报告模板、活动持有人 / 转移人、计分批次 |
| 人员 `Personnel` | 360 自有人员副本：姓名、邮箱（唯一标识）、手机、部门、职位、上级ID、工号、北森ID、来源（活动录入 / 组织架构同步） |
| 评价对象 `ObjectRelation` | 活动 × 人员；评价者数量、已评价、无效任务数、他评得分、确认状态、顺序 |
| 评价对象套卷关系 `ObjectRelationQuestionnaire` | 评价对象 × 套卷（1–3 个） |
| 评价关系 `AppraiserRelation` | 活动 × 评价对象 × 评价者 × 角色 × 套卷；状态、是否有效 / 无效、是否同一选项、放弃作答率、单题作答时间、是否忽略、作答地址 |
| 评价关系确认者 `ConfirmRelation` | 确认者（上级 / 本人 / 其他）、确认状态、进度、是否完成 |
| 租户评价角色 `UserRoles` + 角色分组 `UserRolesGroup` | 内置 自评、上级、同事、下级、客户、其他；可扩展 |
| 套卷 `QuestionnaireInfo` → 维度 `DimensionInfo`（复合 / 基础指标）→ 维度指标 `Diemsnion` → 题目 `Question` → 选项 `QuestionsOption` | 套卷类型、评定方式、总分等级、优秀率 / 不合格率、参照标准 |
| 角色缺失时的替代权重 `IgnoreRolesWeightSet`；角色人数上限 `ActivityUserRoleMax` | |
| 进程控制 `ProgressControl`；高低分屏蔽记录 `HighLowRightInfo` | 发送状态、到达状态（邮件 / 短信 / 待办 / 企微）、进度 |
| 得分：题目 / 指标 / 问卷 × 总体 / 角色 / 二级角色；等级（Bars）得分与分布；排名 | 计分结果表 |
| 报告：评价对象报告 `ObjPersonReport`、团队报告 `TeamsReport`、报告模板 | |

## 3. 规则（🟡 官方文档）

### 3.1 套卷
| # | 规则 |
|---|---|
| E3-R1 | 四类套卷：**关键行为**（复合指标 → 基础指标 → 题目，评价者对题目打分，只支持加权平均，可录发展建议，适合发展 / 盘点）；**等级评定**（复合指标 → 基础指标，评价者对指标选等级，支持加权求和或加权平均，适合考核 / 民主测评）；**民主推荐表**、**多选题**（无分数，只统计频次，无报告与报表） |
| E3-R2 | 套卷状态：草稿 / 已启用 / **已使用**。草稿、已启用可删可改；已使用不可删，只能在活动为草稿或停用时局部修改。要大改：另存为模板 → 新建套卷 → 替换（替换会**清空该对象已有作答**） |
| E3-R3 | 一个活动套卷数量不限；**一个评价对象最多 3 个套卷**，至少 1 个；只能选“已启用”的套卷 |
| E3-R4 | 评价角色：内置 6 个，租户最多扩展到 90 个（另一处写 50，⚠️ 口径不一）；**单套卷最多 15 个角色（含自评）** |
| E3-R5 | 角色权重为 ≥0 的整数；**自评权重固定为 0**；他评角色权重不能全为 0，否则套卷不能启用 |
| E3-R6 | 选项最多 15 个；可设“不做评价 / 不计分”选项——**不计入统计，不按 0 分算**；可设选择某选项后必须补充说明 |
| E3-R7 | 等级评定：同一复合指标下的基础指标必须用同一套评定等级；基础指标权重之和 = 100%，不能全为 0；总分规则：仅 1 套等级且无不计分项 → 加权平均或加权求和；1 套含不计分项 → 只能加权平均；≥2 套等级 → 只能加权求和 |
| E3-R8 | 可按指标 / 题目限定评价角色（未勾选的角色不评该项） |
| E3-R9 | 优秀率 / 不合格率控制（仅“一次评价多人”）：例 满分 100、优秀线 90%、上限 20%、某评价者评 12 人 → 超过 90 分的人数 ≤ ⌈12×20%⌉ = 3 |
| E3-R10 | 题库 / 套卷模板被套卷引用后是**复制**：套卷里改内容不回写模板 |

### 3.2 计分
| # | 规则 |
|---|---|
| E3-R11 | **角色加权模式（默认）**：每个评价者：题目分 →(题目权重) 基础指标分 →(基础指标权重) 复合指标分 →(复合指标权重) 总分；角色分 = 该角色评价者分数**简单平均**；他评分 = Σ(角色分 × 角色权重) / Σ角色权重 |
| E3-R12 | **指标聚合模式**：先按题目算角色分，再逐层（题目 → 基础指标 → 复合指标 → 问卷）加权；有“无法评价”时两种模式结果会不同 |
| E3-R13 | **角色缺失**：默认把缺失角色的权重从分母中去掉（例 上 5 同 3 下 2，无下级 → (3.5×5+4.0×3)/8 = 3.69）；也可为“缺失某些角色”的情形单独配置一套权重 |
| E3-R14 | 屏蔽：可手工屏蔽某条评价关系，或批量屏蔽系统判定的“疑似无效数据”，均可恢复；被屏蔽的数据不参与计分。另有角色内去掉最高 / 最低分（灰度 ⏸） |
| E3-R15 | 报表与计分在**停用活动**后进行；改了权重、姓名、邮箱等需重新启用再停用以重算 |

### 3.3 评价关系与作答
| # | 规则 |
|---|---|
| E3-R16 | 评价对象来源：手动录入（姓名 + 邮箱必填）、从已有人员选、批量导入（可直接带套卷）；**一个活动最多 30,000 个评价对象** |
| E3-R17 | **一个评价对象最多 500 个评价者**（各角色合计）；**一个活动最多 50,000 个评价者** |
| E3-R18 | 按组织架构自动添加：上级 = 直线经理；同事 = 与其同一直线经理的人；下级 = 以其为直线经理的人；可设各角色人数上限 |
| E3-R19 | 可邀请 上级 / 评价对象本人 / 其他人（如 HRBP）**确认或自行设置**评价关系；上级、同事、下级、其他只能从内部员工中选，客户可手工录入；**确认后不可再改**，只能由管理员后台调整 |
| E3-R20 | 一个评价者在一个活动内只有**一个作答链接**（一封邮件、一条短信），iTalent 待办重复发送也只保留一条；停用活动前应“取消所有待办” |
| E3-R21 | 重新作答：管理员清空某评价者对某对象的作答，评价者用原链接重答 |
| E3-R22 | 作答页每 10 秒自动保存，支持断点续答；PC 与移动端均可 |

### 3.4 报告
| # | 规则 |
|---|---|
| E3-R23 | 个人报告：活动停用后生成 / 更新；可批量导出、转发给本人 / 直线上级 / 虚线上级（依赖汇报关系） |
| E3-R24 | 参照标准：同样套卷者得分的 80 分位（可改 50）、得分区间、以往活动得分（取最近一次）、手动指定 |
| E3-R25 | 团队报告：同一活动内、相同套卷或相同指标的人员才能组成；不跨活动 |
| E3-R26 | **匿名阈值（DEC-065）**：🟢 已取证（Q-M0-03，§7）——原站**没有**“最少评价人数”阈值，也不按人数隐藏分数：只在设置评价者页提示“建议各评价角色至少3人（上级和自评除外）”，同事角色仅 1 人时报表照样单列该角色分数。匿名相关只有活动级开关（作答页是否显示评价者姓名、是否显示评价角色）与报告模板“文本答案中是否呈现评价角色”。D-044 用户选①，已登记 **DEC-149**：照搬（不设阈值，给出同样提示，做两个匿名开关），取代 DEC-065 兜底 |

### 3.5 与盘点的衔接（`SuccessionAndDevelopment.Questionnaire360` 🟢）

## 7. 匿名与最少评价人数（Q-M0-03，2026-10-05，A5 只读）

来源：本租户 360 度评估系统（活动“创新意识问卷HTC”，已停用、结果已计算）与手册 118949540 / 118949589 / 118950535 / 118950490 / 210929280 / 204407503。

- **没有人数阈值设置**：活动「基本信息」只有“作答页评价者姓名（显示 / 不显示）”“评价角色是否显示（显示评价角色名称 / ……）”“评价形式”“评价对象分组规则”等；报告模板设置只能删减模块、设置“文本答案中是否呈现评价角色”（手册 118949540）。手册与升级日志中均未出现“最少人数”“人数不足隐藏”类配置。
- **只有建议提示**：「设置评价者」页顶部常驻提示“建议各评价角色至少3人（上级和自评除外），以增加匿名性和准确性”，不拦截保存。
- **实例**：评价对象 Tind3 的评价者为 上级 1 人（Tind1）、同事 1 人（Tind2）、自评 1 人；「报表 → 总分清单（行为）」仍分别列出 自评 4.5000、同事 5.0000、上级 3.8333、他评 4.4167，即**单人角色的分数照样单独呈现**。个人报告是 PDF 文件（需下载才能查看，未打开）；手册 118950535 说明个人报告开头的“评价关系表”会列出各角色参与人数。
- 角色缺失时的计分：缺失角色的权重从分子、分母同时去掉（手册 118950490 / 210929280），也可个性化配置缺失角色的权重。
- 对复刻：DEC-065 约定“取到证据就照搬，取不到才按 3 人阈值”。原站无阈值 → 照搬意味着首版不做“少于 3 人隐藏”，与 AC-360-16 的写法相反 → 登记册 **D-044**。

| 360 一般管理员 | 全部 | 同高级管理员（自己创建的 + 被授权的） | 与高级管理员的区别：能看到「人员」模块，但**看不到「从系统管理中同步人员信息」**功能 |
| 360 分子公司 HR-组织者 | 首页、评估活动、题库、设置（看不到人员、报表） | 被授权活动内只见 基本信息、套卷、评价关系、进程监控 | 进程监控里不能“重新作答” |
| 360 分子公司 HR-进度推进者 | 首页、评估活动、设置 | 活动内只有进程监控 | 不能“重新作答” |

- **数据范围**（169709769）：默认情况下，管理员能看到某活动就能看到活动内全部数据。可选开启“精细化权限”：系统管理员和实施顾问不受影响；其余 4 个身份只能看到数据权限范围内（管理单元、组织关系、汇报关系）的评价对象 / 评价者，人员模块同样按此裁剪。套卷和套卷模板可设“共享部门 / 共享人”，对高级、一般、组织者三个身份生效。
- **人员表可见范围**：默认（未开精细化权限）时，一般管理员能看到「人员」模块的全部人员；开了精细化权限后，只看到数据权限范围内的人员。手册没有提到按字段（如手机号）单独脱敏。
- **首位 360 管理员从哪里来**（74613839 / 28345212）：360 系统内**没有**“管理员设置”页。本租户 360「设置」下只有 通知模板设置、通信记录、报告模板设置、评价角色设置、应用场景设置。360 身份由企业设置后台授予：**「权限管理」→「用户授权」→「新增」→ 选业务用户 →「身份」选「360评估反馈」的相应身份 → 保存**。授权人是拥有后台“管理员”权限的企业管理员；找不到 360 应用说明本人没有该应用的授权权限。
- 复刻影响（R3-T03 暂定口径对照）：
  - 系统管理员管全部：一致。
  - 高级管理员：原站**只见自己创建或被授权的活动**，不是“全部活动”，暂定口径需改。
  - 一般管理员：活动范围同高级管理员；区别只在“人员同步”入口。
  - 人员同步、冲突处理仅系统管理员和高级管理员可做（一般管理员看不到同步入口）。
  - 首位管理员由企业管理员在权限管理里授予，与暂定口径一致。

**8.2 活动授权（新增 / 编辑活动的「基本信息 → 活动授权」区，说明文字“只有已授权用户才能看到此活动”）**
- 形态：双栏穿梭框「未授权用户 / 已授权用户」，按钮只有「添加 / 移除」，**没有“查看 / 管理”之分**。授权后，对方在活动内的能力完全由其 360 身份决定（见 8.1）。
- 可选范围：**只列持有 360 身份的用户**。新增活动时，左栏“未授权用户”只有 8 人且都是 360 高级管理员；右栏“已授权用户”默认 46 人，包括创建者（标注“创建者”）、全体 360 系统管理员，以及同时持有多种 360 身份的人。一般管理员和分子公司身份者是否出现在左栏，本租户没有样本（他们大多同时持有系统管理员身份，已在右栏）。
- 谁能授权：授权区是活动基本信息的一部分，能编辑这个活动的人就能改授权（创建者、系统管理员、被授权的高级 / 一般管理员）。手册没有单独限制；不同身份逐一实测需要换角色登录，未做。
- 活动列表行操作另有「移交」（转交活动所有权），与授权是两回事。

**8.3 作答页显示的默认值与完整选项（新增活动页，未保存）**
- 作答页评价者姓名（字段 IsHideAppPersonName）：**显示 / 不显示**，新增时默认 **显示**。
- 评价角色是否显示（字段 ShowRoleTypeInt，数据源 I360Cloud.ShowRoleTypeCategory）：**显示评价角色名称 / 显示固定文案 / 不显示评价角色名称**，只有这 3 项，新增时默认 **显示评价角色名称**。选“显示固定文案”时，另有文本字段 ShowRoleTypeDesc（显示固定文字时展示的内容）。
- 同页其他默认值：评价形式 = 一次评价多人（另一选项：一次评价一人；启用后不可改）；评价对象分组规则 = 按套卷和角色分组（另：仅按套卷分组）；评价对象显示顺序 = 按系统默认顺序（另：按评价对象列表顺序）；评价者忽略评价任务 = 不允许；作答过程不认真提醒 = 关；提交时不认真提醒 = 开（允许直接提交 / 必须重新作答）；无效数据提示卡 = 不显示。另有“基于已有活动创建：是 / 否”。
- 两个字段在表单元数据里都没有配置默认值；默认值来自 360 的自定义单选组件（@360/activity-extra-radio）。复刻可以在创建时用上述默认值，不必强制显式传入。
