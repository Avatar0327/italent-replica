## 1. 两个模块的定位

| | 人才标准 `TalentCenter` | 任职资格 `Qualification` |
|---|---|---|
| 回答的问题 | 某类岗位的优秀人才画像：**能力、潜力、经历**（另有“成就”说明） | 某个**任职类别**在每个**任职级别**上必须达到的能力标准，以及员工的发展通道 |
| 被谁引用 | 盘点项目（`Activity.人才标准Id`）、盘点模块（`Module.人才标准`）、人才池入 / 出池标准、IDP 发展目标、职位胜任力 | 人才评定（申请类别 / 级别、按标准明细打分）、盘点指标（`AssessItem.任职资格-指标`）、调动表单联查、员工发展通道、任职资格子集 |
| 本租户数据 🟢 | 人才标准 6、指标库 26、分类 1、描述设置 4 | 任职类别 75、任职级别 114、指标 380、任职资格标准 38、等级方案 6 |
| 数据权限 | 按管理单元（🟡 73045023） | 按**所属资源集合**分权：集团与各板块各管各的类别、级别、指标、标准（🟡 142345983） |

## 2. 人才标准（R3-T01）

### 2.1 对象
```
指标库 DimensionLibrary（类型 = 能力 / 潜力 / 经历）
 └─ 指标 Dimension（编码、名称、定义、分类、顺序、状态）
     ├─ 等级描述 GradeDescription（等级顺序、别称、说明）
     ├─ 行为描述 Behavior（行为描述、关键点、顺序）
     ├─ 发展建议 Description（类型、描述、顺序）
     └─ 面试问题 Question（问题、关键点、顺序）
人才标准分类 TalentCriterionCategory
人才标准 TalentCriterion（名称、分类、状态、模型图、测评方案 Lookup）
 └─ 人才标准里的指标 RelationTalentCriterionDimension（指标库、指标、指标类别、权重、目标、顺序）
人才标准说明 TalentCriterionDescription（能力 / 潜力 / 经历 / 成就 四段说明）
```

### 2.2 规则（🟡 官方文档）
| # | 规则 |
|---|---|
| TC-R1 | 指标库按 **能力 / 潜力 / 经历** 三类建立；指标库内可分类 |
| TC-R2 | 人才标准中的指标是**引用关系**：指标库里改了指标内容，人才标准里立即显示最新内容 |
| TC-R3 | **只有能力指标**可以设置权重和目标；潜力页签可以上传潜力模型图 |
| TC-R4 | 只有**已启用**的指标和指标库才能被人才标准引用 |
| TC-R5 | 被人才标准引用的指标**不能删除**；还有未删除指标的指标库**不能删除** |
| TC-R6 | 指标库导入须**整库一次性导入**，不支持增量导入 |
| TC-R7 | 人才标准可以关联测评方案，但只能选操作人有权限的测评方案（依赖测评中心，首版 ⏸） |
| TC-R8 | 标签库属于独立的标签能力（DEC-009 暂缓）；首版在盘点对象上用一个多选“标签”字段代替，**新盘点项目添加对象时自动带出上一次盘点的标签**（上一次 = 开始时间最接近的上一个盘点项目；开始时间相同时按对象创建时间取最近） |

## 3. 任职资格（R3-T02）

### 3.1 对象
```
任职类别分类 EmploymentCategoryClassify（最多 5 级，上级分类，编码，顺序号，所属资源集合）
任职类别 EmploymentCategory（编码、名称、所属分类、关联岗职务类型 + 关联岗职务数据、所属资源集合）
层级 Level  ──  任职级别 EmploymentLevel（编码、名称、顺序号＝从低到高、层级、关联岗职务类型 + 数据、所属资源集合）
指标类型 TargetType（多层级树，顺序号）── 指标 Target（编码、名称、指标说明、是否通用指标、评价方式＝评分/评级、等级方案、行业指标来源）
等级方案 GradeScheme ── 等级明细 GradeDetail（级别数字越大越高、分值、描述）
指标等级描述 TargetGradeDescription（指标 × 等级明细，是否修改等级描述）
任职资格标准 QualificationStandard（任职类别 1:1、任职级别范围、指标范围、生效日期、版本号、所属资源集合随类别）
 ├─ 任职资格标准明细 QualificationStandardDetail（类别 × 级别 × 指标：能力标准、目标值、权重%、学习课程、获取/过期时间）
 │    └─ 能力标准明细 AbilityStandardDetail（1–10 条：能力标准、目标值、目标等级、权重）
 ├─ 级别和指标对应关系 LevelTargetMapping（级别范围 × 指标范围）
 ├─ 级别描述 LevelDescription
 └─ 职业发展通道 DevelopmentChannel（任职类别 × 级别 → 发展方向、发展类别、发展级别、发展的任职资格标准）
编码规则 CodingRule（类别 / 级别 / 指标类型 / 指标 的前缀、起始序号、启用）
```
组织员工侧：人员子集「任职资格」、设置「同步任职资格」（`TenantBase`，🟢 菜单）。

### 3.2 规则（🟡 官方文档，另注明 🟢 者为配置证据）
| # | 规则 |
|---|---|
| QL-R1 | **任职类别**来源两种：从组织员工**引入**职务序列 / 职务 / 职位 / 职级类别（自动建立关联），或**新建**后手工关联岗职务数据（可一对多） |
| QL-R2 | **任职级别**来源两种：引入职级 / 职等，或新建。**顺序号定义从低到高**；新建时默认为当前最大顺序号 + 1 |
| QL-R3 | 编码：开启自动编码规则时自动生成、可手改；规则只能编辑（前缀、起始序号、启用），不能新增或删除 |
| QL-R4 | 指标必须挂在**指标类型**下；指标类型可多层级，不填上级即为一级；导入时先导类型再导指标 |
| QL-R5 | **通用指标**：指标说明带入标准的能力标准且**不可编辑**，改指标说明会联动所有标准；非通用指标：新建标准时带入一次，之后互不影响。非通用改为通用时，会用指标说明覆盖能力标准 |
| QL-R6 | 评价方式：**评分**时不能选等级方案；**评级**时必须选启用的等级方案，只有评级指标才能在标准中设置**目标等级** |
| QL-R7 | 等级方案名称不能重复；修改等级明细时联动指标等级描述：新增 → 为每个引用指标补一条；删除 → 删掉对应描述；编辑 → 只更新“未手工修改”的描述 |
| QL-R8 | **一个任职类别只对应一条任职资格标准**；标准的资源集合跟随类别，不可修改 |
| QL-R9 | 新建标准分两步：选类别、级别范围、指标范围 → 生成“级别 × 指标”网格，逐格维护能力标准、目标值、权重、课程；不同级别可以考察不同指标 |
| QL-R10 | 每个“级别 × 指标”有 **1–10 条**能力标准；通用指标的能力标准不可增删改 |
| QL-R11 | 导入的本质是导入**标准明细**：一行 = 类别 × 级别 × 指标（按编码）。**编辑导入会先删除该指标的全部能力标准，再按模板重建** |
| QL-R12 | 图谱：把一个类别所有级别的标准横向拉平查看，可导出 Excel；多选导出时每个类别一个文件，打成压缩包 |
| QL-R13 | 发展通道：纵向 = 本类别内级别晋升（默认）；在任一级别节点可以添加**多条横向**发展路径（到其他类别的某级别） |
| QL-R14 | 员工查看发展通道的**前提**是任职资格子集里有其当前类别和级别；点击任一级别可查看该级别的标准与关联课程 |
| QL-R15 | 🟢 原站实测补充（T-408，G-047）：自动同步时跨类型多命中**只生成 1 条**、无提示，取值顺序 **职位 > 职务序列 > 职级类别**；原站子集无来源标识，复刻增加「来源」字段（初始化 / 任职同步 / 手工）为增强项。**任职资格子集的生成**：① 初始化：按任职记录上的岗职务和起止日期一次性生成（只新增、不更新）；② 自动同步：入职、转正、调动、新增员工生效时，若岗职务能**唯一**映射到一个类别和级别，自动生成一条（开关在「设置 > 员工 > 同步任职资格」，可设置同步生成的记录是否允许手工改删）；③ 人才评定结果：按评定活动类型的设置生成 |
| QL-R16 | 人才评定生成的调动记录**不会**再触发 QL-R15 ② 的同步（避免重复） |
| QL-R17 | 调动表单可配置「关联任职资格」字段：选定职位 / 职务 / 序列 / 职级类别后自动显示对应标准，选了职级 / 职等时定位到对应级别 |
| QL-R18 | 版本：标准对象有“生效日期、版本号”字段（🟢），手册未说明版本规则。🟢 2026-10-08 只读补证（R3-T02 开工前扫描）：标准的新建 / 编辑表单**不显示**版本号和生效日期；任职类别编辑时只读，级别范围编辑时不可见（建好后不能改），指标范围、名称可改；本租户 39 条标准的生效日期都是建立日期 → 原站对用户**没有版本管理**，标准原地修改（与 DEC-055 一致） |

### 3.3 与组织员工的衔接（复刻要点）
- 任职类别、级别与职务体系（`19`）的关联是 **引用 + 同步**：引入时建立一对一关联，也允许手工一对多。
- 任职资格子集的自动同步依赖任职记录生效事件（`07` 版本链），与 `22` 人员子集的“来源追踪”一致：来源 = 初始化 / 任职同步 / 人才评定 / 手工。

## 7. 人才标准取证补充（Q-M0-107 / GitHub #103，2026-10-08，A0；只读 ＋ 写入 W-577～580）
来源：
- 手册 73045023（人才标准模块）、73045042（人才标准）、73045040（人才指标库）、113737762（人才标准 / 岗位标准搭建）、24248488（人才标准用户授权说明）。
- 原站表单元数据（`/api/v2/UI/FormView`）：TalentCenter.Dimension、DimensionLibrary、Category、Description、TalentCriterion、TalentCriterionCategory、RelationTalentCriterionDimension。
- 指标库 / 指标 / 人才标准各页面。截图含账号信息，未入库。

| # | 项目 | 原站（证据） |
|---|---|---|
| 1 | 能力指标 **目标** | 关系对象 RelationTalentCriterionDimension.Target：**数值**（Double，1 位小数），**可空**；只校验“请输入数值”（正则允许负号），没有范围限制。手册 113737762 称之为“标准目标分值 / 能力要求分值”，“目标默认非必填”。不是等级，也不是文本。 |
| 2 | **权重** | 同一对象的 Weight：数值（Double，1 位小数），可空，**新增时默认 1**；表单层只有“请输入数值”校验，**没有范围、没有合计 100% 的约束**（样本 P1V 标准中唯一指标的权重为 1.0）。手册：只有能力指标能设权重和目标。 |
| 3 | 指标库内 **分类** | **独立对象** TalentCenter.Category，在库详情的「分类」页签维护：字段只有 **类别名称**（必填，≤50）和 **类别顺序**（整数，必填），挂在所属指标库下；**没有编码、没有层级**。指标的「分类」是查找字段 CategoryV2，引用这个对象。 |
| 4 | **发展建议** | 指标详情下的子表 TalentCenter.Description，字段：呈现顺序（整数，必填）、**类型**（下拉，必填，数据源 TalentCenter.DescriptionType）、发展建议描述（长文本，必填）。样本类型值为“行动建议”；完整选项没能取到（下拉在本页加载失败），是否可由租户配置待查（🟡）。同级子表还有 等级描述（等级顺序、等级别称、所属要素、等级说明）、行为描述（顺序、关键点、描述）、面试问题（顺序、关键点、问题）。 |
| 5 | 指标 **编码** | **必填**，≤50，格式“首字符必须是字母，且只能包含字母数字下划线”。**库内唯一**：同库重复编码保存被拒，提示原文“名称或者编码重复，请重新输入”（W-578，无数据）；跨库同编码可以保存（W-577）。提示语说明名称也按库内唯一校验。编辑时编码**只读**。 |
| 6 | 类型 / 所属库能否改 | 指标库的「类型」在编辑表单里不可见，**建好后不能改**；指标的「指标库」在编辑表单里不可见，**不能改所属库**；关系对象编辑时「指标」只读（不能换指标）。 |
| 7 | 分类下有标准能否删 | **未能实测（🟡）**：人才标准分类是独立对象 TalentCriterionCategory（分类名称必填、说明、状态），但本租户人才标准的新建、编辑表单都没有配置“分类”字段，现有 5 个标准分类均为空，构造样本需要改表单配置，所以没做。手册只写了“指标被标准引用不能删、库内还有指标不能删”。 |

## 8. 人才标准取证补充（Q-M0-113 / #106 第 3 轮审查，2026-10-08，A0，只读）

对照 #106 的暂定口径，逐项说明一致还是不一致。

**① 所属人与所属管理单元：缺省取值与能否转移 → 与 #106 暂定口径不一致**
- 指标库、指标、人才标准，以及“人才标准里的指标”关联记录，都带两个系统字段：`Onwer`（所属人，原站拼写如此）和 `OnwerMou`（所属管理单元）。
- **新建表单上没有这两个字段**，由系统在新建时自动填写：
  - 所属人：所有记录都等于创建人。实测 26 个指标库、258 个指标、可见的 6 个人才标准，全部一致。
  - 所属管理单元：按创建人分组。何份晓（A0）、廖国江建的记录都是“华夏集团”，其余（系统预置、森豆、朱建晓、高继伟）都是根管理单元“北京SR样板间”。
  - Q-M0-107 中 A0 新建的指标 ZZ_Q107_DUPCODE（W-577），新建时没有任何选择，管理单元自动为“华夏集团”。
- 推断：所属管理单元取创建人在“人才标准”应用授权中的管理单元。用户授权列表里，人才标准管理员共 3 条授权：2 条是“北京SR样板间”，1 条是“华夏集团”。官方文档没有写明这条规则。
- **建好后不能转移**：
  - 编辑表单里没有这两个字段，它们只出现在记录数据中。
  - 列表行操作只有“编辑 / 删除”，页面按钮只有“新增 / 导入 / 启用 / 停用”，没有“转移 / 变更所属人”。
  - 帮助手册里也没有找到针对这些对象变更所属人的说明。
- 对照 #106 暂定口径“所属人和管理单元手选、建后不可改”：
  - **“手选”不一致**：原站是系统自动填写，不能手选。
  - **“建后不可改”一致。**

**④ 预置“人才标准管理员”身份的许可类型 → 与 #106 暂定口径一致（不占名额）**
- 本租户「企业设置 → 许可管理 → 余额」共 31 项。**没有“人才标准”相关的许可项。**
- 按身份扣许可的只有两项：“AI寻聘用户”“在线学习用户”。计费说明为：身份绑定了扣该许可证的页面权限 / 功能权限，就扣一个。
- 其余按人数或业务参与计费，例如：
  - 核心人力：在职员工数。
  - 数字人才：进入数字人才的员工数。
  - 继任与发展：当前合同周期内参与盘点或使用 IDP 的员工。
- 身份列表接口里“人才标准管理员（人才标准）”只有所属应用 TalentCenter，没有许可字段。
- 结论：授予人才标准管理员身份不单独消耗许可名额。这是按计费规则推断的，没有实际授予一次去验证余额变化。

**⑤ 人才标准指标列表中“指标类别”的来源 → 与 #106 暂定口径部分一致**
- 标准详情的指标列表，“指标类别”列绑定的是关联记录（`RelationTalentCriterionDimension`）自己的字段 `DimensionCategory`。
  - 这是**纯文本字段**（`BC_TextBox`）。
  - 不是经由指标读取的库内分类 `CategoryV2`。库内分类是指标上的 `CategoryV2`，指向分类对象 `Category`。
- 列表上方有「设置指标类别」按钮：勾选指标后，在弹窗（`TalentCenter.DimensionCategoryForm`）里给所选指标批量填写一个文本类别。也就是说，类别可以按标准单独设置，与库内分类脱钩。
- 抽样“华夏中层干部”：15 个指标的指标类别**全部与库内分类相同**；所属库没有分类的指标（P1V、胜任力情况），指标类别为空。
- 推断：选入指标时把库内分类复制成默认值，之后可以按标准单独改。是“复制后各自独立”还是“实时引用”，需要写入实测（改库内分类，看标准中的类别变不变），本次未做。
- 对照 #106 暂定口径“指标类别取库内分类”：
  - 默认值一致。
  - 但原站是**关联记录上可单独修改的文本字段**。如果复刻做成实时读取库内分类，就缺了“按标准单独设置类别”的能力。
