## 2. 所有子集共有的结构（复刻要点）

1. **冗余的排序与筛选字段**：每个子集都冗余了员工的 工号、入职日期、最后工作日，以及 组织 / 职务 / 职位 / 职级 / 职等的排序号。作用是子集列表可以直接按员工属性排序和筛选，不必回查任职记录。复刻时可以改用视图或关联查询，但**列表按员工属性排序的能力要保留**。
2. **来源追踪**：几乎每个子集都有 `个人信息变更Id`（员工自助提交的个人信息变更审批）和 `在职信息采集id`（HR 发起的信息采集）。→ 子集数据有三种来源：HR 直接维护、员工申请变更（走审批）、信息采集。复刻时每条子集记录要带来源。
3. **跨模块同步**：
   - 工作履历有“是否本单位工作经历”和“任职记录ID”：本单位的工作经历由任职记录**自动同步**生成，对应开关 `TransferSyncJobHistory` / `EntrySyncJobHistory` / `DismissSyncJobHistory`（`09` 附录）；
   - 考核结果来自绩效模块（绩效ID、九宫格落位）；
   - 培训经历与证书来自学习模块（培训活动编号、学习证书Id）。
   → 首版中绩效和学习不在范围内，这两个子集先按手工维护实现，同步接口预留。
4. **“最高 / 第一”标记**：教育经历的“是否最高学历 / 最高学位 / 第一学历”，专业技术职务、执业资格的“是否最高级别 / 最高等级”。这些标记会被员工信息主表引用（如“最高学历”字段）。复刻时要保证同一员工同类标记**最多一条为“是”**。
5. **多语言**：学校名称、单位名称、职务、绩效评语等提供日、法、繁体、英文版本。首版是否支持多语言由 DEC-001（固定配置）决定，建议只做中文、保留字段结构。

## 3. 首版范围建议（R1-T12）

| 子集 | 首版 | 说明 |
|---|---|---|
| 教育经历、工作履历、家庭成员、证书执照、语言能力、专业技能、表彰与奖励、惩罚情况、项目经历 | ✅ | 手工维护 + 员工自助变更 |
| 工作履历中“本单位经历”的自动同步 | ✅ | 与任职记录联动，按开关控制 |
| 专业技术职务、执业资格 | ✅ | 与任职资格模块（DEC-009 纳入）相关 |
| 考核结果、培训经历 | 🟡 只做手工维护 | 绩效与学习模块不在首版，同步接口预留 |
| **测验结果**（复刻新增，DEC-031） | ✅ R3-T00 | 原站无此子集，测评结果在测评中心 `Assess`。字段：测验名称、维度名称（空 = 总分行）、总分、维度得分、测验时间、来源（导入 / 接口）；支持导入与开放接口写入；供 `LastestAssessmentCent` 取数（`26` TR-R28） |
