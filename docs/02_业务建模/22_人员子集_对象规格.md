## 2. 所有子集共有的结构（复刻要点）

1. **冗余的排序与筛选字段**：每个子集都冗余了员工的 工号、入职日期、最后工作日，以及 组织 / 职务 / 职位 / 职级 / 职等的排序号。作用是子集列表可以直接按员工属性排序和筛选，不必回查任职记录。复刻时可以改用视图或关联查询，但**列表按员工属性排序的能力要保留**。
2. **来源追踪**：几乎每个子集都有 `个人信息变更Id`（员工自助提交的个人信息变更审批）和 `在职信息采集id`（HR 发起的信息采集）。→ 子集数据有三种来源：HR 直接维护、员工申请变更（走审批）、信息采集。复刻时每条子集记录要带来源。
3. **跨模块同步**：
   - 工作履历有“是否本单位工作经历”和“任职记录ID”：本单位的工作经历由任职记录**自动同步**生成，对应开关 `TransferSyncJobHistory` / `EntrySyncJobHistory` / `DismissSyncJobHistory`（`09` 附录）；
   - 考核结果来自绩效模块（绩效ID、九宫格落位）；
   - 培训经历与证书来自学习模块（培训活动编号、学习证书Id）。
   → 首版中绩效和学习不在范围内，这两个子集先按手工维护实现，同步接口预留。
4. **“最高 / 第一”标记**：教育经历的“是否最高学历 / 最高学位 / 第一学历”，专业技术职务、执业资格的“是否最高级别 / 最高等级”。这些标记会被员工信息主表引用（如“最高学历”字段）。复刻时要保证同一员工同类标记**最多一条为“是”**。
5. **多语言**：学校名称、单位名称、职务、绩效评语等提供日、法、繁体、英文版本。首版是否支持多语言由 DEC-001（固定配置）决定，建议只做中文、保留字段结构。

## 附：离职同步工作履历（Q-M0-37，2026-10-05 只读，A0）

- 配置：本租户「任职记录同步工作履历」对调动、转正、入职、重聘、离职、退休等均开启（`01_证据/导出/R2_本租户配置与数据_A0.md` 第 24 项）。
- 样本：测试员工 FWD_F2。任职记录：09-01 入职（O1）→ 09-10 调动（O2）→ 09-20 调动（O3，止于 09-24）→ 09-25 离职记录（W-410，最后工作日 09-24，止于 09-27，任职结束）→ 09-28 重聘（W-411，止于 10-09）→ 10-10 组织调整（未来，已生效状态）→ 10-20 调动（未生效）。
- 工作履历「本单位工作经历」共 5 行：09-01～09-09、09-10～09-19、09-20～09-24、09-28～10-09、10-10～至今。即**每条在职任职记录对应一行**，区间与任职记录一致。
- 结论：**离职不另建履历行**。离职记录（09-25～09-27，任职结束）没有对应行；离职前那一行的结束日期是最后工作日 09-24（离职前该行为“至今”）。重聘后另起新行。
- 附带：10-10 的未来「组织调整」记录保存后已同步成“10-10 至今”一行，前一行同步截止到 10-09；10-20 未生效的调动没有对应行。
- 未取到：履历表单布局只显示单位名称、职务、开始 / 结束日期、证明人、是否本单位工作经历；对象上的离职日期、离职原因、任职记录 ID 等字段不在布局中，是否随离职回填未核实。
- 与复刻一致：R1-T12（PR #26）只闭合已有区间的离职终点、不伪造离职后履历（`docs/plans/R1-T12-delivery.md`）。

## 附：未来生效业务何时同步工作履历（Q-M0-69，2026-10-05 只读，A0）

| 测试员工 | 未来记录（审批状态） | 是否已有履历行 |
|---|---|---|
| EST_EMP_02 | 10-10 直接调动、10-20 直接调动到 OUT（生效） | 都有：10-10～10-19、10-20 至今 |
| FWD_F3 | 10-12、10-15、10-31 直接调动（生效） | 都有 |
| FWD_F4 / FWD_F2 | 10-10 组织调整（生效） | 有 |
| FWD_F1 | 10-20 直接调动（生效）+ 同日调动申请（审批中） | 有一行 10-20 至今（对应生效那条） |
| FWD_F2 | 10-20 调动申请（审批通过，未到生效日） | **没有** |

- 结论：原站按**审批状态**而不是生效日判断。直接业务（直接调动、组织调整等）保存即为“生效”状态，未来日期也**保存时就同步出履历行**，并截断前一行；走审批的申请在审批中 / 审批通过（未到生效日）时**不同步**。
- 与复刻一致：`employment/write-service.ts` 直接模式保存即 `materializeEmploymentRecord` 并调用履历同步；申请审批通过只记 approved，到生效日落地时才同步（`transitions.ts`）。AC-SUB-02 的“生效后联动”按“记录落地（生效状态）”理解即可。
- 未取样：未来日期的入职（添加待入职后办理入职）。
