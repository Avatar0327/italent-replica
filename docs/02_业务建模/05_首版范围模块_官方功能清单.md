## 1. 任职管理模块（调动闭环的主战场）

官方划分为 **10 个子域**：

### 1.1 调动管理 ⭐（推荐首个深验闭环）
`调动管理功能介绍`｜`调动管理视图`｜**`调动申请`**（含 `调动时变更合同`、`调动时试岗`、**`各调动类型表单自动带出调动前任职的规则说明`**）｜`调动交接`｜**`直接调动`**｜`导入调动`｜`批量调动`｜`批量调动申请`｜`调动时电子签`｜`导出调动记录`

> 📌 **关键**：官方同时存在 **`调动申请`（走审批）** 与 **`直接调动`（不走审批）** 两条路径 —— 这直接回答了你要求查清的「保存是否直接生效、审批与生效是否分离」。两条路径都必须取证。
> 📌 **`各调动类型表单自动带出调动前任职的规则说明`** 正是「调动类型 × 字段自动带出」的规则来源，是复刻表单联动的核心依据。

### 1.2 任职记录 ⭐（历史与生效机制的核心）
`时间轴介绍`｜`系统字段含义介绍`｜**`继承字段和不继承字段介绍`**｜**`任职周期介绍`**｜**`向后更新`**｜`单个编辑任职记录`｜`批量编辑任职记录`｜`导入任职记录`｜`任职记录查看操作日志`

> 📌 **`继承字段和不继承字段`**、**`任职周期`**、**`向后更新`** 三章，正是你要求查清的「生效日期及追溯变更、历史快照」的官方规则所在。这是整个人事模块**最不能猜的部分**，必须读正文 + 实测。

### 1.3 其余子域
| 子域 | 主要功能 |
|---|---|
| 试用期管理 | 试用中考核、转正考核、转正/转正申请、批量转正、编辑试用期信息、催办/转交/撤销、到期提醒、考核中编辑 |
| 试岗期管理 | 调动时设置试岗期、到期提醒、发起试岗考核 |
| 实习生管理 | 新增/重聘/导入/编辑、校招&实习转正（含入职日期赋值逻辑）、结束实习、导出、离职取消待入职、带出正式 offer 薪资 |
| 劳务人员管理 | 新增/编辑劳务人员、劳务转正式 |
| 离职管理 | 离职申请（批量申请/批量催办）、直接离职（无需审批）、导入离职、配置离职交接事项、发起及办理离职交接（含员工本人查看进度、流程节点发起、发起人默认规则、催办）、离职人员职责转交、离职证明电子签、打印离职交接单、撤销离职、离职人员重聘、查看重聘员工上次离职合同、改期离职、离职交接并行审批、编辑离职 |
| 退休管理 | 即将退休、退休中、过期未退休、已完成、全部退休记录 |
| **兼职管理** | 功能介绍、数字板、新增/编辑/查看/结束兼职、导入、新增/延长/结束兼职申请、到期提醒、导出、**基于兼职任职的审批流程** |
| 汇报关系（HR端） | 汇报关系树、汇报关系图 |

> 📌 **兼职管理独立成子域** —— 证实你提到的「主职/兼职」在原站是**一等公民**，不是人员字段上的一个标记。对象模型必须支持一人多任职。

## 5. 由本清单产生的取证优先级

| 优先级 | 取证对象 | 理由 |
|---|---|---|
| P0 | 任职记录：继承/不继承字段、任职周期、向后更新 | 整个人事模块最不可猜的机制；错了全盘皆错 |
| P0 | 调动申请 vs 直接调动 | 直接回答「审批与生效是否分离」 |
| P0 | 各调动类型表单自动带出规则 | 表单联动的唯一依据 |
| P1 | 组织调整审批（新版/旧版，本租户用哪版） | 组织变更闭环前置 |
| P1 | 兼职任职模型 | 一人多任职，影响对象基数设计 |
| P1 | 多维组织架构（业务组织/利润中心） | 组织对象不是单棵树 |
| P2 | 流程版本与流程干预 | 配置变更对存量流程的影响 |
| P2 | 人才链路各模块 | 依赖底座先稳定 |
