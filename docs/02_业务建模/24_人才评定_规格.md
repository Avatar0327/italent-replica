# 人才评定：规格（R3-T02 子功能，DEC-009）

> 取证：2026-09-28，A0 只读。
> - 配置证据 🟢：`TEvaluation` 29 个对象（`01_证据/导出/R3_对象字段_配置证据.md`）；本租户 评定活动 35、员工评定记录 133、活动周期 9、活动类型 7、评价表 15、通用评分项 17、评审组 7
> - 官方文档 🟡：HRSAAS 164495902、169710159、265620215、169710164、234881603、169710172/75/78/81/84/87/90、164495904、202834537
> - 定位：DEC-009 把人才评定作为**任职资格的评定环节**纳入。「干部述职」菜单复用同一套对象（数量相同），首版不单独做。

---

## 1. 业务主线

```
基础设置：活动周期、活动类型、评审组、通用评分项、评价表（标准模式 / 高级模式）
        ↓
评定活动（适用范围 + 参评条件 + 环节）──发布──> 通知范围内员工
        ↓
[资格申报] 员工申报 / 上级或 HR 提名（可破格）→ 资格审批流程
        ↓（自动或手动转入）
[材料举证 ×≤3] 自评 + 材料 → 材料审批流程（上级评价、HRBP 审核）
        ↓（自动或手动转入；可提前转入）
[答辩评审 ×≤3] 安排场次（评委、时间、地点、跟场人）→ 评委打分 → 跟场人结果校准
        ↓（手动转入）
[结果发布] 提前通知（可选）→ 发布结果 → 同步任职资格子集 / 生成调动记录
        ↓
评定记录（员工评定数据）→ 人员档案查看、统计分析
```

## 2. 对象（🟢 配置证据）

| 对象 | 作用 |
|---|---|
| 活动类型 `ActivityType` | 名称、业务类型、**是否同步任职资格子集、是否同步任职记录、任职记录的异动类型**（只能选业务类型 = 调动的启用异动类型） |
| 活动周期 `ActivityCycle` | 评定窗口期，用于统计 |
| 评定活动 `EvaluationActivity` | 编码、名称、类型、周期、年度、起止日期、所属组织、组织范围、负责人、申请人（本人 / 非本人）、申请类别 / 级别范围、员工可申报级别（跨级限制）、评定生效日期、通知范围与模板、状态 |
| 参评条件 / 明细 `EvaluationActivityCondition(Detail)` | 条件类型（通用 / 附加）、申请人类型、适用类别 / 级别范围、表达式；明细 = 应用 + 对象 + 字段/函数 + 操作符 + 值 |
| 活动环节 `EvaluationActivityChain` | 环节类型（资格申报 / 材料举证 / 答辩评审 / 结果发布）、顺序号、起止日期、评价表、资格 / 材料审批流程、材料提交模板、是否强控报名截止、是否允许破格、破格提名角色、转入下一环节方式、各类通知模板与角色 |
| 评价表 `EvaluationForm` + 模块 `Module` + 评分项明细 `EvaluationScoreDetail` + 结果设置 `ResultSetting` + 模块结果明细 `ModuleResultDetail` | 评分方式、满分、通过分数、总分计算规则、公式、结果选项 |
| 通用评分项 `GeneralScoreItem` | 任职资格标准之外的评分项（现场表现、业绩等），可评分或评级 |
| 评审组 / 成员 `ReviewGroup` / `ReviewMembers` | 评委分组，一个组长 |
| 员工评定数据 `StaffEvaluationData` | 一人一活动一条：原 / 申请 类别级别、状态、各环节流程 ID、自评 / 上级 / 预置 评分评价、最终得分 / 结果 / 通过票数、优势、发展建议、破格、生效日期 |
| 指标明细 `EvaluationIndicatorsDetail` | 一人 × 一评分项：自评、上级、预置评分 / 评级 / 评价，各环节权重 |
| 评审场次 / 明细 `EvaluationSessions(Detail)` | 场次（评委、跟场人、开始时间、每人时长、地点）；明细 = 每个参评人的时段、答辩状态、得分、纪要 |
| 评委评审记录 / 明细 / 模块 `EvaluationRecord(Detail)`、`JudgeEvaluationModule` | 每个评委对每个参评人的总分、结果、弃权；逐项打分 |

## 3. 规则（🟡 官方文档）

### 3.1 基础设置
| # | 规则 |
|---|---|
| EV-R1 | 活动类型决定评定通过后：是否**同步任职资格子集**、是否**同步任职记录**（生成调动，异动类型限调动类）。生成任职记录的前提：申请类别或申请级别关联的岗职务数据**唯一** |
| EV-R2 | 用人才评定做晋升时，须关闭组织员工「员工岗职位信息变动同步生成任职资格子集」开关，避免重复（与 `23` QL-R16 一致） |
| EV-R3 | 评价表（标准模式）评分方式：**按指标评分**（设满分、通过分数、总分计算方式）或**评总分**（只设满分、通过分数）；另有按投票 |
| EV-R4 | 评分项：**最多一条“任职资格标准”**（按参评人申请类别 / 级别动态取指标，可设置不显示的指标）＋ 任意条通用评分项。加权时实际权重 = 标准整体权重 × 指标在标准中的权重；例：标准 80、产品能力 40% → 32 |
| EV-R5 | 评价表被“**进行中且已有提名人员**”的活动引用后，评分方式、满分、通过分数、总分计算规则、评分项区域**全部锁定**（高级模式只允许改模块名称、列配置、评价标准） |
| EV-R6 | **评分项在员工提名成功时一次性生成**并计算各环节权重，之后不再随标准或评价表变化 → 复刻时这是一次“快照”。⚠️ 2026-10-05 实测与此不符：提交申报后才出现评分项，且审核中 / 审核通过后改标准都会同步变化（Q-M0-01，D-045） |
| EV-R7 | 高级模式：评价表由多个**模块**组成（任职资格标准模块 / 通用评分项模块，至少 1 个，名称不重复）；每个模块设 评价方式（评分 / 评级）、评价范围（指标类型，一个类型只能被一个模块选一次；评级时所选类型下指标的等级方案必须相同；空类型不可选）、评价维度（指标类型 / 指标 / 能力标准）、模块结果计算规则（评分标准 / 高级公式 / 评级算分 / 按数目统计 / 高级公式） |
| EV-R8 | 高级模式结果：结果选项从数据源「人员评审结果」中选并可改显示名；**要驱动后续业务（生成任职记录、任职资格）必须用系统预置的“通过 / 不通过”**。单评委结果计算方式三选一：按公式（不可人工改）/ 按投票（人工评，可有公式预填）/ 按范围计算等级；多评委汇总也可用公式（预置函数：取模块分或结果、统计指定结果的模块数、指定模块所有评委平均分、统计指定得分或结果的评委数、所有评委平均分；弃权评委不参与） |

### 3.2 活动
| # | 规则 |
|---|---|
| EV-R9 | 活动适用范围按 **申请人任职部门 + 申请类别 + 申请级别** 匹配活动；可限制跨级申报的级数 |
| EV-R10 | 参评条件：**通用条件**对全体生效；**附加条件**按类别 / 级别范围叠加；员工本人申请与非本人提名可各设一套（可从本人条件复制一次）。不设条件则不校验 |
| EV-R11 | 参评条件可引用：当前生效的员工信息、任职记录字段；人事子集（删除状态 = 否，审批状态 = 通过或空，**任一条满足即达标**）；考核结果函数（如“最近 12 次月度考核中 A/B 超过 10 次”，表达式里子集条件须写在函数条件之后）；学习任务完成情况（依赖学习，⏸） |
| EV-R12 | 环节：资格申报、材料举证（≤3 个）、答辩评审（≤3 个）、结果发布。只有资格申报可以**强控截止日期**，其他环节日期仅作进度参考 |
| EV-R13 | 转入下一环节：“流程完成后自动转入”或“手动转入”；答辩评审 → 结果发布**只能手动** |
| EV-R14 | 编辑限制：未报名时可取消发布、改全部内容（开启通知模板、活动类型、适用范围、材料提交模板除外）、增删环节；**已有报名后**只能改名称、组织、年度、周期、负责人、起止日期、申请人、可申报级别、参评条件、环节的名称 / 日期 / 顺序 / 流程 / 转入方式 / 通知，**不能增删环节** |
| EV-R15 | 发布：按当前生效的员工信息、任职记录、任职资格子集匹配通知范围，发送开启通知。取消发布**不撤回**已发通知（员工点链接将无法报名） |
| EV-R16 | 完成活动须手动操作；完成时仍在进行中的评定数据**全部终止** |
| EV-R17 | 新建 / 编辑活动为三步向导，第三步才一次性保存 |

### 3.3 资格申报
| # | 规则 |
|---|---|
| EV-R18 | 原类别 / 原级别、上次通过情况、历练时长：**优先取任职资格子集，取不到再取员工评定记录**，且按**相同活动类型**取上一条 |
| EV-R19 | 默认申请类别 = 原类别，申请级别 = 原级别 + 1，可修改；据此自动匹配进行中的活动 |
| EV-R20 | 不可提交的情况：无匹配的进行中活动；超出跨级限制；活动未开始；强控截止且已过期；**同一活动重复申报**；活动只允许他人提名而本人申报；不满足参评条件且不允许破格 |
| EV-R21 | 破格：活动允许且操作人是破格提名角色时，可选“是否破格 + 原因”后跳过参评条件。兼容规则：表单未配置破格字段、但满足上述前提且不满足条件时，**仍允许提交并自动标记为破格** |
| EV-R22 | 批量提名：可编辑表格最多 **500 条**；校验在职、在操作人管理范围内、满足活动组织范围与类别级别、不重复；保存为“待申报”，提交时逐条校验参评条件，失败者可“继续提名”补破格原因 |
| EV-R23 | 申报审核中可批量催办、撤销（撤销即终止该申报） |

### 3.4 材料举证与评委评价
| # | 规则 |
|---|---|
| EV-R24 | 员工在“材料待提交”状态才能提交；页面实时保存，提交即发起材料审批流程；**仅 PC** |
| EV-R25 | 可编辑字段仅限分组为「员工自评 / 上级评价 / HRBP 评价」的字段；人员、状态、原 / 申请 类别级别、活动、环节**永远只读** |
| EV-R26 | 评分上限与评价标准取**第一个材料举证环节**所配评价表的满分；指标明细的自评分、上级评分、预置评分（×2）自动汇总到员工评定数据对应字段（同分组、同短编码、同为数值型的自定义字段也按此汇总） |
| EV-R27 | 审批人可编辑的条件：流程在途（撤回 / 驳回 / 审批中）且节点关联了业务操作且本人是节点审批人且元数据允许编辑 |
| EV-R28 | 材料审核通过至待评审期间，员工可更新“答辩材料”及自定义字段，系统记录更新人和时间（可配业务规则通知跟场人） |
| EV-R29 | **提前转入**：仅当下一环节是答辩评审时，允许在材料未提交 / 审核中（或资格审核中）提前转入。若资格审批最终不通过，员工**退回资格审核并从场次中删除**；材料审批不通过则不影响答辩 |
| EV-R30 | 评委按场次收到待办；可按指标打分（实时算指标类型分和是否通过）或评总分；提交后自动跳到同级别下一人 |
| EV-R31 | **弃权**：评委本人或跟场人可设弃权，须填原因，**不可撤销**，清空评价、不参与计算；所有在职评委都已提交或弃权时，参评人变为“已评审”（DEC-044：有评委既未提交也未弃权时不得进入“已评审”）。原站弃权按钮受功能权限 `TEvaluation.EvaluationRecord / Abstain` 控制，本租户所有预置身份都没有该对象。🟢 原站实测（W-319/W-320）：弃权表单只有「被评价人」「*弃权原因」，提示「弃权后将清空评价内容，不可撤回，不可再次评价」，无二次确认；弃权后只读、无撤销；校准页显示「已弃权」，平均分不计入 |
| EV-R32 | 评委在跟场人**校准前**可修改并重新提交；校准后锁定 |

### 3.5 答辩安排与校准
| # | 规则 |
|---|---|
| EV-R33 | 安排场次：按“开始时间 + 每人时长”自动排出每人时段；可插入时段、插入人员、拖拽排序，后续时间自动顺延；评委日程冲突时提示（可查看 30 天内日程，含第三方日程 ⏸） |
| EV-R34 | “暂存”不发通知；“确定并发送通知”后给各角色发待办并生成日程；已评审 / 已校准的人不能再调整安排 |
| EV-R35 | 跟场人“开始答辩”后计时，同一时刻只有一人处于评审中；结束后不能再次开始 |
| EV-R36 | 结果校准：最终得分 / 结果为空时默认取答辩得分 / 结果；优势、发展建议为空时**自动拼接所有评委的内容**；显示通过率 = 通过 /（通过 + 未通过） |
| EV-R37 | 删除场次：场次内有已评审 / 已校准人员时不能删；删除人员：有在途审批时须先撤销 |

### 3.6 计分（164495904）
| # | 规则 |
|---|---|
| EV-R38 | 满分制：所有打分不得超过满分；得分 ≥ 通过分数 → 通过，否则不通过 |
| EV-R39 | 单评委总分：平均分 = Σ指标分 / 指标数；加权平均 = Σ(指标分 × 权重)；加总 = Σ指标分 |
| EV-R40 | 指标权重：平均分时 = 100% / 参与评分项数（剔除不显示的、能力标准为空的指标）；加权时按 EV-R4 计算，标准中部分指标权重为空的按 0% |
| EV-R41 | **多评委最终得分 = 各评委总分之和 / 评委人数**（固定规则，不可配置；弃权者不计）。单评委总分 = 各指标分的平均，未填指标按 0（原站实测 T-405）。**DEC-044：只统计已提交的评委**；原站连未提交的草稿分也计入（D-013），复刻不照搬。结果须经跟场人「确认校准」后才落库 |

### 3.7 结果与记录
| # | 规则 |
|---|---|
| EV-R42 | 结果发布须手动；可先对部分员工“提前通知”直线经理 / BP |
| EV-R43 | 发布时，**通过**的评定数据自动同步到任职资格子集（同短编码、同类型的自定义字段一并同步）；是否同时生成调动记录由活动类型决定 |
| EV-R44 | 评定记录支持导入历史数据（新增 / 编辑），员工、经理、HR 可在人员档案中查看 |

### 3.8 状态机（员工评定数据）
| 环节 | 状态 |
|---|---|
| 资格申报 | 待申报（流程撤回 / 驳回 / 终止）→ 申报审核中（初始）→ 申报通过 / 申报未通过；异常：申报已终止（离职） |
| 材料举证 | 材料待提交（初始）→ 材料审核中 → 材料审核通过 / 未通过；异常：已终止 |
| 答辩评审 | 待安排评审（初始）→ 待评审 → 已评审 → 已校准；异常：已终止 |
| 结果发布 | 结果待发布（初始）→ 结果已发布；异常：已终止（离职、活动完成） |
