## 1. 继任管理（R3-T05）

### 1.1 对象
```
关键岗位 KeyPosition（名称、类别、所属组织、向下公开、是否启用）── 职位 TenantBase.Position 上标记“关键职位”
准备度 Readiness（阶段、描述、颜色、排序）
继任地图 Map：继任类型（组织 / 职位）× 目标组织 或 目标职位 × 继任者 × 准备度
             后备类型（正职 / 副职）、现任人员、开始时间、结束时间、生效状态、结束原因
继任地图版本 SuccessionMapVersion（时间标记：名称、时间、描述、可见范围、继任类型）
职位风险等级规则 / 结果（条件表达式、优先级、颜色 → 职位的风险等级，可手动赋值）
健康度规则 / 结果（组织的健康度，按规则从上到下匹配，可手动赋值）
组织关联信息 OrgRelationInfo（绿化率、在岗人数、编制数、版本时间）
```

### 1.2 规则（🟡）
| # | 规则 |
|---|---|
| SC-R1 | 组织继任：目标组织（管理单元内）+ 负责人（自动带出）+ 继任者 + 准备度 + 开始时间（默认今天）+ 结束时间（空 = 至今）；职位继任：目标职位（管理单元内组织下的**关键职位**）+ 现任人员（主职 + 兼职，逗号拼接）+ 继任者 + 准备度 + 岗位胜任度 |
| SC-R2 | **时间轴**：开始时间**不得晚于今天**，结束时间**不得晚于今天**（不允许维护未来生效的继任）；结束时间为空时存 `9999-12-31` = 当前生效；有结束时间 → 状态“已结束” |
| SC-R3 | “结束”操作：批量把继任结束时间设为所选日期（≤ 今天），可填原因；结束后不再出现在最新地图上 |
| SC-R4 | **员工离职时，自动结束其作为继任者的当前生效记录**，结束时间 = 离职生效日 |
| SC-R5 | 组织继任地图：从一个根展开（默认 3 层，可 2–4 层）；多个同级有权组织时取顺序号最小者；可隐藏指定部门及其下级、隐藏虚拟组织；负责人含副职；可在组织卡片内显示该组织的**关键职位卡片** |
| SC-R6 | 组织卡片：绿化率、在岗人数（每 4 小时计算一次，或改卡片显示设置时触发）、编制数（实时取组织员工） |
| SC-R7 | 开关「本人继任者是否可见」= 否时，登录人看不到自己的继任者 |
| SC-R8 | 职位继任地图：可**多根**展示；中间职位停用导致断层时，下级挂到断层的上级；因权限导致的断层则多根显示；可选“展示无继任者的职位” |
| SC-R9 | 职位风险等级：按规则（条件、优先级）异步计算，完成后消息通知；也可手动赋值 |
| SC-R10 | 组织健康度：规则**自上而下匹配，先匹配先得**；已手动赋值或导入的组织**不被重算覆盖** |
| SC-R11 | 时间标记：给当前地图打快照（名称、描述、可见范围），之后可打开历史快照查看（只读） |
| SC-R12 | 人才对比：地图中最多选 5 人对比 |

### 1.3 盘点 → 继任地图的同步（193134846、193134868）
| # | 规则 |
|---|---|

| SC-R17 | 盘点项目可设“业务日期”：盘点继任地图按该日期的组织与职位展示 |

## Q-M0-82 职位风险等级与组织健康度规则的语法（R3-T05 开工前，2026-10-07 只读，A0）
来源：「继任与发展 → 设置 → 继任地图设置 → 职位风险等级设置」（pageCode `orgMapSetting`）、「健康度规则设置」（pageCode `HealthyRulesSetting`）只读查看（下拉展开后取消，未保存）；手册 193593725、193134868、207126954。

**结论：两类规则都不是自由公式，而是“结构化条件行 + 条件表达式”。**

### 职位风险等级
- 页面说明原文要点：设置风险等级名称与颜色；不加计算规则时可在职位卡片上手动赋值；**每日凌晨 0 点自动运算**，改规则或数据变化后可在职位继任地图手动「计算职位风险等级」（异步，完成后消息通知）。
- 多个等级同时满足时“按照规则优先级进行顺序匹配，排序越靠前优先级越高”，拖拽调整顺序；都不满足用「默认颜色」。开关「兼岗人员是否参与计算」（计算现任人员时是否含兼岗）。
- 每个等级：颜色、描述、若干**计算规则行**：序号、计算对象（现任人员 / 继任人员）、字段（人员字段，如 姓名、机构）、可选条件（为空 / 不为空 / 等于 / 不等于）、值、计算方式（人数 / 人数/现任者人数 / 人数/继任者人数）、运算符、数值（比例时带 %）；**条件表达式**“仅支持 and、or、括号，字符间需加入空格、如：(1 or 2) and 3”。
- 本租户：高风险 = `1`（现任人员 姓名 为空 的 人数 为空）；中风险 = `1 and 2`（现任人员 姓名为空 的 人数/现任者人数 不为空；现任人员 机构 等于 … 的 人数/现任者人数 不为空）；低风险 = `1`（继任人员 姓名 不为空 的 人数/继任者人数 不为空）。

### 组织健康度
- 规则自上而下匹配，先匹配先得（207126954）；不满足任何规则按「默认颜色」。手动赋值 / 导入的组织计算时不覆盖（193134868）。
- 两个页签：**人员范围**（自定义命名人群，如“青年人才 = 年龄 小于 …”，供规则引用）与 **继任地图健康度**。
- 每个健康度等级：名称、颜色、描述、计算规则行：序号、人员范围（全部 / 继任者 / 现任者 / 自定义人员范围）、字段（盘点 / 组织 / 继任字段，如 校准后绩效、负责人；部分计算类型不需字段）、可选条件 + 值（如 校准后绩效 等于 高）、**计算类型**（绿化率、盘点结果占比、继任者人数、平均值、占比、人数、人数/继任者人数、人数/现任者人数）、比较符（为空、不为空、等于、不等于、大于、小于、大于等于、小于等于、**范围**）、数值（比例带 %）；条件表达式同上（and / or / 括号）。
- 本租户 6 个等级（满星、5 星 … 1 星）都用同样 4 行：绿化率 ≥/< 30%；校准后绩效=高 的 盘点结果占比 ≥/< 20%；负责人 不为空；负责人 继任者人数 ≥1 / =0；表达式分别为 `1 and 2 and 3 and 4`、`1 or 2 or 3 or 4`、`(1 or 2 )or 3 or 4` 等。
- 取数（193134868）：盘点对象字段按“触发计算的项目 / 校准会 > 当前项目 > 最近一次盘点”取；继任地图字段经字段映射从盘点继任信息取，取不到则**跳过该规则**；计算范围 = 项目所属组织及下级 ∩ 用户 MOU ∩ 地图中显示的组织。

### 对复刻（DEC-211）
- DEC-211 定为“继任规则统一用 R3-T00 表达式引擎表达”，而原站是结构化条件行 + 只含 and / or / 括号的组合表达式，没有函数、没有算术 → 登记册 **D-062**。

## 7. 人才池补充取证（Q-M0-114，2026-10-08，A0，只读）

- **自动入池规则的存储**：人才池表单上“人才池规则”`PoolRule` 只是一个文本字段的占位，实际由自定义组件 `TalentPoolRules` 编辑。规则通过 `SuccessionAndDevelopmentMRest/…/Pool/GetPoolRuleData?poolId=` 读取，样本为“安擎管理及管理后备梯队人才池”。结构如下：
  - 每个池可以有多组规则。每组字段：`GroupID`、`UserDataSource`、`FieldValuePriority`、`DuplicateHandleType`、`Expression`（逻辑表达式，如 "1"，引用条件行编号）、`EnterPoolFieldValue`（入池时给成员赋的字段值，由 StoreTalent 的“通用规则表单” `GeneralRulesForm` 维护：阶段、指导人角色等）、`Fields`（条件行）。
  - 每个条件行：`Num`、`FieldName / FieldLabel`、取值对象 `ItemMetaObjectName`（样本为盘点对象 `CalibrationObjective`）、`Values`、`SearchItemID`。运算符可选 为空 / 不为空 / 等于 / 不等于 / 大于 / 小于 / 大于等于 / 小于等于 / 范围。
