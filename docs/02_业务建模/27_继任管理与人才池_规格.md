## 1. 继任管理（R3-T05）

### 1.1 对象
```
关键岗位 KeyPosition（名称、类别、所属组织、向下公开、是否启用）── 职位 TenantBase.Position 上标记“关键职位”
准备度 Readiness（阶段、描述、颜色、排序）
继任地图 Map：继任类型（组织 / 职位）× 目标组织 或 目标职位 × 继任者 × 准备度
             后备类型（正职 / 副职）、现任人员、开始时间、结束时间、生效状态、结束原因
继任地图版本 SuccessionMapVersion（时间标记：名称、时间、描述、可见范围、继任类型）
职位风险等级规则 / 结果（条件表达式、优先级、颜色 → 职位的风险等级，可手动赋值）
健康度规则 / 结果（组织的健康度，按规则从上到下匹配，可手动赋值）
组织关联信息 OrgRelationInfo（绿化率、在岗人数、编制数、版本时间）
```

### 1.2 规则（🟡）
| # | 规则 |
|---|---|
| SC-R1 | 组织继任：目标组织（管理单元内）+ 负责人（自动带出）+ 继任者 + 准备度 + 开始时间（默认今天）+ 结束时间（空 = 至今）；职位继任：目标职位（管理单元内组织下的**关键职位**）+ 现任人员（主职 + 兼职，逗号拼接）+ 继任者 + 准备度 + 岗位胜任度 |
| SC-R2 | **时间轴**：开始时间**不得晚于今天**，结束时间**不得晚于今天**（不允许维护未来生效的继任）；结束时间为空时存 `9999-12-31` = 当前生效；有结束时间 → 状态“已结束” |
| SC-R3 | “结束”操作：批量把继任结束时间设为所选日期（≤ 今天），可填原因；结束后不再出现在最新地图上 |
| SC-R4 | **员工离职时，自动结束其作为继任者的当前生效记录**，结束时间 = 离职生效日 |
| SC-R5 | 组织继任地图：从一个根展开（默认 3 层，可 2–4 层）；多个同级有权组织时取顺序号最小者；可隐藏指定部门及其下级、隐藏虚拟组织；负责人含副职；可在组织卡片内显示该组织的**关键职位卡片** |
| SC-R6 | 组织卡片：绿化率、在岗人数（每 4 小时计算一次，或改卡片显示设置时触发）、编制数（实时取组织员工） |
| SC-R7 | 开关「本人继任者是否可见」= 否时，登录人看不到自己的继任者 |
| SC-R8 | 职位继任地图：可**多根**展示；中间职位停用导致断层时，下级挂到断层的上级；因权限导致的断层则多根显示；可选“展示无继任者的职位” |
| SC-R9 | 职位风险等级：按规则（条件、优先级）异步计算，完成后消息通知；也可手动赋值 |
| SC-R10 | 组织健康度：规则**自上而下匹配，先匹配先得**；已手动赋值或导入的组织**不被重算覆盖** |
| SC-R11 | 时间标记：给当前地图打快照（名称、描述、可见范围），之后可打开历史快照查看（只读） |
| SC-R12 | 人才对比：地图中最多选 5 人对比 |

### 1.3 盘点 → 继任地图的同步（193134846、193134868）
| # | 规则 |
|---|---|
| SC-R13 | 盘点模板「继任信息」模块：**提名组织继任者**（仅当盘点对象是组织负责人）、**提名职位继任者**（仅当盘点对象主职最新生效任职的职位是关键职位；开关「开启兼岗提名」时兼职关键职位也显示）、**目标继任组织 / 职位**（为盘点对象指定意向继任）；权限按步骤：可编辑 / 仅查看 / 不可见 |
| SC-R14 | “同步继任信息”三种策略（开关参数）：① **覆盖**：本次涉及的组织 / 职位的继任者被替换，未涉及的不变；② **追加**：保留原继任者，追加本次；③ **范围内覆盖**：所选组织范围内原有继任全部结束，再写入本次 |
| SC-R15 | 盘点对象状态为**流程中**时，其全部继任信息同步失败并列入错误报告（手动同步例外：会同步流程中已填的继任者与准备度） |
| SC-R16 | 健康度随组织继任信息一起同步（含“是否手动赋值”，空值也同步）；盘点中计算健康度的范围 = 项目所属组织及下级 ∩ 管理单元 ∩ 地图中显示的组织；取数优先级：触发计算的项目或校准会 > 当前项目 > 最近一次盘点 |
| SC-R17 | 盘点项目可设“业务日期”：盘点继任地图按该日期的组织与职位展示 |

## 2. 人才池（R3-T06）

### 2.1 对象
```
人才池分类 PoolCategory
人才池 Pool（名称、所属分类、所属组织、向下公开、共享组织、目标岗位、预计人数、现有人数、入池标准 / 出池标准（→ 人才标准）、自动入池、入池提醒、状态）
 ├─ 人才池规则 PoolRule（数据来源、入池字段、入池条件表达式、字段值优先级、重复人员处理方式）
 └─ 储备人才信息 StoreTalent（人员、入池类型、入池日期、阶段、准备度、指导人 / 指导人角色、出池日期、出池原因）
```

### 2.2 规则（🟡）
| # | 规则 |
|---|---|
| TP-R1 | 人才池按管理单元中的组织范围控制；**向下公开**后，下级组织可以往池中加入**各自管理范围内**的人 |
| TP-R2 | 预计人数用于衡量**饱和度**（现有 / 预计，按颜色区间显示） |
| TP-R3 | 入池方式：① 手动入池（单人，填阶段、准备度、指导人）；② 从盘点九宫格 / 校准会勾选加入（`26` TR-R42）；③ 导入（新增 / 更新 / 新增或更新；空单元格“不处理”或“清空”）；④ **自动入池** |
| TP-R4 | 自动入池来源：**盘点对象**（按九宫格格子、标签、职级等条件；**盘点项目结束后**触发）、**继任者**、**现任人员**（现任某岗位或新晋升 / 调岗到该岗位） |
| TP-R5 | 自动入池时已在池中的人：可设置“覆盖”（更新准备度、指导人角色等，**入池时间不覆盖**）或不覆盖 |
| TP-R6 | 入池提醒：通知入池人任职部门的 HRBP，或指定人（≤10 人） |
| TP-R7 | 阶段：新入池 → 培养中 → **已出池**；出池须填出池日期和原因。开关「人才池中是否自动执行出池」= 是时，**员工离职自动出池**（原因 = 离职） |
| TP-R8 | 删除储备人才 = 不留痕；出池 = 留痕（已出池列表可查） |
| TP-R9 | 从人才池勾选人员**发起 IDP**：“创建”只建未开始的计划，“创建并启动”同时开启并发待办（`28`） |
| TP-R10 | 人才梯队地图：按 人才池 × 准备度 的矩阵展示，可转置、可隐藏空池、可**拖拽调整准备度**、可导出 Excel |

## 5. 验收场景（AC-SC-* / AC-TP-*）

| 编号 | 场景 | 预期 | 状态 |
|---|---|---|---|
| AC-SC-01 | 新增继任，开始时间填明天 | 拒绝 | 🟡 |
| AC-SC-02 | 继任者离职生效 | 其当前生效继任记录自动结束，结束日 = 离职日 | 🟡 |
| AC-SC-03 | 盘点同步继任（覆盖策略），组织 A 原有继任者 X，本次提名 Y | A 的继任者变为 Y；未涉及的组织 B 不变 | 🟡 |
| AC-SC-04 | 同上改为追加策略 | A 的继任者为 X、Y | 🟡 |
| AC-SC-05 | 盘点对象仍在流程中时同步继任 | 该对象的继任全部同步失败，错误报告列出 | 🟡 |
| AC-SC-06 | 职位继任地图中间职位停用 | 其下级职位挂到停用职位的上级 | 🟡 |
| AC-SC-07 | 组织健康度已手动赋值后点“计算健康度” | 该组织不被覆盖 | 🟡 |
| AC-TP-01 | 盘点项目结束，自动入池规则 = 7/8/9 格 | 落在 7–9 格的对象自动入池 | 🟡 |
| AC-TP-02 | 已在池人员再次自动入池，覆盖 = 是 | 准备度更新，入池日期不变 | 🟡 |
| AC-TP-03 | 在池人员离职，自动出池开关开 | 阶段变为已出池，原因 = 离职 | 🟡 |
| AC-TP-04 | 下级组织管理员向上级公开的人才池加人 | 只能加自己管理范围内的人 | 🟡 |
