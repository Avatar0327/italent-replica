## 1. 对象关系

```
编制方案 EstestablishmentScheme ──被引用── 组织编制 OrganizationEstablishment（组织 × 周期）
   │ 周期类型、起始月、细分维度(≤10)、维护方式、不占编组织、占编人员范围(≤5 条取并集)、未匹配细分时的处置
   │                                         └── 细分编制（组织 × 周期 × 维度值组合）＋ 预留编制
编制维度（标准 + 预置 1–5 + 自定义）：编制维度字段（编制对象上，多选） ↔ 业务控编字段（任职记录 / Offer 上，单选）
编制时机设置：5 类业务 × 占用 / 释放时机
编制调整历史、编制向后更新明细 EstestablishmentSyncDetailMessage、细分编制审批、组织编制审批
```

## 2. 编制方案（39387438）

| 配置项 | 规则 |
|---|---|
| 周期类型 | 年度 / 季度 / 月度；起始月份默认本年 1 月；月度只能按自然月 |
| 细分维度 | 可以为空，最多 10 个维度组合；可用标准维度或自定义维度 |
| 未匹配到细分编制时 | A. 只按组织编制校验。本部门没有组织编制时，向上找最近一个有编制的部门，按其方案的设置处理；整条上级链都没有编制时，默认 A。<br>B. 不允许发起 Offer、入职、调入 |
| 维护方式 | ① 只维护本级（含下级 = 本级 + 所有下级的本级，自动汇总）<br>② 只维护含下级（本级始终为空，只管控含下级）<br>③ 本级和含下级分别维护（两者都必填） |
| 不占编组织 | 这些组织不参与本方案下的编制校验和人数统计 |
| 占编人员范围 | 用雇佣关系等维度写条件，最多 5 条，**多条取并集** |
| 生命周期 | 预置「默认方案」，可以停用。方案**已被编制引用时不能删除**，也不能再改周期类型、起始时间、细分维度。方案被当前或未来的编制引用时不能停用；只被历史编制引用时可以停用 |

## 3. 组织编制字段与校验（28345509、39387187）

- 数字字段：本级编制、含下级编制、预留编制，以及实有人员、预增员、预减员、缺编数（后四项各有本级 / 含下级两个口径）。
- **缺编数 = 编制 − 实有人员 − 预增员 + 预减员**（本级、含下级分别计算）。
- 保存时的**一致性约束**（违反即报错）：
  1. 含下级编制 ≥ 本级编制；
  2. 组织编制 ≥ 组织内细分编制之和（本级、含下级分别比较）；
  3. 含下级编制 ≥ 本级编制 + 所有直接下级的含下级编制之和；
  4. 同一上级下，各兄弟部门的含下级编制之和 ≤ 上级含下级编制 − 上级本级编制。
- 有细分维度时，组织编制**不能手填**，自动等于 细分编制之和 + 预留编制。
- **严格控制**（`StrictControl`，G-012）：决定人员进入组织时如果超编，是**只提醒**，还是**强制拒绝**。强制拒绝作用于 Offer、入职、调入。
- **同步各上级**：勾选后，新建编制的含下级编制数会累加到各级上级的含下级编制上（细分编制同理，按同维度累加）。

## 4. 时间轴与向后更新（G-040）

| 场景 | 规则 |
|---|---|
| 新建月度编制 | 填了某个月的编制后，**后续月份自动带出同样的值**，可以手动修改 |
| 调整月度编制（126747427） | 修改某个月的编制后，后续月份**按差值联动**。例：1–3 月原为 1/2/3，1 月改成 4，则 2、3 月变为 5/6。**实测修正（AC-EST-05，2026-09-28）：差值只传播到本次所选「调整周期范围」内的后续月份，范围外月份不变；新建时只有空月份会被自动带出** 🟢 |
| 调整季度编制 | 可以选择“调整周期范围”，把本次增减量**逐期加到**范围内的各个后续周期上；新增或调整的细分编制也在范围内各期同步。勾选「同步更新上级组织的编制」时，范围内各期的上级编制同步更新 |
| 调整留痕 | 每次调整都记入「组织编制调整历史」 |
| 复制生成下期（144048458） | 选中本期的编制条目，复制出下一期。**后台异步执行，整批要么全部成功，要么全部不生成**，结果通过消息通知 |

→ 复刻要点：编制是 **（组织，周期）** 粒度的时间序列。「向后更新」是按**差值**传播，不是覆盖，且**只作用于调整时选定的周期范围**（AC-EST-05 实测）。

## 5. 编制时机：何时占编、何时释放（24248348）

| 业务 | 可选时机 | 占编 / 释放含义 | 何时做超编校验 |
|---|---|---|---|
| Offer 占用 | 发起 Offer 审批 / Offer 审批通过 / 发送 Offer / 接受 Offer / 不占编 | 从该状态起计为预增员，占**入职日期所在周期**的编制 | 该时机及其后续各步骤。选“接受 Offer”时，超编也不影响候选人接受，但超编的 Offer **不能转为待入职** |
| 入职占用 | 新增待入职 / 提交申请 / 审批通过 | 计为预增员，占入职日期所在周期 | 入职、入职申请、审批通过、新增内部员工、新增实习生、实习转正等 |
| 调入占用 | 提交申请 / 审批通过 | 计为预增员，占**调动生效日期所在周期** | 调动、调动申请、审批通过、转正相关 |
| 调出释放 | 提交申请 / 审批通过 | 计为预减员，释放生效日期所在周期的编制 | — |
| 离职释放 | 提交申请或审批通过，各自再分“按生效日期释放”或“立即释放”（当前及未来周期） | 计为预减员 | — |

- 约束：**设置了 Offer 占编时，入职占编时机必须是「新增待入职」**。进入待入职阶段的 Offer 只算入职预增员，不重复计为 Offer 预增员。
- 审批被拒或撤销时，预增员 / 预减员自动回退。

## 6. 编制在业务中的使用（88375670）

- Offer、入职、调动、新增人员表单上配置「编制信息」字段后，会联动显示编制情况。**支持带编调动**（对应任职记录字段 `IsTranferWithEstablish`、`TranferChangeEstablishResult`，见 15 字段规格）。
- 部门负责人在「我的团队」可以看到所负责组织的编制与在编人员；HR 在组织列表中可以看到编制数。
- ⚠️ **批量操作不做编制校验**：批量发 Offer、导入、批量调动、批量入职。**这是原站的已知缺口。复刻版按 DEC-015：批量操作不拦截，但逐行标出超编警告。**
- **定时生效时的编制（DEC-052，2026-09-30，复刻规则）**：未来日期的调动在生效日由定时任务落地时，如严格控制下编制已不足，该单**生效失败**（记 failed、次数、原因，生成 HR 待办），不静默超编；HR 调整编制或单据后重试（AC-TRF-31）。
- **带编调动（Q-M0-18，2026-10-05 只读：字段说明 + 手册）**：
  - 数量：固定 1 人份。字段 `IsTranferWithEstablish` 说明原文：选【是】则「调动完成后人员原部门编制减1，新部门编制加1」→ **调出方同步减编**。
  - 时点：调动**生效后**执行；执行结果记入任职记录 `TranferChangeEstablishResult`（调动调编结果，“记录调动业务生效后，编制调整的执行结果”），失败原因记入 `TranferChangeEstablishRemark`（调动调编执行备注）→ 原站允许调编执行失败、事后可查。
  - 校验：手册 247661639「客户操作的是带编调动，当前**不会进行超编校验 + 细分编制匹配校验**」。即带编调动跳过编制管控。
  - 细分编制如何分配（Q-M0-18，2026-10-05 写入实测 W-488～W-491）：测试方案 SCH_P 按职位细分、仅维护本级。FWD_O1 细分 POS_B = 3、FWD_O2 细分 POS_C = 3（预留 0，组织编制各 3）。TRF_T1 当天带编调动 O1（**无职位**）→ O2 / POS_C，保存后立即执行：
    - 调入方：O2 组织编制 3 → **4**，与新职位匹配的细分 POS_C 3 → **4**（实有 1 → 2）；
    - 调出方：O1 组织编制 3 → **2**，细分 POS_B 仍为 3（员工原无职位，没有可匹配的细分）→ 组织编制**小于细分之和**，违反 §3「组织编制 ≥ 细分之和」约束也照样执行；
    - O1 的「组织编制调整历史」只有一条“本级 2、版本 1、最新”→ 带编调整是**原地改写**编制数，不生成新的调整版本；
    - 未测：调出方原职位**有**匹配细分时是否同步 −1（F2 被“存在未生效的调动记录”拦下，见下条）；按调入方表现推断为同样按原职位 −1。
    - 复刻现状：`transfer/service.ts` 对带编调动返回 503（TODO 需取证 Q-M0-18）→ 登记册 **D-054**，用户选②，已登记 **DEC-181**（F-018 实现）。
  - 附带（W-491 前的失败尝试）：员工有**审批通过、尚未生效**的调动申请时，直接调动同样被拒，提示“〈员工〉当前存在未生效的调动记录（生效日期：…），无法进行此操作”（与审批中时的提示语不同）→ 登记册 **D-055**，用户选①，已登记 **DEC-182**（并入 F-017）。
  - 关联手册（编制时机，24248348 / 101192256）：调入占编、调出释放各按「提交申请 / 审批通过」时机统计在途增员 / 减员，统计在**调动生效日期对应周期**的编制中；这是普通调动的占编口径，与带编调动改编制数是两件事。
  - 旁证：W-461 把 EST_EMP_01 调回 EST_A 时（未选带编）弹出「本级编制将超编1人（编制1，实有1，预增0，预减0，本次1）」的确认框，确认后可保存（该组织为非严格控制）。
- 招聘需求超编时，满足以下任一条件的操作人可以看到「调编申请」链接：① 超编部门或其上级部门的负责人；② 持有指定 HR 类身份，且其管理单元覆盖该超编部门。

## 7. 编制维度（138117861）

- 自定义维度 = **编制维度字段**（编制对象上，多选才能多值控编）＋ **业务控编字段**（任职记录 / Offer 上，单选，且任职记录上的必须是继承字段）。两者的选项编码必须一致，系统提供「查看字段选项」来检查是否匹配。
- 也可以用 职务序列、职级、职位、职务 对象上的属性（如职级类别、一级序列）做维度，通过触发器数据源实现。
- 新建维度后，系统会自动在 细分编制审批 和 占编人员范围 对象中创建同编码字段。
- 标准维度只能改名，不能停用或删除；预置维度 1–5 和自定义维度的可操作项更多（原表截断，⏸）。

## 10. 组织编制对象实际字段（2026-09-22 🟢 配置证据）

`TenantBase.OrganizationEstablishment`：84 个标准字段、3 个自定义字段。要点如下：
- 周期：`Year`、`Quarterly`、`Month`、`EstablishmentMonth`（年月）、`StartDate`、`StopDate`、`EstestablishmentScheme`（编制方案）、`AdjustmentOrgEstCycleScope`（调整的周期范围）
- 数字：`ThisLevelEstablishment`/`WithLowerEstablishment`、`ThisLevelSubdivideEstablishment`/`WithLowerSubdivideEstablishment`、`ReserveThisLevelEstablishment`/`ReserveWithLowerEstablishment`、实有 `ThisLevelCount`/`WithLowerCount`、预增 `OccupyThisLevel`/`OccupySubordinate`、预减 `ReleaseThisLevel`/`ReleaseSubordinate`、缺编 `ThisLevelVacancyCount`/`WithLowerVacancyCount`、各项预估成本
- 管控：**`StrictControl` 严格控制（单选框）**、`SyncAllParent` 同步各上级、`EstablishmentType` 编制类型
- **版本**：`Version`（版本号）、`YearLatestVersion`（是否最新版本）。说明编制记录本身也有**版本链**，调整编制会产生新版本，而不是原地修改 → 与「组织编制调整历史」对应（🟡 推断）
- 细分维度：每个维度都有两种字段，**复选框版**（编制行上多值，如 `OIdJobPost`、`EmployType`）和 **V3 单选版**（如 `OIdJobPostV3`），另有预置维度 `Dimension1–5`。这与 §7 的“编制维度字段（多选）↔ 业务控编字段（单选）”一致
- 其他：`SubdivisionEstablishmentList(V2)`、`EstablishOrganSettingScope`（编制部门范围）、`ReserveCostsInfo`

职位 `TenantBase.Position` 上也直接挂有 编制数 / 实有 / 预增 / 预减 / 超缺编，说明**编制可以细分到职位**（见 19 §2）。

## 11. 2026-10-03 取证：占编人员范围与在岗人数口径（Q-M0-15，A5，只读）

> 来源：本租户「编制设置 - 编制方案」列表（36 个方案）只读；官方手册 HRSAAS 39387438（编制方案）、CustomerKB 158925045、196182071、126749072、100565522、170721984、202015630。

| 项 | 原站口径 |
|---|---|
| 占编人员范围的条件 | 用**雇佣关系**及其他编制维度（标准：用工形式、人员类别、人员来源等；也可用任职记录自定义字段建“编制自定义维度”）写条件；一条条件内**不同字段之间“且”、同一字段多个值之间“或”**；最多 5 条，**多条取并集**。不在任何一条里的人不占编 |
| 本租户实际取值 | 测试方案 SCH_Y / SCH_M 为“雇佣关系 = 内部员工”；其他方案常见“雇佣关系 ∈ {内部员工, 实习生, 外部人员} 且 用工形式 ∈ {…} 且 人员类别 ∈ {…}” |
| 外部人员 | 新增、编辑外部人员**不做编制校验**；但若占编人员范围包含外部人员，会计入实有人员、预增员、预减员 |
| 实有人员 / 预增 / 预减 | 按编制时机（§5）计：符合占编人员范围的人，在占编时机之后计入预增员，生效后计入实有；释放同理 |
| 组织架构图“在岗人数” | **另一套口径**，与占编人员范围无关：设置在「组织员工 - 设置 - 组织架构图显示信息 - 在岗 / 兼职人数统计范围」，按雇佣关系、用工形式、人员类别、人员来源筛选（不选则不过滤）；只算**主职**、审批状态 = 生效、人员状态 = 试用或正式、在数据日期当天有效的任职记录（数据日期 = 今天时再加“当前生效 = 是”）；兼岗数单列 |
| 职务 / 职位的在岗人数 | 只在“启用的职务”等视图实时计算，其他视图显示“--” |

- 复刻（R1-T09 / R1-T04 编制衔接）：占编判定按方案的“条件并集”实现，条件字段可配置；“在岗人数”统计口径单独做租户设置，不要复用占编范围。
