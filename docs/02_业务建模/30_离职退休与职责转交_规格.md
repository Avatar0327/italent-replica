## 1. 离职（R2-T03）

### 1.1 入口与方式
| 方式 | 说明 |
|---|---|
| 离职申请 | 员工自助（PC / 移动）、经理为下属、HR 代发；走审批，审批中可编辑 |
| 批量离职申请 | 添加人员或 Excel 导入；提交后**每人一条流程**，审批人收到**合并待办**，可批量同意 / 不同意 / 编辑；失败记录可在消息中查看并修改重提 |
| 直接离职 / 批量离职 | 无审批，直接写任职记录 |
| 导入离职 | ① 在职员工批量导入离职；② 导入**历史离职人员**（系统中不存在的人，上线初始化用） |

### 1.2 规则
| # | 规则 |
|---|---|
| DM-R1 | 前置：配置离职流程；维护 离职类型（异动类型）、离职原因（变动原因）、**离职去向**（设置 > 离职退休，可停用，只有启用的可选） |
| DM-R2 | 离职申请可勾“加入黑名单”，**离职生效后**进入黑名单；黑名单人员不允许再入职 |
| DM-R3 | **离职自动加黑规则**：规则 = 名称、优先级（不可重复）、适用组织、加黑条件（离职次数、任职 / 员工信息字段、考核结果个数、其他子集）、加黑期限（永久 / 指定 N 个月 / 离职当月，自然月或非自然月）、原因、说明；总开关开启后离职时自动匹配 |
| DM-R4 | 审批通过且到最后工作日次日**自动生效**，员工变离职状态 |
| DM-R5 | **撤销离职**（按审批状态分四种）：审批中 / 驳回 / 草稿 → 流程作废；审批通过 → 删除离职记录；生效且今天 ≤ 最后工作日 → 删除记录；生效且今天 > 最后工作日 → 删除记录并**恢复在职**。撤销后列出需手工处理的下游数据（合同、职责转交、离职交接、薪资档案等）；可填撤销原因，有“撤销的离职记录”视图 |
| DM-R6 | 撤销 / 删除任职 / 撤销离职三者区别：撤销 = 只撤审批中的流程；删除任职 = 删任意已通过或生效的任职记录；撤销离职 = 按状态自动选择并提示下游 |
| DM-R7 | **改期离职**：编辑最后工作日；按改期方向校验下游数据并提示：改早 → 薪资档案、社保档案；改晚但早于今天 → 另加 假期余额、调休假、育儿假；改到今天之后 → 另加 职责转交 |
| DM-R8 | 离职 / 退休**生效时终止在途流程**（可配置哪些流程）；同时终止不走审批的待办：新员工融入（状态、任务改为已终止）、入职准备待办（删除）、信息采集待办（改为已办） |
| DM-R9 | **账号停用时间**：可在“实际离岗日”（≤ 最后工作日，未填时 = 最后工作日）或“最后工作日”的指定时刻停用账号；可选审批中也停用；发起时已过该时刻则**立即停用**；之后把日期改晚于今天 → **重新启用账号** |
| DM-R10 | **离职人员重聘**：新建 Offer / 待入职 / 员工时，证件号码、邮箱（手机号需开关选为重聘标识）与离职人员重复 → 弹窗确认后带出原信息并关联，变动类型 = **重聘入职**；编辑待入职、信息采集确认时也可合并；导入可选重聘方式 |

### 1.3 离职交接
| # | 规则 |
|---|---|
| DM-R11 | 交接事项在「设置 > 离职退休交接事项」配置：待办类别（工作交接 / 其他）、事项办理表单、**适用人群 + 负责人**规则；可复制 |
| DM-R12 | 两种模式（**互斥**）：① **独立交接流程**（交接未完成不影响离职生效）；② **交接节点嵌在离职流程中**（交接不完成则离职流程无法完成）——使用②时须关闭“是否启用离职交接流程” |
| DM-R13 | 独立交接的发起方式：手工；离职 / 退休流程**发起时**或**某节点同意时**（触发器，条件：开关开启、雇佣关系 = 内部员工 / 实习生、交接状态 ≠ 进行中 / 已完成）；审批通过时自动；审批通过且距最后工作日 ≤ N 天自动（审批通过晚于或等于最后工作日 → 立即；早于 → **离职生效当天凌晨**）；“包含最后工作日早于审批通过日期的人员”可选 |
| DM-R14 | **直接离职（无审批）只能手工发起交接** |
| DM-R15 | 自动发起时的发起人默认：审批通过 / 距 N 天 → 离职流程发起人；流程发起触发 → 流程发起人；节点触发 → 该节点审批人（可另设发起人规则） |
| DM-R16 | 交接审批人由触发器按事项取；支持**并行交接节点**，每个事项独立设流转规则（一人同意 / 全部同意 / 50%） |
| DM-R17 | 各事项负责人勾“办理完成”；全部完成 → 交接状态 = 已完成；发起失败显示原因；员工本人可在人事申请中查看交接进度 |

### 1.4 复刻口径：申请单层与版本链（DEC-215 / DEC-125，有意差异）
- 原站离职**审批中就写入任职版本链**（Q-M0-50、登记册 D-031）；复刻按 DEC-125 **生效时才写**。审批期间只存离职申请单。
- 因此以下状态都由**离职申请单**表达，不读版本链：
  - “离职中”（工作台、员工自助，口径对照 Q-M0-76 / Q-M0-86）：存在未作废、未生效的离职申请单的人；在岗统计不排除（与原站一致）。
  - 撤销离职（DM-R5）：审批中 / 驳回 / 草稿 → 申请单作废；审批通过未生效 → 申请单作废（无版本可删）；已生效 → 删除离职版本，今天 > 最后工作日时恢复在职。
  - 改期（DM-R7）：未生效时改申请单的最后工作日；已生效时改版本，下游校验同 DM-R7。
- 与在途调动（DEC-166）：发起离职时若该员工有审批中的调动申请，**保存前弹确认框**提示该调动将在离职生效时作废；确认后保存，离职生效时作废该调动申请（对应原站 Q-M0-64 的确认框）。存在“审批通过未生效”的调动时：🟢 原站同样**不拦截**，提交时弹确认“请确认以下信息后，再继续操作——〈员工〉存在晚于离职最后工作日的调动任职（生效日期：2026-10-20），离职生效后会自动终止作废该任职”（Q-M0-87，2026-10-06，A0 对 FWD_F2 发起离职、最后工作日 10-15，确认框处取消、未提交）。只提示**生效日晚于最后工作日**的调动；生效日不晚于最后工作日的调动先生效、再离职，推定不提示。复刻口径见登记册 D-059。
- 职责转交时机（DEC-213）：租户级可配置，系统默认“业务生效时”（DT-R3）；本租户迁移可配为实测的“流程审批通过时”。
- 撤销离职时合同的终止范围：待 Q-M0-88 实测后由用户决定（暂不定口径）。

## 2. 退休（R2-T04）

| # | 规则 |
|---|---|
| RT-R1 | 视图：即将退休（默认 30 天内，未发起）、退休中（流程中或已通过未到日期）、**过期未退休**、已完成、全部 |
| RT-R2 | 退休 / 退休申请（HR、员工自助）；支持审批、职责转交、退休交接；生效后员工信息「实际退休日期」= 退休生效日 |
| RT-R3 | **退休同时返聘**：返聘日 = 退休最后工作日次日；可同时填返聘后的合同、薪资；**账号不关闭**，未转交的管理角色保留；入职类型记为“退休返聘” |
| RT-R4 | 撤销退休 = 删除退休任职记录，人员回到退休前状态 |
| RT-R5 | **预计退休日期自动计算**（每天凌晨）：规则类型 = 固定年龄（按组织范围 + 人员条件，最多 10 条条件字段）或高级公式；预置“延迟法定退休年龄”标准规则（**不可改**，需复制后改）；按优先级匹配，**命中一条即停止**；“预计退休日期已核准 = 是”的人不再被重算 |
| RT-R6 | 弹性退休范围：最早提前 / 最晚延迟退休日期按规则计算；预计退休日期为空时清空范围；任职记录「退休类型」区分提前 / 正常 / 延迟退休 |
| RT-R7 | 预置规则中若员工未维护“个人身份”，**女员工预计退休日期会被算为空**（手册明确提示） |

## 3. 职责转交（R2-T09）

| # | 规则 |
|---|---|
| DT-R1 | 职责范围：组织角色（部门负责人、HRBP 等）、下属员工（直线 / 虚线）、入离职事项负责人、流程矩阵角色、流程变量角色、绩效活动负责人、**系统身份（仅手动授权的，不含自动授权）**；页签按设置显示，未开通的应用不显示 |
| DT-R2 | 入口：「职责转交」菜单（立即生效，可选未来日期）；离职 / 调动 / 退休 的表单与审批中 |
| DT-R3 | 转交时机（开关开启后可选，默认“业务生效时”；DEC-213：租户级可配置，系统默认业务生效时，本租户迁移可配为“流程审批通过时”）：业务生效时 / 流程审批通过时 / 指定日期。指定日期 ≤ 今天 → **当前节点通过后**立即转交；晚于业务生效日 → 业务生效时一并转交，并把时机改为“业务生效时”；已转交的不能再改时机 |
| DT-R4 | 强校验：离职按钮参数或审批“同意”按钮类型决定——存在未转交职责时**拒绝**或**仅二次提示**；可按节点选择不校验 |
| DT-R5 | **未转交就离职**：系统清空其作为部门负责人 / HRBP / 直接上级的值；离职 / 退休人员（3 个月内）可在菜单中补转交 |
| DT-R6 | 接收人已离职 / 退休或有已通过的离职申请 → 提示；下属转交造成**汇报线循环** → 报错 |
| DT-R7 | 转交生成记录（开关）：**生成任职记录**（下属的直线经理变化 → 在其生效主职时间轴上插入异动类型 = “数据调整”的调动记录；待入职、审批中、兼职记录只更新字段不插入）；**生成组织变更记录**（负责人、分管领导变化）。生效日：流程内指定日期 → 该日；未指定 → 取 转交执行日 与 业务任职生效日 中的**较早者**；直接转交 → 执行日 |
| DT-R8 | 转交身份：接收人为默认管理单元时，被转交人的管理单元一并转给接收人；否则接收人的管理单元不变 |
| DT-R9 | 转交记录只能查看权限范围内人员的 |

## 5. 验收场景（AC-DM-* / AC-RT-* / AC-DT-*）

| AC-RT-01 | 退休同时返聘 | 返聘日 = 最后工作日 + 1，账号不关闭，入职类型 = 退休返聘 | 🟡 |

| AC-DT-01 | 离职未转交职责，强校验按钮提交 | 拒绝 | 🟡 |

| AC-DT-05 | 指定日期晚于离职生效日 | 离职生效时一并转交，时机改为业务生效时 | 🟡 |

## 7. 本租户证据（🟢，`01_证据/导出/R2_本租户配置与数据_A0.md` §4）
