## 1. 离职（R2-T03）

### 1.1 入口与方式
| 方式 | 说明 |
|---|---|
| 离职申请 | 员工自助（PC / 移动）、经理为下属、HR 代发；走审批，审批中可编辑 |
| 批量离职申请 | 添加人员或 Excel 导入；提交后**每人一条流程**，审批人收到**合并待办**，可批量同意 / 不同意 / 编辑；失败记录可在消息中查看并修改重提 |
| 直接离职 / 批量离职 | 无审批，直接写任职记录 |
| 导入离职 | ① 在职员工批量导入离职；② 导入**历史离职人员**（系统中不存在的人，上线初始化用） |

### 1.2 规则
| # | 规则 |
|---|---|
| DM-R1 | 前置：配置离职流程；维护 离职类型（异动类型）、离职原因（变动原因）、**离职去向**（设置 > 离职退休，可停用，只有启用的可选） |
| DM-R2 | 离职申请可勾“加入黑名单”，**离职生效后**进入黑名单；黑名单人员不允许再入职 |
| DM-R3 | **离职自动加黑规则**：规则 = 名称、优先级（不可重复）、适用组织、加黑条件（离职次数、任职 / 员工信息字段、考核结果个数、其他子集）、加黑期限（永久 / 指定 N 个月 / 离职当月，自然月或非自然月）、原因、说明；总开关开启后离职时自动匹配 |
| DM-R4 | 审批通过且到最后工作日次日**自动生效**，员工变离职状态 |
| DM-R5 | **撤销离职**（按审批状态分四种）：审批中 / 驳回 / 草稿 → 流程作废；审批通过 → 删除离职记录；生效且今天 ≤ 最后工作日 → 删除记录；生效且今天 > 最后工作日 → 删除记录并**恢复在职**。撤销后列出需手工处理的下游数据（合同、职责转交、离职交接、薪资档案等）；可填撤销原因，有“撤销的离职记录”视图 |
| DM-R6 | 撤销 / 删除任职 / 撤销离职三者区别：撤销 = 只撤审批中的流程；删除任职 = 删任意已通过或生效的任职记录；撤销离职 = 按状态自动选择并提示下游 |
| DM-R7 | **改期离职**：编辑最后工作日；按改期方向校验下游数据并提示：改早 → 薪资档案、社保档案；改晚但早于今天 → 另加 假期余额、调休假、育儿假；改到今天之后 → 另加 职责转交 |
| DM-R8 | 离职 / 退休**生效时终止在途流程**（可配置哪些流程）；同时终止不走审批的待办：新员工融入（状态、任务改为已终止）、入职准备待办（删除）、信息采集待办（改为已办） |
| DM-R9 | **账号停用时间**：可在“实际离岗日”（≤ 最后工作日，未填时 = 最后工作日）或“最后工作日”的指定时刻停用账号；可选审批中也停用；发起时已过该时刻则**立即停用**；之后把日期改晚于今天 → **重新启用账号** |
| DM-R10 | **离职人员重聘**：新建 Offer / 待入职 / 员工时，证件号码、邮箱（手机号需开关选为重聘标识）与离职人员重复 → 弹窗确认后带出原信息并关联，变动类型 = **重聘入职**；编辑待入职、信息采集确认时也可合并；导入可选重聘方式 |

### 1.3 离职交接
| # | 规则 |
|---|---|
| DM-R11 | 交接事项在「设置 > 离职退休交接事项」配置：待办类别（工作交接 / 其他）、事项办理表单、**适用人群 + 负责人**规则；可复制 |
| DM-R12 | 两种模式（**互斥**）：① **独立交接流程**（交接未完成不影响离职生效）；② **交接节点嵌在离职流程中**（交接不完成则离职流程无法完成）——使用②时须关闭“是否启用离职交接流程” |
| DM-R13 | 独立交接的发起方式：手工；离职 / 退休流程**发起时**或**某节点同意时**（触发器，条件：开关开启、雇佣关系 = 内部员工 / 实习生、交接状态 ≠ 进行中 / 已完成）；审批通过时自动；审批通过且距最后工作日 ≤ N 天自动（审批通过晚于或等于最后工作日 → 立即；早于 → **离职生效当天凌晨**）；“包含最后工作日早于审批通过日期的人员”可选 |
| DM-R14 | **直接离职（无审批）只能手工发起交接** |
| DM-R15 | 自动发起时的发起人默认：审批通过 / 距 N 天 → 离职流程发起人；流程发起触发 → 流程发起人；节点触发 → 该节点审批人（可另设发起人规则） |
| DM-R16 | 交接审批人由触发器按事项取；支持**并行交接节点**，每个事项独立设流转规则（一人同意 / 全部同意 / 50%） |
| DM-R17 | 各事项负责人勾“办理完成”；全部完成 → 交接状态 = 已完成；发起失败显示原因；员工本人可在人事申请中查看交接进度 |

### 1.4 复刻口径：申请单层与版本链（DEC-215 / DEC-125，有意差异）
- 原站离职**审批中就写入任职版本链**（Q-M0-50、登记册 D-031）；复刻按 DEC-125 **生效时才写**。审批期间只存离职申请单。
- 因此以下状态都由**离职申请单**表达，不读版本链：
  - “离职中”（工作台、员工自助，口径对照 Q-M0-76 / Q-M0-86）：存在未作废、未生效的离职申请单的人；在岗统计不排除（与原站一致）。
  - 撤销离职（DM-R5）：审批中 / 驳回 / 草稿 → 申请单作废；审批通过未生效 → 申请单作废（无版本可删）；已生效 → 删除离职版本，今天 > 最后工作日时恢复在职。
  - 改期（DM-R7）：未生效时改申请单的最后工作日；已生效时改版本，下游校验同 DM-R7。
- 与在途调动（DEC-166）：发起离职时若该员工有审批中的调动申请，**保存前弹确认框**提示该调动将在离职生效时作废；确认后保存，离职生效时作废该调动申请（对应原站 Q-M0-64 的确认框）。存在“审批通过未生效”的调动时：🟢 原站同样**不拦截**，提交时弹确认“请确认以下信息后，再继续操作——〈员工〉存在晚于离职最后工作日的调动任职（生效日期：2026-10-20），离职生效后会自动终止作废该任职”（Q-M0-87，2026-10-06，A0 对 FWD_F2 发起离职、最后工作日 10-15，确认框处取消、未提交）。只提示**生效日晚于最后工作日**的调动；生效日不晚于最后工作日的调动先生效、再离职，推定不提示。复刻口径见登记册 D-059。
- 职责转交时机（DEC-213）：租户级可配置，系统默认“业务生效时”（DT-R3）；本租户迁移可配为实测的“流程审批通过时”。
- 撤销离职时合同的终止范围：待用户决定（Q-M0-88 实测见 1.5）。

### 1.5 离职与合同、离职交接、离职证明（Q-M0-88、Q-M0-85、Q-M0-90 补充，2026-10-06 写入实测 W-513～W-518，用户同意）
样本：测试员工 M01_EMP_005，名下劳动合同 CONTRACT_001（固定期限，生效 2026-09-11，原终止日 2026-10-10，状态有效、业务类型新建）。A0 发起离职申请，最后工作日 2026-10-05（已过），两个审批节点转交 A0 后同意，随后在「已完成的离职」撤销离职。
- 🟢 **提交（审批中）**：合同不变（仍有效、无实际终止时间）。
- 🟢 **审批通过（最后工作日已过 → 立即生效）**：同一份合同被自动改为 状态 = 终止、实际终止时间 = 最后工作日（2026-10-05）、业务类型 = 终止（签订次数不变，不新增记录），并出现「终止协议电子签署」操作。本样本审批通过与生效是同一时刻，“通过即终止”还是“生效才终止”未能区分（未来最后工作日的情形转后续 Q-M0-100）。
- 🟢 **撤销离职（已生效后）**：入职任职记录恢复为任职中、离职记录删除；**合同不恢复**，仍为终止 / 实际终止时间 10-05——与 DM-R5“撤销后列出需手工处理的下游数据（合同…）”一致。撤销需填写必填的“撤销离职原因”。
- 🟢 离职生效时离职记录换了新 id（审批中记录 f1cd… → 生效记录 090c…），即生效时重写版本。
- 🟢 离职生效后自动发起离职交接（离职交接状态 = 进行中，交接人为异常管理员），与交接发起规则（审批通过时发起）一致；**撤销离职后该离职交接流程被系统自动置为“已终止”**（与合同不同，交接会自动收回）。
- 🟢 HR「离职管理（离职中的员工 / 已完成的离职 / 全部离职记录）」：离职中的员工默认审批状态 ∈ {草稿, 审批中, 审批通过, 已驳回}，行操作「离职处理 / 编辑离职」——**审批中的离职可由 HR 编辑**；已完成的离职行下拉有「撤销离职」，页面说明含“批量打印离职证明”，列含“签署状态 / 离职证明电子签署附件 / 附页”（离职证明入口线索，Q-M0-90）。
- 本租户离职流程：「新版标准离职流程」DimissionProcessNew，开始 → 直接上级 → HR访谈 → 结束；直接上级为空时转异常管理员。


**离职证明 / 离职交接单的打印入口（Q-M0-90，2026-10-07 只读：手册 38801232、103254656、101189588、100565387、133531538、100565510 + 列表视图定义）**
- 🟢 **有非电子签入口**，共三类：
  1. **批量打印离职证明**：在「已完成的离职 / 全部离职记录」列表勾选人员后点此按钮。选 1 人时直接弹出生成的离职证明预览；选多人时提示到“通知”里下载。前提是租户已配好离职证明打印模板（组织员工 → 模板管理 → 打印模板，实体 = 任职记录，按钮的高级设置里挂模板），并且这个按钮已配到列表上（它是可配置按钮，不一定默认显示）。
  2. **打印离职交接单**：在「全部离职记录」行上点，选择打印模板后生成打印表单。系统预置模板「离职全部事项交接单」，数据集为【离职交接全部事项详情页】。用于离职交接审批完成后存档。
  3. **服务中心开具离职证明**：员工侧服务中心，模板在 服务中心 → 模板管理 → 打印模板 中维护。
- 🟢 电子签入口（对照）：列表行按钮【离职证明电子签署】，列表上有 签署状态 / 签署附件 / 附页 三列；还有详情页级按钮，可配到离职流程或离职交接流程的审批详情页，在审批中就能发起。场景为员工签字、企业自动盖章，盖章法人取离职人员当前生效的劳动合同、实习协议或劳务合同对应的法人公司。撤销签署要到电子签应用里操作，不支持提醒签署。
- 🟢 本租户列表行操作（DimissionEmployeeListView 定义）：催办、转交、撤销、离职处理、编辑离职、撤销离职、删除任职，**没有配置打印 / 电子签行按钮**。2026-10-07 复查发现，A0 的「离职管理」菜单已改为单视图（ConsoleHRBPDimissionListView），10-06 看到的三个页签不再显示（租户配置变化，非我方写入），所以批量打印按钮这次没能在界面上看到。
- 复刻口径：首版做「打印离职证明」（单人预览 / 多人生成后到通知下载）和「打印离职交接单」，都按打印模板渲染；电子签按 R2 范围另议。

**撤销离职、改期时的下游处理清单（Q-M0-94，2026-10-08 只读：手册 103254658 撤销离职、165348606 改期离职、183304770 编辑离职、150012971、133532064；实测对照 W-108、W-518）**
- 🟢 **改期入口**：离职管理行按钮【编辑离职】，修改“最后工作日”。审批中的离职需由当前审批人在审批详情页的【同意 / 编辑】中修改；也可以在任职记录【编辑任职】改离职记录的开始日期。手册列出会触发同一校验的按钮共 20 余个，包括 EditDimissionRecord、EmploymentRecord.Edit、EditUser、EmpInfo.Edit 等。
- 🟢 **改期校验的下游数据**（只有**原最后工作日**上确有这些数据时，才在**保存成功后**弹出“可能受影响、需要手工处理的数据及操作路径、操作方法”；没有就不弹）：
  - 改早（早于原最后工作日）：薪资档案、社保档案。
  - 改晚但早于今天：薪资档案、社保档案、假期余额、调休假、育儿假。
  - 改到今天之后：职责转交、薪资档案、社保档案、假期余额、调休假、育儿假。
- 🟢 **撤销离职**：撤销前会对离职生效时处理过的“合同、职责转交、离职交接、薪资档案等”给出提示；撤销的离职记录在生效时触发过下游更新的，撤销成功后弹出需手工处理的数据及操作路径、操作方法。撤销原因必填，事后可在「撤销的离职记录」视图查看和修改。
- 🟢 **弹窗前提**：提示页是「通用信息承载页面」（CommonInformationPage），要在身份管理里给相应身份授予这个页面的 PC 端页面权限才会显示。
- 🟢 **本租户实测**：
  - W-108：四种审批状态下撤销离职，均无下游数据，**不弹清单**，只有必填的撤销原因。
  - W-518：撤销一条生效时已把合同改为终止的离职，**也没有弹清单**，合同保持终止不恢复（见上文）。这说明，要么合同不在弹窗触发范围内，要么本租户没给 A0 的身份授予 CommonInformationPage 页面权限。
  - 清单原文没能取到：本租户测试员工没有薪资 / 社保 / 假期档案，也没有可转交的职责，构造样本代价大。🟡 待 TRF_T1（Q-M0-100）生效后撤销时再观察一次。
- 复刻口径（DM-R5 / DM-R7）：按上面三个改期方向，以及撤销时的“合同、职责转交、离职交接、薪资档案”生成待处理清单（数据项 + 操作路径）。没有下游数据就不显示；有下游数据时，在保存或撤销成功后展示。清单文字由复刻自拟。

## 2. 退休（R2-T04）

| # | 规则 |
|---|---|
| RT-R1 | 视图：即将退休（默认 30 天内，未发起）、退休中（流程中或已通过未到日期）、**过期未退休**、已完成、全部 |
| RT-R2 | 退休 / 退休申请（HR、员工自助）；支持审批、职责转交、退休交接；生效后员工信息「实际退休日期」= 退休生效日 |
| RT-R3 | **退休同时返聘**：返聘日 = 退休最后工作日次日；可同时填返聘后的合同、薪资；**账号不关闭**，未转交的管理角色保留；入职类型记为“退休返聘” |
| RT-R4 | 撤销退休 = 删除退休任职记录，人员回到退休前状态 |
| RT-R5 | **预计退休日期自动计算**（每天凌晨）：规则类型 = 固定年龄（按组织范围 + 人员条件，最多 10 条条件字段）或高级公式；预置“延迟法定退休年龄”标准规则（**不可改**，需复制后改）；按优先级匹配，**命中一条即停止**；“预计退休日期已核准 = 是”的人不再被重算 |
| RT-R6 | 弹性退休范围：最早提前 / 最晚延迟退休日期按规则计算；预计退休日期为空时清空范围；任职记录「退休类型」区分提前 / 正常 / 延迟退休 |
| RT-R7 | 预置规则中若员工未维护“个人身份”，**女员工预计退休日期会被算为空**（手册明确提示） |

## 3. 职责转交（R2-T09）

| # | 规则 |
|---|---|
| DT-R1 | 职责范围：组织角色（部门负责人、HRBP 等）、下属员工（直线 / 虚线）、入离职事项负责人、流程矩阵角色、流程变量角色、绩效活动负责人、**系统身份（仅手动授权的，不含自动授权）**；页签按设置显示，未开通的应用不显示 |
