## 1. 权限体系的七个组成部分

| # | 组成 | 官方章节 | 作用（据章节名推断，待正文验证） |
|---|---|---|---|
| 1 | **用户授权** | 用户授权 | 给用户授予**身份**（Profile）；每个产品模块有独立的身份体系 |
| 2 | **管理员** | 管理员 | 企业管理员角色体系，存在多种管理员身份且权限不同 |
| 3 | **管理单元** | 管理单元 | 管理范围（MOU，对应对象 `UserFramework.Mou`） |
| 4 | **数据权限设置** | 数据权限设置（企业设置） | 数据范围控制 |
| 5 | **实施人员授权** | 实施人员授权 | 实施顾问的特殊授权 |
| 6 | **动态授权** | 动态授权 | **规则驱动的自动授权** |
| 7 | **权限查询** | 权限查询 | 反查某员工拥有什么权限 |

另有独立的《北森权限操作手册》，分为「功能类权限操作手册」与「数据权限操作手册」两册 —— 印证**功能权限与数据权限是两套独立机制**。

## 2. 身份（Profile）是按产品模块划分的

手册为 **36 个产品模块**各写了一份「XX用户授权说明」：

组织员工、假勤、薪酬、审批中心、薪酬工具、薪酬激励、预算管理、学习云、招聘、闪面、入职管理、目标管理、继任与发展、绩效管理V5、360度评估系统、员工调查、测评中心、报表、电子签、北森iTalent、ocean、Smart报告、个人发展计划、个税通、人才标准、人才模型、叫号系统、干部管理、成本管理、推荐运营中心、模板中心、证书证照、服务中心、数字人才、Mr. Sen、People Analytics

**对复刻的含义**：权限不是一张全局角色表，而是 **「模块 × 身份」** 的二维结构。用户在每个模块里各自持有若干身份。首版权限模型必须按这个结构建模，否则跨模块权限叠加会失真。

> 与运行证据的交叉印证：A0 实测可访问 `UserFramework.UserPermissionV2`（用户授权）、`UserFramework.AdminPermission`（管理员）、`UserFramework.Mou`（管理单元）三个独立对象，与手册的三个独立章节对应。

## 3. 从常见问题中提取的业务规则线索（待正文验证）

这些问题标题本身暴露了**必须复刻或必须明确差异**的规则：

| 线索 | 暗示的规则 | 复刻含义 |
|---|---|---|
| 「为什么门户管理员身份撤销不了？」「为什么问卷管理员身份撤销不了？」 | 存在**不可撤销的系统身份** | 需要身份的「可撤销性」属性 |
| 「撤销用户授权，提示自动授权的不能撤销」 | **自动授权产生的身份不能手工撤销** | 授权来源需区分「手工」与「自动」 |
| 「业务单元权限自动授权逻辑」 | 存在**基于业务单元的自动授权** | 权限可由组织归属自动推导 |
| 「新建和复制的身份，为什么授权时选择不到？」 | 身份有**生效/可授权前置条件** | 身份有状态，不是建完即可用 |
| 「为什么我自定义了一个角色但是在授权时却选不到这个角色呢？」 | **身份与角色是两个不同概念**，且角色可授权性受限 | 必须区分「身份 Profile」与「角色 Role」 |
| 「如何查看管理员的可授权身份/角色有哪些？」 | 管理员**只能授予自己可授权范围内的身份** | 授权存在**上限继承**：不能授出自己没有的权限 |
| 「启用动态授权规则后会自动执行吗？」「编辑后会自动执行吗？」「停用后会自动撤销之前授权的身份吗？」 | 动态授权规则的**启用/编辑/停用三个动作对存量授权的影响各不相同** | 这是典型的「配置变更对存量数据的影响」问题，需求必须写死 |
| 「登录页面提示【您没有登录系统的权限，请联系管理员】」 | 存在**登录级权限**，独立于功能权限 | 账号可登录 ≠ 有业务权限；需单独建模 |
| 「为什么已经购买开通了360产品，员工登录后还是在【暂不可用的业务】里？」 | **许可（License）与授权是两层**：买了不等于授了 | 许可管理需单独建模 |
| 「如何批量导入授权？」 | 授权支持批量导入 | 批量操作需求 |
| 「新来的员工，想给ta授权成和我一模一样的权限」 | 存在**权限复制**诉求（是否有功能待验证） | 候选需求 |

## 5. 复刻建模的强制要求（基于以上）

权限矩阵必须覆盖 **「角色 × 对象 × 操作 × 数据范围 × 字段范围 × 业务状态」**，且：

1. **功能权限与数据权限分开写**（原站是两套独立机制，两册独立手册）。
2. **身份按模块建模**，不做全局角色表。
3. **区分授权来源**：手工授权 / 自动授权（自动的不可手工撤销）。
4. **区分三层**：平台运营层（身份定义）／租户管理层（授予身份）／业务角色层（本人·直属团队·组织及下级·跨组织·全局）。
5. **许可与授权分层**：许可管理是独立前置条件。
6. **登录权限独立**：可登录 ≠ 有业务权限。
7. **管理员例外不得作为普通用户默认规则**（已实证 A0 与 A1 的差距是 966 : 37）。
