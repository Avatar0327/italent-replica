# 调动的跨对象联动：对象规格（R1-T10）

> 来源：配置证据 🟢（2026-09-27，A0 只读，`GetMetaFieldList`）+ `08_调动闭环_完整规格.md` §4–6（官方文档）+ `13` §7（调动表单结构，运行证据）。
> 下表只列业务字段，已剔除系统记账字段与共享人 / 共享部门字段。

---

## 1. 一次调动会碰到的对象

```
任职记录（调动记录，版本链上的一条）
 ├─ 合同协议 EmploymentContract ── 合同变动记录 ContractChangeRecord（LU_变动前合同）      ← 「是否变更合同」
 ├─ 兼职审批 ParttimeJobApproval（结束 / 调整兼职）                                    ← 「调整兼职」
 ├─ 职责转交 DutyTransfer ─┬─ 下属员工转交 DutyTransferEmployee                        ← 「转交职责」
 │                        └─ 组织角色转交 DutyTransferOrgRole
 ├─ 调动交接 TransferHandoverV2（交接状态、审批状态）                                  ← 调动交接规则（13 §6）
 ├─ 试岗期信息 OnTrialInformation ── 试岗期考核 OnTrialEvaluation                       ← 「试岗方式 / 试岗期限」
 ├─ 薪资档案 Compensation.SalaryProfile / 调薪管理 Compensation.SalaryAdjustment        ← 「是否调整薪资」
 └─ 组织变更记录 OrganizationChange（调整组织角色时，见 SwitchType 98）
```

任职记录上对应的关联字段（`15` 已取）：`IsChangeContract`、`LUContract`、`NeedTerminateContracts`、`AdjustSalary`、`LUSalaryProfile`、`LUSalaryAdjustment`、`DutyTransferLookUp`、`LUTransferHandoverV2Id`、`OnTrialMode`、`LUOnTrial`、`ParttimeJobInfo`、`AddSubordinate`、`IsTranferWithEstablish`。

## 2. 各联动对象要点

| 对象 | 标准业务字段（节选） | 与调动的关系 |
|---|---|---|
| **合同协议** `EmploymentContract`（66 个标准字段） | 编号、合同类型、公司名称/法人公司、期限类型、合同期限(月)、签订日期、生效日期、终止日期、实际终止时间、试用期起止、试用期工资、试用期满工资、签订次数、状态、审批状态、**版本号**、**原合同ID**、`LUEmploymentRecord`、`LUContractChangeRecord`、电子签署记录、是否即将到期、合同到期天数 | 调动勾选“变更合同”时生成合同变更。**合同本身也有版本号和原合同 ID**，变更 = 新版本，不是原地改 |
| **合同变动记录** `ContractChangeRecord` | 人员、组织、`LUBeforeChangeObjectID`（变动前合同） | 与任职记录同一模式：用“变动前”Lookup 串起版本链 |
| **兼职审批** `ParttimeJobApproval`（60） | 申请类型、是否结束兼职、兼职原结束日期、生效/失效日期、机构/部门/职务/职位/职级/职等、直线/虚线经理、是否部门负责人、`LUPartTimeRecord`、`LUPartTimeSalaryProfile`、执行结果、来源（含组织调整申请） | 调动时一并结束或调整兼职 |
| **职责转交** `DutyTransfer`（25） | 人员、**转交时机**、转交日期、职责总数、下属员工 / 组织角色 / 入离职事项职责数、任务数、失败数 | 调动时把原岗位上的职责转给他人 |
| 　下属员工转交 `DutyTransferEmployee` | 下属员工、接收人、汇报关系（直线/虚线）、转交状态、转交时间、批次ID、任职记录ID | 每个下属一条 |
| 　组织角色转交 `DutyTransferOrgRole` | 组织、组织角色、接收人、转交状态、转交时间、批次ID | 每个组织角色一条（如部门负责人、HRBP） |
| **调动交接** `TransferHandoverV2`（23） | 员工、任职记录 lookup、交接状态、审批状态、交接事项明细 | 审批通过时自动发起（13 §6） |
| **试岗期信息** `OnTrialInformation`（29） | 试岗开始日期、试岗期限(月)、预计 / 实际试岗结束日期、原预计结束日期、试岗状态、试岗到期天数、考核评价、考核结果 | 调动表单“试岗方式”触发 |
| 　试岗期考核 `OnTrialEvaluation`（32） | 考核日期、自评、考核评价、考核结果、**是否调整薪资**、`LU_调薪管理` | 考核通过可联动调薪 |
| **薪资档案 / 调薪** `Compensation.SalaryProfile`（266）/ `SalaryAdjustment`（299） | **每个薪资项展开成一组列**：`SalaryAmountN`（当前）、`…Adjusted`（调整后）、`…AdjustAmount`（调整额）、`…AdjustRatio`（调薪比例）；档案上还有“转正前 / 转正后”两组 | 属于薪酬模块。**薪资项是租户可配置的，字段随薪资项动态生成** |

## 3. 对复刻的要求

1. **联动是事务**：调动审批通过后，在**生效时**（不是审批通过时）一起执行：任职新版本、合同变更、兼职调整、职责转交、组织角色变更、试岗开始。任一失败时要有明确的补偿策略。原站职责转交有“失败数”，说明允许部分失败并记录。
2. **合同与任职同构**：都采用“新版本 + 指向变动前版本”的版本链，复刻时共用同一套版本化机制。
3. **删除回滚**：DEC-012，存在联动变更时阻止删除调动任职（见 REQ-TRF-005）。
4. **薪酬不在首版范围**（DEC-002 首版为组织员工、企业设置、审批中心、员工自助、人才链路）：
   - 首版调动只保存“是否调整薪资”标志，并在生效时生成一条“待调薪”提醒（任务或消息），**不直接改薪资档案**；
   - 薪资档案的“按薪资项动态展开列”是薪酬模块的设计要点，记录在此，留给后续阶段。
5. 试岗期、调动交接首版可以只做数据记录与到期提醒；试岗考核联动调薪同样依赖薪酬，暂缓。

## 4. 验收场景（AC-LNK-*）

| 编号 | 场景 | 预期 | 状态 |
|---|---|---|---|
| AC-LNK-01 | 调动勾选“变更合同”，审批通过，未到生效日 | 合同尚未变更 | 🔴 |
| AC-LNK-02 | 同上，到达生效日 | 生成新合同版本，并有一条合同变动记录指向变动前合同 | 🔴 |
| AC-LNK-03 | 调动人是部门负责人，勾选转交职责给 B | 生效时生成职责转交：组织角色转交 1 条（负责人 → B），下属员工转交 N 条 | 🔴 |
| AC-LNK-04 | 职责转交中 1 个下属转交失败 | 调动生效，职责转交记录的失败数 = 1，可查看失败明细并重试 | 🟡 由字段推断 |
| AC-LNK-05 | 调动勾选“调整薪资”（首版） | 不改薪资档案，生成“待调薪”提醒 | 🔴 |
| AC-LNK-06 | 调动勾选“结束兼职” | 生效时对应兼职的失效日期 = 调动生效日 − 1 天（🟡 推断，需确认口径） | 🔴 |
