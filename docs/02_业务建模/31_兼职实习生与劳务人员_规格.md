# 兼职、实习生与劳务人员：规格（R2-T05 / R2-T07）

> 取证：2026-09-28，A0 只读。官方文档 🟡：兼职 36798708、38798792、109724693/775/806/839/911/952、109725013/52/92/131/167、150011995；实习生 24248361、123241332/456/590/609/643/655、36800663、211715212、224297025、224297039；劳务 156565921/23/27。
> 与 R1 衔接：兼职是任职记录上的一条非主职记录（`07`、`15`），`ParttimeJobApproval` 对象见 `21`；主职 / 兼职区分影响向后更新（R1-T06）与审批人取值（`14`）。

## 1. 兼职（R2-T05）

### 1.1 模型
- 兼职 = 任职记录（非主职），与主职共用任职记录对象；**兼职审批**是独立对象 `ParttimeJobApproval`，审批通过后回写为一条任职记录。
- 兼职类型三种：**兼职、外派、借调**。外派、借调**同一时间只能有一份**；兼职可以同时多份。

### 1.2 规则（🟡）
| # | 规则 |
|---|---|
| PT-R1 | HR 直接维护：新增 / 编辑 / 结束 / 删除 / 导入 / 导出；结束兼职 = 填结束日期，**次日**任职状态变“结束” |
| PT-R2 | 走审批：新增兼职申请、延长兼职申请、结束兼职申请；发起人可为 HR（主职在其管辖范围内的员工）、员工本人（人事申请）、经理 / 部门负责人（团队成员） |
| PT-R3 | 兼职部门的选择范围受权限控制，开关「兼职部门受权限控制」（默认开）关闭后可选权限外部门；**员工本人发起申请时兼职部门始终不受权限控制** |
| PT-R4 | 兼职审批对象上的自定义字段按编码映射回写任职记录：审批对象字段编码 = `rzjl` + 任职记录字段编码 |
| PT-R5 | 兼职管理数据权限：主职在管理单元内的人的全部兼职 **∪** 主职不在管理单元内但兼职在管理单元内的兼职记录 |
| PT-R6 | 视图：兼职中（不含主职）、即将到期（结束日期 30 天内）、未开始、已结束、审批中的兼职、全部兼职 |
| PT-R7 | 可用自定义“预计兼职结束日期”做到期跟踪（企业只维护预计日期，到期不强制结束） |
| PT-R8 | **基于兼职发起审批**：假勤等单人申请表单上加“对应任职”Lookup，员工可选主职或兼职，审批人按所选任职取；批量场景不支持 |
| PT-R9 | **按兼职汇报线审批**：“直线经理的任职”取直线经理各条任职中**所在部门离员工任职部门（及其上级）最近**的一条，再取该任职的上级作为隔级经理；需在流程中改用该表达式并重新发布 |

## 2. 实习生（R2-T07）

| # | 规则 |
|---|---|
| IN-R1 | 新增实习生（可同时填实习协议）；选部门后直线经理默认 = 部门负责人；证件号、邮箱、手机号（后两者需在重聘判定规则中勾选）与离职人员重复 → 重聘提示（证件号是**固定**重聘标识） |
| IN-R2 | 离职的实习生可在“已离职”视图中直接“入职” |
| IN-R3 | 实习转正方式：HR 直接（单个 / 批量）、HR 申请（单个 / 批量，每人一条流程）、上级申请、员工本人申请、**正式 Offer**（来源 = 实习生转正） |
| IN-R4 | 实习转正会新增一条“实习转正”任职记录，到生效日变正式员工；**已结束实习（离职）的人不能再实习转正**，只能重聘入职 |
| IN-R5 | 实习转正的入职日期：开关「实习转正入职日期默认为实习入职日期」开 → 入职日期 = 实习入职日期（实习期计入司龄）；关 → 入职日期 = 实习转正生效日期 |
| IN-R6 | 实习转正定薪：按薪酬开关生成“待定薪”或直接更新薪资档案（薪酬不在首版 → 只记标志，同 `21` §3） |
| IN-R7 | 结束实习：选结束日期；实习转正中的人也可结束实习 |
| IN-R8 | **离职同步取消待入职**：最后工作日之后仅存在实习转正待入职时显示该字段；选“是”则离职时一并取消该待入职（校招先离校再回来入职的场景） |

## 3. 劳务人员（R2-T07）

| # | 规则 |
|---|---|
| LB-R1 | 用 **用工形式类别** 区分人员属性：正式员工 / 劳务 / 实习 / 外部（预置映射：劳务 = 劳务派遣、外包、兼职用工、退休返聘；外部 = 外部顾问）；劳务人员雇佣关系 = **内部员工**，可登录、可调动 |
| LB-R2 | 劳务人员管理视图：在岗（内部员工 + 用工形式类别 = 劳务 + 在职）、转正式中、已转正式、已离职；**所有视图依赖用工形式类别有值** |
| LB-R3 | 新增 / 编辑 / 导入劳务人员与正式员工规则一致（邮箱、工号生成等），用工形式只能选类别 = 劳务的 |
| LB-R4 | **劳务转正式** = 生成一条新任职记录：业务类型 = 入职，入职类型 = 变动类型 = 劳务转正式；用工形式只能选类别 = 正式；入职日期 = 转正式日期（**司龄重算**，如需沿用原入职日期须在表单上配置入职日期字段）；工号按工号生成规则沿用或新生成 |
| LB-R5 | 转正式可同时新签合同、薪资；可选“需要终止的原合同”，转正式生效时终止，实际终止日 = 新合同开始日 − 1 |
| LB-R6 | 转正式可发起信息采集（手动，走入职前信息采集规则与流程）；可给在职劳务人员发 Offer，但 Offer **不会转入待入职**，转正式仍需通过劳务转正式操作完成 |
| LB-R7 | 「离职 / 退休生效时终止在途流程」未勾选“劳务转正式”时，**不允许发起晚于劳务转正式日期的离职** |

## 补充：任职类型、用工形式类别与兼职占编字段（Q-M0-121 ①② / Q-M0-122 ③，2026-10-08，A0，只读）
- **任职类型 `TenantBase.ServiceType`**：主职 = 0、兼职 = 1、**返聘 = 3**、借调 = 4、外派 = 5（没有 2）。“返聘”是一种独立的任职类型，与 Q-M0-118 的返聘样本对应。PT-R1 的兼职 / 外派 / 借调同属非主职类型。
- **雇佣关系 `EmployType`**：内部员工 = 0、外部人员 = 1、实习生 = 2（与 `15` 一致）。
- **用工形式类别 `EmploymentFormType`**（在用工形式对象 `TenantBase.EmploymentForm` 上）：正式员工 = 1、劳务 = 2、实习 = 3、外部 = 4。劳务人员靠用工形式的类别 = 劳务来识别（LB-R1）。
- **兼职占编**：标准字段里**没有**“是否占人头 / 占编”。本租户有两个**自定义字段**：
  - `extshifouzhanbian_…` “兼职是否占编”（是否）；
  - `extjianzhizhanbianbili_…` “兼职占编比例”（小数 1 位）。
  - 任职记录编辑抽屉中出现的“兼职是否占人头”属于租户自定义（表单标签），不是标准能力。复刻首版不需要实现，可以留作扩展字段。
- 未做：外派 / 借调同期唯一的实测、兼职结束时点、申请回写、主职离职联动（写入）。

## 补充：人员信息各列表的过滤口径（Q-M0-122 ②，2026-10-08，A0，只读）
各列表都基于任职记录（`TenantBase.EmploymentRecord`）。口径取自页面默认带的筛选条件（search_data），条数为当日本租户值。

| 菜单（组织员工 → 人员信息） | 视图 / 搜索视图 | 默认条件 | 条数 |
|---|---|---|---|
| 在职员工 | `EmployedEmployeeListView` / `EmployedEmployeeSearchView` | 雇佣关系 = 内部员工(0)；人员状态 ∈ 试用(2)、正式(3)；任职类型 = 主职(0)；当前生效 = 是；审批状态 = 生效(4)；未删除 | 当日带了邮箱筛选，未取总数 |
| 实习生 | `TraineeEmploymentRecordList` / `TraineeEmployeeSearchView` | 雇佣关系 = 实习生(2)；人员状态 = 正式(3)；主职；当前生效；生效；未删除 | 28 |
| 劳务人员 | `OnDutyLaborListView` / `OnDutyLaborSearchView`（列表名“在岗劳务人员列表”） | 雇佣关系 = **内部员工(0)**；人员状态 ∈ 试用、正式；主职；当前生效；生效；未删除；**用工形式类别（EmploymentFormType）= 劳务(2)** | 21（用工形式：劳务派遣 6、兼职人员 15） |
| 外部人员 | `ExternalPersonEmploymentRecordList` / `ExExternalPersonSearchView` | 雇佣关系 = 外部人员(1)；人员状态 = **非正式(12)**；当前生效；生效；未删除；另带“来源类型 SourceType = 培训讲师(1)”（可能是上次保留的筛选，未确认是否为默认） | 7 |
| 全部人员 | `DimissionEmploymentRosterList` / `EmployeeRosterSearchView`（“员工花名册列表”） | 主职；人员状态 ∈ 试用、正式；当前生效；生效；未删除；**不限雇佣关系** | 3410 |

- 结论：
  - 劳务人员不是独立的雇佣关系，而是“内部员工 + 用工形式类别 = 劳务”。所以“在职员工”（不限用工形式）**包含**劳务人员，两个列表会重叠。
  - 实习生只取人员状态 = 正式（实习生没有试用态）。
  - 外部人员的人员状态是专用值“非正式(12)”。
  - “全部人员”跨三种雇佣关系，但只含在职（试用 / 正式）。
- 外部人员列表的列：姓名、电子邮件、加入日期、业务部门、身份证号、手机号码、简介、备注、最后工作日、直线经理 / 虚线经理、银行信息、外部人员文档附件。说明外部人员**也走任职记录**，有部门和直线经理（对应 ① 的部分答案）。
- 对复刻：五个列表按上表实现为“同一张任职记录表 + 预置筛选”。劳务与在职员工重叠这一点要在 AC 中写明。

## 补充：兼职写入实测（Q-M0-121 ③～⑥，2026-10-08，A0，W-610～W-613）
- **兼职管理页**（`ParttimeJobEmployeeListView`，默认条件：任职状态 = 任职中、当前生效、生效、未删除）。
  - 卡片：兼职中 / 即将到期 / 未开始 / 已结束 / 全部兼职记录 / 审批中的兼职。
  - 按钮：新增兼职（直接生效）、新增兼职申请（两个：管理员代提 `ParttimeJobApprovalFormView`、本人申请 `PersonalCustomizedParttimeJobApprovalFormView`）、批量结束兼职；行操作：编辑、结束兼职申请。
- **④ 新增兼职表单**（`ParttimeJobEmployeeFormView`）：
  - 必填：员工、任职类型（下拉只有 **兼职 / 借调 / 外派**）、开始日期、部门。
  - 选填：结束日期、是否部门负责人、新增下属、直线经理、职位、职务、职务序列、职级、虚线经理、兼职是否占人头（默认否）、兼职占人头比例、用工形式、人员类别。
  - 只读带出：雇佣关系、主职信息（部门 / 直线经理 / 职务 / 业务组织等）、员工信息。
  - 另有“兼职薪资档案”区（薪资组、发薪机构、成本中心、缴税类型、法人公司、银行信息、币种、兼职基本工资）。
  - 选完部门后，**自动带出直线经理（该部门负责人）和职位**。
  - 申请表单（ParttimeJobApproval）字段相近，带“提交”；回写时机须走审批，会派待办，未实测。
- **③ 状态**：
  - 状态在**保存时就按日期算好**：结束日已过 → 立即“任职结束”、当前生效 = 否（W-611）。
  - 开始日在未来 → 任职状态“任职中”、当前生效 = 否，计入“未开始”卡片（W-612）。
  - 当天开始当天结束 → 任职中、当前生效 = 是，计入“即将到期”（W-613）。
  - 结束日**次日**是否由定时任务转“任职结束”，待 10-09 回查 W-613。
- **② 校验**：
  - 主职已有未来生效的离职（EMP_10，10-09 生效），仍可新增兼职，不拦截（W-610）。
  - 同一员工在同一部门可以有多段不重叠的兼职（W-611 / W-613），重叠是否拦截未测。
- **⑥ 调动联动**：直接「调动」表单有“**兼职调整**”区。
  - 原文：“此处展示调动人员进行中的兼职。若有调动时需要结束的兼职，请勾选对应的选框”“选中的兼职将于调动日期前一天结束”。
  - 列：兼职部门、兼职职务、兼职开始日期、兼职原结束日期、结束兼职（勾选）。
  - 只列**当前进行中**的兼职；未来开始的 W-612 不在列表中。
  - 调动表单同时带“职责转交”区。（只读打开，未保存）
- **⑤ 主职离职联动**：待 10-09 回查 W-610（EMP_10 离职生效后，兼职是否自动结束、失效日是哪天）。
- 对复刻：
  - 兼职状态在保存时按日期计算，结束日次日的转换待回查后定。
  - 调动单内嵌“兼职调整”，勾选的兼职在调动日前一天结束（对 DEC-191 暂定口径是实证）。
  - 新增兼职时，部门变化自动带出直线经理和职位。

## 补充：外部人员、实习转正、劳务转正式的入口与表单（Q-M0-122 ①④⑤，2026-10-08，A0，只读）
- **① 外部人员**（列表 `ExternalPersonEmploymentRecordList`）：
  - 行按钮：「编辑」（`AddExternalPersonEmpFormView`）、「**停用**」、「重新启用」。
  - 停用表单 `StopExternalEmployeeeFormView` 只有一个字段“停用生效日期”（默认当天）。保存走**离职接口** `…/Emp/dimission?id=…&empChangeType=31`，即外部人员“停用”= 一种离职（异动类型 31）。

- **④ 实习转正**：
