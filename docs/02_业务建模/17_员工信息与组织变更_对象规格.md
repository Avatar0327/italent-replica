### 1.2 ⭐ 重聘方式（新增硬规则）
字段说明原文：
> 1、**合并人员**：与离职人员合并，可查看离职前后完整的任职档案、考勤档案、薪资档案；若有多个离职人员，与最新离职的人合并
> 2、**生成新人员**：生成一个新人员，与离职人员档案不连续。适用于离职前后需分开计算考勤、算薪的场景

与任职周期规则合并后：
| 重聘方式 | 人员（UserID） | 员工信息 | 任职周期 `StaffID` | 历史可见 |
|---|---|---|---|---|
| 合并人员 | **沿用**离职人员 | 沿用 | **新周期**（重聘入职更新 StaffID） | 离职前后连续可见 |
| 生成新人员 | **新建** | 新建 | 新周期 | 与离职档案不连续 |

→ 需求：REQ-EMP-005（待入 R2 入职/重聘需求）。

### 1.3 技术债信号（不复刻）
个别字段说明写有内部沟通记录（如 360/测评人员 id 字段注明"与某同学沟通结论是创建为文本"）、专用于某报表的标志位。这类字段属原站实现妥协，复刻时不照搬。

## 2. 组织变更记录 `TenantBase.OrganizationChange`（G-023 已解决）

标准字段 **21 个**：

| 名称 | 编码 | 说明 |
|---|---|---|
| **组织对象Id** | `OIdOrganization` | 发生变更的组织（对象级 ID） |
| **变更前组织RId** | `RIdBefore` | 变更前的组织**版本记录** ID |
| **变更后组织RId** | `RIdAfter` | 变更后的组织**版本记录** ID |
| 变动类型 | `ChangeType` | — |
| 变动日期 | `ChangeDate` | — |
| 文号 | `ChangeNumber` | — |
| 变动描述 | `Description` | — |
| 操作人 / 操作时间 | `Operator` / `OperateTime` | — |
| 生效时间 / 生效日期 | `StartDate` / `StopDate` | ⚠️ 原站标签错位：`StopDate` 的标签也写作「生效日期」 |
| 备注 | `Comment` | — |
| 其余 | `OId`、`PObjectDataID`、创建/修改/业务修改 人与时间、删除状态 | 系统字段 |

### 2.1 由此确认：组织采用「对象 ID + 版本记录 ID」两级标识
- `OId`：组织这个"实体"的恒定标识
- `RId`：组织某一时段的**版本记录**标识（生效日期~失效日期）
- 组织变更记录用 `RIdBefore` → `RIdAfter` 串起版本链

**这与任职记录完全同构**：
| | 版本对象 | 变动记录对象 | 前版本指针 | 后版本指针 |
|---|---|---|---|---|
| 人员任职 | `EmploymentRecord` | `EmploymentChange` | `AfterRecordLookUp`（命名反直觉） | `AfterEmpRecordID` |
| 组织 | `Organization`（带 RId） | `OrganizationChange` | `RIdBefore` | `RIdAfter` |

> ⭐ **复刻硬规则**：组织与任职共用一套「有效期版本 + 变动记录」机制。
> 建议复刻版抽象为**通用的时间轴版本化能力**，组织、任职、（以及编制——对象注册表中有「编制向后更新」）三处复用，
> 而不是各写一套。

### 2.2 编制也有向后更新（新线索）
对象注册表中存在 `EstestablishmentSyncMessage` 编制向后更新、`EstestablishmentSyncDetailMessage` 编制向后更新明细。
→ 编制同样是时间轴数据，插入历史编制变更会同步后续记录。**R1-T04 编制任务需按版本化对象设计**（G-040 已关闭，规则见 `18_编制管理_规则规格.md` §4 / §10）。

| 员工信息 | `Age` | 年龄 | 0 位 | **每天根据出生日期由系统自动赋值，向下取整** | 🟢 字段说明原文 |

司龄开关规则（官方 145723560）：
- 「实习转正累计司龄」「离职重聘累计司龄」「退休返聘累计司龄」三个开关**只对开启之后发生的业务生效**，不回算历史数据。
- 实习转正和退休返聘也可以用“表单不放入职日期、自动继承原入职日期”的方式来累计司龄。此时开关必须**保持关闭**，否则会重复累计。
- 复刻含义：“是否累计”是**业务发生时一次性写入校正值**，而不是查询时动态计算。

**2026-09-27 更正（G-041 关闭）**：6 个“现 / 累计 任职时长”字段的口径来自配置中心字段元数据的 `note`（字段说明）原文，推翻了上表原先“从最近一次变更起算”的推断。复刻实现：
- 口径：遍历该员工**当前任职周期**（`StaffID`）内的所有任职记录版本（🟡：是否跨任职周期累计，原文未说明），把“职务（职级 / 职位）= 当前值”的有效区间时长相加；年 = 天数 / 365。
- 精度：“现 X”保留 1 位小数，“累计现 X”保留 4 位小数；两者按同一口径计算。
- 计算时机：参照工龄、年龄，由**每日定时任务**刷新（🟡 时长字段本身原文未写时机，按同类字段推断）。
- 验收：AC-EMP-12（新增）员工历史职务依次为 A（2 年）→ B（1 年）→ A（至今 0.5 年）→ 现职务任职时长 = 2.5，累计现职务任职时长 = 2.5000。
