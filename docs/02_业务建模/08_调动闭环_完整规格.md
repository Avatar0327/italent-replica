## 1. 发起人角色（官方原文，三类）

| # | 发起人 | 说明 |
|---|---|---|
| 1 | **HR** | 为员工发起调动申请 |
| 2 | **经理、部门负责人** | 为员工发起调动申请 |
| 3 | **员工本人** | 自助发起调动申请 |

> ⭐ 这**正式推翻**了最初设想的「调出方 HR 发起 → 调入方 HR 接收」模型。
> 原站的调动是 **发起（任一角色）→ 审批流转 → 生效** 的单链路，没有"调出方/调入方 HR 对接"这一机制。
> 跨组织的语义由 **调动后部门** 字段 + **数据权限（调动后部门权限控制）** 表达，不是由两个 HR 角色表达。

## 2. 发起入口（官方"系统路径"原文）
| 角色 | 入口 | 端 |
|---|---|---|
| HR | 组织员工 → 任职管理 → **调动管理** 视图（可选人） | PC |
| HR / 经理 / 部门负责人 | 员工详情页（员工自助-我的团队-团队成员-人员详情页；组织员工-人员信息-员工/实习生-人员详情页） | PC / 移动 |
| 经理 / 负责人 | 员工自助 → 我的团队 → 团队成员-在岗人员列表 **行操作** | PC |
| **员工本人** | **组织员工 → 员工自助 → 我的信息 → 人事申请** | PC |
| **员工本人** | **移动端 → 自助服务 → 人事申请** | 移动 |

> 📌 与实测吻合：A2/A3 拥有 `自助服务 → 人事申请`；A1（纯员工）**没有**「自助服务」，说明该入口本身受身份控制。

## 3. 预置调动申请类型（官方）
`调动申请`｜`跨部门调动申请`｜`职务职位调整申请`｜`职级调整申请`｜`跨业务单元调动申请`｜`调入申请`｜`调动类型 1–7 申请`

## 4. 调动申请中可同时完成的业务
`转交职责`｜`调整薪资社保`｜`变更合同`｜`调整兼职`｜`设置试岗期`｜`同步设为部门负责人`｜`同步调整店长`｜`新增下属`｜`撤销调动申请`

> 📌 一次调动是**多对象事务**：任职记录 + 薪资档案 + 合同协议 + 兼职 + 职责转交 + 汇报关系，一起变更。

## 5. 调动生效时的联动规则 ⭐
| 表单字段 | 生效时的系统行为 |
|---|---|
| `任职记录.是否部门负责人` = 是 | 调动人被设为**所在部门的负责人** |
| `任职记录.是否店长` = 是 | 调动人被设为**所在部门的店长** |
| `任职记录.新增下属` 填值 | 填写的这些下属的**直线上级被设为调动人** |

> 这三条都在 **生效时**触发，不是保存/审批通过时。与「审批通过 ≠ 生效」一致。
> 注意：`是否部门负责人` 同时是**不自动向后更新**的字段（见 07 文档 A5.1 规则④）。

## 6. 撤销与回滚边界 ⭐⭐（直接回答「撤回/驳回/撤销后结果」）

| 状态 | 可用动作 | 结果 |
|---|---|---|
| 已发起，**流程尚未审批完成** | 调动管理视图 → **撤销** | 撤销调动流程 |
| 已发起，**流程已审批完成** | 调动管理视图 → **删除任职** | 删除该条调动任职记录 |
| **直接调动（未走审批）** | 调动管理视图 → **删除任职** | 同上 |

### 6.1 删除任职后**不会自动回滚**的部分（官方明确）
| 联动业务 | 删除任职后的状态 | 需要的补救 |
|---|---|---|
| 调动过程中的**合同变更** | **不自动恢复** | 需**手动**将合同恢复至变更前状态 |
| 调动过程中的**职责转交** | **不自动恢复** | 需**手动**将职责恢复至变更前状态 |

> ⚠️ **这是原站的已知缺陷性行为**，复刻时必须明确决策：
> - 选项 A：照搬（删除任职不回滚合同与职责，由 HR 手动处理）
> - 选项 B：改进（删除任职时级联回滚，或阻止删除并提示先撤销关联变更）
> 已列为**建议差异 D-001**，需用户决策。

## 8. 审批详情页的原值显示
- PC 端：与调动前相比有变化的字段，**完整显示原值**，供审批人快速发现区别
- 移动端：同样显示原值，并提供**区块锚点**快速定位
- 关闭开关：**设置 → 调动管理 → 其他设置 → 调动审批详情页显示【原信息】**

## 9. 移动端差异（官方）
1. 发起 / 审批中编辑 / 重新提交时，若表单中**变更前后字段同时存在**，**默认隐藏变更前字段**；可用【显示原值】/【隐藏原值】切换
2. 表单中各可见且有标题的区块展示为**上方锚点**，点击快速定位

## 12. 闭环的完整状态机（综合 07 + 08）

```
[发起]  HR / 经理·部门负责人 / 员工本人
   │        入口：调动管理视图 · 员工详情页 · 团队人员列表 · 人事申请(PC/移动)
   │        表单：TenantBase.*TransferMultiFormView（HR端）
   │             TenantBase.Personal*TransferMultiFormView（人事申请端）
   ▼
[草稿] ──（暂存）
   │ 提交
   ▼
[审批中] ──（撤销）──► 流程撤销
   │   审批人可「审批中编辑」（EmploymentRecord.Approval / ApprovalingEdit 等）
   ├──（驳回）──► [已驳回]
   ▼
[审批通过]
   │
   ├─ 审批通过日期 ≥ 调动日期 ──────────────► 立即生效
   └─ 审批通过日期 <  调动日期 ──► 挂起 ──► 定时任务在调动日期当天 ──► 生效
   ▼
[生效]
   ├─ 新增一条任职记录（继承未变更字段，同一 StaffID 周期内）
   ├─ 向后更新：按「值匹配替换」同步到后续任职记录
   ├─ 是否部门负责人=是 → 设为部门负责人
   ├─ 是否店长=是 → 设为店长
   ├─ 新增下属 → 这些人的直线上级设为调动人
   ├─ 联动：薪资档案（*Adjusted 字段）、合同协议、兼职、职责转交
   └─（删除任职）──► 任职记录删除，但**合同与职责不自动恢复**

[直接调动] 保存即生效（跳过审批中/审批通过），同样触发向后更新与全部联动
```

## 14. 建议差异（需用户决策）
| 编号 | 原站行为 | 建议 | 理由 |
|---|---|---|---|
| **D-001** | 删除调动任职记录后，**合同变更与职责转交不自动恢复**，需 HR 手动处理 | 复刻版级联回滚，或阻止删除并提示先撤销关联变更 | 手动恢复依赖 HR 记得做，漏做会造成合同与任职状态不一致，属数据一致性隐患 |
| **D-002** | 越权访问返回「获取权限信息失败，请刷新重试」 | 改为语义准确的权限拒绝文案 | 原文案会误导用户反复重试 |
