# 合同协议：规格（R2-T06）

> 取证：2026-09-28，A0 只读。官方文档 🟡：HRSAAS 22478933、42991636、38801562、153321503、38801808、113743000、113743672、156569210、113743744、70320204、124879712。
> 配置证据 🟢：`TenantBase.EmploymentContract`（66 个标准字段，含 版本号、原合同ID、签订次数、期限类型、实际终止时间 等）、`ContractChangeRecord`，见 `21` §2。

---

## 1. 模型

- 合同协议：编号、员工、合同类型、公司（法人公司）、期限类型（固定 / 无固定 / 以完成一定任务为期限）、期限（月）、签订日期、生效日期、终止日期、**实际终止时间**、试用期起止与工资、**签订次数**、状态（有效 / 终止 / 作废）、审批状态、版本号、原合同ID、电子签署记录。
- 变更与任职同构：新版本 + 指向变动前合同（`ContractChangeRecord.LU_变动前合同`，`21`）。

## 2. 规则（🟡）

### 2.1 视图
即将到期、**入职缺失**（在职但无有效合同）、**过期未续签**、审批中、有效、全部。

### 2.2 新建
| # | 规则 |
|---|---|
| CT-R1 | 新建合同（直接）/ 新建合同申请（审批）；新增员工、入职、调动、实习转正、劳务转正式、Offer 表单中填合同信息会**同时生成合同** |
| CT-R2 | 维护法人公司、合同类型时可在下拉中直接跳转去新建，返回后可直接选到 |

### 2.3 续签
| # | 规则 |
|---|---|
| CT-R3 | 只有 审批状态 = 生效 且 状态 = 有效或终止 的合同可续签；作废的不可续签；续签**不能改合同类型**；续签后终止日期必须晚于生效日期 |
| CT-R4 | 续签方式：直接续签、续签申请、批量续签、批量续签申请（每条合同一条独立流程）；审批人可收到**合并待办**，批量同意 / 不同意 / 驳回 / 重新提交 / 发起电子签（PC 与移动端） |
| CT-R5 | **自动续签**（开关 + 规则）：规则 = 组织范围 + 附加人员范围 + 多条明细（合同类型、续签期限（月）、发起人、到期前 N 天发起、终止日期后已存在哪些类型的合同则不续签）；**员工匹配到优先级最高（数值最小）的一条规则后，其所有合同类型都只按该规则**；自动发起的流程发起人显示“xxx（系统代发）” |
| CT-R6 | 自动续签的合同条件：状态 = 有效、实际终止日期为空、**同类型中终止日期最晚的一条**、审批状态 = 生效、命中规则 |
| CT-R7 | 自动续签的期限类型按**签订次数**：续签后签订次数 > 2 → 无固定期限（忽略规则中的月数）；≤ 2 → 固定期限，按规则月数 |
| CT-R8 | 手工维护实际终止日期会影响自动续签（原站建议不要手填，由到期自动终止开关维护） |
| CT-R9 | “是否已续签”（过期未续签视图用）：同类型合同后接续同类型合同 → 已续签；不同类型须都在「合同续签类型设置」内且连续才算已续签；该设置只选一种类型时按同类型逻辑 |

### 2.4 变更
| # | 规则 |
|---|---|
| CT-R10 | 变更方式：直接变更、变更申请、**调动时变更**（调动表单“是否变更合同” = 是） |
| CT-R11 | 开启自动编码时：变更后生效日期 **≤** 原合同生效日期 → **原合同作废**，新合同沿用原编号；**>** → **原合同终止**，新合同按规则生成新编号 |
| CT-R12 | 新合同终止日期默认 = 原合同终止日期 |

### 2.5 终止
| # | 规则 |
|---|---|
| CT-R13 | 终止 / 终止申请 / 批量终止；填实际终止时间，状态变终止 |
| CT-R14 | **离职时自动处理**：合同类型不在「离职 / 退休后可签订合同类型」中时——合同开始日期 > 最后工作日 → **删除**该合同；开始 ≤ 最后工作日 < 终止日期 → **终止**，实际终止日期 = 最后工作日。在该设置中的类型（如竞业协议）则都不处理，且离职后仍可新增 |
| CT-R15 | 开关「合同到期后自动终止」：到期自动置为终止 |

### 2.6 其他设置
| # | 规则 |
|---|---|
| CT-R16 | 「期限类型联动」：所选类型**第 3 次**签订时期限类型默认为无固定期限 |
| CT-R17 | 「离职重聘累计合同签订次数」开关：重聘后签订次数接着离职前累计 |
| CT-R18 | 导入四种方式：新增、编辑（按唯一键定位）、**变更**（按合同类型 + 生效日期找原合同，编号填新合同编号）、**按人员初始化**（删除该人全部已有合同后按表格重建）；≤3000 条可预览检查，否则直接导入；唯一键通过字段分组“唯一键”配置（如 编号，或 员工 + 合同类型 + 开始日期） |
| CT-R18a | 🟡 2026-10-05 手册补充（Q-M0-66）：①「编辑」导入只写“通过唯一键定位合同并更新合同信息”（HRSAAS 113743672，CustomerKB 145719508），**没有限定合同状态**；②新建 / 导入时终止日期早于今天会同步写入实际终止日期，且只有终止日期晚于今天才允许清空实际终止日期（198738184）；③生效日期晚于今天时，实际终止时间只读并被清空（251167153）；④变更（非编辑）时新合同生效日早于等于原合同生效日 → 原合同作废，晚于 → 原合同终止（101192004）。由此推定：编辑导入**不因合同已终止而拒绝**，但能否借编辑把已终止合同改回有效，受“实际终止日期能否清空”规则约束（终止日期已过则清不掉、仍为终止）。需写入实测确认 |
| CT-R18b | 🟢 2026-10-05 写入实测（Q-M0-66，A0，W-477～W-479）：给 TRF_T1 新建劳动合同（编号 ZZ_R2_RUN20261005_CT01，生效 10-05、终止 10-31），批量终止（实际终止 10-05，状态变“终止”），再用「导入合同 → 编辑」按编号导入一行（终止日期改 12-31，其余同原值，模板无“实际终止日期”列）：**预览“检查”无报错、导入成功**；导入后该合同**状态变回“有效”、实际终止日期被清空**，终止日期 12-31，审批状态“生效”，但**业务类型仍为“终止”**（残留）。即原站编辑导入不拦已终止合同，且在终止日期晚于今天时会把它“复活”。终止日期已过的情形未测（按 198738184 推定实际终止日期清不掉、仍为终止） |

**复刻护栏（DEC-167 / F-013，优先于 CT-R18b 的原站行为）**：编辑导入追加更正版本、不计签订次数。到期终止（含自动到期）只有终止日期改晚且晚于租户今天时恢复有效，清空实际终止日，业务类型记为编辑；新日期不晚于今天时保持终止和原实际终止日。离职终止、人工提前终止只允许更正不影响状态的字段；试图恢复状态或改变实际终止日返回 409，逐行错误带 `CONTRACT_TERMINATION_PROTECTED` 与终止原因。终止原因跨更正版本保留，审计与 outbox 同事务写入。按 DEC-167④⑤及④补充，恢复前检查主职有效任职历史与已保存的未来离职：合同生效后发生过离职 / 退休，即使之后已重聘，只要新终止日越过最后工作日，仍拒绝恢复（`CONTRACT_EMPLOYEE_DEPARTED`）；已删除 / 撤销的离职不算。已保存且已批准的未来离职同样拦截，不依赖尚未接入的离职端口。已有更新的同类型合同或审批中 / 已批准未生效的同类型新建、续签申请，与延期后的旧合同有重叠时拒绝恢复（`CONTRACT_SUPERSEDED_BY_RENEWAL`，提示修改后续合同）。**有空档且延期后不重叠的后续合同允许恢复**；同一源合同已有在途操作时仍须先处理该申请，遵守源合同 revision 门禁；不能以恢复旧合同的方式使在途申请失效。这不改变 CT-R9 / DEC-164② 在视图中要求连续才算“已续签”的口径。冲突均返回 409，仍允许日期不晚于今天、保持终止的更正。

**F-016 一致性与权限补充（DEC-180）**：

- 合同设置与续签规则走平台配置门禁；租户管理员可配置，也可在既有管理员记录上授予 / 撤销 `contractConfiguration`（“合同配置”）。此开关默认 false，仅租户管理员可变更，撤销管理员记录亦立即失效。普通 HR 业务身份不预置配置权，遗留的业务对象授权不能绕过门禁。
- 同一员工、同一合同类型只能有一份在途的新建 / 续签 / 变更合同（审批中或已批准未生效）；已有时再提交返回 409 / `CONTRACT_IN_FLIGHT`，提示先处理在途申请。签订次数由已生效的新建 / 续签事件数加本次唯一在途推导；编辑、更正及变更不增加次数，不用日期最晚合同的旧序号推算自动续签期限。重聘累计开关继续适用。
- “我创建的”不能替代新建时的人员管理范围；初始化在员工锁内先对整个待删除集合逐条验真实创建人权限，再删除和重建。组织与汇报范围复用公共人员范围解析与任职投影。
- 自定义字段按键合并，未提交键保留；显式 null 清空必须有该键编辑权。审批变化字段取前后键并集；重提只复核实际提交的载荷及更正字段。
- CT-R18a 的实际终止日规则用于新建 / 新增导入及生成、调动合同端口：生效日晚于租户今天时清空实际终止日；终止日早于今天时同步实际终止日，延迟激活时再次按当日处理。编辑已终止合同继续优先遵守 DEC-167，不覆盖其受保护的实际终止日。
- 合同审批条件当前仅开放 `processCode`、`business.kind`，与实际快照逐项一致。未实现字段禁止保存 / 发布；升级前已发布但含未实现字段的流程在发起时返回 `APPROVAL_CONDITION_UNSUPPORTED`，须由流程管理员更正后重新发布，不能按空值误匹配。
- 已批准且到期激活失败的申请，可在有合同 update 与 withdraw 按钮权限、当前范围内，通过 `POST /api/tenant/contracts/requests/:id/cancel` 撤销。需 `If-Match` 和幂等键；成功追加审计与 outbox，保留原批准审批历史，释放在途限制，再以更正后的载荷新建申请。无失败记录、未到期或已生效的申请不能使用此入口。
