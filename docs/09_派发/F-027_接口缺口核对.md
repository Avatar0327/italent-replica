| 我的待办 | `GET /api/tenant/approval/todos`，返回 taskId、instanceId、节点名、异常管理员标识 | 支持 page / pageSize；未提供状态、类型、标题搜索，前端不能自行增加服务端筛选语义 |

## 2. F027-Q1：参与过不能代替已处理

源码证据（行号以核对基线为准）：

- `apps/api/src/modules/approval/routes.ts:421`：role 只接受 initiated / participated。
- `apps/api/src/modules/approval/queries.ts:65`：participated 包含本人任意非 self_skip 任务，
  未限制 pending 状态；也包含本人被抄送的实例。返回项没有“本人已处理”标志。
- `apps/api/src/modules/transfer/manager-routes.ts:118` 明确写明“已处理不等于参与过”，
  查询本人 approve / reject / disagree / transfer 日志，并在 SQL 层分页。
- 同文件 `:92` 的 managerContext 校验经理身份；普通员工、非经理 HR 不能普遍调用该入口。
- `apps/api/src/modules/approval/disclosure.ts:255`：隐藏记录时不返回已处理任务及意见。
  前端逐单补拉历史无法可靠判定本人已处理，也不能在服务端分页以后再过滤来冒充准确的已处理分页。

可检查的例子：X 仅有待办、Y 仅被抄送、Z 已转交且实例仍 running。
participated 会收录三者，已处理应排除 X / Y、保留 Z；实例 running / approved 状态不能代替本人处理状态。
经理专用接口已有口径，不需要在 F-027 重新定义审批规则。

## 3. F027-Q2：可见字段不能代替可编辑字段

源码证据：

- `apps/api/src/modules/approval/disclosure.ts:232`：form 只有 nodeKey、values、可选 originals；
  没有 editableFields、editMode，也没有节点允许字段与当前对象编辑权限的交集。
- 同文件 `:177`：独立编辑模式才公布 edit；with_approve 模式仍只公布 approve。
  仅靠 actions 无法区分“只同意”与“编辑并同意”。
- `apps/api/src/modules/approval/actions.ts:183`：服务端根据 node.editableFields 和查看权拒绝越界字段。
- `apps/api/src/modules/approval/routes.ts:458`：写接口还校验对象修改权和字段编辑权。
  校验存在于服务端，不等于已经向前端提供了表单配置。
- `apps/api/src/modules/approval/access.ts:61`：流程定义查看另需流程对象查看权或流程管理员身份。
  流程详情也不能保证是当前实例绑定的旧版本。不能为了编辑普通审批单要求扩大流程配置权限（DEC-057、DEC-102）。

可检查的例子：节点 formFields 包含 departmentId 与 place，editableFields 只有 place。
返回两个字段并不意味着两个都可编辑；若 editMode 为 with_approve，前端还需知道修改随同意一并提交。
审批中编辑在任职类业务确实有后端支持，不能写成“后端完全不支持编辑”；
员工信息 / 子集类禁用编辑按 DEC-105 单独处理。
