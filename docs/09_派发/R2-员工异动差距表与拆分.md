## 1 总览

判定口径：
- **已有**：前端页面和后端能力都具备，可直接演示。
- **部分**：有后端接口、数据模型或底座，但缺页面、缺视图或缺规则。
- **缺失**：没有模型、接口，也没有页面。

main 上**没有任何 R2 前端页面**：`apps/web/src/foundation/routes.ts`、`AppPages.tsx` 里没有合同、入职、试用、离职、退休、兼职、实习、组织调整审批、数据分析的路由。另外审批中心 `approval` 在 main 上仍是空的 LandingPage。所以按上面的口径，“已有”一项也没有。

各块概况：
- **合同（R2-T06）**：后端相对完整，PR #64 及 F-013/014/016 已合并。`apps/api/src/modules/contracts` 约 3000 行，有 11 张表，调度器也已上线。主要缺页面，以及少量后端补齐项。
- **入职**：只有任职底座。`POST /api/tenant/employment/employees/:id/businesses` 支持 kind=hire/rehire/retire_rehire，有直接办理和申请两种方式。F-022 人员状态和入职状态模型已合并，但 `changePendingEntryStatus`、`completePendingEntry` 等端口**未接线**（注释写的是“由 R2-T01 接线”）。
- **Offer、信息采集、扫码、融入，以及约 20 项录用入职设置**：全仓零命中。
- **试用、离职、退休、实习**：只有通用业务接口 + kind（regularization/leave/retirement/intern_regularization），加上对应的审批类型。没有视图、规则、设置，也没有专用页面。R2-T03 离职停在 PR #100（暂停，DEC-475），未合入。
- **兼职**：数据库约束 `employment_records_primary_only` 只允许主职，BUSINESS_KINDS 里没有兼职类型。联动端口 `transfer/linkage/part-time.ts` 目前返回“兼职模块尚未上线”。
- **组织调整审批**：只有“直接改组织 → 追加任职”这条不走审批的通路，见 `employment/org-adjustment.ts` 和 `org/employment-linkage.ts`。没有单据、明细、审批适配器，审批的 business_type CHECK 也不包含它。
- **人事数据分析**：没有任何模块、接口或页面。

## 补证结论 R2c（10-14，远程 Codex，F-131）

- **B15 离职办理结果**：有两条路径，要分别复刻。① 离职申请：走审批（本租户流程为 开始→直接上级→HR访谈→结束），通过后在“离职中的员工”里，审批状态为审批通过；② 员工档案 → 离职 → 保存：直接办理，不产生离职审批。生效后生成离职任职（开始日 = 最后工作日次日，业务类型“离职”，任职状态“任职结束”，人员状态“离职”），原入职任职结束日改为最后工作日。最后工作日当天员工仍为正式，次日起为离职；改到过去日期后进入“已完成的离职”和员工“离职人员”视图。**改期**：“编辑离职”改最后工作日，保存时有二次确认“最后工作日将修改为…”。**撤销**：已完成的离职行内“撤销离职”，填“撤销离职原因”（是否必填未验证），撤销后恢复正式、入职任职恢复至今、离职节点不再展示、交接流程变为已终止。行内“离职处理”按钮本身未取得表单，仍未验证。
- **B64 交接执行**：离职申请审批通过后自动生成“离职交接申请”（系统代发，发起人为员工本人）；节点 工作交接→其他事项交接→员工确认→HRBP办离职证明。设置 30 项，本员工实际生成 16 项（按类别分行政 / IT / 财务 / 人力），每项含 办理完成（是/否）、负责人、备注、交接人；本人负责项可编辑，其他人负责项灰显。“负责人”与“交接人”是两个字段。**交接未完成不阻止离职生效**（本租户配置）。档案直接离职路径没有自动发起交接（显示“未发起”）。
- **B65 交接发起规则**：当前为“离职退休流程审批通过后自动发起”；另有“审批通过且距最后工作日 N 天自动发起”、提交 / 中间节点同意时发起两种方式；“包含最后工作日早于审批通过日期的人员”勾选；发起人 = 指定角色·员工本人；自动催办开启，距最后工作日前 5 天，且最后工作日后 15 天内每天催办。
- **B68 自动加黑**：总开关关闭，租户有 2 条规则；规则字段 = 规则名称*、优先级*、适用组织*、规则说明；条件（离职次数 / 任职记录 / 员工信息 / 考核结果 / 其他子集 + 运算符 + 值）；加黑期限*（永久 / 指定期限 / 离职当月）、加黑原因*、加黑说明。命中多条按优先级数字最小者；关闭时仍可手动加黑；页面提示黑名单人员不能重聘（未实测）。离职表单有“加入黑名单”（默认否）。
- **B63 终止在途**：设置勾选“调动”后，离职时弹窗提示“存在审批中的调动流程（生效日期：…），离职生效后会终止作废该流程”，确认后调动申请变“已终止”、调动任职作废。其他流程类型和不勾选时的分支未验证。
