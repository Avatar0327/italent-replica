# BE-2 入职接线：范围估算与拆分建议

> 2026-10-15，BE-2 开发窗口（只读代码后估算，未写实现）。结论：新增业务范围预计 **约 2000～2400 行（含测试，不含迁移快照与生成物）**，超过 1500 行（DEC-338②），按派发规则先停下等决定。

## 1. 估算依据

对照 #347（R2-T03 B1a：3 张字典表 + 3 个路由，不含快照 JSON 共约 1450 行）。BE-2 的路由与存储远多于它，并且每个新路由都要在 `employment/policy.ts` 登记（F-039：声明、必需项表、基准、发现探测）。

| 块 | 内容 | 预计行数（含测试） |
|---|---|---|
| a. 待入职入口 | 添加待入职（建人员 + 待入职首版，`EntryOptions.pendingEntry`）；`hire` 直入口开放“是否有试用期”（`EntryOptions.probation`）；办理入职路由（`completePendingEntry`） | 300～350 |
| b. DEC-138 / 139 校验 | 入职日不早于部门设立日；整个时段停用；两种停用提示语照搬原站；待入职保存 / 编辑 / 办理入职 / 接口四处共用一个入口。现有 `assertEmploymentDepartmentAvailable` 只有一种停用提示，也没有“早于设立日”拦截 | 200～250 |
| c. 改期 / 取消 / 删除 | 路由 + 改期挪日期（日期必填、备注可选、状态延期、已取消改期恢复）、取消原因（5 项下拉，复用 #347 的字典思路或固定枚举）与备注落库（需迁移）、删除（只删待入职本身、拒绝已入职、不可恢复） | 350～450 |

## 2. 拆分建议

- **推荐 ①：BE-2a = a + b + c + d（+ h 中对应部分，约 1000～1250 行）**：入口、校验、改期 / 取消 / 删除、失效删除端口。FE-R2b-2 的新增 / 编辑 / 改期 / 取消 / 删除 / 办理入职对话框只依赖这一片。
- **BE-2b = e + f + g（+ h 其余，约 900～1200 行）**：四视图查询、邮箱规则、合同端口。先于 BE-2b，页面列表可临时沿用现有 `GET /employees?status=pending&entryStatus=`（DEC-540 之前口径）。
- 备选 ②：BE-2a = a + b + c + e（入口、校验、状态动作、四视图，约 1100～1400 行），BE-2b = d + f + g。这样 FE-R2b-2 列表四视图不用等第二片，但 a/b/c/e 已贴近 1500 行上限，余量很小。

两种拆法都不改变 DEC-484② / DEC-540 的保守口径：改期 / 取消 / 删除只做已核实的状态变化，不联动 Offer / 信息采集 / 合同随改期（其余未验证项会在各片 PR 描述“未验证”一节列出）。
