# R1-T14 经理自助交接

## 入口与共享契约

经理入口 `/manager`：管理者工作台 → 人事申请 → 他人调动申请。工作台成员列表只读，无行操作。无 HR 身份不显示汇报关系页 / 图（DEC-206）。HR 原入口保留。

按派发单 §21，本任务负责 `apps/web/src/self-service/shared/`，R1-T13 后合并并复用：

| 导出 | 契约 |
|---|---|
| `SelfServiceShell` | `title`、`children(tenantId)`；统一租户选择、切换与内容卸载 |
| `EmploymentList<Row>` | `items`、`columns: {key,label}[]`、可选 `renderCell(row,key)`；只读，不内置操作列 |
| `TransferApplication` | `tenantId`、`initiator: 'hr' \| 'manager' \| 'employee'`；完整申请交互、命令 ID、冲突显式刷新、未知结果处理 |
| `TransferForm` / `useTransferForm` | 共用预览、字段模式、参照查询、暂存和提交；经理候选调用 `/transfers/manager/employees`；员工模式保留现有本人候选接口 |

调动类型与接口客户端、资源文案保留在 `transfer/`，共享组件直接复用；原 `transfer/TransferForm.tsx`、`transfer/useTransferForm.ts` 保留兼容导出，`TransferPage` 保留 `TransferManager` 导出，避免 HR 和并行联动任务重复维护表单。R1-T13 在自己的页面目录组合上述组件，其员工任职列表、本人表单与撤回规则仍由 R1-T13 实现。

## 服务端与权限

- 有有效租户成员绑定，且担任组织负责人或有当前在职直线下属，即时取得经理自助身份；身份没有静态授权行，不缓存人员范围。
- 租户可通过现有身份配置创建编码 `department_manager_self_service` 的身份；自动身份使用该身份的应用、对象、字段和按钮配置，完整替换内置后备配置，不需要再给负责人逐个授权。其他有效身份按 DEC-042 合并。后备仅提供最小申请及人员读取权限，不给予 HR 或通用任职新增按钮。
- 数据范围仍按用户 × 应用，显式空范围不会被覆盖。默认管理单元仅对 `TenantBase.Employee` / `EmploymentRecord` 派生负责组织及下级。调动候选、预览、创建和同单写入额外检查当前主职在负责组织范围且在职；历史可见与单纯汇报关系不构成资格。
- 预览、提交和继承复用原调动服务。经理不能直接生效；申请继续由同类型流程条件、优先级匹配。审批详情及动作复用 DEC-057/058 原实现。员工 → 业务 → 实例取锁顺序未改。
- 字段返回与表单模式取有效可见 / 可编辑字段交集。只读字段保留版本链原值；隐藏 / 只读字段显式写入被拒。参照选择仍服从现有相关对象权限。
- 所有组织、人员、待办查询均带租户；工作台使用可信租户日期，按当前组织过滤后分页。待办分别按待办任务、本人已处理日志、本人发起实例查询。
