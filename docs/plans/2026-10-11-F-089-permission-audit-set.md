# F-089 权限保存审计的集合语义

依据：后续任务 F-089、DEC-409⑦、REQ-PRM-001/002、权限模型 §7.2、数据权限模型 §13。

目标：权限集合内容相同而排列不同的保存，不产生字段级变更；权限读取返回确定顺序，鉴权结果保持一致。

## 方案与边界

选择权限模块内的集合规范入口，同时供审计快照、范围版本快照和权限读取使用。
与只排序写入请求相比，这能覆盖历史数据库行的任意排列；与修改通用审计数组比较相比，
只登记明确的权限集合，不会改变其他业务里有顺序含义的数组。

| 集合 | 排序键 | 完整成员值 |
| --- | --- | --- |
| 身份应用、管理员可授权角色/身份、应用允许范围类型 | 字符串编码 | 字符串 |
| 字段授权 | 字段编码 | 字段编码、查看、编辑 |
| 按钮授权 | 按钮编码、级别 | 按钮编码、级别 |
| 组织范围 | 组织 ID、维度 | 组织 ID、维度、包含下级 |
| 范围消费规则 | 维度、角色、关系类型 | 维度、角色、关系类型 |

完整成员值参与去重和比较，排序键相同但值不同的成员不会被丢弃。
固定字段记录的属性也规范排序，避免 JSON 比较受到属性插入顺序影响。
不改变已有输入校验：原来拒绝的重复字段、按钮、组织引用和范围类型仍拒绝。
消费规则本来允许重复，读取与审计将完全相同的规则按一项集合成员表示；运行时规则并集不变。

保存仍执行原有鉴权、校验、revision 冲突检查、命令台账、授权补装台账及事务写入。
审计事件、outbox、范围版本照常记录，只把纯顺序变化的字段差异变为空。
历史审计和版本不改写；不新增路由、授权编码或迁移；不改通用审计差异引擎。

3. 通过真实授权器比较重排前后的允许/拒绝结果，并覆盖无身份用户被拒。
