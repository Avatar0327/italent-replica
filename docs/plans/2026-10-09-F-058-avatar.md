# F-058 人员头像实现计划

**目标：**本人个人设置上传、替换、删除独立账号头像，员工和人员摘要只读引用，默认彩色圆底姓名缩写。

**架构：**头像以租户 × 用户为归属，不写入任职或证件照字段。独立头像 revision 与附件元数据、字节同事务维护；读取经现有用户与成员校验，摘要按当前字段权限投影。

**技术栈：**TypeScript、Hono、Drizzle/PostgreSQL、React；图片解码复用 F-038。

## 1. 独立红测提交

- 新增 `tests/acceptance/AC-EMP-F058-avatar.test.ts`：真实 HTTP 生命周期、本人授权、租户隔离、内容解码、revision、幂等、审计。
- 新增 `tests/acceptance/AC-EMP-F058-avatar-summaries.test.ts`：员工档案、范围外上级、字段裁剪、审计与重放。
- 新增 `tests/acceptance/AC-EMP-F058-avatar-ui.test.ts`：默认头像、带租户下载、本人操作和未知结果回查。
- 运行上述相关文件，确认未实现接口 / UI 造成失败，单独提交测试。

## 2. 存储与本人入口

- `packages/db/src/schema/avatar.ts`：账号头像设置、附件与 outbox；每行带 tenant_id，外键限定租户内成员。
- 通过 `pnpm db:generate` 生成 schema 迁移，再 custom generate RLS，不手工指定序号。
- `apps/api/src/modules/avatar/`：本人身份来自 tenantOf，不接收目标用户 ID；登记、上传、删除、固定投影下载。
- 每个写入口同源、JSON、revision、客户端命令 ID；成员锁 → 头像锁，回执重放前后重验本人当前授权。
- registered / pending_cleanup 均不可读；旧图保留删除快照，字节不进入审计、命令回执或 outbox。
- `audit/visibility.ts` 登记头像审计仅本人可见，沿用审计入口额外功能守卫。

## 3. 只读摘要与界面

- `modules/avatar/references.ts` 批量按人员 / 员工查账号头像，绝不使用 idPhoto。
- 接入员工信息、任职员工摘要、自助本人、上级候选、经理团队、360 人员 / 上级 / 关系摘要。
- 摘要保留原范围守卫；引用头像与姓名字段权限一致，范围外上级只带既定白名单。
- 匿名作答入口不能借头像披露评价者身份；公开 token 不因此获得全租户图片访问权。
- `apps/web/src/account/` 个人设置与共享 PersonAvatar；引用需租户认证下载，失败回退缩写；租户切换清旧图。
- 路由按 F-039 现行 Markdown 契约登记；尚未合入 main 的评审组模块后续复用 helper，不修改其他分支。
