# R1-T12 人员信息与人员子集 Implementation Plan

> 执行车道：Codex；交叉审计：Claude（DEC-071）。用户已授权本会话直接实施并创建 PR。

**Goal:** 在现有员工主档上实现标准人员属性、13 个显式人员子集、同事务派生与授权闭环。

**Architecture:** `employment_employees` 继续作为唯一人员实体；人员属性采用显式列的不可变版本表，最新版本为读投影。13 个子集各有独立当前表和不可变版本表，员工行锁串行化同一人的最高标记切换。统一命令台账、字段审计和不含敏感值的 outbox 与业务同事务提交。所有列表在 SQL 中先筛范围、再排序分页。

**Tech Stack:** TypeScript、Hono、PostgreSQL/Drizzle、Vitest/PGlite。

## 3. 人员 API 与权限

- `apps/api/src/modules/personnel/**`：字段解析、人员范围 SQL、版本/审计、CRUD、分页、标准目录注册。
