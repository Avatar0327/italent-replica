# 列车 A 第 7 轮 P2-1：离职替代后的交接补发

依据：F-140 §3.4、DM-R9 / DM-R14、DEC-684 / 685、审查 `rta7_1.md` 与续作 8 派发。

## 方案与边界

F-261 在员工事务内登记账号任务，提交后独立执行全局账号命令；直接在替代事务中恢复账号会逆转锁序，并改变失败隔离。保留该边界，采用持久补发方案。

仅当后继离职申请发起交接遇到 `NO_INITIATOR_ACCOUNT`，且被替代单有恢复请求时，在现有 `employment_outbox` 登记补发意图。自动停用凭据可归另一租户的离职单，恢复资格仍由 F-261 全局判定。普通无账号审批保持原行为；不从历史 skipped 审计回填任务，不加开关或迁移（DEC-402）。

账号消费完成后，在独立租户事务中补发。账号分钟调度、任职调度和提交后即时消费复用同一出口；即使即时消费中断，持久意图仍可由调度恢复。

## 校验、锁序和幂等

- 员工锁 → 离职业务头 → 交接 / 审批。员工锁内重读待办回执和业务状态；撤销、删除等未确认状态关闭待办，不复活。
- 发起仍复用 BE-8b `launchExitHandover`：当前账号、成员、触发开关、流程与处理人照常检查。判定“包含最后工作日早于审批通过日”沿用登记时的批准日，审计发生时间使用实际重试时间。
- 发起与成功回执同事务；用现有 `employment_outbox_attempts` 追加次数、结果和失败原因，绝不改写 outbox。事务异常回滚交接及成功回执，再另记失败；单项失败不阻挡后页。
- 员工锁内去重与交接既有唯一约束保证重复提交、重复调度和多实例并发不多发。成功 / 已有 / 按配置跳过 / 未发起记录均结束补发；无可用账号或发起失败保持可重试。
- 账号何时停用、何时恢复、人工停用保护、多租户到期判定与账号审计逻辑均不修改。交接补发自身不调用账号状态写入。

## 验证

红测单独提交：真实 HTTP 已生效替代，以及即时消费者未运行后由调度补偿，旧实现双库均后继交接为零。保留未生效改期和替代前手工启用账号的因果对照。

补充账号 revision / 审计恰好一次、重复提交 / 调度、补发回滚与失败重试、并发去重、撤销、关闭开关、撤销成员、手工停用、原批准日、跨租户隔离及自动停用凭据归属另一租户的验证。随后串行执行派发要求的相关验收、旧库升级、严格集、F-039 重算、类型 / 风格 / 构建检查。
