# R2-T06 合同协议交付

范围依据：`32_合同协议_规格.md` CT-R1～18、AC-CT-01～10；`后续任务.md` §15.1、§16。

## 对象与字段取舍（DEC-005）

保留 `21` §2 列出的有业务语义字段：编号、人员、合同类型、法人公司、期限类型、期限（月）、签订日期、生效日期、终止日期、实际终止日期、试用期起止日期、试用期工资、试用期满工资、签订次数、状态、审批状态、版本号、原合同关联、任职记录关联、合同变动记录，以及原站编码映射。金额以 decimal 存储。内部 UUID 与业务编号分离，编号按租户唯一（作废和已删除版本不占用当前编号）。

变更记录独立关联人员、组织、变动前合同、变动后合同和申请单；业务字段数据库触发器禁止覆盖，只允许追加版本。状态、实际终止日期、revision、逻辑删除为可维护投影；每次投影变化保留同事务审计快照。删除保留快照，不物理清除历史。

未照搬的字段：电子签署记录与签署模板属明确延期范围；“是否即将到期”“合同到期天数”为日期派生值，不重复存储；共享人、共享部门、原站系统记账字段不复制。`21` 只列出 66 个标准字段中的业务节选，不假定未列字段的语义。自定义字段复用已有 `employment_custom_field_objects(object_type='contract')`，以 `custom:<id>` 独立鉴权，不提供绕过字段权限的 JSON 总开关。

`rootContractId` 为合同版本族标识，`previousContractId` 为前合同引用；续签、变更新建版本，状态变化保留原版本。申请单与生效记录分表，审批通过的未来业务在租户日期到达后写入生效版本。

## 复用与新增

- 复用：统一 `runCommand` 幂等台账、审计表、`withTenant` 与 RLS、人员主档锁、任职当前记录与周期、自定义字段定义/类型校验、权限目录与字段裁剪、数据范围 SQL。
- 复用：审批中心流程匹配/快照/盲审/本人回避/重提/撤回；F-003 合入后直接复用 `approveTask`、`disagreeTask`、`rejectTask`、`resubmit`。
- 复用模式：R1-T08 按租户时区执行、员工 `SKIP LOCKED`、有界扫描、失败可见及重试；合同调度代码独立，不修改任职调度器。
- 新增：合同生效版本、申请、变动关联、法人和类型主数据、配置、续签规则及明细、失败尝试、outbox、合同导入。
- 导入没有可直接复用的全模块框架，沿用原有模块的“结构校验→事务内验证→整批写入”方式。预览在 savepoint 内执行后回滚，实际导入整批验证成功后才提交。

## API

统一前缀 `/api/tenant/contracts`，写请求带 `Idempotency-Key`、`If-Match`；已存在对象的 revision 不匹配返回 409。

| 接口 | 行为 |
| --- | --- |
| `POST /commands` | `operation=create/renew/change/terminate`，`mode=direct/application`，员工、目标合同和字段 |
| `POST /batch` | 最多 100 项，每项独立 revision；整体成功或整体回滚；申请每项独立流程 |
| `POST /todos/batch` | 最多 100 项；同意、不同意、驳回、原发起人重提；逐项回执与独立命令台账 |
| `GET /` | `view=all/valid/expiring/expired_unrenewed/missing/in_review`；SQL 范围先于分页 |
| `GET /?view=expiring&days=N` | 调用方明确传入即将到期窗口，1～3660 天；规格未确定默认天数，服务端不猜默认值 |
| `GET /records/:id`、`GET /requests/:id` | 当前权限下的合同或申请详情 |
| `GET /employees/:id/revision` | 人员合同集合版本，初始化导入用 |
| `GET/POST /master-data/types`、`.../companies` | 类型和法人主数据；`PUT /:id` 按 revision 修改；新建返回可立即选择的 ID |
| `GET/PUT /settings` | 自动续签、自动到期终止、自动编号、第三次期限联动、重聘累计、离职后可签类型、续签类型、导入唯一键 |
| `GET/POST /rules`、`PUT /rules/:id` | 规则优先级、组织和附加人员、逐类型明细、代发人、提前天数、后续类型排除 |
| `POST /imports` | add/edit/change/initialize，单批最多 10000 行；编辑和变更需原合同 revision |
| `POST /imports/preview` | 最多 3000 行、完整验证、不保留写入 |
| `POST /imports/errors` | 同一输入重新验证，直接下载错误 CSV，不保存可跨租户访问的临时文件 |
| `GET /failures` | 当前范围内调度失败尝试；修正流程、规则等原因后，下次调度自动重试 |

导入的 edit 是按唯一键定位后的版本化修正；change 是按人员、合同类型和原生效日定位，执行 CT-R11/12。initialize 要求每个员工的合同集合 revision；存在未完成申请时拒绝，防止初始化后旧申请重新生成合同。已存在记录逻辑删除后重建，整批事务保证失败不清空原数据。

全部视图包括生效合同和未完成申请，以 `rowType` 区分；申请的 `approvalStatus` 与生效合同区分。即将到期窗口由调用方提供。入职缺失仅取已生效任职、非离职退休且无有效合同的人。

本租户证据中的类型名称、组织与开关是租户配置证据，不复制真实租户数据。新租户的自动动作默认关闭，配置主数据和流程后显式开启；离职后可签、续签类型、期限联动类型均由 ID 配置。

## 并发、权限、调度

| 路径 | 锁顺序 |
| --- | --- |
| 合同单条、版本生效、导入 | 员工主档 → 合同/申请 → 写入 |
| 合同批量、初始化 | 员工 ID 升序预锁 → 各条合同/申请 |
| 合同审批 | 员工主档 → 业务单 → 审批实例（遵守 F-008） |
| 合并待办 | 每条独立事务，逐条复用审批锁协议；逐单重新验权 |
| 调度 | 员工主档 `FOR UPDATE SKIP LOCKED` → 合同/申请 → 成功尝试与命令台账 |
| 主数据、设置、续签规则 | 租户专属合同配置 advisory lock → 对应对象 revision |

调度每次最多处理 500 个候选、最多扫描 20 个租户，返回员工/合同候选游标和租户游标，进程下一轮续跑。规则最多 200 条，每规则最多 100 条类型明细；单人合同读取设 10000 条保护上限。失败尝试单独保存错误码，不提交失败业务写入。跨实例依靠员工锁、成功尝试与台账去重。

自动到期终止只改变状态投影；已审批续签若仅遇到这一变化，通过对应同事务 outbox 的原/新 revision 核验后仍可生效。人工修改造成的 source revision 冲突不放行。

审批详情沿用节点字段白名单、字段权限、盲审与本人回避。审批人不需要员工档案的数据范围，普通详情和列表仍按当前数据范围鉴权；合并待办不扩展档案权限。重提检查当前范围及完整载荷字段权限；导入初始化另查删除权；幂等响应重放后仍重新验范围并裁剪字段。

## 对外事务端口及未覆盖

`@italent/api` 导出 `generateContractForBusiness`、`changeContractForTransfer`、`handleContractsOnExit`；输入 `Tx`、可信 `ContractContext` 与业务参数，均不自行开事务，失败抛机器可读 `AppError`。调用方须在统一命令台账和业务事务内调用，注入当前权限或明确的可信系统上下文。合同侧同事务写审计和 outbox。

- R2-T01/R2-T07 随业务生成合同的表单和触发接入未覆盖。
- R2-T03 离职触发未接入；合同端口直接调用验证 AC-CT-07/08，处理未来申请并结束其在途实例。
- R1-T10 调动表单及生效编排未接入，AC-LNK-01/02 的跨模块整单验收留给 R1-T10；合同变更端口及变动记录已具备。
- 电子签署、签署/打印模板、合同看板按规格延期。
- 合同预置流程带标准 FlowCode 条件；未取证节点结构沿用预置流程既有 TODO（需取证 #38），以草稿安装，配置异常管理员和节点后发布。

## 验证与恢复点

首个提交独立包含失败的 AC-CT-01～10 测试。补充测试涵盖四种申请、合并待办动作、期满与续签交错、重聘和期限联动、四种导入、幂等、整批回滚、租户/范围/字段权限与调度失败重试。

PostgreSQL 强制交错用例：自动续签双实例、自动到期终止双实例、批量先于单条、单条先于批量；通过实际行锁屏障及 `pg_stat_activity` 确认参与方被阻塞，非 Promise.all 概率碰撞。本云环境无 PostgreSQL，本地运行跳过这四条，以 PR CI PostgreSQL 16 为准。

已同步 F-003 main，合同迁移由 `pnpm db:generate` 重生成，随后生成独立 RLS/版本保护迁移。合并前若 main 新增迁移，后合并者继续重新生成。未修改共用会话状态与恢复点文档；最终检查结果、迁移编号和恢复位置以 PR 描述为准。
