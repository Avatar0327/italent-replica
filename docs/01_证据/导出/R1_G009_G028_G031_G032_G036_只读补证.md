## G-031 流程时效与不计时时段
- 位置：流程「基本信息」的“时效设置”（流程级，对全部节点生效）；节点上可选 同步流程级 / 启用节点级 / 不启用（61637061）。
- 配置结构（前端代码与流程定义字段）：
  - `timeSpan` **计划时长**：1–9999 的整数，单位**小时**。
  - **到期前**（`isTimeEffectBefore` / `timeEffectBefore`）：提前 `remindTime` 小时发提醒，`remindTime` 须小于计划时长；可重复提醒（`frequencyType`、`intervalTime` 间隔小时、`remindNum` 次数，不超过 20，间隔须 ≤ 到期前时长）；消息模板 `messageCodes`，渠道 邮件 / 消息 / 短信。
  - **到期后**（`isTimeEffect` / `timeEffect`）：`handleType` = 1 **发送催办消息**（可重复，参数同上）或 2 **自动审批**（`defaultComplateAction` = 节点上的一个审批动作，如同意 / 驳回）。
  - 两者至少勾选一种（校验“必须勾选一种时效类型”）。
- 不计时时段（`period`，流程级，对全部节点的时效生效，133530713）：两项可同时勾选——**国家法定节假日及双休日**（`isHolidays`）、**每日**某个时段（`isEvery` + 起止时间）。含义：这些时段不计入计划时长。
- 流程侧**不引用**假勤的「工作日历」（109725385，假勤的工作日历组 / 组织日历另有用途）；节假日数据来自平台。
- 本租户调动流程（5eb0f5e9…）节点 `duration=0`，未启用时效。
- 催办设置（28345562）：流程级开关 + 节点级覆盖；运行时在详情页出现“催办”按钮，给当前节点未审批人发催办通知。

## G-032 按对象仿真
- 两种仿真（25887410）：**单流程仿真**（在设计器内，任意状态的流程都可仿真；数据全部虚拟，不发消息 / 待办；输出发起日志与流程日志：节点状态 通过 / 警告 / 异常、预计审批人、审批区域、连接线条件核算、消息接收人）；**按对象仿真**（105548258）：选 审批类型 + 对象 + 仿真范围（已发布版本 / 最新版本），输入数据后按优先级依次核算同一对象下**所有流程的发起条件**，展示每条流程的核算结果，命中的继续核算提交条件，可查看其仿真详情。按租户 + 应用灰度。
- 前端接口：`ProcessV2/GetSimulationDataItem`、`StartSimulation`、`GetSimulationLog`、`GetSimulationFlowChart`。
- 与 C-006 的关系：按对象仿真正是用来发现“调动申请被离职流程接住”这类问题的工具。

## G-036 排序编码计算引擎
- 文档 39387531「排序规则」：人员默认排序规则可按 所属部门（依据：行政上级 + 行政维度顺序号）、职务（编码）、职位（顺序号）、职级（级别）、职等（等级）、工号 排序；组织默认排序规则可按 行政隶属关系（层级 + 行政维度顺序号）或 编码。系统据此给 员工信息、任职记录、合同协议（人员规则）和 组织单元（组织规则）的【排序编码】写值，**每三小时刷新一次**；列表可按排序编码排序。
- 元数据：`TenantBase.OrderRule`（编码、名称、类型、状态、适用应用 / 对象 / 字段、选择子集、备注）+ `TenantBase.OrderRuleItem`（序号、排序属性、排序规则 正序 / 倒序、**引用规则**、类型）。`OrderCode` 是**长整数**（员工信息、任职记录；合同协议上叫“人员排序编码”）；任职记录另有 `OrderCode1` 已废弃。字段说明：开启人员排序规则后，先算各排序属性的【排序号】（如组织排序号、职级排序号），再按优先级组合算出【排序编码】；人员子集也可按这些排序号排序（`22` §2 的冗余排序号即来源于此）。
- 本租户 7 条规则：人员默认排序规则（启用，所属部门 ↑ → 工号 ↑ → 职级 ↑）、组织默认排序规则（**停用**）、以及被引用的子规则 组织行政隶属关系规则、职位 / 职务 / 职级 / 职等默认排序规则（均启用）。页面上只显示人员、组织两条。
