## 1. G-057：360 人员表的同步与冲突

### 1.1 原站对象 `I360Cloud.Personnel`（41 个标准字段，无自定义）🟢
- 关联员工：`BeisenUserID`（北森ID，员工单选）；另有 **`OldUserId`（旧BeisenUserID）**，说明原站考虑过员工 ID 变化后重新挂接。
- 人员属性：`PersonnelName`、`PersonnelMail`（人员邮箱）、`PersonnelMobile`、`PersonnelStaffCode`（工号）、`EmployedDate`、`StaffStatus`（员工状态）、`PSource`（来源，整数）、`IsPlat`（是否平台的人）、`ReportCount`。
- 组织信息是**文本副本**：`PersonnelDep`（部门，文本）、`PersonnelJob`（职位，文本）、`FullOrg`（组织全称，文本）、`DepartmentCode`（组织机构ID）、`SuperiorID`（上级ID，文本）。不是实时引用组织对象，而是同步时写入的快照。
- 本租户 360「人员」0 条：该租户从未使用过同步。

### 1.2 官方文档（118949527「360度评估人员」）🟡
- 人员来源两种：从活动中添加参与人；从系统管理中同步人员信息。
- 从组织机构同步后，“信息将以组织机构为准”。
- 同步后，在活动中批量导入评价者时，可选择是否从组织架构同步人员信息；选“不同步”则以上传的信息为准。
- 同步后，360 中**可更改“邮箱”之外的个人信息**（即邮箱锁定，其余可改）。

### 1.3 可借鉴的原站做法：测评中心 `Assess` 的员工关联 🟢
测评中心也有一套独立人员表（`Assess.PersonalBasicInfo`，含 `I360UserId` 360人员ID、`FK_BeisenUser_ID`），与组织员工之间用**显式关联表**挂接：
- `TenantBaseEmployeeAssessPersonalRelation`（员工测评人员关联表）：员工ID、组织员工人员ID、任职记录、测评人员ID、**匹配原因**、**来源**、**类型（状态）**、操作人、操作时间。
- `TenantBaseEmployeeAssessPersonalRelationRecord`（员工关联记录日志）：每次关联变化的记录。
- `TenantBaseAndPersonalBasicInfoCheck`（员工一键查重）：按 **姓名、身份证号、邮箱、手机号、性别、出生日期** 两边比对，记录匹配原因与**绑定失败原因**，分批次。

→ 原站对“独立人员表 ↔ 组织员工”的标准解法是：关联表 + 多字段查重 + 失败原因 + 关联日志。

## 2. G-058：测评取数函数的数据来源

### 2.1 函数（239045415）🟡
- 函数：`LastestAssessmentCent(测验信息.<总分|维度得分|锐途星级|综合指数|匹配度>, 过滤条件…)`，中文名“获取当前人员测评测验下的最近一次测评得分/维度得分”。
- 过滤条件至少一个，常用 `测验信息.测验名称=…`、`测验信息.维度名称=…`；可与 `Average` 等组合。
- 只支持文档所列的北森测评方案（约 40 种），其他特殊维度不支持。
- **“最近一次”的时间口径两处文档不一**：239045415 写“当前盘点活动**结束时间**前”；256213460 写“盘点项目**开始时间**之前”。另外，如果盘点项目创建时关联了测评项目，盘点对象会被自动加入测评活动，满足有效性条件（有效时间、可信度）的历史测评结果会被复制过去。
- 第三方测评（76874290）：可把维度数据导入组织人事或继任与发展，再用 Ocean 报表在盘点报告中呈现。文档未说函数能读第三方数据。

### 2.2 数据在哪 🟢
- 测评中心应用 `Assess` 共 198 个对象，含：测验 `AssessmentTest`（名称、类型、是否自定义测验）、维度得分 `Assessment_DimentionDetailResultInfo`（活动ID、测验ID、维度ID/别名、得分 Cent、得分类型、北森用户ID、邮箱）、甄选中心数据集 `AssessmentResultPool`（2248 个维度列）、各测验专用结果表（`TestResult*`，约 40 张）。
- 结果与员工的对应靠 §1.3 的员工测评人员关联表。

### 2.3 本租户用没用 🟢
- 14 条盘点计算规则：启用 8、草稿 3、停用 3；已读其中 5 条启用规则（GLD盘点规则HTC、GLD360结果、安擎绩效转化计算规则、jb-绩效结果、SG点计算规则）。
- **「SG点计算规则」（启用）**：计算项目“潜力” = `Def(a, 获取当前人员测评测验下的最近一次测评得分/维度得分(测验信息.总分, 测验信息.测验名称="商业综合推理能力测验")); 如果 a>=3.5 那么 3 如果 a>=3 那么 2 否则 1`。
- 其余 4 条已读规则用的是 360（`获取最近一次360总分`）、绩效（`获取指定年度指定周期的绩效得分/等级`）、排名（`获取某个结果在指定人员范围内的排名`）和盘点对象字段。
- → 本租户**实际在用**测评取数函数，G-058 不是纸面问题。
