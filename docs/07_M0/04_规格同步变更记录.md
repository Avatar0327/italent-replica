## 5. 同步中发现的矛盾与待确认点（需用户或下一轮决定）

1. **自审跳过后“转上级”口径未定义（DEC-058）**：上级是该节点审批人的直线经理、部门上级负责人，还是下一节点？文档暂按“该节点审批人的直线经理，无法解析转异常管理员”写，需确认。另：原站本流程配置“相同审批人 / 历史相同审批人跳过，结果 = 同意”（`14` §8.3）；若发起人恰是调出部门负责人，原站会按“同意”跳过，DEC-058 要求“不计为同意”，两者冲突处已在 `14` §10 写为“自审跳过优先”，请确认。
2. **盲审被拦后没有明确出路（DEC-058）**：审批人既不能同意也不能驳回，流程会停住。文档写的出路是“转交（节点开启时）或流程管理员干预（DEC-063）”，但原站多数节点未开转交（`14` §8.2），实际只能靠管理员干预；是否需要“自动转异常管理员”等兜底，需决定。另“无权查看”按字段权限判定；变化字段根本不在节点表单上（DEC-057 只显示节点表单字段）是否也算盲审，未定义。
3. **管理员转交给自己（DEC-063）**：原站实测管理员把任务转交给自己后再同意（W-014/W-015）。若复刻仍允许“转交给自己”，“不得代签”可被绕过；建议同时禁止管理员把任务转交给本人，需确认。
4. **AC-TEN-06 暂时无法执行（DEC-061 × DEC-050）**：部署位置与数据库托管方式未决，RPO/RTO 目标无法验证，且可能按 DEC-061 降档。M1 判据已注明“部署环境就绪后补跑”。
5. **REQ-APV-001 配置边界仍有“审批人表达式是否开放给管理员 → 待决”**：DEC-053（X-6）只澄清了“流程可配置、不写死两级”，未回答表达式是否开放，该待决项仍在。
6. **既有编号重复（非本次引入）**：`14` 在 §8 表中 AC-APV-10 = 时效、AC-APV-11 = 按对象仿真；§8.6 末尾又有 AC-APV-10 = 发布校验（DEC-018）、AC-APV-11 = 找不到调动流程报错（DEC-017）；`02_已确认决策.md` DEC-018 也写“新增 AC-APV-10”。本次未改动（避免删改原有内容），新增编号从 13 起避开；建议另行把 §8.6 末两行改编为 AC-APV-18/19。
7. **DEC-051 开关的覆盖范围**：文档写明覆盖两个直接调动按钮及将来的导入调动 / 批量调动；DEC-029 组织调整单据内的调动（生效即落地、不走调动审批）是否受该开关约束，未定义。
8. **租户时区修改的影响**：REQ-PLT-001 R5 中“修改只影响之后的日期判定，不改写已生效数据”是本次按常理补的口径，决策原文未写，需确认。
