### 1.2 拒绝码（status + error.code，必要时 details.reason）

| 名称 | 拒绝 | 现状来源 |
|---|---|---|
| `NF(X)` | 404 NOT_FOUND「X不存在」；**不存在与范围外同一个响应体** | `access.requireVisible`、`write-support.lockOwned / referenced`、`routes` 详情 |
| `NOVIEW(X)` | 403 FORBIDDEN「无权查看X」（引用对象没有查看权） | `write-support.referenced`、`criterion-service.checkReferences` |
| `NO_UNIT` | 403 FORBIDDEN「无可用的管理单元，请联系管理员授权」，reason `NO_MANAGEMENT_UNIT` | `owner-units.chooseUnit` |
| `UNIT_REQUIRED` | 400 VALIDATION_FAILED，reason `MANAGEMENT_UNIT_REQUIRED` | 同上 |
| `NF_UNIT` | 404 NOT_FOUND「所属管理单元不存在」（选了不属于本人的单元，存在与否同一个 404） | 同上；`ownerUnit` 再按 DEC-082 复核新建范围 |
| `F_ACCESS` | 403 FORBIDDEN（没有对象数据操作权 / 按钮 / 字段编辑权） | `objectContext`、`button`、`writeFields` |
| `ID400` | 400 VALIDATION_FAILED「对象标识必须为 UUID」 | `talent/http.uuidParam`（invalidId） |
| `Q400` | 400 VALIDATION_FAILED（page / pageSize / type / enabled / name / UUID 查询参数非法） | `talent/http.*Query` |
| `REV` | 400 REVISION_REQUIRED（缺 If-Match）；409 REVISION_CONFLICT（新建非 0 / revision 不符） | `talent/http.revision / requireNew`、`lockOwned` |
| `IDEM` | 400 IDEMPOTENCY_KEY_REQUIRED（缺 Idempotency-Key）；409 IDEMPOTENCY_CONFLICT（同键异内容） | `runCommand` |

### 1.3 谓词、定位器、守卫、形状

| 种类 | 名称 | 含义（现状实现） |
|---|---|---|
| 谓词 | `talent.ownedScope(<表>)` | `scopeSql(scope, { org: owner_org_id, creator: owner_id })`，分页前生效；列表信封 `hasDataPermission` |
| 谓词 | `talent.dictionaryScope` | 看全部 ∪ `created_by = 本人`（DEC-121） |
| 定位器 | `talent.<object>.byId` | 写：事务内 `FOR UPDATE` 行锁 → 范围（`NF`）→ revision（`REV`）；读：加载 → 范围（`NF`） |
| 守卫 | `talent.referenced(<object>)` | 引用对象：查看权（`NOVIEW`）→ `FOR SHARE` → 存在与范围（`NF`） |
| 守卫 | `talent.libraryCreatable` | 所属指标库的管理单元在操作人对新对象的新建范围内（DEC-082；`NF(指标库)`） |
| 守卫 | `talent.ownerUnit(<object>)` | 所属管理单元 = 创建人的授权管理单元（DEC-294③ 及补充一 / 二）：`NO_UNIT` / 一个自动 / 多个须选 `UNIT_REQUIRED` / `NF_UNIT`，再按 DEC-082 新建范围复核 |
| 守卫 | `talent.relationUnit` | 编辑标准新加的关联记录：所属人 = 添加人，管理单元 = 添加人的授权管理单元（规则同上，不继承标准；授权随标准的编辑） |
| 守卫 | `talent.copyCategoryName` | 选入指标时复制库内分类名：只有操作人当前对 DIM.`categoryName` 有查看权才复制，否则留空（DEC-309） |
| 守卫 | `talent.descriptionTypeChoice` | 发展建议类型：新选用须启用；已有行（按行 id）可保留停用的类型（400 `DESCRIPTION_TYPE_INVALID` / `SUGGESTION_ROW_INVALID`） |
| 足迹 | `talent.commandScope` | 命令内行锁后再判范围；新建按 `ownerUnit` / `libraryCreatable` |
| 返回后 | `generic { targets: 'id', locator: talent.<object>.byId }` | `runTalentWrite`：首次与幂等重放都按**当前**范围复核结果对象（撤权后重放 `NF`） |
| 形状 | `talent.<object>` | 读模型视图，经 `trimModuleResponse` 按本对象字段权限裁剪 |
| 投影器 | `talent.criterionNested` | 标准视图：顶层按 CRIT 字段权限；嵌套指标只投影 `name / definition`，另按 DIM 查看权 + DIM 范围 + DIM 字段权限（看不到整段省略，只留引用本身，DEC-281⑪ / DEC-178） |
| 谓词 | `org.scope` | 组织员工应用的当前数据范围：`scopeSql(scope, { org: org_id, creator: creatorSql(org.create) })`，与组织列表同一谓词（org/read-model.ts） |
| 投影器 | `talent.ownerUnits` | `id` 恒有；`code / name` 只在查看人当前对 ORG 有查看权与该字段查看权、且该组织在 `org.scope` 内时带出，否则只返回 `id`（DEC-309 / DEC-316②） |
| 投影器 | `talent.descriptionTypeOptions` | `id / displayOrder` 恒有；`name` 仅当查看人当前看得到 DIM.`suggestions`（DEC-309） |

### 1.4 写入共性

- 全部写路由：`If-Match` 必带（`REV`），`Idempotency-Key` 必带（缺失 400 IDEMPOTENCY_KEY_REQUIRED，`IDEM`；命令台账 `ledger single`，同键同内容重放首次结果），业务写与审计同事务（DEC-019 / 216）。
- `write.fields = 'body'`（parseBody 严格结构，未知键 400）；`controls = ['ownerOrgId', 'relationOwnerOrgId']`：所属管理单元的**选择**不是写字段，不按字段编辑权拦截，由 `ownerUnit / relationUnit` 校验（`access.checkWriteFields`）。
- 按钮：新建 `create@list`、修改 `update@detail`、删除 `delete@detail`；CRIT 另有 `setDimensionCategory@detail`（数据操作按 update）。

## 3. 示例声明（PR-A 合并后照此转写）

```ts
// 文案「<label>不存在」，不存在与范围外同一响应体（label 只决定文案）
const NF = (_label: string): Denial => ({ status: 404, code: 'NOT_FOUND' });
const UNIT_CONTROLS = ['ownerOrgId', 'relationOwnerOrgId'];

declare(router, 'PATCH', `${TALENT_BASE}/criteria/:id`, {
  kind: 'object', object: CRIT, operation: 'update', button: { code: 'update', level: 'detail' },
  scope: { mode: 'point', target: { param: 'id' }, locator: 'talent.criterion.byId', denied: NF('人才标准') },
  fields: { mode: 'projector', projector: 'talent.criterionNested', shape: 'talent.criterion' },
  optional: { nestedDimension: NESTED_DIMENSION },
  guards: ['talent.referenced(criterionCategory)', 'talent.referenced(dimension)', 'talent.copyCategoryName', 'talent.relationUnit'],
  write: {
    fields: 'body', controls: UNIT_CONTROLS, footprint: 'talent.commandScope',
    result: { generic: { targets: 'id', locator: 'talent.criterion.byId' } },
    preconditions: ['talent.criterionDimensionRules'], ledger: 'single',
  },
  invalidId: { status: 400, code: 'VALIDATION_FAILED' },
}, handler);

/** 标准里嵌套的指标内容：可选分支，未通过只省略内容、不拒绝（DEC-281⑪ / DEC-178）。 */
const NESTED_DIMENSION: RoutePolicy = {
  kind: 'object', object: DIM, operation: 'view', button: { none: true, reason: '嵌套内容按对象查看权' },
  scope: { mode: 'list', predicate: 'talent.ownedScope(talent_dimensions)' },
```

## 4. 带出值入口清单（DEC-309，第 6 轮清单 2）

凡是把对象 X 的字段值写进对象 Y、或经 Y 返回给操作人的入口，都按查看人**当前**对源字段的查看权裁剪；每个入口至少一条“看不到就留空 / 不带出”的反向测试。

| # | 入口 | 源对象.字段 | 目标对象.字段 | 裁剪方式 | 对应测试 |
|---|---|---|---|---|---|
| E1 | 新建 / 编辑人才标准时选入指标（`POST /criteria`、`PATCH /criteria/:id`） | 指标.categoryName（库内分类.name 的查找显示值） | 关联记录.dimensionCategory（写入） | 写入时按操作人当前对 DIM.categoryName 的查看权：看不到留空；没解析到按看不到（fail-closed）；自己填写的值照存 | `AC-TC-carry` E1 ×3（新建、编辑、正例） |
| E2 | 人才标准列表 / 详情 / 写入与重放响应里的嵌套指标 | 指标.name / definition | 标准.dimensions[].dimension | 读时按 DIM 查看权 + DIM 范围 + DIM 字段权限，看不到整段或该字段省略 | `AC-TC-carry` E2；`AC-TC-permissions`「看全部 + 字段权限」「没有指标对象权限」 |
| E3 | 指标列表 / 详情 / 写入响应 / 可引用指标候选 | 库内分类.name、指标库.type | 指标.categoryName / type（查找显示值） | 按 DIM.categoryName / type 字段查看权（系统字段，可配查看） | `AC-TC-carry` E3 |
| E4 | 指标详情的发展建议；发展建议类型下拉 | 发展建议类型.name | 指标.suggestions[].typeName；候选 name | 按 DIM.suggestions 查看权：看不到时详情无 suggestions、下拉只给 id / displayOrder | `AC-TC-carry` E4（含正例） |
| E5 | 所属管理单元候选（新建表单 / 新加关联的下拉） | 组织.code / name | 候选 code / name | 按查看人当前对 ORG 的查看权与字段查看权，且该组织在查看人组织员工应用的当前数据范围内（`org.scope`，DEC-316②）：任一不满足只返回 id，前端以 id 显示 | `AC-TC-carry` E5 ×2（无组织权限；组织范围只含 A、授权单元为 B 的五种对象 + A 正例）、DEC-316③ 只有编辑权；`AC-TC-owner`「看不到组织名称时下拉以 ID 显示」 |
| E6 | 审计数据变更日志（指标的新增 / 修改 / 删除快照） | 库内分类.name 等查找显示值 | 审计快照里的 categoryName | 审计查询按查看人当前对 DIM 的字段权限逐字段裁剪 | `AC-TC-audit`「审计查询按…裁剪（含快照里带出的分类名称，DEC-309）」 |

不属于“带出值”、已确认无需裁剪的：
- 关联记录.type（能力 / 潜力 / 经历）：标准内的分组本身（DEC-281⑪，TC-R3 只有能力可设权重），随标准的 dimensions 字段授权；
- 关联记录.dimensionCategory **已保存后**：是标准自己的独立文本（DEC-294⑤），按标准的权限处理（DEC-309）；
- 「设置指标类别」批量入口：写入的是操作人自己填写的文本，不从其他对象带值；
- 可信端口 `port.ts`：不面向操作人，调用方按自己的业务权限裁剪（端口注释已写明）。
