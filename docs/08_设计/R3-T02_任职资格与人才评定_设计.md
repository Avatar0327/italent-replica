**通用指标联动（QL-R5 / AC-QL-03）**：通用指标的能力标准**不落副本**，读取时由 `ql_targets.description` 投影为唯一一条不可编辑的能力标准；非通用指标新建标准时复制一次，之后独立；非通用 → 通用时删除各标准该指标的能力标准行（读取改为投影）。理由：原站“改指标说明联动所有标准”就是实时引用，存一份副本再同步会多出并发窗口（DEC-285② 不自造）。

**导入（QL-R11 / AC-QL-05）**：标准明细导入一行 = 类别编码 × 级别编码 × 指标编码；“编辑导入”对每个（标准, 级别, 指标）先删该格全部能力标准再按文件重建；整批一个事务，上限 2000 行，失败返回逐行回执、整体回滚（AGENTS §10 批量）。导入任务按 DEC-199 持久保存条数、结果与错误报告。

- 新建 / 编辑三步向导（EV-R17）只是前端形态；服务端一次性接收整份活动（条件、环节嵌套），整体成功或整体失败。

### 3.5 评定数据状态机与“状态 × 操作”表（`24` §3.8）

阶段 stage ∈ {apply, material, defense, result}；异常终态 `terminated`（原因：`leave` 离职 / `activity_completed` 活动完成 / `revoked` 撤销申报）。

| 阶段 · 状态 | 进入方式 | 允许的操作（其余一律 409 `EVALUATION_STATE`） |
|---|---|---|
| apply · `draft` 待申报 | 批量提名保存；资格审批驳回 / 撤回 | 申报人或提名人修改申请类别级别 / 破格；提交（逐条校验 §7.1）；删除（未提交过的草稿） |
| apply · `reviewing` 申报审核中 | 提交 → 发起资格审批 | 审批动作（审批中心）；催办；撤销（= 终止 `revoked`，EV-R23）；提前转入（仅下一环节是答辩，EV-R29） |
| apply · `passed` / `failed` | 资格审批通过 / 不同意 | passed：自动或手动转入下一环节；failed：终态（不再流转） |
| material · `pending` 材料待提交 | 转入 | 员工保存（实时保存）/ 提交 → 发起材料审批；可在答辩待安排期间被提前转入 |
| material · `reviewing` | 提交 | 审批动作（节点可编辑上级评价 / HRBP 评价，EV-R27） |
| material · `passed` / `failed` | 审批结束 | passed：更新答辩材料（EV-R28，记更新人 / 时间）；自动或手动转入答辩；failed：只能手动转入（🟡 Q-T02-11） |
| defense · `unscheduled` 待安排评审 | 转入答辩 | 排入场次（暂存不变状态） |
| defense · `scheduled` 待评审 | 场次“确定并发送通知” | 跟场人开始 / 结束答辩；评委保存 / 提交 / 弃权；场次内移除（有在途审批须先撤销，EV-R37） |
| defense · `reviewed` 已评审 | 所有在职评委都已提交或弃权（DEC-044） | 评委改分重提（回到计算，仍为 reviewed）；跟场人确认校准 |
| defense · `calibrated` 已校准 | 跟场人确认校准 | **评委提交 / 弃权一律 409 `CALIBRATION_LOCKED`（DEC-046）**；跟场人重新校准；手动转入结果发布 |
| result · `pending` 结果待发布 | 手动转入（EV-R13） | 提前通知（EV-R42）；发布 |
| result · `published` | 发布 | 只读；通过者已写子集（§4.4） |
| 任一非终态 → `terminated` | 撤销 / 完成活动 / 离职生效 | 只读；在途审批实例作废（engine `cancel`，🟡 Q-T02-12） |

- 提前转入后资格审批最终不通过（AC-EV-11 🟡）：回到 apply · `failed`，从场次中删除时段（时段已有评委记录的一并删除，审计保留）；材料审批不通过不影响答辩（EV-R29）。
- 完成活动（AC-EV-10 🟡）：活动 published → completed，同一事务把该活动所有非终态评定数据置 `terminated(activity_completed)`，作废在途审批。0 报名的活动没有“完成”（🟢 Q-M0-108 附带观察，只能取消发布）。

### 4.2 唯一映射（QL-R15 🟢 G-047）

### 4.3 任职生效的订阅方式（不改任职写入路径）

- **订阅 `employment_outbox` 的 `employment.record.create`**（落地记录时已同事务写入，`write-service.ts` → `auditEmployment`），新建消费者 `ev_sync_cursors(tenant, consumer, created_at, outbox_id)` 按游标拉取，每个事件一条 `ev_sync_receipts(tenant, consumer, outbox_id UNIQUE, state, attempts, reason)`，失败记 failed、次数、原因，可重试（DEC-052）；与 `job/sequence-worker.ts` 同模式（平台路径遍历租户，逐租户 `withTenant`，`runPlatformCommand` 幂等键 `ql-sync:<slot>[:cursor]`）。
- 理由：任职版本链同时只放 1 个 PR（DEC-249），本任务不改 `materializeEmploymentRecord` 与 `PersonnelHooks`（单实现，已被任职履历占用）。代价是最终一致（一个调度间隔），对子集“自动生成一条”可接受。
- 触发业务（QL-R15②）：入职（含重聘、退休返聘）、转正（含实习转正）、调动、新增员工；其他任职业务（组织调整、序列同步、撤销 / 删除任职）不生成、不删除（🟡 Q-T02-05）。
- **离职终止（DEC-032）**：同一消费者对 `leave` / `retirement` 记录的落地事件，把该员工所有非终态评定数据置 `terminated(leave)`，终止原因“离职”、作废在途审批。在消费落地之前，**评定的每个写命令都在锁内检查员工当前有效任职是否已是离职 / 退休**，是则拒绝（409 `EMPLOYEE_LEFT`），保证生效日当天不出现离职员工继续被评分的窗口（读时判定 + 异步落地）。R2-T03（#100）合并后若提供 `exitPostEffectHooks.effective`，改为同事务订阅（届时单开 F 任务，不在本任务）。

### 4.4 结果发布 → 子集（DEC-025 / AC-EV-09 / AC-QL-07）

发布在一个事务里：锁评定数据 → 校验 `calibrated` 后已转入 result · pending → 写 published → 通过者写子集一行（§4.1）→ 审计 → 通知登记。**不生成调动任职**（DEC-025）；AC-QL-07 按 DEC-025 改写为“发布后子集只多 1 行、任职记录不变”。HR 之后另发起的调动若命中同步开关会再生成一行——是否去重见 §12 P-2。

## 7. 规则实现要点

### 7.1 申报校验（EV-R19～R22，AC-EV-01～04）

按顺序，第一条不满足即拒绝（400 `APPLY_REJECTED`，`details.reason` 机读）：
1. 员工在职、在活动适用范围（任职部门 ∈ org_range 展开）且申请类别 / 级别在活动范围内（`OUT_OF_ACTIVITY_RANGE`）；
2. 活动已发布、在活动起止内（`ACTIVITY_NOT_STARTED`）；资格申报环节强控截止且已过（`APPLY_DEADLINE_PASSED`）；
3. 申请人方式：本人申报而活动只允许他人提名（`SELF_APPLY_NOT_ALLOWED`），反之亦然；
4. 跨级：申请级别顺序号 − 原级别顺序号 > max_level_jump（`LEVEL_JUMP_EXCEEDED`，AC-EV-01：默认申请 = 原级别 + 1）；原级别为空时不校验跨级（🟡 Q-T02-06）；
5. 同一活动重复（`DUPLICATE_APPLICATION`，AC-EV-04；部分唯一索引兜底并发）；
6. 参评条件：通用条件 + 匹配本人申请类别 / 级别的附加条件，按申请人类型取对应一套；不达标且（活动不允许破格或操作人不在破格角色）→ 400，`details.failedConditions = [{seq, text}]`，提示原文格式“{姓名} 以下参评条件不达标：{序号}）{条件文本}”（🟢 Q-M0-108，AC-EV-02）；允许破格且操作人是破格角色：勾选破格须填原因；未勾选也自动标记破格（EV-R21 兼容规则 🟡，AC-EV-03）。
- 批量提名（EV-R22）：≤ 500 行；保存为“待申报”时校验 1～5，提交时逐条校验 6；返回逐条回执（部分成功按 AGENTS §10 回执口径），失败者可补破格原因后“继续提名”。

### 7.2 计分（EV-R38～R41，DEC-044，AC-EV-06 / 07 / 12）

- 所有分 ∈ [0, 满分]（EV-R38）；按指标评分：每个评分项一个分；评总分：一个总分。
- 评分项权重（EV-R4 / R40，纯函数，PR-B 交付并测试）：`average` → 100% / 参与项数（剔除不显示的指标、能力标准为空的指标）；`weighted` → 指标 = 标准整体权重 × 明细权重%（明细权重空按 0%），通用评分项 = 自身权重；`sum` → 不加权。AC-EV-07：标准 80（A 40%、B 60%）+ 现场 20 → A 32%、B 48%、现场 20%。
- 单评委总分：`average` = Σ分 / 项数（未填按 0，🟢 T-405）；`weighted` = Σ(分 × 权重%)；`sum` = Σ分。是否允许留空提交 🟡 Q-T02-07（暂按原站允许、按 0 计）。
- 多评委最终得分 = Σ**已提交**评委总分 / 已提交评委数（DEC-044；弃权不计；固定规则不可配，EV-R41）；**所有在职评委都已提交或弃权**时才进入 `reviewed`，否则不可校准（AC-EV-12）。离职评委不计入“所有在职评委”。
- 精度：以 numeric 精确计算，最终得分四舍五入保留 2 位（🟢 W-320 显示 80.00）；通过 = 最终得分 ≥ 通过分数（🟡 Q-T02-07 用舍入前还是舍入后）。
- 弃权（EV-R31 🟢 W-319/320）：评委本人或跟场人，原因必填，不可撤销，清空该评委的评价与逐项分，提示原文“弃权后将清空评价内容，不可撤回，不可再次评价”；功能权限 `TEvaluation.EvaluationRecord / Abstain`（本租户预置身份都没有，🟢）→ 复刻同样作为可授权按钮，预置身份不给，评委 / 跟场人身份经关系入口判定（🟡 Q-T02-13）。
- 校准（EV-R36 / DEC-046）：最终得分 / 结果为空时默认取答辩得分 / 结果；优势、发展建议为空时按评委顺序拼接已提交评委内容；显示通过率 = 通过 / (通过 + 未通过)；确认后锁定评委评价，跟场人可重新校准。

### 7.3 场次（EV-R33～R35、R37）

开始时间 + 每人时长自动排时段；插入时段 / 人员、拖拽排序后续顺延；评委日程冲突只查本系统场次 30 天内（第三方日程 ⏸），冲突返回 `warnings` 不阻断；暂存不发通知，“确定并发送通知”给评委 / 跟场人 / 参评人登记待办（`ev_notifications`）；`reviewed` / `calibrated` 的人不能再调整；跟场人开始答辩时同一场次同一时刻只有一人 `in_progress`，结束后不能再开始；评委打分是否须先“开始答辩” 🟡 Q-T02-08（暂不要求）；有已评审 / 已校准人员的场次不能删。

### 7.4 并发与锁

- 锁序：员工（评定写入涉及员工时）→ 活动（计数）→ 评定数据 → 场次 → 评委记录 → 审批实例；与 org/locks.ts 的“员工闭包 → 业务 → 组织 → 编制 → 审批实例”一致（评定数据即“业务”）。
- 真实 PostgreSQL 交错测试：同一员工并发两次申报同一活动（只成功一次）；校准与评委提交交错（校准后提交 409）；离职落地与评分交错；冻结评分项与修改标准交错（冻结在评委首次保存的事务里，读标准用 `FOR SHARE`）。
