# F-125 新前端片怎么登记（DEC-476 / DEC-492①）

> 目标：新增或替换一个模块页面时，**只新建或修改本模块目录 `apps/web/src/<模块>/` 下的文件**，不碰底座的公共登记表。
> F-132、F-127b 等后续前端片按本文登记。

## 1. 两个登记文件

| 文件 | 导出 | 内容 |
|---|---|---|
| `src/<模块>/pages.ts` | `pages: ModulePages` | 应用页、应用内入口、子路由、菜单下一层适配 |
| `src/<模块>/annotations.ts` | `notes: Record<string, DecisionAnnotation>` | 本模块页面的注释（`<DecisionNote id="..." />` 用的键） |

底座用 `import.meta.glob('../*/pages.ts')` 与 `import.meta.glob('../*/annotations.ts')` 自动汇总，**不需要也不允许**再去改 `foundation/AppPages.tsx`、`foundation/routes.ts`、`foundation/messages.ts`、`annotations/index.ts`。

- 登记文件只能放在模块目录第一层（`src/<模块>/pages.ts`），放到更深层不会被汇总，`AC-FE-F125-03` 会报错。
- `src/annotations/` 目录只剩汇总入口 `index.ts`，不要再往里加模块注释文件。
- 文件存在却没导出 `pages` / `notes`，加载时直接报错。

## 2. `pages.ts` 写法

```ts
import { lazyPage, type ModulePages } from '../foundation/page-registry.js';

const OrgPage = lazyPage('OrgPage', () => import('./OrgPage.js'));
export const pages: ModulePages = {
  // 应用页：每个后端应用（domain APP_IDS）恰好由一个模块登记一次
  apps: [
    { app: 'org', label: '组织管理', group: 'people', objectCode: 'TenantBase.Organization', page: OrgPage },
  ],
  // 子路由：路径全局唯一；legacy 时装在 .legacy-page 内；ungated 只要求会话、不按菜单拦截（仅个人设置这类入口）
  routes: [{ path: '/org/changes', page: OrgPage }],
};
```

- `lazyPage(导出名, () => import(...))`：导出名受类型检查，懒加载与代码拆分和原先逐页 `lazy` 相同。同一页面在多个路由复用时，先赋给常量再引用。
- 应用页字段：`app`、`label`（菜单名）、`group`（`people` / `work` / `settings` / `talent`，分组本身由底座 `ui.groups` 定义）、`objectCode`（主入口对象，须与 domain `APP_OBJECT_DIRECTORY` 第一个对象一致）、`page`（不填显示空首页）、`legacy`（旧页面布局）。
- `children(snapshot, route)`：菜单下一层的 L2 结构适配（例：企业设置的后台菜单），只做结构转换，可见性仍来自服务端快照，不授予权限。
- **应用内入口** `entries`（不新增后端应用的独立菜单，如合同页）：`{ id, app, label, group, objectCode, page }`，菜单路径 `/<id>`，路由挂在 `/<id>/*`（子路径由入口页自管）；只在所属应用可见且其入口对象含 `objectCode` 时显示，排在全部应用之后、按 id 排序。现有用例：`contracts/pages.ts`（合同协议，属 staff）。
- `pages.ts` 只能 import `foundation/page-registry.js`、类型和本模块页面（懒加载）。**不要** import `foundation/routes.js`、`AppPages`、`Shell` 等运行时模块：会形成循环依赖；Playwright 也会在 Node 里直接加载 `pages.ts`。

## 3. `annotations.ts` 写法

```ts
import type { DecisionAnnotation } from '../annotations/index.js';

export const notes: Record<string, DecisionAnnotation> = {
  'org-tree': { original: '…', decision: '…', decisions: ['DEC-456'], level: 'L2' },
};
```

注释键全局唯一，重复直接报错（不再靠展开顺序静默覆盖）；建议以模块名作前缀。

## 4. 汇总规则（底座）

| 项 | 规则 |
|---|---|
| 应用顺序 | domain `APP_IDS`（后端权限快照同一份） |
| 应用内入口 | 排在应用之后，按 id 码点序 |
| 子路由 | 按路径码点序（React Router 按路径特异度匹配，与顺序无关） |
| 注释 | 按键码点序 |
| 重复 | 应用、菜单键、路径（应用 / 入口 / 子路由之间）、注释键任一重复即报错，报错写明两个模块 |
| 缺失 | 任一后端应用无人登记、登记了未知应用，即报错 |

汇总函数是纯函数（`collectPages` / `collectAnnotations`），不依赖 glob 的文件遍历顺序。

## 5. 测试怎么写

- 本片的登记测试写在本片自己的验收文件里，按模块声明逐项断言（例：`expect(annotationOwners['org-tree']).toBe('org')`、`SUB_ROUTES` 含本片路由），**不要写全局总数**（F-124 / DEC-475④）。
- `tests/acceptance/AC-FE-F125-registry.test.ts` 固定的是 F-125 迁移前的条目：新增条目不用改它；**有意改动已有条目**（换新页面、去掉 `legacy`、改菜单名）时，改它对应的那一行，作为行为变化的显式记录。
- Playwright 冒烟要拿应用列表时，从 `smoke/page-registry.ts` 取（Node 侧按同一规则扫目录、调同一个汇总函数），不要 import `src/foundation/routes.ts`（它用 `import.meta.glob`，只能在 Vite / Vitest 里运行）。

## 6. 仍由底座定义、页面片不改的位置

| 位置 | 原因 |
|---|---|
| `packages/domain/src/permission/app-directory.ts`（`APP_IDS` / `APP_OBJECT_DIRECTORY`） | 后端权限快照共用的应用与对象目录，属后端契约；新增后端应用要连同后端一起改，已有应用的页面片不碰 |
| `foundation/messages.ts` 的 `ui.groups` | 菜单分组与分组顺序由底座定义 |
| `foundation/routes.ts` 的 `legacyTarget` | 旧链接兼容（`/`、`/jobs`、`/account`），属底座 |
| `foundation/` 的组件与公共文案（`templates.tsx`、`ui.*`） | 底座组件改动，不是登记；需要时走底座改动 |
| `smoke/fixtures.ts` 的合成快照 | 公共冒烟夹具，按 `smoke/page-registry.ts` 自动覆盖全部应用；本片专用桩写在本片自己的 spec / fixture 里 |

## 7. 旧公共触点与新写法对照

迁移 #296 #297 #298 #303 #315 时出现过的公共触点，今后一律改在本模块文件里：

| 过去改的公共位置 | 现在的写法 |
|---|---|
| `annotations/index.ts` 追加 import 与展开 | `src/<模块>/annotations.ts` 导出 `notes` |
| `AppPages.tsx` 追加 lazy、`existing` 表、显式 `<Route>` | `pages.ts` 的 `apps[].page` / `legacy`、`routes[]` |
| `routes.ts` 的 `APP_ROUTES`、`messages.ts` 的 `ui.routes` | `pages.ts` 的 `apps[]`（`label` / `group` / `objectCode`） |
| `AppPages.tsx` 的 `isAccount` 一类免拦截特判 | `routes[].ungated` |
| `permission-snapshot.ts` 的菜单下一层（企业设置） | `apps[].children` |
| `routes.ts` 的 `appRoute`、`AppPages.tsx` 的 `/<id>/*`、`permission-snapshot.ts` 的菜单追加（#315 合同入口） | `pages.ts` 的 `entries[]` |
| 公共测试里直接 import `annotations/<模块>.ts` | 改从 `src/<模块>/annotations.ts` 读 `notes`，或断言 `annotationOwners[键]` |
