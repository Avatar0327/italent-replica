# F-120 本人命令结果查询路由与授权声明

依据：#303 FE-R1d-1 第 2 轮（03 按 DEC-464 口径答复 A）、AGENTS.md §10「幂等」「错误」、DEC-067（结果未知先按原命令 ID 回查）、DEC-385③（台账结果只走统一出口）；沿用 F-039 当前 Markdown 声明格式（参照 F-058 人员头像路由声明）。

## 背景与目标

员工首次提交本人调动，或经理首次提交 / 暂存他人调动时，服务端可能已保存而响应丢失。客户端手里只有原命令 ID（`Idempotency-Key`），没有服务端新生成的业务 ID：

- `GET /api/tenant/employment/businesses/:id` 需已知业务 ID；
- 审计接口要求 `admin.audit_log`，普通申请人没有；
- 重放原 POST 会进入写链路，不可作为回查。

本任务新增一个**只读**入口：发起人凭原命令 ID 取回该命令自身的结果摘要。前端据此把“处理中 / 结果待确认”的只读锁定升级为精确回查（接入另派，不在本 PR）。

## 授权契约

- 只返回**当前登录用户自己发起**的命令。查询条件固定为 `tenant_id = 当前租户`（RLS + 显式条件）且 `actor_user_id = 当前用户`；不是本人的、不存在的、其他租户的、结果未知的，一律 `404 NOT_FOUND`，不用 403，不泄露命令是否存在，也无法与“不存在”区分。
- 不新增授权项编码。F-039 声明为 `own`（谓词 `command.result.initiator`），只要求有效成员身份（租户中间件）；必需项表只登记“按发起人定位”的证据，授权项编码集合不变，`STANDARD_GRANT_*` 不动。
- 经理代他人发起的调动，命令发起人是经理：经理本人可查；被调动员工、租户管理员、同租户其他成员查同一命令 ID 都是 404。
- 只读：不写命令台账、不写审计、不写失败审计，不进 `runCommand` / `ledgerExit`。结果只来自台账已存的摘要字段，不返回业务正文，不返回他人信息（员工 ID、姓名、字段值都不在响应里）。
- 响应带 `Cache-Control: private, no-store`。

## 新路由

| 方法 | 路径 | 类型、操作、按钮 | 范围 | 字段 | 写足迹、其他 |
|---|---|---|---|---|---|
| GET | `/api/tenant/commands/:commandId/result` | own；命令发起人；无按钮 | 当前租户内 `actor_user_id = 当前用户` | commandId、status、commandType、businessType、businessId、revision、httpStatus、completedAt | 无；命令 ID 格式同 Idempotency-Key（`[A-Za-z0-9:_-]{1,100}`），不合法 400 VALIDATION_FAILED；no-store |

## 返回结构

```json
{
  "commandId": "…",
  "status": "succeeded",
  "commandType": "POST /api/tenant/self-service/transfer",
  "businessType": "transfer",
  "businessId": "<uuid>|null",
  "revision": 3,
  "httpStatus": 201,
  "completedAt": "2026-10-13T05:12:00.000Z"
}
```

| 字段 | 来源 | 缺失时 |
|---|---|---|
| status | 命令台账有记录 → `succeeded`（台账里响应码 ≥ 400 时为 `failed`）；失败命令审计有 `business_failed` 记录 → `failed` | — |
| commandType | 台账 `command_type`（“方法 路径模板”，路径里的 UUID 段换成 `:id`）；失败时由失败审计的 method / path 按同一函数生成 | null |
| businessType | 台账响应体的 `kind`（字符串） | null |
| businessId | 台账响应体的 `id`（须为 UUID） | null |
| revision | 台账响应体的 `revision`（整数） | null |
| httpStatus | 成功：台账 `response_status`；失败：失败审计写入时记录的 `http_status`（失败分类时取自错误本身的状态，含各模块自有错误码，如 `EMPLOYMENT_BEFORE_CYCLE_ENTRY` → 409），没有记录时回退公共 `ERROR_STATUS` | 找不到映射为 null，不默认 500 |
| completedAt | 台账 `created_at`；失败为失败审计 `occurred_at`（UTC ISO） | — |

失败命令没有业务产出，`businessType / businessId / revision` 恒为 null。

### 判定顺序与同键重试

1. 先按（租户，命令 ID）查台账，**不带发起人条件**：命中且 `actor_user_id` 是本人 → succeeded；命中但不是本人（含 `actor_user_id` 为空的历史 / 系统行）→ 404，**不再回退失败审计**（否则他人用同一命令 ID 碰撞得到的 `IDEMPOTENCY_CONFLICT` 失败审计会被当成本人失败）。本人台账成功结果始终优先于失败审计（先失败后原键重提成功）。
2. 台账没有 → 对本人该命令 ID 的失败审计取**最新时间的整组**判类别（`latestFailureGroup`，数据库里一次聚合、恒返回一行，不用固定条数窗口）：组内含存储不可写 / 结果未知 → 404（例：首次业务失败，原键重提时提交阶段连接中断记 unknown，回查不得返回旧的 failed）；整组都是 `business_failed` → failed，摘要取组内按 id 排序的第一条。同一时刻并列任意多条时，含未知类即按未知处理（保守）；未知早于最新一组确定失败，则以最新组为准。
3. 其余（台账无记录且无本人失败审计、别人的命令）→ 404。

## 结果未知与 404（前端必须遵守）

**404 不是“确定失败”。** 台账无记录意味着：命令从未到达服务端、仍在处理、已提交但本人不可见，或失败类别为存储不可写 / 结果未知（这两类失败审计刻意不返回，因为不是确定结论）。前端对 404 应继续保持“结果待确认”，可稍后重试回查，不得据此提示失败或重新发起写入。只有 `200 + status = failed` 才是确定失败；`200 + succeeded` 才是确定成功。

## 对写入链路的影响（唯一的写入侧改动）

台账原来不记发起人，无法判定“本人”。本任务给 `command_ledger` 增加两个**可空**列，只在 `runCommand` 已有的那条台账 `INSERT` 里多写两个值，不改变写入顺序、事务边界、幂等判定与 `ledgerExit` 出口：

| 列 | 值 | 说明 |
|---|---|---|
| `actor_user_id` | 当前用户；系统任务为空 | 无外键（与审计一致，台账只追加）；迁移 `0127_command_ledger_actor`（合并时按实际顺序由 `pnpm merge:main` 定号） |
| `command_type` | `commandTypeOf(method, path)` | 来自请求上下文；非 HTTP 入口（定时任务）为空 |

另给 `audit_command_failures` 增加可空列 `http_status`（迁移 `0128_command_failure_http_status`）：失败命令分类时（`classifyCommandFailure`）把错误本身携带的状态一并写入，错误不带状态时为空；不改变分类、审计事务与响应。

不考虑存量行（DEC-402）：迁移前写入的台账行两列为空，按本人查询为 404。`ledgerExit` / `CommandGuard` 不变；本路由不经过它们，因为只返回自身摘要、不重放响应正文，撤权后无新增披露（成员身份由租户中间件每次校验）。

## 与 F-110 / #303 前端的衔接

- 前端提交调动前生成命令 ID 并保存；响应丢失或超时后，对该 ID 调本接口：
  - `200 succeeded` → 用 `businessId` 打开业务详情（`GET /api/tenant/employment/businesses/:id`，仍按当前权限），解除“处理中”锁定；
  - `200 failed` → 确定失败，用 `httpStatus` 提示并允许显式修改后以**新**命令 ID 重提；
  - `404` / 网络错误 → 保持“结果待确认”，稍后再查。
- F-110 把“处理中 / 结果待确认”的只读锁定升级为精确回查时按上述三分支接入；接入前端另派，本 PR 不改 `apps/web`。

## 查看人 × 出口 × 字段

| 查看人 | 本人发起的命令 | 他人发起的命令 / 不存在 / 其他租户 |
|---|---|---|
| 有效成员（员工、经理、HR、管理员均相同） | 200，上表 8 个字段 | 404，与不存在无法区分 |
| 非成员 / 租户不可用 / 匿名 | 沿用租户中间件的 401 / 403 | 同左 |
| 被调动员工（经理代发起） | — | 404 |

## 未覆盖项

- **失败原因不返回**：响应没有 `errorCode` / 中文原因，只有 `httpStatus`；需要展示原因的另行扩展（契约变更）。
- **存储不可写 / 结果未知类失败**不返回（见上），也就没有对它们的“确定”结论。
- **非 HTTP 入口**（定时任务）写入的台账行没有发起人，不可按本人查询。
- **平台命令**（`platform_command_ledger`）不在本接口范围。
- **各业务写入口的响应体若没有 `id` / `revision` / `kind`**，对应字段为 null；本任务不为此改任何业务写入链路。
- 若失败审计按保留期被清理，此后失败命令回查退化为 404（台账成功记录不受影响）。
