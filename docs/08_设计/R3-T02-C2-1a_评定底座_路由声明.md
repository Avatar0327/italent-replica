# R3-T02 C2-1a：评定数据底座与活动发布

依据：实现拆分方案 §6 C2-1a、设计 §3.2～3.5 / §5.1 / §8、DEC-320②、DEC-442①。
本片新增 4 个端点，沿用 P0 授权项，无新增授权编码或授权版本变化。

| 方法与路径（前缀 `/api/tenant/evaluation`） | 对象与操作 | 按钮 | 数据范围与字段 |
|---|---|---|---|
| `POST /activities/:id/publish` | `TEvaluation.EvaluationActivity` update | `publish@list_row` | 活动所属组织 / 创建人范围；活动字段裁剪 |
| `POST /activities/:id/unpublish` | 同上 | `unpublish@list_row` | 同上，不要求活动内全员在操作人人员范围 |
| `GET /staff-evaluations` | `TEvaluation.StaffEvaluationData` view | 无 | 活动可管理 ∧ 人员范围，分页及计数前过滤；按字段权裁剪 |
| `GET /staff-evaluations/:id` | 同上 | 无 | 同一谓词；范围外与不存在均为 404；按字段权裁剪 |

写命令接受空 JSON 对象，要求 `If-Match` 和 `Idempotency-Key`；返回裁剪后的 `id / revision / status`。
复用 `commands.ts` 的 `ledgerExit` 与 `CommandGuard.before`：首次、重放及失败回查均检查当前对象权、
共享 `button(..., 'list_row')` 和活动范围，响应重新按当前字段权裁剪。无用户输入业务字段，不另要求编辑字段权。

发布只允许 draft → published，取消发布只允许 published → draft 且报名数为 0。非法状态返回 409
`ACTIVITY_STATE`，已有报名返回 409 `ACTIVITY_HAS_APPLICANTS`，版本不符返回 409 `REVISION_CONFLICT`。
发布复用 B5 `assertScopeUnique`，按“包含下级”有界展开组织范围，重复返回 409 `ACTIVITY_SCOPE_DUPLICATE`；
冲突名称仍按当前活动范围及名称字段权呈现。锁序沿用 B6：`coordinateActivityForms` → 活动行 → 类别范围锁。

列表支持 `page / pageSize / activityId`，activityId 格式错误返回 400，按该字段过滤需有字段查看权。
列表、详情及 P0 `activityPersonRule` 共用活动与人员的 SQL 谓词，历史审计按当前范围和字段权裁剪。

`terminateEvaluations(tx, ctx, ids, reason)` 是唯一终止内核：调用方负责活动 / 员工级准入，内核按 ID 锁评定行，
只处理 `inProgressSql / isInProgress` 定义的进行中记录，逐条写审计和 pending 通知，重复调用不增加记录。
审批 cancel 步骤留给 C2-3；C2-1b / C2-9 复用该内核。没有独立终止 HTTP 入口。

活动发布登记活动通知事件；终止按评定逐条登记员工通知，均只存 pending，不外发。
取消发布保留通知登记；无报名草稿删除时将登记纳入同事务删除快照，避免通知外键阻断既有删除流程。

F-039 登记位：`modules/evaluation/policy.ts`、`required/evaluation.ts`、冻结基准及发现探测。
核心门禁变化：无（未修改 `evidence-core.ts` / `core-digests.ts`）。
