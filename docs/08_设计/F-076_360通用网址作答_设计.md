## 0. 一页摘要

- **原站已知**（`25` §10.4，W-692）：
  - 邀请作答邮件有“电脑作答通用网址 / 电脑作答序列号 / 电脑作答密码”三个变量；
  - 短信示例写“在电脑上登录[电脑作答通用网址]，请用序列号[…]，密码[…]作答”。
  - **除此之外没有证据**（§1.2）。
- **定位**：通用网址是个人作答链接、站内待办之外的第三个作答入口，与前两者同一套作答页面与命令。
  answering.ts 已经把入口抽象成 `Entry.locate`，本任务新增 `sessionEntry`，作答处理函数不改。
- **凭据**：按“评价者 × 活动”一组（暂定，待 E2），挂在 `survey360_links` 作答链接行上，与个人链接同发、同换、同作废。
  - 序列号只存 HMAC（库外密钥，按版本）；密码只存 `scrypt(HMAC(密钥, 密码), 盐)`。
  - **异步发放**：启用 / 重发命令只把链接行标为“凭据待发放”，由维护任务分批在事务外做 KDF，写入摘要，
    再把明文放进邀请 outbox 的加密封装 `sealed`（§2.5）。命令事务里不做 KDF。
  - **密钥版本**：版本 ↔ 密钥映射；登录成功提交后迁移到当前版本。凭据行记**实际用过的版本集合**，
    会话每次检查都读所属凭据的当前集合。泄露处置由配置标记立即生效，凡集合含该版本的凭据与会话都拒绝（DEC-379），
    运维命令只负责持久化清理（§2.4）。
- **换取**：`POST /api/survey360/portal/login` 用序列号 + 密码换一个 8 小时作答会话（令牌只存摘要，经请求头传递）。
  登录与每次会话使用都要求“该评价者在该活动仍有有效评价关系”（§4.2）。
- **防暴力（v3，§3）**：
  - 会拒绝请求的维度都含请求方 IP，攻击者不能跨出口封禁别人；**同一出口（NAT）后的其他人会受影响**，
    Q6 已定方案 C（DEC-379③）：只限频、不设 IP 级认证锁，残余风险已由用户接受；
  - 不设序列号全局锁和租户锁，租户维度只告警；
  - 检查、预扣、拒绝原子完成；每种限频行的窗口与锁定语义相同，崩溃留下的预扣最多影响到窗口结束；
  - 取锁顺序固定为 IP 行 → 序列号 × IP 行 → 链接行；
  - 两类 429（`REQUEST_RATE_LIMITED` / `AUTH_LOCKED`），都带整数秒 `Retry-After`，锁定时给出解锁时间（AGENTS §10，#194）；
  - 资源保护：成功、失败都计入的 IP 请求预算；单凭据每小时成功上限；KDF 并发“全局 + 单租户”双限；可信代理契约。
- **F-039**：新增 7 条公开路由（声明端点 main 基数 + 7，当前为 514 → 521）；登录 / 登出不进命令台账（DEC-377③，§4.8）。
- **拆分**：PR-0 契约 → PR-1 凭据（异步发放、密钥、sealed）→ PR-2a 登录与防暴力 → PR-2b 会话入口与路由声明，各 1500 行内。
- **不做**：模板库、变量渲染、短信与发送、旧邀请抑制、sealed 清理（F-077，§2.6 给交接接口与约束，DEC-377⑤）；360 前端页面；确认链接的通用网址入口（E9）；
  现有个人链接 / 待办入口的“最后一条关系移除后仍可读活动信息”问题（同类，已登记 F-084，§11）。

## 2. 凭据模型

### 2.1 粒度与生命周期
- **粒度**：评价者 × 活动一组（暂定）。依据是 K2 + K3：一条短信给一组凭据，一个评价者在一个活动只有一条短信。E2 尚未取证。
  若 E2 证实为“每评价关系一组”，§6 唯一约束、§2.5 发放点、§4.2 会话定位都要重新设计，不只是改索引。
  所以 Q2 是 PR-0 的前置决策（§8）。
- **挂载位置**：`survey360_links` 中 `kind = 'answer'` 的行加凭据列（§6）。理由：
  - 凭据与个人链接同发、同换、同作废（Q4 推荐 ①），“同一时刻一组有效凭据”由现有部分唯一索引 `survey360_links_answer` 保证；
  - 会话外键指向链接行，链接作废后会话随之失效。
  - Q4 若选 ②“重发不换凭据”，凭据要搬到独立表，差异见附录 A。Q4 也是 PR-0 的前置。
- **凭据状态** `credential_state`：`none`（F-076 前的存量行、确认链接）/ `pending`（待发放）/ `issued` / `retired`（所在密钥版本退役）。
  只有 `issued` 的行能登录；摘要列非空当且仅当 `issued`。
- **生命周期**：

```
创建 ── 启用活动（issueAnswerLinks）、启用中新增评价者（addRelation → ensureAnswerLink）、重发邮件邀请（reissueAnswerLink）
  │       链接行 credential_state = pending；邀请 outbox state = awaiting_credential，sealed 只含个人链接令牌
  ├─ 发放：维护任务分批生成、做 KDF、写摘要（issued），把序列号与密码加进 sealed，outbox 转为 pending（§2.5）
  ├─ 使用：换取会话（§3）；成功时若密钥版本不是当前版本，顺带迁移（§2.4）
  ├─ 轮换：重发邮件邀请 → 旧行 revoked（凭据、会话一并失效），旧邀请由 F-077 按 linkId 抑制（§2.6）；新行重走“创建”
  ├─ 退役：所在密钥版本退役 → retired，摘要清空；泄露处置部署即拒绝曾暴露于该版本的凭据与会话，批处理再落库（§2.4）
  └─ 失效：活动删除 → 不改行，登录与会话按 §4.2 失败；评价者最后一条有效评价关系被移除（DEC-401⑧）→ 凭据作废（同重发：
     该评价者的作答链接作废，凭据与全部会话随之失效，提示同凭据错误）；重新加回关系时发新链接与新凭据（旧凭据不恢复）
```

- **存量链接**（DEC-377①）：F-076 上线前已发放的链接行为 `none`，**不自动补发**；管理员手动“重发邮件邀请”后才有凭据。

### 2.2 生成（熵）
- 随机源：`crypto.randomInt`（CSPRNG）逐位取字符。
- **字符集与长度待 E3**。取证不到时的复刻备选（Q3）：
  - 字母表 31 个字符 `23456789ABCDEFGHJKMNPQRSTUVWXYZ`（去掉易混字符）；
  - 输入不区分大小写；规范化 = 去掉首尾空白、空格与连字符后转大写，再限长 64；
  - 序列号 10 位（约 49.5 位熵），密码 8 位（约 39.6 位熵）。
- 若 E3 证实原站密码更短（如 6 位数字，约 20 位熵），建议复刻保持上面的长度，按有意收紧登记差异。
- 序列号在租户内按当前版本的 `serial_lookup` 唯一（含已作废、已退役的行，不复用）。冲突时由维护任务下一轮换一个值重试（§2.5）。

### 2.3 存储与 KDF 参数
| 值 | 存什么 | 算法 |
|---|---|---|
| 序列号 | `serial_lookup`（hex） | `HMAC-SHA256(K_v, 'survey360:serial:' ‖ 规范化序列号)`，K_v = 第 v 版凭据密钥 |
| 密码 | `password_hash`（`scrypt$<N>$<r>$<p>$<salt>$<hash>`，参数随行存储） | `scrypt(HMAC-SHA256(K_v, 'survey360:password:' ‖ 规范化密码), 16 字节随机盐, N, r, p, 32 字节)` |
| 密钥版本 | `credential_key_version`（smallint） | — |

- **scrypt 参数（Q3 一并定）**：推荐 `N=2^14, r=8, p=1`，参数写进摘要串，以后可在登录成功时升级重算。成本依据：
  - 本机微基准约 40 ms/次（审查实测）。与 OWASP 对人类口令的推荐（同 N / r 时 p=5）相比，单次成本约为其 1/5；
  - 这里的密码是机器生成的 39.6 位随机串，不是可用字典猜的人类口令；
  - 离线攻击的前提是**库与密钥同时泄露**。按 40 ms/次，穷举期望约 2^38.6 × 0.04 s ≈ 520 核·年 / 条。
    专用硬件能把单次成本降多少没有实测，若按 1/1000 粗估，约 0.5 核·年 / 条。以上都是**工程估算**；
  - 凭据**没有强制有效期**：链接行未作废就一直可登录，活动停用后也是（Q11）。所以不能拿“活动期短”当保护，
    能依靠的是泄露处置会立即作废整个版本（§2.4，DEC-379）；
  - p=5 会让发放与登录的 CPU 成本乘以 5：5 万人的活动约 2.8 核·小时，登录并发闸也要相应收紧。
  - 结论：机器生成的 39.6 位随机密码配合库外密钥，p=1 是可接受的工程取舍；这是推荐，不是证明。
- **低熵格式的风险**（Q3 若照原站选了短密码）：只靠提高 p 不够。
  - 例：6 位数字（约 20 位熵）、KDF 约 200 ms 时，单租户 2 个名额约每秒校验 10 次；
  - 已知某个序列号的攻击者轮换约 1800 个 IPv6 /64（每个每 15 分钟 5 次），就能维持这个速率，平均约 14 小时猜中（审查测算）。
  - 所以低熵格式必须同时加长或另加控制（例如序列号级的人工解锁保护），并重审 §3.4、§3.5。
- **密钥存放**：库外 Secret（§2.4 配置）；生产缺失或长度不足即启动失败；test / development 缺省时生成进程内随机值。
- `node:crypto` 只在 `apps/api` 用；领域包 `packages/domain/src/survey360/credential.ts` 只放字母表、长度、规范化、格式校验等纯函数。
- 比较用 `timingSafeEqual`；scrypt 用异步版本（线程池）。

### 2.4 密钥版本、轮换、退役与泄露处置（P2-3、R2-P2-4）
**配置**（只放 Secret 管理，`.env.example` 只写键名）：

| 键 | 值 | 约束 |
|---|---|---|
| `SURVEY360_CREDENTIAL_KEYS` | `版本:base64密钥` 逗号分隔，如 `3:…,2:…` | 版本为正整数，至多 4 个；每个密钥 32 字节 |
| `SURVEY360_CREDENTIAL_KEY_CURRENT` | 当前版本号 | 必须在 KEYS 里，且不小于已记录的上一个当前版本（`rotate` 命令登记，版本只增不减） |
| `SURVEY360_CREDENTIAL_KEYS_RETIRED` | 已退役版本号列表 | 不得与 KEYS 重叠 |
| `SURVEY360_CREDENTIAL_KEYS_COMPROMISED` | 已判定泄露的版本号列表 | 必须是 RETIRED 的子集；**部署即生效**，不依赖批处理（R2-P2-4） |
| `SURVEY360_THROTTLE_KEY` | 限频键用的独立密钥 | 不随凭据密钥轮换，轮换不会清空限频计数 |

**暴露模型：实际用过的版本集合**（R3-P2-1、R3-P2-2；§6）：
- 凭据行记 `credential_key_version`（当前摘要所用版本）和 `credential_key_versions`（smallint 数组：**这条凭据实际用过的
  全部版本**）。发放时为 `{CURRENT}`；每次迁移把新版本**并入**集合，不删旧值；退役清空摘要时集合保留。
- **曾暴露于 v** ⇔ `v ∈ credential_key_versions`。不用版本区间推断：k1 直接迁移到 k3、从未用过 k2 的凭据，k2 泄露时不算暴露。
  已迁移的凭据明文没变：拿到旧库快照和旧版密钥的人可以离线还原明文，所以它对用过的每个旧版本都算暴露。
- **会话不存版本快照**。会话属于哪条凭据由 `link_id` 决定；每次检查会话时都读该链接行的当前集合
  （`credential_key_versions && COMPROMISED` 即拒绝）。这样凭据在会话签发之后才迁移、才暴露，
  会话也会被拒绝；迁移那次请求签发的会话、迁移前已有的会话，结论都一样。

**登录查找**：对 KEYS 中每个版本各算一次 `serial_lookup`（至多 4 次 HMAC），一次查询
`WHERE (credential_key_version, serial_lookup) IN (…)`。版本在 KEYS 里，旧版本凭据就能登录。

**登录时迁移**：放在 T2 成功提交**之后**（§3.5 第 5 步），只有登录确已成功才做，失败分支不会多出一次 KDF。
- 在事务外按 CURRENT 重算两项摘要（第二次 KDF）；
- 用短事务按版本 CAS 写回：`credential_key_version = CURRENT`、`credential_key_versions = 并入 CURRENT`，
  条件 `WHERE id = ? AND credential_key_version = 旧版本 AND credential_state = 'issued' AND NOT revoked`；
- CAS 不成立（期间被重发、退役）或进程崩溃，都只是这次没迁移，下次登录再迁；登录结果不受影响。

**轮换**（例：k2 → k3）：
1. 部署配置：KEYS 加入 k3，CURRENT = 3，k2 保留。新发放用 k3；k2 凭据照常登录，登录时迁移。
2. 运行 `survey360-credentials rotate --to 3`：校验配置（3 在 KEYS 里、大于上一个当前版本），为每个租户写一条 `key_rotated` 安全事件。
3. 宽限期：k2 至少保留到“用 k2 发放的凭据所在活动都已停用”或 90 天，以先到者为准。
   `survey360-credentials stats --version 2` 按租户 / 活动列出仍以 k2 存摘要的数量。

**计划退役**（只进 RETIRED）：
1. 部署配置：把 2 从 KEYS 移到 RETIRED。此后仍以 k2 存摘要的凭据统一 401（查找时算不出 k2 的 `serial_lookup`）。
2. **已签发的会话照常可用到过期**：计划退役不是安全事件，会话是用当时有效的凭据换来的。
3. 运行 `survey360-credentials retire --version 2`（§2.4.1），把这些凭据标为 `retired`、清空摘要。
4. 受影响的评价者由管理员手动“重发邮件邀请”（DEC-377① 不自动补发；`retire` 同样输出手动重发清单）。

**泄露处置**（RETIRED + COMPROMISED；R2-P2-4；DEC-379 Q14 已定：同一 pepper 派生的凭据一律视为暴露，相关会话立即撤销，只生成手动重发清单、不自动群发）：
1. 立即部署配置：新增 k3 为 CURRENT，2 同时进入 RETIRED 与 COMPROMISED，不经宽限期。
2. **部署即生效，不等批处理**：
   - 登录：找到的凭据若 `credential_key_versions` 与 COMPROMISED 有交集 → 按失败处理（同一个 401），包括已经迁移到 k3 的凭据；
   - 会话：`requireSession`（事务外预检）与 `sessionLink`（事务内定位）都连接会话所属链接行，
     读它当前的 `credential_key_versions`，与 COMPROMISED 有交集即拒绝（401 / 404）。只依赖配置和链接行的现值，不需要先跑批处理。
3. 运行 `survey360-credentials retire --version 2 --compromised`：把所有曾暴露于 k2 的凭据（不论当前是 `issued` 还是
   已被计划退役为 `retired`）标为 `retired`，并作废这些链接上的**全部**会话。它只负责落库清理，中断或未运行都不影响第 2 步的拒绝。
4. 个人链接令牌（SHA-256，不用凭据密钥）、待办不受影响，评价者可先用这两条路作答。
5. 命令输出**手动重发清单**（租户 / 活动 / 受影响评价者的链接行 ID 与人数，不含任何凭据），运维交各租户管理员手动重发；不自动群发（DEC-379、DEC-377①）。
6. COMPROMISED 列表只增不减；该版本的行与会话全部清理完后仍保留在列表里（成本只是一次整数比较）。

#### 2.4.1 退役命令 `retire`（`apps/api/src/ops/`，平台运维命令行）
- 前置检查：版本不在 KEYS 里且在 RETIRED 里；带 `--compromised` 时还必须在 COMPROMISED 里。否则拒绝执行。
- **持久进度**：每个租户一行 `survey360_key_retire_runs`（§6）：run_id、版本、是否泄露、状态、游标（已处理到的链接行 ID）、
  已作废凭据数、已作废会话数、尝试次数、错误、起止时间。`retire --resume <run_id>` 从游标续跑。
- 逐租户、按链接行 ID 升序每批 500 行，每批一个事务，在同一事务内：
  - **计划退役**：选 `credential_key_version = v AND credential_state = 'issued'` 的行 → `credential_state = 'retired'`、
    摘要置空（`credential_key_version` 与集合保留）；不动会话；
  - **泄露处置**：选 `v = ANY(credential_key_versions)` 的行，**不论 `credential_state`**：
    - 其中仍为 `issued` 的 → `retired`、摘要置空；
    - 这些链接上所有 `revoked_at IS NULL` 的会话 → `revoked_at = now`。已被计划退役的凭据，其会话也在这里清理；
  - 推进游标、累加计数，写一条 `credential_revoked` 安全事件（本批凭据数、会话数、run_id）。
- 租户完成时写 `key_retired` 事件（版本、是否泄露、两个总数）。条件只挑仍需处理的行与未作废的会话，重跑幂等。
- 手动重发清单 = 本次处理到的链接（泄露处置时含原本已 `retired` 的）中、链接未作废且评价者仍有有效关系的那些。

### 2.5 异步发放（P3：批量 KDF 不进命令事务）
- DEC-379 已定 Q15：采用异步发放与等待状态，不提供长事务内同步 KDF。
- **`issue()` 是作答与确认邀请共用的写入口**，按 `kind` 分支：
  - `kind = 'answer'` 且开关 `SURVEY360_PORTAL_CREDENTIALS` 打开：链接行 `credential_state = 'pending'`；邀请 outbox
    `state = 'awaiting_credential'`，`sealed` 只含个人链接令牌；
  - `kind = 'confirm'`，或开关关闭：链接行 `credential_state = 'none'`；outbox 直接 `pending`，`sealed` 只含令牌。
    行为与现在相同，只是令牌改为加密（AC-06、AC-07）；
  - 两种都在 `payload` 里带 `linkId`；命令事务内都不做 KDF。启用命令的耗时与现在相同，现有逐人持活动锁的循环不变。
- **重发**（`reissueAnswerLink`）：旧行作废、新行按上面的分支创建；每个评价者写一条 `credential_reissued` 事件。
- **维护任务** `survey360-credential-maintenance`（DEC-052：可重复执行、失败记次数与原因、可重试；按租户执行）：
  1. 认领（短事务）：`SELECT … WHERE credential_state = 'pending' AND NOT revoked AND (claimed_at IS NULL OR claimed_at < now - 5 分钟)
     ORDER BY created_at LIMIT 100 FOR UPDATE SKIP LOCKED`，写 `credential_claimed_at = now`，提交；
  2. 生成与 KDF（事务外）：每行生成序列号与密码并做 KDF，任务自身 KDF 并发 ≤ 2（与登录的并发闸分开计数，登录优先）；
  3. 写回（每行一个短事务）：`UPDATE … SET 摘要, credential_state = 'issued', credential_key_version = CURRENT,
     credential_key_versions = ARRAY[CURRENT]
     WHERE id = ? AND credential_state = 'pending' AND NOT revoked AND credential_claimed_at = 认领时间`（CAS）。
     然后解封该链接的邀请 outbox，加入序列号与密码，换新 IV 重新封装，`state` 改为 `pending`；写 `credential_issued` 事件（同一事务）。
     - CAS 失败（期间被重发作废或被别的工作进程重领）→ 丢弃本次明文，不写；
     - 序列号唯一冲突 → `credential_attempts + 1`、记 `credential_error`，留待下一轮；
     - 连续 5 次失败 → `credential_state` 保持 `pending`，写结构化运行日志提醒运维（不自动放弃）。
  4. 进程在第 2、3 步之间崩溃：明文只在内存里，库里仍是 `pending`、邀请还没发，下次重领生成新值即可，不会有两组凭据。
- **吞吐**：每进程 2 路 KDF × 约 25 次/秒 ≈ 50 次/秒，5 万人约 17 分钟发完。可由环境变量调大，但不得超过 CPU 核数的一半。
- 邀请 outbox 在 `awaiting_credential` 期间不发送；进程控制里的邮件状态按“待发送”显示（progress.ts 读取 `state` 时
  把 `awaiting_credential` 归入 pending）。
- **等待状态**：`awaiting_credential` 的邀请在进程控制里显示“待发送”。若某行超过 1 小时仍是 `pending`，写运行日志告警
  （维护任务停摆或持续失败）。
- 同一维护任务还负责：清理过期会话与限频行（§3.2、§4.1），以及把已到期但无人清理的锁定记为解锁事件（§5.4）。
  outbox 的 `sealed` 清理不在这里，归 F-077（§2.6）。

### 2.6 明文边界、outbox 加密与交接 F-077（DEC-377②⑤）
明文只允许出现在两处：维护任务生成那一刻的内存里，以及发送方（F-077）渲染那一刻。

**outbox 秘密字段加密（F-076 实现）**
| 项 | 规则 |
|---|---|
| 范围 | 邀请 outbox 里所有秘密字段：个人链接令牌、序列号、密码。现有明文 `payload.token` 一并迁入（DEC-377② 的“秘密字段”），`AC-360-B-support` 的 outbox 读取改为解封 |
| 算法 | `AES-256-GCM`，128 位认证标签 |
| IV | 每次封装（包括维护任务的重新封装）都用 CSPRNG 生成新的 12 字节随机 IV；同一密钥下不复用 IV。每个密钥的封装次数远低于随机 IV 的安全上限（2^32），超过前必须换 `kid` |
| AAD | `tenantId:outboxId:eventType`（outboxId 由应用在插入前生成），密文挪到别的行或别的租户无法解封 |
| 格式 | `payload.sealed = { v: 1, kid, iv, tag, data }`（base64），明文为 JSON `{ token, serial?, password? }` |
| 密钥配置 | `SURVEY360_OUTBOX_KEYS`（`kid:base64` 列表，每个 32 字节）+ `SURVEY360_OUTBOX_KEY_CURRENT`；新封装一律用 CURRENT；生产缺失即启动失败 |
| 密钥保留条件 | 某 `kid` 只要还有非终态 outbox 行（`awaiting_credential` / `pending` / `unknown`）引用它，就不得从配置移除。终态行的 `sealed` 由 F-077 清空后，该 `kid` 方可退役；在此之前只能把它从 CURRENT 换下（仍保留解封能力）。泄露处置：立即换 CURRENT，并由 F-077 抑制引用旧 `kid` 的未发邮件 |
| 维护任务的重新封装 | 解封 `{token}` → 加入 `serial`、`password` → 新 IV、CURRENT `kid` 封装 → `state` 由 `awaiting_credential` 改为 `pending` |

**交给 F-077 的接口与约束（F-076 不实现、不验收）**
| 主题 | F-076 提供 | F-077 须做到 |
|---|---|---|
| 可发送的行 | `state = 'pending'` 的邀请行才完整；`awaiting_credential` 不得发送 | 只取 `pending`；按 `kid` 解封；渲染后不落明文 |
| 旧消息抑制 | 每条邀请 `payload` 带 `linkId`（本次新增），重发后旧链接行 `revoked = true` | 发送前按 `linkId` 复核链接行未作废，否则置 `superseded` 并清空 `sealed`，不发送 |
| `sealed` 清理 | — | 进入终态（`sent` / 最终 `failed` / `superseded` / 过期）时清空 `sealed`；`unknown` 保留到确认终态或过期；过期期限由 F-077 定（建议 7 天） |
| 重试 | 密文可重复解封 | `pending` 期间可重试；不得把明文写入重试队列或日志 |
| `kid` 退役 | 上表的保留条件 | 提供“某 `kid` 是否仍被非终态行引用”的检查，供运维退役密钥前执行 |
| 模板变量 | 通用网址 = `PUBLIC_BASE_URL` + 前端路由 + 租户标识（非秘密）；序列号、密码只在 `sealed` | 按变量名渲染（邮件 / 短信） |

**其他位置**
| 位置 | 处理 |
|---|---|
| 审计 | 所在命令的审计 `after` 只记人数（如 `credentialPending: n`），不记明文与摘要 |
| 命令台账 | 登录 / 登出不走 `runCommand`（§4.8）；启用、重发的回执不含秘密 |
| 错误响应 / 日志 | 登录处理函数不把请求体放进任何错误对象；zod 4 默认不带 `input`（已核对 too_big / unrecognized_keys），不得开启 `reportInput`；部署手册要求代理不记录请求体与 `x-survey360-*` 头 |
| 限频表 / 安全事件 | 只存 HMAC（`SURVEY360_THROTTLE_KEY`）或其前 8 位，不存序列号或 IP 原值 |

### 2.7 轮换、作废与重发语义
| 操作 | 凭据 | 会话 | 待定 |
|---|---|---|---|
| 启用 / 启用中加评价者 | 已有有效链接行则不新建（`ensureAnswerLink`）；否则新行 `pending` | — | E5 |
| 重发邮件邀请 | 旧行作废，新行 `pending`；旧邀请由 F-077 发送前按 `linkId` 抑制 | 旧行上的会话全部失效 | E5 / Q4 |
| 发送 / 重发 / 取消站内待办 | 不变（K4、K5） | 不变 | — |
| 清空作答（重新作答） | 不变（E3-R21 “用原链接重答”） | 不变 | — |
| 停用活动 | 不变 | 仍可登录（DEC-401⑦）：已全部完成者进完成页；未完成者不能作答，明确提示活动已停用；写入 409 `ACTIVITY_NOT_OPEN` | DEC-401⑦、⑧ |
| 删除活动 | 不改行 | 登录 401；会话 401（§4.2） | E8 |
| 移除最后一条有效评价关系（DEC-401⑧） | 作废该评价者的作答链接（凭据随之失效）；重新加回关系发新链接与新凭据 | 登录 401（提示同凭据错误）；已有会话 401，加回关系后也不恢复 | DEC-401⑧ |
| 计划退役 / 泄露处置 | `retired`，摘要清空（泄露处置含曾暴露于该版本、已迁移的凭据） | 计划退役不动会话；泄露处置时配置部署即拒绝，批处理再作废 | DEC-379 |
| 管理员查看 / 导出凭据 | **不能**（DEC-377①，只存摘要）；忘记时“重发邮件邀请”生成新凭据 | — | E4 只作差异登记 |

## 3. 防暴力（v3 / v4：R2-P2-1～3；Q6 = 方案 C，DEC-379③）

### 3.1 原则
1. **锁定范围尽量窄，并且要有恢复办法**（OWASP account lockout）。会拒绝请求的维度都含请求方 IP，所以攻击者不能跨出口
   封禁别人；但**与攻击者共用同一出口 IP（NAT）的其他评价者会受影响**。这一点不能完全避免，只能缩小影响面、写明恢复办法，
   用户已按 Q6 接受方案 C 及其残余风险（DEC-379③，§3.4）。
2. **检查、预扣、拒绝原子完成**：一个请求要么所有维度都放行、一起预扣，要么在第一个拒绝的维度停下，不扣任何维度、
   不新建任何限频行。
3. **窗口与锁定语义对每种行都相同**（§3.3）：过期窗口在内存里重置，锁定到期视为解锁，崩溃留下的预扣最多影响到窗口结束。
4. **固定取锁顺序**：IP 行 → 序列号 × IP 行 → 链接行，T1 与 T2 的成功、失败分支都按这个顺序（§3.5）。
5. **两类 429 分开**（AGENTS §10，#194）：频率限制 `REQUEST_RATE_LIMITED` 与认证锁定 `AUTH_LOCKED`，都带整数秒 `Retry-After`（§3.7）。
6. **资源与认证分开**：防猜测靠失败计数；防耗尽 CPU 靠“成功、失败都计入”的请求预算与并发双限，再由代理限速兜底。

### 3.2 维度与阈值（方案 C，DEC-379③）
| # | 维度 | 键 | 窗口 | 阈值 | 超限 | 作用 |
|---|---|---|---|---|---|---|
| D1 | IP 请求频率 | `HMAC(TK, 'ip:' ‖ IP)` | 15 分钟固定窗口 | 3000 次（成功、失败都计） | 频率限制 `REQUEST_RATE_LIMITED`，到窗口结束 | 资源（P2-2） |
| D3 | 序列号 × IP 失败 | `HMAC(TK, 'pair:' ‖ 规范化序列号 ‖ IP)` | 15 分钟固定窗口 | 5 次失败 | 认证锁定 `AUTH_LOCKED` 15 分钟 | 防猜单个序列号的密码 |
| D4 | 单凭据成功 | 链接行 ID（密码正确后才知道） | 1 小时滑动 | 20 次成功 | 频率限制，不签发会话 | 资源；不构成存在性探针 |
| D5 | 租户失败 | 常量键 | 15 分钟 | 300 次失败 | **只告警**（结构化运行日志），不拒绝 | 发现分布式撒网 |
| G | KDF 并发 | 进程内 | — | 全局 4 / 单租户 2 | 503，不计任何维度 | 资源（参照 F-060 `admitted` 双限） |

- TK = `SURVEY360_THROTTLE_KEY`；IP 按 §3.6 从可信代理取得并规范化（IPv6 按 /64 聚合）。
- 方案 C 不设 v2 的 D2（IP 失败锁），编号保留以便对照；IP 行只计请求数（D1），不计失败数。
- **D1 为什么是 3000**：单 IP 平均至多约 3.3 次 KDF/秒，每个租户的 KDF 又受 G 的 2 个名额约束，打不满全局；
  一个几百人共用出口的单位集中登录（含少量重试），也在预算之内。
- 行数有界：D3 行只在请求被放行时才建，每个 IP 每窗口至多 3000 行（受 D1 约束）；D1 每个 IP 一行；
  维护任务删除空闲超过 24 小时且未锁定的行。
- 阈值是常量（带出处注释），不做租户配置。原站的锁定表现与文案待 Q-M0-167。

### 3.3 窗口与锁定的统一语义（R2-P2-2）
对任一限频行（IP / 序列号 × IP / 租户），T1 与 T2 读到它时按以下顺序判断（W = 窗口长度，阈值见 §3.2）：

| 状态 | 判定 | 处理 |
|---|---|---|
| 锁定中 | `locked_until > now` | 拒绝 `AUTH_LOCKED`，`Retry-After = ceil(locked_until − now)`，`unlockAt = locked_until`；不写任何行 |
| 锁定已到期 | `locked_until ≤ now`（非空） | 视为已解锁：本事务内写 `unlock` 安全事件（解锁时间 = 原 `locked_until`），**并立即把该行 `locked_until` 置空**（这是清理，不是计数；即使本请求随后被其他维度拒绝也照做，所以同一把锁只记一次 `unlock`），再按“窗口过期”处理 |
| 窗口过期 | `window_started_at + W ≤ now` | 在内存里 `requests = failures = 0`、`window_started_at = now` |
| 窗口内已达阈值但未锁 | `failures ≥ 阈值` 且无锁（例如第 5 次预扣提交后、T2 前崩溃） | 视同锁到窗口结束：`AUTH_LOCKED`，`unlockAt = window_started_at + W`；不写库。窗口一过就按上一行重置 |
| 窗口内、未达阈值 | 其余情况 | 放行 |

- **放行后写回**：把内存里（可能已重置）的值连同预扣一起写回：`window_started_at`（重置过就用新值）、`requests + 1`、`failures + 1`、
  `locked_until = NULL`（若原值已到期）。写回带的 `window_started_at` 就是本次的**预扣标识**。
- 结果：
  - 第 5 次预扣后崩溃：窗口内返回 429，`unlockAt` = 窗口结束；超过窗口后用正确密码可以登录（AC-15）；
  - 旧窗口留下 4 次失败、新窗口第 1 次失败：重置后从 1 计，不锁（AC-16）。
- **锁定**只在 T2 失败分支设置：失败确认后若 `failures ≥ 阈值`（且行的 `window_started_at` 仍等于预扣标识），置
  `locked_until = now + 15 分钟`、`failures = 0`、`window_started_at = now`，写 `lock` 事件。
  若该行此前有一个已到期但未清的 `locked_until`，先按上表写 `unlock`。

### 3.4 共享出口（NAT）的影响与 Q6 决定（DEC-379③：方案 C）
所有方案的共同前提：会拒绝请求的维度都含 IP，攻击者不能跨出口影响别人；**同一出口后的其他评价者会受影响**，程度因方案而异。
- **“同一出口”的口径**：按 §3.6 规范化后落在同一个限频桶，即同一个 IPv4 地址，或同一个 IPv6 /64。
  同一 /64 下不同地址的人也算同一出口。
- 代理的每 IP 限速（§3.6）对同一出口的人是**跨租户**共享的额度，所以代理阈值要高于 D1，只用来挡洪泛。
- 下表的“上限”都按 **15 分钟固定窗口**计。窗口交界处，攻击者可以在上一窗口末尾和下一窗口开头各用满一次额度，
  所以短时间内的实际上限最多是表中数值的 2 倍。

| 方案 | 会拒绝请求的维度 | 单 IP 每 15 分钟的猜测上限 | 同出口其他评价者的可用性 | 恢复办法 | 实现成本 |
|---|---|---|---|---|---|
| **A 硬锁**（v2） | D1 600 次频率；D2 IP 失败 100 次锁 15 分钟；D3 | 随机序列号 100 次；已知序列号 5 次 | 攻击者约 0.11 次/秒（每 15 分钟 100 次失败）即可**持续锁住整个出口**；D1 600 次也是共享额度 | 攻击停止后最多 15 分钟；个人链接 / 待办；运维解锁命令（按 IP 算键清行） | 低 |
| **B 分桶** | D1 3000 次频率；D2 按“IP + 序列号输入前 2 位”分桶、失败 100 次锁该桶；D3 | 3000 次 | 一个 IP 每窗口至多锁 30 个桶（3000 / 100），共 961 个桶。攻击者**盲选**桶时，某个同出口评价者受影响的概率约 3%；若攻击者知道目标序列号的前 2 位，可以直接锁住目标所在的桶（定向） | 同 A；重发换序列号后多半落到另一个桶 | 中 |
| **C 只限频、不锁 IP（推荐）** | D1 3000 次频率；D3 | 3000 次（每次猜中有效序列号的概率见 §3.5）；已知序列号 5 次 | **没有 IP 级锁**。攻击者在一个窗口内用满 3000 次（不必均匀：例如前 10 分钟每秒 5 次后停止），同出口其他人在该窗口剩余时间（此例约 5 分钟）收到频率限制；3.3 次/秒只是“整个窗口都被占满”所需的平均速率。知道某人序列号且同出口时，5 次错误可锁住该人的序列号 × IP | 见下方“恢复办法的前提” | 低 |
| **D 验证码** | 超过阈值的 IP 要求人机验证，而不是锁定 | 取决于验证码的破解成本 | 同出口的人做验证后可继续 | 无需等待 | 高：要引入验证码服务（不在技术栈内），原站有无验证码待 Q-M0-161 |

- 上表是决策记录。**用户已选 C**（DEC-379③），A / B / D 不实现。选 C 的理由：
  - 猜测主要靠 D3 与熵约束（§3.5），D2 对安全的增益很小，却是共享出口上最便宜的拒绝服务杠杆；
  - C 把“让整个出口在整窗口内都不可用”的成本，从 A 的每窗口 100 次失败提高到每窗口 3000 次请求；
    影响限于攻击发生的窗口，窗口结束即恢复；
  - 针对个人的 D3 锁有恢复办法（见下）。
- **恢复办法的前提**：
  - **频率限制**：等 `Retry-After`（≤ 本窗口剩余时间）。
  - **管理员重发**：得到的新序列号对应新的 D3 键，但要等维护任务异步发放新凭据、F-077 把邀请送达后才能用（通常几分钟，
    取决于维护任务间隔与发送状况），而且同出口的 D1 与代理额度当时没有被耗尽。
  - **个人链接**：评价者要已收到邀请邮件里的个人链接（与通用网址同一封邀请，F-077 送达后才有）。
  - **站内待办**：只适用于挂接了组织员工且有有效账号的评价者（DEC-128）；外部评价者没有这条路。
- **用户已接受的残余风险**（DEC-379③，如实写入）：
  1. 与攻击者同一网络出口（按 §3.6 规范化后的桶：同一 IPv4 地址，或同一 IPv6 /64）的人会被限频。攻击者在一个窗口内
     用满 3000 次请求即可，攻击停止后限频仍可能持续到本窗口结束（数分钟）；每个窗口都这样做就能一直压住。
     代理的每 IP 额度跨租户共享，同样受影响；
  2. 知道某评价者序列号、且与其同出口的人，能把该评价者的通用网址登录（序列号 × IP）锁 15 分钟，每 15 分钟只需 5 次请求；
  3. 恢复是有条件的：管理员重发要等异步生成的新凭据送达，且当时出口额度未被耗尽；改用个人链接 / 待办，须已经有
     相应的链接（已收到邀请）或身份（有账号的内部评价者）。

**为什么不设序列号全局锁和租户锁**：任何不含 IP 的拒绝维度，都能被换很多 IP 的攻击者用来封禁不相关的人（租户锁封整个租户，
序列号全局锁封目标本人）。这两类风险由熵约束（§3.5），D5 只告警。

### 3.5 换取流程（`POST /api/survey360/portal/login`）与取锁顺序（R2-P2-3）
请求体 `{ serial, password }`：两个字段都必填，均为不超过 64 字符的字符串；不合格返回 400，不计数、不回显值。请求头 `x-tenant-id`。

```
0. 租户：非 UUID / 不存在 / 停用 → 401（不做 KDF，§3.8 的取舍）
1. 并发闸 G：取全局 + 单租户名额，取不到 → 503（未计数）；名额到第 6 步才释放
2. T1 原子检查与预扣（短事务，withTenant，不做 KDF）。取锁顺序：IP 行 → 序列号 × IP 行
   a. IP 行：INSERT … ON CONFLICT DO NOTHING；SELECT … FOR UPDATE；按 §3.3 判定 D1（requests ≥ 3000 → 频率限制）
   b. 序列号 × IP 行：SELECT … FOR UPDATE（不存在不建）；按 §3.3 判定 D3
   c. 任一拒绝 → 不写任何计数、不新建行（只可能按 §3.3 清理已到期的锁并写 unlock 事件），提交，返回 429
   d. 查凭据：按 KEYS 各版本算 serial_lookup，一次查询取链接行（不按状态过滤；找到 / 找不到走同一条索引路径）
   e. 预扣：IP 行 requests + 1；序列号 × IP 行 upsert failures + 1；
      记下两行的 window_started_at 作为预扣标识；提交
3. 事务外 KDF：恰好一次校验
      找到 → 用该行摘要；找不到 → 用启动时生成的哑摘要（同参数，结果恒为假）
4. T2 落定。取锁顺序与 T1 相同，再加链接行：IP 行 → 序列号 × IP 行 → 链接行
   先 SELECT … FOR UPDATE IP 行、序列号 × IP 行；成功候选再 SELECT … FOR UPDATE 链接行
   成功条件 = 摘要相等 ∧ 行存在 ∧ credential_state = 'issued' ∧ ¬revoked ∧ kind = 'answer'
              ∧ credential_key_versions 与 COMPROMISED 无交集 ∧ 活动未删除 ∧ hasActiveTask（§4.2）
   a. 成功：
      · D4：该链接 1 小时内签发的会话数 ≥ 20 → 频率限制 429（不签发，不退预扣）
      · 插入会话（只记 link_id，不存版本快照）；同一链接有效会话超过 5 个时作废最早的；
        退回预扣：序列号 × IP 行 failures 清零，带条件 window_started_at = 预扣标识（IP 行的 requests 不退，成功也计入 D1）；
        写 login_success 事件 → 201 { session, expiresAt }，Cache-Control: no-store
   b. 失败（含复核不通过）：预扣即确认；按 §3.3 设置锁定并写 lock 事件；
      最后 upsert D5 租户行 failures + 1，跨过 300 时写运行日志告警 → 401
5. 仅在第 4a 步已提交成功、且 credential_key_version ≠ CURRENT 时：事务外第二次 KDF 算新摘要，
   短事务按版本 CAS 写回并把 CURRENT 并入集合（§2.4）；失败不影响已返回的登录结果
6. 释放并发闸名额
```

- **取锁顺序（R2-P2-3）**：所有同时涉及限频行与链接行的事务都按“IP 行 → 序列号 × IP 行 → 链接行”取锁，D5 租户行永远最后、
  且只在 T2 失败分支用单条 upsert 更新。会锁链接行的其他写入（重发、维护任务、retire）都不碰限频行，不会与登录形成等待环。
  同 IP、同序列号的两个正确登录重叠时，B 的 T1 与 A 的 T2 依次排队，不再互相等待（AC-24）。
- T1 中 IP 行的 `FOR UPDATE` 让同一 IP 的请求串行通过 T1，预扣计入在途请求，所以同 IP 的并发突发不会超过 D3 阈值。
- **熵约束**：一个租户内全部可登录凭据数记为 N_t（不只是单个活动）。随机猜中任一有效序列号的概率每次约 N_t / 31¹⁰：
  - N_t = 100 万时约 1.2×10⁻⁹；
  - 猜中序列号后，还要在该序列号 × IP 上过每 15 分钟 5 次的密码限制。
  若 Q3 选了低熵格式，这里要重算（§2.3）。

### 3.6 资源保护与代理契约（P2-2）
| 层 | 规则 | 防什么 |
|---|---|---|
| D1 | 每 IP 每 15 分钟至多 3000 次登录请求（成功也算） | 单 IP 用合法凭据反复登录耗 CPU |
| D4 | 每个凭据每小时至多签发 20 个会话 | 合法凭据跨 IP 循环登录；会话表膨胀 |
| G | 每进程 KDF 并发全局 4、单租户 2，满则 503 | 单个租户占满全部名额，导致其他租户 503 |
| 维护任务 | KDF 并发 ≤ 2，与登录分开计数 | 批量发放挤占登录 |
| 代理（部署契约） | 见下 | 跨租户的单 IP 洪泛（应用内的限频表按租户隔离，做不到跨租户） |

**代理契约**（写进 `docs/06_部署/01_部署运行手册.md`，PR-2a）：
- **可信代理**：后端只接受来自可信代理网段的连接（网络策略）；应用配置 `TRUSTED_PROXY_CIDRS`。
- **转发头**：代理必须**覆盖**（不是追加）客户端带来的 `X-Forwarded-For`，写成它看到的对端地址。应用只在套接字对端属于
  `TRUSTED_PROXY_CIDRS` 时才读取该头，否则用套接字地址，忽略请求自带的转发头。所以伪造头无法改变限频身份（AC-30）。
- **IP 规范化**：去掉 IPv4-mapped 前缀（`::ffff:`）；IPv6 按 /64 聚合（同一用户通常持有整个 /64）；无法解析时记为 `unknown`。
- **代理限速**：`/api/survey360/portal/login` 每 IP（同口径聚合）跨租户每分钟 300 次、突发 600，超出返回
  429 `REQUEST_RATE_LIMITED` + `Retry-After`。这个阈值高于 D1，只用来挡洪泛；同一出口的人共享它，属于 §3.4 的残余风险。
- **日志**：代理不记录请求体与 `x-survey360-*` 头。
- 现有审计请求上下文（`audit/request-context.ts`）无条件采信 `X-Forwarded-For` 第一跳；门户限频不复用它，改用上面的可信提取。
  审计口径的同类问题不在本 PR（§11）。
- 503 不计认证失败，合理；总量由 D1 / D4 与代理约束。大规模分布式流量仍能把某租户的门户登录打到 503，由代理 / WAF 承担；
  个人链接与待办不受影响。

### 3.7 错误响应（与 AGENTS §10 / #194 对齐）
| 情况 | 状态 | `error.code` | `Retry-After` | 响应体附加 |
|---|---|---|---|---|
| 凭据错及 §3.8 列出的各种失败 | 401 | `UNAUTHENTICATED` | — | 无；响应体逐字节相同 |
| D1、D4、代理限速 | 429 | `REQUEST_RATE_LIMITED` | 整数秒，`ceil(窗口结束 − now)`（D4：最早一个计数会话满 1 小时的时刻） | 无 |
| D3 锁定（含“已达阈值未锁”） | 429 | `AUTH_LOCKED` | 整数秒，`ceil(unlockAt − now)`，至少 1 | `details.unlockAt`（UTC ISO 8601） |
| 并发闸满 | 503 | `SERVICE_UNAVAILABLE` | — | `details.reason = 'LOGIN_BUSY'` |
| 请求体不合格 | 400 | `VALIDATION_FAILED` | — | 只给字段路径，不回显值 |

- 401 的情况：序列号不存在、密码错、凭据 `pending` / `retired` / 已作废、曾暴露于 COMPROMISED 版本、活动已删除、
  已无有效评价关系、链接行属于确认链接、租户不存在或停用。
  响应体 `{ "error": { "code": "UNAUTHENTICATED", "message": "您输入的密码和序列号不匹配，请重新输入" } }`（DEC-401⑥，原站同文案），只有 `X-Trace-Id` 不同。
  文案定为“您输入的密码和序列号不匹配，请重新输入”（DEC-401⑥，原站同文案）；`message` 只给人看，客户端按 `error.code` 判断。
- **不泄露存在性**：D1、D3 的判定都不依赖序列号是否存在，对不存在的序列号同样计数、同样锁定；D4 只在密码正确后才可能触发。
  `REQUEST_RATE_LIMITED` 与 `AUTH_LOCKED` 的区分只暴露“命中了哪类限制”，不涉及凭据是否存在。
- PR-0 在 `errors.ts` 中新增 `REQUEST_RATE_LIMITED: 429`、`AUTH_LOCKED: 429`。
  已有的 409 `RATE_LIMITED`（360 生成报告等业务冷却）不变（AGENTS §10 边界）。
- 客户端在 `Retry-After` 到期前不得自动重试，也不得把 429 当作结果未知去重放（§4.8 恢复表）。

### 3.8 计时侧信道
- 失败的各分支工作量相同：T1 的两次加锁读、一次凭据索引查找、预扣写入；一次校验 KDF；T2 的失败分支写入。
  成功分支本来就可区分；迁移的第二次 KDF 在 T2 成功提交之后才做，所以凡是 T2 判为失败的请求（含正确密码但关系已删、
  凭据已暴露、D4 超限）都只有一次 KDF。
- 哑摘要在启动时以随机盐、相同参数生成；摘要比较用 `timingSafeEqual`；输入先规范化、限长 64。
- 有意的取舍：租户无效时不做 KDF。从耗时能看出租户标识是否有效，但租户标识写在通用网址里，本就不是秘密（Q1）；
  不存在的租户没有限频行，若仍做 KDF，就成了一个不受 D1 约束的 CPU 消耗入口。
- 测试注入计数器断言 KDF 调用次数（AC-31）：
  - 各失败分支 = 1；
  - 成功分支 = 1（无需迁移）或 2（需要迁移，第二次在提交成功之后）；
  - 正确的旧版本密码但 T2 复核失败（关系已删、凭据已暴露）= 1；
  - 400、D1 / D3 的 429、503、租户无效 = 0；
  - D4 的 429 = 1（发生在校验之后）。
  调用次数证明的是“失败分支工作量相同”，不等于完整的计时不可区分。

## 4. 作答会话

### 4.1 令牌、有效期、同源、登出
- 令牌：32 字节随机数，base64url；库里存 SHA-256；经请求头 `x-survey360-session` 传递，不放 Cookie，不放路径。
- 有效期：签发起 8 小时绝对过期，不做滑动续期（Q9，待 E6）。过期后重新登录可续答，草稿不丢（E3-R22 自动保存）。
- 同源（AGENTS §10）：门户不放开 CORS；写请求只接受 `application/json`（全局中间件），跨源页面的请求会触发预检并被拒，
  所以不能替受害者登录攻击者的会话，也不能读走响应。
- 登出 `POST /api/survey360/portal/logout`：**不用严格会话守卫**。请求头格式合法时，作废与令牌摘要匹配的会话（不论状态）；
  任何情况一律 204，包括二次登出、已过期、无效或缺失的令牌。只有持有令牌才能作废对应会话，所以不需要其他资格判断。
- 有界：每条链接至多 5 个有效会话（T2 按链接行加锁串行签发）；每条凭据每小时至多 20 个（D4）；
  维护任务删除过期或作废超过 24 小时的会话行。
- 登录 / 登出结果未知时的恢复见 §4.8。

### 4.2 有效评价关系（P2-4）
- **条件** `hasActiveTask(tx, activityId, personId)`：该评价者在该活动存在一条 `NOT r.removed` 的评价关系，且其评价对象
  `NOT o.removed`（与 answering.ts `taskQuery` 同一组连接）。
- **用在三处**：
  1. 登录 T2 成功复核（§3.5 第 4 步）：不满足 → 按失败处理，返回同一个 401；
  2. 会话预检（事务外，`requireSession`）：不满足 → 401；
  3. 会话事务内定位（`sessionLink`）：不满足 → 返回 undefined，由 `resolve` 返回 404（只在预检后恰好被移除的竞态里出现）。
- **覆盖**：主页 `GET /`、三条任务路由、头像（含“作答页评价者姓名”开启时的本人头像）都经过 `sessionEntry`，一并失效。
- **只看“是否还有任何一条”**：评价者还有其他有效关系时照常可用，只是任务清单少了被删的那项（被删的任务访问 404）。
- **移出即作废（DEC-401⑧）**：最后一条有效关系被移除时，该评价者的作答链接随之作废（与重发同一机制，凭据与全部会话失效，
  提示同凭据错误）；之后重新加回关系，`ensureAnswerLink` 发新链接与新凭据，旧凭据与旧会话**不恢复**。上面三处判定仍然保留，
  作为竞态下的读侧兜底（移除与会话请求交错时）。移除入口（删关系、移除评价对象等，见 F-084 列出的三个来源）落到哪个函数、
  是否会与活动级联删除重复作废，由 PR-2a / 2b 开工前对照 F-084 的实现确认。
- 会话的另一项每次检查：所属链接行**当前的** `credential_key_versions` 是否与 COMPROMISED 有交集（§2.4），有则同样 401 / 404。
  这一项读配置和链接行现值，部署即生效，也覆盖会话签发之后凭据才迁移、才暴露的情况（R2-P2-4、R3-P2-1）。
- 会话检查**不要求** `credential_state = 'issued'`：计划退役把凭据改为 `retired` 后，已有会话照常可用到过期（§2.4）。
- 现有个人链接 / 待办入口也有同样的情况（最后一条关系移除后，`answerPage` 仍返回活动名称与欢迎语），本设计不改，
  已登记为 F-084（§11）。

### 4.3 `sessionEntry`
```ts
// apps/api/src/modules/survey360/portal.ts（PR-2b）
function sessionEntry(deps): EntryOf {
  return async (c) => {
    const { tenant, token } = await portalTenant(c, deps);   // x-tenant-id + x-survey360-session；不合格 → 401
    await requireSession(deps, tenant, hashToken(token));     // 事务外预检：未过期、未作废、链接未作废、链接行当前的
                                                               // 版本集合与 COMPROMISED 无交集、§4.2 有效关系 → 否则 401
    return {
      tenant, caller: tenant, avatarBase: PORTAL_BASE,
      locate: (tx) => sessionLink(tx, hashToken(token)),      // 事务内复核同一组条件
    };
  };
}
```

### 4.4 会话失效的时点
| 事件 | 结果 |
|---|---|
| 过期 / 登出 | 401 |
| 重发邮件邀请（链接行作废） | 401 |
| 所属凭据实际用过的版本中有 COMPROMISED 版本（含会话签发后才迁移到该版本的） | **配置部署即 401**，不等 `retire` 批处理（R2-P2-4、R3-P2-1） |
| 计划退役（只进 RETIRED） | 照常可用到过期 |
| 活动删除 / 最后一条有效评价关系被移除（链接作废） | 401（预检）；竞态时 404；加回关系后也不恢复 |
| 部分评价关系被删除 | 可用；访问被删的那项任务返回 404 |
| 活动停用 | 可读；写入 409 `ACTIVITY_NOT_OPEN` |
| 租户停用 | 401 |

### 4.5 幂等（P3 改为“同入口保证”）
- 命令指纹包含请求路径与 `caller.userId`，所以只承诺**同入口**的幂等：同一入口、同一 Idempotency-Key、同一内容 → 重放；
  同一个键拿到另一个入口（个人链接、待办、门户之间）→ 409 `IDEMPOTENCY_CONFLICT`。不做跨入口的业务级指纹。
- 前端每个入口自己生成键，不跨入口复用。

### 4.6 评价关系与匿名口径
- 会话代表“该评价者在该活动”，作答页沿用 `answerPage`，匿名开关（DEC-149）照旧：作答页评价者姓名关闭时，`appraiser` 键缺席。
- 写入的操作人记为“系统”，与另外两个入口一致；外部人员（DEC-027）可用。
- 待办完成判定（`completeTodo`）在提交时触发，与入口无关。

### 4.7 边界
| 能力 | 会话能否访问 | 机制 |
|---|---|---|
| 本评价者本活动的作答页、答卷读写、本单人员头像 | 能（受 §4.2 约束） | `registerAnswerRoutes` + 单独注册的主页与头像 |
| 确认链接 | 不能 | 门户不注册确认路由；`sessionLink` 只认 `kind = 'answer'` |
| 报告转发收件人链接（F-060） | 不能 | 不同路径、不同请求头、不同摘要表 |
| 个人报告 | 不提供 | 现有证据只覆盖“转发”这一种报告出口（`25` §10.3 ⑮），没看到评价者作答入口里有报告。会话不开放报告，是复刻按范围做的决定，不是原站结论 |
| 管理端 | 不能 | 需要租户成员身份 |
| 其他活动 | 不能 | 一组凭据对应一个活动（E2 暂定） |

### 4.8 登录 / 登出不走命令台账：替代方案评估与恢复语义（DEC-377③）
**为什么现有台账不能直接用**：`runCommand` 把响应体原样存进 `command_ledger.response_body`，登录的响应就是会话令牌明文；
请求指纹是 `SHA-256(userId + fingerprint)`，fingerprint 含请求体，等于给 39.6 位的密码做了一个无盐、无密钥的摘要，可离线穷举。

**评估过的替代方案**
| 方案 | 做法 | 为什么不采用 |
|---|---|---|
| A. HMAC 指纹 + 存会话令牌密文 | 指纹改用服务端密钥 HMAC；响应体里的令牌用 outbox 同款 AES-GCM 加密后存台账，重放时解封返回同一令牌 | 按所评估的实现（在现有 `runCommand` 上扩展）：① 台账是长期保留的通用表，会多出一份可解密的有效凭据，泄露面比会话表大（会话表只存 SHA-256）；② 要在公共执行器里为一个接口加入加密与密钥管理（契约 PR）；③ 现有执行器在重放命中时直接返回存档结果、不再执行业务逻辑，要让重放也经过 D1～D3 计数，需另加处理。另建专用台账可以避开 ②③，但仍有 ① |
| B. HMAC 指纹 + 专用敏感回执 | 台账只存 HMAC 指纹与会话行 ID；重放时为同一会话行换发新令牌 | ① “重放”实际变成了“重新签发”，语义上与再次登录相同，却多出一条要单独加锁、计数的路径；② 若在现有执行器上实现，要改公共执行器（另建专用台账可避免）；③ 原令牌已在途且无法收回，换发后旧令牌失效，网络恢复后先到的那个响应反而不能用，客户端更难处理 |
| C. 只存 HMAC 指纹、不存回执 | 同键同内容第二次请求返回 409 或空 | 客户端恰恰在“结果未知”时最需要结果，返回 409 / 空等于让它重新登录，台账没带来任何好处 |
| **D. 不走台账（采用）** | 登录是认证，不是业务命令；重试即重新登录 | 见下：每次重试都经过同样的校验与限频，产生的多余会话有界且自然过期 |

**恢复语义（采用 D）**
| 情况 | 客户端 | 服务端 |
|---|---|---|
| 登录请求超时 / 网络断开 / 5xx | 用同一组序列号和密码重新登录，不带 Idempotency-Key；拿到的新会话即为准 | 每次都是独立的登录：经过 D1～D3 计数与 KDF；之前若已签发会话，它成为孤儿会话（无人持有），8 小时后过期，并计入“每链接 5 个有效会话”（超出时作废最早的）与 D4 |
| T1 已提交、T2 前进程崩溃 | 收到连接错误，按上一行重试 | 预扣不退回，相当于记了一次失败；若恰好是第 5 次，按 §3.3 最多锁到该窗口结束（≤ 15 分钟），窗口一过即重置 |
| 收到 429 | 等 `Retry-After` 到期后再由用户发起登录；不自动重试，不把 429 当作结果未知去重放 | — |
| T2 提交结果未知（提交请求已发出、连接中断） | 收到 503 `SERVICE_UNAVAILABLE`，重新登录 | 不回查、不补偿：若实际已提交，产生的孤儿会话同上处理；若未提交，预扣按失败记 |
| 登出结果未知 | 重试登出（总是 204）；无论成败都丢弃本地令牌 | 登出幂等：重复作废同一会话无副作用；若始终未送达，会话 8 小时后过期 |
| 客户端只想确认会话是否还有效 | 调 `GET /portal`：200 表示有效，401 表示需重新登录 | — |

- 声明：两条路由 `write.ledger = 'none'` 并写理由（§5.1）；`audit/capture.ts` 的失败命令审计只挂在租户成员路径上，门户不受影响。
- AGENTS 中“认证专用例外”的条文由进度窗口起草（DEC-377⑤）。

## 7. 写入口 × 值来源

| 写入口 | 写什么 | 值来源 |
|---|---|---|
| `links.ts issue()`，`kind = 'answer'`，开关开 | 链接行 `credential_state = 'pending'`；邀请 outbox `awaiting_credential` + `payload.linkId` + `sealed{token}` | 令牌由 CSPRNG 生成；outbox 密钥 `SURVEY360_OUTBOX_KEY_CURRENT` |
| `links.ts issue()`，`kind = 'confirm'`，或开关关 | 链接行 `credential_state = 'none'`；outbox `pending` + `payload.linkId` + `sealed{token}`（行为同现在，只是令牌加密） | 同上 |
| `reissueAnswerLink` | 旧行 `revoked`；新行同上；每个评价者一条 `credential_reissued` 事件 | 管理员命令 |

| `login` T2 失败 | 锁定字段与 `lock` / `unlock`；D5 租户行 failures | 同上 |
| `logout` | 会话 `revoked_at`；作废了有效会话时写 `logout` | 服务端时钟 |
| `rotate` 运维命令 | 每租户一条 `key_rotated` | 配置中的 CURRENT |
| `retire` 运维命令 | 计划退役：`issued` 行 → `retired`、摘要置空；泄露处置：集合含该版本的行 → `retired`（已 `retired` 的不变），并作废这些链接上的全部会话；进度行；`credential_revoked` / `key_retired`；手动重发清单 | 版本号参数 |
| 经会话的答卷保存 / 提交 | 答卷、答案、审计、命令台账 | 现有 `answerSave / answerSubmit` |
| 模板变量（F-077 渲染，只读） | — | 通用网址 = `PUBLIC_BASE_URL` + 前端路由 + 租户标识；序列号、密码取自解封后的 `sealed` |
