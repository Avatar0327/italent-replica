## 0. 一页摘要

- **原站已知**（`25` §10.4，W-692）：邀请作答邮件有“电脑作答通用网址 / 电脑作答序列号 / 电脑作答密码”三个变量；短信示例写
  “方法2：在电脑上登录[电脑作答通用网址]，请用序列号[电脑作答序列号]，密码[电脑作答密码]作答”。**除此之外没有证据**：
  通用网址长什么样、序列号与密码的格式、何时生成、重发是否换、错几次锁、错误文案、登录后进哪个页面，都没取证（§1.2）。
- **定位**：通用网址是个人作答链接之外的**第三个作答入口**，与现有“令牌链接”“站内待办”同一套作答页面与命令。
  answering.ts 已经把入口抽象成 `Entry.locate`（待办入口就是这么复用的），本任务新增一个 `sessionEntry`，不改作答处理函数。
- **凭据**：按“评价者 × 活动”一组（与 E3-R20“一个评价者一个作答链接、一条短信”同粒度，待 E2 证实），
  挂在现有 `survey360_links` 作答链接行上，与链接**同发、同换、同作废**。
  - 序列号：只存 `HMAC-SHA256(pepper, 规范化序列号)`，用于查找；
  - 密码：只存 `scrypt(HMAC(pepper, 规范化密码), 随机盐)`；
  - 明文只出现在邀请 outbox 的**加密封装**里，发送方渲染后即清除（§2.5）。
- **换取**：`POST /api/survey360/portal/login` 用“序列号 + 密码”换一个短期**作答会话令牌**（只存 SHA-256 摘要，经请求头传递）。
  会话只能进入本评价者本活动的作答页，不能访问报告收件人链接、确认链接与管理端。
- **防暴力**：按序列号、IP、租户三个维度计失败次数，原子预扣，超限锁定 15 分钟，返回 429。
  - 序列号维度按**输入值**的 HMAC 计数，不论该序列号是否存在，所以表现完全相同；
  - 所有失败原因（序列号不存在、密码错、已作废、活动已删、评价者已移除）返回**逐字节相同**的 401；
  - 失败路径与成功路径都恰好执行一次口令派生（不存在时对固定的哑摘要校验），并加进程内并发闸。
- **F-039**：新增 7 条公开路由（`kind: public`，DEC-291 Q2），守卫 `survey360.credentialExchange` / `survey360.answerSession`；
  登录与登出**不进命令台账**（台账会存响应体，即会话令牌明文），这是对 AGENTS §10“幂等”的有限例外，需决策（Q8）。
- **拆分**：PR-0 契约（迁移、错误码、环境变量键、领域常量）→ PR-1 凭据发放与轮换 → PR-2 换取、会话、防暴力与路由声明。
  PR-1 依赖 E2 / E3 / E5 取证或 Q2～Q4 决策；PR-2 的文案依赖 E7、停用活动登录依赖 E8，可先留 `TODO(需取证)`。
- **不做**：通知模板库与变量渲染、短信通道（F-077）；360 前端页面（复刻目前没有 360 前端）；确认链接的通用网址入口（E9）。

## 2. 凭据模型

### 2.1 粒度与生命周期
- **粒度**：评价者 × 活动一组（暂定，待 E2）。理由是 K2 + K3：一条短信给一组凭据，而一个评价者在一个活动只有一条短信。
  E2 若证实为“每评价关系一组”，改的只是 §6 唯一索引和 §2.4 发放点，会话与防暴力不变。
- **挂载位置**：现有 `survey360_links` 中 `kind = 'answer'` 的行加三列（§6）。理由：
  - 凭据与个人链接**同发、同换、同作废**（Q4 推荐），放在同一行，“一个评价者同一时刻只有一组有效凭据”就由现有部分
    唯一索引 `survey360_links_answer` 保证，不必再建一套；
  - 会话外键指向链接行，链接作废时会话随之失效，不需要额外的级联逻辑。
  - 若 Q4 定为“重发不换序列号 / 密码”，凭据要搬到独立表 `survey360_answer_credentials`（按活动 + 评价者唯一），
    会话改挂凭据行。差异在附录 A 列出。
- **生命周期**：

```
发放 ── 活动启用（issueAnswerLinks）、启用中新增评价者（relations.ts addRelation → ensureAnswerLink）
  │       与个人链接同一次 issue()，写同一条邀请 outbox
  ├─ 使用：换取会话（§3）
  ├─ 轮换：管理员“重发邮件邀请”（todos.ts → reissueAnswerLink）：旧链接行 revoked=true（序列号、密码、会话一并失效），
  │       发新链接行与新凭据（待 E5 / Q4）
  └─ 终止：链接行作废即终止；活动删除、评价者被移除时不改链接行，但 resolve / 任务查询已找不到活动或任务，登录统一失败
```

- **存量链接**：F-076 上线前已发放的链接行三列为空，不能用通用网址登录，直到下一次“重发邮件邀请”。不做回补：
  回补得重新发通知才能把明文交到评价者手上，那就等于重发（Q12）。

### 2.2 生成（熵）
- 随机源：`crypto.randomInt`（CSPRNG）逐位取字符；不用 `Math.random`。
- **字符集与长度待 E3**。取证前的复刻备选（Q3）：
  - 字母表 31 个字符：`23456789ABCDEFGHJKMNPQRSTUVWXYZ`（去掉 0 / O、1 / I / L 等易混字符）；输入不区分大小写，
    规范化 = 去掉首尾空白、空格与连字符后转大写；
  - 序列号 10 位（约 49.5 位熵）；密码 8 位（约 39.6 位熵）。
  - 抗猜测估算：单个序列号每 15 分钟最多 5 次（§3.2），即每天至多 480 次；猜中 8 位密码的期望时间约 2^38.6 / 480 天，
    远超活动周期。攻击者也几乎猜不中有效序列号：一个活动最多 5 万名评价者，单次猜中任一有效序列号的概率约 5×10⁴ / 31¹⁰ ≈ 6×10⁻¹¹，
    且租户维度每天至多约 2.9 万次失败。
- 若 E3 证实原站是更短的纯数字密码（例如 6 位），建议**复刻保持上面的长度**，属于有意收紧，登记差异（同 DEC-209 类）。理由：
  6 位数字只有约 20 位熵，在租户维度的上限下，几天内就能对少量序列号猜中。
- **序列号唯一**：在租户内按 `serial_lookup` 唯一（包括已作废的行，不复用）。发放时遇到唯一冲突重试至多 3 次，
  仍冲突抛 500（概率可忽略）。

### 2.3 存储（只存摘要）
| 值 | 存什么 | 算法 | 理由 |
|---|---|---|---|
| 序列号 | `serial_lookup`（hex） | `HMAC-SHA256(pepper_v, 'survey360:serial:' + 规范化序列号)` | 登录时要按序列号查行，摘要必须是确定的，所以不加盐；加 pepper（不在库里）后，只拿到库也无法枚举 |
| 密码 | `password_hash`（`scrypt$1$N$r$p$salt$hash`） | `scrypt(HMAC-SHA256(pepper_v, 'survey360:password:' + 规范化密码), 16 字节随机盐, N=2^14, r=8, p=1, 32 字节)` | 先过 pepper，再做加盐慢哈希：库与 pepper 同时泄露时，仍要逐条做 scrypt 暴力，8 位密码不可行 |
| pepper 版本 | `credential_key_version`（smallint） | — | 轮换 pepper 时按版本选密钥 |

- **pepper**：环境变量 `SURVEY360_CREDENTIAL_PEPPER`（base64 编码的 32 字节，放 Secret 管理；`.env.example` 只写键名）。
  轮换时另设 `SURVEY360_CREDENTIAL_PEPPER_PREVIOUS`，登录对每个已配置版本各算一次 `serial_lookup`（最多 2 个）；
  新发放一律用当前版本。生产环境缺失或长度不足即**启动失败**（fail-closed，同 `BACKUP_ENCRYPTION_KEY` 与开发身份密钥的做法）；
  test / development 缺省时生成进程内随机值。
- `node:crypto` 只能在 `apps/api` 用（domain 包禁止 IO）。领域包 `packages/domain/src/survey360/credential.ts` 只放
  字母表、长度、`normalizeCredential()`、格式校验等纯函数；生成、HMAC、scrypt 放 `apps/api/src/modules/survey360/credentials.ts`。
- 比较一律 `timingSafeEqual`；scrypt 用异步版本（线程池），不阻塞事件循环。

### 2.4 轮换、作废与重发语义
| 操作 | 凭据 | 会话 | 待定 |
|---|---|---|---|
| 活动启用 / 启用中加评价者 | 已有有效链接行则不重发（`ensureAnswerLink`）；否则新链接行 + 新凭据 | — | E5：原站是否在启用时就生成 |
| 重发邮件邀请（`reissueAnswerLink`） | 旧行作废，新行新凭据（推荐，Q4） | 旧行上的会话全部失效 | E5 |
| 发送 / 重发站内待办 | 不变（待办不带凭据，K5） | 不变 | — |
| 取消待办 | 不变（K4：取消待办不让链接失效） | 不变 | — |
| 清空作答（重新作答） | 不变（原站“用原链接重答”，E3-R21） | 不变 | — |
| 停用活动 | 不变 | 不变，写入被 `ACTIVITY_NOT_OPEN` 拦下 | E8 |
| 删除活动 / 移除评价对象 | 不改行；登录时找不到活动或任务，统一失败 | 会话请求 404 | E8 |
| 管理员查看 / 导出凭据 | **不能**（只存摘要，无从回显）。忘记密码的处理办法是“重发邮件邀请” | — | E4：原站若能查看，登记为有意差异（Q5） |

### 2.5 邀请变量与明文边界
明文只允许出现在两个地方：发放那一刻的内存里，以及发送方渲染邀请那一刻（F-077）。其余地方逐项处理：

| 位置 | 现状 | F-076 处理 |
|---|---|---|
| 邀请 outbox `payload` | 链接令牌 `token` 明文存于 jsonb（links.ts `issue`） | 新增 `sealed` 字段：`AES-256-GCM` 加密 `{ token, serial, password }`，格式 `{ v: 1, kid, iv, tag, data }`，AAD = `tenantId:outboxId`。密钥 `SURVEY360_OUTBOX_KEY`（base64 32 字节，Secret 管理）。发送方解封、渲染；该条进入终态（sent / 最终 failed）时把 `sealed` 置空（F-077 落实）。现有 `token` 明文字段是否一并移入，见 Q7（推荐一并移入） |
| 模板变量 | 复刻没有模板库（F-077） | outbox 给出变量的值来源（§7）：通用网址 = `PUBLIC_BASE_URL` + 前端路由 + 租户标识（非秘密，可明文）；序列号、密码只在 `sealed` 里 |
| 审计（`audit360`） | 链接发放不单独审计；所在命令（启用、重发）有审计 | 审计 `after` 只记 `credentialIssued: <人数>`，不记序列号、密码、摘要 |
| 命令台账（`command_ledger`） | 启用 / 重发的回执不含令牌 | 不变；**登录不走 `runCommand`**（台账存响应体，会把会话令牌明文落库；指纹会把低熵密码做无盐 SHA-256），见 Q8 |
| 失败命令审计（`audit/capture.ts`） | 只挂在租户成员路径上 | 门户路径不挂，不受影响；在 PR-2 测试里断言门户失败不产生失败审计行 |
| 错误响应 / 服务日志 | `handleError` 对非 AppError 只打 `console.error(err)` | 登录处理函数**不把请求体放进任何错误对象**；zod 解析失败只返回字段路径与规则，不回显值（`parse()` 现状：zod 4 默认不带 `input`，已核对 too_big / unrecognized_keys；不得开启 `reportInput`，PR-2 加测试） |
| 访问日志 / 反向代理日志 | 令牌走请求头不走路径 | 序列号、密码走 JSON 请求体，会话令牌走请求头；路径里只有租户标识。部署手册补一句：代理不得记录请求体与 `x-survey360-*` 头 |
| 限频表 | — | 只存 HMAC（序列号输入、IP），不存原值（§3.2） |

## 3. 防暴力

### 3.1 换取流程（`POST /api/survey360/portal/login`）
请求体 `{ serial, password }`。两个字段都必填，且为不超过 64 字符的字符串；不合格返回 400 `VALIDATION_FAILED`，不计失败次数，不回显值。
请求头 `x-tenant-id`（UUID）。

```
0. 租户：x-tenant-id 不是 UUID / 租户不存在 / 停用 → 统一 401（不做 scrypt，见 §3.5 的取舍）
0'. 并发闸（§3.6）：先取一个名额，取不到 → 503，此时尚未计数；名额在第 4 步结束后释放
1. 规范化：s = normalize(serial)，p = normalize(password)；k_serial = HMAC(pepper, s)，k_ip = HMAC(pepper, ip)
2. 预扣（短事务 T1，withTenant，提交）：
   a. 依次（租户 → IP → 序列号，固定顺序）对三行 throttle 做“原子加一”：
      INSERT … ON CONFLICT (tenant_id, scope, key_hash) DO UPDATE
        SET failures = CASE WHEN locked_until > now THEN failures              -- 锁定期内不计数
                            WHEN window_started_at < now - 窗口 OR locked_until <= now THEN 1  -- 窗口或锁定到期，从 1 重计
                            ELSE failures + 1 END, …
        RETURNING failures, locked_until
   b. 任一维度 locked_until > now，或加一后超过阈值（超过时同时写 locked_until = now + 锁定时长、failures 清零）
      → 记下“限流”，跳到 4
   c. 按 serial_lookup（各 pepper 版本）查链接行：不按 revoked 过滤（找到 / 找不到走同一条索引路径），
      取 id、password_hash、revoked、activity_id、person_id
3. 校验（不在事务里，不持锁，占用第 0' 步取得的名额）：执行一次 scrypt
      找到 → 校验该行的 password_hash；找不到 → 校验进程启动时生成的哑摘要（结果恒为假）
   ok = 摘要相等 ∧ 行存在 ∧ ¬revoked
4. 落定（事务 T2）：
   - 限流 → 429 TOO_MANY_ATTEMPTS（不做第 3 步）
   - ok：重查链接行仍未作废、活动未删除、kind = answer（防第 3 步期间被轮换）；
         插入会话；序列号维度清零，IP / 租户维度各减一（抵消预扣）；同一链接行有效会话超过 5 个时作废最早的
         → 201 { session, expiresAt }，Cache-Control: no-store
   - 否则：不再写库（第 2 步已计数）→ 401
```

要点：
- **先扣后验**。第 2 步在校验前已提交加一，所以并发猛刷同一序列号时，至多“阈值”个请求能进入第 3 步（AC-360-F076-09）；
  进程在第 3 步崩溃也已计数。
- 第 2 步用单条 upsert 原子加一，不长时间持行锁；三行固定顺序，避免死锁。scrypt 不在事务里执行，租户行不会成为串行瓶颈。
- 第 2c 步查行时不过滤 `revoked`、不连活动表；第 4 步成功分支才连。这样失败路径的数据库访问在“有 / 无此序列号”两种情况下相同。

### 3.2 限频维度与阈值（复刻自定，原站不可观察的部分；锁定提示与时长待 E7）
| 维度 | 键 | 窗口 | 阈值 | 锁定 | 说明 |
|---|---|---|---|---|---|
| 序列号 | `HMAC(pepper, 规范化输入)`：**不论是否存在** | 15 分钟（固定窗口） | 窗口内失败 5 次（第 6 次起 429） | 15 分钟 | 成功即清零；锁定期内不计数，到期后从 1 重计 |
| IP | `HMAC(pepper, 客户端 IP)` | 15 分钟 | 30 次失败 | 15 分钟 | IP 来源同审计：`X-Forwarded-For` 第一跳（部署须由代理覆盖该头，`docs/06_部署`），其次 `X-Real-IP`、套接字地址；取不到时记为 `unknown`，与其他取不到 IP 的请求共享一个键 |
| 租户 | 常量键 | 15 分钟 | 300 次失败 | 15 分钟 | 防分布式（换 IP）撒网；锁定期间该租户所有通用网址登录 429，个人链接与待办不受影响 |

- 阈值做成常量（`credentials.ts` 顶部，带出处注释），不做租户配置。
- IP 维度依赖代理覆盖 `X-Forwarded-For`。代理没配好时攻击者可伪造 IP 绕过 IP 维度，但绕不过序列号和租户两个维度（纵深防御）。
  跨租户的 IP 限频在应用内做不到（限频表受 RLS 约束、按租户隔离），由反向代理或 WAF 承担，写进部署手册。
- 清理：第 4 步顺带删除本租户 `updated_at` 早于 24 小时、且未处于锁定的行，单次至多 100 行，保持有界。

### 3.3 锁定与解锁
- 到期自动解锁，不做管理员“解锁”接口。若评价者被他人锁住（攻击者故意输错其序列号），管理员有两条路：
  - 让评价者改用个人链接或站内待办；
  - 点“重发邮件邀请”：发新序列号，旧序列号的锁随之无关紧要。
  这两条路都已有接口，只需在设计中写明（Q6）。
- 锁定只阻止通用网址登录，不影响已签发的会话，也不影响个人链接与待办。

### 3.4 错误响应不可区分
- 以下情况**一律**返回同一个 401，响应体逐字节相同，只有 `X-Trace-Id` 不同：序列号不存在、密码错、凭据已作废（重发后用旧的）、
  活动已删除、链接行属于确认链接、租户不存在或停用。
  响应体：`{ "error": { "code": "UNAUTHENTICATED", "message": "序列号或密码错误" } }`。文案待 E7，取证前用这一句并留 `TODO(需取证 #190)`。
- 限流统一返回 429，不带 `Retry-After`（Q6）。响应体：`{ "error": { "code": "TOO_MANY_ATTEMPTS", "message": "尝试次数过多，请稍后再试" } }`。
  - 不论锁的是哪个维度、该序列号是否存在，429 都相同，所以不泄露存在性；
  - 不带 `Retry-After` 是为了不暴露命中的是哪个维度（三个维度的窗口不同步）。
- 为什么用 401 而不是令牌链接的 404：登录是“凭据错”，不是“资源不存在”；前端据 401 提示重输。统一错误码已有 `UNAUTHENTICATED`。
  429 是统一错误码表的新增项（AGENTS §10 列 401 / 403 / 400 / 409 / 413 / 415 / 503），需决策（Q7）并经契约 PR 修改 `errors.ts`。
- 活动停用时能否登录（E8）：取证前按“可以登录、页面显示活动状态、写入 409 `ACTIVITY_NOT_OPEN`”实现，与令牌链接一致（K4）。
  若原站是登录时就拒绝，也只能返回同一个 401；不能新开一种只有“凭据正确”时才出现的提示，否则就成了密码校验的旁路。

### 3.5 计时侧信道
- 失败的各分支执行的工作相同：第 2 步三次 upsert + 一次索引查找，第 3 步一次 scrypt（找不到时对哑摘要），第 4 步无写入。
- 哑摘要在进程启动时用随机盐、相同 scrypt 参数生成，耗时与真摘要相同。
- 摘要比较用 `timingSafeEqual`；HMAC 输入先规范化、限长 64，避免超长输入拉长耗时。
- **有意的取舍**：租户不存在 / 停用时直接返回 401、不做 scrypt。
  - 代价：从耗时能看出租户标识是否有效；
  - 可以接受，因为租户标识写在通用网址里，本来就不是秘密（Q1）；
  - 好处：不存在的租户没有限频行可用，若仍做 scrypt，就成了一个不受限的 CPU 消耗入口。
- 测试不测墙钟时间（CI 不稳定），改为注入计数器，断言每个失败分支 scrypt 恰好被调用一次（AC-360-F076-17）。

### 3.6 资源耗尽
- scrypt 并发闸：每进程同时至多 4 个（参数 N=2^14、r=8 时每个约 16 MB 内存），超出立即返回 503 `SERVICE_UNAVAILABLE`，
  不排队。名额在预扣**之前**取得（§3.1 第 0' 步），所以 503 不计失败次数，也不会出现“已扣未验”。
  实现可参照 export-runtime.ts 的准入方式（F-060）。
- 闸满本身可被刷满造成登录 503（拒绝服务），但个人链接与待办不受影响；跨请求的总量由三维限频与反向代理限速兜底。
- 请求体默认 32 KB 上限与“只接受 JSON”沿用全局中间件。

## 4. 作答会话

### 4.1 令牌与有效期
- 令牌：32 字节随机数，base64url 编码；库里只存 SHA-256（与链接令牌同法，`hashToken`）。经请求头 `x-survey360-session` 传递，
  不放 Cookie：现有链接入口都走请求头，这样浏览器不会自动携带，也就没有 CSRF 面；也不放路径。
- 有效期：签发起 **8 小时绝对过期**，不做滑动续期（续期会让每个 GET 都写库）。8 小时足够一次作答；
  页面每 10 秒自动保存（E3-R22），过期后重新登录即可续答，草稿不丢。待 E6 / Q9 定。
- 同源（AGENTS §10「请求」）：门户不放开 CORS；写请求只接受 `application/json`（全局中间件），跨源页面发起的请求
  会触发预检并被拒，所以既不能替受害者登录攻击者的会话（登录 CSRF），也不能读走响应。会话令牌不在 Cookie 里，浏览器不会自动携带。
- 登出：`POST /api/survey360/portal/logout`，作废本会话；幂等（已作废、已过期、不存在都返回 204）。
- 每个链接行至多 5 个有效会话，超出时作废最早的，使会话表有界。

### 4.2 `sessionEntry`
```ts
// apps/api/src/modules/survey360/portal.ts（PR-2）
function sessionEntry(deps): EntryOf {
  return async (c) => {
    const { tenant, token } = await portalTenant(c, deps);      // x-tenant-id + x-survey360-session；不合格 → 401
    await requireSession(deps, tenant, hashToken(token));        // 事务外预检：无效 / 过期 / 已作废 → 401
    return {
      tenant, caller: tenant, avatarBase: PORTAL_BASE,
      locate: (tx) => sessionLink(tx, hashToken(token)),         // 事务内复核：会话有效 ∧ 链接行未作废 ∧ kind = answer
    };
  };
}
```
- 事务外预检返回 401，让前端知道要重新登录；事务内复核失败（预检之后恰好被轮换或登出）由 `resolve` 返回 404，与令牌链接一致。
  这个竞态窗口只有一个请求那么长，不泄露任何信息。
- 命令指纹仍是 `link: link.id`。同一评价者经个人链接、待办和通用网址三个入口用同一个 Idempotency-Key 提交同一内容时，
  按幂等重放处理，与现状（待办与链接共用）一致。

### 4.3 会话失效的时点
| 事件 | 结果 |
|---|---|
| 过期 / 登出 | 401 |
| 重发邮件邀请（链接行作废） | 401（预检时查到 `link.revoked`） |
| 活动删除 | 预检通过，`resolve` 找不到活动 → 404（与令牌链接一致） |
| 评价对象被移除 / 评价关系被删除 | 任务清单里不再有该项；访问该任务 404 |
| 活动停用 | 可读；写 409 `ACTIVITY_NOT_OPEN`（“活动暂停中，请稍后评价”） |
| 租户停用 | 401 |

### 4.4 评价关系与匿名口径
- 会话代表的身份就是“该评价者在该活动”，与令牌链接相同，所以作答页的任务清单、评价对象、角色显示、评价者姓名显示都沿用
  `answerPage`，匿名开关（DEC-149）照旧生效：“作答页评价者姓名”关闭时，`appraiser` 键缺席。
- 写入的操作人记为“系统”（`SYSTEM_USER_ID`），审计不留评价者身份，与令牌链接、待办两个入口一致（answering.ts 头注释）。
- 外部人员（DEC-027，无租户账号）可用；组织员工也可以用，与是否持有账号无关。
- 待办完成判定（`completeTodo`）在提交时由处理函数触发，与入口无关，照旧生效。

### 4.5 与 F-060 报告转发、确认链接、待办的边界
| 能力 | 会话能否访问 | 机制 |
|---|---|---|
| 本评价者本活动的作答页、答卷读写、本单人员头像 | 能 | `registerAnswerRoutes` + `avatarRoute`，挂在 `/api/survey360/portal` 下 |
| 确认链接（上级确认评价者） | 不能 | 门户不注册 `registerConfirmRoutes`；`sessionLink` 只认 `kind = 'answer'`（E9 若证实确认也用通用网址，另开任务） |
| 报告转发收件人链接（F-060，`/api/survey360/report-link`） | 不能 | 不同路径、不同请求头（`x-survey360-token`）、不同摘要表（`survey360_report_links`）。会话令牌拿去当链接令牌查不到，反之亦然 |
| 本人的个人报告 | 不能 | 原站个人报告只经“转发”发出（`25` §10.3 ⑮），评价者作答入口里没有报告 |
| 管理端 `/api/tenant/survey360/*` | 不能 | 需要租户成员身份 |
| 其他活动 | 不能 | 一组凭据只对应一个活动（E2） |

### 5.4 审计
| 事件 | 记录 | 理由 |
|---|---|---|
| 凭据发放 / 轮换 | 记在所在命令（启用活动、重发邀请、新增评价者）的现有审计里，`after` 增加 `credentialIssued` 人数 | 发放不是独立命令；不记序列号、密码或摘要 |
| 登录成功 / 失败、登出 | **不进业务审计**（推荐，Q10） | 会话是认证状态，不是业务数据（同平台登录）；失败次数由限频表承载；若逐次写审计，攻击流量会冲垮审计表 |
| 触发锁定 | 结构化运行日志一条：租户、维度、键的 HMAC 前 8 位、时间；不含序列号或 IP 原值 | 供运维发现撒网攻击；不进审计，原因同上 |
| 经会话的答卷保存 / 提交 | 照旧 `audit360`（操作人“系统”） | 与令牌链接一致 |

## 6. 表结构（PR-0 一个迁移，只增不改）

```sql
-- 作答链接行加凭据三列（kind = 'answer' 才可能非空）
ALTER TABLE survey360_links
  ADD COLUMN serial_lookup text,
  ADD COLUMN password_hash text,
  ADD COLUMN credential_key_version smallint;
ALTER TABLE survey360_links ADD CONSTRAINT survey360_links_credential CHECK (
  (serial_lookup IS NULL AND password_hash IS NULL AND credential_key_version IS NULL)
  OR (kind = 'answer' AND serial_lookup IS NOT NULL AND password_hash IS NOT NULL AND credential_key_version IS NOT NULL));
CREATE UNIQUE INDEX survey360_links_serial ON survey360_links (tenant_id, serial_lookup) WHERE serial_lookup IS NOT NULL;

-- 作答会话
CREATE TABLE survey360_answer_sessions (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  tenant_id uuid NOT NULL,
  link_id uuid NOT NULL,              -- (tenant_id, link_id) 外键 → survey360_links
  token_hash text NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  expires_at timestamptz NOT NULL,
  revoked_at timestamptz,
  UNIQUE (tenant_id, token_hash));
CREATE INDEX ON survey360_answer_sessions (tenant_id, link_id) WHERE revoked_at IS NULL;

-- 登录限频
CREATE TABLE survey360_login_throttle (
  tenant_id uuid NOT NULL,
  scope text NOT NULL CHECK (scope IN ('serial', 'ip', 'tenant')),
  key_hash text NOT NULL,             -- tenant 维度为 ''
  window_started_at timestamptz NOT NULL,
  failures integer NOT NULL,
  locked_until timestamptz,
  updated_at timestamptz NOT NULL,
  PRIMARY KEY (tenant_id, scope, key_hash));
```
- 两张新表都启用租户 RLS，与 360 其他表同一套策略（R1-T00）；外键按租户复合键。
- 会话与限频行是认证状态，不属于业务对象，不进字段级变更日志（Q10）。
- 迁移序号在 PR-0 开工时取 main 上的下一个号（当前最新 0085）。
