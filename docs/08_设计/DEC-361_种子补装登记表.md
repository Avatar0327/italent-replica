# DEC-361 种子补装登记表

> 目的：各模块的预置数据（开通租户时下发）只维护一份安装逻辑，新租户开通与存量租户回补共用；上线后新增的预置数据不再要“重放开通命令”。
> 代码：`apps/api/src/seeds/registry.ts`；平台命令：`POST /api/platform/tenants/:tenantId/seeds/backfill`（`modules/platform/operations.ts#backfillSeeds`）。

## 1. 登记项（`SeedEntry`）

| 字段 | 含义 |
|---|---|
| `module` | 登记模块，如 `talent-review`；平台回补可按模块筛选 |
| `key` | 数据集编码，模块内唯一，如 `preset-fields` |
| `version` | 预置内容版本，清单变化时 +1，只用于回补报告，**不触发覆盖** |
| `codes` | 该数据集全部预置项的稳定编码（不随租户改名变化） |
| `existing(tx, tenantId)` | 租户里已经存在的预置编码（含被租户改名 / 停用 / 定制的） |
| `install(tx, write, missing)` | 只构造并写入 `missing` 里的编码，含子数据、配对关系与**审计**（DEC-216，同事务） |

`write = { tenantId, actorUserId, now, commandId }`：开通时是开通命令的上下文，回补时是平台命令的上下文。

## 2. 统一规则（`installMissingSeeds`）

- 只补缺失编码：`missing = codes − existing`；已有编码一律不动，重复执行无副作用。
- `installMissingSeeds` 在读取已有编码之前先取**租户级事务锁**（`pg_advisory_xact_lock`），开通与回补共用；并发回补 / 开通排队，后到者读到“已存在”，不会撞唯一约束（真 PG 交错测试 `AC-SEED-concurrency-pg`）。
- 安装在调用方的租户事务里执行；开通租户（`provisioning.ts`）与平台回补都调用同一函数。
- 平台回补：只认平台运营身份、显式指定租户、命令台账幂等（同命令 ID 重放返回原结果）、可选 `modules` 筛选（未知模块 400 `SEED_MODULE_UNKNOWN`）；租户审计由登记项写，平台审计留一条汇总。
- 返回 `{ items: [{ module, key, version, installed: [编码], existing: 个数 }] }`。

## 3. 接入方式（各任务自己处理）

1. 在模块里 `registerSeed({...})`（预置清单、`existing` 查询、`install` 只装缺失编码并写审计）；
2. 在 `apps/api/src/seeds/index.ts` 加一行 `import` 收录该文件；
3. 不要再在 `provisioning.ts` 里直接调用自己的 `installXxxPresets`。
