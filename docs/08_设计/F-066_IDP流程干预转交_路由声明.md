# F-066 IDP 流程干预：转交：路由权限声明

> 依据：规格 `28` IDP-R16 与“补充：流程干预”（Q-M0-115 ⑥）；DEC-063、DEC-321、DEC-329；F-048 设计 §6 #17 / #20。
> 格式沿用 F-039 的逐路由声明与 F-047、F-048 PR-2 路由声明。
> 范围：新增 1 条路由；不改现有路由、不新增迁移。
> F-068（DEC-354）补充：转交目标增加“该计划当前的指导人 / 带教人”例外，见 §1 转交目标一条与 §5；路由不变、不新增迁移。

## 1. 共用契约

- 应用 `IDP`，对象 PLAN = `IDP.Idp`（计划对象）。转交复用审批 `adminAct`（kind = `transfer`），转交当前运行阶段审批实例的当前待办。
- 权限：PLAN update 数据操作权 + 新按钮 `transfer`（level = detail，requires = update，登记在 `packages/domain/src/idp/catalog.ts`）；
  数据范围按用户 × IDP（DEC-043）解析，缺省为空；范围外与不存在同为 `404 NOT_FOUND`（与跳转一致）。
- 本人回避（DEC-321 / F-048 §6 #17、#20）：不查实时账号绑定，由 `adminAct` 按发起 / 重提时冻结的主体集合判定（I′）：
  计划所有者（发起人）可干预；计划员工本人及冻结的 U(S) 回避，`403 APPROVAL_ADMIN_SELF`；冻结之后才首次绑定到该员工的所有者本轮不追溯。
- 转交目标先由本入口校验范围：目标须是已绑定员工，且该员工在操作人的 IDP 范围内（IDP-R16“受管理单元限制”）。账号不存在、
  未绑定员工的纯账号（DEC-354 已定：拒绝）、范围外且不是该计划指导人 / 带教人三种情况同为 `404 NOT_FOUND`，不暴露存在性。`adminAct` 本身不看操作人范围，
  审批中心通用的 `admin-transfer / admin-intervene` 不在本 PR 改动范围（另开 F）。
- **例外（F-068，DEC-354）**：目标是该计划**当前登记**的指导人（`idp_plans.tutor_employee_id` 的当前值，不是开始时冻结值），或带教期间与计划起止有交集的带教人
  （`idp_tutorships`：带教人 = 目标、被带教人 = 计划员工，交集口径同计划详情的关键信息，IDP-R7），即使在操作人范围外也可以作为转交目标。
  纯账号（未绑定员工）仍拒绝；范围外且既非指导人也非带教人、纯账号、账号不存在三种情况的完整错误响应一致（同一个 404 `转交目标不存在`）。
  改掉计划指导人、删除 / 改期带教记录后立即失效（每次转交现查）。例外所依赖的来源字段（计划的 `tutorEmployeeId`；带教信息的 `tutorEmployeeId`、
  `tuteeEmployeeId`、`startDate`、`endDate`）操作人看不到时视同不是（DEC-309 / E3），与其他范围外目标同一个 404。
  **失败不得暴露该关系（F-068 第 2 轮）**：仅凭例外放行的目标，其后 `adminAct` 的任何失败（无效 / 已关闭的 `taskId`、实例已关闭、业务单已变更、本人回避、会签重复办理人、目标无效或回避等）一律改成与普通范围外拒绝相同的 `404 NOT_FOUND`「转交目标不存在」；与目标无关的校验（无运行阶段 `409 IDP_NO_RUNNING_STAGE`、多条待办未指定 `400 IDP_TRANSFER_TASK_REQUIRED`）排在目标判定之前，对所有目标一样。
- 其余目标校验由 `adminAct` 判定，IDP 不另写一套（目标是例外放行的指导人 / 带教人时，这些失败对外统一为上条的 404）：目标须是有效的租户成员（`400 APPROVAL_USER_INVALID`）；
  目标回避同时受节点 `avoidSelf`（发起人账号，即所有者；单主体时也包括计划员工的冻结账号 U(primary)）和 `avoidSubjects`（冻结主体集合 U(S)）
  两个开关影响，命中 `409 APPROVAL_SELF_REVIEW`（预置 IDP 节点两项都未开启）；不能转给同节点其他在办的办理人（`400 APPROVAL_ALREADY_NODE_ASSIGNEE`，会签场景）。
  转给自己必须填写原因（`400 APPROVAL_REASON_REQUIRED`），转给自己时审批侧审计动作是 `approval.admin.self_transfer`。
- REV = 缺 If-Match `400 REVISION_REQUIRED`；计划 revision 不符 `409 REVISION_CONFLICT`。IDEM = 缺命令键
  `400 IDEMPOTENCY_KEY_REQUIRED`；同键异内容 `409 IDEMPOTENCY_CONFLICT`；同键同内容重放不重复转交、不重复审计；重放响应是重新读取并按当前字段权限裁剪的计划详情，不是原响应快照。
- 业务变更（待办转交、计划 revision +1）、审批侧审计 `approval.admin.transfer`（原审批人、新审批人、原因，DEC-063）、
  计划审计（intervention = `transfer`）与命令台账在同一租户事务中写入。

## 2. 逐路由声明

| 方法 | 路径 | 类型 | 对象·操作·按钮 | 范围 | 字段 | 写足迹 | 拒绝码 |
|---|---|---|---|---|---|---|---|
| POST | `/api/tenant/idp/plans/:id/transfer` | object | PLAN；update；transfer@detail | point id → 计划行锁 → HR 范围（范围外 404）→ revision；返回前按当前范围复核 | 请求：`toUserId`（UUID，必填）、`taskId`（可选，缺省取当前阶段唯一待办；多条待办时必填）、`reason`（可选，≤500）；响应为计划详情，按 PLAN 字段查看权裁剪 | 计划行 + 审批任务 / 实例 + 计划审计 + 审批审计 + 命令台账 | 无按钮 `403`；范围外 `404`；转交目标不存在 / 未绑定员工 / 范围外且不是该计划指导人或带教人 `404 NOT_FOUND`；无运行阶段 `409 IDP_NO_RUNNING_STAGE`；多条待办未指定 `400 IDP_TRANSFER_TASK_REQUIRED`；待办已关闭 `409 APPROVAL_TASK_CLOSED`；本人回避 `403 APPROVAL_ADMIN_SELF`；目标回避 `409 APPROVAL_SELF_REVIEW`（后四类对例外放行的目标一律 `404 NOT_FOUND`）|

## 3. 审计登记

- 计划审计沿用 `idp.plan.update`，前后值只用计划对象已登记的字段：`intervention = transfer`、`reason`、`stageId`；
  新旧审批人账号不进计划审计（避免经计划字段权限绕过审批侧可见性），只在审批实例的 `approval.admin.transfer` 里。
- `intervention` / `reason` / `stageId` 已在 PLAN 的审计展示字段登记，无新增字段，字段可见性登记不变。

## 4. 查看人 × 接口 × 字段

| 查看人 | 转交接口 | 审计 |
|---|---|---|
| 范围内、有 update 权与 transfer 按钮的 HR | 成功，返回按字段权限裁剪的计划详情 | 按既有 PLAN 审计可见性展示 intervention / reason |
| 无 transfer 按钮 | 403 | — |
| 范围外 / 空范围 | 404 | — |
| 范围内 HR，转交目标不在其 IDP 范围且不是该计划指导人 / 带教人 / 未绑定员工 / 账号不存在 | 404 NOT_FOUND（不可区分），计划与待办不变 | 无记录 |
| 范围内 HR，转交目标是该计划**当前**指导人或期间有交集的带教人（F-068，范围外也可以） | 成功；之后任何失败都是同一个 404，与上一行不可区分 | 成功时同「范围内 HR」；失败无记录 |

| 计划所有者（发起人） | 可转交（DEC-321①） | 同上 |
| 计划员工本人（冻结 U(S)） | 403 APPROVAL_ADMIN_SELF | 无记录 |

## 5. F-068：转交目标例外的口径与残余

- 指导人取计划行的**当前值**（以计划当前登记为准）；带教人取**现查**的带教记录。审批实例发起时冻结的指导人（`idp_tutor` 解析结果）不参与本例外。
- 带教记录在操作人的关键信息范围判定里要求带教双方都在范围内，范围外的带教人本来就看不到这条记录；例外正是放开这一点，所以按来源字段查看权判定，不再叠加关键信息范围。
- 失败的转交不能用来探测不可见的带教 / 指导关系：例外目标的 `adminAct` 失败统一改成普通范围外的 404，目标无关的校验在目标判定之前、对所有目标一样；只有真正成功（一次可见的状态变更：待办、审计）才表明目标是该计划的指导人 / 带教人，这是 DEC-354 接受的结果。
- 例外只放开“范围”这一道：目标是有效成员、同节点其他在办办理人（会签）、冻结主体回避、转给自己须填原因仍由 `adminAct` 判定，不变。
