> 任务：F-474-7a（DEC-776 / DEC-778；续批规划 F-474-7 行）。只出设计，实现另派 7b（缺口 #7）。
> 基线：main `c20147c6f`。作用对象全部是**复刻系统**；北森原站只引用已有取证，没有证据的标“待取证”。

## 0. 一页摘要

- 图谱是一张**二维矩阵**：行 = 职等（从高到低），列 = 职级类别（承载职级）+ 职务序列（承载职务）；单元格里写职级名 / 职务名。
- 原站有“缓存的图谱 + 最新生成时间”：页面首次只读缓存，点“重新生成”才重算。复刻**把生成结果落表**（每租户一份当前快照），页面、导出、“待确认记录”三处都读这份快照，保证“看到的 = 导出的”。
- “记录”图标实为**不规范数据**入口：生成时把无法放进图谱的职级 / 职务连同原因记成一张表，列表页分页、筛选、导出。
- 权限：新增对象 `TenantBase.JobPostAndJobLevelGraph`（原站对象注册表有）及“重新生成”“导出”两个按钮；生成 / 查看要求对职务体系各源对象有**看全部**范围，否则整体拒绝（不做部分结果）。
- **含授权项变化**（新对象 + 按钮进标准身份），7b 要按 DEC-439④ 更新授权指纹与版本，是否按授权类单独审见 §8-U1。

## 3. 数据模型与迁移草案

迁移序号占位，由 `pnpm merge:main` 定。两张表都是**派生缓存**，不是业务事实，因此不走事件溯源版本链，也不留“变更前”列；是否保留历史见 §8-U3。

### 3.1 `job_graph_snapshots`（每租户一份当前快照）

```sql
CREATE TABLE job_graph_snapshots (
  tenant_id       uuid PRIMARY KEY REFERENCES tenants(id),
  revision        integer NOT NULL DEFAULT 1 CHECK (revision > 0),
  generated_at    timestamptz NOT NULL,
  generated_by    uuid NOT NULL REFERENCES users(id),
  as_of_date      date NOT NULL,                 -- 生成时点（租户本地日期）
  contains_error  boolean NOT NULL,              -- 对应原站 containErrorData
  empty           boolean NOT NULL,              -- 没有任何可放入图谱的职务 / 职级
  issue_count     integer NOT NULL CHECK (issue_count >= 0),
  layout          jsonb NOT NULL,                -- 已布局的矩阵：列树、行、单元格、合并区域、着色键
  CONSTRAINT job_graph_layout_object CHECK (jsonb_typeof(layout) = 'object')
);
SELECT enable_tenant_isolation('job_graph_snapshots');
GRANT SELECT, INSERT, UPDATE ON job_graph_snapshots TO app_user;
```

- `layout` 保存**布局结果**而不是原始数据，页面和导出都不再二次计算：`{ rowGrades:[{id,grade,name}], levelColumns:[{typeId,name,colorKey,cells:[{levelId,name,fromRow,toRow}]}], sequenceColumns:[树，含 depth/colspan/rowspan], postCells:[{sequenceId,row,names:[…]}], merges:[…] }`。
- 大小上限在应用层检查（见 §4.3），不靠数据库。
- 每个租户一行，`revision` 每次重新生成 +1，供写请求的 `If-Match`（AGENTS §10 并发）。

### 3.2 `job_graph_issues`（待确认的职务职级记录）

```sql
CREATE TABLE job_graph_issues (
  tenant_id   uuid NOT NULL REFERENCES tenants(id),
  id          uuid NOT NULL DEFAULT gen_random_uuid(),
  kind        text NOT NULL CHECK (kind IN ('level','post')),
  object_id   uuid NOT NULL,
  object_name text NOT NULL,                     -- 生成时的名称快照，列表不再联表
  reasons     jsonb NOT NULL,                    -- [{ "code": "...", "params": ["名称", …] }]
  sort_key    integer NOT NULL,
  PRIMARY KEY (tenant_id, id),
  CONSTRAINT job_graph_issues_reasons_array CHECK (jsonb_typeof(reasons) = 'array' AND jsonb_array_length(reasons) > 0)
);
CREATE INDEX job_graph_issues_tenant_kind ON job_graph_issues (tenant_id, kind, sort_key);
SELECT enable_tenant_isolation('job_graph_issues');
GRANT SELECT, INSERT, DELETE ON job_graph_issues TO app_user;
```

- 重新生成时在同一事务里**整体替换**（先删后插）；所以这张表需要 `DELETE`，与多数追加表不同，原因是它是缓存，不是审计事实。
- 原因用**编码 + 参数**存，文案走资源文件（DEC-045），不存中文整句：

| 编码 | 对象 | 参数 | 对应原站文案 |
|---|---|---|---|
| `LEVEL_GRADE_RANGE_EMPTY` | 职级 | — | 该职级的职等范围为空 |
| `LEVEL_TYPE_DISABLED` | 职级 | 类别名 | 该职级的职级类别【X】为停用 |
| `LEVEL_GRADE_RANGE_OVERLAP` | 职级 | 重叠职级名… | 与同一类别的职级【X】、【Y】重叠 |
| `POST_LEVEL_RANGE_EMPTY` | 职务 | — | 该职务的职级范围为空 |
| `POST_SEQUENCE_EMPTY` | 职务 | — | 该职务的职务序列为空 |
| `POST_SEQUENCE_HAS_CHILDREN` | 职务 | 序列名 | 所属序列【X】，其下级序列已有职务 |
| `POST_BOUND_LEVEL_OVERLAP` | 职务 | min/max、职级名、重叠职级名 | 最低（最高）职级【X】的职等范围与同类别职级【Y】重叠 |
| `POST_BOUND_LEVEL_TYPE_DISABLED` | 职务 | min/max、职级名、类别名 | 最低（最高）职级【X】，其职级类别【Y】为停用 |
| `POST_BOUND_LEVEL_GRADE_EMPTY` | 职务 | min/max、职级名 | 最低（最高）职级【X】，其职等范围为空 |

### 3.3 不新增什么

- 不改任何职务体系主数据表；不建“图谱节点”表。
- 不存导出文件：导出每次从当前快照现生成，`no-store`，不落对象存储（同 R3-T02 先例）。
- 租户隔离：两张表都带 `tenant_id` + `enable_tenant_isolation`；快照主键就是 `tenant_id`，没有跨租户引用。

## 4. 接口与权限

路径沿用 `/api/tenant/job`。

### 4.1 生成口径（纯函数，放 `packages/domain`，禁止 IO）

输入：生成时点 `asOf`（租户本地今日）的**启用**职等、职级类别、职级、职务序列、职务（均取 `asOf` 当天有效的版本）。

1. **行**：启用职等按 `grade` 从高到低。
2. **职级**：每个职级占其类别列中 `[minGrade.grade, maxGrade.grade]` 的行区间，纵向合并，单元格写职级名；职级类别 = 列，同类别内区间重叠即不规范（`LEVEL_GRADE_RANGE_OVERLAP`）。
3. **职务序列**：按 `parentId` 成树；叶子序列各占一列，上层序列横向合并，表头行数 = 树深度（原站样本 4 层；序列最多 10 层，超过 4 层时表头行数待取证，先按实际深度）。
4. **职务**：必须有序列，且序列是叶子；必须有最低或最高职级之一。占位行区间 = 最低职级的起始职等 ～ 最高职级的结束职等（只有一端时取该端职级自己的区间）——**这是推断，原站待取证 ①**；同格多个职务按 `displayOrder, code` 排序后用英文逗号拼接（排序待取证 ②）。
5. **不规范**：命中 §3.2 任一规则的职级 / 职务**不进图谱**，写入 `job_graph_issues`；同一对象的多条原因合并在一条记录里。
6. **空图谱**：没有任何可放入图谱的职务 → `empty = true`，仍保存快照与不规范记录，页面显示原站的两条件提示。
7. 上限（应用层，超限 400，不返回部分结果）：参与计算的职务 ≤ 5000；矩阵列 ≤ 300；矩阵单元格 ≤ 100000；快照 `layout` JSON ≤ 4 MiB；单元格文本 ≤ 32767 字符。具体数值是预算假设，7b 开工前按本租户规模复核。

### 4.2 路由

| 方法 路径 | 作用 | 授权 | 说明 |
|---|---|---|---|
| `GET /graph` | 读当前快照 | 对象查看 + 范围 + 字段（§4.4） | 无快照返回 `{ snapshot: null }`；**GET 不触发生成** |
| `POST /graph/rebuild` | **同步**重新生成 | 对象按钮 `rebuild` + §4.4 | 头 `Idempotency-Key`（命令 ID）；`If-Match` = 当前快照 `revision`（无快照为 0）；同事务：算布局 → 替换不规范记录 → 写快照（`revision`+1）→ 写审计；返回新快照 |
| `GET /graph/issues` | 待确认记录分页 | 同 `GET /graph` | 查询：`kind`、`name`（包含）、`page`、`pageSize`（默认 15、上限 100）；排序 `sort_key` |
| `GET /graph/issues/export` | 导出待确认记录 | 按钮 `export` | `ids`（≤ 500）或 `all=true`；xlsx，≤ 10000 行 |
| `GET /graph/export` | 导出图谱 xlsx | 按钮 `export` | 读快照现生成，`Cache-Control: no-store`，文件名 `职务职级图谱_yyyyMMddHHmmss.xlsx`（租户时区的导出时刻），Sheet 名 `Sheet0`，无快照 409 `GRAPH_NOT_GENERATED` |

- 并发：同租户同时只允许一个生成。`pg_try_advisory_xact_lock('job-graph:'||tenant)` 取不到 → 409 `GRAPH_GENERATING`；`If-Match` 不一致 → 409 `REVISION_CONFLICT`（页面提示“图谱已被他人更新”并刷新显示新快照，不自动重试）。
- 幂等：同命令 ID、同内容重放返回同一结果；同 ID 异内容 → 冲突。生成中途失败整体回滚，旧快照保持不变。
- 错误码沿用统一表（400 / 401 / 403 / 409 / 503）；超限用 400 + 机器可读原因（`GRAPH_LIMIT_*`），数据库不可写 503。
- 审计：`job.graph.rebuild`，对象 `JobPostAndJobLevelGraph`，只记摘要（生成时点、`issue_count`、`contains_error`、`empty`、新旧 `revision`），不把整份 `layout` 写进审计。
- 导出是只读，没有命令台账 / outbox / 审计（同 R3-T02 先例）；每次请求重新授权。

### 4.3 授权对象

- 新增对象编码 `TenantBase.JobPostAndJobLevelGraph`（原站对象注册表同名，`MODULE_OBJECTS.jobGraph`），应用 = 组织员工；字段：无业务字段；按钮：`rebuild`（level `list`）、`export`（level `list`）；对象“查看”决定能否进图谱页和待确认记录页。
- 原站该菜单只给系统管理员 / 组织管理员。复刻**只预置给 `standard_org_system_admin`**，不给人事管理员、人事专员（fail-closed；需要的租户用身份详情手工授权）。

### 4.4 范围与字段：整体通过或整体拒绝

图谱把**整个租户**的职务体系名称、数值、范围和关系汇总到共享快照；布局、原因和计数也能间接披露源字段，不能只检查 `name`。规则：

- 读 / 生成 / 导出前，调用者对 `jobGrade / jobLevelType / jobLevel / jobSequence / jobPost` 五个源对象必须同时有：**对象查看权、看全部范围、下表全部字段的查看权**。任何一项缺失 → 统一 403，不返回部分图谱、原因、计数、生成摘要或文件，也不在错误体列出被隐藏的值 / 对象存在性。
- 字段编码按 `packages/domain/src/permission/module-actions.ts:65-77,258-272`；下表是生成器的源字段投影与授权清单，覆盖矩阵、原因列表以及两种导出的显式值和派生披露：

| 源对象 | 必查字段 | 披露位置 / 推导用途 |
|---|---|---|
| 五个对象共同 | `id, name, enabled, startDate, stopDate` | 快照 ID / 名称、原因参数、启停筛选与按时点入图；职级类别停用原因也会披露 enabled |
| `jobGrade` | `grade` | `rowGrades.grade`、行排序、职等区间端点、合并范围；图谱 xlsx 行头 |
| `jobLevelType` | 无额外字段 | 类别 ID / 名称和状态来自共同字段；颜色只按类别列分配，不另读隐藏业务字段 |
| `jobLevel` | `levelTypeId, minGradeId, maxGradeId` | 类别列、纵向跨度、空范围 / 重叠原因及其关联职级、职等名称 |
| `jobSequence` | `parentId` | 多级表头、叶子与下级序列关系、下级已有职务原因；depth / colspan / rowspan 仅由 parentId 树推导 |
| `jobPost` | `sequenceId, minLevelId, maxLevelId, displayOrder, code` | 序列归属、职级端点和落位范围、边界职级异常原因、同格职务顺序 |

- 本版职务的职等跨度只由 `minLevelId / maxLevelId` 所指职级的 `minGradeId / maxGradeId` 推导，不另读职务自身的 `minGradeId / maxGradeId / levelTypeId`；序列不读祖先缓存列或 `level`，职级不读 `level`，生成器须按表投影。若实现新增排序键 / 输出字段，必须同提交扩充此清单和拒绝验收，不能读了却不验。原因参数引用的其他职级、类别、序列同样适用清单，不能因其为停用或不入图就绕过检查。
- 五条路由统一调用同一个源权限检查；生成请求在取源数据前检查，**命令重放在返回台账里的旧快照前按当前成员身份、范围和字段权限再查**，重放也检查 rebuild 按钮。GET 快照、原因分页及两种导出每次都重查，包含空快照 / 缓存命中；不得以生成者权限或快照生成时权限替代。导出只有通过检查才能写响应头 / 文件字节；撤权后返回统一 403，不生成半份文件。
- 标准系统管理员已预置对这些对象的“看全部”（DEC-121），仍须经过相同对象 / 字段检查，不能按身份名称绕过。
- 数据范围默认值保持**空**（fail-closed）：没有范围行的身份恒拒绝；代码里不出现“全部组织”写死。
- “待确认记录”里的“编辑”行操作跳转到对应职级 / 职务编辑页，按钮是否显示取决于调用者对该源对象的**编辑权**，图谱对象本身不授编辑。

## 7. 验收要点（后续开发单可直接抄作 AC）

编号待分配，下面用占位 `AC-JG-xx`。

1. **AC-JG-01 同步生成**：有合规数据的租户调用 `POST /graph/rebuild`，一次请求返回新快照（`revision`+1、`generated_at` 更新），期间无任务 / 消息；`GET /graph` 立即读到同一份。
2. **AC-JG-02 矩阵口径**：职等从高到低；职级按类别列、按职等区间纵向合并；序列树生成多级列头；同格多职务逗号拼接且排序稳定。
3. **AC-JG-03 不规范记录**：构造 §3.2 九种原因各一例，`job_graph_issues` 产生对应记录，同对象多原因合并一条；不规范对象不出现在矩阵里；`contains_error` 为真。
4. **AC-JG-04 空图谱**：没有合规职务时 `empty=true`，仍保存快照与不规范记录，页面显示两条件提示。
5. **AC-JG-05 并发与幂等**：两请求同时生成，一个成功、另一个 409 `GRAPH_GENERATING`；`If-Match` 过期 409；同命令 ID 重放返回同一结果；失败回滚后旧快照不变。
6. **AC-JG-06 权限 fail-closed**：缺对象查看权 / 缺 `rebuild` 或 `export` 按钮 / 对任一源对象没有看全部范围 / §4.4 任一字段不可见 → 403；无范围行恒拒绝。专门构造“五对象查看 + 全部范围 + 全部 name 可见”的调用者，分别隐藏 `jobGrade.grade`、`jobLevel.minGradeId / maxGradeId`、`jobPost.minLevelId / maxLevelId`：逐字段验证五条路由均拒绝，无矩阵、原因、计数或文件字节。先成功生成，再撤销每个字段的查看权，用原 Idempotency-Key / If-Match 重放也须拒绝，不泄露台账快照；类别 enabled、序列 parentId 及其余清单字段逐项覆盖。
7. **AC-JG-07 租户隔离**：A 租户生成的快照与不规范记录，B 租户（含同一用户的另一租户身份）读到 0 行 / 404；B 租户生成不影响 A。
8. **AC-JG-08 导出**：文件名符合 `职务职级图谱_yyyyMMddHHmmss.xlsx`（租户时区）；单 Sheet `Sheet0`；合并区域、边框、底色符合 §5；导出内容 = 当前快照；无快照 409；超限 400；响应 `no-store`；每次请求重新授权。
9. **AC-JG-09 记录页**：分页 15/页；类型、名称筛选；导出已选 / 全部；原因文案来自资源文件并随参数替换；“编辑”按钮随源对象编辑权显示。
10. **AC-JG-10 审计**：重新生成写 `job.graph.rebuild`（同事务，摘要不含整份布局）；生成失败不写“成功”审计。
11. **AC-JG-11 授权版本**：标准系统管理员获得新对象与两个按钮，人事管理员 / 专员没有；`STANDARD_GRANT_DIGEST` 与 HISTORY 自洽；存量租户经补装获得，且不覆盖租户已撤销的项。
12. **AC-JG-12 F-039**：新路由已声明并通过准入义务检查；基准经 `merge:main` 重算后严格校验通过。
