## 0. 一页摘要

- **只做“基于盘点模板”一种机制**（`26` §1）。**评价任务与结果审批分开**（P2-05）：评价步骤（单人 / 批量 / 多人）由盘点模块自己的任务运行时执行，执行人按盘点角色解析，本人自评不经审批人路由（审批引擎会把本人改派上级并拒绝自审）；盘点结果审批走 R1 审批引擎（新审批类型「盘点结果审批」，自审禁止保留）。评价运行时与盘点流程定义都归 R3-T04 自身（DEC-304），不复用审批引擎做评价任务（§3.3）。
- **数据模型**（§2）：配置对象（分类、角色、评价规则、模块等级、盘点字段目录、九宫格 + 位置字段占用表 + 比例规则组、计算规则、字段映射、租户开关）、**准备度共享字典**（DEC-301①，PR-A 先交付，T05 只引用）、盘点流程定义、模板（**版本复制写**：模块、步骤、步骤 × 角色 × 字段权限、评价规则与模块等级的全部评分配置快照、结果规则、流程节点）、项目（状态机、向下公开、共享组织、校准原因必填字段）、盘点对象（固定列 + 盘点字段值表；**项目结束不改对象业务状态**，P2-06）、指标快照与模块结果、评估记录（对象 × 步骤 × **角色** × 执行人 × 指标，P2-08）、盘点继任信息（稳定行 ID、kind × direction）、校准会（参与者授权）、校准路径、结果审批 / 快照、提名、计算 run、同步 run（冻结快照）、outbox。
- **计算**（§4）三层：① 指标 / 模块算分（纯函数）；② 模板结果设置公式；③ 盘点计算规则。**持久化保存**（单人、批量逐格、含盘点信息字段）在引用字段变化时触发 ② ③（P2-02，DEC-260）；失焦只做不落库的预算分。**一次逻辑计算 = 一个 calc run**：总体 = 本次计算对象（排除终止对象）在 run 开始时冻结，排名对全体一次性求值，分页只用于读写不用于求值（P2-03，DEC-301②）。公式输出经统一的目标字段适配（P2-04）：非法输出 = 该项目失败，不触发数据库错误。计算主体按最保守口径：**显式授权的系统主体**执行，所属人失效或撤权时计算失败（DEC-301 / 304，待定 Q-M0-125）。排名口径按 **DEC-302**（降序；并列 1、1、3；百分位 = 名次 ÷ 参与人数 × 100 保留两位小数、数值越小越靠前；空值不参与不计数、自身为空；范围可限定到单个项目）；与 F-033 现有 `Ranking`（2～4 参、百分位不舍入、自身为空报失败）的差异由 **F-045** 单独对齐（DEC-304），本任务依赖 F-045 合并（P2-01）。
- **取数端口**（§5）：绩效 ← 人员子集「考核结果」；360 ← #107 `loadSurvey360Port`，契约补齐由 **F-046**（#107 合并后单开，DEC-304）交付，本任务依赖 F-046；测评 ← 人员子集「测验结果」（归属待定 Q-T04-02）；排名 ← run 总体；人才评定 / 参数规则端口不注入。指标来源：人才标准 ← #106 端口，**引用守卫与首个引用入口同一 PR 交付**（P2-17）；任职资格 ← 端口接口由本任务定义，由 R3-T02 实现并登记。
- **权限**（§6）：应用 `TalentReview` 独立数据范围，范围解析依赖 #106 / #107 引入的“按对象所属应用解析”契约（C-03，P2-07）；每个对象的范围锚点（项目 / 模板 / 校准会 = 所属组织；盘点对象 / 评估 / 评价关系 / 继任 / 提名 = 对象员工，`26` §3.9 各页签按对应实体）统一列表；步骤 × 角色 × 字段的可见 / 可编辑模型；校准会参与者关系守卫；“输出路径 → 权限对象 / 字段 → 派生值规则”表覆盖写响应、重放与历史（P2-09）。
- **同步端口契约 v2**（§8，DEC-301①）：稳定 run 驱动——触发时冻结快照（对象结果、逐提名行、健康度、版本），消费方按 run 读取、按提名行写回执；幂等键 = `(runId, consumer)` + 逐行；源读取按 run 的主体冻结，目标写入由消费方按同一主体模型复核（P2-10～13）。
- **口径清单**（§11）：Q-M0-81 / 84 剩余点；设计自定项 D-01～D-20；待定项一律“待定 + 选项”，不自选（Q-M0-125 取证中）；契约协调项 C-01～C-06（C-01 → F-045、C-04 → F-046）。
- **PR 切分**（§12）：开工前置 = F-045、F-046 合并 + gate ✅ + Q-M0-125 清零；PR-A 契约与准备度字典（首个 PR，T05 依赖）；PR-B 配置、流程定义、模板、项目（含人才标准引用守卫，依赖 #106）；PR-C 对象、评估、计算（360 接线依赖 F-046）；PR-D 九宫格、校准、结果审批、同步实现。迁移每 PR 1 个，编号以合并时 main 顺延（main 0062；#106 占 0063；#107 占 0063 / 0064）。

### 3.3 评价任务运行时与盘点流程定义（P2-05）

**为什么不复用审批引擎做评价任务**：`packages/domain/src/approval/routing.ts` 的 `decideNode` 把“候选人 = 流程主体本人”改派为其直线经理（`origin = self_skip_manager`），`approval/actions.ts` 的 `assertNotSelf` 拒绝发起人或主体本人审批；会签席位解析（`approval/engine.ts countersignSeats`）会合并同一用户的多席。盘点需要本人自评、同一人可在不同角色各占一席、步骤 × 角色 × 字段权限，三者都与引擎的审批语义冲突。

**归属（DEC-304）**：评价任务由盘点模块自有运行时执行；盘点流程定义（`talent_review_flows`）归盘点设置（R3-T04），模板版本内冻结节点副本。

| 动作 | 规则 |
|---|---|
| 启动采集 | 项目 → 对象（initial）逐个：按模板版本冻结的步骤 × 角色解析执行人写 `evaluators`（§3.4），为第一个步骤建 `tasks`（round = 1）；缺人：`designated` 缺 → 400 `EVALUATOR_MISSING` 整批不启动；`direct / indirect` 无上级 → 400 `EVALUATOR_UNRESOLVED`（无异常管理员兜底，和审批引擎 DEC-054 不同，设计自定 D-16） |
| 保存 | 本席位任务 pending 时可写本席位评估记录 / 可编辑字段 / 继任信息；触发 §4.4 |
| 提交 | 必填校验（评分 / 评语 / 字段 / 继任必填）；批量提交前对整批做 `flow` + `block` 比例校验；席位任务 → submitted；节点完成条件：single = 该席位提交；countersign = 节点全部席位提交（无“席位合并”）；节点完成 → 建下一步任务；最后一步 → 对象 `flow_ended` |
| 驳回上一步（allow_return） | 当前节点席位 → returned；上一节点席位任务重开（round + 1），其已提交记录保留可改 |
| 转交（allow_transfer） | 本席位任务 → transferred，新建同席位任务给被转交人（`evaluators` 增一行 source = transfer）；原执行人的已保存记录随席位转移（执行人字段改为新人，审计留痕） |
| 不同意（allow_disagree） | 对象 → `terminated`，当前步骤全部席位任务 cancelled、评估记录 `invalid = true`，①重算 |
| 管理员撤销 / 重开 | 项目管理员：撤销采集 → 对象 `initial`、任务全部 cancelled（记录保留 invalid）；终止对象可重开采集（新 round） |

**已否决的备选（记录，DEC-304）**：复用审批流程定义 + 审批引擎运行评价任务。需要在共享审批域加 `selfPolicy: 'allow'`、会签席位按角色不按用户合并、新增审批人表达式（隔级上级、业务指定人员）、`BusinessSnapshot.pinnedProcessId` 进入匹配与模板 / 已发布版本核对等契约，改动集中在共享审批域且与 DEC-058 自审语义冲突，不采用；评价步骤的“流程编码进入匹配 / 版本对应”问题在自有运行时下由模板版本冻结节点副本解决。

**结果审批**：审批类型 `talent_review_result`（`APPROVAL_TYPES` 登记，objectCode `TalentReview.ResultApproval`），业务类型 `talent_review`，适配器 `talent-review/approval-adapter.ts`；发起人 = 项目管理员；`subjectEmployeeId = null`；快照 `fieldObjectCode = TalentReview.ResultApproval`，各对象的校准后字段作为 `foreignFields`（对象 `TalentReview.Object`，DEC-057 最小披露按该对象字段权，盲审 DEC-058 按嵌套字段）；审批中编辑开放校准后字段；通过 → 写回对象并记 `decided_snapshot`、`result_version + 1`；不同意 → 审批单 `rejected`，对象不变；自审禁止由引擎保留（发起人不能审批）。流程匹配按 DEC-017（类型 + 发起条件：项目所属组织、盘点分类）。

## 4. 计算

### 4.1 三层计算、计算单位与主体

| 层 | 内容 | 位置 |
|---|---|---|
| ① 指标 / 模块算分 | TR-R21～R24 | `packages/domain/src/talent-review/scoring.ts`（纯函数） |
| ② 模板结果设置 | 模块结果 → 盘点字段（TR-R19） | 引擎 `evaluateBatch`，字段目录 = `模块.<名>.得分 / .等级` |
| ③ 盘点计算规则 | 外部取数 + 对象字段 → 盘点字段（TR-R27～R30） | 引擎 `evaluateBatch` + §5 端口 |

**计算单位 = calc run**（P2-03，DEC-301②）。一次 run：确定本次计算对象 → 按有效规则分组 → 冻结总体 → 预读端口数据 → ①→②→③ 在内存中对全体一次性求值 → 按页写入 → 收口。

**计算主体（D-04，DEC-301 / 304；待定 Q-M0-125，取证前按最保守口径）**：计算由**显式授权的系统主体**执行——租户管理员在盘点设置里指定一个开通时预置、不可登录的“盘点系统服务账号”成员（`talent_review_settings.system_principal_user_id`），并在用户授权里显式授予它 TalentReview 身份、对象权限与数据范围（无默认、无隐式看全部；与 `apps/api/src/system-actor.ts` 的系统任务一样不冒用真实用户：审计 actor 记为系统，run 上记录 `principal_user_id`）。run 开始时：① 系统主体未指定、无 TalentReview 身份或无本项目对象查看权 → run `principal_unavailable`；② **项目所属人失效或撤权**（已停用 / 不再持有 TalentReview 身份 / 对本项目无 `calculate` 按钮）→ 同样计算失败（`OWNER_UNAVAILABLE`）；两种失败都不写任何值，对象 `calc_status = failed`、`calc_message = "计算失败：计算主体不可用（…）"`，不回落到触发人、不回落到看全部。取数端口按系统主体的范围与字段权预读裁剪。待办触发（`task_save`）同样以系统主体执行、同样校验所属人。Q-M0-125 取证后若选触发人 / 所属人方案，只改主体解析函数与对应测试。

### 4.5 排名总体、分页与输出适配（P2-03 / P2-04，DEC-301②）

- **总体**：run 的本次计算对象（`requested ∖ terminated`，手动勾选或待办的单对象）即排名总体（手册“排名范围受本次计算对象范围与筛选条件影响”）；公式自身的范围条件再在总体内过滤（DEC-302：范围可限定到单个项目，本设计的总体本就不跨项目）；总体在 run 开始时冻结（对象 id 列表 + 字段值快照读入内存）。
- **排名口径（DEC-302，坐实 DEC-262①）**：排序字段按**降序**，并列为竞争排名（1、1、3）；百分位 = 名次 ÷ 参与人数 × 100，**保留两位小数**，数值越小越靠前（不是统计学百分位）；排序字段为**空的对象不参与排名、不计入参与人数**，其自身的排名 / 百分位结果为空（不是计算失败）；示例：4 人参与，第 1 名 25.00、第 4 名 100.00；并列 1、1、3 时两个第 1 名都是 25.00、第 3 名 75.00。参与人数 = 通过范围条件且排序字段非空的对象数。
- **按人采用不同规则**：按有效规则分组，每组一次 `evaluateBatch`，总体 = 该组对象（本次计算且用该规则的对象）；组间互不参与排名（设计自定 D-17，🟡 原站未取证，列入 Q-M0-125 附注）。
- **失败对象**：引擎按项目逐个判定——某对象某依赖项目失败时，该对象只在**依赖它的项目**上不参与总体（`DEPENDENCY_FAILED`），其余项目照常参与；`calc_status = failed` 不整体排除对象。
- **一次性求值**：全组一次 `evaluateBatch(items, subjects)`（不注入 `RankingPort`，引擎默认总体 = subjects 叠加已算值）；分页只用于 DB 读（端口与字段值按 500 一页预读）和写（每 500 对象一个事务，run 记录每页完成情况，崩溃后按 run 续写，写入幂等按 (run, object)）。整体一致性：循环依赖在求值前判出（DEC-274）→ 整 run 不写；其余按对象 / 项目写值与失败。
- **性能**：目标 2 000 对象 × 10 项目 ≤ 5 s、10 000 × 10 ≤ 30 s（PGlite 与真 PG 各一条性能用例，断言上限）；总体上限 20 000 对象 / run，超出 413 `CALC_POPULATION_TOO_LARGE`（设计自定 D-18）。
- **输出适配**（两类公式共用 `coerceToField(field, value)`，P2-04）：

| 目标字段类型 | 允许的引擎值 | 转换 | 失败（该对象该项目失败，不写、不抛 DB 错误） |
|---|---|---|---|
| number | number；数字文本（`"5"`）；empty | 文本按 `ToNumber` 语义转；按 `precision` 存 | 非数字文本、boolean、date、option → `OUTPUT_TYPE_MISMATCH`“盘点字段“X”计算项目计算有误，详细信息：输出不是数值” |
| option | number / text / option，值与某启用选项的 **value** 相等；empty | 写 option_value | 无匹配选项 → `OUTPUT_OPTION_INVALID`（文案含输出值不含隐藏字段） |
| text | 任意标量；empty | 格式化（数值按 precision；日期 ISO；布尔 true / false） | — |
| date | date；ISO 文本；empty | 存日期（精度到日） | 其他 → `OUTPUT_TYPE_MISMATCH` |
| boolean | boolean；0 / 1；"true" / "false"；empty | | 其他 → `OUTPUT_TYPE_MISMATCH` |
| multi_option、`system_written` 字段（位置字段）、pair 的 before 字段被 ② 写入 | **不允许作为公式目标**，保存计算项目 / 结果规则时 400 `TARGET_FIELD_NOT_ALLOWED` | | |

empty 一律写 null（清空），空串视为 empty。

### 8.3 幂等、版本、重试（P2-12）

- **幂等键**：消费方命令 ID = `${runId}:${consumer}`（确定性），T05 的 `succession_sync_batches.command_id` 用它；同一 run 对同一 consumer 只有一个批次；重复投递 / 重试 = 同一命令 ID 重放。回执按 (run, consumer, nominationId) 唯一；消费方写入继任与 `recordOutcome` 放在**同一事务**（T05 事务内调用本端口）。
- **重试**：`retryable = true` 的失败行可由消费方在新一次执行（同命令 ID）中重试，已 `synced` 行跳过；永久失败码（`SUBJECT_IN_PROCESS`、`TARGET_NOT_KEY_POSITION`、`TARGET_OUT_OF_SCOPE`、`SUCCESSOR_NOT_ACTIVE`、`READINESS_UNKNOWN`、`TARGET_NOT_FOUND`、`ACTOR_REVOKED`）不重试；基础设施错误 `retryable = true`。
- **unknown**：消费方事务结果未知时，先 `getOutcomes(runId, consumer)` 回查，已有回执即视为完成，否则按原命令 ID 重放（AGENTS §10 幂等口径）。
- **版本**：run 冻结后不随项目变化；项目重启把本项目所有未产生回执的 run 标 `superseded`（`supersededByRunId` 指向重启后的新 run，无新 run 时为空）；消费方读到 `status = superseded` 的自动 run 一律写 `superseded` 回执、不写继任；手动 run 不被取代。场景“结束 → 重启改值 → 再结束”：E1 run 被 superseded，E2 run 新冻结，消费 E1 只写 superseded 回执。
- outbox：`pending → sent / failed / unknown`，失败按次数重投（同事件 ID 幂等），`unknown` 时投递器先查消费方是否已有回执。

### 8.4 授权（P2-13）

- **源读取**：由 run 冻结时的主体决定（§8.1），之后消费者读快照为可信读取（`viewer = { kind: 'trusted' }`），不再放宽也不再收窄。
- **目标写入**：消费方（T05）在执行时以 run 的 `principalUserId`（自动 = 系统主体，同样须被显式授予继任写权限与范围）/ `actorUserId`（手动）为主体复核目标组织 / 职位是否在其当前继任范围、是否仍有继任写权限（DEC-301③ 同一主体模型）；撤权 → 该行 `ACTOR_REVOKED` 永久失败。内部 trusted 读取不代替目标写授权。
- `manualOverride` 只在 `trigger = sync_requested` 时可为 true，否则 400。

### 8.5 其他约定（P2-10）

- 范围内覆盖：`scopeOrgIds` 来自手动触发的选择（自动触发为空数组 = 不适用）；消费方按策略（SC-R14，开关归 T05）处理。
- target 方向：`direction = 'target'` 行照常进 run；是否写正式继任记录待定 Q-T04-10（与 T05 Q-SC-11 一并取证），决定前消费方按 `skipped` 回执。
- 健康度：`listRunOrgHealth` 来自 `talent_review_project_org_health`（T05 健康度端口登记后由“计算健康度”写入，含 manual 与空值），未计算为空数组。
- 三档取数 `readReviewFields`：tier 1 = `context` 指定的项目 / 校准会（会 → 其项目）且员工在其中；tier 2 = 进行中项目里 `business_date ?? planned_start_at` 最近的（并列取 `code` 小者）；tier 3 = 已结束项目里 `ended_at ≤ asOf` 最近的（并列按 `result_version` 大者再 `code`）。对象 `terminated` 不计。
- 绿化率：`context.projectId` 给定用该项目，否则取该组织（行政维度子树内员工为对象）的 tier 3 项目；绿化率参考九宫格缺失或分母 0 → `rate = null`。
- 批量：对象页 ≤ 500、提名页 ≤ 2000，是读取分页；消费方的逻辑批次 = 一个 run。
- 稳定性：`fields` 键为盘点字段 `code`；类型元数据经 `listReviewFields`。

## 9. 并发、幂等、锁（P2-16）

**统一锁序**（所有写入口与后台任务一致；首个排他资源按操作列出）：

```
员工行（FOR SHARE，仅新增对象 / 设置执行人时）
→ 盘点项目（FOR SHARE：对象级操作、计算、校准、加人；FOR UPDATE：启动 / 结束 / 重启 / 删除 / 编辑配置）
→ 校准会（FOR SHARE：校准、加人移人；FOR UPDATE：结束 / 删除）
→ 结果审批单（FOR UPDATE：发起 / 撤销 / 审批回调）
→ 盘点对象（FOR UPDATE，按 id 升序批量锁）
→ 评估记录 / 任务 / 继任行（按对象顺序）
→ 审批实例（引擎内部，结果审批）
```

| 操作 | 加锁顺序 |
|---|---|
| 计算 run | 项目 S → 对象 X（总体按 id 升序，分页写时每页重新按序加锁；总体冻结值已在内存） |
| 评估保存 / 提交 | 项目 S → 对象 X → 任务 / 记录 |
| 校准（拖拽 / 表单） | 项目 S → 校准会 S → 对象 X |
| 校准会结束 | 项目 S → 校准会 X → 对象 X（升序） |
| 项目结束 / 重启 | 项目 X → 校准会 S（存在时）→ 对象 X（升序）→ 同步 run |
| 删除对象 | 项目 S → 对象 X（任务 / 记录级联） |
| 结果审批发起 / 回调（适配器 `lock`） | 项目 S → 审批单 X → 对象 X（升序）→ 引擎锁实例 |
| 手动同步 | 项目 S → 对象 S（只读冻结） → run |

校准（会 S → 对象 X）与校准会结束（会 X → 对象 X）在校准会这一级串行，不再出现互等；真 PG 交错用例：① 校准 vs 会议结束同时发生；② 同一对象两席位并发保存；③ 两次开始计算并发；④ 校准拖拽 vs 开始计算；⑤ 项目结束 vs 评估提交；⑥ 位置字段交叉列并发（P2-14）。

幂等：`Idempotency-Key` + `If-Match`（DEC-067），复用 `runCommand`；重放按当前权限复核。批量上限：添加对象 / 导入 / 批量提交 / 开始计算 / 校准会加人 单次 ≤ 500（跨页全选分次 = 体验差异，DEC-301②；**不改变排名总体与失败语义**，§4.5）。审计：每个写入口同事务 `recordAudit`，显式传 `scope`（org / employee）；计算写入按对象一条含 before / after；不伪造审计。

## 13. 边界用例（实现时逐条写测试）

1. 同一员工加入同一项目两次 → 409 `OBJECT_DUPLICATE`；从其他项目添加候选按管理单元过滤并去重。
2. 启动采集：`designated` 缺人 / `direct` 无上级 → 400 列出对象，整批不启动，前后读不变。
3. 同一人多席位（自评 + 某角色）→ 两个任务、两套记录；提交一席不影响另一席。
4. 模板在项目使用中被编辑 → 新版本只影响之后新建对象；评价规则上下限 / allow_unable / 等级修改同样不影响（P2-15）。
5. 项目重启：对象状态不变；未消费 run → superseded；重启后再次结束产生新 run。
6. 开始计算时对象正被保存 → 行锁串行；总体值在 run 开始冻结。
7. 计算规则含循环且只勾选部分对象 → 整 run 不写，未勾选对象不变。
8. 501 人一次计算末人 501；分页写入不改变名次（P2-03）。
9. 公式输出 `"abc"` 到数值字段 → 该项目失败、其余项目写入、事务不回滚（P2-04）。
10. 校准会中对象被另一校准会加入 → 409；校准拖拽到同一格不记路径；轴不可拖 / 缺必填原因 → 400。
11. 校准与会议结束并发 → 会议级串行，无死锁（真 PG）。
12. 结果审批进行中管理员改校准后字段 → 409 `RESULT_APPROVAL_PENDING`。
13. 下级管理员对向下公开项目的写入 → 403 `PROJECT_READONLY`。
14. 被盘点人调动后：执行人以启动时为准；团队人才视图按当前任职组织。
15. 终止对象不计比例 / 排名 / 绿化率 / calc run；管理员仍可编辑字段。
16. 删除对象：级联任务 / 记录 / 继任行 / 路径并写快照审计；流程中先取消任务。
17. 位置字段交叉占用（A.before = F 与 B.after = F）→ 409；并发两条只过一条。
18. 所属人被停用后触发计算 / 结束项目 → run `principal_unavailable` / 409，不写值。
19. 批量导入末条非法 → 整批回滚，台账 / 审计 / outbox 计数不变。
20. 撤权后重放写命令 → 403 / 404 且数据不变。
21. 10 000 对象 run 的内存与耗时在上限内；20 001 → 413。
