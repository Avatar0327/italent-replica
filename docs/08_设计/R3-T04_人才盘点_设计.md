## 0. 一页摘要

- **只做“基于盘点模板”一种机制**（`26` §1）。盘点流程复用 R1 审批引擎：盘点模板绑定一条审批类型为「盘点流程」的流程，模板的每个步骤对应流程的一个节点；多人评估步骤 = 会签节点（`26` TR-R18）；“不同意”沿不同意出口结束 → 盘点对象「终止」（TR-R25）。盘点结果审批复用同一引擎（审批类型「盘点结果审批」）。为此需要一个**契约改动**（§12 PR-A 首次合并时带上）：审批域新增两个审批类型、一个业务类型 `talent_review`、两个审批人表达式（隔级上级、业务指定人员）。
- **数据模型**（§2）：配置对象（分类、角色、评价规则、模块等级、盘点字段目录、九宫格与比例规则、盘点计算规则、字段映射、准备度）、盘点模板（**模板版本**：结构按版本复制写，盘点对象钉住版本，满足 TR-R12 / TR-R20“修改不影响已发起的盘点”）、盘点项目（状态机、向下公开、共享组织）、盘点对象（固定列 + 盘点字段值表，`26` 本租户 105 个自定义字段 → 规格要求自定义字段，允许字段值表）、指标 / 模块结果（指标在对象创建时快照）、评估记录（对象 × 步骤 × 执行人 × 指标）、盘点继任信息、校准会与校准路径、结果审批与快照、提名、同步 outbox。
- **计算**（§4）分三层：① 指标 / 模块算分（纯领域函数，TR-R21～R24）；② 模板“盘点结果设置”公式（模块结果 → 盘点字段，走 R3-T00 引擎，字段目录 = 模块）；③ 盘点计算规则（走 `evaluateBatch` + 取数端口）。触发矩阵按 DEC-260 / 257 / 274：评估保存只在引用字段变化时触发、含排名函数的项目在待办触发时不算；手动“开始计算”一律算；循环依赖保存只提示、计算整次不写并报“计算失败：循环依赖 A→B→A”；部分失败其余照常写入、对象“计算失败”逐项列原因。排名并列 1、1、3（DEC-262①）。**计算以项目所属人的身份与范围取数**（可信系统上下文，同定时任务），不以触发人（§4.6）。
- **取数端口接线**（§5）：绩效 ← 人员子集「考核结果」；360 ← #107 的 `loadSurvey360Port`（需按 F-033 合并后的端口契约补 `endAt / reportGeneratedAt / activityId`，并补两个字段别名，§5 表 360 行）；测评 ← 人员子集「测验结果」（**main 上尚无此子集表**，PR-B 作为契约建表，§5 表测评行）；排名 ← 本次计算对象；人才评定、参数规则 ← 端口未接入（`DATA_UNAVAILABLE`）。指标来源：人才标准 ← #106 的 `loadTalentCriterion`；任职资格 ← R3-T02 尚无代码，端口占位（`unavailable`）。
- **权限**（§6）：对象目录新增 `TalentReview.*` 11 个对象；数据范围按（用户 × TalentReview）管理单元，项目 / 校准会可见性 = 管理单元 ∪ 上级向下公开（只读）∪ 共享组织（只读）（TR-R3）；评估人 / 校准人 / 被盘点人上级 / 本人走“关系入口”（待办、团队人才、我的盘点），不经管理单元。所有路由先用 `module-route-access.ts` 公共守卫，F-039 PR-A 合并后补框架声明。“查看人 × 接口 × 字段”矩阵见 §6.4。
- **盘点结果同步端口**（§8）：供 R3-T05 继任同步、R3-T06 入池、组织健康度（SC-R16）引用；同步时点 = 项目结束 / 校准会结束 / 手动同步三种触发，经 `talent_review_outbox` 事件 + 同步只读函数 + 回执写回；字段按查看人裁剪，永不返回评估人逐人打分。
- **口径清单**（§11）：Q-M0-81 / 84 剩余点逐项列入；设计自定项 14 条（供设计审否决）；需产品决策 4 条（§11.3，停下等总编排转达）。
- **PR 切分**（§12）：PR-A 契约 + 配置对象 + 模板 + 项目；PR-B 盘点对象 + 评估待办 + 算分 + 计算规则 + 带入上次 + 提名；PR-C 九宫格落位 + 比例校验 + 绿化率 + 校准会 + 结果审批 + 同步端口。预计迁移：PR-A 2 个（生成 + 自定义隔离）、PR-B 2 个、PR-C 2 个，编号以合并时最新 main 顺延。

### 3.3 盘点流程 = 审批实例（R1 审批引擎）

- 审批类型 `talent_review_flow`（「盘点流程」，`APPROVAL_TYPES` 登记，适配器 `talent_review`），业务单 = 盘点对象；启动采集时逐对象 `startOrResume`。流程匹配按 DEC-017：先按类型过滤，再按优先级判定发起条件（发起条件字段 = 项目所属组织、盘点分类、对象主职部门）。
- 节点 ↔ 模板步骤按 `node_key` 对应；会签节点 ↔ multi 步骤。节点的 `approver`（单人）/ `approvers`（会签）表达式决定执行人：盘点角色的 resolver 映射为审批人表达式（`direct_manager` → 直接上级；`indirect_manager` → **新增**隔级上级；`self` → 流程主体本人；`designated` → **新增** `business_designated`，由业务快照 `designatedAssignees[roleKey]` 提供人员）。这是对审批域的契约改动（§12 PR-A 首批合并）。
- 执行人在启动采集时解析一次并落到 `talent_review_evaluators`（随实例任务；之后由引擎的转交 / 加签改变任务归属时同步更新）。
- 动作映射：提交 = `approveTask`（校验必填评分 / 评语 / 继任必填 / 字数，TR-R43、R44；批量提交逐对象一次命令、整体回执）；驳回上一步 = `rejectTask`（按节点配置）；转交 = `transferTask`；不同意 = `disagreeTask` → 适配器 `disapproved` → 对象 `terminated`，当前步骤评分 `invalid = true` 并重算（TR-R25）；撤销 = 管理员 `withdraw` → 对象回 `initial`。
- 适配器快照（DEC-057 最小披露）：`fieldObjectCode = TalentReview.Object`，`values` 只含当前步骤可见的盘点字段；评估打分不是审批表单字段（各执行人各自的评估记录），盲审（DEC-058）按盘点字段判断。
- 批量盘点（mode = batch）：同一执行人在同一步骤的多个对象任务在待办里按项目聚合展示，列表内编辑实时保存（每格一次 `PUT` 评估命令）；批量提交 = 对勾选对象逐个 `approveTask`，提交前对整批做比例规则 `flow` + `block` 校验（TR-R44）。
- 盘点结果审批（TR-R41）：审批类型 `talent_review_result`，业务单 = `talent_review_result_approvals`；节点“审批中编辑”开放校准后字段（DEC-057 按 `TalentReview.Object` 字段权裁剪）；通过时把编辑后的结果写回对象并记 `decided_snapshot`。

## 4. 计算

### 4.1 三层计算与归属

| 层 | 内容 | 位置 |
|---|---|---|
| ① 指标 / 模块算分 | 指标结果分、模块分、按指标数目匹配等级、多人角色分（TR-R21～R24） | `packages/domain/src/talent-review/scoring.ts`（纯函数，无 IO） |
| ② 模板结果设置 | 模块结果 → 盘点字段公式（TR-R19） | 引擎 `evaluateBatch`，字段目录 = `模块.<名>.得分` / `模块.<名>.等级`，无端口 |
| ③ 盘点计算规则 | 外部取数 + 对象字段 → 盘点字段（TR-R27～R30） | 引擎 `evaluateBatch` + §5 端口；项目级 / 按人级规则 |

计算顺序：① → ② → ③（③ 可引用 ② 写入的字段）。每次计算在一个事务内：锁对象（按 id 排序 FOR UPDATE）→ 读字段值 → 求值 → 写值 / 写 `calc_status`、`calc_message`、`calc_at` → 审计（对象字段级变更，DEC-216）。

### 4.2 指标 / 模块算分（TR-R21～R24）

- 指标打分值：numeric 规则取分值；grade 规则取等级对应分值（版本快照 `module_levels`）；`unable = true` 或未评价不参与。
- 指标结果分 = Σ(各执行人打分 × 步骤评价权重) / Σ(参与的步骤评价权重)，只计有评分权限且有有效评分的步骤（AC-TR-05：60% × 4 + 40% × 5 = 4.4）；多人步骤先按角色：指标角色分 = 该角色所有有效评分的平均（TR-R24），步骤分 = 各角色按权重再加权。
- 模块结果分：算术平均 = Σ指标结果分 / 有效指标数；算术求和 = Σ；加权求和 = Σ(结果分 × 指标权重) / Σ有效指标权重；按指标数目 = 取最后一个有有效评价且有评分权限的步骤的结果，按 `min_count` 匹配模块等级。
- 模块等级：按 `module_levels`（得分区间）匹配；无匹配为空。
- 管理员调整（TR-R26）：写 `adjusted_*`，`final_* = adjusted ?? computed`；**不触发**②③；“开始计算”时 ① 只重算 `computed_*`，`adjusted_*` 保留，`final_*` 以 adjusted 优先（AC-TR-12）。

### 4.3 模板结果设置公式（TR-R19）

- 保存校验：`validateFormula(formula, { isKnownField, fieldKind })`，字段目录 = 版本内模块的 `得分`（number）/ `等级`（text），目标字段来自盘点字段目录；计算项目间依赖用 `orderComputationItems`。
- 求值：对象 = 模块结果读取器（`final_score / final_level`），空值与类型按 DEC-257 / 270 语义。

### 4.4 盘点计算规则（TR-R27～R30、`26` §8）

**保存 / 启用**（PR-A）
- 每个计算项目 `validateFormula`：语法、函数名、参数个数、参数类型（DEC-287 统一类型推导）、未知字段（字段目录 = 盘点字段目录 ∪ 本规则其他目标字段 ∪ 端口记录对象 `考核结果.* / 360结果.* / 测验信息.* / 盘点活动.*`）。**文本与数字字面量比较**在保存时拦截（DEC-257 “随 R3-T04 公式编辑器补”）：用引擎导出的 `TypeInference` 对比较节点两侧推导，确定一侧文本字面量、一侧数字时报 `ARGUMENT_TYPE`，文案照原站“第 N 行公式有误，缺少半角双引号”（`26` §8.5）；推导不确定时只提示。若需在 `packages/domain/src/expression` 增加比较节点的类型核对入口，作为契约小改动随 PR-A 提交。
- `orderComputationItems(items, { isKnownField, fieldKind })`：循环依赖 **不拦截**，响应 `warnings` 与 `cycles`（DEC-274）；优先级与依赖矛盾给提示。
- `uses_ranking` 由 `functions` 中带 `skipInTodoTrigger` 的函数推出。

**触发矩阵**（DEC-260 / 257 / 274；AC-TR-12）

| 触发 | 计算对象 | 计算项目 | 取数身份 |
|---|---|---|---|
| 评估保存（失焦 / 列表内编辑） | 本对象 | ①（本执行人步骤分与结果分） | — |
| 评估提交 / 节点结束 / 驳回 / 不同意 | 本对象 | ① → ② → ③ 中**引用的盘点字段本次有变化**的项目（引用集合 = `validateFormula().fields` 经绑定解析；含依赖链下游）；`uses_ranking` 的项目**跳过**（结果保持旧值，不写、不报错，`calc_message` 注明“含排名函数，待办触发不计算”） | 项目所属人（§4.6） |
| 管理员「开始计算」（项目 / 勾选对象） | 勾选对象（默认项目全部非 project_ended 对象；terminated 对象也算，但不计入排名范围与比例） | ① → ② → ③ 全部项目，不论引用是否变化 | 项目所属人 |
| 管理员调整指标结果 | — | 不计算（TR-R26） | — |
| 校准会保存 / 结束 | 本对象 | 不重算 ①②③；只写校准后字段并重算落位（§4.5） | — |
| 结果审批通过 | 本对象 | 同上 | — |

**失败口径**
- 循环依赖：`evaluateBatch` 返回 `CYCLIC_DEPENDENCY` → 本批**所有对象所有项目不写值**，每个对象 `calc_status = failed`、`calc_message = "计算失败：循环依赖 A→B→A…"`（DEC-274），写审计。
- 部分项目失败：其余项目照常写入；对象 `calc_status = failed`，`calc_message` = “最近计算时间:… 盘点字段“X”计算项目计算有误，详细信息：<引擎 message>”逐项换行（`26` §8.5，DEC-257）；失败原因不含被隐藏字段的取数结果（引擎已保证）。
- 排名：并列同名次、后续跳号（DEC-262①）；百分位 = 名次 / 人数 × 100；本人不在范围 → `OUT_OF_SCOPE`（DEC-299 Q2）。
- 空值 / 文本：全部沿用引擎 `DEFAULT_SEMANTICS`（DEC-257 / 264 / 270 / 299），本任务不另配。

### 4.5 九宫格落位与比例规则（PR-C）

- 落位（纯函数 `locate(matrix, values)`）：按 `placement_source` 取校准前 / 校准后的 X、Y 字段值 → 轴分段 → 格子号；任一轴无值 → 不落位；结果写位置字段（before / after 各自）。校准拖拽直接写校准后 X / Y 字段与校准后位置字段并记路径。
- 比例校验（纯函数 `checkRatio(group, placements)`）：人数 < `min_population` 跳过；范围 = 校验范围内未终止且已落位的对象；组内规则“且”；`block` 时拒绝（项目结束 / 校准会结束 / 批量提交），`warn` 时返回 `warnings`。**项目 / 校准会结束时的校验范围 = 该项目 / 校准会的全部对象**（结束是管理动作，不按操作人数据范围），页面展示的“比例异常 N”按查看人范围另算（TR-R34；§11.2 D-05）。
- 绿化率 = 计入格子人数 / 该九宫格落位总人数（分母不含未落位与终止对象），只读函数，经 §8 端口暴露给组织继任地图。

### 4.6 计算身份与取数范围

计算规则求值用**项目所属人（`projects.owner_id`）**的身份解析（用户 × TalentReview）管理单元与各取数对象的字段权限：端口按该范围预读；范围外对象的取数返回 `forbidden` → 该项目 `DATA_FORBIDDEN` 计算失败（不泄露值）。理由：待办触发时执行人通常无绩效 / 360 查看权，按触发人取数会让计算规则在流程中必定失败；定时任务同理。属设计自定（§11.2 D-04）。

```ts
  /** 绿化率（TR-R35）：绿化率参考九宫格按组织汇总，供组织继任地图。 */
  greenRate(tx: Tx, input: {
    tenantId: string; projectId: string; orgIds: readonly string[]; viewer: TalentReviewSyncViewer | TalentReviewSyncByUser;
  }): Promise<ReadonlyMap<string, { readonly green: number; readonly placed: number }>>;
  /** 消费者写回逐对象结果；同一 runId 幂等；错误报告在项目 / 校准会详情可见。 */
  recordOutcome(tx: Tx, input: {
    tenantId: string; runId: string; consumer: 'succession' | 'talent_pool';
    items: readonly { objectId: string; status: 'synced' | 'failed' | 'skipped'; reason?: string }[];
  }): Promise<void>;
}
```

- **事件**：`talent_review_outbox` 写 `project_ended` / `meeting_ended` / `sync_requested`（手动），payload = `{ runId, projectId, meetingId, trigger, actorUserId, objectIds }`，与状态变更同事务；消费者（R3-T05）按游标拉取，调用 `loadSnapshot` 再按自己的策略（SC-R14 覆盖 / 追加 / 范围内覆盖，开关归 R3-T05）写继任，最后 `recordOutcome`。手动同步按钮 `sync` 在盘点侧只写事件与 run 记录，不直接写继任。
- **权限裁剪**：`viewer.kind = 'user'` 时对象按其 TalentReview 范围过滤、字段按其 `Object` 字段查看权裁剪、继任信息按 `succession` 字段权；`trusted` 不裁剪。两种模式都不含评估逐人打分、执行人、校准原因。
- **稳定性**：`fields` 键为盘点字段 `code`（预置固定、自定义按租户）；R3-T05 的字段映射按 code 配置。
- **数据口径**：已删除对象不返回；`terminated` 对象 `syncEligible = false`；`project_ended` 后对象只读，快照可重复读取（幂等）。

## 9. 并发、幂等、锁与审计

- 写命令：`Idempotency-Key` + `If-Match` revision（DEC-067），复用 `runCommand`；重放按当前权限复核。
- 锁序：员工（对象员工行 FOR SHARE）→ 盘点项目 → 盘点对象（按 id 排序）→ 校准会 → 审批实例（引擎内）；计算批次先锁项目 FOR SHARE 再锁对象；校准会结束锁会 → 对象。真 PG 交错用例：同一对象两执行人并发保存评估；两次“开始计算”并发；校准拖拽与开始计算并发；项目结束与评估提交并发。
- 批量上限：添加对象 / 导入 / 批量提交 / 开始计算 / 校准会加人单次 ≤ 500（跨页全选分批，TR-R37 的“异步处理”复刻为分批同步 + 回执，§11.2 D-11）。
- 审计：每个写入口同事务 `recordAudit`（对象字段值变化逐字段；计算写入按对象一条含 before / after）；计算失败记 `calc_message`，不伪造审计。
- 定时：无需新定时任务（未来生效不涉及）；outbox 投递复用各模块 outbox worker 写法。

## 13. 边界用例（设计阶段登记，实现时逐条写测试）

1. 同一员工加入同一项目两次 → 409 `OBJECT_DUPLICATE`；从其他项目添加时按操作人管理单元过滤候选且去重（TR-R8）。
2. 启动采集时某对象的执行人为空（direct / indirect 无上级）→ 引擎 DEC-054；`designated` 缺人 → 400 列出对象，整批不启动。
3. 评估人既是对象本人（自评步骤）又是多人步骤某角色 → 任务按（对象 × 步骤 × 执行人）区分；本人只见自评任务。
4. 模板在项目使用中被编辑 → 新版本只影响之后新建对象；已有对象仍用旧版本；模板停用不影响已发起对象。
5. 评价规则被模板版本引用后修改 → 版本快照不变（TR-R20）；被使用的规则不能删除（409）。
6. 项目重启：对象恢复 `status_before_end`；重启后再次结束重新校验比例规则并再次写 `project_ended` 事件（runId 不同）。
7. 开始计算时对象正被评估人保存 → 行锁串行；计算读取提交后的值。
8. 计算规则含循环依赖且管理员只勾选部分对象 → 整批失败，未勾选对象不变。
9. 校准会中对象被另一个校准会加入 → 409 `OBJECT_CALIBRATING`。
10. 校准拖拽到同一格 → 不记路径、不写值；拖拽目标格对应的轴字段为选项型时按选项值写入。
11. 结果审批进行中管理员改校准后字段 → 409 `RESULT_APPROVAL_PENDING`。
12. 下级管理员对向下公开项目的对象发起“开始计算”“添加对象” → 403 `PROJECT_READONLY`，前后读不变。
