## 0. 一页摘要

- **只做“基于盘点模板”一种机制**（`26` §1）。**评价任务与结果审批分开**：评价步骤（单人 / 批量 / 多人）由盘点模块自己的任务运行时执行，盘点流程定义归 R3-T04（DEC-304），本人自评不经审批人路由；盘点结果审批走 R1 审批引擎（新审批类型「盘点结果审批」），**回避集合 = 发起人 ∪ 本单全部被盘点人**，覆盖审批域全部单主体入口（选人、转交 / 加签、审批、管理员干预、异常交接、详情能力、异常管理员回避、实例持久化），以“可选集合 + 单主体归一化”扩展——由审批域通用契约 **F-048** 交付（DEC-309③，C 档先出设计），本任务只提供“对象 → 主体”映射适配器；**集合审批保留在 T04**（R3-08）。
- **数据模型**（§2）：配置对象、**准备度共享字典**（DEC-301①，PR-A 先交付）、盘点流程定义、**盘点内容表单**（字段逐个三档：可编辑 / 仅查看 / 不可见，DEC-306①）、模板（版本复制写，含评分配置快照；步骤 × 角色选用表单）、项目（只有计划开始 / 结束时间、业务日期、全量计算时间，DEC-306③）、盘点对象（业务状态不随项目结束变；结果版本用全局序列 `result_seq`，不再更新项目行，N11）、指标 / 模块结果、评估记录（对象 × 步骤 × 角色 × 执行人 × 指标）、盘点继任信息（稳定行 ID、kind × direction）、校准会与参与者、校准路径、结果审批 / 快照、提名、**计算 run（持久化冻结输入、暂存输出、结构化失败）**、**同步 run（冻结快照）+ 消费记录 + 逐行回执**、outbox。
- **计算**（§4）三层：① 指标 / 模块算分；② 模板结果设置公式；③ 盘点计算规则。**一次逻辑计算 = 一个 calc run**：先登记完整逻辑总体（全部 / 筛选 / 显式分页追加后封存，500 只是传输页大小，N02），冻结输入快照到库（N03），在内存对全体一次性求值（排名口径 DEC-302；**排名总体 = run 总体，由公式里的过滤条件再过滤，与所挂计算规则无关**，DEC-306④），**每个项目的输出先经目标字段适配再进入 computed 集合、失败沿依赖链传播**（N04，引擎钩子 C-07 → **F-049**，DEC-309③），输出暂存后按页发布，发布时逐对象校验冻结后未被改写（旧结果不覆盖新值），崩溃按暂存续写。三个身份分开（N05）：`principalUserId` = **显式授权的系统主体**负责执行；项目所属人有效性与授权是额外前置检查；`actorUserId` = 触发人——**管理入口**（手动计算 / 同步）按其按钮与管理范围决定可选对象，**待办联动**（保存 / 提交 / 驳回 / 不同意 / 撤销 / 重开）按当前席位、动作与字段编辑权授权该对象，不要求管理范围（R3-01）。执行与重试时按**实际使用的对象、字段、外部来源、组织**逐项复核源授权，撤权明确失败（R3-02）；公共 run 详情不暴露原始取数快照（R3-03）；发布中途规则变化与 run 级失败都受对象版本校验保护（R3-04）。
- **取数端口**（§5）：绩效 ← 人员子集「考核结果」；360 ← #107 端口 + **F-046**；测评 ← 人员子集「测验结果」（归属待定）；排名 ← run 总体（**F-045**）；人才评定 / 参数规则端口不注入。指标来源：人才标准 ← #106 端口，引用守卫与首个引用入口同 PR；任职资格 ← 本任务定义接口、R3-T02 实现。
- **权限**（§6）：独立应用 `TalentReview`（范围解析契约 C-03）；逐对象范围锚点；步骤 × 角色 × 字段权限模型；校准会“校准”与“结束”分开授权（N08）；输出路径裁剪表补齐三类缺口（N07）：计算失败结构化存储、按查看人生成文案；同步回执按对象 / 人员范围逐行过滤；审计用复合谓词（项目可见 ∧ 人员范围 / 组织范围）。
- **同步端口契约 v4**（§8）：**同步只有手动一种触发**（DEC-306②：项目页“同步数据 → 同步继任信息”勾选对象后同步，项目进行中即可，项目结束 / 校准会结束不自动同步 🟡）；不可变 run 作为快照身份（A-03）；事件枚举只剩 `sync_requested`，`manualOverride` 是该命令的显式参数（A-04）；覆盖策略未给范围时 **拒绝**（A-05，🟡 保守口径）；`readReviewFields` 返回 `value / empty / forbidden / unavailable` 状态；健康度 DTO 带 `levelCode` 与 `value / empty / not_provided / forbidden`、继任信息与 `unmapped`，并定义健康度**回写**接口（A-06，N09）；字段目录选项域有确定类型（A-07）；三档取数与绿化率用同一选择器，`meetingId` 不降级（A-08 / A-09）；run 身份 / 执行身份（带租约与执行序号）/ 页命令身份 / 行幂等键 / 完成标志分开，事务内校验执行有效性，含可重试失败不得完成（R3-05，A-10 / A-11 / A-15）；健康度计算接口由本任务定义、T05 实现登记，DTO 区分“无继任模块”与“零提名”，回写有凭据、按钮、幂等、revision 与项目状态检查，重置为明确授权的例外（R3-06 / R3-07，A-06 / A-16 / A-19）；公共错误码表（A-17）；PR-A 交付唯一完整的类型定义与共用契约测试（A-13）。
- **口径清单**（§11）：D-26 跨规则排名取值时点与本人成果页两项并入取证 **Q-M0-128**，写成“待定（Q-M0-128）”🟡，只列两种候选做法及其对接口 / 权限 / 数据的影响，不选定、不据此展开表结构或路由；C-05 被否决时的审批粒度问题已由 DEC-309③ 结案（保留集合审批，契约走 F-048）；Q-M0-125 已由 DEC-306 结案——①字段权限按步骤 × 表单逐字段三档、②提名记录两个方向 + 手动同步、③项目只有计划时间、④排名总体由公式过滤决定；其余 🟡 按保守口径写进正文（系统主体、结束比例按当前用户范围、测验子集 / 本人成果页 / 绩效映射按手册、覆盖同步未给范围拒绝）；契约协调项 C-01～C-07。

## 3. 状态机与流程

### 3.1 盘点项目（TR-R1、R2；DEC-306③）

| 状态 | 编辑 | 启动采集 | 结束 | 重启 | 删除 | 添加 / 删除对象 | 开始计算 | 校准会 / 结果审批 | 同步继任信息（手动） |
|---|---|---|---|---|---|---|---|---|---|
| new | ✅ | ✅ → in_progress | ✅ | — | ✅（须无对象，409 `PROJECT_HAS_OBJECTS`） | ✅ | ✅ | — | ✅ |
| in_progress | ✅ | — | ✅（比例规则 `project_meeting` + `block` 校验，范围 = **当前操作人数据范围内的对象**，🟡 保守口径 DEC-306⑤；运行中的 calc run → 409 `CALC_RUN_IN_PROGRESS`；通过后 `status = ended`；**对象业务状态不变，不自动同步**，确认文案“结束评估后，盘点项目数据禁止修改”） | — | ✅（须无对象） | ✅ | ✅ | ✅ | ✅ |
| ended | ❌ 409 `PROJECT_ENDED` | — | — | ✅ → in_progress（`ended_count + 1`；本项目未完成消费的同步 run → superseded） | ✅（须无对象） | ❌ | ❌ | ❌ | ✅（只读数据的同步，🟡） |

无“进行中退回新建”；时间只有计划开始 / 结束与业务日期，实际进度看状态；“全量计算时间”在手动对项目全部对象的 calc run 发布完成时更新。

### 3.3 评价任务运行时、盘点流程定义（DEC-304）与结果审批（N12）

### 4.2 指标 / 模块算分与精度（P3-02）

- 指标打分值：numeric 规则取分值；grade 规则取等级分值（版本快照）；`unable` 或未评价不参与。指标结果分 = Σ(各席位打分 × 步骤评价权重) / Σ参与权重；多人步骤先按角色平均（TR-R24）。模块结果分四种算法（TR-R23）：算术平均 = Σ指标结果分 / 有效指标数；算术求和 = Σ指标结果分；加权求和 = Σ(指标结果分 × 指标权重) / Σ有效指标权重；按指标数目 = 取最后一个有有效评价且有评分权限的步骤的结果，按 `min_count` 匹配模块等级。模块等级按版本快照 `module_levels` 得分区间匹配，无匹配为空；只计有评分权限且有有效评分的步骤（AC-TR-05：60% × 4 + 40% × 5 = 4.4）。
- **精度分两层**：① 内部评分与模块分用 JS number 计算，写入前用引擎 `functions/math.ts` 的 BigInt 定点舍入（DEC-299）按 **4 位小数**存 `numeric(14,4)`，等级匹配用 4 位值（区间含下界不含上界，最后一段含上界，临界值用例：恰等于下界 → 本段；上界 − 0.0001 → 本段）；② ③ 写入盘点字段时按字段 `precision`（默认 2）定点舍入（DEC-265 四舍五入：2.5 → 3，2.345 → 2.35）；|值| ≥ 10^10 或非有限数 → 该项目失败 `OUTPUT_OVERFLOW`；展示不再二次舍入。
- 管理员调整：写 `adjusted_*`，`final = adjusted ?? computed`；不触发②③（TR-R26；AC-TR-12）。

### 4.3 模板结果设置公式

- 保存校验：`validateFormula(formula, { isKnownField, fieldKind })`，字段目录 = 版本内模块的 `模块.<名>.得分`（number）/ `模块.<名>.等级`（text）；目标字段来自盘点字段目录，类型允许性同 §4.5(d)；规则间依赖与循环用 `orderComputationItems`（循环不拦截，返回 `warnings` / `cycles`，DEC-274）；文本与数字比较保存时拦截（D-15）。
- 求值：无端口；对象 = 模块结果读取器（`final_score / final_level`），空值与类型按引擎 `DEFAULT_SEMANTICS`（DEC-257 / 270）；输出经 §4.5(d) 适配钩子（F-049）与 §4.2 精度舍入后写盘点字段；② 写入的字段可被 ③ 引用，同一 run 内按 §4.5(c) 的依赖顺序求值。

**(b) 冻结输入（N03）**：`seal` 后状态 `frozen`：按页读取总体对象的引用字段、模块结果、对象 `revision / result_seq`，并以系统主体预读端口记录，写入 `calc_run_inputs`（≤ 500 / 事务）；记录 `rule_revisions`（计算规则与模板版本）。之后的求值与续写只读 inputs，不再读实时数据。

**(c) 求值（一次性，N02 / DEC-306④）**：状态 `evaluating`。按对象有效规则分组逐组求值（每组一次 `evaluateBatch`），**排名总体 = 整个 run 总体**（DEC-306④：总体由公式过滤条件决定，与所挂规则无关）。**跨规则排名的取值时点（D-26）：待定（Q-M0-128）🟡**，v3 的“组内用新值、组外用冻结值”已撤回（反例：A、B 冻结分 0，各组新算 10 / 20，各自排第 1）。两种候选做法及影响（不选定，不据此展开表结构）：

| 候选 | 做法 | 接口影响 | 权限影响 | 数据影响 |
|---|---|---|---|---|
| A 统一冻结时点 | 全部组的排名项目只读冻结输入（`calc_run_inputs`），本 run 内其他项目的新值不参与排名 | F-049 `population` 传冻结输入读取器即可；排名项目不依赖同 run 其他项目 | 无 | 排名用的字段值 = 冻结快照；同一 run 内“先算得分再排名”不成立，需两次 run |
| B 统一在适配完成后的阶段时点 | 两阶段求值：先对全部组完成非排名项目并适配、写入一份“阶段快照”，再以同一份快照对全部组求排名项目 | F-049 需支持分阶段调用（排名项目延后）或 `population` 传阶段快照读取器；依赖链中排名项目的下游也延后 | 无 | 暂存输出增加阶段快照（内存或 `calc_run_inputs` 的阶段列）；排名总体的值对所有组一致 |

取证结论回来后再定 F-049 `population` 的取值语义与本节实现。排名口径 DEC-302：降序；并列 1、1、3；百分位 = 名次 ÷ 参与人数 × 100 保留两位小数、越小越靠前；排序字段为空的对象不参与、不计数、自身为空；范围条件可限定到单个项目（引擎对齐由 **F-045** 交付）。

**(d) 输出适配进入依赖链（N04；引擎钩子 C-07 由 **F-049** 交付，DEC-309③，B 档，F-045 后、T04 写代码前合并）**：`evaluateBatch(items, subjects, context, { adapt, population })`（第四参可选，不传时行为与现状完全一致）：
- `adapt(item, subjectId, value): EvaluationResult` 在引擎把某对象某项目的值放入 `computed` **之前**调用；返回失败则该项目记失败，下游依赖项目 `DEPENDENCY_FAILED`，该对象在下游项目的排名总体中不参与；返回成功则 `computed` 存适配后的值（number / option / text / date / boolean 的引擎值），排名与下游都用适配后的值。复现用例：A（number 目标）返回 `"abc"`，B = `ToNumber(A)+1` → A 失败、B `DEPENDENCY_FAILED`、A / B 都不写。
- `population?: readonly SubjectReader[]`：排名总体的额外成员（参数形状；取值时点按 Q-M0-128 决定）。**优先级**：调用方显式注入 `context.ports.ranking` 时引擎用该端口、忽略 `population`（本任务从不注入 `ranking` 端口）；未注入时总体 = `subjects`（叠加已算值）∪ `population`，**按 subject id 去重，`subjects` 优先**；引擎按现有规则排除当前项目依赖失败的成员。**缓存生命周期**：F-045 的总体级排序缓存按“一次 `evaluateBatch` 调用 × 一个项目 × (范围条件, 分组)”建立，调用结束即丢弃；本任务在冻结输入上另做列式缓存，随 run 结束释放。第四参可选，不传时引擎行为与现状完全一致。
- 交付方式已定（DEC-309③）：F-049 独立前置 PR（验证既有 `RankingPort` 调用方与缓存行为；“传与不传钩子”对照测试由 F-049 承担）。本任务不再保留“模块自行循环”的备选（若需，`orderComputationItems` 遇环仍可能返回 `ok: true` 并把成环项目放在 `blocked` / `cycles`，不能只看 `ok`，此处只作记录）。

适配规则（两类公式共用 `coerceToField`）：

| 目标字段类型 | 允许的引擎值 | 转换 | 失败（单项目失败，不触发 DB 错误） |
|---|---|---|---|
| number | number；数字文本；empty | `ToNumber` 语义；按 precision 定点舍入；溢出校验 | 非数字文本 / boolean / date / option → `OUTPUT_TYPE_MISMATCH`；`OUTPUT_OVERFLOW` |
| option | number / text / option，值与某启用选项 **value** 相等；empty | 写 option_value | `OUTPUT_OPTION_INVALID` |
| text | 任意标量；empty | 格式化 | — |
| date | date；ISO 文本；empty | 到日 | `OUTPUT_TYPE_MISMATCH` |
| boolean | boolean；0 / 1；"true" / "false"；empty | | `OUTPUT_TYPE_MISMATCH` |

**(e) 暂存与发布协议（N03 / R3-02 / R3-04）**：求值结束状态 `evaluated`：全部结果（含 ① 模块算分）写 `calc_run_outputs`（≤ 500 / 事务）。发布 `publishing` 按页进行，每页一个事务：

1. **页前校验**（每页事务内，R3-02 / R3-04）：① 重新解析系统主体当前授权，对本页对象逐项复核——对象查看权、本页涉及的每个盘点字段（目标与引用）的查看 / 编辑权、`source_refs` 指向的每个外部来源对象（绩效 / 测评 / 人事子集对象、360 结果）的查看权；任一撤权 → 该对象本页输出不发布，输出 `failed: SOURCE_REVOKED { scope: 'object' | 'field' | 'source', ref }`（**明确失败，不当作缺字段 / 空值，也不继续用冻结值**）；② 所属人前置检查；③ `rule_revisions` 核对（见表）。
2. 按 id 升序锁对象 → 逐对象校验 `object.revision == inputs.object_revision`（冻结后无人改写）且 `object.last_calc_run_seq < run.run_seq`（没有更新的 run 已写入）→ 两者都成立才写字段值、模块 / 指标结果、`result_seq = nextval`、`calc_status`、`last_calc_run_id / _seq`，输出 `applied`；否则输出 `stale`，对象不变。
3. 每页提交后 `publish_cursor` 前移。

| 情形 | 处理 |
|---|---|
| 已发布页的结果可见性 | 每页提交即可见（对象级原子）；run 详情显示逐对象 `applied / stale / pending / failed` |
| 进程在发布中途退出 | 重启后按 `publish_cursor` 续写（已 `applied` 的对象跳过）；输入 / 输出都在库中 |
| 冻结后、**首页发布前**规则 / 模板版本变化 | run `rules_changed`，整 run 不发布 |
| **首页发布后**规则 / 模板版本变化（页前校验发现） | 停止后续页；已发布页保留（不可撤回，对象级原子）；run `partial_rules_changed`，未发布对象输出 `superseded`，提示重新计算（R3-04） |
| run 级失败（循环、主体不可用、规则变化、源撤权） | 对象 `calc_status = failed` 与 `last_calc_run_id` **同样受版本校验保护**：只写 `revision` 未变且 `last_calc_run_seq < run.run_seq` 的对象；较新的 run 已写入成功状态的对象不被旧 run 的失败收尾覆盖（R3-04） |
| 项目结束 | run 处于 `collecting～publishing` → 409 `CALC_RUN_IN_PROGRESS` |
| 同一项目并发两个 run | 允许；发布按对象 revision + `run_seq` 校验，后发布者遇变化即 `stale` |
| 旧 run 被新 run 取代 | 新 run 发布后，旧 run 未发布的输出标 `superseded`，不再发布 |
| 循环依赖 | 求值前判出 → `cyclic`，不写任何值（DEC-274） |
| 各阶段主体复核（N06 / R3-02） | 冻结（每页）、求值（开始）、发布（每页）、续写（每页）都重新按实际使用内容复核系统主体与所属人授权 |

**诊断信息边界（R3-03）**：公共 run 详情（`GET /calc-runs/:id`、`/outputs`、`/inputs`、历史快照）**不返回 `port_snapshot`**；只返回 `inputs[].values`（按 `Object.<code>` 字段权投影）与 `source_refs` 的**来源摘要**（来源对象、记录数，不含记录内容）。确需诊断外部记录内容时，走 `GET /calc-runs/:id/inputs/:objectId/sources`：按 `source_refs` 把每条记录映射到来源对象 / 字段，按查看人**当前**对该来源对象（人员子集「考核结果」「测验结果」等子集对象、`Survey360.Result`）的查看权与字段权逐项投影，无权记录不出现；原始失败参数（`OUTPUT_*` 的输出值）与历史快照采用同一边界。

**(f) 性能（P3-03）**：排名密集负载实测（审查探针）纯引擎 2 000 × 10 个 `Ranking` 项目 ≈ 7.3 s，原因是每个对象对总体逐一扫描（O(n²)）。优化：**F-045 实现“按（项目, 范围条件, 分组）一次预排序 + 二分查名次”的总体级缓存**（C-01 扩展，排名在全体上一次性求值本就是 F-045 范围）；模块侧对冻结输入做列式缓存。目标：2 000 × 10 Ranking ≤ 5 s、10 000 × 10 ≤ 60 s（PGlite 与真 PG 各一条，含常量公式与 Ranking 两种负载）。**没有“优化前过渡目标”这一验收分支**：F-045 合并是写代码前置，性能用例只以上述目标断言；若 F-045 未含排序缓存而目标未达，补充优化随 PR-C 一起提交，不降低目标。

### 6.2 项目可见性谓词（TR-R3）

### 8.1 触发、冻结与身份（DEC-306②；A-04 / A-05 / A-12 / A-14；N05 / R3-01）

| 项 | 规则 |
|---|---|
| 触发 | **只有手动**：项目页“同步数据 → 同步继任信息”勾选对象后 `POST /projects/:id/sync` → `trigger = 'sync_requested'`（事件枚举唯一值，A-04；T05 预留的自动分支禁用）；项目进行中或已结束都可；项目结束、校准会结束**不**触发（🟡） |
| `manualOverride` | 命令显式参数，缺省 false：false → `in_flow` 对象 `syncEligible = false`（SC-R15）；true → `in_flow` 对象 `syncEligible = true` 且只带已填提名行。消费方只看 `syncEligible / blockReason` |
| 范围 | `scopeOrgIds` 来自命令参数并冻结，`scopeExplicit = true`（**显式空数组也算显式**：表示“范围内覆盖”的范围为空集 → 消费方按空集处理，不扩大）；未给 → `[]`、`scopeExplicit = false`。消费方策略为 `overwrite_in_scope` 且 `scopeExplicit = false` → 整 run 拒绝（`SCOPE_REQUIRED`，永久）；盘点侧命令阶段按当时租户开关预检 400 🟡 |
| 身份 | `actorUserId` = 触发人（管理入口：`sync` 按钮；对象选择限其管理范围）；`principalUserId` = 显式授权的系统主体（源数据冻结与消费期源授权复核按其范围与字段权）；**项目所属人**（A-14：= `projects.owner_id`，不是触发人）有效性与授权为前置检查（失效 → 409 `SYNC_PRINCIPAL_UNAVAILABLE`，不留半成品 run）。消费方目标写入按同一身份模型复核：目标写主体 = `actorUserId`（手动 run；T05 复核其当前继任写权限与范围，撤权 → `ACTOR_REVOKED`）|
| 冻结内容 | 对象结果（字段按系统主体字段权）、逐提名行、健康度行、`businessDate`（= 项目 `business_date ?? 冻结日租户本地日期`，冻结后不变）、`excluded` 计数；`sourceSeq` 仅说明。**每行回执预建 `pending`** |
| 事件 | outbox `{ runId, projectId, trigger: 'sync_requested', principalUserId, actorUserId, scopeExplicit, businessDate }` 与 run 同事务；消费方以 `runId` 为快照身份（A-03，不依赖 `snapshotId / resultVersion / snapshotVersion`） |

| 行幂等键 | (runId, consumer, rowKind, rowId)；已 `synced / superseded` 的行再次写入 = 幂等忽略；`failed` 行写 `synced` = 更新最新状态 + 追加历史（含旧 `pageCommandId`） |
| 页事务 | **每页一个事务**：`assertExecutionActive` → 业务写入 → 本页 `recordOutcome`，同一事务；T05 §5.7 须同事务，不允许业务已提交而回执另补 |
| unknown 回查 | 消费方事务结果未知 → `getOutcomes({ pageCommandId })`：**只有带本页命令身份的终态**才证明本页已提交；旧执行留下的 `failed` 终态不作数 → 在新执行中重做该页 |
| 完成条件 | `completeConsumption`：所有行终态且**没有 `failed ∧ retryable` 行**；否则 409 `RETRYABLE_ROWS_REMAIN` / `PENDING_ROWS_REMAIN`。“已有回执”≠ 完成 |
| 重试 | 新执行（同 `executionNo` 续租或接管后的新序号）只处理 `pending` 与 `failed ∧ retryable` 行；永久失败码见 §8.7 |
| 终止 / 取代（事务内防护） | `abortConsumption` 或项目重启（`superseded`）都**对消费记录取 `FOR UPDATE`** 后改状态；页事务第一步 `assertExecutionActive` 对同一行取 `FOR SHARE`，两者串行：重启发生在页前检查之后、业务提交之前时，页事务在取 S 锁时阻塞，待重启提交后断言失败，**本页业务写入不提交**。被取代 / 终止后剩余 `pending` 行由盘点侧批量写 `superseded` 回执 |
| 对象 / 健康度回执键 | `rowKind = object`（rowId = objectId）、`org_health`（rowId = orgId）；T05 须回传健康度回执（A-11） |

### 8.4 源读取授权（R3-02；A-12 / A-18）

- **只冻结数据，不冻结权限**。`authorizeSourceRead` 在每次执行、每页事务开始、每次重试前，按 run 的 `principalUserId` **当前**授权，对本页**实际使用的内容**逐项复核：对象（项目可见 ∧ 人员范围）、字段（每个将被消费的盘点字段的查看权）、外部来源（该对象 `source_refs` 指向的子集对象 / 360 结果的查看权）、组织（健康度行的组织范围）。撤权 → 返回 `forbidden` 明细；消费方对相应行写 `SOURCE_REVOKED { scope }` **永久失败**（不是缺字段、不是空值、不继续消费冻结值）；整 run 不可读（主体 / 所属人失效、项目不可见）→ `ok = false`，本执行终止（`PRINCIPAL_UNAVAILABLE` / `OWNER_UNAVAILABLE`）。
- 无 run 的 `readReviewFields / readSuccessionEntries / greenRate` 同样按 `viewer` 当前授权逐字段 / 逐来源 / 逐组织返回 `forbidden`。
- 盘点侧的同步页、健康度页按查看人实时权限裁剪（§6.6）；回执重试同样先复核。
- 目标写入由消费方按 §8.1 身份模型复核；`SourceViewer` 只有 `principal` 与 `user`。

### 8.5 版本与取代（A-03）

run 冻结后不变；项目重启 → 本项目所有未 `completed` 的消费记录与 run 标 `superseded`（取消费记录 `FOR UPDATE`，§8.3）；手动 run 只被“项目重启”取代，两次手动同步各自独立。消费方读到 `superseded` 只写 `superseded` 回执。

### 8.9 选择器与其他约定

- **选择器（A-08 / A-09 统一）** `resolveReviewSource(employeeId | orgId, context)`：tier 1 = `triggerMeetingId` 给定时只取该校准会的会中对象（员工不在会中 → tier 2），否则 `triggerProjectId` 的对象；tier 2 = 当前项目：`status = in_progress ∧ period_start_date ≤ asOf` 里按 `coalesce(business_date, period_start_date)` 最近者（并列 `code` 小者）；tier 3 = 最近一次盘点：`status = ended ∧ period_end_date ≤ asOf` 里 `period_end_date` 最近（并列 `period_start_date` 最近，再 `code`）。对象 `terminated` 不计。绿化率按组织（行政子树内员工为对象）用同一选择器，分母 0 → `rate = null`。

- 批量：对象页 ≤ 500、提名页 ≤ 2000 是读取分页；逻辑批次 = 一个 run。
- `direction = target` 行照常进 run；是否写正式继任记录 🟡（Q-T04-10，保守：消费方回执 `skipped`）。

## 9. 并发、幂等、锁（P2-16 / N11 已关闭；R3-05）

**结果版本不再写项目行**：对象级结果写入只更新对象行并取 `talent_review_result_seq.nextval` 写 `objects.result_seq`；项目级“版本”派生自对象 `result_seq` 最大值；calc run 另取 `run_seq`（同一序列）用于新旧 run 先后判定。

**统一锁序**（首个排他资源按操作列出）：

```
员工行（FOR SHARE，仅新增对象 / 设置执行人）
→ 盘点项目（对象级操作 FOR SHARE；项目级状态变更 FOR UPDATE；对象级操作不更新项目行）
→ 校准会（校准 FOR SHARE；结束 / 删除 FOR UPDATE）
→ 结果审批单（FOR UPDATE）
→ calc run 行（FOR UPDATE，发布 / 续写 / 取消）
→ 同步 run 行 / 消费记录（页事务 FOR SHARE；接管 / 终止 / 取代 FOR UPDATE）
→ 盘点对象（FOR UPDATE，按 id 升序批量）
→ 评估记录 / 任务 / 提名行 / 健康度行（按对象 / 组织顺序）
→ 审批实例（引擎内部）
```

| 操作 | 加锁顺序 | 更新的行 |
|---|---|---|
| 评估保存 / 提交 | 项目 S → 对象 X → 任务 / 记录 | 对象、记录 |
| 校准 | 项目 S → 校准会 S → 对象 X | 对象、路径 |
| 校准会结束 | 项目 S → 校准会 X → 对象 X（升序） | 校准会、对象 |
| calc run 冻结 / 发布页 | 项目 S → run X → 对象 X（本页升序） | run、inputs / outputs、对象（含失败收尾，受 revision + `run_seq` 保护） |
| 项目结束 / 重启 | 项目 X → 校准会 S → calc run S（running → 409）→ **消费记录 X（重启：标 superseded）** → 对象 X（升序） | 项目、消费记录 |
| 删除对象 | 项目 S → 对象 X | 级联 |
| 结果审批发起 / 回调（适配器 `lock`） | 项目 S → 审批单 X → 对象 X（升序）→ 引擎锁实例 | 审批单、对象 |
| 手动同步 | 项目 S → 对象 S（只读冻结）→ run X | run、快照表、预建回执 |
| 消费页事务（T05） | **消费记录 S（`assertExecutionActive`）** → 员工 S → 目标行 … → 回执行 | 继任记录（T05）、回执 |
| 消费接管 / 终止 | 消费记录 X | 消费记录、剩余回执 `superseded` |
| 健康度回写 | 项目 S → 健康度行 X（按 org 升序） | 健康度行 |

真 PG 交错用例：① 两人同时校准同一项目的不同对象（无死锁、各自 `result_seq` 递增）；② 校准 vs 校准会结束；③ 同一对象两席位并发保存；④ 两个 calc run 并发（后者对已改对象 `stale`）；⑤ 校准拖拽 vs calc run 发布；⑥ 项目结束 vs 评估提交；⑦ 位置字段交叉列并发；⑧ 同一 run 两个消费执行并发（第二个 `CONSUMPTION_LEASED`）；⑨ **项目重启 vs 消费页事务**（页前检查已过、业务未提交 → 页事务在 `assertExecutionActive` 取 S 锁阻塞，重启提交后断言失败，页不提交）；⑩ 旧 run 失败收尾 vs 新 run 已发布（旧 run 不覆盖）；⑪ 健康度：计算回写 vs 手动赋值（手动先提交 → 计算 `MANUAL_KEPT`）。

幂等：`Idempotency-Key` + `If-Match`（DEC-067），复用 `runCommand`；重放按当前权限复核。批量：勾选类命令单次 ≤ 500（体验差异，DEC-301②）；calc run 总体不受 500 限制。审计同事务，不伪造。

## 13. 边界用例

1～28 同 v3；新增：

32. 冻结后撤系统主体对绩效子集 / 某字段 / 某组织的权限 → 发布页 / 消费页 / 无 run 读取逐项 `SOURCE_REVOKED`。

34. 消费执行租约过期 → 新执行接管，旧执行后续 `assertExecutionActive` 失败不提交。
35. unknown 回查只认本页命令身份的终态；旧执行的 `failed` 不作数。
36. 含 `failed ∧ retryable` 行时 `completeConsumption` 409。
37. 项目重启与消费页事务交错 → 页事务阻塞后断言失败，不提交。
38. 计算启动后用户手动赋健康度 → 计算回写 `MANUAL_KEPT`；重置一次事务覆盖并清标记；已结束项目任何回写 `PROJECT_ENDED`。
