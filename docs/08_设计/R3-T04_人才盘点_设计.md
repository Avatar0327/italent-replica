## 0. 一页摘要

- **只做“基于盘点模板”一种机制**（`26` §1）。**评价任务与结果审批分开**：评价步骤（单人 / 批量 / 多人）由盘点模块自己的任务运行时执行，盘点流程定义归 R3-T04（DEC-304），本人自评不经审批人路由；盘点结果审批走 R1 审批引擎（新审批类型「盘点结果审批」），**集合审批保留**（DEC-309③），多主体回避按审批域通用契约 **F-048**（#128，DEC-329：节点级开关、新建节点默认关闭、命中后自动“跳过”🟡、实例级回避覆盖全部主体、开启时不得抄送集合内主体），本任务只提供“审批单 → 全部被盘点人”的主体适配器，不自写回避。
- **数据模型**（§2）：配置对象、**准备度共享字典**（DEC-301①，PR-A 先交付）、盘点流程定义、**盘点内容表单**（字段逐个三档：可编辑 / 仅查看 / 不可见，DEC-306①）、模板（版本复制写，含评分配置快照；步骤 × 角色选用表单）、项目（只有计划开始 / 结束时间、业务日期、全量计算时间，DEC-306③）、盘点对象（业务状态不随项目结束变；结果版本用全局序列 `result_seq`，不再更新项目行，N11）、指标 / 模块结果、评估记录（对象 × 步骤 × 角色 × 执行人 × 指标）、盘点继任信息（稳定行 ID、kind × direction）、校准会与参与者、校准路径、结果审批 / 快照、提名、**计算 run（持久化冻结输入、暂存输出、结构化失败）**、**同步 run（冻结快照）+ 消费记录 + 逐行回执**、outbox。
- **计算**（§4）三层：① 指标 / 模块算分；② 模板结果设置公式；③ 盘点计算规则。**一次逻辑计算 = 一个 calc run**：登记完整逻辑总体（全部 / 筛选 / 显式分页追加后封存，500 只是传输页大小）→ 冻结输入快照入库（含①所需评分、范围内非 run 对象的已存值）→ 一次性求值 → 输出经 **F-049**（已合并）适配钩子进入依赖链 → 暂存 → 按页发布（对象 revision + `run_seq` 校验）→ 崩溃续写。**排名口径定稿（DEC-312）**：同一次计算里先算分再排名，本 run 的对象用本次新算出的值，范围内其他对象用库中已存值，未参与计算的对象排名不回写；排名总体由公式过滤条件决定（DEC-306④）。三个身份：系统主体执行、项目所属人前置检查、触发人（管理入口按按钮 + 管理范围；待办联动按席位 / 动作 / 字段权）。执行期按实际使用的对象、字段、来源、组织逐项复核源授权；公共详情里的来源摘要同样按查看人当前来源权限投影（R4-06）。
- **取数端口**（§5）：绩效 ← 人员子集「考核结果」；360 ← #107 端口 + **F-046**；测评 ← 人员子集「测验结果」；排名 ← run 总体 + 冻结的范围内非 run 对象（**F-045**、F-049，已合并）；人才评定 ← R3-T02 C2 `loadTalentReviewRecords`（DEC-320⑦，C2 合并前不注入）；参数规则端口不注入。指标来源：人才标准 ← #106 端口；任职资格 ← **R3-T02 维护的 `QualificationIndicatorPort`**（接口、登记、实现都归 R3-T02，DEC-317④ / 320⑥）。**多选字段取证前不参与公式**（DEC-314②）。
- **权限**（§6）：独立应用 `TalentReview`（范围解析契约 C-03）；逐对象范围锚点；步骤 × 表单逐字段三档；校准会“校准”与“结束”分开授权；输出路径裁剪表（计算失败按查看人渲染、同步回执逐行过滤、审计复合谓词、calc run 来源摘要与诊断按查看人当前来源权限投影）。
- **同步**（§8）：只有手动一种触发（DEC-306②）。全部跨模块契约见协议：身份以 T05 为准（SP-01：系统主体执行、项目所属人前置、原触发人在首次计划时授权完整目标集合、显式重试调用人另验入口）；T04 消费租约与 T05 租户互斥分层（SP-08 / SP-09）；目标登记与封存、`target` 回执、页提交证明 `PageCommit`、完成门槛覆盖目标（SP-10～SP-12）；公共错误码与三类恢复动作（SP-14）；健康度逐组织 CAS 与完整上下文、导入延期 F-050（SP-16）。本文 §8 只列 T04 侧落点。

- **PR 切分**（§12）：PR-A 契约与字典（协议类型、替身工厂与共用契约测试、准备度字典、审批类型登记 C-08；**不含** C-05 / C-07，二者分别由 F-048、F-049 交付）→ PR-B 配置 / 流程 / 模板 / 项目 → PR-C 对象 / 评估 / 计算 → PR-D 九宫格 / 校准 / 结果审批 / 同步实现。

## 3. 状态机与流程

### 3.1 盘点项目（TR-R1、R2；DEC-306③）

| 状态 | 编辑 | 启动采集 | 结束 | 重启 | 删除 | 添加 / 删除对象 | 开始计算 | 校准会 / 结果审批 | 同步继任信息（手动） |
|---|---|---|---|---|---|---|---|---|---|
| new | ✅ | ✅ → in_progress | ✅ | — | ✅（须无对象，409 `PROJECT_HAS_OBJECTS`） | ✅ | ✅ | — | ✅ |
| in_progress | ✅ | — | ✅（比例规则 `project_meeting` + `block` 校验，范围 = **当前操作人数据范围内的对象**，🟡 保守口径 DEC-306⑤；运行中的 calc run → 409 `CALC_RUN_IN_PROGRESS`；通过后 `status = ended`；**对象业务状态不变，不自动同步**，确认文案“结束评估后，盘点项目数据禁止修改”） | — | ✅（须无对象） | ✅ | ✅ | ✅ | ✅ |
| ended | ❌ 409 `PROJECT_ENDED` | — | — | ✅ → in_progress（`ended_count + 1`；本项目未完成消费的同步 run → superseded） | ✅（须无对象） | ❌ | ❌ | ❌ | ✅（只读数据的同步，🟡） |

无“进行中退回新建”；时间只有计划开始 / 结束与业务日期，实际进度看状态；“全量计算时间”在手动对项目全部对象的 calc run 发布完成时更新。

### 3.3 评价任务运行时、盘点流程定义（DEC-304）与结果审批（N12）

**为什么不复用审批引擎做评价任务**：`packages/domain/src/approval/routing.ts` 的 `decideNode` 把“候选人 = 流程主体本人”改派为其直线经理（`self_skip_manager`），`approval/actions.ts` 的 `assertNotSelf` 拒绝发起人或主体本人审批；会签席位解析会合并同一用户的多席。盘点需要本人自评、同人多席、步骤 × 表单逐字段权限，三者都与审批语义冲突。

### 4.2 指标 / 模块算分与精度（P3-02）

- 指标打分值：numeric 规则取分值；grade 规则取等级分值（版本快照）；`unable` 或未评价不参与。指标结果分 = Σ(各席位打分 × 步骤评价权重) / Σ参与权重；多人步骤先按角色平均（TR-R24）。模块结果分四种算法（TR-R23）：算术平均 = Σ指标结果分 / 有效指标数；算术求和 = Σ指标结果分；加权求和 = Σ(指标结果分 × 指标权重) / Σ有效指标权重；按指标数目 = 取最后一个有有效评价且有评分权限的步骤的结果，按 `min_count` 匹配模块等级。模块等级按版本快照 `module_levels` 得分区间匹配，无匹配为空；只计有评分权限且有有效评分的步骤（AC-TR-05：60% × 4 + 40% × 5 = 4.4）。
- **精度分两层**：① 内部评分与模块分用 JS number 计算，写入前用引擎 `functions/math.ts` 的 BigInt 定点舍入（DEC-299）按 **4 位小数**存 `numeric(14,4)`，等级匹配用 4 位值（区间含下界不含上界，最后一段含上界，临界值用例：恰等于下界 → 本段；上界 − 0.0001 → 本段）；② ③ 写入盘点字段时按字段 `precision`（默认 2）定点舍入（DEC-265 四舍五入：2.5 → 3，2.345 → 2.35）；|值| ≥ 10^10 或非有限数 → 该项目失败 `OUTPUT_OVERFLOW`；展示不再二次舍入。
- 管理员调整：写 `adjusted_*`，`final = adjusted ?? computed`；不触发②③（TR-R26；AC-TR-12）。

### 4.3 模板结果设置公式

- 保存校验：`validateFormula(formula, { isKnownField, fieldKind })`，字段目录 = 版本内模块的 `模块.<名>.得分`（number）/ `模块.<名>.等级`（text）；目标字段来自盘点字段目录，类型允许性同 §4.5(d)；规则间依赖与循环用 `orderComputationItems`（循环不拦截，返回 `warnings` / `cycles`，DEC-274）；文本与数字比较保存时拦截（D-15）。
- 求值：无端口；对象 = 模块结果读取器（`final_score / final_level`），空值与类型按引擎 `DEFAULT_SEMANTICS`（DEC-257 / 270）；输出经 §4.5(d) 适配钩子（F-049）与 §4.2 精度舍入后写盘点字段；② 写入的字段可被 ③ 引用，同一 run 内按 §4.5(c) 的依赖顺序求值。

| 暂存后发布 | 管理入口：手动「开始计算」（`scope = all / filter / explicit`） | ① 在 calc run 内用冻结的 `scoring_inputs` 重算，输出写 `calc_run_outputs`（`layer = scoring`），与②③同页发布并受 revision + `run_seq` 校验 | 与②③同一冻结时点，发布中途失败或规则变化时 ① 与②③一起保留或一起不写 |

### 4.5 calc run：总体登记、冻结、求值、适配、发布（N02 / N03 / N04；DEC-301② / 302 / 306④）

**(a) 登记完整逻辑总体（N02）**

| 入口 | 总体 | 说明 |
|---|---|---|
| `POST /projects/:id/calc-runs { scope: 'all' }` | 项目全部对象 ∖ terminated ∩ actor 范围 ∩ principal 可读 | 服务端枚举，无条数上限（上限 20 000，D-18） |
| `{ scope: 'filter', filter }` | 按服务端筛选条件（状态、模板、组织、标签…）枚举 | 同上 |
| `{ scope: 'explicit' }` → `POST /calc-runs/:id/objects`（每页 ≤ 500 个 id，可多次）→ `POST /calc-runs/:id/seal` | 显式勾选分页追加后**封存** | 页只是传输单位；封存前不求值；封存后总体只读 |

501 人一次计算的入口 = `scope: 'all'` / `filter` / `explicit` 两页后 `seal`；两次各 500 的“分次提交”不再存在（分次提交 = 两个 run，各自总体，属误用，UI 不提供）。

**(b) 冻结输入（N03）**：`seal` 后状态 `frozen`：按页读取总体对象的引用字段、模块结果、对象 `revision / result_seq`，并以系统主体预读端口记录（`port_snapshot` + `source_refs`），写入 `calc_run_inputs`（≤ 500 / 事务）；记录 `rule_revisions`（计算规则与模板版本）；同时按 §4.5(c) 冻结排名用的范围内非 run 对象到 `calc_run_population`。之后的求值与续写只读冻结数据，不再读实时数据。**管理入口 run 的 `scoring_inputs`**（① 重算所需，P3）：① 全部评估记录（步骤、角色、执行人、指标、`score_value / level_value / unable`）及其 `invalid` 标记（`invalid = true` 的只记 id 与标记，不参与计算）；② 模板版本冻结的步骤 × 角色评分权限（`score_enabled`）与**步骤评价权重**；③ 对象指标快照的**指标权重**、目标值、所属模块；④ 模块算法、评价规则头部快照（上下限、显示、`allow_unable`）、等级快照（`module_levels`）；⑤ 现有 `adjusted_*`（保留不重算）。

**(c) 求值与排名取值时点（DEC-312 定稿 D-26；DEC-306④）**：状态 `evaluating`。

- **口径**（Q-M0-128 取证，`26` §10）：同一次计算里先算分再排名——源字段（优先级小）先算出新值，排名项目读到的就是这个新值；**本 run 的对象用本次新算出（并经适配）的值，排名范围内其他对象用库中已存值**；未参与计算的对象排名不回写，要得到一致排名须对整个范围全选重算。排名总体由公式里的过滤条件决定，与所挂计算规则无关（DEC-306④）。两处原站异常不复刻（DEC-312 🟡）：排序号按百分位体现的名次计算；负数源值照常参与排名。
- **非 run 成员（冻结）**：冻结时取“系统主体可读、未终止、不在本 run 的盘点对象”中可能落入排名范围的对象——排名范围条件里能下推为 SQL 的项目 / 年度等价条件先过滤，不能下推时不过滤——把排名项目用到的排序 / 范围 / 分组字段的**库中已存值**写入 `calc_run_population`；run 总体与非 run 成员合计 ≤ 20 000（D-18），超出 → run `failed: POPULATION_LIMIT`，不写值。之后不读实时值，保证续写与重算一致。
- **按层求值**（计算规则可能按人不同，对象按有效规则分组）：把全部规则组的计算项目放进一张以目标字段为节点的依赖图——公式引用是依赖；排名项目除依赖自己公式里的字段外，还依赖**所有规则组**里计算其排序 / 范围条件 / 分组字段的项目（排名总体跨组）——按拓扑分层；有环 → run `cyclic`，不写值（DEC-274）。逐层、逐规则组调用一次 `evaluateBatch(本层本组项目, 本组对象, context, { adapt, population })`：`subjects` 的读取器叠加本 run 前面各层的适配后新值；`population` = 本 run 其他规则组对象（同样叠加前面各层新值）∪ `calc_run_population` 成员（库中已存值）。前层依赖失败的对象不进入本层调用，直接记 `DEPENDENCY_FAILED`，也不进入其他组的排名总体。只有一个规则组时等价于一次调用。
- 跨规则组对象读到同 run 新值这一点原站未测（`26` §9 D-17 🟡），按 DEC-312“本次参与计算的对象用新值”的口径实现。
- 排名口径 DEC-302 / 310：降序；并列 1、1、3；百分位 = 名次 ÷ 参与人数 × 100，四舍五入保留两位（1/32 → 3.13）；排序字段为空的对象不参与、不计数，自身为空返回空；本人取不到排序值 → `OUT_OF_SCOPE`，本人排序值类型错误 → `TYPE_CONVERSION`（F-045 已合并）。

**(d) 输出适配进入依赖链（N04；引擎钩子由 **F-049** 交付，已合并 #118 fc2fb59）**：`evaluateBatch(items, subjects, context, { adapt, population })`（第四参可选，不传时行为与旧版一致）：
- `adapt(item, subjectId, value): EvaluationResult` 在引擎把某对象某项目的值放入 `computed` **之前**调用；返回失败则该项目记失败，下游依赖项目 `DEPENDENCY_FAILED`，该对象在下游项目的排名总体中不参与；返回成功则 `computed` 存适配后的值（number / option / text / date / boolean 的引擎值），排名与下游都用适配后的值。复现用例：A（number 目标）返回 `"abc"`，B = `ToNumber(A)+1` → A 失败、B `DEPENDENCY_FAILED`、A / B 都不写。
- `population?: readonly SubjectReader[]`：排名总体的额外成员。**读取优先级**（F-049 已实现，DEC-312）：调用方显式注入 `context.ports.ranking` 时引擎用该端口、忽略 `population`（本任务从不注入 `ranking` 端口）；未注入时总体 = `subjects` ∪ `population`，**按 subject id 去重，`subjects` 优先并叠加同轮新值**；`population` 成员只读调用方提供的值（本任务提供：其他规则组的同 run 新值或冻结的库中已存值，§4.5(c)），不求值、不返回输出；引擎排除当前项目依赖失败的 `subjects`，`population` 成员的依赖失败由本任务在调用前剔除。**缓存生命周期**：F-045 的总体级排序缓存按“一次 `evaluateBatch` 调用 × 一个项目”建立，调用结束即丢弃；本任务在冻结输入上另做列式缓存，随 run 结束释放。
- 交付已完成（DEC-309③，F-049 #118）：“传与不传钩子”对照测试由 F-049 承担；本任务只做 §4.5(c) 的分层调用。`orderComputationItems` 遇环仍可能返回 `ok: true` 并把成环项目放在 `blocked / cycles`，分层建图时不能只看 `ok`。

适配规则（两类公式共用 `coerceToField`）：

| 目标字段类型 | 允许的引擎值 | 转换 | 失败（单项目失败，不触发 DB 错误） |
|---|---|---|---|
| number | number；数字文本；empty | `ToNumber` 语义；按 precision 定点舍入；溢出校验 | 非数字文本 / boolean / date / option → `OUTPUT_TYPE_MISMATCH`；`OUTPUT_OVERFLOW` |
| option | number / text / option，值与某启用选项 **value** 相等；empty | 写 option_value | `OUTPUT_OPTION_INVALID` |
| text | 任意标量；empty | 格式化 | — |
| date | date；ISO 文本；empty | 到日 | `OUTPUT_TYPE_MISMATCH` |
| boolean | boolean；0 / 1；"true" / "false"；empty | | `OUTPUT_TYPE_MISMATCH` |
| multi_option、`system_written`、pair 的 before 字段被②写入 | 不允许为目标：保存时 400 `TARGET_FIELD_NOT_ALLOWED` | | |

empty 一律写 null，空串视为 empty。

**(e) 暂存与发布协议（N03 / R3-02 / R3-04）**：求值结束状态 `evaluated`：全部结果（含 ① 模块算分）写 `calc_run_outputs`（≤ 500 / 事务）。发布 `publishing` 按页进行，每页一个事务：

1. **页前校验**（每页事务内，R3-02 / R3-04）：① 重新解析系统主体当前授权，对本页对象逐项复核——对象查看权、本页涉及的每个盘点字段（目标与引用）的查看 / 编辑权、`source_refs` 指向的每个外部来源对象（绩效 / 测评 / 人事子集对象、360 结果）的查看权；本页含排名项目输出时，另用一次集合查询复核系统主体对排名总体成员（同 run 其他对象与 `calc_run_population`）的对象查看权及排序 / 范围 / 分组字段查看权，有成员被撤权 → 本页依赖排名的输出 `failed: SOURCE_REVOKED { scope: 'object' }`；任一撤权 → 该对象本页输出不发布，输出 `failed: SOURCE_REVOKED { scope: 'object' | 'field' | 'source', ref }`（**明确失败，不当作缺字段 / 空值，也不继续用冻结值**）；② 所属人前置检查；③ `rule_revisions` 核对（见表）。
2. 按 id 升序锁对象 → 逐对象校验 `object.revision == inputs.object_revision`（冻结后无人改写）且 `object.last_calc_run_seq < run.run_seq`（没有更新的 run 已写入）→ 两者都成立才写字段值、模块 / 指标结果、`result_seq = nextval`、`calc_status`、`last_calc_run_id / _seq`，输出 `applied`；否则输出 `stale`，对象不变。
3. 每页提交后 `publish_cursor` 前移。

| 情形 | 处理 |
|---|---|
| 已发布页的结果可见性 | 每页提交即可见（对象级原子）；run 详情显示逐对象 `applied / stale / pending / failed` |
| 进程在发布中途退出 | 重启后按 `publish_cursor` 续写（已 `applied` 的对象跳过）；输入 / 输出都在库中 |
| 冻结后、**首页发布前**规则 / 模板版本变化 | run `rules_changed`，整 run 不发布 |
| **首页发布后**规则 / 模板版本变化（页前校验发现） | 停止后续页；已发布页保留（不可撤回，对象级原子）；run `partial_rules_changed`，未发布对象输出 `superseded`，提示重新计算（R3-04） |
| run 级失败（循环、主体不可用、规则变化、源撤权） | 对象 `calc_status = failed` 与 `last_calc_run_id` **同样受版本校验保护**：只写 `revision` 未变且 `last_calc_run_seq < run.run_seq` 的对象；较新的 run 已写入成功状态的对象不被旧 run 的失败收尾覆盖（R3-04） |
| 项目结束 | run 处于 `collecting～publishing` → 409 `CALC_RUN_IN_PROGRESS` |
| 同一项目并发两个 run | 允许；发布按对象 revision + `run_seq` 校验，后发布者遇变化即 `stale` |
| 旧 run 被新 run 取代 | 新 run 发布后，旧 run 未发布的输出标 `superseded`，不再发布 |
| 循环依赖 | 求值前判出 → `cyclic`，不写任何值（DEC-274） |
| 各阶段主体复核（N06 / R3-02） | 冻结（每页）、求值（开始）、发布（每页）、续写（每页）都重新按实际使用内容复核系统主体与所属人授权 |

**诊断信息边界（R3-03 / R4-06）**：公共 run 详情（`GET /calc-runs/:id`、`/outputs`、`/inputs`、历史快照）**不返回 `port_snapshot`**；`inputs[].values` 按 `Object.<code>` 字段权投影；**来源摘要 `inputs[].sources[]` 也按查看人当前来源权限投影**：每个来源条目（来源对象、记录数、使用的字段）只在查看人**当前**同时满足——对该来源对象（人员子集「考核结果」「测验结果」等子集对象、`Survey360.Result`）有查看权、该员工在该来源对象所属应用的人员范围内、对条目里的字段有查看权——时出现；记录数只数查看人可见的记录；无权的来源**整个条目缺席**（不显示名称、不显示数量、不显示“已隐藏”）。确需看记录内容时走 `GET /calc-runs/:id/inputs/:objectId/sources`，同一判定逐条投影。原始失败参数（`OUTPUT_*` 的输出值）、审计与历史快照采用同一边界；裁剪表见 §6.6。

**(f) 性能（P3-03）**：排名密集负载实测（审查探针）纯引擎 2 000 × 10 个 `Ranking` 项目 ≈ 7.3 s，原因是每个对象对总体逐一扫描（O(n²)）。优化：**F-045 实现“按（项目, 范围条件, 分组）一次预排序 + 二分查名次”的总体级缓存**（C-01 扩展，排名在全体上一次性求值本就是 F-045 范围）；模块侧对冻结输入做列式缓存。目标：2 000 × 10 Ranking ≤ 5 s、10 000 × 10 ≤ 60 s（PGlite 与真 PG 各一条，含常量公式与 Ranking 两种负载）。**没有“优化前过渡目标”这一验收分支**：F-045 合并是写代码前置，性能用例只以上述目标断言；若 F-045 未含排序缓存而目标未达，补充优化随 PR-C 一起提交，不降低目标。

### 4.6 失败口径与结构化（N07）

失败不再存文案：`calc_run_outputs.failure = { code, params }`，`params` 可含目标字段 code、引用字段 code、函数名、行列、输出值（原始值只在 `OUTPUT_*` 失败时存，按 §4.5(e) 诊断边界投影）。读取时按查看人渲染：查看人对相关字段无查看权 → 字段名显示“（隐藏字段）”、输出值不显示；有权 → 原站风格文案“最近计算时间:… 盘点字段“X”计算项目计算有误，详细信息：…”。循环依赖、主体不可用、规则已改为 run 级失败，对象 `calc_status = failed` 指向 run。

### 4.7 九宫格落位、比例规则、绿化率（PR-D）

- 落位（纯函数 `locate(matrix, values)`，`packages/domain/src/talent-review/placement.ts`）：按 `placement_source` 取校准前 / 校准后的 X、Y 字段值 → 轴分段 → 格子号；任一轴无值 → 不落位（位置字段清空）；结果写位置字段（before / after 各自，`system_written`，人工写入 400）。计算发布、校准拖拽 / 表单、结果审批通过写回后都重算落位；校准拖拽直接写校准后 X / Y 字段与校准后位置字段并记路径。
- 比例校验（纯函数 `checkRatio(group, placements)`）：人数 < `min_population` 跳过；组内规则“且”；`block` 时拒绝（项目结束 / 校准会结束 / 批量提交），`warn` 时返回 `warnings`。**比例总体一律 = 当前操作人数据权限内、未终止且已落位的对象**（TR-R34；R4-07）：项目结束 = 本项目中操作人人员范围内的对象（§3.1）；校准会结束 = 会中对象 ∩ 操作人人员范围（§3.5）；批量提交 = 本项目中操作人人员范围内的对象，按本次提交后的落位计算，**不是**本次选中的对象（例：范围内 100 人、某格 20 人，选 5 人提交 → 按 20% 判定）。🟡 结束时的范围取操作人范围属 DEC-306⑤ 保守口径（Q-T04-03）；纯评估人（无 TalentReview 人员范围）批量提交时的总体 = 空集 → 低于起始人数不校验，待定 Q-T04-18。页面“比例异常 N”按查看人范围另算，有部门筛选时另显示“整体比例异常 N”（TR-R34）。
- 绿化率 = 计入格子（`counts_green`）人数 / 该九宫格已落位人数；分母不含未落位与终止对象；**零分母 → `null`**（不是 0）；只读函数，经 §8 端口 `greenRate` 暴露给组织继任地图（`GreenRateResult`）。

## 9. 并发、幂等、锁（P2-16 / N11 已关闭；R3-05）

**结果版本不再写项目行**：对象级结果写入只更新对象行并取 `talent_review_result_seq.nextval` 写 `objects.result_seq`；项目级“版本”派生自对象 `result_seq` 最大值；calc run 另取 `run_seq`（同一序列）用于新旧 run 先后判定。

**统一锁序**（首个排他资源按操作列出）：

```
员工行（FOR SHARE，仅新增对象 / 设置执行人）
→ 盘点项目（对象级操作 FOR SHARE；项目级状态变更 FOR UPDATE；对象级操作不更新项目行）
→ 校准会（校准 FOR SHARE；结束 / 删除 FOR UPDATE）
→ 结果审批单（FOR UPDATE）
→ calc run 行（FOR UPDATE，发布 / 续写 / 取消）
→ 同步 run 行 / 消费记录（页事务 FOR SHARE；接管 / 终止 / 取代 FOR UPDATE）
→ 盘点对象（FOR UPDATE，按 id 升序批量）
→ 评估记录 / 任务 / 提名行 / 健康度行（按对象 / 组织顺序）
→ 审批实例（引擎内部）
```

| 操作 | 加锁顺序 | 更新的行 |
|---|---|---|
| 评估保存 / 提交 | 项目 S → 对象 X → 任务 / 记录 | 对象、记录 |
| 校准 | 项目 S → 校准会 S → 对象 X | 对象、路径 |
| 校准会结束 | 项目 S → 校准会 X → 对象 X（升序） | 校准会、对象 |

真 PG 交错用例：① 两人同时校准同一项目的不同对象（无死锁、各自 `result_seq` 递增）；② 校准 vs 校准会结束；③ 同一对象两席位并发保存；④ 两个 calc run 并发（后者对已改对象 `stale`）；⑤ 校准拖拽 vs calc run 发布；⑥ 项目结束 vs 评估提交；⑦ 位置字段交叉列并发；⑧ 同一 run 两个消费执行并发（第二个 `CONSUMPTION_LEASED`）；⑨a **页先持 S 锁**：页事务已过 `assertExecutionActive`，随后项目重启 → 重启等待页事务；页提交后重启提交；断言按提交顺序：该页回执与 `PageCommit` 有效，其余非终态行 `superseded`，下一页 `RUN_SUPERSEDED`（协议 SP-19 #3）；⑨b **重启先持 X 锁**：重启已锁消费记录未提交，页事务执行 `assertExecutionActive` → 等待；重启提交后断言失败，页回滚，无业务写入、无 `PageCommit`（SP-19 #4）；⑩ 旧 run 失败收尾 vs 新 run 已发布（旧 run 不覆盖）；⑪ 健康度：计算回写 vs 手动赋值（手动先提交 → 计算 `MANUAL_KEPT`）；⑫ 健康度：重置 vs 手动赋值（手动先提交 → 重置该组织 `REVISION_CONFLICT`，手工等级与标记保留，SP-19 #10）。“两个 run、同一目标、都做覆盖同步”属 T05 租户互斥（SP-09），由 T05 按 SP-19 #1 / #2 测试。

幂等：`Idempotency-Key` + `If-Match`（DEC-067），复用 `runCommand`；重放按当前权限复核。批量：勾选类命令单次 ≤ 500（体验差异，DEC-301②）；calc run 总体不受 500 限制。审计同事务，不伪造。

## 13. 边界用例

1. 同一员工加入同一项目两次 → 409 `OBJECT_DUPLICATE`；从其他项目添加候选按管理单元过滤并去重。
2. 启动采集：`designated` 缺人 / `direct` 无上级 → 400 列出对象，整批不启动，前后读不变。
3. 同一人多席位（自评 + 某角色）→ 两个任务、两套记录；提交一席不影响另一席。
4. 模板在项目使用中被编辑 → 新版本只影响之后新建对象；评价规则上下限 / `allow_unable` / 等级 / 表单修改同样不影响。
5. 项目重启：对象状态不变；未完成消费的同步 run → `superseded`；重启后再次结束不产生同步 run（DEC-306②）。
6. 开始计算时对象正被保存 → 行锁串行；总体值在冻结时固定，冻结后被保存的对象发布时 `stale`。
7. 计算规则含循环且只勾选部分对象 → 整 run 不写，未勾选对象不变。
8. 501 人一次计算末名 501；分页发布不改变名次。
9. 公式输出 `"abc"` 到数值字段 → 该项目失败、其余项目写入、事务不回滚。
10. 校准会中对象被另一校准会加入 → 409；校准拖拽到同一格不记路径；轴不可拖 / 缺必填原因 → 400。
11. 校准与会议结束并发 → 会议级串行，无死锁（真 PG）。
12. 结果审批进行中管理员改校准后字段 → 409 `RESULT_APPROVAL_PENDING`。
13. 下级管理员对向下公开项目的写入 → 403 `PROJECT_READONLY`。
14. 被盘点人调动后：执行人以启动时为准；团队人才视图按当前任职组织。
15. 终止对象不计比例 / 排名 / 绿化率 / calc run；管理员仍可编辑字段。
16. 删除对象：级联任务 / 记录 / 提名行 / 路径并写快照审计；流程中先取消任务。
17. 位置字段交叉占用（A.before = F 与 B.after = F）→ 409；并发两条只过一条。
18. 系统主体未指定 / 被撤权 / 所属人停用 → calc run `principal_unavailable`，输出不发布；手动同步 409。
19. 冻结后用户保存了第二页的对象 → 发布时该对象 `stale`，新值保留，run `partial`。
20. 发布第一页后进程退出 → 续写从 `publish_cursor` 开始，不重复、不改名次。
21. 规则在冻结后、首页发布前被修改 → `rules_changed`，不发布。
22. 冻结后撤系统主体对某对象的查看权 → 发布 / 消费该对象明确失败 `SOURCE_REVOKED`。
23. 同一 run 两个消费执行并发 → 第二个 `CONSUMPTION_LEASED`；页提交结果未知 → 查 `PageCommit`，存在且执行号匹配才算已提交。
24. 项目重启后旧 run 仍有未终态行 → 回执 `superseded`，消费方停止，不能在新执行中重做（`RUN_SUPERSEDED`）。
25. 被盘点人 A 在实例级入口（管理员干预、交接等）一律回避；节点级回避按节点开关（DEC-329）。
26. 两人同时校准不同对象 → 无死锁。
27. 覆盖策略 + 未给范围的手动同步 → 400 `SCOPE_REQUIRED`。
28. 3 人排名 33.33 / 66.67 / 100.00；过滤条件限定到单个项目；1/32 → 3.13；本人范围外 `OUT_OF_SCOPE`、类型错误 `TYPE_CONVERSION`、显式空值 → 空。
29. 无 TalentReview 管理范围的评估人在本席位保存 / 提交 → 建 run、总体 = 本对象、计算由系统主体执行。
30. 首页发布后计算规则被修改 → 停止后续页，已发布页保留，run `partial_rules_changed`，未发布对象 `superseded`。
31. 新 run 已发布成功后旧 run 才失败 → 旧 run 的失败收尾对 `last_calc_run_seq` 更大的对象不写。
32. 冻结后撤系统主体对绩效子集 / 某字段 / 某组织的权限 → 发布页 / 消费页 / 无 run 读取逐项 `SOURCE_REVOKED`。
33. 公共 run 详情与历史快照不含 `port_snapshot`；来源摘要与来源诊断只投影查看人当前有权的来源与记录，无权来源连数量也不出现。
34. 消费执行租约过期 → 新执行接管，旧执行后续 `assertExecutionActive` 失败不提交。
35. 结果未知只认当前执行的 `PageCommit`；旧执行的 `failed` 不作数。
36. 含 `failed ∧ retry_same_run` 行或 `pending` 的 `target` 行时 `completeConsumption` 409。
37. 项目重启与消费页事务交错 → 两种先后（页先持 S 锁 / 重启先持 X 锁）分别断言（§9 ⑨a / ⑨b）。
38. 计算启动后用户手动赋健康度 → 计算回写 `MANUAL_KEPT`；重置期间他人手工赋值 → `REVISION_CONFLICT`、手工值保留；已结束项目任何回写 `PROJECT_ENDED`。
39. 被盘点人 A 兼管理员：干预 / 跳转 / 交接 / 详情操作一律回避（F-048 实例级）。
40. 部分重算：5 人中只算 F3（新值 0.1，其余库中 1、1）→ F3 百分位 100.00、排序号 3；F1 / T1 不回写（DEC-312）。
41. 两条计算规则各管一部分对象、同一 run：排名读到另一组对象本次的新值，不出现两组各排第 1。
42. 公式引用多选字段 → 保存 400 `MULTI_OPTION_IN_FORMULA`。
43. 批量提交只选 5 人，范围内 100 人某格 20 人 → 比例按 20% 判定。
44. 只做删除（无提名）的目标页 → 有 `target` 行终态与 `PageCommit`；该目标未完成时消费不能完成。
45. 首次计划时原触发人不覆盖某健康度目标 → `ACTOR_SCOPE_EXCEEDED`，消费记录 `aborted`（新建 run），重试 403。
