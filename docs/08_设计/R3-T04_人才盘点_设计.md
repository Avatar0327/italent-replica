## 0. 一页摘要

- **只做“基于盘点模板”一种机制**（`26` §1）。**评价任务与结果审批分开**：评价步骤（单人 / 批量 / 多人）由盘点模块自己的任务运行时执行，盘点流程定义归 R3-T04（DEC-304），本人自评不经审批人路由；盘点结果审批走 R1 审批引擎（新审批类型「盘点结果审批」），**回避集合 = 发起人 ∪ 本单全部被盘点人**，在选人、转交 / 加签、审批时都回避（N12，审批域契约 C-05）。
- **数据模型**（§2）：配置对象、**准备度共享字典**（DEC-301①，PR-A 先交付）、盘点流程定义、**盘点内容表单**（字段逐个三档：可编辑 / 仅查看 / 不可见，DEC-306①）、模板（版本复制写，含评分配置快照；步骤 × 角色选用表单）、项目（只有计划开始 / 结束时间、业务日期、全量计算时间，DEC-306③）、盘点对象（业务状态不随项目结束变；结果版本用全局序列 `result_seq`，不再更新项目行，N11）、指标 / 模块结果、评估记录（对象 × 步骤 × 角色 × 执行人 × 指标）、盘点继任信息（稳定行 ID、kind × direction）、校准会与参与者、校准路径、结果审批 / 快照、提名、**计算 run（持久化冻结输入、暂存输出、结构化失败）**、**同步 run（冻结快照）+ 消费记录 + 逐行回执**、outbox。
- **计算**（§4）三层：① 指标 / 模块算分；② 模板结果设置公式；③ 盘点计算规则。**一次逻辑计算 = 一个 calc run**：先登记完整逻辑总体（全部 / 筛选 / 显式分页追加后封存，500 只是传输页大小，N02），冻结输入快照到库（N03），在内存对全体一次性求值（排名口径 DEC-302；**排名总体 = run 总体，由公式里的过滤条件再过滤，与所挂计算规则无关**，DEC-306④），**每个项目的输出先经目标字段适配再进入 computed 集合、失败沿依赖链传播**（N04，引擎钩子 C-07），输出暂存后按页发布，发布时逐对象校验冻结后未被改写（旧结果不覆盖新值），崩溃按暂存续写。三个身份分开（N05）：`principalUserId` = **显式授权的系统主体**负责执行；项目所属人有效性与授权是额外前置检查（失效或撤权即失败）；`actorUserId` = 触发人负责入口授权与对象选择。执行与重试时**重新校验源读取授权**，撤权明确失败（N06）。
- **取数端口**（§5）：绩效 ← 人员子集「考核结果」；360 ← #107 端口 + **F-046**；测评 ← 人员子集「测验结果」（归属待定）；排名 ← run 总体（**F-045**）；人才评定 / 参数规则端口不注入。指标来源：人才标准 ← #106 端口，引用守卫与首个引用入口同 PR；任职资格 ← 本任务定义接口、R3-T02 实现。
- **权限**（§6）：独立应用 `TalentReview`（范围解析契约 C-03）；逐对象范围锚点；步骤 × 角色 × 字段权限模型；校准会“校准”与“结束”分开授权（N08）；输出路径裁剪表补齐三类缺口（N07）：计算失败结构化存储、按查看人生成文案；同步回执按对象 / 人员范围逐行过滤；审计用复合谓词（项目可见 ∧ 人员范围 / 组织范围）。
- **同步端口契约 v3**（§8）：**同步只有手动一种触发**（DEC-306②：项目页“同步数据 → 同步继任信息”勾选对象后同步，项目进行中即可，项目结束 / 校准会结束不自动同步 🟡）；不可变 run 作为快照身份（A-03）；事件枚举只剩 `sync_requested`，`manualOverride` 是该命令的显式参数（A-04）；覆盖策略未给范围时 **拒绝**（A-05，🟡 保守口径）；`readReviewFields` 返回 `value / empty / forbidden / unavailable` 状态；健康度 DTO 带 `levelCode` 与 `value / empty / not_provided / forbidden`、继任信息与 `unmapped`，并定义健康度**回写**接口（A-06，N09）；字段目录选项域有确定类型（A-07）；三档取数与绿化率用同一选择器，`meetingId` 不降级（A-08 / A-09）；run 身份 / 执行身份 / 行幂等键 / 完成标志四样分开，业务写与回执同事务（A-10 / A-11，N10）；源读取在执行与重试时按系统主体复核（A-12）；PR-A 固定导出替身工厂与共用契约测试（A-13）。
- **口径清单**（§11）：Q-M0-125 已由 DEC-306 结案——①字段权限按步骤 × 表单逐字段三档、②提名记录两个方向 + 手动同步、③项目只有计划时间、④排名总体由公式过滤决定；其余 🟡 按保守口径写进正文（系统主体、结束比例按当前用户范围、测验子集 / 本人成果页 / 绩效映射按手册、覆盖同步未给范围拒绝）；契约协调项 C-01～C-07。
- **PR 切分**（§12）：PR-A 契约与字典（含 C-05 扩展、C-07 钩子、替身工厂与契约测试）→ PR-B 配置 / 流程 / 模板 / 项目 → PR-C 对象 / 评估 / 计算 → PR-D 九宫格 / 校准 / 结果审批 / 同步实现。

### 3.3 评价任务运行时、盘点流程定义（DEC-304）与结果审批（N12）

**为什么不复用审批引擎做评价任务**：`packages/domain/src/approval/routing.ts` 的 `decideNode` 把“候选人 = 流程主体本人”改派为其直线经理（`self_skip_manager`），`approval/actions.ts` 的 `assertNotSelf` 拒绝发起人或主体本人审批；会签席位解析会合并同一用户的多席。盘点需要本人自评、同人多席、步骤 × 表单逐字段权限，三者都与审批语义冲突。

**归属（DEC-304）**：评价任务由盘点模块自有运行时执行；盘点流程定义（`talent_review_flows`）归盘点设置，模板版本内冻结节点副本。

| 动作 | 规则 |
|---|---|
| 启动采集 | 项目 → 对象（initial）逐个：按模板版本冻结的步骤 × 角色解析执行人写 `evaluators`（§3.4），为第一个步骤建 `tasks`（round = 1）；**无执行人**（`designated` 缺人、`direct / indirect` 无上级）→ 400 `EVALUATOR_MISSING` / `EVALUATOR_UNRESOLVED` 列出对象，整批不启动（🟡 保守口径 DEC-306⑤，原 D-16） |
| 保存 | 本席位任务 pending 时可写本席位评估记录、表单 `edit` 档字段、提名行；触发 §4.4“持久化保存” |
| 提交 / 批量提交 | 必填校验（评分 / 评语 / 表单 required 字段 / 提名行）；批量提交前对整批做 `flow` + `block` 比例校验（范围 = 操作人数据范围内的对象，🟡 同上）；席位任务 → submitted；节点完成：single = 该席位提交；countersign = 全部席位提交；节点完成 → 下一步任务；最后一步 → 对象 `flow_ended`。提交后按 §4.4 触发 |
| 驳回上一步（allow_return） | 当前节点席位 → returned；上一节点席位任务重开（round + 1），已提交记录保留可改；按 §4.4 触发 |
| 转交（allow_transfer） | 本席位任务 → transferred，新建同席位任务给被转交人；已保存记录随席位转移（审计留痕） |
| 不同意（allow_disagree） | 对象 → `terminated`，当前步骤全部席位任务 cancelled、评估记录 `invalid = true`；按 §4.4 触发（① 重算后②③按引用变化） |
| 管理员撤销 / 重开 | 撤销采集 → 对象 `initial`、任务 cancelled（记录保留 invalid）；终止对象可重开（新 round）；按 §4.4 触发 |

**已否决的备选（记录，DEC-304）**：复用审批流程定义 + 审批引擎运行评价任务（需 `selfPolicy: 'allow'`、按角色席位、新增审批人表达式、`pinnedProcessId` 等共享审批域契约，且与 DEC-058 自审语义冲突），不采用。

**结果审批（N12）**：审批类型 `talent_review_result`（`APPROVAL_TYPES` 登记，objectCode `TalentReview.ResultApproval`），业务类型 `talent_review`，适配器 `talent-review/approval-adapter.ts`；发起人 = 项目管理员；**回避集合 = 发起人 ∪ 本单全部被盘点人（`subject_employee_ids`）**。审批域契约 **C-05**：`BusinessSnapshot` 增 `subjectEmployeeIds: readonly string[]`（兼容既有单主体 `subjectEmployeeId`），`RoutingFacts` 增 `subjectEmployeeIds / subjectUserIds`，`isSelf`（`routing.ts`）、`assertNotSelf`（`actions.ts`）、转交 / 加签目标校验、审批人候选解析都按集合判断；命中回避 → 自审跳过转直线经理 / 异常管理员（DEC-058 / 091 现有规则不变）。快照 `fieldObjectCode = TalentReview.ResultApproval`，各对象的校准后字段作为 `foreignFields`（对象 `TalentReview.Object`，DEC-057 最小披露按该对象字段权，盲审 DEC-058 按嵌套字段）；审批中编辑开放校准后字段；通过 → 写回对象、`decided_snapshot`、对象 `result_seq = nextval`；不同意 → 审批单 `rejected`，对象不变。评价任务允许自评**不**延伸到结果审批。若 C-05 契约被否决，备选 = 每个对象一个审批实例（单主体，引擎现有回避即可，批量发起 = N 个实例），在 PR-D 开工前定。

### 4.2 指标 / 模块算分与精度（P3-02）

- 指标打分值：numeric 规则取分值；grade 规则取等级分值（版本快照）；`unable` 或未评价不参与。指标结果分 = Σ(各席位打分 × 步骤评价权重) / Σ参与权重；多人步骤先按角色平均（TR-R24）。模块分四种算法同 v2；按指标数目取最后一个有效步骤的结果按 `min_count` 匹配等级。
- **精度分两层**：① 内部评分与模块分用 JS number 计算，写入前用引擎 `functions/math.ts` 的 BigInt 定点舍入（DEC-299）按 **4 位小数**存 `numeric(14,4)`，等级匹配用 4 位值（区间含下界不含上界，最后一段含上界，临界值用例：恰等于下界 → 本段；上界 − 0.0001 → 本段）；② ③ 写入盘点字段时按字段 `precision`（默认 2）定点舍入（DEC-265 四舍五入：2.5 → 3，2.345 → 2.35）；|值| ≥ 10^10 或非有限数 → 该项目失败 `OUTPUT_OVERFLOW`；展示不再二次舍入。
- 管理员调整：写 `adjusted_*`，`final = adjusted ?? computed`；不触发②③（TR-R26；AC-TR-12）。

### 4.5 calc run：总体登记、冻结、求值、适配、发布（N02 / N03 / N04；DEC-301② / 302 / 306④）

**(a) 登记完整逻辑总体（N02）**

| 入口 | 总体 | 说明 |
|---|---|---|
| `POST /projects/:id/calc-runs { scope: 'all' }` | 项目全部对象 ∖ terminated ∩ actor 范围 ∩ principal 可读 | 服务端枚举，无条数上限（上限 20 000，D-18） |
| `{ scope: 'filter', filter }` | 按服务端筛选条件（状态、模板、组织、标签…）枚举 | 同上 |
| `{ scope: 'explicit' }` → `POST /calc-runs/:id/objects`（每页 ≤ 500 个 id，可多次）→ `POST /calc-runs/:id/seal` | 显式勾选分页追加后**封存** | 页只是传输单位；封存前不求值；封存后总体只读 |
| 待办触发 | 本对象 | `trigger = task_save`，排名项目跳过 |

501 人一次计算的入口 = `scope: 'all'` / `filter` / `explicit` 两页后 `seal`；两次各 500 的“分次提交”不再存在（分次提交 = 两个 run，各自总体，属误用，UI 不提供）。

**(b) 冻结输入（N03）**：`seal` 后状态 `frozen`：按页读取总体对象的引用字段、模块结果、对象 `revision / result_seq`，并以系统主体预读端口记录，写入 `calc_run_inputs`（≤ 500 / 事务）；记录 `rule_revisions`（计算规则与模板版本）。之后的求值与续写只读 inputs，不再读实时数据。

**(c) 求值（一次性，N02 / DEC-306④）**：状态 `evaluating`。按对象有效规则分组逐组求值（每组一次 `evaluateBatch`），但**排名总体 = 整个 run 总体**（DEC-306④：总体由公式过滤条件决定，与所挂规则无关）——组外对象以冻结输入作只读成员进入排名（C-07 `population` 选项，§4.5(d)），组内对象叠加本组已算值；🟡 两条规则同时计算时是否互相看到对方刚算出的值：按“只看冻结输入”实现（`26` §9 未测，记差异候选）。排名口径 DEC-302：降序；并列 1、1、3；百分位 = 名次 ÷ 参与人数 × 100 保留两位小数、越小越靠前；排序字段为空的对象不参与、不计数、自身为空；范围条件可限定到单个项目（引擎对齐由 **F-045** 交付）。

**(d) 输出适配进入依赖链（N04，引擎钩子 C-07）**：`evaluateBatch(items, subjects, context, { adapt, population })`：
- `adapt(item, subjectId, value): EvaluationResult` 在引擎把某对象某项目的值放入 `computed` **之前**调用；返回失败则该项目记失败，下游依赖项目 `DEPENDENCY_FAILED`，该对象在下游项目的排名总体中不参与；返回成功则 `computed` 存适配后的值（number / option / text / date / boolean 的引擎值），排名与下游都用适配后的值。复现用例：A（number 目标）返回 `"abc"`，B = `ToNumber(A)+1` → A 失败、B `DEPENDENCY_FAILED`、A / B 都不写。
- `population?: readonly SubjectReader[]`：排名总体的额外只读成员（组外对象的冻结输入）；引擎按现有规则排除当前项目依赖失败的成员。
- 若 C-07 契约被否决，备选 = 模块用引擎导出的 `orderComputationItems` + `evaluateFormula` 自行实现同一循环（绑定叠加、依赖失败传播、排名总体注入），语义与上述一致。

适配规则（两类公式共用 `coerceToField`）：

| 目标字段类型 | 允许的引擎值 | 转换 | 失败（单项目失败，不触发 DB 错误） |
|---|---|---|---|
| number | number；数字文本；empty | `ToNumber` 语义；按 precision 定点舍入；溢出校验 | 非数字文本 / boolean / date / option → `OUTPUT_TYPE_MISMATCH`；`OUTPUT_OVERFLOW` |
| option | number / text / option，值与某启用选项 **value** 相等；empty | 写 option_value | `OUTPUT_OPTION_INVALID` |
| text | 任意标量；empty | 格式化 | — |
| date | date；ISO 文本；empty | 到日 | `OUTPUT_TYPE_MISMATCH` |
| boolean | boolean；0 / 1；"true" / "false"；empty | | `OUTPUT_TYPE_MISMATCH` |
| multi_option、`system_written`、pair 的 before 字段被②写入 | 不允许为目标：保存时 400 `TARGET_FIELD_NOT_ALLOWED` | | |

empty 一律写 null，空串视为 empty。

**(e) 暂存与发布协议（N03）**：求值结束状态 `evaluated`：全部结果写 `calc_run_outputs`（≤ 500 / 事务）。发布 `publishing` 按页进行，每页一个事务：按 id 升序锁对象 → 逐对象校验 `object.revision == inputs.object_revision`（冻结后无人改写）→ 相等则写字段值、模块结果不变、`result_seq = nextval`、`calc_status`、`last_calc_run_id`，输出 `applied`；不等（冻结后有保存 / 校准 / 审批写回）→ 该对象**不发布**，输出 `stale`，对象 `calc_status` 保持；每页提交后 `publish_cursor` 前移。规则：

| 情形 | 处理 |
|---|---|
| 已发布页的结果可见性 | 每页提交即可见（对象级原子）；run 详情显示逐对象 `applied / stale / pending` |
| 进程在发布中途退出 | 重启后按 `publish_cursor` 续写（幂等：输出已 `applied` 的对象跳过）；输入 / 输出都在库中，不依赖内存 |
| 过期 run（冻结后计算规则 / 模板版本 revision 变化） | 发布前核对 `rule_revisions`：不一致 → run `rules_changed`，整 run 不发布，提示重新计算（不静默重算） |
| 项目结束 | run 处于 `collecting～publishing` → 409 `CALC_RUN_IN_PROGRESS`，不能冻结混合版本 |
| 同一项目并发两个 run | 允许；发布时按对象 revision 校验，后发布者遇 revision 变化即 `stale`（不覆盖新值） |
| 旧 run 被新 run 取代 | 新 run 发布后，旧 run 未发布的输出标 `superseded`，不再发布 |
| 循环依赖 | 求值前判出 → `cyclic`，不写任何值（DEC-274） |
| 主体 / 所属人在任一阶段开始时失效（N06） | 每阶段（冻结、求值、发布、续写）开始重新校验系统主体与所属人授权；失败 → `principal_unavailable`，已暂存输出不发布 |

**(f) 性能（P3-03）**：排名密集负载实测（审查探针）纯引擎 2 000 × 10 个 `Ranking` 项目 ≈ 7.3 s，原因是每个对象对总体逐一扫描（O(n²)）。优化：**F-045 实现“按（项目, 范围条件, 分组）一次预排序 + 二分查名次”的总体级缓存**（C-01 扩展，排名在全体上一次性求值本就是 F-045 范围）；模块侧对冻结输入做列式缓存。目标：优化后 2 000 × 10 Ranking ≤ 5 s、10 000 × 10 ≤ 60 s；优化前的过渡目标 2 000 × 10 ≤ 10 s（用例断言取当时目标，PGlite 与真 PG 各一条，含常量公式与 Ranking 两种负载）。


- **状态语义**：`value` 有值；`empty` 真实空值；`forbidden` 系统主体 / 查看主体对该字段或该对象无权；`unavailable` 数据源不可用（如 360 端口未接）。消费方按 T05 §4.4 分别处理（`forbidden` → 对象失败，`unavailable` → 失败，`empty` → 条件按不满足）。
- **选择器（A-08 / A-09 统一）**：`resolveReviewSource(employeeId | orgId, context)`：tier 1 = `triggerMeetingId` 给定时**只取该校准会的会中对象**（不降为项目；员工不在会中 → 进入 tier 2），否则 `triggerProjectId` 的对象；tier 2 = 当前项目：`status = in_progress ∧ period_start_date ≤ asOf` 的项目里，按 `coalesce(business_date, period_start_date)` 最近者（并列取 `code` 小者）；tier 3 = 最近一次盘点：`status = ended ∧ period_end_date ≤ asOf` 里 `period_end_date` 最近（并列 `period_start_date` 最近，再 `code`）。对象 `terminated` 不计。绿化率用同一选择器（按组织：行政子树内员工为对象的项目），分母 0 → `rate = null`。
- **健康度 DTO**：`levelId / levelCode` 同时给（T05 等级字典的 id 与 code）；`status = not_provided` = 盘点侧没有该组织的健康度行（“不动旧值”）；`empty` = 有行但等级为空（“同步清空”）；`manual` 来自回写（手动 / 导入值，T05 规则计算不覆盖，DEC-305④）。

### 8.3 消费协议：身份、幂等、分页、完成（N10；A-10 / A-11）

| 概念 | 定义 |
|---|---|
| run 身份 | `runId`，不可变快照；项目重启把本项目未 `completed` 的消费记录标 `superseded`（§8.5） |
| 执行身份 | `executionId = ${runId}:${consumer}:${attempt}`，每次（重）执行递增 attempt；`beginConsumption` 登记，同一 run × consumer 同时只允许一个 running 执行（409） |
| 行幂等键 | (runId, consumer, rowKind, rowId)；`recordOutcome` 对已 `synced / superseded` 的行再次写入 = 幂等忽略；对 `failed` 行写 `synced` = **更新最新状态并追加历史**（首次失败回执留在 history） |
| 页 | 消费方按读取分页处理，**每页一个事务：业务写入 + 该页行的 `recordOutcome` 同一事务**（T05 §5.7 须改为同事务，不允许业务已提交而回执另补） |
| 完成标志 | `completeConsumption`：所有行都有终态（synced / failed / skipped / superseded）才允许；否则 409 列出未终态行。“已有回执”≠ 完成 |
| 重试 | 新执行从未终态或 `failed ∧ retryable` 的行继续；永久失败码（`SUBJECT_IN_PROCESS`、`TARGET_NOT_KEY_POSITION`、`TARGET_OUT_OF_SCOPE`、`SUCCESSOR_NOT_ACTIVE`、`READINESS_UNKNOWN`、`TARGET_NOT_FOUND`、`ACTOR_REVOKED`、`SOURCE_REVOKED`、`SCOPE_REQUIRED`）不重试 |
| unknown | 消费方事务结果未知 → `getOutcomes(runId, consumer)` 回查该页行的终态，已有终态即视为已提交，否则在新执行中重做该页 |
| 部分成功的旧 run 终止 / 恢复 | 项目重启或消费方 `abortConsumption` → 消费记录 `superseded / aborted`，剩余未终态行由盘点侧批量写 `superseded` 回执；消费方每页开始前 `authorizeSourceRead` 返回 `runStatus = superseded` 即停止 |
| 对象 / 健康度回执键 | `rowKind = object`（rowId = objectId）、`org_health`（rowId = orgId） |

### 8.4 授权（N06；A-12）

- **源读取不冻结权限**：`authorizeSourceRead` 在每次执行、每页开始、每次重试前按 run 的 `principalUserId` **当前**授权复核：系统主体被撤 TalentReview 身份 / 对象查看权 / 人员范围收窄 → 返回 `forbiddenObjectIds`（整 run 不可读时 `ok = false`）；消费方对这些对象的行写 `SOURCE_REVOKED` 永久失败，**不是空数据**。盘点侧的同步页、健康度页按查看人实时权限裁剪（§6.6）；回执重试同样先复核。
- **目标写入**由消费方按同一身份模型复核（§8.1），撤权 → `ACTOR_REVOKED`。
- `SourceViewer` 只有 `principal`（系统主体，消费 / 端口）与 `user`（页面查看人）两种，不再有不裁剪的 trusted。

### 8.5 版本与取代（A-03）

run 冻结后不变；项目重启 → 本项目所有未 `completed` 的消费记录与 run 标 `superseded`（`supersededByRunId` 指向重启后第一个新 run，没有时为空）；手动 run 只能被“项目重启”取代，不被后续手动 run 取代（两次手动同步各自独立）。消费方读到 `superseded` 只写 `superseded` 回执。

### 8.6 健康度回写契约（A-06；N09）

```ts
export interface OrgHealthWrite { orgId; levelId: string | null; levelCode: string | null; manual: boolean; status: 'value' | 'empty' }
export type HealthWriter = { kind: 'run'; runId: string; consumer: 'succession' } | { kind: 'user'; userId: string }   // 手动“计算健康度”/“重置”由 T05 以用户身份回写
```
- T05 规则计算（同步触发或手动）得到的结果经 `recordOrgHealth` 写 `talent_review_project_org_health`（`method = computed`，带 `computed_by_run_id` 或用户）；手动赋值 / 导入值由 T05 以 `manual = true` 回写（`method = manual`），之后 T04 输出 `manual = true`、T05 计算不覆盖（DEC-305④）；“重置”以 `method = reset` 覆盖手动值并清标记。回写前 T04 校验：项目可见于写主体、组织在其范围；否则 403。
- 无 run 的手动健康度计算：T05 用 `readReviewFields` / `readSuccessionEntries` / `greenRate`（`context` 不带 run）取数，再回写，无需 run。

### 8.7 其他约定
- 批量：对象页 ≤ 500、提名页 ≤ 2000 是读取分页；逻辑批次 = 一个 run。
- `direction = target` 行照常进 run；是否写正式继任记录 🟡（Q-T04-10，保守：消费方回执 `skipped`）。
- 字段目录 `optionDomain` 的 `value` 一律字符串（与 `talent_review_field_options.value` 同），`kind = option` 的 `values` 返回选项 value；`multi_option` 返回 `string[]`。

## 9. 并发、幂等、锁（P2-16 已关闭；N11）

**结果版本不再写项目行**：对象级结果写入（评估提交、计算发布、校准、结果审批通过）只更新对象行并取 `talent_review_result_seq.nextval` 写 `objects.result_seq`；项目级“版本”派生自对象 `result_seq` 最大值；同步 run 冻结记录 `source_seq = max`。于是对象级操作不再需要把项目共享锁升级为排他锁，N11 的升级环消失。

**统一锁序**（首个排他资源按操作列出）：

```
员工行（FOR SHARE，仅新增对象 / 设置执行人）
→ 盘点项目（对象级操作 FOR SHARE；项目级状态变更 FOR UPDATE；对象级操作不更新项目行）
→ 校准会（校准 FOR SHARE；结束 / 删除 FOR UPDATE）
→ 结果审批单（FOR UPDATE）
→ calc run 行（FOR UPDATE，发布 / 续写 / 取消）
→ 盘点对象（FOR UPDATE，按 id 升序批量）
→ 评估记录 / 任务 / 提名行（按对象顺序）
→ 审批实例（引擎内部）
```

| 操作 | 加锁顺序 | 更新的行 |
|---|---|---|
| 评估保存 / 提交 | 项目 S → 对象 X → 任务 / 记录 | 对象、记录（`result_seq` 仅提交时） |
| 校准 | 项目 S → 校准会 S → 对象 X | 对象、路径 |
| 校准会结束 | 项目 S → 校准会 X → 对象 X（升序） | 校准会、对象 |
| calc run 冻结 / 发布页 | 项目 S → run X → 对象 X（本页升序） | run、inputs / outputs、对象 |
| 项目结束 / 重启 | 项目 X → 校准会 S → run S（存在 running → 409）→ 对象 X（升序） | 项目、对象状态不变 |
| 删除对象 | 项目 S → 对象 X | 级联 |
| 结果审批发起 / 回调（适配器 `lock`） | 项目 S → 审批单 X → 对象 X（升序）→ 引擎锁实例 | 审批单、对象 |
| 手动同步 | 项目 S → 对象 S（只读冻结）→ run X | run、快照表 |

真 PG 交错用例：① **两人同时校准同一项目的不同对象（N11，断言无死锁、两边都成功、各自 `result_seq` 递增）**；② 校准 vs 校准会结束；③ 同一对象两席位并发保存；④ 两个 calc run 并发（发布时后者对已改对象 `stale`）；⑤ 校准拖拽 vs calc run 发布（同对象：发布方校验 revision → `stale`）；⑥ 项目结束 vs 评估提交；⑦ 位置字段交叉列并发；⑧ 同一 run 两个消费执行并发（第二个 409）。

幂等：`Idempotency-Key` + `If-Match`（DEC-067），复用 `runCommand`；重放按当前权限复核。批量：添加对象 / 导入 / 批量提交 / 校准会加人 / 手动同步勾选单次 ≤ 500（体验差异，DEC-301②）；calc run 总体不受 500 限制（§4.5(a)）。审计同事务，不伪造。
