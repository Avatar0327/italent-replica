# F-123 表单提交内核（先行段）

依据 DEC-464、DEC-473、DEC-474、DEC-475②、DEC-483①。只处理前端提交生命周期，不改变服务端命令、权限、日期或业务规则。

## 页面片接入

1. 页面根放 `<FormCommands>`，必须高于页签、详情、表单，关闭重开不能销毁它。租户、身份、业务路径组成隔离键。页面离开后的持久化不在本段范围，不写 localStorage。
2. `useCommandForm(resource)` 的 resource 用稳定业务路径，新建用集合路径，编辑用原单路径；不要带 revision。返回 `state`（未提交为 idle）、`busy`、`locked`、`submit`、`reread`、`confirm`、`clear`。
3. `submit` 传当前 `values`、服务端原值 `baseline`、**当前**可编辑字段 `editableFields`、`revision`、可选 `businessId` 和命令函数 `send`。内核同步上锁并创建命令 ID；命令函数接收固定的 `{id, revision, body}`，不得自行再建 ID。`patchOnly` 只提交编辑字段与基线的差异。
4. 有生效日期的业务，可传 `effectiveDate`（服务端要求的业务日期上下文，按租户时区由页面提供）；若日期本身是可编辑业务字段，放在 `values` 并列入编辑字段集合。没有该契约的接口不要额外传日期。内核不把无编辑权的日期从表单中带回，也不推算日期。
5. `send` 必须返回已验证回执适配后的 `{id}`，无效回执按未知处理。传了 `businessId` 时此 ID 必须对应原单；源对象与结果对象不同的命令须按下文适配，不能直接把结果 ID 当作原单 ID。成功后页面回读服务端，不用输入拼装已保存对象；再 `clear`、关闭表单。
6. 显示 `<CommandStatus submission={...} labels={字段中文名}>`；用 `locked` 禁用输入及提交，但允许关闭未知/冲突表单。AntD `FormOverlay` 可传 `submission`，自动显示状态并回填内核保留的值。不要用“不可编辑权限”替代提交锁，否则输入组件会被卸载。

```tsx
// 原单更新且回执 ID 与原单相同：例如 360 活动。
const command = useCommandForm(`/api/tenant/survey360/activities/${id}`);
const submission = {
  ...command,
  reload: () => command.reread(async (originalId) => {
    const latest = await api.request<Activity>(`/api/tenant/survey360/activities/${originalId}`);
    return { id: latest.id, revision: latest.revision, values: project(latest) };
  }),
};
const result = await command.submit({
  values, baseline, editableFields, revision, businessId: id, patchOnly: true,
  send: (request) => api.request<Activity>(`/api/tenant/survey360/activities/${id}`, {
    method: 'PATCH', command: request,
  }),
});
// result.status === 'done' 才可关闭；否则保留输入并展示 submission。
```

复杂 DTO 的投影/规范化参见 `evaluation/useRecordForm.ts`。`reread` 的投影必须与表单初始值同构，读取失败不能清掉表单。编辑权限和业务状态锁使用 `current`（最新读取值）重新计算。

## 提交锁与只读值

`FormOverlay` 自动提供 `<FormLock locked={submission.locked}>` 和 `LockedField`；自建向导须同样提供它们。
`LockedField` 放在 `Form.Item` 内，转交 value/id/onChange，并拦截锁定期间的变更。
复杂子控件使用 `useFormLock(businessDisabled, readOnly)`：将返回的 `disabled` 传到每个输入控件，
用 `guard(onChange)` 包装内容变更、增删、排序等回调。最终禁用条件是提交锁、业务禁用、只读及 AntD Form 禁用上下文的并集；
不能用 `disabled={false}` 覆盖上下文。守卫执行时读取当前锁，旧浮层保存的回调也不能绕过。

只读显示使用最新服务端记录（`submission.state.latest.values` / `useRecordForm().current`），包括链路和条件。
Form 初始值与内核 `state.values` 是草稿来源，只用于仍可编辑的字段；不得拿旧 initialValues/row 显示重读后的只读值。
复合字段部分转只读时，用 `editableRows` 按稳定行 ID/key 将仍可编辑的子字段投影到最新服务端结构；
展示与提交必须复用同一投影。当前套卷/模板的分值、结构引用以及有报名链路的类型、评委表单、硬截止均按此处理。
权限不可见字段仍不展示。只读文案/格式化值也必须从 current 派生，不能闭包捕获旧记录。

## F-127b：合同源对象与结果对象适配

当前合同接口见 `apps/api/src/modules/contracts/routes.ts`、`service.ts`、`configuration.ts`。
合同新签/续签/变更/终止走 **POST `/api/tenant/contracts/commands`**，请求体为
`{ operation, mode, employeeId, targetId?, fields }`；原合同读取走 `/records/:id`，不是 PATCH `/contracts/:id`。
`revision` 对应源合同（新签为 0）。`fields` 必须来自内核过滤后的 `request.body`；生效日期放在 fields 中。
申请模式返回新申请，直接模式也可能因未来生效返回申请，或返回已生效合同；不能仅按 mode 推断结果对象种类。

已有源合同的示意接法如下（DTO 校验函数由合同页面片按实际可见回执定义）：

```tsx
const sourceId = source.id; // 稳定原合同，不是续签结果或申请 ID
const command = useCommandForm(`/api/tenant/contracts/records/${sourceId}/${operation}/${mode}`);
const submission = {
  ...command,
  reload: () => command.reread(async (originalId) => {
    const latest = await api.request<ContractRecord>(`/api/tenant/contracts/records/${originalId}`);
    return { id: latest.id, revision: latest.revision, values: projectContractFields(latest) };
  }),
};
// 在每次显式保存函数内定义，避免失败时误用上次回执。
let receipt: ContractReceipt | undefined;
const result = await command.submit({
  values, baseline, editableFields, revision: source.revision, businessId: sourceId,
  send: async (request) => {
    const raw = await api.request<unknown>('/api/tenant/contracts/commands', {
      method: 'POST',
      command: { ...request, body: { operation, mode, employeeId: source.employeeId,
        targetId: sourceId, fields: request.body } },
    });
    // 验证服务端成功回执的非空 id、revision、对象形态、employeeId 与当前操作相符。
    // 验证不通过须抛异常进入 unknown，不能在 finally 或 catch 中返回 sourceId。
    receipt = parseContractReceipt(raw, { employeeId: source.employeeId, operation });
    return { id: sourceId }; // 确认本源对象命令已有回执，保持内核的原单核对身份
  },
});
if (result.status === 'done' && receipt) {
  // done.businessId 在该适配中仍是 sourceId；结果 ID 必须取 receipt.id。
  // 按真实回执区分申请/合同并回读结果，不能用 sourceId 导航到新申请或新合同。
  await reloadContractResult(receipt);
  command.clear();
}
```

`parseContractReceipt`、`projectContractFields`、`reloadContractResult` 是页面 DTO 适配函数的示意名，
不是内核提供的 API；不能省略回执验证，也不能用输入拼造成功回执。
新签没有源合同时不传 `businessId`，`send` 验证回执后返回真实结果 `{id: receipt.id}`，
此时 `done.businessId` 就是结果 ID。未知结果即使回读源合同成功也仍锁定，不把它当成结果对象。

合同设置没有独立 `id`：GET/PUT `/api/tenant/contracts/settings` 返回 `tenantId`、`revision` 等。
用回执确认的租户单例 ID 适配即可，无须修改状态机：

```tsx
const command = useCommandForm('/api/tenant/contracts/settings');
const result = await command.submit({
  values, baseline, editableFields, revision, businessId: tenantId, patchOnly: true,
  send: async (request) => {
    const saved = await api.request<ContractSettings>('/api/tenant/contracts/settings', {
      method: 'PUT', command: request,
    });
    if (saved.tenantId !== tenantId || saved.revision !== request.revision + 1) {
      throw new Error('合同设置回执无效'); // 产品文案在页面资源文件中定义
    }
    return { id: saved.tenantId };
  },
});
// 冲突显式重读适配（不是重发命令）：
await command.reread(async () => {
  const latest = await api.request<ContractSettings>('/api/tenant/contracts/settings');
  return { id: latest.tenantId, revision: latest.revision, values: projectSettings(latest) };
});
```

若 `tenantId` / `revision` 被裁掉或回执无法验证，必须维持 unknown，不能无条件用本地 tenantId 伪造成功。
设置无生效日期契约，不额外附日期。所有适配沿用同一 command.id/revision，不重新生成命令 ID。

## 状态与恢复

| 状态 | 输入 / 命令 | 可执行动作 |
| --- | --- | --- |
| idle | 可编辑 | 显式提交 |
| submitting | 只读；同键重复提交直接返回原状态，不创建 ID | 等待回执 |
| rejected | 4xx 明确拒绝，保留输入及原因 | 修改后显式提交新命令 |
| unknown | 断网、超时、5xx、无效回执，页面保留原命令与输入 | 关闭重开仍锁定；已知 ID 可只读回查原单 |
| conflict | 仅 409 REVISION_CONFLICT；保留输入 | 显式重读、查看原值/最新值/我的输入，核对后继续编辑 |
| done | 服务端确认的业务 ID | 回读、关闭或清理已完成状态 |

冲突重读比较原基线与最新版本；只回填服务端有变化且用户未编辑的字段，用户修改始终保留。确认只解除冲突锁，不发送命令；下次显式提交使用最新 revision，再次冲突仍进入同一流程。无字段变化也必须核对。普通 409 不进入版本冲突分支。

**未知结果不能仅凭当前 revision 或字段碰巧相等判成功**。原单读取会把 `latest` 回填到只读核对区，仍保留 unknown 与原 ID；本段不提供强制解锁/重放接口。新建无业务 ID 时仅展示未确认命令，待对应业务提供权威命令查询契约后接入。页面重开和页签切换受保护，整页刷新/跨页面持久恢复需后续业务回执契约支持。
