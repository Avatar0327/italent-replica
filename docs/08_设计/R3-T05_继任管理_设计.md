## 2. 接口与命令执行协议

### 2.1 命令执行协议（所有写入口，含幂等重放）

1. **命令前**（路由层）：`uuidParam` / 请求体 UUID 小写化（DEC-194）→ `objectContext(对象, 操作)` → `button(对象, 按钮)` → **资源范围判定**（本模块显式做：目标 / 对象 / run / 批次按 §8.2 锚点与谓词；对 run / 批次驱动类入口按 §4.0 的“实际执行集合”判定）→ 结构校验（输入白名单）→ `writeFields(对象, 操作, 写字段)`（含显式置空键）→ `requestScope(对象)`。
2. **命令内**（`runCommand` 的 `execute`，一个租户事务）：`authorizeInTransaction` 重验对象 / 按钮；按 §7 锁序加锁；锁内重读并重验资源（目标仍在范围、继任者仍在职、revision 一致、计划屏障）；业务写 + 审计（同事务）+ outbox / 通知登记。
3. **返回前**（另开事务，首次响应 / 直接重放 / 失败回查重放三条路径同一函数 `authorizeSuccessionResult`）：按台账命令 ID 读审计足迹与响应引用的对象 ID，逐个按请求人**当时**的对象权限与范围复核（不可见 → 404），再做 §8.4 投影。`commands.ts:41 / 59 / 81` 命中台账直接返回原响应体，所以投影每次都在返回前重做。
4. **失败**：业务失败 / 存储不可写 / 结果未知三类按 `audit/failures.ts` 记录；结果未知返回 503 `RESULT_UNKNOWN`。

### 2.2 路由

前缀 `/api/tenant/succession`；写命令带 `Idempotency-Key` 与 `expectedRevision`（对象级）/ `expectedCollectionRevision`（集合级）/ `items[].expectedRevision`（多对象）；请求体 ≤ 32KB，规则保存放宽到 64KB。

## 3. 条件行编译器（公共模块 `packages/domain/src/expression/rules/`）

R3-T06 入池规则（Q-M0-114 `PoolRule`：`Fields` + `Expression`）与本任务的风险 / 健康度 / 人群共用；规则组、字段值优先级、重复人员处理留在 T06 宿主。

### 3.1 对象、字段引用与类型适配

```ts
type FieldKind = 'text' | 'number' | 'option' | 'multi_option' | 'date' | 'boolean';
interface FieldRef { object: 'employee' | 'employment' | 'successor' | 'review_object' | 'org'; code: string; path: string; kind: FieldKind;
                     optionDomain?: readonly { value: string; label: string; enabled: boolean }[] }   // 以 T04 ReviewFieldDescriptor 为准（A-07）
type Operator = 'is_empty' | 'not_empty' | 'eq' | 'ne' | 'gt' | 'lt' | 'ge' | 'le' | 'between';
interface ConditionRow { rowNo: number; kind: 'aggregate' | 'field'; field?: FieldRef; operator: Operator; values?: readonly (number | string | boolean)[] }
interface RuleSet { rows: readonly ConditionRow[]; expression: string }
interface CompiledRule { formula: string; rowSpans: readonly { rowNo: number; start: number; end: number }[]; referencedRows: readonly number[]; unreferencedRows: readonly number[]; constantFalseRows: readonly number[]; compilerVersion: string }
```

| `FieldKind` | 宿主注入值（`PlainValue`） | 引擎 `StaticKind`（`fieldKind` 回调） | 说明 |
|---|---|---|---|
| `number` | number | `number` | — |
| `text` | string | `text` | — |
| `date` | Date / 日期文本 | `date` | — |
| `boolean` | boolean | `boolean` | — |
| `option` | `OptionValue { optionValue, label }`（T04 选项 `value` 一律字符串） | `text` | 比较经引擎 `unwrapOption`，字面量按字符串发码 |
| `multi_option` | 端口值为 `PortValue = readonly string[]`（A-07）；T05 适配层可无损序列化为 `"\|v1\|v2\|"`（无选中 → `null`，值内含 `\|`、`"`、换行 → `RULE_LITERAL_INVALID`） | `text` | **取证前多选字段不进条件行**（DEC-314②；是否适用于 T05 条件行 → Q-SC-23，正文暂按适用：保存 400 `RULE_FIELD_NOT_ALLOWED` 并提示）；放开后用上述编码，不改引擎 `PlainValue` |

- **`aggregate` 行**（风险 / 健康度）：宿主先算度量值，以字段 `行n.值`（number）注入；度量为空（§4.1）注入 `EMPTY`，**不注入布尔值**。
- **`field` 行**（人群、T06 入池）：直接对对象字段比较；无权字段返回 `forbidden`（§4.1）。
- T06 映射：`ItemMetaObjectName = CalibrationObjective` → `object = 'review_object'`；`FieldName` → T04 字段 `code`；`Values` → `values`；`Expression` → `expression`。

### 3.2 发码表（引擎实际语法；R3-06）

引擎支持中缀 `and / or / not`（`lexer.ts` 关键字 `且 / 或 / 非`，`and` 为 JS 短路）、`IN(值, 候选…)`、`IsEmpty(x)`、`Contains(文本, 子串)`；比较符 `= != < > <= >=`。

| 行定义 | 发码 | 空值行为 |
|---|---|---|
| `is_empty` | `IsEmpty(F)` | 度量 / 字段为空 → 满足 |
| `not_empty` | `not IsEmpty(F)` | 为空 → 不满足 |
| `eq` 单值 / 多值 | `(not IsEmpty(F) and F = L)` / `(not IsEmpty(F) and IN(F, L1, L2, …))` | 为空 → 整行 false（守卫在前，`and` 短路，不触发空值比较失败） |
| `ne` 单值 / 多值 | `(not IsEmpty(F) and F != L)` / `(not IsEmpty(F) and NOTIN(F, L1, …))` | 为空 → false（避免 `!= 0` 误命中） |
| `gt / lt / ge / le` | `(not IsEmpty(F) and F > L)` 等 | 为空 → false（不触发 `TYPE_CONVERSION` / `EMPTY_IN_COMPARISON`） |
| `between` | `(not IsEmpty(F) and F >= L1 and F <= L2)` | 为空 → false |
| `multi_option` `eq`（含任一） | `(not IsEmpty(F) and Contains(F, "\|v1\|"))`；多值 `(not IsEmpty(F) and (Contains(F, "\|v1\|") or Contains(F, "\|v2\|")))` | 无选中 → false |
| `multi_option` `ne` | `(not IsEmpty(F) and not (<含任一发码去守卫>))` | 无选中 → false |
| 需要值的运算符而值列为空 | 编译为常量 `false`，记入 `constantFalseRows`，保存时警告 `RULE_ROW_VALUE_MISSING n`（DEC-305④“值为空的条件行按不满足”） | — |
| 字面量 | number → 十进制；text / option → 英文双引号包裹，**值内不得含 `"` 或换行**（`scanString` 无转义，`RULE_LITERAL_INVALID`）；date → `"YYYY-MM-DD"`；boolean → `true` / `false` | — |
| 组合 / 整体 | 行引用 → `(<子式>)`；`and / or` 中缀；`IF(<组合>, 1, 0)` | 结果 `1` 即匹配 |

样例：T06 九宫格 `IF((not IsEmpty(盘点对象.绩效_潜力九宫格位置_after) and IN(盘点对象.绩效_潜力九宫格位置_after, 7, 8, 9)), 1, 0)`；本租户中风险 `1 and 2`：`IF((not IsEmpty(行1.值)) and (not IsEmpty(行2.值)), 1, 0)`；健康度“绿化率 ≥ 30%”：`(not IsEmpty(行1.值) and 行1.值 >= 0.3)`。

### 3.3 编译、规模与保存

1. `parseRowExpression`：词法只认 `and / or / ( ) / 正整数`（大小写不敏感；容忍无空格）；文法 `expr := term (or term)* ; term := factor (and factor)* ; factor := int | '(' expr ')'`；错误 `RULE_EXPRESSION_SYNTAX`（位置）、`RULE_ROW_UNKNOWN n`；未引用行记入 `unreferencedRows`（拦截还是警告 → Q09 🟡，正文暂按警告）。
2. `compileRuleSet(rules, catalog)`：逐行类型校验（字段存在、运算符与类型合法、值个数）→ 发码 → 组合；记录 `rowSpans`（同一行多处引用 → 多区间）。
3. 规模上限：行数 ≤ 50、每行候选值 ≤ 20、括号嵌套 ≤ 20；发码后以 `validateFormula` 对齐引擎 4000 字符 / 800 词 / 100 层；超限 400 `RULE_TOO_LARGE`。
4. `validateFormula(formula, { registry, isKnownField, fieldKind })`：`fieldKind` 按 §3.1 降映射；推导不确定 → 保存报错（DEC-287 补充）。
5. 保存：条件行 + 表达式 + 编译缓存同事务；任一步失败 400 定位到行号（`RULE_ROW_INVALID n`）；`compiler_version` 随缓存写入；引擎语义变化后用平台命令重新编译（#19），**不得用表达式反写条件行**（DEC-261）。

### 3.4 求值、错误定位与安全文案

- 定位：`ComputationFailure` 顶层 `offset / line / column` 落在 `rowSpans` 区间 → 行号；缺省或组合层 → 条件表达式。
- **文案**：引擎 `message` 可能带字段值（`operators.ts:207`），一律不存、不出站；失败只记 `code` + `level_id` + `row_no`；所有出口（列表、详情、失败明细、首次响应、两种重放、通知、审计）按固定映射渲染：

| 错误码 | 固定文案 |
|---|---|
| `TYPE_CONVERSION`、`ARGUMENT_TYPE` | 第 n 行条件出错：比较或转换时类型不符 |
| `EMPTY_IN_COMPARISON`、`EMPTY_IN_ARITHMETIC` | 第 n 行条件出错：空值参与运算 |
| `DIVISION_BY_ZERO` | 第 n 行条件出错：除以 0 |
| `FIELD_FORBIDDEN` | 第 n 行条件出错：计算主体无权读取字段 |
| `DATA_UNAVAILABLE` | 第 n 行条件出错：数据源不可用 |
| `UNKNOWN_FIELD`、`UNKNOWN_FUNCTION`、`SYNTAX_ERROR` | 第 n 行条件出错：规则需要重新编译 |
| 其他 / 无行号 | 条件表达式出错 |

同步回执 `error_code` 同样只按码渲染（`SUBJECT_IN_PROCESS` → “盘点对象仍在流程中”等）；T04 `OutcomeItem.errorParams` 只带行号 / 等级等结构化参数，不带文案。

### 4.1 共同口径

- 时间：业务日期按租户时区（`tenantLocalDate`，DEC-056）；事件时间 UTC。
- 在职员工 = `asOf` 当日时间轴（`employment_timeline.valid_during @> asOf`）上的主职版本人员状态 ∉ {离职 8、调出 4、退休 6}（待入职 1 不算现任）；已删除（墓碑）/ 撤销的任职不参与。
- 现任人员（职位）= 该日主职 `position_id = 职位` 的员工；`part_time_in_risk_calc` 开时并入兼职任职（端口，R2-T05 前为空集）；负责人（组织）= 该日组织版本 `person_in_charge_id`。
- 继任者 = `succession_records` 中目标匹配、在 `asOf` 生效（§5.1 区间）、未删除；同一人对同一目标只计一次。
- **度量 / 字段来源五态**：

| 状态 | 含义 | 对等级判定的影响 |
|---|---|---|
| `value` | 取到值 | 正常求值 |
| `empty` | 真实空值：字段为空、人口为空、**分母为 0** | 注入 `EMPTY`，由 §3.2 的守卫把该行判为“不满足”（DEC-305④ 健康度取证；**风险等级同一规则**，Q-SC-19 由 DEC-311 定，🟡 取证待补）；零分母在卡片与结果里显示“--” |
| `forbidden` | 执行主体无该字段 / 该对象读权（T04 `FieldStatus = forbidden`；引擎 `FieldLookup.status = 'forbidden'` → `FIELD_FORBIDDEN`）；同步批次里一律记协议公共码 `SOURCE_REVOKED { scope: object \| field \| source \| org, ref }`（A-17 / A-18，不再有 `SOURCE_FORBIDDEN`） | **该等级失败 → 对象计算失败**，不注入 EMPTY，不向下匹配 |

| `module_absent` | 规格允许的“映射取不到”：健康度 `succession` 字段在盘点来源里**没有继任模块**（SC-R16；DTO `succession.status = module_absent`，或 `SuccessionReadResult.status = module_absent`，A-06 / A-19）；有模块但零提名（`present` + `count = 0` / `value` + 空数组）不属于此态，人数按 0 | **跳过该等级**，记 `skipped`，继续下一等级 |

- **等级判定**：按 `display_order` 顺序求值（健康度：满星 → 1 星，DEC-305④）；第一个得 `1` 的等级即结果；某等级**失败**（求值失败、无权、不可用、编译缓存失效）→ 对象“计算失败”（DEC-257），**结果不改写**，失败明细带等级与行号，不向下匹配；只有 `module_absent` 跳过；全部不匹配或全部跳过 → `level_id = null`（默认颜色）。
- 比例度量按小数计算（0.3 = 30%），不预先舍入（比较用原值还是舍入值 🟡 §9）；显示保留 1 位小数（“100.0%”）。
- 执行主体按 §4.0。

### 4.6 调度、幂等键与状态机

| trigger | 键格式 |
|---|---|
| 定时 `position_risk` / `exit_sweep` | `<kind>:schedule:<tenant>:<本地日期>` |
| 定时 `org_stats` | `org_stats:schedule:<tenant>:<本地日期>:<interval_h>h:<slot_index>`，`slot_index = floor(自当日租户本地 0 点起的分钟数 / (interval_h × 60))`；纪元 = 该本地日期的租户本地 0 点；当天把间隔改回旧值时旧槽键已存在 → 视为已跑，下一槽起生效 |
| 手动（含重置） | `<kind>:manual:<commandId>` |
| 显示设置变更 `org_stats` | `org_stats:preferences:<user>:<preferences revision>` |

| 重试 | 不换键；`attempt_no + 1`、状态回 `pending` |

**本模块 run（风险 / 健康度 / 重置 / 统计 / sweep）状态机**：`pending → running → succeeded | partial | blocked | aborted`（无 T04 消费记录）。

| 状态 | 含义 | 恢复入口 |
|---|---|---|
| `blocked` | 可恢复：系统主体（= 所属人）不可用、规则缓存失效（`RULE_CACHE_STALE`，重新编译后可续）、基础设施错误；冻结的对象集合不变 | 同一 run `retry`（#10，不换幂等键，`attempt_no + 1`）：只跑未终态与可重试失败的对象 |
| `partial` | 有对象失败（§3.4 码、`PRINCIPAL_SCOPE_MISSING`、`revision_conflict`） | `retry` 重跑可重试对象；`revision_conflict` 不重跑（DEC-311：刷新后重新发起重置） |
| `aborted` | SA 终止 | 不可恢复，只能新 run |
| `succeeded` | 无失败（允许 `manual_kept`、`unchanged`） | — |

**同步批次状态机（三类失败，A-17；动作以协议为准，本表是 T05 侧落地）**

| 批次状态 | 进入条件 | T04 消费记录 | 计划 / 屏障 | 租户互斥 | 恢复入口 |
|---|---|---|---|---|---|
| `waiting` | 互斥被另一未结束批次持有（`BATCH_IN_PROGRESS`） | 未开始（不调用 `beginConsumption`） | 无 | 不持有 | outbox 重投（退避）/ `POST /sync`；互斥释放后进入 `planning` |
| `planning` | 持互斥且 `beginConsumption` 成功 | `running` | 本事务写 | 持有 | — |
| `executing` | 计划已提交 | `running`（逐页 `renewLease`） | 屏障生效 | 持有 | — |
| `blocked`（**R 类：保留计划、可恢复**） | 计划或执行阶段：源授权 `ok = false`（`PRINCIPAL_UNAVAILABLE` / `OWNER_UNAVAILABLE` / `PROJECT_INVISIBLE`）、写主体失效（`PRINCIPAL_UNAVAILABLE`）、页级基础设施错误；一轮结束仍有 `failed ∧ retryable` 行 | **保持 `running`，不调用 `abortConsumption`**；租约自然到期，恢复时 `beginConsumption` 接管（`executionNo + 1`） | 有计划 → 计划与屏障保留；计划阶段受阻 → 无计划、无屏障 | 有计划 → 保持；无计划 → 释放 | 自动重试（退避 1 / 5 / 30 分钟，最多 3 次）；之后 #17 `retry`（调用人范围检查）或权限恢复后 outbox 重投；恢复扫描定时找“`blocked` 且到期”的批次。每次恢复都重做源授权、写主体、所属人复核；同一 run 继续，不重做原触发人授权 |

| `INFRA_ERROR` | 目标 / 行，或整页 | 行 `failed ∧ retryable`；整页失败 → 批次 R 类 | 协议公共码（取代 T05 旧 `STORAGE_UNAVAILABLE`） |
| `SOURCE_UNAVAILABLE` | 行 | 外部来源暂不可用：行 `failed ∧ retryable` | **提请协议收入**；协议不收则映射为 `INFRA_ERROR { cause: 'source' }` |
| `PRINCIPAL_UNAVAILABLE { principal: source \| write }`、`OWNER_UNAVAILABLE`、`PROJECT_INVISIBLE` | 批次 | R 类 `blocked` | 协议公共码；`principal` 参数提请协议收入（区分源读取主体与写主体） |
| `CONSUMPTION_LEASED` / `BATCH_IN_PROGRESS` | 批次 | 前者：另一 worker 在执行本批次，本次退出；后者：`waiting` | 协议公共码 |
| `EXECUTION_INACTIVE` | worker | 本 worker 已被接管：停止、不改批次 | 协议公共码（取代 T05 旧 `LEASE_LOST`） |
| `RUN_SUPERSEDED`、SA 终止（原因 `ADMIN_ABORT`） | 批次 | T 类 `terminated` | 协议公共码；`ADMIN_ABORT` 提请协议收入为 `abortConsumption` 原因 |
| `SCOPE_REQUIRED`、`UNSUPPORTED_TRIGGER`、`ACTOR_SCOPE_EXCEEDED` | 批次 + 全部行 | N 类 `rejected` | 协议公共码 / 后两个提请协议收入 |
| `ACTOR_REVOKED` | — | T05 不再产生（触发人不是写主体；写主体失效用 `PRINCIPAL_UNAVAILABLE { principal: write }`） | 协议按 A-12 调整 |
| 入口拒绝：403 `BATCH_SCOPE_EXCEEDS_REQUESTER`、409 `RUN_NOT_RETRYABLE`、409 `TARGET_SYNC_IN_PROGRESS`（手动写撞屏障）、409 `BATCH_IN_PROGRESS`（`/sync` 时） | HTTP | 不进批次状态、不写回执 | T05 接口码 |

`RULE_CACHE_STALE` 只出现在本模块 run（同步批次不求值规则）。本模块 run 的对象失败码见 §3.4 与 §4.0，不进此表。

## 5. 业务规则落地

### 5.1 时间轴（SC-R1、SC-R2；DEC-305 ①②③）

- 区间定义：记录在日期 `d` 生效 ⇔ `start_date ≤ d < end_date`（半开）；`end_date = 9999-12-31` 为当前生效。
- 新增 / 编辑：`startDate ≤ 今天`（400 `START_DATE_IN_FUTURE`）；`endDate` 给出时 `≤ 今天`（400 `END_DATE_IN_FUTURE`，提示原文“结束时间不可以大于今天”）且 `≥ startDate`（400 `END_BEFORE_START`）；历史补录允许开始、结束都在过去，保存即“已结束”；列表默认只返回当前生效，`status=all` 才含已结束。
- 区间不重叠（同目标同继任者）：命令内在目标锁下先查重叠：与当前生效记录重叠 → 409 `SUCCESSION_DUPLICATE`；只与历史记录重叠 → 409 `SUCCESSION_PERIOD_OVERLAP`；不交叉的历史区间可并存；同一目标可有多名继任者；§1.1 排他约束兜底；恢复生效（置空结束时间）同样查重。
- 目标校验：组织继任的目标组织在执行人范围内且当日有效（否则 404）；职位继任的目标职位在范围内、启用、`is_key`（400 `TARGET_NOT_KEY_POSITION`，候选接口也只列关键职位，DEC-305③）；继任者在职（400 `SUCCESSOR_NOT_ACTIVE`；按 §4.1 定义，待入职 1 算在职、可被提名，与 DEC-308 下拉含待入职一致），**不校验继任者是否在操作人员工范围内**（DEC-308，用户选择的原站口径）；准备度启用（400 `READINESS_DISABLED`）；目标存在未完成同步批次的计划屏障 → 409 `TARGET_SYNC_IN_PROGRESS`。
- 继任者候选（#3a `GET /successor-candidates?q=`）：**全租户**关键词搜索，含待入职，最多返回 30 条，**不受操作人 HR 数据范围限制**，返回 `{ employeeId, name, email, status }`（原站显示“姓名(邮箱)”，关键词匹配姓名 / 邮箱；是否还匹配工号 🟡 未取证，正文暂按姓名 / 邮箱），不按数据范围、也不按员工信息字段权裁剪——**DEC-308，用户选择的原站口径**（2026-10-07 用户选 C，不采纳收紧方案；审查不作为信息泄露缺陷）。入口授权 = 持 Record `create` 或 `update` 按钮；排除离职 / 调出 / 退休与墓碑；不返回其他字段；`q` 为空 → 400。保存后记录里嵌套的继任者同样**照北森正常显示**，不按查看人数据范围隐藏（DEC-311③，Q02 后半；🟡 具体展示字段未取证，正文暂按姓名(邮箱)）。

### 5.2 结束（SC-R3）

- `POST /records/end`：整批原子；逐条校验 `endDate ≤ 今天`、`≥ 该条 startDate`（400 `END_BEFORE_START` 列出 ID）、可见（任一不可见整批 404）、未结束（409 `ALREADY_ENDED` 列出 ID）、`expectedRevision`（409 `REVISION_MISMATCH` 列出 ID）、无计划屏障（409 `TARGET_SYNC_IN_PROGRESS`）；写字段级审计（`end_date`、`end_reason`、`end_source = manual`）。**锁序（R4-02）**：先无锁读出各记录的目标 ID（目标列不可改，`FIELD_IMMUTABLE`），按目标锁行升序 `FOR UPDATE`，再按记录 ID 升序 `FOR UPDATE` 重读记录，用重读后的状态、`revision`、屏障做上述校验（取锁前被删除 → 404，被结束 → `ALREADY_ENDED`，revision 变了 → `REVISION_MISMATCH`），再写入；与 §7 全部入口一致“目标锁 → 记录行”。

### 5.3 删除

- 软删除 + 审计整条快照；删除后不参与任何统计 / 规则 / 同步比对；同键重放返回原回执（返回前仍复核当前范围）；新命令对已删记录 404；有计划屏障 → 409。锁序同 §5.2（R4-02）：无锁读目标 ID → 目标锁行 → 记录行重读（存在、revision、屏障）→ 删除。

### 5.4 离职自动结束（SC-R4，AC-SC-02）

### 5.7 盘点 → 继任同步（SC-R13～R16；按《R3-T04/T05 同步协议》）

> **协议只引用、不重写**（DEC-330 A'）：run / 执行 / 页命令身份、消费租约与接管、行幂等键、完成条件、`authorizeSourceRead` 返回结构、公共错误码与三类失败、A-20 目标登记、健康度凭据与逐组织 CAS 都以 T04 维护的《R3-T04/T05 同步协议》为准（建议路径 `docs/08_设计/R3-T04-T05_同步协议.md`）。本节只写 **T05 侧的执行步骤与实现义务**；条款引用暂用双向核对表编号 A-xx（§6.1），T04 v5 推送协议后替换为条款编号。

**驱动**：只有手动触发（A-04，DEC-306②）——项目页“同步数据 → 同步继任信息”勾选对象后 T04 冻结 run；项目结束 / 校准会结束不自动同步（🟡）。outbox 事件按协议（A-03）`{ runId, projectId, trigger, principalUserId, actorUserId, scopeExplicit, businessDate }` → 本模块 `consumeRun(runId)`；`POST /sync { runId }`、#17 `retry`、自动重试、恢复扫描（§4.6）都调用同一函数，函数按批次当前状态（§4.6）进入下列阶段。

**阶段 P0（准入与写前授权；与 P1 同一事务，任一步失败都不写计划）**

1. 批次头：按 `(tenant_id, source_run_id)` 取或建（`waiting`）。批次已 `completed / terminated / rejected` → 不再执行（`/sync`、#17 → 409 `RUN_NOT_RETRYABLE`，outbox 重投幂等返回）。
2. **租户互斥**（A-10；跨 run 计划串行，T04 消费租约不能替代）：本批次未持有时，`succession_sync_mutex` 行 `INSERT … ON CONFLICT DO NOTHING` 后 `FOR UPDATE`；被另一未结束批次持有 → 本批次 `waiting`（`BATCH_IN_PROGRESS`；`/sync` 409），提交后退出，不调用 `beginConsumption`；否则登记为本批次持有。
3. `loadRun`：`status = superseded` → T 类（P2）；`trigger ≠ 'sync_requested'` → N 类 `UNSUPPORTED_TRIGGER`（P3）。`business_date` = run 头冻结的 `businessDate`（非空，A-03；**不再用计划日兜底**）。
4. **执行身份**（A-10）：`beginConsumption({ leaseOwner, leaseSeconds })`：首次 → `executionNo = 1`；对方租约已过期 → 接管（`executionNo + 1`，旧 worker 此后 `assertExecutionActive` 必失败）；409 `CONSUMPTION_LEASED` → 另一 worker 正在执行本批次，本次退出、不改批次状态。批次记 `execution_no`、`lease_owner`。
5. 批次**已有计划**（`has_plan`，`executing` / `blocked` 恢复）→ 跳到阶段 E；只有**无计划**（第一次，或 planning 阶段受阻后恢复）才继续 6～10。
6. 策略：读租户开关 `succession.sync_strategy` 固化到批次（之后不变）；`overwrite_in_scope ∧ scopeExplicit = false` → N 类 `SCOPE_REQUIRED`（A-05：只看冻结的 `scopeExplicit`；显式空数组 = 空集，不扩大）。
7. **源授权**（A-18）：分页读全部提名（≤ 2000 / 页）与健康度行，每页调 `authorizeSourceRead({ page: { objectIds, nominationIds, orgIds, fieldCodes } })`（本页实际使用的内容）：`ok = false`（`PRINCIPAL_UNAVAILABLE` / `OWNER_UNAVAILABLE` / `PROJECT_INVISIBLE`）→ R 类 `blocked`（无计划：释放互斥；**不调用 `abortConsumption`**）；`runStatus = superseded` → T 类；`forbidden { objectIds, fields, sources, orgIds }` 明细记下，第 11 步对应行写 `SOURCE_REVOKED { scope, ref }`。
8. 写主体（继任侧系统主体）存在、成员有效、持 `standard_succession_runner` 身份与 Record / HealthResult 写权 → 否则 R 类 `blocked`（`PRINCIPAL_UNAVAILABLE`，`params.principal = 'write'`）。
9. **实际执行集合** = 提名目标 ∪（策略 `overwrite_in_scope` 时）范围内有生效记录但无提名的目标（`delete_only`）∪ `status ≠ not_provided` 的健康度组织（`health_write`）。
10. **原触发人目标授权**（R4-01，所有驱动路径都做）：集合 ⊆ run 头 `actorUserId` 的当前范围（Record create / update、HealthResult update，按 #107 以对象所属应用解析）→ 否则 N 类 `ACTOR_SCOPE_EXCEEDED`。`/sync` 与 #17 再加**调用人**检查：集合（重试时 = 未完成目标）⊆ 调用人当前范围，否则 403 `BATCH_SCOPE_EXCEEDS_REQUESTER`、整个事务回滚、批次保持原状态。通过后记 `actor_scope_checked_at`；计划存在后的恢复不重做第 10 步（只做调用人检查）。

**阶段 P1（计划 = 写入屏障；与 P0 同一事务）**

11. 按目标升序取 `succession_target_locks` `FOR UPDATE`（集合内全部目标；健康度目标锁组织目标行）；锁内读当前生效记录作为 `old_record_ids`；逐提名定 `plan_outcome`：`direction = target` → `skipped`（Q11）；`syncEligible = false` → `failed: SUBJECT_IN_PROCESS`（`blockReason = terminated` → `skipped`）；第 7 步 `forbidden` 涉及 → `failed: SOURCE_REVOKED { scope, ref }`；目标在 `business_date` 不存在 / 非关键 / 不在写主体范围、继任者非在职、准备度未知 / 停用 → 对应永久码；其余 `planned`。写 `succession_sync_targets` 的 `pending` 行（`append` / `overwrite` / `scope_overwrite` / `delete_only` / `health_write`）。
12. **同一目标一好一坏**（Q-SC-15 正文暂按 B；P3）：`overwrite` / `scope_overwrite` 目标只要有一条提名计划失败，整个目标 `failed: TARGET_PARTIAL_NOMINATIONS`（永久）、不结束旧记录、不新建；该目标里本来合法的提名回执 = `failed`、`errorCode = TARGET_PARTIAL_NOMINATIONS`、`errorParams = { targetKind, targetId, causeNominationIds }`、`retryable = false`，**在本计划事务内**与坏提名（自身码）一起写回执。`append` 目标不受影响：坏提名单独失败，合法提名照常进计划。
13. **目标登记**（A-20）：按协议把集合内全部目标登记为目标回执行（`rowKind` 与稳定键以协议为准，T05 建议 `target` / `${targetKind}:${targetId}`）并封存 pending 集合，完成门槛覆盖它。T05 的最低需求是无提名的 `delete_only` 目标；正文按**全部目标**登记，使每个有业务写入的执行页（包括只做删除的页）都有带本页命令身份的目标回执可作提交证明。
14. 计划阶段已终态的行（失败 / 跳过的提名、因此终态的对象、计划阶段失败的目标与健康度行）在本事务 `recordOutcome({ executionNo, pageCommandId: ${runId}:succession:${executionNo}:0 })`，本地行同时记 `execution_no / page_command_id`。
15. 零执行目标（集合为空，或全部目标计划阶段已失败）→ 本事务 `completeConsumption`（门槛：无 pending、无可重试失败）→ `completed` → 释放互斥。否则 `has_plan = true`、`executing`，提交。屏障自此对手动写入生效（§7：手动事务取目标锁后见本目标 `pending` 或 `failed ∧ retryable` → 409 `TARGET_SYNC_IN_PROGRESS`）。

**阶段 E（执行；按目标分页 ≤ 200 / 页，每页一个事务，每目标一个保存点）**

- 页命令身份按协议：`pageCommandId = ${runId}:succession:${executionNo}:${pageNo}`（`pageNo ≥ 1`）。页事务前按协议 `renewLease`。
- 页事务**第一步** `assertExecutionActive({ executionNo, leaseOwner })`（协议：对消费记录 `FOR SHARE`）：失败 → 本页不做任何业务读写；按 `ConsumptionState` 分：已被接管 → 本 worker 停止、不改批次；`superseded` → T 类（P2）；`aborted` → 停止（终止事务已清理）。本页不再取租户互斥行（它只在终结事务里释放，而终结一定改变消费记录状态，断言已覆盖；也因此页事务与计划 / 终止事务之间无锁序环，§7）。
- `authorizeSourceRead({ page: 本页使用的对象 / 提名 / 组织 / 字段 })`：`ok = false` → 本页回滚，另起事务置 R 类 `blocked`（计划、屏障、互斥保留，不调用 `abortConsumption`）；`forbidden` 明细 → 涉及行 `SOURCE_REVOKED { scope: object | field | source | org, ref }`（永久）。写主体复核失败 → 同上 R 类 `blocked`（`PRINCIPAL_UNAVAILABLE`）。
- 取本页目标：`pending ∪ (failed ∧ retryable)`，按 `(target_kind, target_id)` 升序。只跳过真正不能再执行的目标：`done`、`failed ∧ ¬retryable`、`aborted`。
- 每目标（保存点内）：继任者员工行 `FOR SHARE`（升序）→ 目标锁行 → 记录行；**锁内重验**：继任者在 `business_date` 与今天都在职（`SUCCESSOR_NOT_ACTIVE`）、目标在 `business_date` 有效且关键（`TARGET_NOT_FOUND` / `TARGET_NOT_KEY_POSITION`）、准备度启用（`READINESS_DISABLED`）、目标在写主体当前范围（`TARGET_OUT_OF_SCOPE`）、计划行仍是 `pending / failed ∧ retryable`；`old = old_record_ids ∩ 当前仍生效`；`append`：同继任者已有生效记录 → `exists`（准备度暂按保留，🟡 Q03），否则新建；`overwrite` / `scope_overwrite`：结束 `old` 中不属于本目标成功继任者的记录（`sync_overwrite` / `sync_scope_overwrite`），再新建 / `updated`；`delete_only`：结束 `old`；`health_write`：按 §4.4 写结果。成功 → 目标 `done`。
- **执行阶段目标失败的回执映射**（P3）：保存点回滚该目标全部写入，然后在**同一页事务**写回执——
  - 目标级原因（`TARGET_NOT_FOUND` / `TARGET_NOT_KEY_POSITION` / `TARGET_OUT_OF_SCOPE`）：目标 `failed`（永久）；该目标全部 `planned` 提名 = 同码、`retryable = false`。
  - 提名级原因（`SUCCESSOR_NOT_ACTIVE` / `READINESS_DISABLED`）：`append` 目标只让该提名失败、其余提名照常（按提名分保存点）；`overwrite` / `scope_overwrite` 目标整体失败：坏提名 = 自身码，其余 = `TARGET_PARTIAL_NOMINATIONS { causeNominationIds }`，均 `retryable = false`，目标 `failed`（永久，旧记录不结束）。
  - 基础设施错误：目标 `failed ∧ retryable`（`INFRA_ERROR`）；该目标全部 `planned` 提名 = `failed ∧ retryable`、同码。
- 页末（同一页事务）：本地目标 / 提名行记 `execution_no`、`page_command_id`；`recordOutcome({ executionNo, pageCommandId, items })` 写本页目标回执、相关提名行、终态已定的对象聚合行、健康度行；提交。
- **unknown**（A-15）：只有“`getOutcomes({ pageCommandId: 本页命令 })` 返回本页行”且“本地 `succession_sync_targets.page_command_id = 本页命令`”才算本页已提交；旧执行留下的终态（含 `failed ∧ retryable`）**不作数**。未提交 → 本执行仍活跃时用同一 `pageCommandId` 重做本页；已被接管 → 由新执行以新页命令重做。
- **一轮结束**：仍有 `pending` 或 `failed ∧ retryable` 的目标 / 行 → 批次 R 类 `blocked`（`block_reason` = 首个可重试码）：**不调用 `completeConsumption`、不释放互斥、屏障保留**，登记自动重试（§4.6）；没有 → `completeConsumption`（协议门槛，否则 409 `PENDING_ROWS_REMAIN` / `RETRYABLE_ROWS_REMAIN` 视为实现错误）→ `completed`（`result = succeeded | partial`）→ 释放互斥 → 登记 `sync_done` 通知（触发人）→ 对涉及组织登记 `org_health` 计算（`review_sync`，§4.6 键）。

**P2 终止 / 取代（T 类，不可恢复）**：一个事务内 `succession_sync_mutex` `FOR UPDATE` → SA `abort` 时调 `abortConsumption`（协议：消费记录 `FOR UPDATE`；run 被取代时 T04 已置 `superseded`，不再调用）→ 未终态目标与提名标 `aborted`、屏障释放、释放互斥，批次 `terminated`（`end_reason = superseded | aborted`）。已提交的页不回滚；剩余 pending 行由盘点侧按协议批量写 `superseded` 回执。终止后不可在本 run 上恢复。

**P3 拒绝（N 类，必须新建 run）**：在 P0 同一事务内对本 run 全部提名、对象、健康度行写 `failed` 回执（码 = `SCOPE_REQUIRED` / `UNSUPPORTED_TRIGGER` / `ACTOR_SCOPE_EXCEEDED`，`retryable = false`，`pageCommandId = …:0`）→ `abortConsumption(reason)` → 批次 `rejected`、不建计划、释放互斥、通知触发人。旧 run 不能改了再试：修正开关 / 范围 / 触发人范围后在盘点侧重新发起同步（新 run）。

**跨 run 串行**（A-10）：同一租户同时只有一个持互斥的批次（`planning` / `executing` / 有计划的 `blocked`）。两个 run 都对同一目标做覆盖同步时，后一个在第 2 步进入 `waiting`；前一个 `completed` / `terminated` 后，后一个才在目标锁内读到**前一个已写好的**生效集合作为 `old_record_ids`，最终只剩后一个 run 的继任者，不会留下两批的并集。代价：有计划的 `blocked` 批次会挡住本租户其他同步，SA 可经 #17 `abort` 解除（§4.6）。

**回执映射与聚合**（`OutcomeItem` 字段以协议为准）：

| 行 | 状态映射 |
|---|---|
| 提名（`nomination`，rowId = nominationId） | `planned → created / updated / exists` ⇒ `synced`；计划或执行失败 ⇒ `failed`（带码、`retryable`）；`skipped` ⇒ `skipped`；终止 ⇒ 由盘点侧写 `superseded` |
| 对象（`object`，rowId = objectId） | 该对象全部提名终态后写：全部 `synced / skipped` ⇒ `synced`；任一 `failed` ⇒ `failed`（码集合，`retryable` = 任一可重试）；全部 `skipped` ⇒ `skipped`；对象有可重试失败时随重试更新 |
| 健康度（`org_health`，rowId = orgId） | `health_write` 目标成功 ⇒ `synced`（含 `manual_kept`，带 `params.manualKept = true`）；失败 ⇒ `failed`（码） |
| 目标（A-20，键以协议为准） | 目标 `done` ⇒ `synced`；`failed` ⇒ `failed`（码、`retryable`）；终止 ⇒ `superseded` |

## 7. 锁序与事务

全局锁序（`org/locks.ts`）：员工闭包 → 业务 → 组织 → 编制 → 审批实例；本模块的锁排在其后：**目标锁行 → 继任记录行**。

| 入口 | 锁序 | 锁内重验 |
|---|---|---|
| 新增 / 编辑恢复生效 | 继任者员工行 `FOR SHARE`（与 employment 的 `FOR NO KEY UPDATE` 互斥）→ `succession_target_locks(目标)` `FOR UPDATE` → 记录行 | 在职；目标有效 / 关键 / 范围；**无计划屏障**（批次处于 `planning / executing / blocked` 且该目标 `pending / failed ∧ retryable` → 409 `TARGET_SYNC_IN_PROGRESS`）；区间不重叠（DEC-305②）；revision |
| 批量结束 / 删除（R4-02） | 无锁读出记录的目标 ID（目标列 `FIELD_IMMUTABLE`，集合稳定）→ `succession_target_locks` 升序 `FOR UPDATE` → 记录行升序 `FOR UPDATE` **重读** | 重读后的存在性（取锁前被删 → 404）、未结束（`ALREADY_ENDED`）、逐对象 revision（`REVISION_MISMATCH`）、无计划屏障（409 `TARGET_SYNC_IN_PROGRESS`） |
| 同步计划（P0 / P1） | 租户互斥行 `FOR UPDATE` → T04 消费记录（`beginConsumption`，协议内 `FOR UPDATE`）→ 目标锁行（升序，实际执行集合全部）→ 锁内读旧集合、写计划行 | 源授权、写主体、所属人；原触发人与调用人目标授权 |
| 同步执行（每页） | T04 消费记录 `FOR SHARE`（`assertExecutionActive`，页事务第一步）→ 每目标：继任者员工行 `FOR SHARE`（升序）→ 目标锁行 → 记录行 | §5.7 E 的锁内重验（在职、有效、关键、准备度、范围、计划行状态） |
| 同步终止（SA abort / 取代清理 / N 类拒绝） | 租户互斥行 `FOR UPDATE` → T04 消费记录（`abortConsumption`，协议内 `FOR UPDATE`；取代时 T04 已置，不再取）→ 计划目标行 | 批次未终结 |
| 离职钩子 / sweep | employment 已持员工行（`FOR NO KEY UPDATE`）→ 目标锁行 → 记录行 | 记录仍生效 |
| 规则集合 | `succession_rule_settings(kind)` 行 → 等级行 | 集合 revision |
| 计算 worker | run 行 `FOR UPDATE SKIP LOCKED` → 结果行升序 | 对象仍在主体范围；重置逐对象 revision |

- 互斥：**所有入口首次取锁都是目标锁 → 记录行**（结束 / 删除按 R4-02 改为先目标锁），与同步执行、离职钩子 / sweep 之间不存在反向等待环；新增与离职都先持继任者员工行（`FOR SHARE` 与 `FOR NO KEY UPDATE` 互斥）；同一目标上的新增 / 同步由目标锁行串行，锁内重查后由排他约束兜底；**计划与手动写入不交错**：计划行在目标锁内写入并与读旧集合同事务提交，手动事务取同一目标锁后一定看到已提交的屏障。
- 跨 run 串行靠租户互斥（批次持有，只在终结时释放）+ 计划屏障；旧 worker 失效靠 T04 消费租约：被接管后它的 `assertExecutionActive` 必失败，页事务不写任何业务数据。页事务不取租户互斥行（互斥只在终结事务释放，而终结必改消费记录状态，断言已覆盖），所以计划 / 终止事务（互斥 → 消费记录）与页事务（只取消费记录）之间没有锁序环；T04 项目重启只取消费记录 `FOR UPDATE`，与页事务按提交顺序串行（协议）。

### 8.4 SELF 谓词与全部出口的投影

- **SELF 谓词**：查看人用户 ↔ 人员绑定得到员工 `E`；记录“是本人的”⇔ 目标组织在请求当日的负责人 = `E`，或目标职位在请求当日的现任含 `E`。`self_successors_visible = false` 时，“是本人的”记录在**所有出口**不返回、不计数；SELF 记录的写入按保守口径**不可写**（命令前 404，Q-SC-17 🟡）。谓词在 SQL 里实现（`succession_self_target_sql(viewer)`），列表 / 地图 / 审计 / 回执共用。
- **整体可见门槛**：run / 批次先判整体可见（§8.2），不可见不返回 ID / 状态 / 申请人 / 时间。
- **投影函数** `projectSuccession(viewer, kind, payload)`：先按对象查看字段裁剪（`getModuleViewableFields`，键缺席），再逐层处理：

## 10. 偏离规格 / 已知差异
