## 2. 接口与命令执行协议

### 2.1 命令执行协议（所有写入口，含幂等重放）

1. **命令前**（路由层）：`uuidParam` / 请求体 UUID 小写化（DEC-194）→ `objectContext(对象, 操作)` → `button(对象, 按钮)` → 资源校验（目标在当前范围内、继任者按 Q02 口径）→ 结构校验 → `writeFields(对象, 操作, 写字段)`（含显式置空的键）→ `requestScope(对象)`。

4. **失败**：业务失败 / 存储不可写 / 结果未知三类按 `audit/failures.ts` 记录；结果未知返回 503 `RESULT_UNKNOWN`，客户端按原命令 ID 回查。

## 3. 条件行编译器（公共模块 `packages/domain/src/expression/rules/`）

R3-T06 入池规则（Q-M0-114 `PoolRule`：`Fields` + `Expression`）与本任务的风险 / 健康度 / 人群共用；规则组、字段值优先级、重复人员处理留在 T06 宿主。

### 3.1 对象与字段引用契约

```ts
type FieldKind = 'text' | 'number' | 'option' | 'multi_option' | 'date' | 'boolean';
interface FieldRef {
  object: 'employee' | 'employment' | 'successor' | 'review_object' | 'org';   // 宿主对象目录
  code: string;                       // 对象内字段编码（T04 盘点字段 code / 人员字段编码）
  path: string;                       // 发码用的引擎字段路径，如 盘点对象.绩效_潜力九宫格位置_after
  kind: FieldKind;
  optionDomain?: readonly { value: number | string; label: string }[];   // option / multi_option 的选项域
}
type Operator = 'is_empty' | 'not_empty' | 'eq' | 'ne' | 'gt' | 'lt' | 'ge' | 'le' | 'between';
interface ConditionRow {
  rowNo: number;                      // 1 起、连续
  kind: 'aggregate' | 'field';
  field?: FieldRef;                   // field 行必填；aggregate 行的过滤字段另在宿主
  operator: Operator;
  values?: readonly (number | string | boolean)[];   // eq / ne 允许多值（T06 `Values`）；between 恰两值
}
interface RuleSet { rows: readonly ConditionRow[]; expression: string }   // expression 只含 and / or / 括号 / 行号
interface CompiledRule {
  formula: string;
  rowSpans: readonly { rowNo: number; start: number; end: number }[];   // [start, end) 字符区间；同一行多处引用 → 多个区间
  referencedRows: readonly number[];
  unreferencedRows: readonly number[];
  compilerVersion: string;            // 'rules/1' + DEFAULT_SEMANTICS 标识
}
```

- **`aggregate` 行**（风险 / 健康度）：宿主先按行定义算出度量值（§4.1），以字段 `行n.值`（number）注入 `SubjectReader`；编译产物只做“度量值 比较符 阈值”。
- **`field` 行**（人群、T06 入池）：直接对对象字段比较；宿主只注入对象字段（`SubjectReader.resolveField(path)`），无权字段返回 `forbidden`（不是 EMPTY，§4.1）。
- T06 映射：`ItemMetaObjectName = CalibrationObjective` → `object = 'review_object'`；`FieldName` → T04 字段目录 `code`（A-07 给 `kind` / `optionDomain`）；`Values` → `values`；`Expression` → `expression`。

### 3.2 发码表（引擎实际语法）

引擎支持中缀 `and / or / not`（`lexer.ts` 关键字 `且 / 或 / 非`）与函数 `IN(值, 候选1, 候选2, …)`（`logic.ts`，参数形式 TODO 需取证 #105 暂定）、`IsEmpty(x)`；比较符 `= != < > <= >=`。

| 行定义 | 发码 | 说明 |
|---|---|---|
| `is_empty` | `IsEmpty(F)` | — |
| `not_empty` | `not IsEmpty(F)` | — |
| `eq` 单值 | `F = L` | — |
| `eq` 多值 | `IN(F, L1, L2, …)` | T06 九宫格格子集合 |
| `ne` 单值 / 多值 | `F != L` / `NOTIN(F, L1, …)` | — |
| `gt / lt / ge / le` | `F > L` 等 | number / date |
| `between` | `(F >= L1 and F <= L2)` | 含边界（原站“范围”） |
| 字面量 `L` | number → 十进制字面量；text → 英文双引号字符串（内部引号转义；含中文引号拒绝 `RULE_LITERAL_INVALID`）；option → 选项 `value` 字面量（按引擎 `=` 对选项值的口径比较）；date → `"YYYY-MM-DD"`（引擎日期字面量口径）；boolean → `true` / `false` | 类型与字段 `kind` 不符 → `RULE_ROW_TYPE n` |
| `multi_option` 字段 | 首版只允许 `is_empty / not_empty`，其余 → `RULE_ROW_TYPE n` | 引擎无多值包含函数 |
| 组合 | 行引用 `n` → `(<行 n 子式>)`；`and / or` → 中缀 `and / or`；括号原样 | 组合形状与原站表达式一一对应 |
| 整体 | `IF(<组合>, 1, 0)` | 结果 `1` 即匹配 |

T06 样例（AC-TP-01，`26` TR-R31 预置“绩效-潜力”九宫格位置 after 字段）：行 1 = `{ field: 盘点对象.绩效_潜力九宫格位置_after (number), eq, [7, 8, 9] }`，表达式 `1` → `IF((IN(盘点对象.绩效_潜力九宫格位置_after, 7, 8, 9)), 1, 0)`。
本租户风险样例（Q-M0-82 中风险 `1 and 2`）：`IF((not IsEmpty(行1.值)) and (not IsEmpty(行2.值)), 1, 0)`。

### 3.3 编译、规模与保存

1. `parseRowExpression`：词法只认 `and / or / ( ) / 正整数`（大小写不敏感；容忍无空格）；文法 `expr := term (or term)* ; term := factor (and factor)* ; factor := int | '(' expr ')'`；错误 `RULE_EXPRESSION_SYNTAX`（位置）、`RULE_ROW_UNKNOWN n`；未引用的行记入 `unreferencedRows`（拦截还是警告待定，Q-M0-124 Q09）。
2. `compileRuleSet(rules, catalog)`：逐行类型校验（字段存在、运算符与类型合法、值个数）→ 发码 → 组合；记录 `rowSpans`。
3. **规模上限**（引擎 `parser.ts`：4000 字符 / 800 词 / 100 层）：编译器限制 行数 ≤ 50、每行候选值 ≤ 20、括号嵌套 ≤ 20；发码后再以 `validateFormula` 校验，超限统一 400 `RULE_TOO_LARGE`（给出字符 / 词数）。按发码表估算，50 行 × 20 值的极端规则约 1100 词，所以超限由校验拦截而不是默认放行。
4. `validateFormula(formula, { registry, isKnownField, fieldKind })`：`isKnownField` / `fieldKind` 来自行字段目录（`行n.值` 为 number；field 行按 `FieldRef.kind`），类型推导不确定 → 保存报错（DEC-287 补充）。
5. 保存流程：条件行 + 表达式 + 编译缓存同事务写入；任一步失败 400，错误定位到行号（`RULE_ROW_INVALID n`）；`compiler_version` 随缓存写入；引擎语义变化后用平台命令重新编译（§2.2 #23），**不得用表达式反写条件行**（DEC-261）。

### 3.4 求值与错误映射

- `evaluateFormula(program, context)`；失败 `ComputationFailure` 带顶层 `offset / line / column`（`failures.ts` `SourcePosition`，可缺省）。映射：`offset` 落在某个 `rowSpans` 区间 → “第 n 行条件出错：<引擎分类文案>”；同一行多处引用时各区间都映射到同一行号；`offset` 缺省或不在任何区间（如 `CONTEXT_INVALID`、`INTERNAL_ERROR`、组合层）→ “条件表达式出错：<分类文案>”。文案只取引擎 `message` 中 `计算失败：` 之后的分类部分，**不带公式文本**。
- 求值前先按 §4.1 的来源状态决定能否求值：任一引用行的度量 / 字段是 `forbidden` 或 `unavailable` → 不调用引擎，直接记该等级失败（`FIELD_FORBIDDEN` / `DATA_UNAVAILABLE`，带行号）。

## 4. 计算语义

### 4.1 共同口径（P2-03）

- 时间：业务日期按租户时区（`tenantLocalDate`，DEC-056）；事件时间 UTC。
- 在职员工 = `asOf` 当日时间轴（`employment_timeline.valid_during @> asOf`）上的主职版本人员状态 ∉ {离职 8、调出 4、退休 6}（待入职 1 不算现任）；已删除（墓碑）/ 撤销的任职不参与。
- 现任人员（职位）= 该日主职 `position_id = 职位` 的员工；开关 `part_time_in_risk_calc` 开时并入兼职任职（端口，R2-T05 前为空集）；负责人（组织）= 该日生效组织版本 `person_in_charge_id`。
- 继任者 = `succession_records` 中目标匹配、在 `asOf` 生效（§5.1 区间）、未删除；同一人对同一目标只计一次。
- **度量 / 字段来源状态**（五种，不得混用）：

| 状态 | 含义 | 对等级判定的影响 |
|---|---|---|
| `value` | 取到值 | 正常求值 |
| `empty` | 真实空值（字段为空；分母为 0 → 待定 Q-M0-124“null 按 0 还是空”） | 注入 `EMPTY`，比较语义照 DEC-257（空值比较为假、`IsEmpty` 为真） |
| `forbidden` | 执行主体无该字段读权（引擎 `FieldLookup.status = 'forbidden'` → `FIELD_FORBIDDEN`，`evaluator.ts:176`） | **该等级失败 → 对象计算失败**，不注入 EMPTY，不向下匹配 |
| `unavailable` | 数据源不可用 / 端口 `unavailable` / 读取异常 | 同上，`DATA_UNAVAILABLE` |
| `unmapped` | 规格允许的“映射取不到”：健康度 `succession` 字段在盘点来源里没有继任信息（SC-R16） | **跳过该等级**，记 `skipped`，继续下一等级 |

- **等级判定**：按 `display_order` 顺序求值；第一个得 `1` 的等级即结果；某等级**失败**（求值失败、无权、不可用、编译缓存失效）→ 对象记“计算失败”（DEC-257），**该对象结果不改写**（保留上次值），失败明细带等级与行号，不再向低优先级匹配；只有 `unmapped` 跳过；全部等级不匹配或全部跳过 → `level_id = null`（默认颜色）。
- **执行主体（D-04，DEC-301③ 保守方案，待定 Q-M0-125）**：定时 / 手动 / 同步触发的计算都以**显式授权的系统主体**执行——平台开通时为租户创建服务账号 `succession_runner`（不可登录）并授予标准身份 `standard_succession_runner`（§8.1）；其数据范围**不预置**（硬规则：默认空），由租户管理员显式授予；主体缺失、身份被撤销或范围为空时 run 失败 `PRINCIPAL_UNAUTHORIZED` / `PRINCIPAL_SCOPE_EMPTY`，不降级为触发人权限。手动触发时触发人只决定**对象集合**（其范围 ∩ 地图显示），字段读取仍以主体身份进行；对象不在主体范围内 → 该对象 `skipped_out_of_scope`。选项 B（触发人身份取数）见 §9。
- 比例度量：分子 / 分母 × 100，**不预先舍入**（舍入口径待定 Q-M0-124）；展示保留两位。

### 4.2 职位风险等级（SC-R9）

- 触发：① 每天租户本地 0 点平台调度（§4.6 键 `position_risk:schedule:<租户>:<本地日期>`）；② 地图按钮 `computeRisk`：登记 run（`manual`）立即 202，worker 异步执行，完成后给触发人登记 `calc_done`。
- 对象：定时 = 租户内全部关键职位（`asOf = 今天`）；手动 = 触发人范围 ∩ 当前地图显示 的关键职位。
- 每职位 × 每启用等级：逐行度量：`subject` 人口（现任 / 继任者）→ 行过滤（`field_code op values`）→ `count` / `count ÷ 现任人数 × 100` / `count ÷ 继任者人数 × 100` → 注入 `行n.值` → 求编译公式；先匹配先得。
- 写结果：`computed` 行覆盖；`manual` 行保留不覆盖（Q04，总编排已定）；对象级结果：`written` / `unchanged` / `manual_kept` / `failed`。
- 职位停用或取消关键标记：结果行保留（取消关键后保留手工值、恢复关键再生效 → 待定 Q-M0-124）；地图不展示非关键 / 停用职位。

### 4.4 组织健康度（SC-R10、SC-R16；P2-09）

- 触发：① 地图 `computeHealth`（手动）；② 同步批次结束后对涉及组织自动计算（`trigger = review_sync`）；③ 每日定时待定（Q-M0-124 Q05）。
- 计算范围：手动 = 触发人范围 ∩ 地图显示；同步触发 = 快照 `ownerOrgId` 及行政下级 ∩ 执行主体范围 ∩ 地图显示（SC-R16）。
- 人口：`all` = 该组织（含不含下级待定，Q06）在 `asOf` 的在职员工；`successors` / `incumbents` / `custom`（`all` 中满足人群规则者，逐人 `field` 型求值）。
- **取数上下文**（三档，定义以 T04 为准，A-08）：触发计算的项目 / 校准会 > 当前项目 > 最近一次盘点；`asOf` = 快照 `businessDate`（同步触发）或今天（手动）；并列选择规则由 T04 端口给出，T05 不自定。
- **`review` 字段**：`readReviewFields(employeeIds, context)`（A-08）→ `value / empty / forbidden / unavailable`。
- **`succession` 字段（S:126，E:88 / E:99）**：不读本地地图。来源对象 = 盘点继任信息（T04 `talent_review_succession_entries`，经端口 `TalentReviewObjectResult.succession[]` 输出，字段 `kind / direction / orgId / positionId / successorEmployeeId / readinessCode / sortNo`）；映射（本模块预置常量，无 UI）：`successor_count` = 该组织在上下文结果中 `kind = org, direction = nominate` 的提名行数（去重继任者）；`readiness_code` = 这些提名行的准备度集合（行过滤 / 比较按集合是否包含）。上下文里该组织**没有任何继任信息模块数据**（结果集里无 `succession` 字段或端口返回 `unmapped`）→ `unmapped` → 跳过该等级；有模块但无提名 → `successor_count = 0`（`value`）；无权 → `forbidden`；端口不可用 → `unavailable`。
- `org` 字段：`green_rate` 经 T04 `greenRate`（项目选择与零分母口径 A-09）；`on_duty_count` 取 `succession_org_stats`；`establishment_count` 经编制模块（口径待定，§9）。
- 已手动赋值（`manual`）的组织：不求值、不覆盖、记 `manual_kept`；清除手动值后下次重算恢复。
- 盘点侧健康度（SC-R16，A-06）：同步批次把端口给出的 `orgHealth` 写 `succession_health_results`：`provided = false` → 不动；`forbidden` → 批次该项失败；`levelCode = null` 且 `provided = true` → 写空（`synced`）；`manual = true` → 写成 `manual`。

### 4.5 组织关联信息（SC-R6）

- `on_duty_count` = 该组织在职员工数（含不含下级与健康度同题，Q06）；`green_rate` 经 A-09 取（来源项目记 `green_source_project_id`）；编制数读取时实时取，不存。
- 触发：平台调度按槽（§4.6）；`PUT /maps/org/preferences` 改卡片显示设置时对本人地图可见组织登记一次（`preferences_change`）。

### 4.6 调度与幂等键（P2-11）

| trigger | 键格式 | 说明 |
|---|---|---|
| 定时 `position_risk` / `exit_sweep` | `<kind>:schedule:<tenant>:<本地日期>` | 跨租户本地午夜后的第一次运行执行（与 `activation-scheduler` 同一跨日判定） |
| 定时 `org_stats` | `org_stats:schedule:<tenant>:<interval_h>h:<slot_index>` | `slot_index = floor(本地时间分钟数 / (interval_h × 60))`，键里带当时生效的间隔小时数：改间隔后旧槽自然失效、新槽从下一次调度起算，不合并当天后续槽 |

## 5. 业务规则落地

### 5.1 时间轴（SC-R1、SC-R2，AC-SC-01）

- 区间定义：记录在日期 `d` 生效 ⇔ `start_date ≤ d < end_date`（半开区间；`end_date = 9999-12-31` 为当前生效）。“有结束时间 → 已结束”（SC-R2）与此一致：`end_date ≤ 今天` 的记录在今天已不生效。
- 新增 / 编辑：`startDate ≤ 今天`（400 `START_DATE_IN_FUTURE`）、`endDate`（给了时）`≤ 今天`（400 `END_DATE_IN_FUTURE`）且 `≥ startDate`（400 `END_BEFORE_START`）；空 `endDate` 存 `9999-12-31`；编辑把 `endDate` 显式置空 = 恢复生效（走同一唯一性边界 §7）。
- 目标校验：组织继任的目标组织在执行人范围内且 `asOf = 今天` 有效（否则 404 `NOT_FOUND`）；职位继任的目标职位在范围内、启用、`is_key`（否则 400 `TARGET_NOT_KEY_POSITION`）；继任者在职（400 `SUCCESSOR_NOT_ACTIVE`）且按 Q02 口径（§9）校验员工范围；准备度启用（400 `READINESS_DISABLED`）。
- 同一（目标, 继任者）已有生效记录：Q03 定唯一 → 409 `SUCCESSION_EXISTS`。

### 5.2 结束（SC-R3）

- `POST /records/end`：整批原子；逐条校验 `endDate ≤ 今天`、`≥ 该条 startDate`（400 `END_BEFORE_START` 列出 ID）、可见（任一不可见整批 404 `NOT_FOUND`）、未结束（409 `ALREADY_ENDED` 列出 ID）、`expectedRevision` 一致（409 `REVISION_MISMATCH` 列出 ID）；写字段级审计（`end_date`、`end_reason`、`end_source = manual`）。

### 5.3 删除

- 软删除 + 审计整条快照；删除后不参与任何统计 / 规则 / 同步比对；同键重放返回原回执（返回前仍复核当前范围）；新命令对已删记录 404。

### 5.4 离职自动结束（SC-R4，AC-SC-02；P2-07）

挂接端口：employment 模块新增 `registerEmployeeStatusHooks({ onRecordMaterialized, onRecordDeleted, onRecordRescheduled })`（与 `personnel-hooks.ts` 同一注册方式，employment 不 import 本模块）。本模块实现 `applyExit(tx, ctx, employee, record)`：持员工行锁（employment 已取）→ 目标锁行（该员工为继任者的生效记录的目标，UUID 升序）→ 记录行；把 `end_date` 设为**离职日**（Q01）、`end_source = exit`、`end_reason = '离职'`、`exit_record_id = 记录 ID`；写审计（执行人 = 触发命令的执行人或系统）；写 `succession_exit_applications`。

| 路径 | 真实触发点（代码） | 挂接 | 幂等判据 |
|---|---|---|---|
| 当前 / 历史 direct 离职（`start_date ≤ 今天`） | `write-service.ts:159` → `materializeEmploymentRecord` 写 `employment_records`（同事务） | `onRecordMaterialized`：新记录 `employee_status = 8` 且 `start_date ≤ 今天` → 立即 `applyExit` | `succession_exit_applications (tenant, employment_record_id)` 唯一 |

- 兼职任职的离职不触发（只有主职状态变化）。

### 5.5 组织继任地图（SC-R5～R7）

- 根：请求 `root` 须在范围内（否则 404）；缺省取查看人范围内行政维度最顶层组织，多个同级取顺序号最小者；层数 2～4（默认开关值）。

- 卡片内容与逐层投影见 §8.4。

### 5.6 职位继任地图（SC-R8，AC-SC-06；P2-10）

两步：
1. **结构父节点**（与查看人无关）：节点 = `asOf` 当日启用且 `is_key` 的职位（节点范围“关键职位 vs 全部职位”待定，§9 Q-SC-13）；沿 `direct_parent_id` 向上，**跳过停用或非关键**的职位，第一个启用且关键的祖先 = 结构父节点；没有 → 结构根。于是中间职位停用 → 其下级挂到停用职位的上级（AC-SC-06）。
2. **可见性断层**：结构父节点不在查看人范围内 → 该节点成为**新根**，**不再向上寻找**；结构父节点可见 → 连边。例：可见 A → 不可见 B → 可见 C：C 的结构父节点是 B（启用、关键），B 不可见 → C 为新根，不挂到 A。
- `show_positions_without_successor = false` 时去掉“自身无继任者且子树内都无继任者”的子树。

### 5.7 盘点 → 继任同步（SC-R13～R16，AC-SC-03～05；P2-05、T04 对齐）

- **驱动**：T04 在项目结束 / 校准会结束 / 手动同步时写 `talent_review_outbox`（`project_ended` / `meeting_ended` / `sync_requested`，payload `{ runId, snapshotId, projectId, meetingId, trigger, actorUserId, scopeOrgIds, manualOverride }`，A-03 / A-05）；本模块消费者按游标拉取，调用 `loadSnapshot` 取**冻结快照**（`snapshotId / version`），按开关策略写继任，最后 `recordOutcome(runId, consumer = 'succession', items)`。`POST /sync { runId }` 是同一服务的手动再驱动入口（不另建快照）。
- **来源与触发分开**：`source_kind = project | meeting` 由快照决定；`trigger` 另存；`manual_override` 只在 `trigger = manual` 时允许为真（否则批次 `failed_permanent`，`INVALID_OVERRIDE`）。
- **执行主体**：读源（`loadSnapshot` 的 `viewer`）与写目标都用 §4.1 的系统主体（DEC-301③ 保守方案）；`actorUserId` 只用于审计与消息。目标写入逐项按主体当前范围复核：提名目标不在主体范围 → 该行 `failed: TARGET_OUT_OF_SCOPE`；**被结束集合**（覆盖 / 范围内覆盖要结束的旧记录）逐项校验目标在主体当前范围内，不在 → 该目标整组失败 `OLD_RECORD_OUT_OF_SCOPE`、不结束、不新建。端口“范围外不返回”只对 `viewer.kind = user` 成立；本模块以主体身份读取，故回执里的 `TARGET_OUT_OF_SCOPE` 来自写入侧复核，两处不再矛盾。
- **逐提名处理**（A-02）：快照中每个对象的全部 `succession[]` 行逐行处理，不取“最早一条”（那只用于入池映射，`26` TR-R42）。`direction = target`（为盘点对象指定意向继任）是否写继任记录待定（Q-M0-124 Q11 / Q-M0-125）；写代码前按取证结论实现，设计里两种都留。
- **资格**：按 T04 `syncEligible / blockReason`（A-04）：`in_flow` → 该对象全部提名 `failed: SUBJECT_IN_PROCESS`（SC-R15）；`manual_override = true` 且 `trigger = manual` 时 T04 快照已只带已填的继任者与准备度，照常处理；`terminated` → `skipped`。
- **逐行校验**：目标存在且在 `business_date` 有效（`TARGET_NOT_FOUND`）、职位须关键（`TARGET_NOT_KEY_POSITION`）、继任者在职（`SUCCESSOR_NOT_ACTIVE`）、准备度 code 可解析且启用（`READINESS_UNKNOWN`）、主体范围（`TARGET_OUT_OF_SCOPE`）。
- **策略**（开关在批次开始时读取一次并存 `strategy`）：
  - `append`：目标已有同一继任者生效记录 → `exists`（准备度是否更新待定 Q03）；否则新建（`source_kind = review_sync`，`start_date` 取值待定：同步日 vs `business_date`，§9 Q-SC-14）。
  - `overwrite`：对本批**成功校验**的每个目标：先结束该目标不在本批成功行里的生效记录（`end_date = 今天`，`end_source = sync_overwrite`）→ 本批已存在的保留并更新准备度（`updated`）→ 其余新建；**同一目标有部分提名行失败**：成功行照常写入、失败行不写，旧继任者是“仍按本批成功行结束”（选项 A）还是“保留并把该目标整组标失败”（选项 B）→ **待定 Q-SC-15**（§9），写代码前定，两种各有测试；未涉及的目标不动（AC-SC-03 组织 B）。
  - `overwrite_in_scope`：先取租户级 `succession_sync_locks`，范围 = `scope_org_ids` 及行政下级（`asOf = business_date`）内的组织与职位目标；逐目标复核主体范围后结束其生效记录（`sync_scope_overwrite`），再按本批新建；范围内有目标不在主体范围 → 该目标失败、其余照常。
- **结果分类**（四种分开）：快照对象为空且端口 `ok` → `succeeded`（`EMPTY_SNAPSHOT`，计数 0）；快照非空但主体范围裁剪后无可写目标 → `partial`（全部行 `TARGET_OUT_OF_SCOPE`）；全部提名行失败 → `partial`（逐行错误码）；端口 `unavailable` / `forbidden` → `failed_retryable`（主体无权读源 → `failed_permanent: SOURCE_FORBIDDEN`）。
- **健康度**（SC-R16）：按 §4.4 末段写 `synced / manual`；批次完成后登记 `org_health` 计算（`review_sync`）。
- **事务边界与重试**：一个批次 = 一个 run 的全部提名；读取按 T04 逻辑批次分页（对象 ≤ 500 / 页，提名数单独计数，A-10）；写入每页一个事务（页内每个目标一个保存点），`succession_sync_items` 先于继任写入在同一事务落行，页提交后不回退；中途异常 → `failed_retryable`，重试跳过已有 `items` 的提名行（按 `nomination_id` 幂等）；`recordOutcome` 失败 → 批次 `partial`，重试只重发回执（继任不重写）；旧版本事件（同一 `runId` 但 `snapshotId` 不同）→ `failed_permanent: SNAPSHOT_MISMATCH`。同一 `runId` 重复投递命中 `unique(source_run_id)` → 返回原批次。
- **回执**：逐提名 `items` → 聚合到对象（对象全部行 `created / updated / exists / skipped` → `synced`；任一行 `failed` → `failed`，reason 列出提名行 ID 与错误码）→ `recordOutcome`。错误报告 = `outcome = failed` 的行。

### 5.8 盘点业务日期与 `asOf`（SC-R17；P2-08）

- 列表、地图接受 `asOf`（租户时区业务日期，缺省今天；`> 今天` → 400 `AS_OF_IN_FUTURE`）。语义：组织树与组织属性取 `org_versions` 中 `start_date ≤ asOf ≤ stop_date` 的版本（与 `listOrgDescendantsInTransaction` 的 `asOf` 一致）；职位取 `asOf` 当日版本（`jobScopeReader.load(…, asOf)`）；现任 / 负责人取该日时间轴与组织版本；继任记录取 §5.1 区间在 `asOf` 生效者（已结束的历史记录因此在历史日期上可见）；风险 / 健康度结果只有当前值，历史 `asOf` 下仍显示当前结果并标 `resultAsOf = computed_at`。
- 同步与同步触发的健康度计算用快照 `businessDate`（为空则今天）作 `asOf`：目标有效性、关键职位、现任 / 负责人、人口都按该日取。
- **历史数据仍按当前权限裁剪**：范围、字段、SELF 谓词一律用请求当日解析，不按 `asOf` 回溯权限。

## 7. 锁序与事务（P2-06）

全局锁序（`org/locks.ts`）：员工闭包 → 业务 → 组织 → 编制 → 审批实例；本模块的锁排在其后：**目标锁行 → 继任记录行**。

| 入口 | 锁序 | 锁内重验 |
|---|---|---|
| 新增记录 / 编辑恢复生效 | 继任者 `employment_employees` 行 `FOR SHARE` → `succession_target_locks(目标)` `FOR UPDATE` → 记录行 | 继任者仍在职（时间轴今天）；目标仍有效 / 关键 / 在范围内；同目标同继任者无生效记录（Q03）；revision |
| 同步批次（三种策略） | `overwrite_in_scope` 先取 `succession_sync_locks(tenant)` `FOR UPDATE` → 本批（及范围内）继任者员工行 `FOR SHARE`（UUID 升序）→ 目标锁行（升序）→ 记录行 | 同上，逐目标 |
| 离职钩子（employment 事务内，已持员工行 `FOR UPDATE`） | → 目标锁行（该员工生效记录的目标，升序）→ 记录行 | 记录仍生效 |
| 每日 sweep | 每员工一个事务：`lockEmploymentEmployee`（`FOR UPDATE SKIP LOCKED`）→ 同钩子 | 台账无记录 |
| 批量结束 / 删除 | 记录行（ID 升序）`FOR UPDATE`（不需目标锁：结束不产生新生效记录） | 逐对象 revision |
| 等级重排 / 新增 / 删除 | `succession_rule_settings(kind)` 行 `FOR UPDATE`（集合锁）→ 等级行 | 集合 revision |
| 计算 worker | run 行 `FOR UPDATE SKIP LOCKED` → 结果行按对象 ID 升序 | 对象仍在范围 |

互斥保证：新增与离职都要先持继任者员工行（`FOR SHARE` 与 employment 的 `FOR UPDATE` 互斥），因此“新增先读到在职、离职事务扫描空集并提交、新增再插入”不可能发生；两个新增 / 新增与同步在同一目标上由目标锁行串行，锁内重查后由部分唯一索引兜底（Q03 唯一时）。真 PG 交错测试见 §11。
