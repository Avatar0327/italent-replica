## 1. 数据模型

所有表带 `tenant_id`，RLS 与授权镜像按 `0064`（#107）同样方式用 `--custom` 迁移补；主键系统 UUID，业务唯一键按租户；写命令带 `revision` 与命令 ID（AGENTS §10）。表名前缀 `succession_`。

## 3. 条件行编译器（公共模块 `packages/domain/src/expression/rules/`，R3-T06 入池规则直接复用）

### 3.1 对象
```
ConditionRow  { rowNo, kind: 'aggregate' | 'field', fieldCode?, filter?: { operator, value }, measure?, comparator, threshold?, thresholdHigh?, isPercent? }
RuleSet       { rows: ConditionRow[], expression: string }           // expression 只含 and / or / 括号 / 行号
CompiledRule  { formula: string, rowSpans: Array<{ rowNo, start, end }>, referencedRows: number[], compilerVersion }
```
- `aggregate` 行（风险 / 健康度）：宿主先按行定义算出**度量值**（人数、比例、平均值、绿化率……），以字段 `行n.值` 注入 `SubjectReader`；编译产物只做“度量值 比较符 阈值”与 and / or 组合。
- `field` 行（人群、R3-T06 入池规则）：直接对对象字段比较（`盘点对象.格子名称 IN (...)`、`员工.年龄 < 35`），宿主只注入对象字段。
- 两种行可在同一规则集混用（健康度“自定义人群”= 人群规则集先逐人求值，再作为健康度行的人口）。

### 3.2 编译
1. `parseRowExpression(expression)`：词法只认 `and` / `or` / `(` / `)` / 正整数（大小写不敏感，“字符间需加入空格”照原站提示，但容忍无空格）；语法 `expr := term (or term)* ; term := factor (and factor)* ; factor := int | '(' expr ')'`；错误码 `RULE_EXPRESSION_SYNTAX`（位置）、`RULE_ROW_UNKNOWN n`（引用不存在的行）、`RULE_ROW_UNREFERENCED n`（保存时警告，不拦截，🟡 Q-SC-09）。
2. 每行编译为布尔子式：`isEmpty` → `IsEmpty(行n.值)`；`notEmpty` → `NOT`：引擎无 NOT，用 `IF(IsEmpty(行n.值), false, true)`，统一经 `rows/emit.ts` 生成；`eq/ne/gt/lt/ge/le` → `行n.值 op 阈值`；`between` → `AND(行n.值 >= 低, 行n.值 <= 高)`；百分比阈值按度量值同一量纲（度量值以百分数输出，30 表示 30%）。
3. `and` / `or` → `AND(a, b)` / `OR(a, b)`（引擎函数，左结合逐对展开）；整条规则 = `IF(<组合>, 1, 0)`，求值结果 `1` 即匹配。
4. 产物记录每行子式在公式文本中的区间 `rowSpans`，并写 `compilerVersion`（编译器语义版本 + `DEFAULT_SEMANTICS` 标识）；引擎语义变化后（F-032 / F-033 类）由平台命令“重新编译规则”批量刷新缓存，**不得用表达式反写条件行**（DEC-261）。
5. 保存流程：校验条件行枚举组合 → `parseRowExpression` → `compileRuleSet` → `validateFormula`（R3-T00 保存检查）→ 条件行 + 表达式 + 编译缓存同事务写入；任一步失败 400，错误定位到行号（`RULE_ROW_INVALID n`）。

### 3.3 求值与错误映射
- 用 `evaluateFormula`（单对象）或 `evaluateBatch`；失败时 `ComputationFailure.position` 落在哪个 `rowSpans` 区间，就报 **“第 n 行条件出错：<失败原因>”**；失败原因只保留引擎的分类文案（如“比较时出错”），**不带公式文本**（DEC-261）。位置不在任何区间（组合层）→ “条件表达式出错”。
- 度量值求不出（分母为 0、字段取不到）→ 注入 `EMPTY`；比较语义照 DEC-257：空值参与大于 / 小于比较为假、`isEmpty` 为真；不报错、不终止该对象的其他等级判定。
- 等级判定（§4.2 / §4.4）：按 `display_order` 顺序求值，第一个得 `1` 的等级即结果；某等级求值失败 → 记失败明细（对象、等级、行号）并**跳过该等级继续下一等级**；全部等级都跳过或都不匹配 → 空等级（默认颜色）。对象级“计算失败”只在该对象**所有**等级都报错时标记（DEC-257 部分失败照常写入）。

## 4. 计算语义

### 4.1 共同口径
- 时间：业务日期按租户时区（`tenantLocalDate`，DEC-056）；事件时间 UTC。
- 范围内的“在职员工”= 当前生效主职任职版本的人员状态 ∉ {离职 8、调出 4、退休 6}（待入职 1 不计入现任）；已删除 / 撤销的任职不参与。
- 现任人员（职位）= 当前生效主职任职 `position_id = 职位` 的员工；开关 `partTimeInRiskCalc` 开时并入兼职任职（端口，现为空集）；负责人（组织）= 当前生效组织版本 `person_in_charge_id`。
- 继任者 = `succession_records` 中目标匹配、`end_date = 9999-12-31`、未删除的记录；同一人对同一目标只计一次。
- 比例度量输出百分数（分子 / 分母 × 100，保留两位），分母 0 → 空。

### 4.2 职位风险等级（SC-R9）
- 触发：① 每天租户本地 0 点由平台调度（`succession.jobs.run kind=position_risk`，幂等键 `position_risk:<租户>:<本地日期>`；跨午夜后的第一次运行即执行，与 `activation-scheduler` 同一跨日判定）；② 地图“计算职位风险等级”按钮：登记 `calc_run`（`manual`）立即返回 `202 { runId }`，由 worker 异步执行，完成后给触发人登记 `calc_done` 消息。
- 对象：租户内全部关键职位（定时）；手动：触发人数据范围内、当前地图显示的关键职位（查看人范围之外的职位不算、也不出现在失败明细）。
- 每个职位 × 每个启用等级（按顺序）：逐行算度量：`subject` 人口（现任 / 继任者）→ 行过滤（`field_code op value`，为空 / 不为空 / 等于 / 不等于）→ `count`、`count / 现任人数 × 100`、`count / 继任者人数 × 100` → 注入 `行n.值` → 求编译公式；先匹配先得。
- 写结果：`computed` 行覆盖；`manual` 行按 Q-SC-04 处理；每次运行写 `succession_calc_runs` + 失败明细 + 审计（系统执行人 `SYSTEM_USER_ID`，手动触发记触发人）。
- 职位停用 / 取消关键标记：结果行保留但不再展示、下次运行删除其 `computed` 行（`manual` 行保留，重新成为关键职位时仍生效）。

### 4.3 字段与枚举目录（固定枚举，保存时校验）
| 维度 | 取值 |
|---|---|
| 风险行 `subject` | `incumbent` 现任人员 / `successor` 继任人员 |
| 人员字段 `field_code`（风险行、人群行） | 员工信息：`name` 姓名、`gender`、`age`（按生日与业务日期算）、`entryDate`、`workYears`；任职：`orgId` 机构、`positionId`、`jobLevelId` 职级、`jobSequenceId`、`employeeStatus`；继任者行另有 `readinessId`。字段值按**计算执行者**权限读取：定时任务用系统身份读全部；手动触发按触发人字段权限，无权字段 → 该行度量为空（§3.3） |
| 风险 `measure` | `count` 人数 / `countOverIncumbents` 人数/现任者人数 / `countOverSuccessors` 人数/继任者人数 |
| 健康度 `population` | `all` 全部 / `successors` 继任者 / `incumbents` 现任者（= 负责人）/ `custom` 自定义人员范围 |
| 健康度 `field_source` × `field_code` | `review`：盘点字段（`calibratedPerformance` 校准后绩效、`calibratedPotential`、`cellName` 格子名称 等，目录由 R3-T04 端口 `listReviewFields()` 提供）；`org`：`personInChargeId` 负责人、`greenRate`、`onDutyCount`、`establishmentCount`；`succession`：`successorCount`、`readinessId` |
| 健康度 `measure` × 需要的输入 | `greenRate`（组织，无字段）；`reviewResultRatio`（`review` 字段 + 过滤；分母 = 人口中有该盘点字段值的人数）；`successorCount`（无字段，人口 = 继任者；配合 `incumbents` 人口时 = 负责人的继任者人数）；`average`（数值字段）；`ratio`（过滤命中 / 人口）；`count`；`countOverSuccessors`；`countOverIncumbents` |
| 比较符 | `isEmpty` / `notEmpty` / `eq` / `ne` / `gt` / `lt` / `ge` / `le` / `between`（含边界） |

### 4.4 组织健康度（SC-R10、SC-R16）
- 触发：① 地图“计算健康度”按钮（异步，消息）；② 盘点同步批次结束后对涉及的组织自动算一次（`trigger = review_sync`）；③ 无每日定时（手册未提，🟡 Q-SC-05）。
- 计算范围：手动 = 触发人数据范围 ∩ 当前地图显示的组织；同步触发 = 项目所属组织及下级 ∩ 触发人管理单元 ∩ 地图显示组织（SC-R16）。
- 人口：`all` = 该组织及其行政维度下级的在职员工（🟡 Q-SC-06：本组织还是含下级）；`successors` = 该组织当前生效的组织继任者；`incumbents` = 负责人；`custom` = `all` 中满足人群规则的人。
- 盘点字段取数优先级：**触发计算的项目或校准会 > 当前项目（进行中、业务日期最近）> 最近一次盘点（已结束，按结束时间倒序）**，经 R3-T04 端口 `readReviewField(employeeId, fieldCode, context)` 一次给出；取不到 → 该行度量为空。
- 继任字段取不到（如 `readinessId` 对无继任者的组织）→ **跳过该等级**（原站“跳过该规则”），记为 `skipped`，不算失败。
- 已手动赋值（`method = manual`）的组织：不求值、不覆盖、不进失败明细（AC-SC-07）；清除手动值后下次重算恢复。
- 结果写 `succession_health_results`（`computed`）+ `calc_run`。

### 4.5 组织关联信息（SC-R6）
- `on_duty_count` = 该组织（不含下级，🟡 与 Q-SC-06 同题）在职员工数；`establishment_count` 读取时实时取编制模块当前编制数（经 establishment 读端口）；`green_rate` 经 R3-T04 端口 `orgGreenRate(orgId, context)`（`26` TR-R35：计入格子人数 / 落位总人数，最近一次盘点），取不到为空。
- 每 4 小时一次（平台调度 `kind = org_stats`，幂等键按租户 + 4 小时槽）；改卡片显示设置（§2 #9）时对本人地图可见组织触发一次。

## 5. 业务规则落地

### 5.1 时间轴（SC-R1、SC-R2，AC-SC-01）
- 新增 / 编辑：`startDate ≤ 今天`、`endDate`（给了时）`≤ 今天` 且 `≥ startDate`，否则 400 `START_DATE_IN_FUTURE` / `END_DATE_IN_FUTURE` / `END_BEFORE_START`；空 `endDate` 存 `9999-12-31`。
- 目标校验：组织继任的目标组织须在查看人数据范围内且当前有效；职位继任的目标职位须在范围内、启用、`is_key = true`（否则 400 `TARGET_NOT_KEY_POSITION`）；继任者须是查看人员工范围内的在职员工（🟡 Q-SC-02）；准备度须启用。
- 同一（目标, 继任者）已有当前生效记录 → 409 `SUCCESSION_EXISTS`（🟡 Q-SC-03）。
- 现任人员 / 负责人字段响应时派生（§1.1）。

### 5.2 结束（SC-R3）
- 批量：每条校验 `endDate ≤ 今天` 且 `≥ 该条 startDate`；已结束 / 已删除 / 范围外的条目在回执里逐条标 `skipped` 原因（范围外写 `NOT_FOUND`，不泄露），其余整体一个事务；写字段级审计（`end_date`、`end_reason`、`end_source = manual`）。

### 5.3 删除
- 软删除（`deleted_at`），审计保留整条快照（AGENTS §5）；删除后不参与任何统计 / 规则 / 同步比对；同键重放返回原回执，新命令对已删记录 404。

### 5.4 离职自动结束（SC-R4，AC-SC-02）
- 挂接点：employment 模块新增端口 `registerEmployeeStatusHooks({ onStatusEffective })`（与 `personnel-hooks.ts` 同一注册方式），F-022 在任职版本**生效**（含定时生效落地与直接写入的当前生效版本）且新版本 `employeeStatus = left(8)` 时，在**同一事务**内调用；本模块实现：锁该员工为继任者的当前生效记录（`FOR UPDATE`，按记录 ID 升序），把 `end_date` 设为**离职日**、`end_source = exit`、`end_reason = '离职'`，写审计（执行人 = 触发该流转的命令执行人，来源标 `exit`）。
- 离职日取值：🟡 Q-SC-01（`lastWorkDate` 最后工作日 vs 离职版本 `effectiveDate`），等 Q-M0-109 10-09 回查；实现为单一常量函数，两种口径一行切换。
- 幂等：已结束的记录不再改；同一命令重放不重复写。锁序：钩子在 employment 已持有员工闭包与业务锁之后执行，继任记录是锁序最后一环（§7）。
- 不做反向：离职被撤销 / 删除（R2-T03 范围）时不自动恢复已结束记录（🟡 Q-SC-01 附注）；现任人员离职不影响该职位的继任记录（职位本身不变）。
- 兼职任职离职（R2-T05 后）：只有主职离职（人员状态变离职）触发；兼职结束不触发。

### 5.5 组织继任地图（SC-R5～R7）
- 根：请求指定 `root` 须在范围内；缺省取查看人数据范围内行政维度最顶层的组织，多个同级取顺序号最小者；层数 2～4（默认开关值 3）。
- 节点：行政维度下级（`org_hierarchy_links.dimension = admin`，按 `sequence`）；个人设置里隐藏的组织及其下级、虚拟组织（`is_virtual`）按设置剔除；范围外组织不出现（其下级也不出现，不做“断层多根”——组织图单根）。
- 卡片：组织名、负责人（`person_in_charge_id`，姓名按员工信息字段权限）、继任者列表（继任者、准备度、后备类型、开始时间）、健康度（等级名 + 颜色，或默认颜色）、绿化率 / 在岗人数 / 编制数、`show_key_positions` 时该组织的关键职位卡片（现任、继任者、风险等级）。
- SC-R7：`selfSuccessorsVisible = false` 时，查看人本人作为**负责人 / 现任**的组织 / 职位，其继任者列表、继任者计数在响应中去掉（键缺席，不是空数组），列表接口同样过滤。

### 5.6 职位继任地图（SC-R8，AC-SC-06）
- 节点 = 查看人范围内、启用且 `is_key = true` 的职位；父节点 = 沿 `direct_parent_id` 向上找到的**第一个**满足“启用 且 关键 且 在查看人范围内”的职位；找不到 → 该节点为根（多根）。于是：中间职位停用 → 其下级挂到停用职位的上级（AC-SC-06）；中间职位因权限不可见 → 断层处成为新根。
- `showPositionsWithoutSuccessor = false` 时，去掉既无继任者又无有继任者的后代的子树。
- 卡片：职位名、所属组织、现任人员（主职 + 开关内的兼职，逗号拼接，按员工信息字段权限）、继任者与准备度、风险等级。

### 5.7 盘点 → 继任同步（SC-R13～R16，AC-SC-03～05）
- 入口：R3-T04 的“同步继任信息”动作（项目结束 / 校准会结束 / 手动）调用本模块 `syncFromReview(ctx, source)`；本模块路由 `POST /sync` 是同一服务的手动入口（给 T04 端口落地前的验收与运维用）。
- 流程（一个事务）：读开关 `syncStrategy` → 经端口读提名行（§6.1）→ 逐行校验（对象状态流程中 → `SUBJECT_IN_PROCESS`，手动同步时例外：流程中已填的继任者与准备度照常同步；目标非关键职位 / 不在范围 / 继任者非在职 / 准备度未知 → 失败）→ 按策略写入：
  - `append`：目标已有同一继任者的生效记录 → `exists`（不改准备度，🟡 Q-SC-03）；否则新建（`source_kind = review_sync`）。
  - `overwrite`：本批涉及的每个目标，先把其**不在本批**的生效记录结束（`end_date = 今天`、`end_source = sync_overwrite`），本批中已存在的保留并更新准备度，其余新建；未涉及的目标不动（AC-SC-03 的组织 B）。
  - `overwrite_in_scope`：`scope_org_ids` 及其下级范围内的全部组织 / 职位继任生效记录先结束（`sync_scope_overwrite`），再按本批新建。
  - 健康度：端口给出的组织健康度（含空值与“手动赋值”标志）写 `succession_health_results`（`synced` / `manual`）；批次完成后对涉及组织登记 `org_health` 计算（§4.4②）。
- 回执：批次计数 + 逐行 `items`；错误报告 = `outcome = failed` 行；范围外目标在回执里只给 `TARGET_OUT_OF_SCOPE` 不给名称。
- 幂等：同一 `commandId` 重放返回原批次；不同命令对同一来源再次同步按当时策略再执行一遍（追加策略下全部 `exists`）。

## 7. 锁序与事务
- 本模块自有写入只锁 `succession_*` 行（记录按 ID 升序；规则按等级行）；读组织 / 职位 / 任职不加锁。
- 离职钩子：在 employment 事务内、员工闭包与业务锁之后执行，继任记录锁排在全局锁序（员工闭包 → 业务 → 组织 → 编制 → 审批实例）**之后**，不反向取任何前序锁。
- 同步批次：先锁批次行，再按目标 ID 升序锁涉及的生效记录，不锁任职 / 组织。
- 计算任务：worker 每个租户一个事务按游标分页处理对象（≤ 200 / 页），`FOR UPDATE SKIP LOCKED` 领取 run，多实例不重复；结果写入整页一个保存点。
- 真 PG 交错测试：① 离职钩子与手动结束同一记录并发；② 两个实例同时领取同一 run；③ 同步批次与手动新增同目标并发（`SUCCESSION_EXISTS` 二者只过一）。
