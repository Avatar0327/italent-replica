## 3. 条件行编译器（公共模块 `packages/domain/src/expression/rules/`）

R3-T06 入池规则（Q-M0-114 `PoolRule`：`Fields` + `Expression`）与本任务的风险 / 健康度 / 人群共用；规则组、字段值优先级、重复人员处理留在 T06 宿主。

### 3.1 对象、字段引用与类型适配

```ts
type FieldKind = 'text' | 'number' | 'option' | 'multi_option' | 'date' | 'boolean';
interface FieldRef { object: 'employee' | 'employment' | 'successor' | 'review_object' | 'org'; code: string; path: string; kind: FieldKind;
                     optionDomain?: readonly { value: string; label: string; enabled: boolean }[] }   // 以 T04 ReviewFieldDescriptor 为准（SP-17）
type Operator = 'is_empty' | 'not_empty' | 'eq' | 'ne' | 'gt' | 'lt' | 'ge' | 'le' | 'between';
interface ConditionRow { rowNo: number; kind: 'aggregate' | 'field'; field?: FieldRef; operator: Operator; values?: readonly (number | string | boolean)[] }
interface RuleSet { rows: readonly ConditionRow[]; expression: string }
interface CompiledRule { formula: string; rowSpans: readonly { rowNo: number; start: number; end: number }[]; referencedRows: readonly number[]; unreferencedRows: readonly number[]; constantFalseRows: readonly number[]; compilerVersion: string }
```

| `FieldKind` | 宿主注入值（`PlainValue`） | 引擎 `StaticKind`（`fieldKind` 回调） | 说明 |
|---|---|---|---|
| `number` | number | `number` | — |
| `text` | string | `text` | — |
| `date` | Date / 日期文本 | `date` | — |
| `boolean` | boolean | `boolean` | — |
| `option` | `OptionValue { optionValue, label }`（T04 选项 `value` 一律字符串） | `text` | 比较经引擎 `unwrapOption`，字面量按字符串发码 |
| `multi_option` | 端口值为 `PortValue = readonly string[]`（SP-17）；T05 适配层可无损序列化为 `"\|v1\|v2\|"`（无选中 → `null`，值内含 `\|`、`"`、换行 → `RULE_LITERAL_INVALID`） | `text` | **取证前多选字段不进条件行**（DEC-314②；是否适用于 T05 条件行 → Q-SC-23，正文暂按适用：保存 400 `RULE_FIELD_NOT_ALLOWED` 并提示）；放开后用上述编码，不改引擎 `PlainValue` |

- **`aggregate` 行**（风险 / 健康度）：宿主先算度量值，以字段 `行n.值`（number）注入；度量为空（§4.1）注入 `EMPTY`，**不注入布尔值**。
- **`field` 行**（人群、T06 入池）：直接对对象字段比较；无权字段返回 `forbidden`（§4.1）。
- T06 映射：`ItemMetaObjectName = CalibrationObjective` → `object = 'review_object'`；`FieldName` → T04 字段 `code`；`Values` → `values`；`Expression` → `expression`。

### 3.2 发码表（引擎实际语法；R3-06）

引擎支持中缀 `and / or / not`（`lexer.ts` 关键字 `且 / 或 / 非`，`and` 为 JS 短路）、`IN(值, 候选…)`、`IsEmpty(x)`、`Contains(文本, 子串)`；比较符 `= != < > <= >=`。

| 行定义 | 发码 | 空值行为 |
|---|---|---|
| `is_empty` | `IsEmpty(F)` | 度量 / 字段为空 → 满足 |
| `not_empty` | `not IsEmpty(F)` | 为空 → 不满足 |
| `eq` 单值 / 多值 | `(not IsEmpty(F) and F = L)` / `(not IsEmpty(F) and IN(F, L1, L2, …))` | 为空 → 整行 false（守卫在前，`and` 短路，不触发空值比较失败） |
| `ne` 单值 / 多值 | `(not IsEmpty(F) and F != L)` / `(not IsEmpty(F) and NOTIN(F, L1, …))` | 为空 → false（避免 `!= 0` 误命中） |
| `gt / lt / ge / le` | `(not IsEmpty(F) and F > L)` 等 | 为空 → false（不触发 `TYPE_CONVERSION` / `EMPTY_IN_COMPARISON`） |
| `between` | `(not IsEmpty(F) and F >= L1 and F <= L2)` | 为空 → false |
| `multi_option` `eq`（含任一） | `(not IsEmpty(F) and Contains(F, "\|v1\|"))`；多值 `(not IsEmpty(F) and (Contains(F, "\|v1\|") or Contains(F, "\|v2\|")))` | 无选中 → false |
| `multi_option` `ne` | `(not IsEmpty(F) and not (<含任一发码去守卫>))` | 无选中 → false |
| 需要值的运算符而值列为空 | 编译为常量 `false`，记入 `constantFalseRows`，保存时警告 `RULE_ROW_VALUE_MISSING n`（DEC-305④“值为空的条件行按不满足”） | — |
| 字面量 | number → 十进制；text / option → 英文双引号包裹，**值内不得含 `"` 或换行**（`scanString` 无转义，`RULE_LITERAL_INVALID`）；date → `"YYYY-MM-DD"`；boolean → `true` / `false` | — |
| 组合 / 整体 | 行引用 → `(<子式>)`；`and / or` 中缀；`IF(<组合>, 1, 0)` | 结果 `1` 即匹配 |

样例：T06 九宫格 `IF((not IsEmpty(盘点对象.绩效_潜力九宫格位置_after) and IN(盘点对象.绩效_潜力九宫格位置_after, 7, 8, 9)), 1, 0)`；本租户中风险 `1 and 2`：`IF((not IsEmpty(行1.值)) and (not IsEmpty(行2.值)), 1, 0)`；健康度“绿化率 ≥ 30%”：`(not IsEmpty(行1.值) and 行1.值 >= 0.3)`。

### 3.3 编译、规模与保存

1. `parseRowExpression`：词法只认 `and / or / ( ) / 正整数`（大小写不敏感；容忍无空格）；文法 `expr := term (or term)* ; term := factor (and factor)* ; factor := int | '(' expr ')'`；错误 `RULE_EXPRESSION_SYNTAX`（位置）、`RULE_ROW_UNKNOWN n`；未引用行记入 `unreferencedRows`（拦截还是警告 → Q09 🟡，正文暂按警告）。
2. `compileRuleSet(rules, catalog)`：逐行类型校验（字段存在、运算符与类型合法、值个数）→ 发码 → 组合；记录 `rowSpans`（同一行多处引用 → 多区间）。
3. 规模上限：行数 ≤ 50、每行候选值 ≤ 20、括号嵌套 ≤ 20；发码后以 `validateFormula` 对齐引擎 4000 字符 / 800 词 / 100 层；超限 400 `RULE_TOO_LARGE`。
4. `validateFormula(formula, { registry, isKnownField, fieldKind })`：`fieldKind` 按 §3.1 降映射；推导不确定 → 保存报错（DEC-287 补充）。
5. 保存：条件行 + 表达式 + 编译缓存同事务；任一步失败 400 定位到行号（`RULE_ROW_INVALID n`）；`compiler_version` 随缓存写入；引擎语义变化后用平台命令重新编译（#19），**不得用表达式反写条件行**（DEC-261）。

### 3.4 求值、错误定位与安全文案

- 定位：`ComputationFailure` 顶层 `offset / line / column` 落在 `rowSpans` 区间 → 行号；缺省或组合层 → 条件表达式。
- **文案**：引擎 `message` 可能带字段值（`operators.ts:207`），一律不存、不出站；失败只记 `code` + `level_id` + `row_no`；所有出口（列表、详情、失败明细、首次响应、两种重放、通知、审计）按固定映射渲染：

| 错误码 | 固定文案 |
|---|---|
| `TYPE_CONVERSION`、`ARGUMENT_TYPE` | 第 n 行条件出错：比较或转换时类型不符 |
| `EMPTY_IN_COMPARISON`、`EMPTY_IN_ARITHMETIC` | 第 n 行条件出错：空值参与运算 |
| `DIVISION_BY_ZERO` | 第 n 行条件出错：除以 0 |
| `FIELD_FORBIDDEN` | 第 n 行条件出错：计算主体无权读取字段 |
| `DATA_UNAVAILABLE` | 第 n 行条件出错：数据源不可用 |
| `UNKNOWN_FIELD`、`UNKNOWN_FUNCTION`、`SYNTAX_ERROR` | 第 n 行条件出错：规则需要重新编译 |
| 其他 / 无行号 | 条件表达式出错 |

同步回执 `error_code` 同样只按码渲染（`SUBJECT_IN_PROCESS` → “盘点对象仍在流程中”等）；T04 `OutcomeItem.errorParams` 只带行号 / 等级等结构化参数，不带文案。

### 4.1 共同口径

- 时间：业务日期按租户时区（`tenantLocalDate`，DEC-056）；事件时间 UTC。
- 在职员工 = `asOf` 当日时间轴（`employment_timeline.valid_during @> asOf`）上的主职版本人员状态 ∉ {离职 8、调出 4、退休 6}（待入职 1 不算现任）；已删除（墓碑）/ 撤销的任职不参与。
- 现任人员（职位）= 该日主职 `position_id = 职位` 的员工；`part_time_in_risk_calc` 开时并入兼职任职（端口，R2-T05 前为空集）；负责人（组织）= 该日组织版本 `person_in_charge_id`。
- 继任者 = `succession_records` 中目标匹配、在 `asOf` 生效（§5.1 区间）、未删除；同一人对同一目标只计一次。
- **度量 / 字段来源五态**：

| 状态 | 含义 | 对等级判定的影响 |
|---|---|---|
| `value` | 取到值 | 正常求值 |
| `empty` | 真实空值：字段为空、人口为空、**分母为 0** | 注入 `EMPTY`，由 §3.2 的守卫把该行判为“不满足”（DEC-305④ 健康度取证；**风险等级同一规则**，Q-SC-19 由 DEC-311 定，🟡 取证待补）；零分母在卡片与结果里显示“--” |
| `forbidden` | 执行主体无该字段 / 该对象读权（T04 `FieldStatus = forbidden`；引擎 `FieldLookup.status = 'forbidden'` → `FIELD_FORBIDDEN`）；同步批次里一律记协议公共码 `SOURCE_REVOKED { scope: object \| field \| source \| org, ref }`（SP-14 / SP-07，不再有 `SOURCE_FORBIDDEN`） | **该等级失败 → 对象计算失败**，不注入 EMPTY，不向下匹配 |
| `unavailable` | 数据源不可用 / 端口 `unavailable`（外部来源未接）/ 读取异常 | 同上，`DATA_UNAVAILABLE`；同步里是页 / 计划级 A 类 `SOURCE_UNAVAILABLE`（SP-14，回滚事务、不写在行上） |
| `module_absent` | 规格允许的“映射取不到”：健康度 `succession` 字段在盘点来源里**没有继任模块**（SC-R16；DTO `succession.status = module_absent`，或 `SuccessionReadResult.status = module_absent`，SP-05 / SP-06）；有模块但零提名（`present` + `count = 0` / `value` + 空数组）不属于此态，人数按 0 | **跳过该等级**，记 `skipped`，继续下一等级 |

- **等级判定**：按 `display_order` 顺序求值（健康度：满星 → 1 星，DEC-305④）；第一个得 `1` 的等级即结果；某等级**失败**（求值失败、无权、不可用、编译缓存失效）→ 对象“计算失败”（DEC-257），**结果不改写**，失败明细带等级与行号，不向下匹配；只有 `module_absent` 跳过；全部不匹配或全部跳过 → `level_id = null`（默认颜色）。
- 比例度量按小数计算（0.3 = 30%），不预先舍入（比较用原值还是舍入值 🟡 §9）；显示保留 1 位小数（“100.0%”）。
- 执行主体按 §4.0。

### 4.2 职位风险等级（SC-R9）

### 4.4 组织健康度（SC-R10、SC-R16；DEC-305④）

- 触发：① 手动 `computeHealth`（#9a）：按规则计算**请求人权限范围内全部组织**，已手动赋值的组织不参与、不被覆盖（`manual_kept`；导入值保护随 F-050 延期，DEC-311②）；② **重置**（#15a）：对勾选组织按规则重算，**重算等级与清除手动标记在同一条写入里原子完成**（本地 `method = computed`、`revision + 1`；逐对象 `expected_revision` 锁内 CAS，冲突拒绝该对象、保留当前等级与手动标记，DEC-311；`org_health_reset`）；③ 盘点侧“计算健康度”：T04 调本模块实现并登记的 `OrgHealthComputePort.compute({ tenantId, principalUserId, context: OrgHealthContext { projectId, meetingId: string | null }, orgIds, businessDate })`（SP-15；项目级显式传 `meetingId: null`），T05 内部转成 `ReviewSourceContext { triggerProjectId: projectId, triggerMeetingId: meetingId ?? undefined, asOf: businessDate }` 取数求值，返回 `{ orgId, levelId, levelCode, failures[{ code, params }] }`（码按 §3.4，不带文案）；写 `talent_review_project_org_health` 由 T04 以 `compute` 凭据完成。T05 侧若发起项目上下文的回写（协议的 `compute / assign / reset` 凭据），按 SP-16：先用 `readOrgHealthRows({ context, orgIds, viewer })`（计算凭据用 `{ kind: 'principal' }`）读取**目标项目 / 会议健康度行**的当前 `revision`，不用本地 `succession_health_results.revision` 或 run 冻结的 DTO；`context = { projectId, meetingId }`（项目级 `meetingId: null`）、逐行 `expectedRevision`（无行为 0），冲突回执 `REVISION_CONFLICT` 保留当前等级与手动标记、前端按回执提示；④ 同步批次把 T04 run 的健康度 DTO 写回地图（下）；每日定时 🟡（页面无说明，暂不做，Q05）。
- 人口：`all` = 该组织（含不含下级 🟡 Q06，正文暂按本组织及行政下级）在 `asOf` 的在职员工；`successors` / `incumbents` / `custom`（`all` 中满足人群规则者，逐人 `field` 型求值）。
- 取数上下文：`asOf` = run / 批次 `business_date`；`context = { triggerProjectId?, triggerMeetingId?, asOf }` **原样**传给 T04 统一选择器（校准会上下文不降级为项目，SP-06）；绿化率用同一选择器（SP-06，`rate = null` 表示分母 0 或缺九宫格 → “--”、行不满足）。
- `review` 字段：T04 `readReviewFields` 返回 `{ status: value | empty | forbidden | unavailable, value }`，按 §4.1 处理。
- **`succession` 字段**（S:126，E:88 / 99）：不读本地地图；经 T04 `readSuccessionEntries(orgIds, context)`（三档，SP-06）取该组织 `kind = org, direction = successor`（SP-05）的提名行：`successor_count` = 去重继任者数；`readiness_code` = 准备度 code 集合（行过滤 / 比较按集合是否包含）。`SuccessionReadResult.status`（SP-06）：`module_absent` → 跳过该等级；`value` + 空数组（零提名）→ `successor_count = 0`；`forbidden` / `unavailable` → 对象失败（§4.1）。同步 DTO 的嵌套 `succession`（SP-05）同样映射：`module_absent` → 跳过；`present` + `count = 0` → 0。
- `org` 字段：`green_rate` 经 SP-06；`on_duty_count` 取 `succession_org_stats(stat_date = asOf)`，无该日缓存则现算并写缓存。

| 重试 | 不换键；`attempt_no + 1`、状态回 `pending` |

**本模块 run（风险 / 健康度 / 重置 / 统计 / sweep）状态机**：`pending → running → succeeded | partial | blocked | aborted`（无 T04 消费记录）。

| 状态 | 含义 | 恢复入口 |
|---|---|---|
| `blocked` | 可恢复：系统主体（= 所属人）不可用、规则缓存失效（`RULE_CACHE_STALE`，重新编译后可续）、基础设施错误；冻结的对象集合不变 | 同一 run `retry`（#10，不换幂等键，`attempt_no + 1`）：只跑未终态与可重试失败的对象 |
| `partial` | 有对象失败（§3.4 码、`PRINCIPAL_SCOPE_MISSING`、`revision_conflict`） | `retry` 重跑可重试对象；`revision_conflict` 不重跑（DEC-311：刷新后重新发起重置） |
| `aborted` | SA 终止 | 不可恢复，只能新 run |
| `succeeded` | 无失败（允许 `manual_kept`、`unchanged`） | — |

**同步批次本地状态**（动作、码、恢复类别以 SP-13 / SP-14 为准；本表只写 T05 本地字段、屏障、互斥与恢复入口）

| 本地状态 | 对应协议 | 计划 / 屏障 | 租户互斥 | 恢复入口 |
|---|---|---|---|---|
| `waiting` | SP-14 A 类 `BATCH_IN_PROGRESS`（计划前） | 无 | 不持有 | outbox 重投（退避）/ `POST /sync`；互斥释放后重走首次计划 |
| `executing` | 消费记录 `running` | 屏障生效 | 持有 | — |
| `blocked`，`has_plan = false` | SP-14 A 类，计划前（整事务已回滚，T04 无消费记录） | 无 | 不持有 | 自动重试（退避 1 / 5 / 30 分钟，最多 3 次）后 #17 `retry`；重走首次计划，仍做首次目标授权 |
| `blocked`，`has_plan = true` | SP-14 A 类，计划后；或一轮后仍有 `failed ∧ retry_same_run` | 屏障保留 | 持有 | 同上；经 `beginConsumption` 接管续跑，只跑未终态与可重试目标 |
| `completed`（`result = succeeded \| partial`） | `completeConsumption` 成功 | 释放 | 释放 | 永久失败是业务结论，要改须重新发起同步（新 run） |
| `terminated`（`end_reason = superseded \| aborted`） | SP-14 B 类（`RUN_SUPERSEDED` / `ABORTED_BY_ADMIN`） | 未终态目标 `aborted`，屏障释放 | 释放 | 不可恢复；#17 `retry` → 403 `RUN_NOT_RETRYABLE` |
| `rejected` | SP-14 C 类（`SCOPE_REQUIRED` / `UNSUPPORTED_TRIGGER` / `ACTOR_SCOPE_EXCEEDED`） | 未建 | 未持有（已回滚） | 不可恢复；#17 `retry` → 403 `RUN_NOT_RETRYABLE`；修正后在盘点侧重新发起 |

`planning` 只存在于首次计划事务内部，不落库（失败即整事务回滚）。T05 产生的码全部取自 SP-14 码表：本地不再使用 `INFRA_ERROR`（改 `STORAGE_UNAVAILABLE`）、`ADMIN_ABORT`（改 `ABORTED_BY_ADMIN`）、`SOURCE_FORBIDDEN`、`ACTOR_REVOKED`、`LEASE_LOST`（DEC-336 模型不产生）。`SOURCE_UNAVAILABLE` 是页 / 计划级 A 类，不写在行上。入口拒绝码见 SP-14 末段。`RULE_CACHE_STALE` 只出现在本模块 run（同步批次不求值规则）。

## 5. 业务规则落地

### 5.1 时间轴（SC-R1、SC-R2；DEC-305 ①②③）

- 区间定义：记录在日期 `d` 生效 ⇔ `start_date ≤ d < end_date`（半开）；`end_date = 9999-12-31` 为当前生效。
- 新增 / 编辑：`startDate ≤ 今天`（400 `START_DATE_IN_FUTURE`）；`endDate` 给出时 `≤ 今天`（400 `END_DATE_IN_FUTURE`，提示原文“结束时间不可以大于今天”）且 `≥ startDate`（400 `END_BEFORE_START`）；历史补录允许开始、结束都在过去，保存即“已结束”；列表默认只返回当前生效，`status=all` 才含已结束。
- 区间不重叠（同目标同继任者）：命令内在目标锁下先查重叠：与当前生效记录重叠 → 409 `SUCCESSION_DUPLICATE`；只与历史记录重叠 → 409 `SUCCESSION_PERIOD_OVERLAP`；不交叉的历史区间可并存；同一目标可有多名继任者；§1.1 排他约束兜底；恢复生效（置空结束时间）同样查重。
- 目标校验：组织继任的目标组织在执行人范围内且当日有效（否则 404）；职位继任的目标职位在范围内、启用、`is_key`（400 `TARGET_NOT_KEY_POSITION`，候选接口也只列关键职位，DEC-305③）；继任者在职（400 `SUCCESSOR_NOT_ACTIVE`；按 §4.1 定义，待入职 1 算在职、可被提名，与 DEC-308 下拉含待入职一致），**不校验继任者是否在操作人员工范围内**（DEC-308，用户选择的原站口径）；准备度启用（400 `READINESS_DISABLED`）；目标存在未完成同步批次的计划屏障 → 409 `TARGET_SYNC_IN_PROGRESS`。
- 继任者候选（#3a `GET /successor-candidates?q=`）：**全租户**关键词搜索，含待入职，最多返回 30 条，**不受操作人 HR 数据范围限制**，返回 `{ employeeId, name, email, status }`（原站显示“姓名(邮箱)”，关键词匹配姓名 / 邮箱；是否还匹配工号 🟡 未取证，正文暂按姓名 / 邮箱），不按数据范围、也不按员工信息字段权裁剪——**DEC-308，用户选择的原站口径**（2026-10-07 用户选 C，不采纳收紧方案；审查不作为信息泄露缺陷）。入口授权 = 持 Record `create` 或 `update` 按钮；排除离职 / 调出 / 退休与墓碑；不返回其他字段；`q` 为空 → 400。保存后记录里嵌套的继任者同样**照北森正常显示**，不按查看人数据范围隐藏（DEC-311③，Q02 后半；🟡 具体展示字段未取证，正文暂按姓名(邮箱)）。

### 5.2 结束（SC-R3）

- `POST /records/end`：整批原子；逐条校验 `endDate ≤ 今天`、`≥ 该条 startDate`（400 `END_BEFORE_START` 列出 ID）、可见（任一不可见整批 404）、未结束（409 `ALREADY_ENDED` 列出 ID）、`expectedRevision`（409 `REVISION_MISMATCH` 列出 ID）、无计划屏障（409 `TARGET_SYNC_IN_PROGRESS`）；写字段级审计（`end_date`、`end_reason`、`end_source = manual`）。**锁序（R4-02）**：先无锁读出各记录的目标 ID（目标列不可改，`FIELD_IMMUTABLE`），按目标锁行升序 `FOR UPDATE`，再按记录 ID 升序 `FOR UPDATE` 重读记录，用重读后的状态、`revision`、屏障做上述校验（取锁前被删除 → 404，被结束 → `ALREADY_ENDED`，revision 变了 → `REVISION_MISMATCH`），再写入；与 §7 全部入口一致“目标锁 → 记录行”。

### 5.3 删除

- 软删除 + 审计整条快照；删除后不参与任何统计 / 规则 / 同步比对；同键重放返回原回执（返回前仍复核当前范围）；新命令对已删记录 404；有计划屏障 → 409。锁序同 §5.2（R4-02）：无锁读目标 ID → 目标锁行 → 记录行重读（存在、revision、屏障）→ 删除。

### 5.4 离职自动结束（SC-R4，AC-SC-02）

挂接端口（契约 PR 已交付，`apps/api/src/modules/employment/status-hooks.ts`）：`registerEmployeeStatusHooks(name, { onRecordMaterialized, onRecordDeleted, onRecordRescheduled })`，按订阅方名称登记、按名称顺序同事务调用（R3-T06 人才池出池用同一端口），employment 不 import 本模块；事件 `{ employeeId, recordId, kind, effectiveDate, lastWorkDate, employeeStatus }`，离职的 `effectiveDate` 即离职生效日。本模块实现 `applyExit(tx, ctx, employee, record)`：employment 已持员工行 `FOR NO KEY UPDATE`（`lockEmploymentEmployee`）→ 目标锁行（该员工为继任者的生效记录的目标，升序）→ 记录行；把 `end_date` 设为**离职生效日**（最后工作日的次日，DEC-343①）、`end_source = exit`、`end_reason = '离职'`、`exit_record_id = 记录 ID`；记录保留不删；写审计；写 `succession_exit_applications`。

**DEC-343 口径**（PR-A 按此实现，下表触发矩阵相应收窄）：离职事件（`onRecordMaterialized`，`employeeStatus = 8`）先写 `succession_exit_applications` 台账；④ **职位继任**由离职事件触发：生效日已到的立即 `applyExit`，未来生效的由 sweep 在离职生效日结束；① **组织继任**由夜间任务（`exit_sweep`）按台账结束（当天办理的离职当晚结束）；两者都**不补处理**：离职事件发生之前已离职的人、离职后才建的记录不结束（端口不补发；组织侧夜间任务是否补处理未取证，🟡 正文暂按与职位相同），记录仍生效而继任者已离职时，列表 / 地图可显示“继任者已离职”提示（🟡 BWGF 离职日期未核对），不自动补结束；③ 组织继任列表默认只显示“当前生效”，可切到“已结束”（§5.1）。

### 5.7 盘点 → 继任同步（SC-R13～R16；按《R3-T04/T05 同步协议》v5）

> **只引用协议**（DEC-330 A'）：协议文件 `docs/08_设计/R3-T04-T05_同步协议.md`（T04 维护；本版核对的是 main 上的 v5，`809df05`）。身份、run、范围、类型、源授权、消费记录与租约、目标登记、页事务与提交证明、回执状态与完成门槛、终止与取代、错误码与三类恢复动作、健康度凭据都以协议为准，下文只写 **T05 的落点**，引用写成 SP-xx。互斥是本模块的批次互斥模型（DEC-336，SP-09；§1.2 `succession_sync_mutex`）。

**驱动**：只有手动触发（SP-02）。outbox 事件 → `consumeRun(runId)`；`POST /sync { runId }`、#17 `retry`、自动重试、恢复扫描（§4.6）都调用同一函数，按批次本地状态进入下列阶段。

**阶段 P0 + P1（首次计划；一个事务）**

1. 批次头按 `(tenant_id, source_run_id)` 取或建（`waiting`）。批次已 `completed / terminated / rejected` → 不执行：`/sync`、#17 返回 **403 `RUN_NOT_RETRYABLE`**（SP-13），outbox 重投幂等返回。
2. 批次已有计划（`has_plan`）→ 跳到阶段 E。
3. 租户互斥（SP-09，DEC-336）：互斥行 `INSERT … ON CONFLICT DO NOTHING` 后 `FOR UPDATE`；被另一未终结批次持有 → 回滚，另起事务记本批次 `waiting`（`BATCH_IN_PROGRESS`；`/sync` 409），不调用 `beginConsumption`。否则写入本批次。
4. `loadRun`：`superseded` → 按 SP-13 停止（本批次 `terminated`）；`trigger ≠ sync_requested` → C 类 `UNSUPPORTED_TRIGGER`。`business_date` = run 头冻结值（SP-02）。
5. `beginConsumption`（SP-08）：`CONSUMPTION_LEASED` → 回滚、本次退出。首次成功计划之前，事务回滚就意味着 T04 侧**没有**消费记录（SP-14 A 类“计划前”）。
6. 策略快照写批次；`overwrite_in_scope ∧ scopeExplicit = false` → C 类 `SCOPE_REQUIRED`（SP-03）。
7. 源授权：按页 `authorizeSourceRead({ page })`（SP-07）。`ok = false` 或来源暂不可用（`SOURCE_UNAVAILABLE`）→ A 类计划前失败；`forbidden` 明细留给第 11 步写 `SOURCE_REVOKED { scope, ref }`。
8. 写主体复核（SP-01）：失效 → A 类计划前失败 `PRINCIPAL_UNAVAILABLE { principal: 'write' }`。
9. 实际执行集合 = 提名目标 ∪（`overwrite_in_scope` 时）范围内有生效记录但无提名的 `delete_only` 目标 ∪ `status ≠ not_provided` 的健康度组织。
10. 原触发人目标授权（SP-01 第 ② 项，只做一次）：不覆盖 → C 类 `ACTOR_SCOPE_EXCEEDED`。`/sync` 与 #17 另做调用人检查，不满足 → 403 `BATCH_SCOPE_EXCEEDS_REQUESTER`、整事务回滚、批次保持原状态。
11. 目标锁升序 `FOR UPDATE`，锁内读 `old_record_ids`，逐提名定 `plan_outcome`（码见 SP-14；`direction = target` → `skipped`；`syncEligible = false` → `SUBJECT_IN_PROCESS`，`blockReason = terminated` → `skipped`），写本地计划行（屏障）。同一覆盖目标一好一坏 → 见下文“回执映射”。
12. 收集 `planOutcomes`（SP-10 第 2 项、SP-12 回执聚合）：计划阶段已确定终态的全部行——计划失败或跳过的提名行、因此终态的对象行、**没有提名的对象行 `skipped`**、计划阶段失败的目标行、计划阶段失败的健康度行（等级未知 / 停用、源撤权）、**`not_provided` 组织预建的 `org_health` 行 `skipped`**；没有任何终态时为空数组。本地目标 / 提名行同时记 `execution_no` 与页 0 命令（关联记录）。
13. **计划提交**（SP-10）：一次调用 `registerTargets({ executionNo, planCommandId: ${runId}:succession:${executionNo}:0, targets, planOutcomes })`，原子完成：登记并封存全部 `org / position` 目标（含无提名 `delete_only`，零执行目标登记空集；健康度目标沿用预建 `org_health` 行，不登记为 `target`）、写 `planOutcomes`、写 `PageCommit { kind: 'plan', pageNo: 0 }`。计划事务**不调用** `recordOutcome`。计划事务结果未知 → `getPageCommit(…:0)` 存在且 `executionNo` 匹配才算计划已提交，否则在当前执行内用同一命令重做（SP-11）。
14. 零执行目标 → 同一事务末尾 `completeConsumption`（SP-09 第 5 条允许；锁序同样是互斥 → 消费记录）→ `completed`、释放互斥。否则 `has_plan = true`、`executing`，提交；屏障生效（§7）。

**首次计划前的失败**（SP-14 A / C 类“计划前”）：第 3～11 步任一失败都**整事务回滚**（不留计划、目标登记、回执、互斥），T04 没有消费记录；然后另起事务：
- A 类（`PRINCIPAL_UNAVAILABLE`、`OWNER_UNAVAILABLE`、`PROJECT_INVISIBLE`、`SOURCE_UNAVAILABLE`、`STORAGE_UNAVAILABLE`）→ 本地批次 `blocked`（`has_plan = false`，不持互斥），按 §4.6 恢复；恢复时从第 1 步重走，**仍要做第 10 步的首次目标授权**（它只在那次成功计划的事务里算数）。
- C 类（`SCOPE_REQUIRED`、`UNSUPPORTED_TRIGGER`、`ACTOR_SCOPE_EXCEEDED`）→ `abortConsumption({ executionNo: null, code, recovery: 'new_run' })`（SP-13 第 3 行），由 T04 把全部预建回执行写 `aborted`；本地批次 `rejected`、通知触发人。T05 **不**自行写失败回执。

**阶段 E（执行；每页一个事务，≤ 200 目标，每目标一个保存点）**

- 每页开始前在页事务**之外**调用 `renewLease`（SP-08）。执行页事务顺序按 SP-11：**第一步** `assertExecutionActive` → `authorizeSourceRead({ page })` → 写主体复核 → 业务写入 → `recordOutcome({ pageNo ≥ 1, pageCommandId })` → 提交。页事务不取互斥行（SP-09 第 4 条）。
- 断言失败按 SP-08 / SP-13：`EXECUTION_INACTIVE` → 本 worker 停止、不改批次；`RUN_SUPERSEDED` → 本批次 `terminated(superseded)`。
- 页级 A 类（源授权 `ok = false`、`SOURCE_UNAVAILABLE`、写主体失效、页事务 `STORAGE_UNAVAILABLE`）→ 本页回滚，另起事务置 `blocked`（计划、屏障、互斥保留；不调用 `abortConsumption`）。
- 取本页目标：本地 `pending ∪ (failed ∧ retryable)`；只跳过 `done`、`failed ∧ ¬retryable`、`aborted`。
- 每目标锁内重验（继任者在 `business_date` 与今天都在职、目标有效且关键、准备度启用、目标在写主体范围、计划行未终态），按动作写入：`append`（同继任者已有生效记录 → `exists`，🟡 Q03）/ `overwrite`、`scope_overwrite`（结束 `old_record_ids ∩ 仍生效` 中不属于本目标成功继任者的记录，再新建 / 更新）/ `delete_only`（结束 `old`）/ 健康度（§4.4）。健康度目标的锁内重验只有两项：组织在 `business_date` 存在（否则 `TARGET_NOT_FOUND`）、在写主体当前范围（否则 `TARGET_OUT_OF_SCOPE`）；失败时该 `org_health` 行 `failed`、`recovery = none`，不写本地结果。
- **执行期来源撤权**：本页 `forbidden` 命中某目标涉及的对象 / 字段 / 来源 / 组织 → 相关提名行 `SOURCE_REVOKED { scope, ref }`（行永久）；该目标若是 `overwrite` / `scope_overwrite`，**整组失败、旧集合保持**（不结束旧记录、不新建），其余提名按下文映射；`append` 目标只让受影响的提名失败。
- 单目标写入的基础设施错误：保存点回滚，目标与其 `planned` 提名 `failed`、`STORAGE_UNAVAILABLE`、`recovery = retry_same_run`（SP-14 行可重试）。
- 每页必须带上本页处理过的每个目标的 `target` 行终态（健康度为 `org_health` 行），本地目标行同时记 `execution_no / page_command_id`。
- **结果未知**：`getPageCommit(pageCommandId)` 存在、`kind = 'execute'` 且 `executionNo` 等于当前执行才算本页已提交（SP-11）；否则在当前执行内用同一命令重做本页，已被接管则由新执行以新页命令重做。
- 一轮结束：仍有 `pending` 或 `failed ∧ retry_same_run` → `blocked`（不 complete、不释放互斥、屏障保留，§4.6 自动重试）；否则在最后一个执行页提交**之后**另起**终结事务**：互斥行 `FOR UPDATE` → `completeConsumption`（SP-09 第 5 条）→ 本地 `completed(result)`、释放互斥 → 登记 `sync_done` 通知 → 登记 `org_health` 计算（`review_sync`）。完成不在执行页内做。

**终止 / 取代**（SP-13 第 1、2 行）：SA `abort`（#17）→ 一个事务：互斥行 `FOR UPDATE` → `abortConsumption({ executionNo: 当前, code: 'ABORTED_BY_ADMIN', recovery: 'terminate' })` → 本地未终态目标与提名 `aborted`、屏障与互斥释放 → `terminated(aborted)`；T04 把剩余回执行写 **`aborted`**。项目重启由 T04 写 `superseded`，T05 在下一次断言 / 源授权得知后做同样的本地清理、**不**调用 `abortConsumption` → `terminated(superseded)`。只有项目重启才产生 `superseded`。终止后 #17 `retry` → 403 `RUN_NOT_RETRYABLE`。

**跨 run 串行**：SP-19 第 1、2 行由 T05 承担（真 PG）；有计划的 `blocked` 批次会挡住本租户其他同步，SA 可经 #17 `abort` 解除。

**回执映射**（状态、聚合、门槛照 SP-12；本地布尔列 `retryable` 在端口适配层转换：`true ↔ recovery = 'retry_same_run'`，`false ↔ 'none'`）。T05 补充：

|---|---|---|
| 计划阶段同一覆盖目标一好一坏（Q-SC-15 暂按 B） | 坏提名：自身码；合法提名：`failed`、`TARGET_PARTIAL_NOMINATIONS { causeNominationIds }`、`recovery = none`；目标行 `failed` 同码；对象行按 SP-12 聚合为 `failed` | 首次计划事务（页 0） |

## 7. 锁序与事务

全局锁序（`org/locks.ts`）：员工闭包 → 业务 → 组织 → 编制 → 审批实例；本模块的锁排在其后：**目标锁行 → 继任记录行**。

| 入口 | 锁序 | 锁内重验 |
|---|---|---|
| 新增 / 编辑恢复生效 | 继任者员工行 `FOR SHARE`（与 employment 的 `FOR NO KEY UPDATE` 互斥）→ `succession_target_locks(目标)` `FOR UPDATE` → 记录行 | 在职；目标有效 / 关键 / 范围；**无计划屏障**（批次处于 `executing / blocked`，或首次计划事务已提交，且该目标 `pending / failed ∧ retryable` → 409 `TARGET_SYNC_IN_PROGRESS`）；区间不重叠（DEC-305②）；revision |
| 批量结束 / 删除（R4-02） | 无锁读出记录的目标 ID（目标列 `FIELD_IMMUTABLE`，集合稳定）→ `succession_target_locks` 升序 `FOR UPDATE` → 记录行升序 `FOR UPDATE` **重读** | 重读后的存在性（取锁前被删 → 404）、未结束（`ALREADY_ENDED`）、逐对象 revision（`REVISION_MISMATCH`）、无计划屏障（409 `TARGET_SYNC_IN_PROGRESS`） |
| 同步计划（P0 / P1） | 租户互斥行 `FOR UPDATE` → T04 消费记录（`beginConsumption`，协议内 `FOR UPDATE`）→ 目标锁行（升序，实际执行集合全部）→ 锁内读旧集合、写计划行 | 源授权、写主体、所属人；原触发人与调用人目标授权 |
| 同步执行（每页） | `renewLease` 在页事务之外；页事务内 T04 消费记录 `FOR SHARE`（`assertExecutionActive`，第一步）→ 每目标：继任者员工行 `FOR SHARE`（升序）→ 目标锁行 → 记录行 | §5.7 E 的锁内重验（在职、有效、关键、准备度、范围、计划行状态） |
| 同步完成（终结事务，最后一个执行页提交之后；零执行目标时在计划事务末尾） | 租户互斥行 `FOR UPDATE` → T04 消费记录（`completeConsumption`，协议内 `FOR UPDATE`）→ 本地计划行 | 无 `pending` 与可重试失败 |
| 同步终止（SA abort / 取代清理 / C 类拒绝） | 租户互斥行 `FOR UPDATE` → T04 消费记录（`abortConsumption`，协议内 `FOR UPDATE`；取代时 T04 已置，不再取）→ 计划目标行 | 批次未终结 |
| 离职钩子 / sweep | employment 已持员工行（`FOR NO KEY UPDATE`）→ 目标锁行 → 记录行 | 记录仍生效 |
| 规则集合 | `succession_rule_settings(kind)` 行 → 等级行 | 集合 revision |
| 计算 worker | run 行 `FOR UPDATE SKIP LOCKED` → 结果行升序 | 对象仍在主体范围；重置逐对象 revision |

- 互斥：**所有入口首次取锁都是目标锁 → 记录行**（结束 / 删除按 R4-02 改为先目标锁），与同步执行、离职钩子 / sweep 之间不存在反向等待环；新增与离职都先持继任者员工行（`FOR SHARE` 与 `FOR NO KEY UPDATE` 互斥）；同一目标上的新增 / 同步由目标锁行串行，锁内重查后由排他约束兜底；**计划与手动写入不交错**：计划行在目标锁内写入并与读旧集合同事务提交，手动事务取同一目标锁后一定看到已提交的屏障。
- 跨 run 串行靠租户互斥（批次持有，只在终结时释放）+ 计划屏障；旧 worker 失效靠 T04 消费租约：被接管后它的 `assertExecutionActive` 必失败，页事务不写任何业务数据。页事务不取租户互斥行（互斥只在终结事务释放，而终结必改消费记录状态，断言已覆盖），所以计划 / 终止事务（互斥 → 消费记录）与页事务（只取消费记录）之间没有锁序环；T04 项目重启只取消费记录 `FOR UPDATE`，与页事务按提交顺序串行（协议）。

### 8.4 SELF 谓词与全部出口的投影

- **SELF 谓词**：查看人用户 ↔ 人员绑定得到员工 `E`；记录“是本人的”⇔ 目标组织在请求当日的负责人 = `E`，或目标职位在请求当日的现任含 `E`。`self_successors_visible = false` 时，“是本人的”记录在**所有出口**不返回、不计数；SELF 记录的写入按保守口径**不可写**（命令前 404，Q-SC-17 🟡）。谓词在 SQL 里实现（`succession_self_target_sql(viewer)`），列表 / 地图 / 审计 / 回执共用。
- **整体可见门槛**：run / 批次先判整体可见（§8.2），不可见不返回 ID / 状态 / 申请人 / 时间。
- **投影函数** `projectSuccession(viewer, kind, payload)`：先按对象查看字段裁剪（`getModuleViewableFields`，键缺席），再逐层处理：
