## 2. 接口与命令执行协议

## 3. 条件行编译器（公共模块 `packages/domain/src/expression/rules/`）

### 3.1 对象、字段引用与类型适配

```ts
type FieldKind = 'text' | 'number' | 'option' | 'multi_option' | 'date' | 'boolean';
interface FieldRef { object; code; path; kind: FieldKind; optionDomain?: readonly { value: number | string; label }[] }
```

| `FieldKind` | 宿主注入值（`PlainValue`） | 引擎 `StaticKind`（`fieldKind` 回调） | 说明 |
|---|---|---|---|
| `number` | number | `number` | — |
| `text` | string | `text` | — |
| `date` | Date / 日期文本 | `date` | — |
| `boolean` | boolean | `boolean` | — |
| `option` | `OptionValue { optionValue, label }` | 选项域值全为 number → `number`，否则 `text` | 比较经引擎 `unwrapOption`（`operators.ts` `valuesEqual`），字面量按值类型发码；选项域混合类型 → `RULE_FIELD_UNSUPPORTED` |
| `multi_option` | **序列化文本** `"\|v1\|v2\|"`（无选中 → `null`） | `text` | `PlainValue` 不支持数组、`plainToValue` 数组 → EMPTY，所以宿主按此序列化；值内含 `\|`、`"`、换行 → `RULE_LITERAL_INVALID` |

### 3.2 发码表（引擎实际语法）

| 行定义 | 发码 |
|---|---|
| `is_empty` / `not_empty` | `IsEmpty(F)` / `not IsEmpty(F)` |
| `eq` 单值 / 多值 | `F = L` / `IN(F, L1, L2, …)` |
| `ne` 单值 / 多值 | `F != L` / `NOTIN(F, L1, …)` |
| `gt / lt / ge / le` | `F > L` 等（number / date） |
| `between` | `(F >= L1 and F <= L2)` |
| `multi_option` `eq`（含任一） | `Contains(F, "\|v1\|")`；多值 `(Contains(F, "\|v1\|") or Contains(F, "\|v2\|"))` |
| `multi_option` `ne` | `not (<eq 发码>)` |
| 字面量 | number → 十进制；text → 英文双引号包裹，**值内不得含 `"` 或换行**（引擎 `scanString` 无转义，`RULE_LITERAL_INVALID`）；option → 选项值字面量；date → `"YYYY-MM-DD"`；boolean → `true` / `false` |
| 组合 / 整体 | 行引用 → `(<子式>)`；`and / or` 中缀；`IF(<组合>, 1, 0)` |

样例同 v2（T06 九宫格 `IF((IN(盘点对象.绩效_潜力九宫格位置_after, 7, 8, 9)), 1, 0)`；本租户中风险 `IF((not IsEmpty(行1.值)) and (not IsEmpty(行2.值)), 1, 0)`）。

### 3.3 编译、规模与保存
同 v2（`parseRowExpression`、`compileRuleSet` 记 `rowSpans`、行数 ≤ 50 / 候选值 ≤ 20 / 嵌套 ≤ 20、`validateFormula` 对齐 4000 字符 / 800 词 / 100 层、`RULE_TOO_LARGE`、`compiler_version`、平台重新编译）。`fieldKind` 回调按 §3.1 降映射给出。

### 3.4 求值、错误定位与安全文案（R2-02）

- 定位：`ComputationFailure` 顶层 `offset / line / column` 落在 `rowSpans` 区间 → 行号；缺省或组合层 → 条件表达式。
- **文案**：引擎 `message` 可能带字段值（如 `比较【<值>><值>】时出错`，`operators.ts:207`），因此**一律不存、不出站**。失败只记 `code`（`FailureCode`）+ `level_id` + `row_no`；所有出口按固定映射渲染：

| 错误码 | 固定文案 |
|---|---|
| `TYPE_CONVERSION`、`ARGUMENT_TYPE` | 第 n 行条件出错：比较或转换时类型不符 |
| `EMPTY_IN_COMPARISON`、`EMPTY_IN_ARITHMETIC` | 第 n 行条件出错：空值参与运算 |
| `DIVISION_BY_ZERO` | 第 n 行条件出错：除以 0 |
| `FIELD_FORBIDDEN` | 第 n 行条件出错：计算主体无权读取字段 |
| `DATA_UNAVAILABLE` | 第 n 行条件出错：数据源不可用 |
| `UNKNOWN_FIELD`、`UNKNOWN_FUNCTION`、`SYNTAX_ERROR` | 第 n 行条件出错：规则需要重新编译 |
| 其他 / 无行号 | 条件表达式出错 |

同步回执的 `error_code` 同样只按码渲染（`SUBJECT_IN_PROCESS` → “盘点对象仍在流程中”等），`errorMessage` 不写入 T04 回执。

## 4. 计算语义

### 4.0 主体模型（R2-01；DEC-301③ / 304 保守口径，待定 Q-M0-125）

四个主体：**请求人**（调用接口的人）、**所属人**（run / 批次对应的责任人）、**源读取主体**（读盘点来源的身份）、**目标写入主体**（写继任 / 结果的身份）。

| 入口 | 请求人检查（命令前） | 所属人 | 源读取主体 | 目标写入主体 | 执行时检查（计划阶段与每页开始） | 失败语义 |
|---|---|---|---|---|---|---|
| 定时风险 / sweep / 组织统计 | 无（平台调度） | 待定 D-04：A 无所属人（仅系统主体）/ B 租户配置的责任人 | 系统主体（`succession.system_principal_user_id`，读员工 / 任职 / 盘点字段，按其范围与字段权） | 系统主体 | 系统主体存在、成员有效、持 `standard_succession_runner` 身份与所需对象权限、范围非空；B 时另查责任人有效 | 任一不满足 → run `failed_permanent`（计划阶段）`PRINCIPAL_UNAVAILABLE` / `OWNER_UNAVAILABLE`，不写任何值 |

### 4.1 共同口径（同 v2）

| trigger | 键格式 |
|---|---|
| 定时 `position_risk` / `exit_sweep` | `<kind>:schedule:<tenant>:<本地日期>` |
| 定时 `org_stats` | `org_stats:schedule:<tenant>:<本地日期>:<interval_h>h:<slot_index>`，`slot_index = floor(自当日租户本地 0 点起的分钟数 / (interval_h × 60))`；**纪元 = 该本地日期的租户本地 0 点**，次日同时刻键不同；当天把间隔改回旧值时，旧槽键已存在 → 视为已跑，不重复，下一槽起生效 |
| 手动 / 显示设置变更 / 同步触发 / 重试 | 同 v2（`<kind>:manual:<commandId>`、`org_stats:preferences:<user>:<rev>`、`org_health:sync:<batch_id>`；重试不换键，`attempt_no + 1`） |

状态机（run 与批次相同）：`pending → running → succeeded | partial | failed_retryable | failed_permanent`（批次另有 `superseded`）。

| 状态 | 含义 | 恢复入口 |
|---|---|---|
| `failed_retryable` | 执行阶段基础设施错误 | `retry`：从未完成页 / `pending` 目标继续，计划不重建 |
| `failed_permanent`，`failed_at_phase = planning` | 主体 / 所属人不可用、源读取撤权、规则缓存失效、run 已被取代（`superseded`）、自动 run 缺范围（`SCOPE_REQUIRED`）等，**未执行任何对象** | 修复后 `retry`：**重建计划**（同一 run / 幂等键，`attempt_no + 1`）；`superseded` 不可重试 |
| `failed_permanent`，`failed_at_phase = executing` | 执行中出现不可恢复情况（如 T04 run 变为 `superseded`、撤权） | 不可 `retry`（403 `RUN_NOT_RETRYABLE`）；只能新 run（手动触发 = 新命令 ID；定时 = 下一周期） |
| `partial` | 部分对象 / 目标失败 | `retry` 只重跑 `failed` 且 `retryable` 的对象 / 目标 |

### 5.1～5.3 时间轴、结束、删除（DEC-305 ①②③ 落实；其余同 v2）
- **新增 / 编辑**：`startDate ≤ 今天`（400 `START_DATE_IN_FUTURE`）；`endDate` 给出时 `≤ 今天`（400 `END_DATE_IN_FUTURE`，提示原文“结束时间不可以大于今天”）且 `≥ startDate`（400 `END_BEFORE_START`）；**历史补录**允许开始、结束都在过去，保存即“已结束”（不能预约未来结束，到期后再补结束日）；列表默认只返回当前生效，`status=all` 才含已结束。
- **区间不重叠**（同目标同继任者，DEC-305②）：命令内在目标锁下先查重叠：与当前生效记录重叠 → 409 `SUCCESSION_DUPLICATE`；只与历史记录重叠 → 409 `SUCCESSION_PERIOD_OVERLAP`；不交叉的历史区间可并存；同一目标可有多名继任者（卡片“继任者 N 人”）；§1.1 排他约束兜底；恢复生效（置空结束时间）同样查重。
- **目标职位只能选关键职位**（DEC-305③）：候选接口与校验都只认 `is_key` 且启用的职位（400 `TARGET_NOT_KEY_POSITION`）。

### 5.7 盘点 → 继任同步（R2-04 / R2-05 重写）

**驱动（DEC-306②）**：同步**只有手动触发**——项目页“同步数据 → 同步继任信息”勾选对象后由 T04 冻结 run（`trigger = sync_requested`），项目进行中即可同步；**项目结束 / 校准会结束不自动同步**（🟡，T04 侧同口径；§4.0 预留行）。T04 run 的 outbox 事件 `{ runId, projectId, meetingId, trigger, snapshotVersion, principalUserId, actorUserId }` → 本模块消费者 `consumeRun(runId)`；`POST /sync { runId }` 与重试调用同一函数；命令 ID 按 T04 协议（A-10）。`manualOverride` 只随 `sync_requested`（SC-R15 手动例外），资格按 T04 `syncEligible`；健康度写回（SC-R16）随同一 run 的 DTO。

**阶段 P（计划，一个事务；`phase = planning`）**
1. 取租约 `succession_sync_leases`：已有未完成批次持有效租约 → 本次 `failed_retryable: BATCH_IN_PROGRESS`（outbox 稍后重投）。
2. `loadRun`：`status = superseded` → 全部提名写 `superseded` 回执、批次 `superseded`、不写继任、结束。否则校验主体（§4.0）。
3. **固化** `business_date = run.businessDate ?? 计划时租户本地日期`、`strategy`（开关快照）、`scope_org_ids`（run 头冻结值）；`strategy = overwrite_in_scope` 且 `scope_org_ids` 为空（自动 run）→ **拒绝**：批次 `failed_permanent: SCOPE_REQUIRED`（保守口径，🟡 Q-SC-18）。
4. 分页读全部提名（`listRunNominations`，源读取授权已在步骤 2 复核），逐行校验 → `succession_sync_items.plan_outcome`：`direction = target` → `skipped`（Q11 定前，T04 §8.5 同口径）；`syncEligible = false` → `failed: SUBJECT_IN_PROCESS`（`terminated` → `skipped`）；目标在 `business_date` 不存在 / 非关键 / 继任者非在职 / 准备度未知或停用 / 目标不在目标写入主体当前范围 → 对应错误码；其余 `planned`。
5. 生成**目标执行计划** `succession_sync_targets`：
   - 每个有 `planned` 行的目标：`action` 按策略（`append` / `overwrite` / `scope_overwrite`），`planned_item_ids` = 该目标全部 `planned` 行，`old_record_ids` = 计划时该目标的生效记录（`exit`、手动创建的都算）。
   - `overwrite_in_scope`：范围 = run 头冻结的 `scope_org_ids` 及行政下级（T05 不推导“全部”）；范围内有生效记录但无 `planned` 行的目标 → `delete_only`；`EMPTY_SNAPSHOT`（提名为空）同样生成 delete_only 计划。
   - 同一目标存在 `failed` 行 → **Q-SC-15**：A 成功行构成新集合（`old_record_ids` 照常结束）/ B 该目标 `failed: TARGET_PARTIAL_NOMINATIONS`、不结束不新建；对 `overwrite` 与 `overwrite_in_scope` 同样适用。
   - `listRunOrgHealth` 每行 → `org_health` 目标（§4.4）。
6. 批次 `phase = executing`、`status = running`；提交。

**阶段 E（执行，按目标分页 ≤ 200 / 页，每页一个事务，每目标一个保存点；`page_no` 递增）**
- 页开始：续租；复核主体（§4.0）；`pending` 目标按 `(target_kind, target_id)` 升序。
- 每目标：锁本目标涉及继任者的员工行 `FOR SHARE`（升序）→ 目标锁行 → 记录行；锁内：`old = old_record_ids ∩ 当前仍生效`（计划后被手动结束的跳过；**计划后新建的记录不在 `old` 里，不结束也不计入**）；`append`：对每个 `planned` 行，已有同继任者生效记录 → `exists`（准备度暂按保留，🟡 Q03 追加项），否则新建；`overwrite` / `scope_overwrite`：先结束 `old` 中不属于本批成功继任者的记录（`sync_overwrite` / `sync_scope_overwrite`），再 `updated` / 新建；`delete_only`：结束 `old`；`org_health`：写结果。目标 `status = done`，记 `ended_record_ids`、各行 `exec_outcome` 与 `record_id`；失败 → 回滚该目标保存点，`status = failed` + `error_code`。
- 页末：按 **T04 统一的分页 / 事务 / 回执协议**（A-10 / A-11 / A-15：run 身份、页 / 执行命令身份、行幂等键、批次完成标志四者分开）写本页回执；本设计的映射：一页 = 一个页命令（页命令 ID 由 T04 协议给出）、目标 `done` 检查点 = 行幂等键之上的本地续写状态、批次完成 = T04 的完成标志（最后一页之后单独发出）；业务与回执是否同一事务以 T04 v3 为准（本设计默认同一页事务，失败行的回执按 T04 规定更新首次回执）；提交。
- 全部目标非 `pending` → 批次 `done`，发出 T04 的批次完成标志，释放租约，登记 `sync_done` 通知（所属人 / 触发人），对涉及组织登记 `org_health` 计算（`review_sync`）。
- **重试**：只跑 `pending`（及 `retryable` 的 `failed`）目标；`done` 目标与已有 `exec_outcome` 的行跳过；计划不重建，所以不会结束前页刚建的记录；无提名的 `delete_only` 目标有自己的 `done` 检查点。
- **互斥**：批次之间靠租约串行；手动新增 / 编辑在取目标锁后发现该目标存在未完成批次的 `pending` 计划 → 409 `TARGET_SYNC_IN_PROGRESS`（防止计划与手动写入交错）；计划之后的手动写入不影响已冻结的 `old_record_ids`。
- **结果分类**：提名为空且无 delete_only → `succeeded`（`EMPTY_SNAPSHOT`）；有目标 `failed` → `partial`；全部目标 `failed` → `partial`（逐目标码）；主体 / 快照问题 → `failed_permanent`（§4.6）。
- **回执聚合**：每提名一条 `OutcomeItem { nominationId, status, retryable, errorCode }`（`planned → created / updated / exists` ⇒ `synced`；`failed` ⇒ `failed`；`skipped` ⇒ `skipped`；`superseded`）；每对象一条聚合（全部行 `synced / skipped` ⇒ `synced`，任一 `failed` ⇒ `failed` 并列出错误码集合，全部 `skipped` ⇒ `skipped`）；`delete_only` 与 `org_health` 目标不对应提名 / 对象，只在本模块 `GET /sync-batches/:id/targets` 展示。

## 7. 锁序与事务（补 R2-04 互斥）

| 入口 | 锁序 | 锁内重验 |
|---|---|---|
