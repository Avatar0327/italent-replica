# F-547 组件明细文件导出契约

> 作用对象为复刻系统。本文是第一步契约设计，审查合入后派发后端，再接 FE-R2f 导出片。依据 DEC-963、DEC-708、规格 35 及 [R2-T10 人事分析前端设计](R2-T10_人事分析前端设计.md) §4.1～4.5、§4.8、§5.1～5.2、§8 U10。接口与披露基线为 `4647856680e8ab8137ed027c8ea8ee4dfec065a6`。

## 1. 范围

> 组件明细文件导出契约与后端｜U10：DEC-708 组件明细文件导出无契约；用户定首版就要导出｜先定导出契约（字段权、数据范围、审计，遵 DEC-708）与后端接口，再接前端导出片

从 B48～B51、B55 的「查看详情」导出当前组件及钻取条件下的全量授权明细。现有分页 JSON（下称 D）继续用于查看详情。DEC-708 的看板标题栏「下载」仍为本地 PNG。B52 名册、B53/B54 统计报表与团队人事看板各走原入口。

## 3. 权限、字段及数据范围

**准入与按钮权。** 分页和导出每次都以当前会话及租户运行 `objectContext(..., 'view')` 与同对象的 `requestScope`。首版采用现有 D 的查看准入，前端在成功且仍有效的组件详情内提供「导出」。授权目录已登记的 `detail@list` 不是现行 D 的准入门禁。设计不新增 `export` 授权按钮，也不额外预置给任何身份。DEC-415 处理新对象的「看全部」，本契约复用五个既有对象。现有预置按 DEC-763② / DEC-767：HR 专员、HR 经理、标准版系统管理员有看板查看和「看全部」，人事管理员的报表授权不能打开看板导出。DEC-404 的授权编码集合没有变化，授权版本、指纹和历史无需改动。B52 名册的 `export@list` 独立生效。

**范围与审批披露。** 查询按当前租户执行，租户表读写使用 `withTenant`。每条路由从现行 `<对象>.list` 解析范围，按 D 的候选谓词裁剪，再做组件筛选、去重、排序与计数。无范围时结果为空，历史 `asOf` 只定位业务时点。B48 保持员工及任职、Offer、组织各自的可见谓词。B49/B50 沿用各自在职、流动、编制候选。B55 继承合同候选与部门/人员范围。B51 审批实例还需满足发起、实际处理、抄送，或审批管理员的 `adminTransfer` / `adminIntervene` 按钮及业务对象范围的披露分支。跳过任务不算处理关系。应用分区可保留 D 已放行的业务单行，其不可披露的关联 `instanceId` 单元格为空。`hit` 是 D 的既有业务命中值，实例 ID 为空时也保持该值。「看全部」只决定看板数据范围，审批实例仍按该分支判断。

**列的来源。** 同一组件的下载和 D 共享最终行投影和披露判断。下表为当前可输出的 `items[]` 键及列序。用稳定的简体中文列名，按真实主体命名 `id`，例如「合同记录 ID」「申请单 ID」「任务 ID」，混合主体用「记录 ID」或「业务单 ID」。当行键与员工 ID 或实例 ID 同时存在且同义时，行键列用「明细行 ID」。每个允许且获准的列保持固定位置，不能根据有没有非空样本来增减表头。

## 4. 文件与行数

- 成功为 HTTP 200，`Content-Type: text/csv; charset=utf-8`，`Content-Disposition: attachment; filename="<看板路径段>-<组件编码>-<asOf>.csv"`，`Cache-Control: no-store`。例如 `hr-movement-6.28-2026-11-21.csv`。文件名只取服务端目录定义的路径段、编码和有效日期，字段值、分组值与租户输入不进入文件名。前端按该契约命名保存。
- 文件采用 UTF-8 BOM、逗号分隔、CRLF 换行，首行是列名。复用名册 CSV 的引号转义及公式前缀中和规则，覆盖流程标题、节点和分组等文本。空值写空单元格，空字符串保持为空，`false` 和 `0` 保留。日期、UTC 时间戳、数值、分组键及枚举用 D 的值，数组用 JSON 文本写进单个单元格。文件无额外说明行、筛选快照、汇总或行外字段。
- 全量是当前授权、筛选和钻取条件下，按 D 去重及排序后的全部行。限 **10,000 条数据行**（表头除外），同一结果集决定总数与数据。B48/B55 可用共享 `pageRows`，B51 用 `hrProcessPage` 的计数和披露，内部 offset 为 0，返回行投影有界。B49/B50 分别从同一次 `componentMembers` / `movementMembers` 结果取总数和行，过限即停在 CSV 序列化前。前端不逐页拉取或拼接文件。
- 0 条返回仅有表头的 CSV，10,000 条完整返回，超过则返回 HTTP 422，`error.code=VALIDATION_FAILED`、`error.details={reason:"EXPORT_ROW_LIMIT",limit:10000,total:<当前授权明细总数>}`，提示「导出最多 10000 行，请缩小筛选范围」。超限无附件、无部分文件、无成功操作日志。参考名册 `exportLimitResponse` 与 R2-T10 前端设计 §4.5。
- 前端导出片复用 `ReportExport` 的租户头、单次提交锁、错误反馈及 Blob URL 回收。切换组件、分组、已应用筛选、会话或租户，或关闭详情后，取消下载并丢弃迟到回执。只保存当前请求的成功 CSV，422 按机器码提示缩小范围后手动再试。

## 5. 操作审计

沿用 F-482 的 `recordOperationLog`：先完整生成文件，再在当前租户事务中写一条成功日志，提交后才返回文件及附件头。因此「成功」指服务端已经生成并允许交付，浏览器保存是否完成不在服务器可观察范围内。每次独立成功请求各一条，包含零行文件。参数错误、拒权、超限、生成失败或审计事务失败均无成功记录。审计失败时通过统一错误出口返回 JSON 错误，文件不交付。

日志使用 `behavior='export'`、`objectType=<看板对象编码>`、`objectId=<固定组件编码>`，记录当前租户、操作者、请求来源和 UTC 时间，`successCount=1`、`failureCount=0` 按导出次数统计。摘要用「导出组件明细」及组件固定名称。`attachment`、`items`、`errorReport` 不存业务数据，省略这些字段以及人员/组织归属。筛选原值、下载内容、业务记录 ID 和数据行数均不写日志。此 GET 无业务写入、命令台账或 outbox。

现有操作日志入口按登记对象决定可见性，F-489/F-509 的统计报表展示规则只适用于对应报表对象。首版审计以租户库留痕验收，看板明细导出沿用当前审计页未登记对象的默认拒绝。另见 §9。

## 6. 与 F-542～546 的边界

- F-542 负责新增人员、组织等名称的授权披露。本契约只用 §3 明确列出的字段，不查其他接口补名。
- F-543 的 B51 7.2.15 和 F-544 的 B50 6.32 当前按 FE-R2f 设计为占位。相应口径片使组件恢复为可用详情前，下载端对这两个编码返回 404 `NOT_FOUND`，与未知组件同样无文件、无成功日志，前端无导出动作。相应修正合入后，接入修正后的 D 行集与投影。哪个实现片后合入，哪个补做开放接线与正向对照，按 §8 的覆盖边界验收。F-547 的其他组件可先实现。
- F-545 负责 B48 6/8/19 与 17/18 的候选人员口径；B48 与 B55 3.1.17 共用到期候选。F-546 负责 B50/B54 编制占编口径，B50 3.1.36 下载当前 D 的实有人员行。F-547 不加导出专属的统计条件。修正后的共享 D 行集生效时下载同步采用，未修正组件的原页面提示沿用 DEC-962。
