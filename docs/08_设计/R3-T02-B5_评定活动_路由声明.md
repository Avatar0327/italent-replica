## 2. 业务规则（服务端，命令事务内；Q-M0-174 / DEC-412 取代 #225 暂行口径）

| 规则 | 说明 |
|---|---|
| 没有活动编码 | 原站没有编码，字段、唯一约束、`ACTIVITY_CODE_EXISTS` 一并删除（DEC-412；DEC-410① 作废）；带 `code` 键 400 |
| 必填 / 非必填 | 必填：名称、类型、所属组织、年度、周期、负责人、评定生效日期、申请人、组织范围、类别 / 级别范围、跨级数（缺省 1）；非必填：起止日期、通知范围、通知模板 |
| 申请人 | 多选 `applicants`：`self`（员工本人）/ `others`（非员工本人），至少一项、不重复，两个都选就是都可以 |
| 组织范围 | `orgRange`：最多 100 个，每项 `{ orgId, includeDescendants }`（缺省勾上），同一组织不能重复；存 `ev_activity_orgs`；新增的组织须在操作人 TEvaluation 范围内（同一 404） |
| 类别 / 级别范围 | 不能为空（范围总落到具体级别，不存在“有类别、级别为空”；取代“空 = 未设置”暂行口径） |
| 整份提交 | 活动 + 组织范围 + 环节，整体成功或失败；环节按 ID（没带 ID 的按同类型顺序）与已有环节对应，就地更新保留稳定 ID（C2 的指标明细按环节 ID 引用），对不上的 ID 400 `ACTIVITY_CHAIN_ID_UNKNOWN` |
| 跨级限制 | `max_level_jump` 必填 1～5 的整数，新建未传取 1，显式空值 / 0 / 6 / 小数 400；列 `NOT NULL DEFAULT 1` + CHECK（DEC-372②） |
| 环节 | 资格申报首、结果发布末，各 1 个；材料举证、答辩评审各最多 3 个、先后不限；评价表**只在答辩评审上且必填**（400 `ACTIVITY_CHAIN_FORM_REQUIRED`）；资格申报审批流程必填（400 `APPROVAL_PROCESS_REQUIRED`，编辑锁下可改不可清空）；转入方式缺省：资格申报 / 材料举证自动，答辩评审只能手动；环节日期在活动起止内（活动起止日期没填则不约束）；不适用字段传值 400 `ACTIVITY_CHAIN_FIELD_NOT_ALLOWED`；纯函数在 `packages/domain/src/evaluation/activity-rules.ts` |
| 适用范围重复 | 与进行中（published）其他活动有交集且申请类别有交集 → 409 `ACTIVITY_SCOPE_DUPLICATE`；**组织范围把下级算进去**：勾了“包含下级”的组织按行政维度、租户时区当天的组织版本展开后求交集，去掉“包含下级”可能不再冲突；新建或改组织范围（含“包含下级”）/ 类别才检查；按“租户 + 申请类别”取事务级咨询锁后判断（`lockActivityScope`，C2-1a 发布复用） |
| 编辑锁 EV-R14 / AC-EV-05 | `apply_count > 0` 时只许改名称、所属组织、年度、周期、负责人、起止日期、申请人、可申报级别、环节的名称 / 日期 / 顺序 / 流程 / 转入方式 / 通知；其余变化（增删环节、类型、适用范围、类别、级别、生效日期、通知范围、环节评价表 / 材料模板 / 强控截止 / 破格）409 `ACTIVITY_HAS_APPLICANTS`；原样提交不算改动 |
| 已完成的活动 | 不能修改：409 `ACTIVITY_COMPLETED`，“此活动已完成，无法修改”（Q-M0-174 第 8 点） |
| 状态 / 报名数 | status 只写 `draft`，`apply_count` 只读（输入带这两个键 400） |
| 删除 | 只有草稿能删；进行中 409 “此活动进行中，无法删除”、已完成 409 “此活动已完成，无法删除”（reason `ACTIVITY_NOT_DRAFT`，原站文案）；草稿有报名 409 `ACTIVITY_HAS_APPLICANTS` |
| 被引用拒删 / 拒停用 | 活动类型 / 周期被活动引用：删除、停用 409（`ACTIVITY_TYPE_IN_USE` / `ACTIVITY_CYCLE_IN_USE`）；评价表被环节引用：删除 409 `EVALUATION_FORM_IN_USE`（停用不拦）；**任职类别 / 级别被活动引用：删除 409（`CATEGORY_IN_USE` / `LEVEL_IN_USE`）** |

写命令经 `runWrite` / `runDelete`：对象权限、按钮、字段、活动范围与引用访问都在命令事务内由 `ledgerExit` 之前的 `before` 重新解析（首次 / 直接重放 / 失败后回查同一出口，DEC-388①）；删除重放按快照所属组织 ∪ 所属人复核。

## 4. 服务端在载荷之外自动改写的字段

仅一处**初始化例外**：新建时请求体省略 `maxLevelJump`，系统初始化为 1（DEC-372②“新建默认 1”）。这是新对象的系统缺省值，不是改动已有值，所以**不**按“实际变更字段”再校验操作人对 `maxLevelJump` 的编辑权（该字段只读的人也能新建，得到缺省 1）；修改时省略该字段不改值。已报总编排确认是否允许（#226 第 1 轮口径）。其余：status（draft）与 apply_count（0）由系统写；环节 `seq` 取提交顺序，属于 `chains` 字段本身。

## 5. 错误提示的字段披露

- 适用范围重复提示：冲突活动在范围内且操作人对活动“名称”字段有查看权才带名称。
- 环节规则提示（日期越界 / 开始晚于结束 / 不适用字段）：操作人对活动 `chains` 字段有查看权才带环节名称，否则只给通用提示与机器错误码（`ACTIVITY_CHAIN_DATE_OUT_OF_RANGE` 等）；修改活动日期时校验的是库里已有环节，不能借错误提示读出被隐藏的环节名称（#226 第 1 轮 P2-1）。

## 6. 被引用拒删（跨模块）

任职类别 / 级别被活动的 `category_ids` / `level_ids` 引用时，`DELETE /api/tenant/qualification/categories|levels/:id` 返回 409（`CATEGORY_IN_USE` / `LEVEL_IN_USE`，通用提示不列活动）。数组列没有外键，所以靠删除入口的引用守卫：删除先 `FOR UPDATE` 类别 / 级别行再查活动引用；活动保存新增引用时 `FOR SHARE` 同一行，两种先后顺序都不会留下失效引用（#226 第 1 轮 P2-2，真 PG 并发回归）。
