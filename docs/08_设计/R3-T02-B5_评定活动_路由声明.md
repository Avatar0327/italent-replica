| 名称 | 说明 |
|---|---|
| 谓词 `ev.owned(ev_activities)` | `scopeSql(scope, { org: owner_org_id, creator: owner_id })`，分页之前 |
| 范围 `ev.evaluationActivity.ownerOrg` / 守卫 `ev.ownerOrgInScope` | 新建 / 改所属组织：须存在且在范围内（范围外与不存在同一 404，DEC-082） |
| 守卫 `ev.newActivityRefs` | 只校验**新增**的引用（原有的原样保留不重校，DEC-281⑧）：类型 / 周期 / 评价表——无查看权 403、不存在 / 范围外同一 404、已停用 400 `REFERENCE_DISABLED`；类别 / 级别——`assertQualificationRefs`；适用组织范围 / 通知范围——组织须存在且在范围内（同一 404）；负责人——人员引用出口（无员工信息查看权 403，不存在 / 范围外同一 404） |

| 删除 | 只回显被删活动，解析负责人的人员访问，不解析各类被引用对象的访问 |

## 2. 业务规则（服务端，命令事务内）

| 规则 | 说明 |
|---|---|
| 整份提交 | 活动 + 环节嵌套，整体成功或失败；环节按类型就地更新，保留稳定 ID（C2 的指标明细按环节 ID 引用） |
| 跨级限制 | `max_level_jump` 必填 1～5 的整数，新建未传取 1，显式空值 / 0 / 6 / 小数 400；列 `NOT NULL DEFAULT 1` + CHECK（DEC-372②） |
| 环节 | apply 与 result 必有且 apply 在首、result 在末；各类 ≤ 1；日期在活动起止内；defense 紧接 result 只能手动转入；apply 审批流程必填（400 `VALIDATION_FAILED`，reason `APPROVAL_PROCESS_REQUIRED`，编辑锁下可改不可清空）；不适用字段传值 400 `ACTIVITY_CHAIN_FIELD_NOT_ALLOWED`；纯函数在 `packages/domain/src/evaluation/activity-rules.ts` |
| 适用范围重复 | 与进行中（published）其他活动组织范围有交集且申请类别有交集 → 409 `ACTIVITY_SCOPE_DUPLICATE`；新建或改组织范围 / 类别才检查；按“租户 + 申请类别”取事务级咨询锁后判断（`lockActivityScope`，C2-1a 发布复用） |
| 编辑锁 EV-R14 / AC-EV-05 | `apply_count > 0` 时只许改名称、所属组织、年度、周期、负责人、起止日期、申请人、可申报级别、环节的名称 / 日期 / 顺序 / 流程 / 转入方式 / 通知；其余变化 409 `ACTIVITY_HAS_APPLICANTS`；原样提交不算改动 |
| 状态 / 报名数 | status 只写 `draft`，`apply_count` 只读（输入带这两个键 400） |
| 删除 | 只有草稿且没有报名才能删（409 `ACTIVITY_HAS_APPLICANTS` / `ACTIVITY_NOT_DRAFT`，保守默认） |
| 被引用拒删 / 拒停用 | 活动类型 / 周期被活动引用：删除、停用 409（`ACTIVITY_TYPE_IN_USE` / `ACTIVITY_CYCLE_IN_USE`）；评价表被环节引用：删除 409 `EVALUATION_FORM_IN_USE`（停用不拦） |
| 编码 | `code` 租户内唯一（AGENTS §10），重复 409 `ACTIVITY_CODE_EXISTS` |

写命令经 `runWrite` / `runDelete`：对象权限、按钮、字段、活动范围与引用访问都在命令事务内由 `ledgerExit` 之前的 `before` 重新解析（首次 / 直接重放 / 失败后回查同一出口，DEC-388①）；删除重放按快照所属组织 ∪ 所属人复核。

## 3. 端点

| 端点 | 数据操作 | 按钮 | 范围 | 额外 |
|---|---|---|---|---|
| `GET /api/tenant/evaluation/activities` | EA 查看 | — | `ev.owned(ev_activities)` 分页前 | `status` 筛选须有 status 字段查看权（403 `FILTER_FIELD_HIDDEN`）；披露 `managerRef` |
| `GET .../activities/:id` | EA 查看 | — | 定位器 `ev.evaluationActivity.byId`，范围外与不存在同一 404 | 披露 `managerRef` |
| `POST .../activities` | EA 新增 + 字段编辑权 | `create@list` | 所属组织须在范围内 | 守卫 `ev.newActivityRefs`；披露 `activityName` / `managerRef` |
| `PATCH .../activities/:id` | EA 编辑 + 字段编辑权（含显式清空） | `update@detail` | 定位器 `ev.evaluationActivity.editable` | 守卫 `ev.newActivityRefs` / `ev.ownerOrgInScope`；编辑锁；披露同上 |
| `DELETE .../activities/:id` | EA 删除 | `delete@detail` | 定位器 `ev.evaluationActivity.editable` | 披露 `managerRef` |

## 4. 服务端在载荷之外自动改写的字段

无。`max_level_jump` 新建缺省取 1 是系统缺省值，不是对已有值的改动；status（draft）与 apply_count（0）由系统写；环节 `seq` 取提交顺序，属于 `chains` 字段本身。
