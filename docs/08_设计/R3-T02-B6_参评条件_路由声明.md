# R3-T02 B6：参评条件与 EV-R5 接入

沿用 B5 的五条活动路由及权限声明，没有新增端点或授权项编码。条件作为活动的 `conditions` 字段随整份命令保存；
F-039 的声明、必需项表、字段投影已在 B5 登记，继续使用 `runWrite` / `CommandGuard.before` / `ledgerExit`，
首次、重放与失败回查均复核当前功能、按钮、字段与活动范围。B6 重算依赖摘要、基准与发现探测。

## 请求与响应

`POST /api/tenant/evaluation/activities`、`PATCH .../activities/:id` 接收可选的 `conditions` 数组：

| 字段 | 形状 |
|---|---|
| kind / applicantKind | `common` / `extra`；`self` / `others` |
| categoryIds / levelIds | UUID 数组，统一小写并去重；未传为 `[]`；新增引用复用 `assertQualificationRefs` |
| expression | 可空；未设置时不调用组合式校验；传非空值时调用 B2，只能引用本组的明细序号 |
| details | `{ seq, source, field, operator, value1, value2 }`；来源 / 字段为标识，值是文本、数字或空 |

新建省略条件得到 `[]`，修改省略条件保留原值，显式 `[]` 清空。条件与明细保留提交顺序；两个值用独立类型列存储，
回读区分数字 `0` 与文本 `"0"`。活动列表 / 详情 / 写响应 / 重放 / 删除快照统一在活动字段投影里裁剪 `conditions`，
显式清空也须有编辑权。条件和明细随活动同事务写入审计快照，删除由复合外键级联。
活动列表 / 详情读取活动头时取共享锁，保持后续条件与明细和活动头属于同一 revision；并发保存须等待读取事务结束。

## 校验与锁

- B2 校验 9 种运算符、必填值、重复 / 非法序号、范围上下界和组合表达式。D-068 的日期反向范围补入 B2，按业务日期比较，
  不使用浏览器时区；`is_empty` / `not_empty` 没有比较值。空白比较值返回 400。
- 明细错误：400 `VALIDATION_FAILED`，`details.reason = CONDITION_DETAILS_INVALID`，带 `conditionIndex`（从 0 开始）与
  `issues[{seq, code}]`；表达式错误 reason 为 `CONDITION_EXPRESSION_INVALID`，带条件组下标及 B2 的行列 / offset。
- EV-R14：已有报名可替换参评条件；增删环节等既有锁规则不变；已完成活动不能改条件（DEC-412）。
- EV-R5：通过 `registerFormLock` 接真实活动引用。活动 / 评价表创建、修改、删除均先经 `coordinateActivityForms` 取租户协调锁；
  评价表写入先按 ID 取引用活动共享锁，再取评价表行锁，随后判 `status = published AND apply_count > 0`。
  活动写入先锁活动，再取评价表显式 / 环节外键隐式锁。草稿、零报名活动也参与等待，保留首次发布 / 报名后的复核。
  协调锁保护动态的活动 / 表单引用集合，代价是同租户配置写命令串行；活动详情 / 列表仍只取原有共享锁。
  锁覆盖 B4 所有评分与投票设置；停用的既有遗漏 P2-F1 转 F 任务，本 PR 不改。
- 类别 / 级别删除统一经 `lockUnusedQualificationRef`：先取本对象排他行锁，再检查标准、发展通道、员工记录、活动主体和全部条件组。
  活动主体与所有条件组的新增引用统一经 `assertQualificationRefs` 取同一类别 / 级别行的共享锁；最后引用清除后才能删除。
- 员工字段为空时的 `ne` / `eq` 求值属于后续申报阶段，本 PR 只保存与校验，不读取人员值。
