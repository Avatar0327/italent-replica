## 0. 一页摘要

- **声明**：每条 Hono 路由改用 `declare(router, method, path, policy, handler)` 注册；`policy` 必须写清六类之一（`public / platform / admin / self / own / object`），`object` 类还要写功能 / 按钮权限、数据范围解析方式与范围外响应码、字段裁剪策略、写字段来源。
- **执行点**：`declare` 把处理函数包成"框架先执行声明、再调用处理函数、最后出口守卫"的三段；现有 `module-route-access.ts` 的 `objectContext / button / writeFields / requestScope / visible / trimModuleResponse` 收编为框架内部调用，各模块自有规则（DEC-177 任职可见、DEC-102 流程管理员、自助绑定员工等）以**具名定位器 / 守卫 / 投影器**登记进框架，不另写一套。
- **缺失即失败**：`createApp` 结束前枚举 `app.routes`（Hono 原生，含子路由器），未经 `declare` 注册且不在白名单的路由 → 抛错，进程起不来、测试也过不了。
- **CI 反向测试**：`AC-PRM-FW-01～07` 自动枚举全部已声明路由，用五个固定测试用户（管理员 A、范围内 HR H、无权限成员 N、范围外 HR O、缺字段权 F）生成反例：无功能 / 按钮权限、范围外对象（含列表深扫）、字段缺席（响应每一层深扫）、幂等重放撤权、批量 / 导入含范围外行；每个负例断言具体状态码并做"前后库校验和"比对。
- **分步上线**：PR-A（本任务）= 框架 + 反向测试 + 迁移"在途 PR 未触碰"的模块（静态粗计 119 条路由）；其余 93 条进**白名单基线**（告警）。PR-B 在 #83 / #96 / #97 / #99 合并后迁移其余模块并清空白名单，白名单清零即切强制模式。白名单只减不增的起算点见 §8。

### 1.3 近期 P2 的共同形态（#96、#97、#99、#106、#107）

1. 某个入口（预览、批量、导入、重放、候选列表）漏掉按钮或范围检查；
2. 响应的某一层（嵌套对象、`before`、汇总计数、候选列表）没有过字段裁剪；
3. 幂等重放直接返回台账里的首次响应，没有按当前权限复核与裁剪；
4. 新模块各写一套 `access.ts`，审查方只能逐个路由人工核对"查看人 × 接口 × 字段"。

框架要做到：这四类漏法在**声明缺失时无法通过 CI**，在**声明存在时由框架而不是处理函数保证**。

## 2. 设计一：路由权限声明的形态

### 2.1 类型（`apps/api/src/route-policy/types.ts`）

```ts
export type RoutePolicy =
  /** 不需要身份：/healthz、外部链接作答（#107）。必须写原因与依据 DEC，FW-01 列入"公开路由清单"供审查。 */
  | { kind: 'public'; reason: string; dec: string }
  /** 平台运营身份（platformContext 已判定）；租户成员 / 租户管理员一律 403。 */
  | { kind: 'platform' }
  /** 8 类企业管理员能力（06 §7.1）；无能力 403。 */
  | { kind: 'admin'; capability: AdminCapability; fields?: FieldsPolicy }
  /** 员工自助：当前用户绑定的员工本人；未绑定 403，路径里不是本人 403。 */
  | { kind: 'self'; fields: FieldsPolicy }
  /** 按接收人 / 参与人过滤的本人数据（待办、我发起的、通知、我已处理），不需要身份权限；守卫在 SQL 里按 userId 过滤。 */
  | { kind: 'own'; guard: GuardName; fields: FieldsPolicy }
  /** 业务对象路由（绝大多数）。 */
  | {
      kind: 'object';
      object: string; // MODULE_OBJECTS.*.code / PERSONNEL_OBJECT / APPROVAL_PROCESS_OBJECT …
      operation: 'view' | 'create' | 'update' | 'delete';
      button?: { code: string; level: ButtonLevel }; // 没有按钮的路由必须写 button: null 并说明（如纯列表查询）
      scope: ScopePolicy;
      fields: FieldsPolicy;
      writeFields?: WriteFieldsPolicy; // create / update 必填；delete 与 view 不填
      guards?: readonly GuardName[]; // 附加具名守卫（DEC-102 流程管理员、DEC-193 直接操作等）
      batch?: 'atomic' | 'receipt'; // 批量 / 导入入口：整体成败或逐条回执（AGENTS §10「批量」）
    };

export type ScopePolicy =
  /** 列表：框架解析范围并注入 access.scope；处理函数必须用 scopeSql 做 SQL 谓词；出口守卫核对响应带 hasDataPermission。 */
  | { mode: 'list'; view?: string }
  /** 单对象：框架在处理函数之前用登记的定位器取对象归属并点判定；范围外按 outOfScope 返回且不泄露存在性。 */
  | { mode: 'point'; target: Target; locator: LocatorName; outOfScope: 404 | 403; view?: string }
  /** 无归属字段的对象（DEC-121 / 081）：只认看全部或"使用用户"创建人维度。 */
  | { mode: 'see-all'; creatorLocator?: LocatorName }
  /** 规则复杂到只能在事务内判定（DEC-177 / 178 / 193）：由具名守卫完成；守卫自身必须登记反向测试（见 §4.6）。 */
  | { mode: 'guard'; guard: GuardName; outOfScope: 404 | 403 };

export type Target = { param: string } | { body: string /* JSON 路径，支持 rows[*].orgId */ };

export type FieldsPolicy =
  /** 框架投影：响应（含数组、嵌套）中属于这些对象字段目录的键按查看人字段权限裁剪；envelope 为协议元数据白名单。 */
  | { mode: 'project'; objects: readonly string[]; envelope?: readonly string[] }
  /** 模块自定义投影器（任职嵌套 fields/customFields/before、审批节点表单 DEC-057、审计 visibility.ts）；出口守卫仍兜底深扫。 */
  | { mode: 'projector'; projector: ProjectorName; objects: readonly string[] }
  /** 响应不含业务字段（204、仅 id + revision、仅枚举字典）。 */
  | { mode: 'none'; reason: string };

export type WriteFieldsPolicy = {
  /** 载荷里哪些键算"要写的字段"：顶层 / fields+customFields（任职）/ rows[*]（批量、导入）/ subdivisions 展开（编制） */
  from: 'body' | 'body.fields+customFields' | 'body.rows[*]' | 'body+subdivisions';
  /** 控制键（expectedRevision、confirmed、reservationId、submit …）不算字段 */
  controls?: readonly string[];
  /** 允许"只带命令、不带字段"的按钮（Employment.Submit / Withdraw / Revoke / RetryActivation） */
  commandOnly?: boolean;
};
```

### 2.3 声明缺失即失败

- `createApp` 末尾调用 `verifyRouteDeclarations(app, { allowlist, strict })`：遍历 `app.routes`，跳过 `method === 'ALL'` 的中间件，用 `__COMPOSED_HANDLER` 还原原处理函数，查 `declare` 登记的 `WeakMap<handler, Declaration>`。
  - 已声明 → 记入运行时清单（供 FW-01 与 PR 描述统计）；
  - 未声明且在白名单 → `console.warn('[route-policy] 未声明路由（白名单）: GET /api/tenant/…')`；
  - 未声明且不在白名单 → `throw new Error('[route-policy] 未声明的路由 …')`，无论 strict 与否。
- 白名单为空时 `strict` 自动为 true：此后任何未声明路由直接抛错。
- 声明本身的静态合法性在 `declare` 调用时校验：`object` 必须在对象目录中；`button` 必须是该对象登记的按钮与级别；`operation` 为 create/update 时 `writeFields` 必填；`scope.locator / guard / projector` 必须已登记；同一 (method, path) 不得重复声明。错误在模块注册时抛出，`pnpm test` 的任意一个 `createApp` 都会命中。

## 3. 设计二：框架执行点与收编

### 3.1 一次请求的执行顺序（`route-policy/enforce.ts`）

```
tenantContext / platformContext（现有）
→ captureCommandFailures（现有）
→ [框架] 1 解析上下文：tenantOf(c)；expectedRevision（If-Match，写请求）
→ [框架] 2 功能权限：object.view|create|update|delete（fields: []）＋ button（object 类）；admin.<capability>（admin 类）；platform / self / own 各自判定
→ [框架] 3 写字段：按 writeFields.from 从**已通过结构校验前的原始 JSON** 提取键 → requireObjectWrite（任一字段不可写 403；控制键剔除；显式 null 同样算写该字段）
→ [框架] 4 数据范围：list → requestScope 注入；point → 定位器取归属 → scopeAllowsInTransaction；see-all → scope.all 或创建人；guard → 具名守卫
→ 处理函数(c, access)：业务校验、runCommand（幂等重放在此，重放前上面 2～4 已重新执行 ⇒ 撤权后重放得 403/404）
→ [框架] 5 出口：fields.project → 框架按查看人字段权限深度裁剪；projector → 调模块投影器；之后**出口守卫**深扫响应
```

- 顺序前移的可观察变化：以前部分路由先解析请求体再鉴权（如审批 `parseBody → requireProcessButton`），无权用户发坏请求体得到 400；改为一律先 403/404。这是收紧，不是放宽；受影响的现有测试在迁移时逐条核对（§3.5）。
- 结构校验（zod）仍在处理函数内；写字段提取只看原始 JSON 的键名，不需要模式信息，与 `writeFields()` 现有口径一致（`controls` 剔除、编制 `subdivisions` 展开）。
- `access` 对象：`{ ctx, expectedRevision, scope?, viewableFields(object), editableFields(object), assertInScope(tx, target), project(value) }`。处理函数在事务内（行锁后）用 `assertInScope` 复核，框架在事务外先拦——两道都来自同一个定位器。

### 3.2 出口守卫（defense in depth）

- 对响应 JSON 做深度遍历（对象、数组、`items / record / before / changes / preview / summary` 等任何层级）；对声明的每个对象，取其字段目录里的**非系统业务字段**集合与查看人不可见字段集合求交，命中即为泄露。
- 行为：`NODE_ENV === 'test'`（Vitest）→ 抛 `RoutePolicyLeak`，测试立即红；生产 → 删除该键并写一条结构化警告日志（`route_policy_leak`，含路由、对象、字段名，不含值）。**fail-closed，不会因守卫让泄露出去。**
- 守卫不理解语义：同名字段属于多个对象时以声明的 `objects` 为准做并集；`envelope` 白名单只接受字段目录以外的键（`valid / errors / hasDataPermission / page / nextCursor …`），不能用来放行业务字段。

### 3.4 定位器 / 守卫 / 投影器登记（`route-policy/registry.ts`）

- `registerLocator(name, (tx, tenantId, id) => Promise<{ orgId?, personId?, creatorId? } | undefined>)`：返回 `undefined` 即对象不存在 → 与范围外同码（不泄露存在性）。
- `registerGuard(name, (access, c, tx?) => Promise<void>)`：抛 `AppError` 即拒绝；**每个守卫必须同时登记一个反向测试工厂** `registerGuardTest(name, factory)`，FW-06 枚举所有守卫，缺测试即失败。
- `registerProjector(name, (access, value) => Promise<unknown>)`。
- 三者由各模块在自己的目录里实现并在 `register*Routes` 开头登记；权限模块不 import 业务实现（沿用 `module-contracts.ts` 的端口思路）。

### 4.5 断言方式（对应自查清单）

- 状态码：一律断言具体码与 `error.code`，不接受"非 2xx"。

- 深扫：`walk(json)` 收集全部键路径与值；字段缺席与 id 不出现都在全树上判断，不只看顶层。
- 空请求体：FW-02 / 03 的反例故意不带合法体，证明拒绝来自框架而不是结构校验（框架先于 zod 执行）。
