## 二、新经验（值得沉淀）

### 1. 多轮不收敛时，先看“新 P2 出在哪”，再决定改结构还是砍范围

| 案例 | 现象 | 处理 | 结果 |
|---|---|---|---|
| #110 F-039 PR-A | 前 3 轮每轮补一个出口，审查又找到下一个 | 改结构（DEC-348②） | 第 4 轮通过 |
| #125 360 PR-B | 匿名披露连续 3 轮各换一个出口（身份 → 差分 → 审计） | 所有答卷读取统一走匿名投影层（DEC-364） | 第 5 轮通过 |
| #189 F-082 契约 | P2 6 → 4 → 3 → 2，但后两轮新 P2 全出在**新加的回退 / 兼容层** | 拿掉 unbind / 回退，只前进修复（DEC-383） | 第 5 轮窄改 |

**建议沉淀**：第 3 轮起，进度窗口给总编排的分析固定回答两问——同类问题是否“换出口重复出现”（→ 改结构、统一收口）；新 P2 是否集中在本轮新增的部分（→ 砍范围或拆出去）。只有两者都不是，才继续逐条修。

### 2. 同类 P2 连续两轮 → 换 Opus 接手，效果明确

#163、#169、#174、#182、#184 都在第 3 轮换 Opus（DEC-338⑤），接手后 1～2 轮合并。**建议**保持；派发提示词里写明“接手会话推送后必须贴‘开发完成，待审’”（#162 / #163 两次漏贴）。

### 3. 合并越频繁，“自己 CI 绿、合进 main 就红”越多

- 迁移号撞车：0076（#136 vs #125 / #161 / #148）、0080 / 0081（#161 vs #180 / #182 / #183 / #172）。
- F-039 证据摘要过期：#172、#173、#174、#178 在 main 合入别的 PR 后 `EVIDENCE_STALE` 或锚点失配。
- 已有对策：F-072（闭包降噪 + 独立核心摘要，PR-1 在审）。
- **建议补两条**（待定）：① 迁移号在**合并前最后一次合 main 时**才定，开发期一律用占位名，避免早占号；② 审查合并窗口每合一个改动 F-039 登记或迁移的 PR，就按现在的做法群发“合 main 提醒”，并在提醒里点名需要顺延的 PR（已在做，写进派发规则）。

### 4. 开发完成的“交审动作”要可校验

监控在本期抓到的衔接问题，按原因分：

| 原因 | 例子 | 对策 |
|---|---|---|
| 推送后与 main 冲突，CI 不触发 | #161、#172、#174、#183 | 开发方贴“开发完成”前先确认 PR 可合并、CI 已开跑（审查合并窗口已要求） |
| 推完不贴“开发完成” | #162、#163（Opus 接手会话） | 写进接手派发模板；监控“待送审”兜底 |
| CI 排队 / 变红 | #172、#173、#174、#178 | 监控已改：CI 跑或红时不报衔接超时（watch.py） |

### 5. 外部依赖要有替身

- **CI 镜像**：10-09 21:00Z 起 Docker Hub 匿名限流，PG 三片全部起不来，靠手动重跑撑了约 5 小时；#186 改用 ECR 公共镜像后解决。**建议**：CI 用到的其他外部镜像 / 下载也换成不限流的源，或配置登录。
- **CI 环境字体**：#174 发现 CI 无中文字体，PDF 下载 503；已开 F-080 内置字体并在启动时检查。部署环境同理。
- **取证浏览器**：ego 空间 21 页面状态崩溃，取证窗口停了约 8 小时等用户刷新。**建议**（待定）：取证窗口遇到页面崩溃时，先自行关闭重开该标签页或改用另一 Profile / 内置浏览器继续，只有登录失效才等用户。

### 6. 产品决策卡在“总编排等用户”时，进度窗口要直接提醒用户
