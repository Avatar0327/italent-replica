## 1. 产品定位

复刻北森 iTalent 的**人力资源管理系统**，以演示租户「北京SR样板间」的实际运行行为为还原基准。

### 1.1 原站是什么（已实证）
原站**不是** 64 个独立开发的业务模块，而是**一套元数据驱动的 PaaS 平台 + 64 份应用配置**：
- 所有业务页面由统一接口渲染（`/api/v2/UI/IndexPage`、`/api/v2/UI/TableList`）
- 配置中心对每个应用提供同一套 9 类配置能力（字段/表单/列表/视图/流程/按钮/数据源/模板/权限）
- 业务对象、视图、字段有统一命名规范（`应用.对象`、`应用.对象.字段`）

**这个事实决定了复刻的成本结构**：业务功能本身不难，难的是配置引擎。

### 1.2 本次复刻的定位（DEC-001）
**R1：固定配置 + 少量可配。**
复刻配置的**运行结果**，不复刻配置引擎。是否开放某配置项给管理员自助，**逐模块显式决策**。

**必须向用户明示的产品差异**：
| 差异 | 影响 |
|---|---|
| 管理员**不能**自助增删字段、调整表单布局、改审批流 | 变更需开发介入 |
| 业务表单上**没有**「配置表单」入口 | 原站可从业务页直接跳配置 |
| **不提供**通用配置中心 | 64 应用 × 9 类配置能力不复刻 |

## 2. 目标用户与规模（DEC-006，2026-09-27 已决）

| 项 | 决策 |
|---|---|
| 内部自用 / 对外产品 | ✅ **对外 SaaS 产品** |
| 是否多租户 | ✅ **多租户** |
| 目标企业规模 | 未单独指定；按原站客群（百人至万人级、含集团化客户）设计 |

**由此带来的范围变化**：
- **租户隔离**是地基：所有业务数据、配置、身份、管理单元、流程、开关都必须按租户隔离（原站所有接口都带 `tenantId=410142` 一类参数）。
- **L1 平台运营层**从“不做”改为**必做**：租户开通、系统级预置（标准对象、标准身份、标准流程、标准开关）下发、许可证发放。原站该层对租户账号不可见，**只能依据官方文档和租户侧可见的痕迹设计**（例如“标准配置可覆盖、可恢复”、身份许可余额）→ 相关规则标 🟡。
- **许可管理**（余额、分配组、使用明细、消耗规则）升为核心能力。
- 组织模型保留集团与多法人结构（原站有 `北京SR样板间 / 华夏九洲集团 / …` 多级）。

## 4. 字段口径（DEC-005）

**复刻结构，不复刻字段实例。**
- 保留「标准字段 + 可扩展自定义字段」的对象机制
- 复刻有明确业务语义的标准字段
- 剔除演示性行业字段，降级为"自定义字段示例"

**实例**：本租户组织对象有 42 列，其中约 24 列是演示性字段（商务标签、是否大客、餐补标准、打卡企微等），不纳入首版。

**强制动作**：对象字典中每个字段必须标注 `标准` / `演示` / `待定`；拿不准一律标 `待定` 交用户确认。

## 5. 端

| 项 | 状态 |
|---|---|
| PC Web | ✅ 首版必做 |
| 移动端 | ✅ DEC-007：**首期不做**；员工端与管理端的移动需求登记在需求基线中（REQ-MOB-001，后置），首期验收通过后提示启动 |

**已知移动端不是简单适配**（原站实证）：
- 有独立配置体系：APP菜单设置、APP页面管理、APP通用设置、签到设置
- 有独立表单行为：调动表单在移动端**默认隐藏变更前字段**，提供【显示原值】切换、区块锚点导航
- 有独立入口：移动端-自助服务-人事申请、移动端-团队成员-人员详情页

→ 若纳入移动端，**不能按"响应式适配"估算**，需按独立端估算。

## 6. 成功标准

### 6.1 首版验收门槛
1. **调动闭环可端到端跑通**：员工/经理发起 → 审批流转 → HR 执行 → 生效 → 任职记录版本链正确 → 向后更新正确
2. **三层权限模型生效**：平台运营层 / 租户管理层 / 业务角色层，且**功能权限与数据权限分别可验证**
3. `05_验收/01_验收场景与追溯表.md` 中标记为首版范围的场景**全部通过**
4. 每条需求可追溯至原站证据或明确的用户决策

### 6.2 明确**不**作为成功标准的
- ❌ 与原站界面像素级一致
- ❌ 复刻原站演示租户的业务数据
- ❌ 复刻配置中心
- ❌ 菜单条目数量对齐
