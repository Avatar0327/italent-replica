> 按 DEC-521⑤ 设立，由 04 优化和答疑窗口起草并维护；2026-10-15 初版。依据：origin/main 上的 `docs/00_状态/02_已确认决策.md`（至 DEC-517）、`docs/09_派发/后续任务.md`（至 F-164），以及对代码的关键词检索。
> 维护规则：新登记的 DEC / F 只要涉及“降到 L2 / 暂停 / 后补”，就在对应节加一行。总编排登记后抄送 04，或由 04 定期对照决策文件和后续任务表补齐。

## 0. 口径

- **DEC-456①**：契约（数据模型、接口、页面）按 L3 形状设计，实现可以先到 L2；升到 L3 只换内部实现，不动页面与接口。
- 本清单只记录“为了 L2 / 演示优先而省掉或降低的东西”。它们分三类：
  - **回调**：做 L3 时必须补；
  - **可保持**：L3 也不必改；
  - **待定**：需要用户判断。
- 来源都写到 DEC / F 编号。后续每登记一条降到 L2 或后补的 DEC / F，就在这里加一行。

## 5. 发现的缺口

1. **代码里没有 L2 / L3 标记。** 检索 `TODO(L3`、`补 L3` 结果为 0。降到 L2 的简化只记在 DEC 和 F 任务里，升 L3 时很难从代码定位。建议今后降到 L2 的位置统一加注释 `// L2(DEC-xxx/F-xxx): 简化说明`，用一条检索就能列全。
2. **“演示数据”混用。** 同一个词既指演示种子，又指接口替身，建议拆成两个标记。
3. **流程层回调（§1 的 P1 / P3 / P4 / P5 / P6）没有触发点。** 建议规定：某个模块开始补 L3 时，派发单必须引用本清单对应的行。
