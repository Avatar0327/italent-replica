## 两项依赖已补齐

- `POST /api/tenant/employment/interns` 在一个命令、一个事务内完成建档或沿用候选人员、实习任职及合同。
  合同终止日必填，必须晚于入职日；当前入职生成正式合同，未来入职保存待入职合同。
- 成功回执显式返回 `view: interning | pendingEntry`。前端只按回执刷新和跳转，不能按客户端日期推断去向。
  后端当前实现对未来入职采用 `pendingEntry`；原站未来实习视图归属仍标未验证，以后端注释为准。
- 失败整单回滚、命令结果可回查由 BE-R2d4c 提供；本片不改后端、不拼接多笔写入。

## 原站一致性与保守边界

本机查看 35-intern-create-form、R2f1 的 06-intern-rehire-id-prompt 及补证文字。
表单沿用员工信息、实习信息、汇报关系、实习协议的分区顺序和双列布局，合同协议终止日期必填。
可写字段按后端一次写入白名单；个人邮箱、手机、性别、出生日期、学校、专业、学历等本接口不接受，
不展示可填写却无法保存的假控件，提示在员工档案维护。额外资料的本表单写入未覆盖。
原图只在本机查看，没有截图、原站链接或真实人员数据入库。

- 证件类型 + 证件号码只用于 `rehire-matches`，不随新增命令保存。已填写证件须先点击校验。
  提示默认“否”，字段裁剪缺省显示 `--`；只有明确离职候选可选“按重聘入职”。
- 退休或结束类型不可见时不开放返聘，引导入职管理；后端支持的 `retire_rehire` 不在本片开放。
- 手机 / 邮箱匹配规则接口未提供，本片不实现；匹配优先级、唯一性、复聘次数来源均未验证。
- 新人员没有可调用的部门经理默认预览接口；现有员工预览与调动默认接口不能冒充新增默认。
  选部门不自行推断负责人，直线经理留空，允许用户从授权候选中选择。
- 未来日期只填写公司和终止日期，其他合同字段在办理入职时维护，与 BE-R2d4c 严格请求一致。
- `hire / rehire` 不在编制确认的 `CAPACITY_KINDS`；本接口严格请求没有 `confirmed` 字段。
  因此本入口无 `CONFIRMATION_REQUIRED` 二次确认路径，不发送虚构确认字段。

## 单一入口与复用

已核对 `entries/EntriesPage.tsx`、`CompleteForm.tsx`、`CompleteFields.tsx`：添加待入职仍为禁用入口，
现有办理入职用于已有人员，没有可直接复用的新增 / 证件重聘判定。判定请求、回执校验与提示统一在
`intern/RehireCheck.tsx`，表单选择和 409 重读均调用同一入口。
复用 F-123 FormCommands / useCommandForm / useDraftRefill / FormLock / CommandStatus、
合同与兼职模块引用选择器、租户日期控件、权限快照和 API 客户端；不复制 entries 的办理流程。

## 提交与恢复

新增和重聘共用页面级固定恢复槽。保存中禁止重复，明确拒绝保留输入允许修正；409 先复核证件候选及
员工 revision，用户确认后继续编辑；重读失败保持锁定。新业务 revision 独立于员工 If-Match。
无回执、回执不一致、写后读取失败都保持未知只读；关闭重开或切换实习视图不能绕过原命令。
命令结果查询只读，使用原命令 ID，不自动重放、不解除未知锁。

没有增加路由或权限编码，不变更 F-039 登记集合；只更新 intern 自有注释。
验证实跑命令、结果和自检清单见本地交付结果文件。
