# 内部招聘职位：业务预验收步骤

本批是基于 BC-R05 表单证据的限定实现，尚未人工业务或生产验收。仅使用合成需求、候选和人员；不向原站写入、不发布外部广告。测试角色是测试夹具中的逻辑身份，不是在线登录凭据；线上应使用现有所有者及已授权合成成员，不扩大站点访问。

1. 以组织范围内 HR 建立合成需求，保存并提交；独立经理审批。HR进入 `/recruitment-jobs` 新建职位，填写类别、用工方式、地点、职责、资格和月薪范围，保存草稿。
2. 草稿不能登记候选；HR“内部启用”后，从招聘与入职页选同需求和该职位登记合成候选。预期候选详情显示冻结的职位版本和原地点、职责，不修改需求名额。
3. 建立后续职位版本，将地点或月薪改成面议并启用；登记第二候选。预期分别保留第一版、第二版内容，不能直接编辑已启用内容，也不能从旧版再分叉。
4. 归档第一版。预期不能向归档版新增候选，但第一候选既有面试、录用、入职可继续。将需求人数设为1并先录用第一候选，第二版候选随后入职必须因共用名额被拒绝。
5. 以越界 HR、普通员工尝试读取/修改；预期拒绝。经理可读范围内职位但不能写。旧修订号修改返回409，刷新后重新评估；审计故障不得部分保存。
6. 查看历史和候选来源，确认归档不删除证据；旧仅关联需求、不含职位的候选流程仍正常。

自动化覆盖版本冻结、错误需求关联、归档、共用名额、角色/组织拒绝、薪资整数/范围、万字中文正文、请求限额、CAS及审计回滚。界面浏览器验证、企业业务确认与生产验收分别待完成。

保留后续范围：广告与审批、外部门户/邮件、共享/关注权限、可配置筛选评分和面试流程、候选人多职位投递与人才库、原站枚举及提交验证。不将“内部启用”解释为原站广告发布。
