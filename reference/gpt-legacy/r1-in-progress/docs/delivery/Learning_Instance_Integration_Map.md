# 学习任务实例接入清单 B–D

基线：A1配置版本已实现；本清单是代码核查后的实施约束，不代表相关功能已开发。

| 文件/消费者 | 已有真实约束 | 实例接入要求 |
|---|---|---|
| development.ts / enroll | 员工+课程版本全局唯一；培训与发展计划范围校验 | 仅携带有效assignmentId的新路径按实例唯一；旧路径保持，禁止凭客户端自造ID放宽 |
| development.ts / attemptExam | 考试次数及通过记录绑定enrollment.id | 保留绑定，新增实例不得引用上一轮attempt |
| development.ts / verifyLearning | 独立核验、必修场次出席 | 不因同步旧进度自动豁免目标出席；核验时重查实例状态与当前人员权限 |
| development-repository.ts | 单次最多20记录、整体CAS+审计事务 | 一个实例+20课程共21记录会超过现有界限；不能静默截断，需专用有界批次或分批有明确准备状态 |
| training-stages.ts / dispatch | 按trainingId和独立核验结果 | 实例完成投影隔离轮次；阶段未派发课程仍计入要求，不按已有任务数充当分母 |
| training-sessions.ts | 报名通过employee+course+training定位 | 多轮场次要明确目标实例；保留历史场次，不让上一轮出席抵本轮 |
| learning-credits.ts及其API | 一任务一次授予，撤销保留；查询选定kind | API必须加载实例与冻结奖励规则；repeatCredit=false跨轮去重，true同轮仍唯一；不得只在前端隐藏按钮 |
| reports.ts / reportKinds | 按数据集选择kind，任务报表按enrollment | 增加实例/要求依赖与轮次来源列；旧任务兼容；不能忘记SQL选择导致实例状态缺失 |
| cadre-profiles.ts | 选定kind后投影学习任务 | 增加必要实例依赖，维持HR/经理/本人当前权限，不把历史快照当访问授权 |
| self-service API / work-inbox | 独立任务筛选，查询kind各自枚举 | 同步实例状态和截止规则；取消/离职/停用不可出现可办理任务，仍按原权限保留历史 |
| development/workspace.tsx | 课程下拉按员工课程唯一；考试按task.id | 实例入口与旧报名分开，展示模式/轮次/来源；详情不能误用其他轮次记录 |

## 连续验收场景
B01 同计划版本/员工/轮次重复与旧修订并发：至多一个实例，事务失败无任务/事件残留。
B02 20课程容量边界必须可解释且原子；未支持容量必须整单拒绝。
C01 两轮同课程考试互不借用；同步模式仅关联有效同员工同版本来源。
C02 阶段、目标出勤、独立核验三者均满足才完成；目标未满足不可借旧成绩解锁。
C03 分派后调动/离职/撤权：命令、待办、学习列表行为一致，历史不扩权。
D01 repeatCredit开关两条路径、重复授予、取消恢复、撤销、到期；积分不混为学分。
D02 未完成内容迁移保留旧版本证据；已完成默认不变，显式重开独立留痕。
D03 学员、HR、经理三角色界面走通后再交人工业务确认；自动化结果不签生产。

现有48组范围不删除；未核实的自动循环触发与企业奖励细则记录待核实，不阻断有明确约束的内部实现。

## B1 已落实的限定路径
首次独立学习relative/fixed已接入实例、任务、考试/提交时间约束、独立核验、恢复截止日冻结、自助/待办、页面与报表。通用事务默认20条保持，此入口显式上限21条，并通过审计失败全量回滚检查。老课程唯一性未放宽，所以跨计划已有课程与循环轮次仍拒绝。复杂培训阶段、出勤、历史复用及循环奖励仍属于C/D，不因B1正常链路通过而删除。
