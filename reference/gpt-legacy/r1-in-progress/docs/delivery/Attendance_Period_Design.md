# 手动考勤期间汇总与冻结：限定设计

依据BC-A01–03及既有假勤交接A03/A04。全量年度期间/多组织/档案匹配/日历/自动冻结发布封存仍保留；本批不是完整原站月报流程。

首批按一名员工与显式起止业务日期（最多31日）生成汇总快照，沿用attendanceReport现有分钟和补卡取值规则，不重新写一套薪资/法定考勤算法。仅已结束期间，至少一个有效班次，不存在待审批假勤、缺卡/补卡冲突或未覆盖时段才可冻结。未知异常处理政策不以零分/正常补齐。

冻结记录保留员工/组织快照、原始revision、逐班分钟与有效打卡/补卡/请假依据、计算版本、汇总结果、操作人与时间。冻结后阻止同员工期间新增或更改班次、打卡、补卡与请假；按班次归属业务日约束跨日班次，完整班次纳入起始日，不假设按日拆分。假期年度余额不纳入此出勤快照，不将冻结解释为锁定全年额度。

更正通过带原因的重新开放办理，旧冻结行和事件保持；重新冻结增加版本并重新核对来源和权限。首批HR/admin管理、范围内manager读取，不自动向员工发布、生成工资或发通知。冻结/解冻是明确内部工作规则，原站真实写入语义待企业业务预验收；独立复核与最终月报发布/封存保留后续。

关键验证：旧无期间数据兼容；跨组织拒绝；重复/并发409；无完整数据拒绝；冻结期间所有已实现假勤写入口均受约束；重开后修订并再冻结不覆盖历史；人员调动/离职后的当前权限和历史归属处理；审计失败回滚。不得把冻结按钮或自动化通过写成G3业务/生产通过。
