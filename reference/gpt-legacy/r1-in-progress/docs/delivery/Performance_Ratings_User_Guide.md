# 绩效等级方案首批预验收

原站证据：Performance_Source_Gaps.md BC-P01、BC-P02。仅字段和说明已核实；未提交原站表单。

## 合成操作

1. 使用现有有权限HR/管理员进入绩效管理→绩效等级，在合成组织新建方案。从高到低填入：[4,5]卓越→人才高档；[3,4)良好→人才高档；[2,3)合格→人才中档；[-1,2)待提升→人才低档。保存并定版。
2. 同组织新建周期，选择该方案。配置目标权重60/40，管理者确认，员工提交合成自评；另一位管理者两项各打4分。输入100应被拒绝。
3. HR创建该等级的第二版并改变名称，定版后归档第一版。原周期发布仍应为第一版卓越/人才高档。重复发布拒绝。
4. 员工申诉。既非原评价人、原发布人亦非本人之独立HR按原目标各改3分；另一位HR发布更正。应得到第一版良好，旧结果保留；人才档位仍高，不按新版改变。
5. 配置区间空隙并用总分落入空隙，发布应拒绝，不能静默归档。跨组织方案、员工和经理管理等级均拒绝；旧周期仍限制0–100。

## 账号与边界

自动化使用内存SQLite合成owner/employee/manager/hr/independentHr；这些不是线上登录凭据。现有所有者私有访问未扩大。人工多角色验收需要按已有授权使用真实身份对应的合成业务；尚未执行或签署。

首批仅自动区间等级，同组织方案，2–20档，数值±1,000,000及两位小数为本实现限制，不是已证实原站限制。每档须显式映射原人才三档；不参与考核不得冒充低档。周期创建时保存方案；未启动且无计划的草稿可通过编辑入口明确更换，启动后固定。已归档方案不可用于新周期，原周期不受影响。

手工等级、系数、强制分布、共享公开、不参与考核、既有周期主动更新方案、完整模板和多级校准仍在后续范围。自动化、构建和私有发布均不代表人工业务或生产验收。

## 活动分类与草稿编辑

新建周期可选填年度、周期分类、绩效类别和业务日期。列表可按年度/类别/状态筛选，搜索包含周期分类；办理报表追加四列，结果与申诉保留原周期快照。分类不控制办理窗口、汇报关系或历史组织。年度1900–2200为本实现输入边界，类别/周期分类由企业填写，尚未复刻原站字典。

未启动且无计划的周期可编辑名称、日期、分类及评分方案；不能更换组织。未主动换方案时保留原冻结版，即使其已归档；选择其他方案须同组织且已定版。选择原三档可显式退回旧尺度。启动后所有上述编辑拒绝。
