# 固定班次与派班预验收

本批为内部限定能力；自动化不替代原站规则核实、人工业务或生产验收。

## 操作闭环

1. 在假勤管理进入“固定班次与派班”。使用已有有权限的管理员/HR角色；测试场景请只用合成组织、员工。
2. 创建该员工所属组织的班次草稿：09:00至18:00、12:00至13:00休息。保存并定版。
3. 选择同组织在职合成员工，填两行不同日期并确认派班。两条排班应一起出现于假勤管理，每条计划480分钟。
4. 重新使用同一日期混合新日期派班，应整批拒绝，新日期不会残留。经理可以在本组织派班，不能维护定义；员工不能访问定义接口。
5. 新建修订草稿、修改时段并定版。既有排班保留旧版本；新派班使用所选版本。归档旧版本后不能再用它派班，已派班继续有效。
6. 跨日合成示例22:00至次日06:00，休息次日01:00至02:00，应得到420分钟。业务日期为开始的北京时间日期。
7. 结合期间预验收步骤冻结包含空排班日的历史期间，再混合期间外日期尝试派班：整批拒绝且修订号不变。调出定义所属组织或离职后不能再派班。
8. 通过历史入口核对定义定版/修订/归档及员工班次快照。原始历史不应被后续修改覆盖。

## 账号与限制

本轮自动化逻辑账号 owner/HR/manager/employee 位于隔离的合成数据库，并非线上可登录账号或密码。使用现有授权成员；不扩大访问、不迁移真实数据。本轮未完成多角色线上人工验收。

首批页面单员工多日期，API同批最多20条，采用现有全局修订锁与同事务审计。不是自动周期排班器，不自动跳过节假日；不支持多时段、组织下级共享、弹性/智能班次、工作日历和加班设置。归档不取消已有排班。批量请求不提供独立幂等键：旧修订拒绝；重试前刷新并检查已生成排班。
