## C-DEF-01：保留员工关联时无法停用离职账号（未修复）

位置：总控保留的`lib/hris/member-rules.ts:validateGrant`，由`app/api/members/route.ts:POST`调用。

复现：通过API建立本人账号及计划/学习→走正式exit审批→管理员POST成员原employeeId、role=employee、active=false和当前revision→返回400“请选择有效的在职员工档案”。修订未变、成员active仍为1，本人旧计划和学习历史仍可200读取。无需真实人员或云资源。

影响：显式撤权操作受业务在职校验阻断；不是仅仅“离职是否自动停用”的政策疑问。至少应阻断依赖该停用路径的G1撤权验收，交总控修复后验证。不以更换角色、取消关联、直改数据库等方式掩盖问题。

建议最小兼容修改：保留员工角色必须关联档案、员工存在、自身管理员保护、授权组织及租户检查；只有active=true时要求员工在职。将当前员工在职校验替换为：

```ts
if (input.employeeId) {
 const employee = state.employees.find(e => e.id === input.employeeId);
 if (!employee || (input.active && employee.status === '离职'))
  throw Error('请选择有效的在职员工档案');
}
```

此建议未应用。停用可保留已离职的同租户员工关联，不允许不存在的employeeId，也不允许重新启用离职关联账号；请求/响应无新增字段、无需迁移。总控应补四个校验：离职关联停用成功及所有读取403；离职关联启用仍400；不存在员工的停用仍400；不能停用当前管理员。若选用专用停用端点，应由总控设计并保留原关联、CAS和审计事务。
