# 绩效文本模板业务预验收

此批为原有单维目标加权流程的可复用文本模板，不是完整原站流程/表单引擎。原站字段依据见BC-P03，阶段权限采用当前系统已有自评/独立评价职责，未推断原站多级执行人。

1. HR在绩效管理→绩效文本模板新建同组织模板，填写不超过200字描述。添加一个自评必填文本项、一个管理评价必填文本项，然后定版。
2. 创建同组织周期，选该模板，启动周期；员工按原流程填写目标并由独立管理者确认。
3. 员工自评缺少必填文本时应拒绝；仅能填写自评阶段项，试图提交管理阶段字段应被服务端拒绝。通用成果依据仍必填。
4. 管理评价也须填写管理阶段必填项。员工在正式发布前不能通过计划接口、详情或历史读取该管理文本；正式结果发布后可查看原模板和答案快照。
5. HR修订模板并改变文本项，新活动使用新版本；旧活动仍按原快照要求，不自动替换。归档只阻止新选择，不影响已引用活动。丢弃修订草稿仍保留版本号，不复用旧编号。
6. 周期仅在未启动且尚无计划时可编辑模板选择，启动后冻结。修改草稿名称时省略原模板参数保留旧快照，避免归档版本使正常草稿无法编辑。
7. 申诉仍沿用原目标权重、评级与模板快照，更正原因独立记录；本批不重新开启模板文本填报。未引用模板的历史周期及流程保持兼容。

限制：最多10个文本项，每项1000字；不支持附件、自定义评分/多维、匿名、分步骤可见配置、目标模板下发、多级角色或在途更新。不改变站点访问，也不创建真实测试账号。使用现有授权角色及合成数据完成实际界面确认；本轮自动化不代表人工或生产验收。

## 工作台入口补齐（v101已私有发布）

合成员工目标已确认、无待审目标调整时，工作台应出现“绩效自评”；点击进入本人具体计划详情。管理员或经理只能看到本角色可办理的目标确认、评价或结果发布任务。提交自评后本人任务消失；退回后恢复；目标调整待审、调出原周期组织或离职后不显示可推进的自评任务。访问无权限recordId只提示不可访问，不显示对象内容，不自动提交操作。

局部合成6/6（Performance_Inbox_Targeted.tap，3.934秒）覆盖待审调整、退回、调动/离职边界和模板隔离。此为领域/API证据，浏览器界面仍需人工核实。

最终待办批次综合214/214（43文件，41.196秒）、类型与构建通过；员工自助以及申诉/更正待办均支持具体记录入口。旧局部6项为子集，不是214之外的独立数量。


## 目标数量/权重检查与调整后重填（v102已私有发布）

1. 合成HR新建模板，勾选限制目标数量与单项权重，例如2–3项目标、每项20%–70%，定版后建立新周期。
2. 合成员工尝试1项100%或2项80%/20%，应拒绝且不生成计划；60%/40%应可保存。
3. 模板修订成其他范围，原周期仍按原快照检查；归档也不改变原规则。目标调整的70%/30%可以提交，1项100%不能提交。
4. 已填写自评被退回后，再申请目标变更并获独立批准，当前回答应清空，员工按新目标重新填写；历史保留原回答，未发布管理文本仍隐藏。

仅强制范围的单维整数子集，不包含软提示、小数权重、多模块计分或指标自动下发。局部10/10（4.023秒）包含既有绩效流和待办子集；人工操作未验收。

本批领域/API综合216/216（43文件，43.608秒）通过。具体记录详情增加当前角色可办理按钮，点击后关闭详情再打开填写表单；不自动提交业务。此界面调整仍待浏览器/人工核实，不计入自动化通过项。
