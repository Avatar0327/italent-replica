# 合同文本字段与续签继承首批设计

来源BC-F02。仅实现合同协议分支，任职记录字段继承、合同变更流程和其他字段类型仍保留。

HR/admin按组织维护文本字段版本：草稿、定版、修订、归档；编号稳定、定版不可改，继承开关缺省为是。新合同使用员工当前组织的有效字段版本，记录字段ID/稳定根ID/版本/名称/值。续签显式指向同员工原已签/结束合同；只有当前定义允许继承且未手工覆盖时，才按稳定根ID复制原合同快照值，并保存原合同和字段版本。清空不等于缺省，后续定义变化不改写已登记合同。

独立设计：首批可选文本、每项最多1000字，每合同最多20个活动字段；归档最新版本停止新合同携带该字段，旧合同及事件保留。新修订草稿不取代已定版版本；归档最新定版不得回退到旧版本。未配置字段的旧合同流程保持。合同基础日期/类别/签署及续签校验不变。员工本人已签合同读取仍按既有基础字段投影，新增字段先限HR直到原站及企业字段可见性规则确认。

必要验收：默认继承/不继承/显式清空/覆盖、原合同和事件不变；新版本改变继承仅影响新合同；草稿不隐式激活、最新归档不回退；跨组织及伪造字段ID拒绝；同员工原合同/重复续签/CAS与审计失败原子性；普通员工/经理读取历史不能泄露专属字段。

## 本轮实现及验证
上述限定闭环已实现。入口：组织员工→编制合同→合同字段与继承。定义定版后，新合同选择员工即显示当前组织字段；续签显示来源默认值，可覆盖、清空或恢复默认；合同详情显示当时的字段版本及来源。字段草稿丢弃不影响当前定版，最新已定版归档不退回旧版。

专项3项，最终98/98关联回归、0失败/跳过，6.772秒，类型检查通过；Contract_Fields_Verification.json和Contract_Fields_Run.tap记录本轮命令。覆盖默认继承/不继承/清空/手工覆盖、版本修订/丢弃草稿/归档、原记录不变、旧ID和越权字段拒绝、重复续签、旧修订、审计失败回滚及员工投影。未访问原站合同正文、未实际签署或迁移真实合同。自动化不替代人工业务与生产验收。
