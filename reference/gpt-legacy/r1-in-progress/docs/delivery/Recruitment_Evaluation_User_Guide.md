# 结构化面试评价业务预验收

本批供集中确认业务结果；自动化和私有发布不代表人工业务或生产验收。只用合成数据。合成HR、经理、员工是本地测试逻辑角色，并非新建在线凭据；站点访问仍限既有所有者，不自动邀请其他人。

1. HR在“结构化面试评价”中新建组织内评价表，添加两个维度、若干指标和四档标签。保存草稿后定版。经理可以读取但不能修改模板；普通员工不可读取。
2. 在招聘模块创建并由独立经理批准一条合成需求，登记合成候选。回到评价页选择候选与岗位同组织定版表。
3. 选择“通过，建议推进”，填写全部指标1–4分及综合依据，保存。预期产生一次独立评价，显示冻结表名/版本、逐项分数与评语，未生成总分。未评全不能通过；超范围、小数、未知指标拒绝。
4. HR修订评价表、改变指标说明并定版，再归档旧表。预期旧评价继续显示原内容，不能向旧归档表新增评价；原通过结果仍可作为录用依据。
5. 对另一合成候选先记录通过，再记录“不通过，不建议推进”，可以只填结论依据。预期未评分保持空缺，最近拒绝阻止录用，不被较早通过覆盖。旧单一等级评价仍保留为兼容模式，顺序与新记录统一。
6. 以越界角色尝试同一对象和异组织模板，预期拒绝；旧revision409。模拟保存响应丢失后用相同请求键及内容重试，应恢复原记录且不新增评价。内容改变需先核对原记录再明确发起一次新评价。
7. 配置修订恢复：定版1→草稿2→归档2→重新修订得到3；不得复用2。仍存在启用的新版本时不能从旧版分叉；历史评价、学习任务及绩效结果不被覆盖。

已知限制：原站总分/维度权重、岗位自动选表、面试官指定与代评授权、排期/邀约/通知、自助约面、完整流程轮次尚未实现或核实；当前以实际登录账号记录，不代他人签署。界面浏览器验证仍受既有预览阻塞影响。业务负责人须核对四档标签、通过必填与不通过简化规则是否适合本企业，再单独记录业务验收。
