# 下一批：计划活动、成绩与完成要求模型

当前状态：混合课程/独立考试、阶段门槛/顺序、成绩聚合和显式循环已开发；客观题增量149/149综合通过。辅导/线下考核等异类活动、内容权重、阶段截止和在途迁移仍未实现。下文保留历史设计演进，以末尾补充及当前检查点为准。依据BC-L03/04/05和当前C1/C2代码；不能直接把课程内考试当成原站计划内独立考试活动。

## 依赖顺序
1. 学习内容要求版本：requirementId稳定、版本不可变，类型course/exam/assignment/mentoring/offlineAssessment；保留旧courseIds到course要求的兼容映射。
2. 独立考试定义与任务：examDefinition版本包含试题/通过线/次数规则；examAssignment绑定员工+计划实例+requirementId；attempt仅引用自己的examAssignment，题目正确答案仅管理权限读取。
3. 实例要求完成投影：逐requirement读取课程核验、考试、作业、带教或线下考核证据；明确哪些是必修、阶段最少数量、时间及顺序。不同证据类型不互相冒充。
4. 计划总成绩：独立于要求完成。规则版本区分none、allHighest、allAttemptsAverage、eachExamHighestAverage、specifiedExamHighest、contentWeighted。
5. 内容版本迁移：未完成实例迁移保留旧要求/任务；已完成实例默认不变，显式重开独立留痕。迁移、成绩重算和奖励不能分散提交导致部分状态。

## 成绩算法的已知与未知
BC-L05只确认四种考试汇总选项名称。allAttemptsAverage与eachExamHighestAverage的分母不同，不能合并成一个average。未作答场次是否计零、是否包含未通过尝试、指定考试是否允许多选、缺失权重、舍入精度、课程内考试是否参与计划成绩、历史同步是否复用计划成绩均待核实。设计保存每个来源和计算参数；缺失成绩先标记未定，禁止自动当零或宣称已计算最终成绩。

contentWeighted需先确认每种活动允许的成绩来源，不能给无考试课程编造100分。源任务完成不等于取得满分；学分、学习完成率、成绩为独立指标。

## 后续代码改造清单
- learning-plan-definitions/model：活动要求版本与输入互斥校验，兼容既有课程清单。
- learning-assignments及API：原子生成异类任务；容量按总写入条数计算，不把21条上限当无限批量。
- development/visibility：独立考试和成绩字段投影、当前成员/组织范围、退出后的历史权限。
- training-stages、任务派发、实例结项：采用统一requirement完成投影，未派发要求仍在分母中。
- 课程学习/考试UI、self-service、work-inbox、reports、cadre-profiles：同批区分原始完成、历史复用、活动考试与课程内考试，避免展示与可办理性不一致。
- learning-credits：仍不把完成率或成绩直接转化为奖励；循环重复奖励另有冻结规则。

## 必须保留的验收
旧普通报名和培训阶段链路、实例考试隔离、C-DEF-01、调动/离职、撤权、重复/旧修订、审计失败回滚、20课程容量、整体取消恢复、历史来源和去重全部保留。新增多考试各两次成绩的合成反例，确保两种平均确实不同；缺失成绩不静默归零。通过自动化后仍需界面与人工业务预验收，生产验收单列。

该设计不删除任何全量范围，不创建新聊天或移交写入者；当前总控继续拥有共享文件与合并发布职责。

## 本轮兼容落地边界

- learningRequirements保存稳定课程要求ID与课程版本引用，旧记录按courseIds只读映射；新实例冻结要求和阶段，不变更旧实例。
- 统一完成投影核对员工、实例、课程、要求ID和独立核验人/时间；重复或缺失任务不能充当完成。
- 学习计划草稿可划分最多10个课程阶段，所有课程恰好属于一个阶段；选必修最低数量分别验证。课程清单改变时清空阶段并提示重新配置，定版后只能建立新版本。
- orderedStages控制阶段间考试/提交/核验与自助待办；达到前阶段门槛后自动开放。所有任务仍一次原子派发，未开放任务可以查看，但不能办理。
- 达到各阶段门槛后可结项；剩余未完成课程原子关闭，不记完成、不授学分。该结项关闭策略为本系统明确设计，尚未核实原站结项后选修继续学习语义，人工业务验收需确认。
- 调动/离职/停用组织后禁止结项，允许管理员取消并保留历史；沿用已有生命周期约束，不冒称原站特殊追补政策。
- 阶段日期、阶段内顺序、独立考试与作业/辅导/线下考核、总成绩、在途内容迁移和循环仍保留待办。

## 后续实装：独立考试首批（2026-09-08，待发布验证）

- learningExamTask按员工与试卷版本唯一派发，learningExamAttempt仅绑定该任务。作答与任务状态同一事务；失败审计整批回滚。
- 当前只有明确填写的及格线与次数；每题等权、百分制四舍五入取整、通过后不再重考是本系统首批规则，未声称原站完全相同。
- 学员仅收到去除correct的试卷投影；通用记录与历史API同样禁止员工/经理读取试卷定义。HR仍受组织范围限制；管理员不能代员工提交作答。
- 未来开始、过期、调动、离职、组织停用和取消阻止作答；历史保留。定版试卷归档停止新派发，已派发任务仍使用该不可变版本，是当前明确策略。
- 独立考试通过不自动完成课程、学习实例或授予学分；绑定计划requirementId与总成绩仍待接入，不能把这个独立任务当作整个活动模型已完工。
- 阶段startAfterDays已经开发：按加入实例的中国业务日期计算，且不得早于固定计划开始；不可达截止配置在派发前整单拒绝。阶段截止/超期和阶段内顺序仍待开发。

## 计划绑定当前增量（覆盖上文“尚未绑定”）

learningDefinition新增examIds，与courseIds合计1–20项，允许仅考试计划。learningRequirements以kind=course/exam区分稳定要求ID；独立试卷只能选择同组织已定版版本。新实例一次保存自身与全部异类任务，仍21条事务容量，不新增迁移或扩大批量上限。

阶段的trainingStages[].courseIds为兼容字段名，在学习计划中存课程与独立试卷资源ID；旧培训项目仍仅课程。配置校验所有资源恰好属于一个阶段。新版本修改不会改写已派发的要求快照。

考试任务绑定learningAssignmentId和learningRequirementId，学员只可在实例有效、阶段开放、前置门槛达标后作答。未开放且无历史作答的试卷不下发给学员；答案始终剥离。考试完成依据属于该员工/任务/试卷的通过尝试，不写课程核验人。原独立派发考试或其他实例成绩不折抵本次考试；历史同步目前仅适用课程。

整体取消/恢复同批处理课程与考试；已通过尝试保持，次数用尽的failed状态恢复后仍failed，不能重置考试次数。达到阶段门槛结项时关闭剩余未完成任务，不授予完成或学分。

新增HR独立考试台账及人才档案独立考试记录：分数和状态不等于课程完成、人才评价或计划总成绩。未实现项目仍包括多题型、阶段内顺序、阶段截止、内容迁移、循环和计划成绩。

## 成绩规则首批实装（覆盖上文“计划成绩未生成”）

- learningDefinition.gradeRule只可在草稿配置，定版后不可变；实例冻结副本。更换考试集合清空旧成绩规则，旧客户端省略examIds时保留现有集合，避免误清除。
- none/allHighest/allAttemptsAverage/eachExamHighestAverage/specifiedExamHighest；后者明确只选一场本计划独立考试。计入全部作答或仅通过作答、0–2位四舍五入由配置明确选择，属于本系统规则，未宣称原站默认。
- 只读取本实例、本人、对应要求/试卷的有效尝试。缺少所选考试的成绩即pending/null，不把缺失当0；真实0分保留。仅在实例结项后标final，此词指已结项成绩，不是人工或生产验收。取消/进行中的计划最多暂计。
- 两种平均的反例：考试A两次0/80、B一次60；全部作答平均46.67，各考试最高平均70。失败是否计入可明确配置；不隐式假定源站分母。
- 新增学习计划要求与成绩报表及HR人才档案计划实例区分，管理者不获得其无权读取的考试成绩。
- 后续仍包括内容权重、阶段截止/超期、阶段内顺序、异类作业/辅导/线下考核、循环与在途内容迁移；完整学习模块未验收。
