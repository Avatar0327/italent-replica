# 考勤期间预验收步骤

本批限已有固定班次，按单人显式1至31个已结束业务日核验。测试使用合成数据；HR/经理/员工为本地测试逻辑角色，非在线新建凭据。站点仅现有所有者可访问，未迁移真实数据或扩大访问。

1. 在假勤管理中为合成员工建立过去日期的09:00–18:00班次，休息12:00–13:00。提交完整补卡并由其他账号独立核验，或提交全天请假并独立批准。
2. HR进入“期间汇总与冻结”，选择该员工和已结束日期区间，点击预览。预期计划480分钟；全天请假时批准请假480、未覆盖0；预览不改变修订号或创建锁。
3. 如有待审批、缺卡、冲突、未来班次、无班次或未覆盖时段，预览显示具体阻止原因，不能冻结。不能把未核实异常自动补正常或推断扣薪。
4. 填写核验依据并冻结。旧预览后如果来源/权限已改变，保存应409并要求刷新。预期生成含逐班结果、来源ID/修订号、计算版本、操作者及时间的快照。
5. 员工页看到班次已冻结。尝试新增期间内班次、补卡或变更已批准请假，服务端拒绝；HR管理和员工界面均不能绕过。年度余额仍独立记账，不在这份出勤快照的冻结范围内。
6. HR记录具体原因重新开放，办理更正并经既有独立审批，再预览和重新冻结。预期冻结版本2保留新结果，历史中版本1不变。若区间本身错误，可重新开放后有依据作废，再建立正确区间，不删除旧记录。
7. 员工调动后，以当前人员范围检查历史读写，原组织越界HR拒绝；锁仍按员工ID保留，不随调动丢失。记录时组织是每次冻结当时的组织，不声称重建历史日期组织归属。

本批HR/admin管理、manager范围内只读；不自动发布员工月报或生成工资。跨日班次完整归属起始业务日。多组织/年度期间/自动任务/员工确认/申诉/发布/封存、复杂排班及法定企业假期规则仍未完成。原站字段与页面说明已核实，实际提交规则、人工业务及生产验收尚未签署。
